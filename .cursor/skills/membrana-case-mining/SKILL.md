# Membrana case mining — добыча кейсов из транскриптов сессий

Родился в исследовании первого мостика 27.07 (PR #1349: пять кейсов-кандидатов из
сессии `7f931953`, находка «первый мостик был 22.07, не 25.07»). Метод повторяем для
любых удачных импровизаций: вечерние эпизоды, долги попугая, восстановление ранних
кейсов (#1229 / #1298).

## Закон Raw (несущий)

- **Цитата существует только с указателем** `{sessionId, uuid, timestamp}` — без него
  это пересказ, не сырьё.
- **Дословность**: перед публикацией каждую цитату сверить с файлом побайтово
  (`grep -c "<фраза>" <файл>`), включая опечатки автора и экзотические символы
  (прецедент: «Кร-ррр» попугая с тайской буквой — так и цитируется).
- **Хронология по таймстампам**, не по драматургии: порядок цитат в Raw обязан
  совпадать с порядком событий.
- Реплика — только события `type: user|assistant` с маркером **в тексте реплики**;
  маркер в tool-результате цитатой не является.

## Метод (пять шагов)

1. **Инвентарь до чтения** — `yarn sessions:scan --markers "слово1,слово2"`:
   одна строка на сессию (первая..последняя метка, размер, счётчики), сортировка
   с ранних. Файлы стримятся — в контекст целиком не тянуть.
2. **Выбор сессий** — по всплеску маркеров; помнить подсказку владельца 27.07:
   самые ранние прогоны часто самые ценные — идти вперёд от ранних, не назад.
3. **Экстракция** — `yarn sessions:extract <sessionId> "<маркер>"` (реплики с
   указателями) и режим окна `--from … --to … [--role user]` — реплики капитана
   вокруг найденного момента.
4. **Сверка** — побайтовый grep каждой цитаты; отрицательный результат поиска — не
   доказательство отсутствия: перечислить перебранные формы записи (норма 27.07;
   прецедент: «Фаррел/Фаррелл/Farrell/Ferris/Фыр»).
5. **Оформление** — один жест = один кейс; два примера одного жеста = один кейс с
   двумя Raw-блоками. Только `status: candidate` — печать bearing/museum и weave
   инструкций — слово капитана (P3–P4 из M4).

## Ловушки

- PS 5.1 `Get-Content` портит UTF-8 — только node-стрим (`sessions:*`) или Read/Grep.
- Сессия может покрывать двое суток — **дата эпизода из timestamp события**, не из
  даты файла и не из даты показа скриншотов (наблюдалось: показ 25.07, эпизод 22.07).
- Ранние вхождения маркера могут быть омонимами («мостик» 16–18.07 = диалог-шаг
  ритуала, не комната) — исключать явно, с перечислением.
- Указатель — на событие (uuid); длинное assistant-сообщение может питать разные
  кейсы разными фрагментами одного uuid — это законно.
