# Membrana — спринт с честными исполнителями

Канон: заседание [`sprint-honest-performers`](../../../docs/meeting/sprint-honest-performers/MEETING_VERDICT.md)
(10/10 вердиктов, ратифицирован владельцем 30.07) · шторм
[`storm-team-volume-in-work-2026-07-30`](../../../docs/storm/storm-team-volume-in-work-2026-07-30/REPORT.md) ·
контракт механизма
[`INTERFACE_CONTRACT.md`](../../../docs/cowork-sprint/cowork-honest-sprint/INTERFACE_CONTRACT.md) ·
решения владельца [`OWNER_ANSWERS.md`](../../../docs/cowork-sprint/cowork-honest-sprint/OWNER_ANSWERS.md).

## Зачем это существует

Участник виртуальной команды — **специализированный профильный контекст**, то есть ещё один
слой ревью. Пока нет нарезки, использование персоны вырождается в подпись под тем, что сессия
сделала бы и так: контур памяти теряет смысл, потому что персона ничего не решала.

Слово владельца: использование членов команды — **не про передоверить исполнение на сторону, а
про придать реализации больший объём и контроль через ответственность**. Медленнее, зато
прозрачнее. Когда нужен просто результат — есть вторая дверь (ниже), и она честно пишет
«персональной ответственности нет».

## Роли — закрытый список, слоты не совмещаются

| Роль | Предмет | Момент |
|---|---|---|
| **Владелец** | аудит **нарезки** через ратификацию | до работы |
| **Тимлид** (`tarasov`) | режет работу на блоки; не программирует. Сопоставляет нарезку с результатом | до · после |
| **Ангелина** (`angelina`) | ведёт спринт по этапам и **контролирует реальную ответственность**: был ли прогон через контекст, подготовлена ли сессия | по ходу |
| **Фаррелл** (`farrell`) | свободный голос: не гейт и не слот, говорит без приглашения | когда сочтёт |

**Ведущий ≠ исполнитель ≠ аудитор** (вердикт M6). Ведущая проверяет **наличие и метки**, а не
достаточность вещдока: она гейт, а не судья. Суждение надзора из её рта — «рот не тот».

## Жизненный цикл

```
1. НАРЕЗКА — тимлид пишет план: blockId · persona · context · zone[] · estimate.changedLines
     yarn sprint:cut --plan docs/sprint/cut/<sprintId>.json
   вердикт: contract | findings | unreadable   (findings и unreadable — оба красные)

2. РАТИФИКАЦИЯ — владелец говорит «ратифицирую», ИНСТРУМЕНТ пишет отметку
     yarn sprint:cut --plan <p> --ratify --at <ISO со смещением>
   правка тела после согласия СБРАСЫВАЕТ ратификацию (дайджест) — это не баг

3. РАБОТА — исполнители идут через свой профильный контекст; акты пишутся в ленту вещдоков
     docs/sprint/trail/<windowId>.jsonl   (append-only, четыре рода следа)

4. ГЕЙТ — Ангелина проверяет, что ответственность реальна
     yarn sprint:gate --plan <план> --traces <лента>
   код 0 — да · 1 — нет · 2 — проверка НЕ состоялась (это разные вещи)

5. ОПЫТ — сопоставление предсказания с исходом, два автора и две метрики
     yarn sprint:experience --record <прогон>
```

## Что проверяет нарезка — шесть findings, список закрыт

`cut_shape` · `block_oversized` · `performer_unnamed` · `context_unnamed` · `zones_overlap` ·
`plan_unratified`. Седьмая — «резчик ≠ исполнитель» (`cutBy` = `persona`) — разрешена владельцем
как **находка, а не запрет**: бывают зоны, где тимлид единственный профильный контекст.

**Мерка компактности не изобретается.** Порог — `OVERSIZED_CHANGED_LINES` из
`scripts/lib/day-work-diff.mjs`, тот самый, которым ревью печатает «oversized» задним числом.
Единица — изменённые строки (`insertions + deletions`), не файлы и не коммиты.

**Порог применяется к ПРОХОДУ ревью, а не к блоку** (ратификация владельца 30.07). Блок,
вводящий алфавит, легально едет N проходами по названным швам — при **всех четырёх** условиях:

1. вводит закрытый алфавит, от которого зависят соседи;
2. DoD требует фикстуру на каждый его элемент;
3. швы названы в плане **до** работы, каждый проход по прогнозу ≤ порога;
4. число проходов ратифицировано тем же актом.

Три из четырёх права не дают. «Блок оказался большим» и «тут много тестов» — не основания.

## Что проверяет гейт — четыре рода следа, список закрыт

`contract_signature` ≺ `session_prep` ≺ `context_run` ≺ `review_pass`. Закрыт **по построению**:
у окна работы четыре момента, в каждом ровно один акт, который исполнитель не может произвести,
не будучи им. Род вне списка → код `2`, вердиктов нет: открытый список означает обход гейта
новым словом.

Семь вердиктов: `honest_pair` · `refused_with_reason` · `plan_lied` · `wrong_performer` ·
`stale_trace` · `unresolvable_ref` · `no_corpus`.

- **«Протух» — относительно ревизии предмета, не календаря**: `at(след) < revisionAt(блок)`.
  Календарного TTL нет намеренно.
- **Пустой корпус → «КОРПУСА НЕТ»**, никогда «нарушений 0» (ратифицированный вердикт M5).
- Нет `window`/`revisionAt` в плане → **ошибка входа**, а не «всё свежее».

## Вторая дверь — четыре причины, список закрыт

Режим `membrana-flow` («персональной ответственности нет») требует причину из четырёх:
`mechanical` · `no_profile_owner` · `owner_solo` · `urgent_recovery`.

**«Разведка/прототип» отвергнута сознательно** — формулировка эластична, разведкой можно назвать
почти всё. Пятая причина требует нового слова владельца. Молчание режимом не является: план без
`mode` читается как `explicit-honest`, и пустая персона там — находка.

## Петля опыта — два автора, две разные метрики

| Автор | Что предсказывает | Сигнал |
|---|---|---|
| Тимлид | нарезку | **бинарен**: проход влез в порог либо переполнился |
| Ангелина | остановки | **не бинарен**: доля ложных остановок (полезна ⟺ после неё что-то изменилось) |

Род записи `forecast` защищён **двумя моментами времени в одной записи** (`predictedAt <
observedAt`) и deep-freeze поля `predicted`: править предсказание, увидев исход, невозможно
механически. Отбор 5–7 лучших прогонов **только номинирует** — в канон пишет человек по слову
владельца. Порога допуска пока нет: число до первого измерения — изобретение, а не мерка.

## Жёсткие правила

- **Только предикаты.** Вердикт из закрытого списка, finding с именем (`toothId`), отказ —
  легальным «нет с причиной», не пустым полем. «Стараться» не существует.
- **Ничего не выдумывать за владельца.** Значение, которого он не называл, — `//provisional`.
- **Перерезка в работе = новая версия плана и новая ратификация.** Правка на месте есть перенос
  согласия на изменённый контракт (запрет M2) и стирает прежний прогноз, лишая петлю предмета.
- **Переполнение в работе — управленческое решение**, названное явно и со своими рекомендациями.
  Тихая перерезка запрещена.
- Идентификатор персоны — `id` из `docs/virtual-team/voices.registry.json`. Не имя человека, не
  модель, не `Co-Authored-By` (одинаков у всех агентов — различающей силы ноль).

## Чего механизм ПОКА не умеет — говорить об этом прямо

Из четырёх родов следа **два не имеют носителя**: `contract_signature` ждёт серверных вызовов
исполнителя, `session_prep` не привязан к блоку. Не построены также привязка сегментов ревью к
блоку (N1) и журнал остановок ведущей (N2).

Следствие: метрики честно отдают `defined:false` с причиной (`no-attribution`,
`no-stops-recorded`, `no-lead-appointed`), и **ни один процент не печатается**. Как диагноз контур
работает; как лечение — частично. Выдавать это за полноту запрещено.

## Команды

| Команда | Что делает |
|---|---|
| `yarn sprint:cut --plan <p>` | вердикт по плану нарезки |
| `yarn sprint:cut --plan <p> --ratify --at <ISO>` | отметка ратификации от имени владельца, по его явному слову |
| `yarn sprint:gate --plan <p> --traces <лента>` | вердикт исполнения по каждому блоку |
| `yarn sprint:experience --record <прогон>` | запись рода «предсказание ↔ исход» + обе метрики |
| `yarn sprint:gate --help` | список стабов и фикстур (прогон без живых данных) |
