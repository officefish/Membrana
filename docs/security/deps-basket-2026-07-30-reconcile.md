## Чем закрывалось

Все правки — записи `resolutions` в корневом `package.json`. Так вышло не из удобства:
**7 из 10 пакетов корзины не объявлены ни в одном `package.json` воркспейсов** — они
транзитивные, и поднять их иначе нечем.

Грабля, стоившая трёх заходов: `resolutions` ключуются по **запрошенному дескриптору**,
а не по разрешённой версии. Запись `postcss@npm:8.5.14` действует только если кто-то
просит ровно `8.5.14`; для `tailwindcss` нужен ключ `postcss@npm:^8.4.47`. Первые два
захода били в пустоту и выглядели как «патча нет».

| пакет | было → стало | ключ resolution |
|---|---|---|
| `tar` | 7.5.15 → 7.5.20 | `tar@npm:^7.5.4`, `tar@npm:7.5.15` |
| `path-to-regexp` | 0.1.12 → 0.1.13 | `path-to-regexp@npm:0.1.12` |
| `postcss` | 8.5.14 → 8.5.25 | `postcss@npm:^8.4.47`, `postcss@npm:8.5.14` |
| `js-yaml` | 3.14.2 → 3.15.0 · 4.1.1 → 4.3.0 · 5.2.1 → 5.2.2 | `^3.13.1`, `^4.1.0`, `4.1.1`, `5.2.1` |
| `minimatch` | 3.0.8 → 3.1.5 | `minimatch@npm:~3.0.3` |
| `brace-expansion` | 1.1.14 → 1.1.17 · 2.1.0/2.1.1 → 2.1.3 · 5.0.6 → 5.0.8 | `^1.1.7`, `^2.0.1`, `^2.0.2`, `^5.0.5` |

## Где карточка описывала мир неверно

**Critical `tar` живёт не там, где заявлено.** Карточка: «Пути распаковки живые: деплой
office (tgz), ingest архивариуса, сборки studio». Проверка: `node-tar` не импортируется
**ни в одном** файле `packages/background-office/src`, `packages/background-media/src`,
`apps/membrana-studio/src`. В дерево он приходил двумя путями — `node-gyp` (компиляция
нативных модулей) и `@mintlify/previewing` (предпросмотр документации). Деплой-скрипты
(`_ssh-office-prod-up.mjs` и соседи) зовут **системный `tar`** по ssh — другой бинарь,
этой advisory не затронутый. Уязвимость была настоящей, но её поверхность — сборка и
docs-тулинг, не прод-рантайм.

**Разрез «рантайм-прод» у дозора шире, чем название.** Дозор отнёс к рантайм-проду
`adm-zip`, `axios`, `sharp` — все три приходят из `@mintlify/*`, то есть из инструмента
документации. Туда же `lodash` и `minimatch` (из `@microsoft/api-extractor`),
`app-builder-lib` и `builder-util-runtime` (из `electron-builder`). По духу регламента
это dev-тулинг, который сам же регламент отправляет в плановый апгрейд-спринт, а не в
корзину «СРАЗУ». Похоже, разрез считается по присутствию в дереве, а не по природе
зависимого — это заявка на правку самого `deps:watch`, здесь не делалась.

## Оставшиеся 10 — с причинами

**Наши прямые, требуют мажора (2):**

- `@fastify/static` 8.3.0, патч только в `>10.1.0`. Мажор 8→10 тянет Fastify v5, а
  `fastify` прижат `resolutions` к `4.29.1`. Поднимать — отдельная работа по миграции
  Fastify, не патч. Носители: `background-media`, `background-office`.
- `music-metadata` 10.9.1, патч только в `>11.12.1`. Линия 11 — ESM-only, а NestJS-сборка
  `background-media` идёт в CJS. Требует проверки сборки, не одной строки.

**Рантайм-транзитивные, патча в своей линии нет (2):**

- `find-my-way` 9.6.0 — уязвимо `<=9.6.0`, то есть вся линия 9; приходит из
  `@nestjs/platform-fastify`. Поднять можно только вместе с NestJS-стеком.
- `brace-expansion` 1.1.17 и 2.1.3 — **это последние версии своих линий**, и обе всё ещё
  в уязвимом диапазоне. Патча не существует; закрыта только линия 5 (5.0.8). Носители —
  `minimatch@3.1.5` и `minimatch@9.0.9`.

**Dev-тулинг — в плановый апгрейд-спринт, не «СРАЗУ» (6):**

- `adm-zip` 0.5.16, `axios` 1.16.1, `sharp` 0.33.5 — из `@mintlify/*` (документация);
- `lodash` 4.17.23 — из `@microsoft/api-extractor`;
- `app-builder-lib` 25.1.8, `builder-util-runtime` 9.2.10 — из `electron-builder`.

Каждый требует мажора своего носителя (`electron-builder` 25→26, mintlify-стек целиком) —
это апгрейд инструмента, а не заплатка. **Строка для апгрейд-спринта:** три носителя —
`@mintlify/*`, `@microsoft/api-extractor`, `electron-builder`; шесть advisories.
