# Консилиум: память персоны от исполнения, не от реплики

**Повестка:** что попадает в журнал персоны из спринта (акт · результат · след), чем запись-исполнение отличается по форме от записи-позиции, что делает память осмысленной для следующего дня; при том что код пишут СЕССИИ — что достаётся журналу ПЕРСОНЫ, если персона держала контракт. Предмет — формат спринта, не код. M1–M6 вход. Вопросы 7 и 9 не решать.

[Верстальщик]: С витрины капитана журнал сегодня — одна и та же карточка: «позиция · комната» + цитата. Это лента сказанного. Требую в формате спринта **два рода карточек**, читаемых без легенды: `позиция` и `исполнение`. Пустота исполнения видна: `acts: none`, не прочерк.

[Музыкант]: На слух это mono-take мнений. Реплика консилиума — count-in и разметка партий; take исполнения — то, что село на ленту. M1 уже развёл assigned и participated: участвовал = след на ленте. Память персоны от исполнения — не «кто в титрах», а **что осталось после take**: акт (что держали), результат (accept/reject/partial), след (адресуемый артефакт). Иначе вся шина memory/archive обслуживает репетицию, не концерт.

[Математик]: Формализую без UI. Пусть журнал персоны p — лента записей E. Сейчас ∀e тип(e)=position. Вводим род `execution`. Минимальный кортеж: `ExecRecord = (sprintId, personaId, act, result, evidenceRefs[])`. Предикат допуска в журнал исполнения: `admit(e) ⇔ holdsContract(personaId, sprintId) ∧ evidenceRefs ≠ ∅ ∧ result ∈ Result`. Пустая evidence при holdsContract — не запись, а дефект закрытия (связь с M1: participated без следа запрещён). Позиция и execution — **разные типы**, не синонимы с разными заголовками.

[Архитектор]: Конструкция: архив и проекция C2 уже богаты (бюджет, pinned, eviction) — менять **предмет**, не обвязку. Граница: запись-позиция живёт от комнаты/консилиума; запись-исполнение — от **закрытия спринта**, где persona = contract holder (не author каждого diff). Сессия — транспорт исполнения, не субъект журнала персоны. Форма решения: один schema-род `execution` в том же jsonl-архиве; provenance указывает sprintId + evidence, не reply-id сеанса. Вопросы 7 и 9 не трогаем.

[Структурщик]: Леммы, иначе снова синонимы. **Позиция** — словарная статья «что персона утверждала в комнате» (уже есть). **Акт** — именованное обязательство контракта в спринте (не diff и не «работал»). **Результат** — закрытый исход акта относительно DoD/приёмки. **След** — адресуемый указатель на артефакт (path, SHA, id карточки, id PR) — не цитата. **Запись-исполнение** — тройка акт·результат·след(+и) + sprintId + personaId. Home тот же `archive/<persona>.jsonl`, дискриминатор рода обязателен. Сессия в лемму персоны не входит.

[Teamlead]: Планка матча узкая: формат спринта отдаёт в журнал персоны **исполнение**, не ещё одну цитату. M1: исполнитель честный = assignment + participation со следом. Здесь следующий шаг — **что именно** из участия оседает в памяти, чтобы завтра был не «мы говорили», а «мы закрыли / срезали / оставили хвост». Связка в комнате: Математик — кортеж и предикаты; Структурщик — леммы; Архитектор — граница session≠persona; Верстальщик — два рода без фальши; Музыкант — take vs count-in. Код не пишем. 7 и 9 — вне стола.

[Верстальщик]: Для следующего дня карточка исполнения должна отвечать на три взгляда капитана за секунду: *что держали* · *чем кончилось* · *куда ткнуть*. Итог `accepted | rejected | partial | blocked` — бейдж, не абзац. След — одна-две ссылки, не простыня лога сессии. Если акт был, а результата нет — витрина `result: missing` (фальшь «тихо ок» запрещена, как в M1 пустой participated).

[Музыкант]: Слышу риск клиппинга: сессия наговорит в PR description роман — и это запихнут в «акт». Нет. Акт — короткая партия из контракта («держать API пакета X», «не пустить цикл Y»). Результат — after-listen: село / не село / село с оговоркой. След — master-tape (файл, тест, merge), не outtakes чата. Память осмысленна завтра, только если из неё можно **продолжить партитуру**, а не переслушать болтовню.

[Математик]: Осмысленность для дня t+1: функция `recall(p, t+1)` должна менять действие, не только тон. Критерий: ∃ запрос q вида «какой контракт p незакрыт / какой result=partial / какой evidence устарел», и answer(q) вычислим из ExecRecord без NLP по цитатам. Инвариант: `position` ⇏ `execution`. Связь M1: `participated(S,p) ⇒ ∃ ExecRecord(S,p)` при закрытии — иначе ложь участия. Обратное: ExecRecord ⇒ holdsContract (персона не копит чужие take).

(B) Только status спринта в registry — нет субъектного среза по persona. (C) **Выбранная:** при закрытии спринта эмит `execution`-записей **по одному на акт контракта**, holder = persona из assignment/contract, evidence из machine-trace закрытия. Объём мал, тип однороден внутри рода, C2/бюджет работают как сейчас. Session id — в provenance как transport, не как author записи.

[Структурщик]: Словарь закрытия спринта (формат, не код): поля минимум `kind: execution` · `sprintId` · `personaId` · `actId` | `act` · `result` · `evidence[]` · `closedAt` · `contractRef`. Запрещённые синонимы: «summary», «notes», «agent log», «цитата реплики» в теле execution. `evidence` — список ref с типом `{path|sha|pr|card|artifact}`, не free text. ## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| Что попадает в журнал из спринта | Записи рода **`execution`**: на каждый **акт контракта** holder-персоны — **акт** (стабильный actId/лемма) · **результат** (enum) · **след** (`evidence[]` refs) + `sprintId`, `personaId`, `contractRef`, `closedAt`; при residual — хвост |
| Алфавит `result` | `accepted` · `partial` · `rejected` · `blocked` · `deferred` · `waived` (waived — не отдельный kind) |
| Отличие от записи-позиции | **Разный `kind` и разные поля.** Position: room + thesis + sourceReplyRef (журнал сказанного). Execution: sprint + act + result + evidence (журнал сделанного/честно несделанного). Не флаг на position, не цитата реплики, не session summary |
| Осмысленность для следующего дня | `recall` отвечает на незакрытое/хвосты/blocked без NLP: partial·deferred·blocked (+ residual) ведут план t+1; accepted подтверждает честное participation (M1) и «что уже в миксе» |
| Код пишут сессии — что достаётся персоне | Persona = **contract holder**, не author diff. Сессия = **transport** (опц. в provenance). Журналу персоны — **квитанции актов** при close, не лог сессии и не «персональной ответственности нет» (это путь membrana-flow, вне этого стола) |
| Когда эмитить | **Обязательный** эмит на **закрытии спринта**: totality — ∀ акт holder’а ровно одна ExecRecord (или явный waived) |
| Evidence | Адресуемые ref (`path` / `sha` / `pr` / `card` / `artifact` / decision id). accepted/partial/rejected **без** evidence — невалидны; blocked/deferred — decision/residual ref |
| Архитектура памяти O/C2/archive | **Не ломаем**: тот же jsonl + проекция с бюджетом; меняется **предмет** (дискриминатор kind), не трубы |
| Вне стола | Вопросы **7 и 9** не решались; код/схема/extract-pipeline — follow-up; M1–M6 не переоткрывались (M1 — вход: execution нормализует след participation) |

**Definition of Done (канон формата спринта, не код продукта):**

1. В каноне sprint-close зафиксированы леммы `ExecRecord`, алфавит `result`, предикаты admit + totality.
2. Close без map(acts→ExecRecord) для holder’ов — **не** считается честным закрытием (матч не сыгран).
3. Проекция `memory/<persona>.md` различает заголовки `позиция · …` и `исполнение · <sprintId>` без легенды.
