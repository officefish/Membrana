# Консилиум: скаляры S0 vs релиз матрицы тарифов (спринт Б)

**Повестка:** матрица в strategic-docs (T13–T16, шторм 08.09) — единственный источник правды; `docs/tariffs/tariff-grid.json` — производная с зубом «сетка ↔ релиз». Сегодня числа ещё живут в `docs/tariffs/tariff-scalars.json` (S0, 29.07: «единственный источник этих чисел»), сид `prisma/tariff-scalars.mjs` их читает, зуб `tariff:grid` сверяет сетку со скалярами (`scalarsCrossFindings`). Линейка владельца T1 расходится со скалярами (буфер датчика 512 МБ vs 1024; старшие тарифы `null`). Пересев базы/приборов — задание В, не этот спринт. Вопрос: (а) сделать скаляры второй производной релиза сейчас; (б) оставить скалярами декларацию сида до В, зуб → «сетка ↔ релиз», расхождение «скаляры ↔ релиз» — явный не-красный список; (в) иное. Критерии: один дом чисел; граница спринта Б (матрица+сетка); честность зубов; сид не молчит о расхождении с релизом.

[Верстальщик]: С витрины тарифов оператор читает числа из кабинета/сида, а не из strategic-docs. Если сид молча посадит 1024, а матрица владельца говорит 512 — на экране будет ложь без красной лампы. [Математик]: Формализую три множества. R — числа релиза/матрицы; G — `tariff-grid.json`; S — `tariff-scalars.json`; DB — то, что сид пишет в базу. Инвариант шторма: R = SSOT, G = f(R). Сегодня фактически S играет роль SSOT для сида, зуб проверяет G↔S, а не G↔R. Расхождение T1: ∃k: S(k)≠R(k) (512 vs 1024; null на старших). Вариант (а): S:=g(R) ⇒ при следующем seed DB:=S' — это смена DB без задания В. Вариант (б): G↔R красный; S↔R — отчёт, не fail. Численно (б) сохраняет границу спринта и убирает ложный инвариант G≡S.

[Музыкант]: С края тракта: прибор и кабинет «звучат» тем, что посеяно, а не тем, что написано в strategic-docs. Если мы подменим партитуру сида под релиз, но не пересеем живые узлы — получим рассинхрон оркестра: одни мембраны на старых квотах, доки на новых. Это хуже явного диссонанса. Лучше оставить сид на старой теме до партии В и вынести диссонанс S↔R в слышимый (не аварийный) список.

[Teamlead]: Положение: спринт Б — матрица и сетка; пересев — В. (а) маскирует пересев под «прическу файлов» — нагрузка В утекает в Б без приёмки. (б) держит границу и честность зуба. Планка: зуб краснеет только на предмете спринта (G↔R). Расхождение сида с релизом — не зелёный матч, а объявленный долг до В. Вердикт-направление: брать (б), не (а). Связка: Архитектор — форма домов; Структурщик — зуб/импорты; Математик — предикаты сверки.

[Структурщик]: Словарь. «Источник правды» ≠ «вход сида» ≠ «производная сетка». S0 назвал S «единственным источником чисел» — это устаревшая лемма относительно T13–T16. Публичный контракт сейчас: R владеет смыслом; G — артефакт релиза; S — декларация посева epoch-S0 до задания В. Зуб `tariff:grid`, который делает `scalarsCrossFindings` как красный G↔S, проверяет не тот предмет — нарушена норма «проверка с предметом». Цена (а): S становится производной R ⇒ следующий прогон сида меняет DB — это пересев без контура В, граница спринта лжёт. [Верстальщик]: Тогда в UI/доках кабинета не писать «числа из tariff-scalars как канон». Если где-то в подсказках тарифа торчит S0-формулировка — это уже враньё витрины. ## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| (а) Сделать скаляры второй производной релиза уже в спринте Б? | **Нет.** Это контрабанда пересева (сид на следующем прогоне меняет DB) — территория задания В. |
| (б) Оставить S декларацией сида до В; зуб «сетка ↔ релиз»; S↔R явным не-красным списком? | **Да — как база.** |
| (в) Иное? | **Не отдельная ветка:** принять **(б) усиленный** четырьмя рёбрами ниже. |
| Единый источник правды | **Релиз/матрица R (strategic-docs, T13–T16).** S **не** SSOT. |
| Статус `tariff-scalars.json` | **Frozen seed-epoch (S0)** до задания В: вход сида, не дом канона. Шапка файла + supersede формулировки S0 29.07. |
| `tariff-grid.json` | Производная f(R); единственный red-предмет зуба: **G ↔ R**. |
| Зуб `tariff:grid` | Red gate **только** G↔R. `scalarsCrossFindings` → **обязательный non-red report** S↔R в основном stdout (не debug). Не silent. |
| Сид `prisma/tariff-scalars.mjs` | По-прежнему читает **S**; **не** импортирует R в спринте Б. |
| Расхождение T1 (512 vs 1024, null на старших) | Живёт в findings-списке до пересева В; **не** краснеет CI Б. |
| Задание В (после) | Пересев DB/приборов; тогда S := derive(R) или сид читает R напрямую — отдельная карточка, не Б. |

**Definition of Done (спринт Б):**
1. Матрица релиза зафиксирована как SSOT; в доке/шапке S явно: `seed-epoch, not SSOT; reseed = task B`; лемма S0 supersede’d.
2. Пересев сетки: G генерируется из R; зуб `tariff:grid` **fail** при G≠proj(R).
3. Зуб **не fail** из-за S≠R; печатает полный список drift (path, S, R), включая буфер 1024→512 и null старших.
4. Сид не переведён на R; DB/приборы не пересеваются в этом PR/спринте.
5. Нет новых презентационных чтений S как «канона тарифа».
6. PR, который «заодно» делает S=derive(R) или red на S↔R — **BLOCK** (граница Б/В).
