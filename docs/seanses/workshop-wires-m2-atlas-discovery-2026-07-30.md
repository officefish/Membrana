## Итоговое решение консилиума

### Посылки (обязательный список)

1. Атлас — **производный** индекс: агрегирует, не хранит собственных описаний SoT (`docs/tooling-atlas/README.md`, канон plane=meta).
2. Контракт **M1** не пересматривается: неймспейс = запись `docs/namespaces/REGISTRY.json` (holder + membership); `belongs → home | namespace | orphan`; дом побеждает; «не строка ATLAS» = не SoT в ATLAS.
3. Правило спутника **M8** не пересматривается (вне механизма обнаружения дома).
4. Факт кода: discover сегодня = только `workshop.manifest.json` (`scripts/lib/tooling-atlas.mjs`); README — post-hoc выжимка, не discover.
5. Факт замера: 12 workshop-строк · 45 README · 33 дома без манифеста; `docs/network` — вещдок ложной невидимости.
6. Шапка `ATLAS.md` объявляет source README+manifest — **не согласована** с кодом.
7. T9 владельца: дом и неймспейс обязаны **находиться** общим справочником (атласом) и **через инструменты** справочника — исполнить механикой, не оспорить молчанием.
8. Запрет повестки: не штамповать 33 манифеста «за компанию»; не решать, кто станет мастерской; не подменять содержание домов.
9. Одна истина членства: справочник не становится вторым SoT `belongs`/membership.
10. Производность: ручная запись в ATLAS как источник истины — запрещена исходом.

### Вердикт

| Вопрос | Решение |
|--------|---------|
| **1. Признак обнаружения контейнера** | **Разделить дом и мастерскую.** `D_home(c) ⇔ ∃ README.md в c ∧ path(c) ⊨ RootPolicy` (политика корней — явный набор path-паттернов в lib атласа; минимум: прямые `docs/*` с README и паттерны, покрывающие де-факто дома вроде `docs/procedures/*`, `docs/seanses/night-hunt`, … — так, чтобы **`docs/network` ∈ D_home**). `D_workshop(c) ⇔ D_home(c) ∧ ∃ workshop.manifest.json`. Манифест **не** паспорт дома; не заводим 33 манифеста. 33 невидимки → видны как **home** после расширения derive. |
| **2. Честность шапки** | **Лгут согласованность текста и кода; чинить оба.** Код **неполон** относительно канона «агрегирует каждый контейнер» и относительно T9. Шапка **нечестна**, называя README источником *обнаружения*. Канон Source: (a) RootPolicy+README → home; (b) `workshop.manifest.json` → workshop-поля; (c) `REGISTRY.json` → проекция ns; README дополнительно = выжимка title/абзац, не discover. |

## Что комната обязана решить

1. **Признак обнаружения** — по чему справочник узнаёт контейнер: только манифест мастерской,
   объединение с признаком контейнера (README и/или свои скрипты), или иной проверяемый
   признак. Ответ обязан объяснить, что делать с 33 сегодняшними невидимками.
2. **Честность шапки** — сегодня `ATLAS.md` называет источником README, а код его источником
   не считает. Либо шапка лжёт, либо код неполон; вердикт называет, что именно.
3. **Место неймспейса** — как реестр неймспейсов относится к справочнику: источник для него,
   отдельная плоскость индекса, или что-то третье. T9 требует находимости **инструментами
   справочника** — вердикт обязан сказать, каким глаголом неймспейс находится.
4. **Статус «контейнер без мастерской»** — это дефект, законное состояние или третий вид
   записи. От ответа зависит, что покажет прибор и на что покраснеет зуб.
5. **Дрейф** — чем ловится расхождение справочника с деревом, если признак обнаружения
   расширится: `--check` существует, но проверяет производное против манифестов.

## Основания, которые заседание считает весомыми

- **производность** — справочник агрегирует, а не хранит; решение, требующее ручной записи в
  индекс, противоречит его собственному канону;
- **невидимка как вещдок** — правило проверяется на `docs/network` и остальных 32, а не на
  удобном примере;
- **исполнимость T9** — тезис владельца либо исполняется механикой, либо честно объявляется
  исполняемым иначе; молчание — не ответ;
- **одна истина** — контракт M1 запретил второй источник истины членства; справочник не должен
