[Математик]: Пункт (4) — численно однозначен. `expiresAt = frozenAt + retentionDays` как снимок в партии даёт инвариант: уборка = предикат `now >= expiresAt`, без гонок на «пользователь сменил срок между freeze и cron». Чтение срока при уборке = скрытое изменение контракта задним числом. Принимаю только снимок.

[Teamlead]: Владелец 05.10 уже зафиксировал режимы, ручную разморозку, per-user срок, v1 = только буфер. Наша работа — не переоткрыть политику, а закрыть шесть вердиктов и выпустить ADR-0031. Планка: пункт без вердикта = протокол недействителен. Связка: Веснин форма → Ожегов пакеты → Дынин чистые функции отбора → Родченко UI подтверждения → Курёхин стык media/потока артефактов.

[Верстальщик]: Для пользователя понижение — не «тихий resize квоты», а явный акт: предпросмотр избытка → режим отбора → подтверждение. Без confirmed preview кнопка «Понизить» disabled или ведёт только в модалку. Состояния media-down mid-flow: `alert-warning`, не silent partial success. Срок хранения — выпадающий список в office, в кабинете мембрана read-only отображает текущий срок, без правки пользователем в v1 (если owner так решил — срок в office).

[Архитектор]: Пункт (1). Канон M5 «Понижение ничего не разрушает» (tariff-transition.ts:18) и «Retain» — про запрет **немедленного уничтожения** при downgrade. Заморозка избытка + удаление только по `expiresAt` — **не разрушение в момент перехода**, а отложенная политика хранения. Исключение формулирую так: *M5 Retain сохраняется для живой квоты; явное подтверждённое понижение переводит избыток в cold-archive с TTL; физическое удаление — только scheduler по снимку expiresAt, не side-effect смены тарифа.* Принять исключение с этой формулировкой.

[Структурщик]: Пункт (2). Пометка статуса на `Sample` смешивает словари «живая проба» и «архивная партия», ломает существующие запросы и индексы квоты. `ArchiveBatch` + `ArchivedSample` (файлы на месте, sampleId-ссылка, batch несёт `frozenAt`/`expiresAt`/mode) — отдельная лемма, слабая связанность с chart-list. Живые запросы Sample не трогаем. Вердикт: отдельные таблицы.

[Музыкант]: С стороны потока артефактов: v1 морозит только буфер — правильно, library/collections не трогаем без отдельного контракта. Разморозка рукой = обратный transfer batch→buffer с проверкой квоты на момент thaw. Media остаётся единственным владельцем байт на диске; кабинет не пишет в FS.

[Математик]: Пункт (6). Режимы chart-list считают **штуки**; квота — **байты**. Нужна чистая функция:  
`selectKeepWithinBytes(candidates, budgetBytes, modeOrder) → { keep, freeze }`.  
Правило tie-break при равенстве приоритета режима: (1) раньше по времени (older first to freeze / newer keep — фиксируем: **оставляем более новые**, морозим старые при прочих равных), (2) `sampleId` asc как стабильный ключ. Неизмеримые (`size == null`) — **после** измеренных в очереди на keep (сначала гарантируем измеренный fit). Размеченные и флаг «хранить» — **первыми в keep**. Детерминизм + unit-тесты без Nest.

[Teamlead]: Согласен с Дыниным по (6): модуль в `plugin-handlers` (или shared pure под media), не в JSX. BLOCK любому PR, где байтовый отбор размазан по UI. Пункт (5) — жёсткий порядок транзакции на стороне кабинета: (a) предпросмотр+confirm, (b) вызов freeze в media, (c) commit тарифа, (d) рассылка лимитов. Если (b) падает — **тариф не меняем**. Отказ понижения при избытке без confirmed preview — да, продуктовый инвариант.

[Верстальщик]: Три режима журнальной витрины уже есть — байтовый слой не рисуем четвёртой «вкладкой», а показываем в модалке понижения: «будет оставлено N / заморожено M, ≈ X МБ». `tabular-nums`, progress по байтам к новой квоте. a11y: `aria-live` на итог предпросмотра, confirm — отдельная primary с явным текстом последствий TTL.

[Архитектор]: Пункт (3). Служебная дверь cabinet←office по образцу `cabinet-register` #2393: `CABINET_OFFICE_TOKEN`, не user-JWT. Граница: office **не** становится admin-API кабинета для произвольных мутаций. Допустимо: `GET` список пользователей мембраны (минимум полей) + `PUT` retentionDays на мембрану. Минимум полей: `userId`, `displayLabel?`, `tariffPlanId`, `retentionDays`, `createdAt` — **без** email/phone/секретов/паролей, без проб и без media-URL. Расширение двери — только новым ADR.

[Структурщик]: Контракт двери — отдельный controller/guard в cabinet, mirror pattern register. Office ходит HTTP+token; cron уборки живёт в **office** `@Cron` (как ведущая свела): выключатель + dry-run «только показать». Media экспонирует: create batch freeze, list expired by expiresAt, purge batch, thaw. Кабинет при freeze **передаёт** `retentionDays` в media — media не читает office.

[Музыкант]: Если media недоступна посреди понижения — не оставляем «тариф уже Free, а байты ещё Pro-буфер». Либо compensating rollback тарифа (если успели), либо лучше **two-phase**: pending-downgrade до ack freeze. Для v1 проще: freeze first, tariff second; на ошибке freeze — abort, UI error. Partial batch (часть sample ушла, часть нет) — batch в статусе `failed/partial`, тариф не коммитить, оператору/логам явный id партии.

[Математик]: Уточнение tie-break: «оставить, пока хватает байт» = knapsack-greedy по приоритету keep-score. Keep-score высокий → в живой набор. Порядок заполнения keep: (размеченные ∪ «хранить») → по mode-order штук → среди равных **newer `createdAt` first** → `sampleId` desc/asc стабильно (фиксируем **asc** для freeze-очереди inverse). Неизмеримые: не занимают байты в сумме (или считаются 0) — иначе квота врёт; политика: **неизмеримые не держат байтовый бюджет**, после keep измеренных либо freeze all unknown, либо keep unknown only if residual policy — рекомендую **freeze unknown after measured keep**, чтобы не взорвать диск.

[Teamlead]: Дынин, unknown = freeze-after-measured-keep — принимаю для v1 (предсказуемость квоты). Пункт (1) — принимаем исключение Веснина; в ADR-0031 и правка канона M5 одной строкой-исключением со ссылкой на ADR. Без «тихого» edit transition.ts в обход ADR.

[Музыкант]: Playback/DSP: замороженные пробы **не** в live library path; engine не должен пытаться decode absent-from-active. Thaw возвращает в buffer path — тот же decode pipeline. Для v1 достаточно hide-from-active queries; файлы на месте = zero-copy freeze, только metadata move — дешёво по I/O.
