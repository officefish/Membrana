| **Отношение** | **Сосуществование слоями**, не взаимоисключение и не «третий гибрид в одном механизме». |
| **Слой A — оптовый** | Хук-пол §6: единая проекция → всем холодным сессиям одинаково. Объект: мастерские, входные глаголы, схема min-callable, doc-ref, отчёт L1. Home: генератор/проекция. Никто не «заслуживает» строку — попал в проекцию → в пол. |
| **Слой B — поштучный** | Метод #1467: один инструмент — один разбор — один провод. Объект: `wire(t)` (стык, парковка, bind callable, разбор cold-start). |

| **Судьба метода прецедентов** | **Жив и обязателен для слоя B.** «Нет прецедента — нет заявки» → нет заявки на **`wire(t)`**. На появление строки пола прецедент не нужен (пол из проекции). Прецедент по-прежнему показывает **КУДА** проводить вглубь. |

| **Словарь M9** | `floor` · `wire(t)` · `precedent(t)` · `ticket(t)⇔precedent(t)` для B · `mode(u)∈{A,B}` |

**Definition of Done (для последующих задач, не скоуп M9-вердикта):**
- В брифах/депо не использовать слово «навигация» одновременно для floor и wire без уточнения слоя.
- Тикеты на инструмент требуют ссылку на cold-start прецедент (или явный owner override).
- Генератор пола не принимает списки bulk-wire; wire-PR не меняет схему выдачи хука.

# M9 — оптовое против поштучного (заседание `workshop-wires`)

**R9 —** Как соотносятся хук-пол, выдаваемый **всем сессиям сразу**, и метод «один инструмент —
один разбор — один провод», названный владельцем в заявке #1467: сосуществуют слоями, или один
