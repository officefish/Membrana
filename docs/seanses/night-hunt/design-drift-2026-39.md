# Weekly-отчёт — `design-token-drift` — неделя 2026-39

## Находки

- **Нет прямого доступа к дереву `apps/client/src`** в этом прогоне: контекст ограничен `DESIGN.md` и excerpt из `ARCHITECTURE.md`. Отчёт построен на разрыве между декларацией токенов и типовыми Tailwind/DaisyUI паттернами; конкретные факты дрейфа подтверждаются чеклистом ниже.
- **Двойной источник цвета.** `DESIGN.md` фиксирует HEX-палитру через CSS-переменные (`--color-bg`, `--color-accent` и т.д.), но карточка детектора и все бейджи описаны в семантике DaisyUI (`badge-info`, `badge-warning`, `alert-warning`, `text-error`). Это две системы цвета одновременно — высокий риск, что `--color-accent (#7C3AED)` и DaisyUI-тема `accent` разошлись по значению.
- **Маппинг семейств детекторов на DaisyUI-цвета не закреплён в палитре.** `dsp→info`, `neural→accent`, `agentic→warning` — цвета `info`/`warning` в базовой палитре DESIGN.md **отсутствуют**, определены только в DaisyUI-теме. Токен для `info`/`warning`/`success` не задокументирован → дрейф гарантирован при смене темы.
- **Числовые токены заданы как «ориентир», а не как шкала.** Размеры шрифта `12/14/16/20/24`, радиусы `6/8`, отступы `16/24` описаны прозой. DaisyUI/Tailwind по умолчанию несут свою шкалу (`rounded-lg`=8, `rounded`=6 — совпадает случайно; `text-sm`=14, `text-xs`=12 — совпадает), но нет гарантии, что кастомная `tailwind.config` не переопределила эти значения.
- **Табличные цифры и focus-ring — «где доступно» / описательно.** `tabular-nums` и focus-ring `2px accent` не привязаны к утилити-классу или плагину, что делает их проверку невозможной автоматически.

## Риски

- **Расхождение accent-цвета (высокий).** Если DaisyUI-тема определяет `--p`/`accent` не равным `#7C3AED`, то progress/бейджи `neural` и кнопки фокуса визуально разъедутся с панелями на `--color-*`. Это ломает визуальный контракт без единой ошибки сборки.
- **Недокументированные семантические цвета (средний).** `info`/`warning`/`success`/`error` используются в device-capture и sample-labels, но не входят в «Базовую палитру» → изменение темы DaisyUI молча меняет статус-индикацию (a11y-критично: «не только цвет для статуса» смягчает, но не отменяет).
- **Дрейф радиусов/отступов через сырые классы (средний).** Прямое использование `rounded-xl`, `p-5`, `gap-3` (=12px, не кратно 8) в компонентах обходит правило сетки 8px без нарушения типов.
- **Анимации live-детекции (средний).** Регламент 400–500 ms + сглаживание легко нарушить, повесив `transition-all duration-150` на индикатор `isDrone` — токен-линтер этого не увидит.
- **Контраст `--color-text-muted (#9CA3AF)` на `--color-surface (#111827)` (низкий-средний).** Близко к границе WCAG AA для мелкого текста (`text-xs` в reasoning/latency) — требует ручной проверки на конкретном размере.

## Рекомендации

- **Ввести единый источник токенов.** Прописать палитру DESIGN.md как CSS-переменные в `tailwind.config`/DaisyUI-теме (`--p: #7C3AED` и т.д.), чтобы `--color-accent` и DaisyUI `accent` физически ссылались на одно значение. Убрать дублирование HEX↔семантика.
- **Задокументировать семантические цвета.** Добавить в «Базовую палитру» строки `--color-info/warning/success/error` с HEX и явным маппингом на DaisyUI, зафиксировать связку `dsp/neural/agentic → info/accent/warning`.
- **Добавить lint-проверку дрейфа** (eslint-plugin-tailwindcss / кастомное правило): запрет сырых HEX в className/style, whitelist радиусов (`6/8`), запрет отступов не кратных 4 (`p-5`, `gap-3`, `m-7`).
- **Прогнать чеклист ручной проверки** (ниже) по `apps/client/src` — при появлении доступа к файлам заменить им предположения этого отчёта.

### Чеклист ручной проверки (когда доступны файлы компонентов)

**Grep-паттерны:**
- Сырые HEX: `grep -rEn "#[0-9A-Fa-f]{3,6}" apps/client/src` → должно быть 0 вне определения токенов.
- Радиусы вне {6,8}: `grep -rEn "rounded-(sm|md|lg|xl|2xl|3xl|full)" apps/client/src` → сверить с 6/8px.
- Отступы не кратные 4: `grep -rEn "\b(p|m|gap|space)[xy]?-(1|3|5|7|9|11)\b" apps/client/src`.
- Длительности анимаций: `grep -rEn "duration-\d+" apps/client/src` → рабочие панели ≤300ms, live-блок 400–500ms.
- `transition` на индикаторе дрона: проверить, что `stableIsDrone`, а не сырой `isDrone`, привязан к анимации.

**Точечные проверки:**
- [ ] DaisyUI-тема: `--p` == `#7C3AED`, hover == `#6D28D9`; `--b1/--b2/--b3` соответствуют `bg/surface/border`.
- [ ] `tabular-nums` присутствует на confidence `NN %`, fundamentals «NN Гц», latency «NN ms».
- [ ] Focus-ring: `focus-visible` даёт видимое кольцо 2px на базе accent (не браузерный дефолт).
- [ ] Иконки-кнопки имеют `aria-label`; статус «дрон/не дрон» дублируется иконкой+текстом.
- [ ] `aria-live="polite"` навешен на **стабильный** статус, `aria-busy="true"` — на loading progress.
- [ ] `CaptureAlertToasts`: alert закрывается **вручную**, не автоскрытие.
- [ ] Контраст `text-muted` на `surface` для `text-xs` — прогнать через контраст-чекер (цель ≥ AA).
- [ ] Бейджи sample-labels и device-capture используют хелперы (`sampleLabelBadgeClass`, `resolveServerFirstBadgeDescriptors`), а не хардкод классов.
