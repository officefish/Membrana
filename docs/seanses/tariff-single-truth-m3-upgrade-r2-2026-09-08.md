## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| (а) Порядок событий | 1) Право: транзакция кабинета + строка `TariffChangeLog`. 2) Разноска: PATCH на сервер записей с лимитами + **версия контракта** (релиз, M1) + **порядок перехода** (`transitionOrder` = id/`TariffChangeLog`). 3) Приём: `syncMembraneContext` пишет лимиты на запись прибора при `version ≥ known ∧ order > known`. 4) «Прибор принял»: **событие перехода** на прибор (T7), не `/quota`. 5) Кабинет узнаёт «принял» по **сигналу состояния узла** (realtime), не по счётчику доставки разноски. |
| (а) Носитель «принял» | Событие перехода с версией **и** порядком. `/quota` — канал объёма/жизни; version в quota если появится — только диагностика, без права на переход. |
| (б) Удержание | Смена тарифа **не** снимает удержание. Выход только `release('human'\|'cleanup')`. Новой причины release нет. Окно оператора и плашка — **снимок старых чисел** эпизода (M2). Локальный страж до события держит snaphot; не пересчитывает свободно. |
| (в) Окно синхронизации | Интервал `[право в базе, лимиты+порядок на записи прибора + событие на приборе)`. Прибор **показывает** снимок удержания; **не считает** лимит; **не решает** отправку (решает сервер записей по записи). `/quota` после sync — новые лимиты. Витрина **права** — новый тариф; витрина **«принял»** — только сигнал прибора. Длительность — до успешного приёма и события; закрывают сервер записей (sync) + прибор (событие) + при отказе разноски — повтор. |
| (г) Отказ разноски | Откат права **запрещён**. Право ждёт; **повтор разноски** с тем же order (идемпотентно). |
| (г) Гонки доставки | Версия контракта порядок **не** защищает (принадлежит релизу).
