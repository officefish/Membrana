# Консилиум: K1 — гранула `disposition(path)`

**Повестка:** K1 — как детерминированно определяется `disposition(path)`: состояние файла/работы в общем рабочем пространстве, различающее `live` · `ready` · `unfinished` · `trash`, — так, чтобы `membrana-leveling` мог поимённо решить, что везти в `main`, что убирать, что регистрировать. Вердикт: чистая функция + граница детерминизм ↔ штамп тимлида (T8).

**Порядок реплик:** Музыкант → Верстальщик → Математик → Структурщик → Teamlead

[Музыкант]: Слышу задачу как маршрутизацию сигнала: каждый path — дорожка, disposition — гейт до микшера. Мне важно, чтобы `live` не глушился посередине сессии, а `trash` не попадал в master-шину. Не проектирую D2-гейт целиком — только классификатор. Предлагаю мыслить четырьмя взаимоисключающими полосами: live / ready / unfinished / trash, без «серого» пятого.

[Верстальщик]: С UI-стороны оператору нужна честная таблица: path → метка состояния, без метафор. `trash` — красный стоп, `unfinished` — янтарный «зарегистрировано, не трогать сносом», `ready` — зелёный «ждёт штампа/везём», `live` — пульс «не трогать». Конструктивизм: данные, не иконки «для души». Вердикт должен дать предикаты, которые я смогу показать в отчёте поимённо.

[Математик]: Чистая функция — мой контур. Сигнатура: `disposition(path, ctx) → {live|ready|unfinished|trash}`, где `ctx` — снимок наблюдаемых входов, без UI и без побочных эффектов. Порядок проверок обязан быть тотальным и детерминированным: одно path → ровно одно состояние. Приоритет ветвлений зафиксируем численно, не «на глаз».

[Структурщик]: Граница пакета: `disposition` живёт как чистый предикат в leveling-слое, не тянет Web Audio, не импортирует React, не читает сеть в рантайме классификации. Входы — факты FS/git/CI/реестра, поданные снаружи. Имена состояний — словарные леммы: одно слово — один смысл. Синонимы вроде «dirty-work» и «unfinished» в API не плодим.

[Teamlead]: Форма решения по K1: только гранула состояния, не D2/D3/D4 (это K4). Посылки T1–T13 и R2 не пересматриваем. Вердикт обязан развести детерминизм и штамп тимлида (T8): функция может сказать «кандидат в ready», но «везти в main» без штампа обоих — нельзя. Поехали по граням.

[Музыкант]: `live` для меня — открытая сессия правки: dirty-файл, который сейчас в активной работе. Признак активности не «мне кажется», а наблюдаемый: path в списке активной сессии агента/редактора **или** mtime внутри окна сессии при явном session-lock. Иначе любой только что тронутый файл станет live навечно — это шум, не сигнал.

[Верстальщик]: Согласен: `live` нельзя определять одним mtime без сессии — оператор не отличит «пишу сейчас» от «бросили вчера». В UI `live` пропускается гейтом визуально (R2): не в колонке «везти», не в «снести». Нужен явный вход `inActiveSession(path)` в ctx — булев факт от оркестратора сессии, не догадка вёрстки.

[Математик]: Фиксирую черновик приоритета (первый match wins):  
1) `isTrashPattern(path) ∧ ¬registered(path) ∧ dirty(path) → trash`  
2) `dirty(path) ∧ inActiveSession(path) → live`  
3) `readyPredicate(path) → ready`  
4) иначе если `isWorkPath(path) ∧ (dirty∨branchHasCommits) ∧ registered(path) → unfinished`  
5) fallback: если dirty ∧ ¬registered → trash; иначе не входит в домен leveling (вне функции / ignore).  
Уточним `ready` и регистрацию — без дыр.

[Структурщик]: Термины ctx, которые принимаю как словарь: `dirty(path)`, `registered(path)`, `inActiveSession(path)`, `ciGreen(path|unit)`, `conflictsMain(unit)`, `prApproved(unit)`, `leadStamp(unit)`, `isScratchPath(path)`, `isTempPath(path)`. `unit` — единица поставки (PR/ветка/карточка), к которой path привязан через регистрацию. Без регистрации path не может быть `ready` или легитимным `unfinished`.

[Teamlead]: Норма T8: `ready` по фактам = `CI_green ∧ ¬conflicts(main) ∧ PR_approved`, **и** штампуют оба (тимлид + вторая сторона по T8). Чистая `disposition` для ready-кандидата без штампа **не** должна врать, что путь «везём». Предлагаю развести: детерминированный предикат `readyFacts` и итог `ready` только при штампе — либо функция возвращает `unfinished` (легитимная ждалка), пока штампа нет. Это граница детерминизм ↔ суждение.

[Музыкант]: Если `readyFacts ∧ ¬leadStamp` кладём в `unfinished` — на слух правильно: работа не мусор, не live, просто не доехала до master. Гейт (K4, не здесь) потом читает disposition и отдельно смотрит штамп. Главное — не снести такую работу как trash. Риск ложного trash критичнее ложного unfinished: снесём живой материал.

[Верстальщик]: Тогда в таблице оператора четыре состояния остаются стабильными. Подпись для `unfinished` с `readyFacts=true` может быть презентационной («ждёт штампа»), но **значение disposition** — `unfinished`, пока нет штампа. Не плодим пятое состояние `ready_pending` в грануле K1 — это нарушит простоту и DESIGN-иерархию меток.

[Математик]: Уточняю `ready`:  
`readyFacts(unit) ⇔ ciGreen(unit) ∧ ¬conflictsMain(unit) ∧ prApproved(unit)`  
`disposition = ready ⇔ readyFacts(unit) ∧ leadStamp(unit) ∧ ¬inActiveSession(path) ∧ registered(path)`  
Штамп — вход ctx (булев/наличие артефакта), для функции это факт наличия, **выставление** штампа — вне функции (человек/тимлид). Детерминизм кончается там, где stamp появляется руками.

[Структурщик]: `trash` по T11/R2 и кандидату Ozhegov:  
`trash ⇔ dirty(path) ∧ ¬registered(path)` при том, что path в рабочем дереве leveling, **или** `isTempPath∨isScratchPath` (корневые времянки, `%TEMP%`, scratchpad) — даже без «осмысленного» diff. Времянки **не** регистрируем, убираем. `unfinished` требует `registered` и отсутствия ready/live/trash. Связь: `trash` и `unfinished` взаимоисключающи по `registered`.

[Teamlead]: Принимаю взаимное исключение по регистрации — это ядро R2. Ложная классификация: unfinished→trash сносит работу; trash→unfinished засоряет реестр. DoD вердикта: регистрация — обязательный вход; отсутствие записи реестра при dirty = trash (стоп гейта), не «молчаливый unfinished». Live всегда выше unfinished при конфликте session∩dirty.

[Музыкант]: Окно сессии: если `inActiveSession` питается только mtime < N минут без session-id — будут ложные live на фоновых тачах. Требую в ctx именно `sessionIds ∋ path` или эквивалент lock-файла оркестратора. Mtime — вспомогательный сигнал для UI, не для чистой функции K1. Иначе детерминизм плывёт между прогонами.

[Верстальщик]: Для a11y-отчёта гейта: trash называется **поимённо** (список path), unfinished — поимённо с id регистрации, ready — поимённо с unit/PR, live — поимённо и **исключён** из перевозки. Пустых «и ещё 40 файлов» без имён — нельзя. Это следует из R2 и повестки, не из красоты.

[Математик]: Полная тотальная функция на домене `path ∈ leveledWorkspace`:

```
disposition(path, ctx):
  if isTempOrScratch(path) ∨ (dirty(path) ∧ ¬registered(path)):
    return trash
  if dirty(path) ∧ inActiveSession(path):
    return live
  if registered(path) ∧ readyFacts(unitOf(path)) ∧ leadStamp(unitOf(path))
     ∧ ¬inActiveSession(path):
    return ready
  if registered(path) ∧ ¬ready(...полный ready выше...):
    return unfinished
  return trash  # защитный fallback: неизвестный dirty/артефакт без регистрации
```

Порядок: trash-pattern → live → ready → unfinished → fallback trash. `ready` включает штамп как вход; без штампа при readyFacts → ветка unfinished.

[Структурщик]: `unitOf(path)` — через реестр регистрации (карточка/PR/ветка), не эвристика «ближайший .git». `registered(path)` истинно только при явной записи манифеста/реестра leveling (форма манифеста — K2, здесь лишь булев порт). Смежные гранулы: `isLeveled` / `legit` (M3/M4) **потребляют** disposition, не подменяют. Публичный API: один экспорт `disposition`, без протечки git-команд в UI-пакеты.

[Teamlead]: Граница детерминизм ↔ штамп: всё, кроме **выставления** `leadStamp` (и человеческой регистрации path в реестр), вычисляется из ctx. Решение «зарегистрировать» и «поставить штамп T8» — суждение человека/тимлида; после появления в ctx функция снова детерминирована. Gейт при `readyFacts ∧ ¬stamp`: disposition=`unfinished`, везти в main нельзя; при `ready` — кандидат на перевозку (сам перевоз — K4). Тезисы T7/T8/T11/R2 соблюдены. Прошу явные «Принимаю».

[Музыкант]: Принимаю. На слух безопасный порядок: сначала отсечь мусор и live, потом ready со штампом, остальное зарегистрированное — unfinished. Ложный trash страшнее ложного unfinished.

[Верстальщик]: Принимаю. Четыре метки, поимённые списки, без пятого состояния. Презентация «ждёт штампа» — подпись над `unfinished`, не отдельный enum.

[Математик]: Принимаю. Функция чистая, тотальная на домене, stamp — вход, не побочный эффект. Покрою юнит-тестами таблицу истинности ветвлений.

[Структурщик]: Принимаю. Словарь ctx и запрет синонимов-состояний фиксируем в вердикте; манифест и рельсы гейта — не наша комната.

[Teamlead]: Принимаю. K1 закрыт по всем граням. K4 не колонизируем. Фиксируем итог и DoD.

## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| Чистая функция | `disposition(path, ctx) → live \| ready \| unfinished \| trash` (тотальная на path ∈ leveled workspace) |
| Порядок ветвлений | 1) trash (temp/scratch ∨ dirty∧¬registered) → 2) live (dirty∧inActiveSession) → 3) ready (registered∧readyFacts∧leadStamp∧¬session) → 4) unfinished (registered∧¬ready) → 5) fallback trash |
| `live` | `dirty(path) ∧ inActiveSession(path)`; `inActiveSession` — факт session-lock/оркестратора, **не** голый mtime; гейт пропускает, не везёт (R2) |
| `ready` | `registered ∧ ciGreen(unit) ∧ ¬conflictsMain(unit) ∧ prApproved(unit) ∧ leadStamp(unit) ∧ ¬inActiveSession`; без штампа при readyFacts → **`unfinished`**, не `ready` |
| `unfinished` | `registered ∧ ¬(полный ready) ∧ ¬live` после отсечения trash; легитимна, регистрируется (T7); включает «ждёт штампа T8» |
| `trash` | `isTempOrScratch(path) ∨ (dirty ∧ ¬registered)`; не регистрируется; останавливает гейт; поимённо (T11, R2) |
| Взаимоисключение | `trash` ⊥ `unfinished` по `registered`; `ready` ⊂ registered; first-match по порядку выше |
| Граница детерминизм ↔ штамп | Детерминированы: dirty, registered, session, CI, conflicts, PR_approved, path-pattern, **наличие** leadStamp в ctx. Не детерминированы функцией: **решение** зарегистрировать path и **выставить** leadStamp (человек/тимлид, T8). После записи в ctx — снова детерминизм |
| Что делает «гейт», если readyFacts∧¬stamp | По K1: disposition=`unfinished`; перевозка в main запрещена. Механика D2/D3/D4 — комната K4 |
| Риск unfinished→trash | Снос реальной работы → недопустимо; поэтому ¬registered обязателен для trash, registered защищает unfinished |
| Риск trash→unfinished | Засорение реестра мусором → недопустимо; temp/scratch и dirty∧¬registered никогда не становятся unfinished без явной регистрации (штамп человека на регистрацию) |
| Связь M3/M4 | `isLeveled` / `legit` только называютcя как Downstream; не проектируются здесь |
