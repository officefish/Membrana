[Архитектор]: Конструкция выемки держится на трёх осях, уже закрытых соседями: владение = `Device.membraneId` (M1), ключ пробы = `id` без `storageRef`/`notes` (M2), ссылка предъявительская с истечением (шторм + M3). [Верстальщик]: С витрины партнёра список — не «картотека метаданных», а пачка одноразовых пропусков. Если UI или прокси закеширует JSON целиком или положит его в лог доступа — связка ключей уехала без выдачи медиа. Презентация должна показывать `total` и страницу, не вываливать ключи в console/toast «для отладки».

[Математик]: Численно: потолок страницы 100, ответ несёт `total`. Ночь 23.08 — 1136 проб → минимум ⌈1136/100⌉ = 12 страниц при фильтре по окну. Счётчика выдач ключей нет, предела частоты на вход нет. Значит цикл `for page in 1..N: GET list → for id in page: GET link` не упирается ни в один существующий предикат. «Нет ручки bulk-media» — не верхняя граница скорости выемки ключей.

[Музыкант]: С тракта: массовой раздачи медиа штормом нет — и правильно, трек по одному. Но ухо слышит другой риск: не «скачали zip двора», а «за вечер собрали связку предъявительских ссылок и унесли на свой CDN». Это та же выемка, только разрезанная на такты. Правило «по одному» без темпа — как метроном без маятника.

[Структурщик]: Леммы. **Список с ключами** ≠ **метаданные каталога**. **Ручка списка** ≠ **ручка выдачи медиа**. **Потолок страницы** ≠ **предел выемки**. Словарь: носитель границы — артефакт рантайма, который отказывает; исполнитель — модуль, который этот отказ чеканит. Пожелание в README без носителя в граф зависимостей не входит.

[Teamlead]: Фиксирую развилку по фильтру дат прямо, как требует гейт. Ночь дежурства и час 21.08 неделю жили как вещдоки. Партнёру без `from`/`to` (или эквивалента) эту ночь целиком не вынуть осмысленно — только слепым листанием. Моё положение: фильтр по промежутку дат **даётся** — это не дыра, это ось доступа к документированному. Но тогда тем жёстче нужен носитель «по одному».

[Архитектор]: Согласен по датам: фильтр по промежутку **даётся** (ось времени рядом с осью владения). Цена: документированная ночь вытягивается целиком по странице 100 + `total`. Это осознанно. Не даём: `storageRef`, `notes`, произвольный query по внутренним полям, bulk-media. `__buffer__` — сырой лоток владельца; наружу он не «ещё один named set», а зона, которая уже под мембранным выключателем M3. Форма: селекторы = membrane-scope + interval + pagination; не больше.

[Верстальщик]: Если фильтр дат даём — на витрине это два честных контрола окна + `total`, без «выгрузить всё». Кнопка «скачать ночь» = антипаттерн: она провоцирует цикл под видом одного жеста. Конструкция экрана: страница, счётчик, поштучный play/get link. Не zip, не «copy all URLs».

[Математик]: Уточняю предикат фильтра. Пусть проба несёт метку времени захвата τ. Фильтр I = [t₀, t₁] допустим ⇔ ответ = { p | τ(p) ∈ I } ∩ scope(membraneId), с |page| ≤ 100 и полем `total = |полный ∩|`. Окно 18:00–19:40 UTC 23.08 при таком фильтре даёт total=1136 — это **факт** ствола, не оценка. Условие «даётся» без дополнительного лимита ширины окна численно означает: партнёр легально вынимает вещдок-ночь. Принимаю как норму комнаты, если носитель ключей держит темп.

[Музыкант]: Вещдок-ночь на слух размечали руками — её и надо уметь вынуть по окну. Я за «фильтр дат даётся». Кеш CDN на `GET list` с ключами внутри — это как оставить мастер-ключи на студийном столе «на пять минут».

[Структурщик]: Публичный контракт списка (имя леммы): `ListSamples(scope, interval?, page) → { items: {id, …public, temporaryKey?}[], total }`. Ключ в элементе — часть **связки**, не decorum. Слой-посредник (API gateway, BFF, SSR-кеш, access-log) обязан классифицировать ответ как **credential-bearing**: no-store, без записи тела в обычные логи, без пересылки целиком в третий контур. Это не «metadata JSON».

[Teamlead]: Переходим к «по одному». Шторм закрыл: нет массовой раздачи медиа. Математик уже показал — этого мало. Кто носитель? Варианты без переоткрытия M3: (a) rate-limit на ручку выдачи ссылки; (b) счётчик выдач на мембрану; (c) уповать на TTL ключа. (c) — не носитель темпа, а носитель срока жизни. M3 уже сказал: поштучный отзыв невозможен, только ротация. Нужен носитель именно **частоты/объёма выдачи ключей**, не только TTL.

[Архитектор]: Носитель границы «по одному» — **квота выдачи предъявительских ссылок на мембрану** (окно + лимит), проверяемая на ручке issue/link. Исполнитель — сервис библиотеки/медиа, тот же контур, что чеканит scope `membraneId` (M1) и отдаёт ключ. Потолок страницы 100 — носитель размера **списка**, не выемки ключей; его не назначаем на роль, которую он не играет. Отсутствие bulk-media оставляем как норму шторма, но в вердикте честно пишем: без квоты на issue правило «по одному» — пожелание.

[Верстальщик]: На UI квота видна как отказ с понятным лицом (не молчаливый 500): «лимит выдачи, подождите» — status, не декоративная модалка. Не показываем «осталось N ключей» как игровой счётчик, если это усиливает вычерпывание. Достаточно блокировки жеста get-link.

[Математик]: Формализую носитель. Пусть на мембрану m в окне W задан лимит L выдач ссылок: счётчик c(m,W) < L, иначе 429 (или эквивалент fail-closed). Сейчас в фактуре: счётчика нет, предела частоты нет — значит L=∞. Вердикт M4 обязан либо ввести конечный L как норму к реализации, либо явно принять L=∞ и назвать «по одному» не правилом. Я против L=∞: 1136 ключей ночи при бесконечном issue — полная выемка вещдока за один проход цикла.

[Структурщик]: Связанность: квота не живёт в UI и не в «джентльменском соглашении» партнёра. ## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| Какие фильтры даются наружу | **Даются:** (1) scope владения по `membraneId` (M1); (2) **фильтр по промежутку дат — даётся** (без доп. потолка ширины окна в этой комнате); (3) пагинация с потолком 100 и полем `total`. **Не даются:** `storageRef`, `notes`, bulk-media, селекторы по внутренним полям хранения. `__buffer__` и named sets — только внутри membrane-scope, не как «анонимный двор». |
| Фильтр по промежутку дат и вещдок-ночь | **Даётся.** Он **позволяет вытянуть документированную ночь целиком** (напр. 1136 проб / page 100 → несколько страниц по `total`). Это осознанная цена доступа к окнам `EVIDENCE_WINDOWS`, не дыра контракта. |
| Чем держится «по одному» | **Носитель границы:** квота выдачи предъявительских ссылок на мембрану (счётчик в окне W, fail-closed при превышении). **Исполнитель:** контур выдачи ссылок media-library (тот же, что чеканит scope и отдаёт temporary key). Потолок страницы 100 — носитель размера *списка*, не выемки ключей. Отсутствие bulk-media (шторм) — необходимое, но **недостаточное** условие: без квоты issue цикл по списку обходит «по одному». Правило без носителя — пожелание; M4 вводит носитель. TTL/ротация остаются за M3 и не подменяют квоту темпа. |
| Как обращаться со списком, внутри которого лежат ключи | Список с ключами = **связка ключей**, не метаданные каталога. **Запрещено:** писать тело ответа с ключами в обычные логи; кешировать на посреднике (shared/CDN/BFF) — `Cache-Control: no-store` (или эквивалент); пересылать JSON **целиком** в третий контур, чат, тикет. **Допустимо:** метрики `total`/page, хеши id, поштучное использование ключа для получения медиа. Утёкшая связка гасится ротацией ключа мембраны (M3) — задний борт, не передний. |
| Носитель границы выемки / исполнитель | **Носитель:** квота issue на `membraneId` + политика credential-bearing на ответ списка. **Исполнитель:** сервис/контур выдачи библиотеки (media-library path), не UI и не «соглашение партнёра». |

**Definition of Done (M4/B1):**

1. В контракте открытого API явно: фильтры `membrane` scope + interval дат + page≤100/`total`; запрет bulk-media сохранён.
2. Ручка issue/link проверяет квоту на мембрану (конечный L, именованная константа, fail-closed); при исчерпании — отказ (429 или принятый эквивалент), покрыто тестом.
3. Ответ списка с temporary keys классифицирован как credential-bearing: `no-store`, нет тела ключей в стандартных access/application-логах; тест/ревью-зуб на места логирования.
4. Документация для партнёра: «список с ключами — связка; не кешировать, не пересылать целиком; трек по одному».
5. Не входит в DoD: изменение TTL/ротации (M3), смена формы id/404/403 (M2), UI-красота сверх отказа квоты.
