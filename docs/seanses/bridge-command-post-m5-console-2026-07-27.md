# Консилиум: M5 — пульт мостика (лента субагента vs чат ведущей)

**Повестка:** V5 — как разделяются лента исполнения (цепочки команд субагента) и чат ведущей (доклад о событиях + журнал); что машинно гарантирует запуск субагента, а не инлайн-цепочку перед капитаном; какие события всплывают в чат и в какой форме; где живёт журнал ведущей; честный отказ носителя пульта вместо имитации.

**Участники:** Teamlead (Tarasov), Архитектор (Vesnin), Структурщик (Ozhegov), Математик (Dynin), Музыкант (Kuryokhin), Верстальщик (Rodchenko).

**Порядок реплик:** Математик → Музыкант → Верстальщик → Архитектор → Структурщик → Teamlead

---

[Математик]: Формализую предмет. Пульт — это пара каналов с разными контрактами: `exec_feed` (поток шагов цепочки) и `lead_chat` (дискретные доклады о событиях). Предикат «субагент запущен» обязан быть проверяем до первого шага цепочки: `carrier = subagent | inline | refused`. Инлайн перед глазами капитана при `carrier≠inline` — нарушение контракта, не «почти норма». Машинная гарантия = гейт на входе фрейма: без успешного spawn — стоп или честный `refused`, без тихой деградации в инлайн.

[Музыкант]: На слух это как master-bus vs talkback. Цепочка команд — ритм-секция: она играет в мониторах инженера, не в зале. Чат ведущей — talkback капитану: «трек стартовал / гейт красный / take готов». Если субагент не поднялся, а цепочка всё равно орёт в лицо капитану — это клиппинг процесса. Хочу честный mute: отказ носителя = тишина исполнения + одно сообщение «носитель не поднялся», без имитации живого микса.

[Верстальщик]: С витрины капитана два блока, не один скролл. (1) **Лента исполнения** — узкая, моноширинная, шаги/статусы, сворачиваема, не главный акцент. (2) **Чат ведущей** — основной столбец: доклады, вопросы к капитану, статус носителя. Конструктивизм: `carrier: refused` виден бейджем в шапке пульта, не прячется в логе шага 14. Пустая лента при живом чате — нормальный empty state, не ошибка вёрстки.

[Архитектор]: Конструкция: пульт — **потребитель** слота из M2, не новый рантайм. Граница: фрейм ядра объявляет `execution.carrier` и `execution.steps[]`; пульт только отображает и маршрутизирует события. Запрет: UI не spawn'ит субагента «по желанию сессии» — spawn делает гейт фрейма / харнесс до входа в presentation. Варианты цены: (A) жёсткий pre-gate spawn — дорого в обвязке, честно; (B) дисциплина промпта — дёшево, уже провалилось по слову владельца 26.07. Рекомендую A.

[Структурщик]: Леммы, иначе синонимы-слои. **Носитель пульта** (`carrier`) ≠ **ведущая** (`lead` | `scribe`). **Лента** = append-only журнал шагов с `stepId, verb, status, ts`. **Чат ведущей** = sequence `LeadReport` с типами `event | ask | journal_note | carrier_status`. Журнал ведущей — отдельный home (путь/артефакт сессии), не смесь с `exec_feed`. Публичный API пульта: `subscribeExecFeed`, `subscribeLeadChat`, `getCarrierState` — без прямого импорта ритуального runner'а в UI-компонент.

[Teamlead]: Положение: владелец уже сказал «не хочу смотреть инлайн». Это не вкус, а бриф матча. Решение комнаты — контракт пульта с машинным зубом на carrier, не памятка «пожалуйста, запускай субагента». Связка: Архитектор+Структурщик — форма и API; Математик — предикаты гейта; Верстальщик — два блока и честный отказ; Музыкант — какие события звучат в talkback. Планка: LGTM только если инлайн нельзя выдать за успех субагента.

[Математик]: Зуб spawn: `trySpawn(subagentSpec) → {ok, carrierId} | {ok:false, reason}`. Дальше `assignCarrier`: если ok → `carrier=subagent`; если false → `carrier=refused` и **запрет** перехода в `inline` без явного `allowInline:true` в спеке фрейма (по умолчанию false для bridge). Инвариант: ∀ step executed visible_to_captain_as_chain ⇒ carrier=subagent ∨ allowInline. Тест: симуляция fail-spawn → ноль инлайн-шагов в капитанском viewport + один `carrier_status=refused`.

[Музыкант]: Какие события в чат, какие в ленту — по аналогии с метрами. В **ленту**: старт/стоп шага, stdout-крошки, код выхода, retry. В **чат ведущей** (доклад): смена фазы фрейма, срабатывание machine-gate (stop/wait), просьба решения капитана, итог цепочки одной фразой, отказ носителя, «журнал записан». Не тащить каждый ping в talkback — будет шум как от открытого hi-hat на каждом четвертном.

[Верстальщик]: Форма доклада в чате — карточка-событие, не простыня лога: заголовок (глагол человекочитаемый), статус-семантика DaisyUI (`info|success|warning|error`), опционально 1–2 строки detail, `ts` tabular-nums. Отказ носителя — `error`/`warning` в шапке + закреплённое первое сообщение чата, пока сессия не закрыта или не перезапущена. Лента по умолчанию collapsed на мобилке; на мостике — secondary column.

[Архитектор]: Журнал ведущей: при live-Ангелине (когда канал bridge появится) — её память/журнал по канону ведущей; **сегодня** live-вызова нет (M1: честное «нет»). Режим absent: `session-scribe` пишет journal_note под своим статусом, **без** подписи `angelina`. Пульт показывает `leadMode: live | scribe | absent` — третье, если даже scribe не назначен. Не смешивать journal home с exec_feed home: разные файлы/потоки, общий только `sessionId`.

[Структурщик]: Homes (словарно, не колонизируя M6): `exec_feed` → артефакт сессии append-only (JSONL/stream); `lead_chat` → то же или duplex-канал UI; `lead_journal` → markdown/jsonl notes с полями `{ts, author_role, text, refs[]}`. author_role ∈ {`angelina`,`session-scribe`} строго; чужое имя — нарушение нормы M1. Связанность: presentation читает фасады, runner пишет в feed через `ExecFeedWriter`, не через React state напрямую.

[Teamlead]: Красная линия: «сессия решила инлайнить, потому что так проще» = BLOCK. Внешние вызовы-гейты уже держат цепочку — значит spawn субагента вешаем **на тот же контур гейтов**, не на вежливость модели. Кто в связке чинит: Структурщик+Математик на pre-step гейт; Верстальщик не начинает виджеты до контракта событий. Требую в вердикте явный default `allowInline=false` для мостика.

[Математик]: Событийная схема (чистые типы, без UI):  
`ExecStepEvent = {stepId, name, status: pending|running|ok|fail|skipped, ts, exitCode?}`.  
`LeadReport = {id, kind: event|ask|journal_note|carrier_status|phase, summary, detail?, severity, ts, refs?: stepId[]}`.  
Функция фильтра talkback: `toLead(e: ExecStepEvent, policy) → LeadReport | null` — по умолчанию null; non-null только на boundary (phase change, fail, gate wait, terminal). Это снимает «каждый чих в чат».

[Музыкант]: Boundary на слух: начало ритуала, конец ритуала, gate=stop/wait, первый fail цепочки, carrier_status, ask капитану. Running-шаги с ok — только лента. Если fail — в чат одна карточка со ссылкой `refs` на stepId, детали — в ленте по клику. Иначе капитан слушает репетицию вместо доклада.

[Верстальщик]: Клик по `refs` в карточке чата раскрывает соответствующий сегмент ленты (scroll-into-view + highlight). Это монтаж слоёв, не второй лог. a11y: live region для `LeadReport` с `severity≥warning`; лента — `aria-label="Лента исполнения"`, не дублировать каждый step в SR если collapsed.

[Архитектор]: Машинная гарантия запуска — не «агент в промпте пообещал». Три слоя: (1) **спека фрейма** требует `carrier: subagent`; (2) **runner/harness** выполняет spawn до `steps[0]`; (3) **presentation-gate** не открывает режим «цепочка на глазах», пока `getCarrierState()∈{subagent, refused}` — при refused показывает отказ, не stream шагов как главный театр. Инлайн остаётся инструментом разработчика/отладки вне капитанского viewport или под явным флагом не-bridge.

[Структурщик]: Имя зубной процедуры: `assertCarrier` в контуре runner, рядом с machine-gates M2 (stop/wait/ignore), не UI-валидатор. Псевдогейт «стараться запустить субагента» — отвергаем тем же приговором, что M2. API: `assertCarrier(spec) → CarrierState`; UI только читает. Если харнесс уже умеет background tasks + notifications — контракт пульта **привязывается** к этому механизму как SoT ленты, не плодит второй bus.

[Teamlead]: Принимаю привязку к существующему фону: не изобретаем рантайм. Изобретаем **обязанность** и **запрет подмены**. Связка на DoD: тест fail-spawn; запрет подписи angelina у scribe; два канала в контракте. Дальше спорьте детали policy, но матч без инлайн-театра.

[Математик]: Отказ носителя — тотальная функция:  
`onSpawnFail(reason) → {carrier: refused, lead: CarrierStatusReport, exec: freeze}`.  
`freeze` = никаких ExecStepEvent с status running в капитанском фиде; допускается diagnostic channel вне пульта (dev). Норма панели (procedure-must-follow-panel-chain): reason пошагово, по месту, без тихой смены пути на inline. Численно: 1 report, 0 maskings.

[Музыкант]: При refused не надо «играть дальше на встроенных динамиках». Капитан слышит: носитель молчит, ритуал ждёт решения (wait) или стоп — по гейту фрейма. Импровизация «ну я сам выполню глазами владельца» — запрещённый cover-band.

[Верстальщик]: Empty/error: лента при refused — явная заглушка «исполнение не стартовало», не вечный skeleton. Чат — одна pinned-карточка reason. Кнопка «повторить spawn» — только если фрейм объявил retry; иначе нет мёртвой кнопки-декора.

[Архитектор]: Режим scribe vs live не меняет разделение лента/чат. Меняется author и глубина journal_note. Форма решения: пульт изоморфен; `leadMode` — параметр презентации и права подписи журнала. Когда bridge-канал Ангелины появится, контракт пульта не ломаем — только flip `leadMode`.

[Структурщик]: Зафиксирую запрет синонима: «чат субагента» не вводим. Субагент пишет в `exec_feed` (+ опционально technical notifications харнесса). Голос в `lead_chat` — только lead/scribe. Иначе снова один скролл и владелец смотрит инлайн под другим соусом.

[Teamlead]: Верно. Субагент — руки в яме оркестра, не собеседник капитана. Ведущая — собеседник. Кто путает — разрушает комбинацию. Держим.

[Математик]: Policy-таблица talkback (минимальный канон v1):

| источник | → лента | → чат |
|----------|---------|-------|
| step running/ok | да | нет |
| step fail | да | да (event+refs) |
| gate stop/wait | да | да (ask\|event) |
| phase begin/end | да | да |
| spawn ok/fail | да | да (carrier_status) |
| journal_note | нет | да |
| heartbeat | опц. лента | нет |

Расширения — PR, не молчаливый if в UI.

[Музыкант]: Heartbeat в чат — нет, это room tone, не реплика. Согласен с таблицей. Ещё: итоговый terminal report — обязательно в чат одной карточкой «ритуал завершён / оборван», даже если все ok-шаги остались в ленте.

[Верстальщик]: Terminal card — primary accent в конце потока чата; severity от исхода. DESIGN: без градиентов «победы», честный `success|error`. Статус носителя дублируется мелким бейджем в хедере на весь сеанс (live pulse / refused).

[Архитектор]: Цена отложенного UI: контракт данных и гейт `assertCarrier` — сейчас; пиксели пульта могут идти после, но **не** цепочка инлайн «пока нет вёрстки». Документ контракта = несущая конструкция; виджет — обшивка. Рекомендация: ADR-короткая или секция в bridge-room каноне — `CarrierState` + event types + defaults.

[Структурщик]: Пакетная граница: типы событий — в процедурном/bridge контракте (packages или docs-contract, как принято у фреймов), не в `apps/*/components`. Хуки UI: `useBridgeExecFeed(sessionId)`, `useBridgeLeadChat(sessionId)`, `useBridgeCarrier(sessionId)`. Runner зависит от writer'ов; UI от reader-фасада. Слабая связанность: нет импорта runner→React.

[Teamlead]: DoD комнаты — контракт и зуб, не splendor панели. Кто рисует раньше контракта — BLOCK. Идём к своду посылок и вердикту.

[Математик]: Инвариант сессии (проверка отзывом):  
`¬(viewport_captain_shows_inline_chain ∧ carrier∈{subagent,refused} ∧ ¬allowInline)`.  
Плюс `lead_chat.author≠angelina` when `leadMode=scribe`. Оба — машинопроверяемые на фикстурах.

[Музыкант]: Фикстура fail-spawn на слух: тишина ленты исполнения + один честный отказ. Если в записи фикстуры есть «шаг 1: yarn …» глазами капитана — тест красный. Принимаю.

[Верстальщик]: Принимаю два блока и pinned refusal. Не тащу M6-попугая в пульт. Виджеты — после типов.

[Архитектор]: Принимаю: pre-gate spawn, freeze on refuse, isomorphic live/scribe, инлайн не default. Пульт = consumer слота M2 + feed/chat фасады.

[Структурщик]: Принимаю леммы carrier/feed/chat/journal, writer/reader split, запрет «чата субагента». API имена — словарные статьи выше.

[Teamlead]: Вердикт: **LGTM** на контракт пульта с машинной гарантией carrier и честным отказом. Инлайн-театр на мостике — вне закона без явного allowInline. Связка на реализацию: Ozhegov+Dynin (assertCarrier+типы), Rodchenko (два блока по контракту), Kuryokhin (policy boundary на фикстурах), Vesnin (форма в каноне bridge). Исполнение — после ратификации владельца; планка не опускается.

[Математик]: Уточнение к allowInline: если когда-либо true, presentation обязана бейджем `carrier: inline (explicit)` — нельзя выглядеть как subagent. Иначе предикат «гарантия» лжёт статистически: 1% тихих inline убивает доверие к метке.

[Музыкант]: Как true-bypass на пульте с красной лампой — да. Без лампы bypass запрещён.

[Структурщик]: `unknown` в API внутренний только до первого assertCarrier; наружу пульта не отдаём. Согласен.

## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| Разделение каналов пульта | **Два канала:** `exec_feed` (лента шагов субагента/харнесса) и `lead_chat` (доклады ведущей/scribe). Субагент **не** собеседник в lead_chat. |
| Кто пишет куда | Runner/субагент → только exec_feed (+ technical harness notifications). Lead/scribe → lead_chat и lead_journal. UI — reader-фасады, без spawn. |
| Машинная гарантия spawn | **Pre-gate `assertCarrier`** в контуре runner/harness **до** `steps[0]`: успех → `carrier=subagent`; провал → `carrier=refused`. Default **`allowInline=false`** на мостике. Тихий fallback inline **запрещён** (норма класса P5). |
| Инлайн | Допустим только при явном `allowInline:true` в спеке **и** видимом badge `inline (explicit)`. Не default капитанского viewport. Dev-diagnostic — вне пульта. |
| Что в ленту / что в чат | Лента: running/ok шаги, детали, опц. heartbeat. Чат: phase begin/end, gate stop/wait, fail (с refs на stepId), carrier_status, ask капитану, journal_note, terminal summary. Policy-таблица v1 — канон; расширения через PR. |
| Форма доклада в чате | Дискретные `LeadReport` (summary + severity + optional detail + refs), не поток stdout. |
