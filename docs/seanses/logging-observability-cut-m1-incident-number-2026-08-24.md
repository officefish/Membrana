[Математик]: Формализую инварианты до спора о синтаксисе. Пусть ответ ошибки рода «сломан» несёт идентификатор `I`. [Структурщик]: Леммы. «Номер происшествия» — ключ картотеки и сшивки. «Request-id» — ключ одного HTTP-прохода. Место: тело обязательно (потребитель UI и любой клиент, который не читает заголовки); заголовок — дополнение для прокси/корреляции, не замена тела. Имя поля одно на весь контур.

[Архитектор]: Конструкция: номер — не украшение 500, а несущий шов трёх хранилищ. Значит тело JSON ответа при роде «сломан» несёт поле номера; заголовок рядом — тот же литерал. `X-Request-Id` остаётся на каждый ответ как сейчас; номер происшествия — только на лице «сломан», не на каждый 200. Смешать их в один заголовок — разрушить границу смыслов.

[Музыкант]: С края оператора слышу диктовку в трубку: UUID — это шум, не мотив. Нужны короткие такты: группы по четыре, алфавит без 0/O/1/I/L. [Верстальщик]: С витрины: человек читает тело и то, что UI вывел крупно. Заголовок ответа оператор не увидит. Три рода отказа — три разных лица на экране: «сломан» с номером; «занят» с «подожди N»; «не дойти» без фальшивого инцидента.

[Teamlead]: Фиксирую рабочую рамку: оба места (тело + заголовок), разные смыслы с request-id, диктуемая форма. Дальше — точный алфавит и поведение, когда Сентри молчит. Без «почти»: временный номер не должен врать, что он уже в картотеке.

[Математик]: Предлагаю форму официального номера: префикс рода + 8 символов Crockford Base32 (исключены I, L, O, U), группами `XXXX-XXXX`. Итого литерал: `INC-A3F7-K2M9`. [Структурщик]: Имена контракта, чтобы #2113 и #2110 не упёрлись в синонимы. Заголовок: `X-Incident-Id`. Тело: `incidentId` (string). [Архитектор]: Цена «только заголовок»: UI и часть клиентов теряют номер; CORS уже знает `X-Request-Id`, для `X-Incident-Id` понадобится expose — это цена, но не запрет. ## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| Место номера | **Оба:** тело JSON (канон для человека/UI) **и** заголовок `X-Incident-Id` (тот же литерал для машин/корреляции). |
| Когда нести | Только при `genus: 'broken'`. Не на каждый ответ; не на `busy` / `unreachable`. |
| Форма официального номера | `INC-XXXX-XXXX`, 8 символов **Crockford Base32** (без I, L, O, U), группы по 4. Чеканит **только Сентри**. |
| Форма при недоступном Сентри | `TMP-XXXX-XXXX`, тот же алфавит/длина; локальный суррогат ответа **не** записывается в картотеку как INC. Лицо «сломан» сохраняется. |
| Тело ответа (broken) | `{ genus: 'broken', incidentId: 'INC-…' \| 'TMP-…', message: string, requestId: string }` — `message` не единственное поле; голый `Internal server error` неканоничен. |
| `X-Request-Id` | **Живёт рядом**, не заменяется номером. Уже на каждый ответ; смысл — один HTTP-проход. В логе при broken — оба поля. |
| Экран клиента | Primary: род + `incidentId` (диктовка/копирование). Secondary: `requestId`. TMP помечен как «не в картотеке». |
| Лог сервера | Структурированные поля `genus`, `incidentId`, `requestId` (+ краткий message). Литерал `incidentId` = body = заголовок. |
| #2113 (линеаризация) | Контракт добавляет стабильные поля события; алгоритм линеаризации не предписывается. |
| #2110 (сортировка) | `incidentId` — opaque string; обязательной колонки/ключа сортировки вердикт не вводит. |
| Запреты | Чеканщик INC не пересматривается; /health/deep, диск, пульс — вне комнаты; прод/деплой — вне комнаты. |

**Definition of Done (кусок N1):**

1. Ответ рода «сломан» всегда содержит `genus === 'broken'` и непустой `incidentId` вида `INC-*` или `TMP-*`.
2. При том же ответе заголовок `X-Incident-Id` равен `incidentId` тела (после CORS expose).
3. В серверном логе того же отказа есть поле `incidentId` с тем же литералом и поле `requestId`.
4. При доступном Сентри: префикс `INC-`, запись находима в картотеке по этому ключу.
5. При недоступном Сентри: префикс `TMP-`, ответ не 500-простыня без лица; картотека не обязана содержать TMP.
6. Ответы `busy` / `unreachable` не несут `incidentId` / `X-Incident-Id`.
7. `X-Request-Id` на обычных ответах сохраняет текущее поведение.
8. Контрактные поля не требуют переделки существа #2113 и #2110 (проверка ревью: нет новых обязательных зависимостей журнала/сортировки от клиента Сентри).

> Задание: [`MEETING_BRIEF.md`](./MEETING_BRIEF.md) — прочесть целиком до реплик.

### Вопрос заседания

**N1 — каким форматом и в каком месте ответа кабинет несёт номер происшествия: заголовок
или тело ответа (или оба); какова форма самого номера; как номер уезжает клиенту на
экран и строкой в лог сервера; и как ведёт себя ответ, когда Сентри недоступен и чеканить
некому — при том что чеканит номер Сентри (решено владельцем), а контракт обязан
выдержать соседние линии #2113 (линеаризация журнала) и #2110 (плагин сортировки), не
решая их существа?**

### Данности (не предмет спора)

- Номер чеканит **Сентри** — отдельный контейнер-картотека на офисе (Т5/Т6, владелец 24.08).
- Номер сшивает три рода хранения: картотека · поток строк · числа (Т6).
- Человек **диктует** номер с экрана — форма обязана быть диктуемой (Т4).
- Три рода отказа — три слова (Т3): номер происшествия — лицо рода «сломан»; «занят»
  несёт «подожди N», «не дойти» — сеть/блокировка. Род в ответе обязан различаться.
- Факт: пятисотка сегодня — `{message: 'Internal server error'}` из единого
  `AllExceptionsFilter` (`http-exception.filter.ts:34`).
- Факт: `X-Request-Id` уже чеканится интерсептором на каждый ответ и разрешён в CORS;
  request-id ≠ номер происшествия (не группирует повторы, не живёт в картотеке).

### Что комната должна выдать

- Место номера: заголовок / тело / оба — с обоснованием от читателей (человек с экрана,
  строка лога, соседние линии #2113/#2110).
- Форму номера: что диктуемо голосом и находимо в картотеке.
- Соотношение с `X-Request-Id`: заменяет, дополняет, живут рядом — и кто из них в логе.
- Поведение при недоступном Сентри: ответ обязан нести лицо и без чеканщика — чем.
- Проверку контракта от лица #2113 и #2110: обе встают без переделки (вердиктов по их
  существу не выносить).
- **DoD куска**: проверяемый предикат готовности (что видно в ответе, в логе, в картотеке).

### Список посылок — обязателен

Секция с заголовком ровно **«Список посылок»**: полный список входов, каждый помечен
**факт** или **норма**; только входы, ровно использованные — лишний вход лжёт об отзыве.

### Запреты этой комнаты

- Не пересматривать решённое владельцем (чеканщик — Сентри; контейнер отдельный; сшивка номером).
- Не выносить вердиктов по существу #2113 и #2110.
- Не проектировать состав `/health/deep`, сторожа диска, пульс — соседние комнаты.
- Прод не трогать: комната решает контракт, не деплой.
