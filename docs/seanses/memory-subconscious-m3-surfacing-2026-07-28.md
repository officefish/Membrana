**Повестка:** C3 — как единица подсознания поднимается в поле внимания персоны: устройство облака кандидатов (похожие + дальние), роль MMR/диверсификации и serendipity-слотов, мультизапрос, качественные веса резонанса; граница «лифт (retrieval) vs акт всплытия (судящее звено персоны)»; v1 при живом RAG vs именованные слоты v2; провенанс в протоколе; право отвергнуть облако целиком. **Участники:** Teamlead (Tarasov), Структурщик (Ozhegov), Математик (Dynin), Музыкант (Kuryokhin), Верстальщик (Rodchenko), Архитектор (Vesnin).

[Структурщик]: Начинаю со словаря, иначе снова синонимы-слои. **Лифт** — детерминированный retrieval-контур: на входе тема/повестка, на выходе конечное **облако** кандидатов с id/provenance из архива C1. **Акт всплытия** — суждение персоны: из облака выбирает 0..N записей и обязана назвать *почему*. **Мультизапрос** — набор запросов к архиву, не один top-K. **Serendipity-слот** — квота «аутсайдеров» вне основного ранга сходства. Не смешивать лифт и память: скрипт не «вспоминает».

[Математик]: Формализую без UI. Пусть архив A_p персоны p — адресуемая лента (C1). Запрос q → embedding e(q). Наивный top-K(sim(e(q), e(a))) даёт ~45% ложных привязок (research #1366) — MMR обязателен. MMR: итеративно argmax [λ·sim(a,q) − (1−λ)·max_{b∈S} sim(a,b)]. Serendipity: 1–2 записи из хвоста распределения, не из top. Акт всплытия — не функция лифта: emerge(p, cloud, topic) ∈ 2^cloud с обоснованием why ⊆ текст. Численные λ и веса — слот v2/C5; здесь — ординальная схема слотов.

[Teamlead]: Планка матча ясна. Владелец: «всплывает, когда касается темы консилиума»; «скрипт — лифт, не память». Не проектируем cron (C4), не метрики recall (C5), не extractor (C6). Нужны четыре закрытия: (1) форма облака и квоты слотов; (2) мультизапрос — какие оси в v1; (3) граница лифт/персона + право reject; (4) провенанс в протоколе. Связка: Математик — предикаты и слоты; Структурщик — API лифта; Архитектор — границы модулей; Верстальщик — честная видимость «из подсознания»; Музыкант — слух на заскриптованность. Планка: одинаковый запрос ≠ одинаковый скучный top без сюрприза — и одновременно облако конечно, не «весь архив».

[Верстальщик]: С витрины протокола и капитана: фальшивое «Дынин вспомнил» без why — декор без смысла, как фальшивое присутствие на M1. Требую в протоколе явную полосу: источник = `subconscious`, id/provenance, who = persona id, why = одна-две фразы персоны. Пустое всплытие честно: `emerged: []` + optional `cloud_rejected: true`. Не рисую UI пульта — только контракт меток, чтобы later витрина не врала.

[Музыкант]: На слух опасение владельца верное: один запрос → один и тот же хит-парад — это не память, а автотюн. Лечение как в редизайне снов: тема + противоположность + «кто спорил» + два аутсайдера в стол. Лифт — count-in и мониторы инженера; соло — персона: «беру этот take, потому что конфликт с сегодняшней позицией». Если лифт сам пишет «вспомнил» в протокол — клиппинг авторства. Облако узкое: case memory-outweighs-topic — полный груз топит повестку.

[Архитектор]: Конструкция. Два модуля, не один комбайн: (1) `subconscious-lift` — pure retrieval+fusion, вход topic/context, выход Cloud; (2) судящее звено — уже существующий вызов персоны по панельной цепочке (ask/consilium), не новый «мозг в скрипте». Граница пакета: лифт не импортирует промпты персон и не пишет journal; персона не ходит в сырой jsonl в обход лифта при штатном всплытии. C1 даёт fullRef/id — лифт резолвит только адресуемое. Рекомендация: форма + тонкий API; ADR только если захотят вшить rerank внутрь persona-runtime.

[Структурщик]: Леммы API. `buildCloud(personaId, topic, opts) → Cloud` где Cloud = { slots: { similar, contrast, outsider }, items: CloudItem[], queryPlan: QuerySpec[] }. CloudItem: `{ id, provenance, class?, lifecycle?, importance?, snippetRef, scores?: ordinal }`. Export только через фасад пакета памяти; ask/consilium потребляют Cloud, не внутренности jsonl. Join с importance/class из C2 — **да, использует** как признаки фильтра/ранга слотов, не как второй бюджет O. Предикат: лифт читает archive+C2-meta; не пишет O.

[Математик]: Мультизапрос v1 — закрытое множество осей, не свободная генерация бесконечных q. Предлагаю ординал: Q1 = topic (повестка/вопрос комнаты); Q2 = contrast (отрицание/оппозиция темы — шаблон или LLM-парафраз *как генератор запроса*, не как память); Q3 = dispute (маркеры конфликта/опровержения в meta или лексике summary); Q4 = optional analogy — слот v2. Fusion: объединение кандидатов по id, затем MMR внутри similar; outsiders — sample из хвоста после фильтра «уже не в similar». Квоты v1 (целые, не float): similar ≤ Ks, contrast ≤ Kc, outsider = {1|2}. Дефолт предлагаю Ks=5, Kc=3, outsider=2; потолок |cloud| ≤ 10. Калибровка чисел — C5, здесь — константы-имена.

[Teamlead]: Квоты принимаю как потолок v1, не как науку. |cloud|≤10 — против memory-outweighs-topic. Outsider ровно паттерн владельца «два аутсайдера». Если pinned из C2 попадает в выдачу — хорошо, но pinned не обязан всегда всплывать: всплытие ≠ operational pack. Reject облака целиком — право персоны, иначе судящее звено декоративное. Связка на реализацию после вердикта: Структурщик+Математик контракт; провод в consilium/ask — пометка C6, не раздуваем DoD этой комнаты.

[Верстальщик]: Квоты на витрине не цифрами «магии», а слотами: блок «близкие», блок «контраст», блок «аутсайдеры». Если слот пуст — честная пустота, не добивка random ради красоты. В протоколе реплики: префикс или подвал метаданных реплики `memory: subconscious` + why. Капитан должен отличить «опираюсь на журнал O» от «всплыло из архива» без детектива.

[Музыкант]: Q2 contrast — это не «ещё пять похожих под другим соусом». Если contrast схлопывается в near-duplicate similar — serendipity умерла. На слух: outsider обязан быть *дальним* по sim, иначе это массовка в первом ряду. Право reject: персона может сказать «облако не про эту комнату» — и играть без подсказки из подполья. Это свобода солиста, не баг лифта.

[Архитектор]: Варианты границы reject. A) Персона молча игнорирует cloud — дешёво, но протокол врёт о причине. B) Явный жест `reject_cloud(reason)` в ответе судящего звена — честно, чуть дороже контракт. Беру B в норме протокола; реализация жеста — минимальная: поле в структурированном следе реплики/секции памяти, не отдельный микросервис. Цена A — регресс доверия к «акт за персоной». Затронутые модули: фасад lift; формат следа в seanse/ask; без перестройки DAY_MEMO.

[Структурщик]: QueryPlan в Cloud — обязательный провенанс *лифта*: какие оси q реально бежали, сколько hit’ов до MMR. Иначе нельзя отличить «архив пуст» от «мультизапрос сломан». Имена: не `helperRetrieve`, а `buildSubconsciousCloud` / `SubconsciousLift`. Запрет: UI → jsonl; persona-prompt → прямой fs archive. Слабая связанность: lift зависит от archive store + embedding port; persona runtime зависит от Cloud DTO.

[Математик]: Веса резонанса в v1 — **качественные ординалы-флаги**, не float-обучение. Флаги кандидата (0/1): `hasConflict`, `hasOwnerQuote`, `isPinned`, `classRank` (из C2: insight/precedent > position > routine), `recencyBucket` (грубо). Comparator до MMR-diversify: лексикографический по флагам + sim-bucket; после — MMR для diversity similar-слота. Обучение ранкера, λ-gridsearch — v2 после C5. Предикат допуска в outsider: sim < τ_out ∧ id ∉ similar∪contrast; τ_out — именованная константа, значение под C5, в v1 — «ниже медианы pool или bottom quartile».

[Teamlead]: Не изобретаем ману и не калибруем τ руками «на глаз» в этом вердикте — слот v2/C5, Математик правильно режет. v1 = слоты + мультизапрос + MMR + ординальные флаги + акт персоны + провенанс. Всё. Кто нарушит «лифт пишет why за персону» — BLOCK на приёмке. Слышу риск: LLM-парафраз для Q2 может размыть детерминизм. Правило: queryPlan логируется; при отсутствии LLM-порта — Q2 = шаблонные антонимы/negation lexicon, fail-open в reduced plan, не silent empty.

[Верстальщик]: Reduced plan тоже виден: `queryPlan: [topic, contrast:template]` — чтобы не казалось, что «полный оркестр» играл. Акт why — текст персоны, не бейдж-генератор из флагов (`why: conflict_flag` запрещён как единственное обоснование). Флаги могут *подсветить* карточку кандидату внутри облака для персоны-потребителя, но в протоколе why — речь роли.

[Музыкант]: Рифма с LLM-reranker из research: персона *и есть* reranker. Лифт не дожимает top-1. Если когда-нибудь поставим машинный pre-rerank — только как optional stage *внутри* лифта до Cloud, с пометкой в queryPlan, и всё равно акт emerge за персоной. Иначе снова автотюн под видом «ума».

[Архитектор]: Фиксирую слои v1/v2 явно, чтобы не расползлось. **v1:** multi-query {topic, contrast, dispute}, fusion, MMR on similar, outsider 1–2, flags from C2+lex, Cloud DTO, persona emerge+why|reject, protocol provenance. **v2 (именованные слоты, не делать сейчас):** analogy-query, learned λ/τ, embedding fine-tune, active serendipity policies beyond 2, cross-persona lift. Живой носитель: существующий `retrieveRagContext` / persona-RAG — **направить** на archive jsonl per C1, не плодить второй RAG-стек без нужды. Цена дубля — два словаря близости.

[Структурщик]: Согласен не плодить второй стек: порт retrieval один, backend archive vs operative docs — strategy. Оперативная O (C2) в облако подсознания **не** подмешивается как основной корпус: O и так в контексте персоны; C3 = подъём из archive. Исключение: de-dup по provenance, чтобы не всплыло то, что уже в O-проекции дословно. Лемма: `notAlreadyOperational(id)`.

[Математик]: De-dup: `cloud := cloud \ { a | prov(a) ∈ operationalProvenanceSet(p) }` — да. Иначе «всплытие» = эхо свежего стека. Ещё предикат: summary+fullRef (C1) — в CloudItem кладём snippet из summary, full текст персона дотягивает по fullRef только для выбранных emerge (экономия токенов; стык с бюджетами, без назначения B_cloud сверх |cloud|).

[Teamlead]: Экономия токенов — не предлог сужать why. Матч: персона видит cloud (snippet+meta), выбирает, пишет why, при необходимости цитирует full по ref. Не тащим 239 полных текстов. Порядок в комбинации: lift → cloud в контексте вызова персоны → реплика с emerge|reject. Расписание *когда* звать lift — C4; здесь только *что* происходит в акте.

[Верстальщик]: Минимальный макет следа для seanse/ask (контракт, не JSX):  
`[память:подсознание] id=<provenance> → why: «…»`  
или  
`[память:подсознание] cloud_rejected reason: «…»`.  
Несколько emerge — несколько строк. Без why строка невалидна (зуб формы на C6/приёмке, правило — здесь).

[Музыкант]: Аутсайдеры — не шутки ради. Паттерн снов: случайность *управляемая* квотой, не rand() по всему архиву без фильтра persona. Outsider из A_p той же персоны, не чужой журнал. Cross-persona — v2 и этически другая комната. Слышу: dispute-ось поднимает старые опровержения охотнее «ровных» routine — это и есть качественный резонанс без float.

[Архитектор]: Форма решения в двух абзацах. Подсознание всплывает через лифт, строящий конечное разнородное облако (similar+contrast+outsider) мультизапросом и MMR; признаки C2 участвуют как флаги ранга, не как operational pack. Акт всплытия — только судящее звено персоны: emerge с why или reject cloud; протокол несёт провенанс subconscious. Модули: archive store (C1), importance/class meta (C2), `SubconsciousLift.buildCloud`, DTO Cloud, consumer в ask/consilium chain; без нового «память-агента» parallel к персонам.

[Структурщик]: Definition границ consumer: консилиум-секретарь и `yarn ask` получают cloud как input-блок к персоне; секретарь **не** выбирает за роли. Гости (Фаррелл) — вне автоматического lift v1 (origin:pet не архив персоны-советчика). Ангелина не судит облако советующих. Имена полей стабильны для зуба: `cloudId`, `queryPlan`, `items[]`, `emerged[]`, `rejected`.

[Математик]: Инвариант размера: `|items| ≤ 10`; `|outsider| ≤ 2`; similar и contrast непустые *только если* archive hit > 0 по оси — иначе пустой слот, не padding. Инвариант авторства: `∀ e ∈ emerged: e ∈ items ∧ why(e) ≠ ∅`. Инвариант reject: `rejected ⇒ emerged = ∅`. Тесты чистые на fixture archive — зона реализации, контракт — здесь.

[Teamlead]: Принимаю инварианты как планку приёмки контракта C3. Не расписываю зелёный CI соседним комнатам. Спор «обязателен ли lift на каждый консилиум» — C4. Здесь: *если* lift вызван, правила облака и акта таковы. Единое решение готовим: без «зависит» — v1 спецификация закрыта.

[Верстальщик]: Последнее по честности: если emerge ссылается на id вне cloud — нарушение витрины (подлог памяти). Зуб: emerged ⊆ items. Капитан и читатель протокола обязаны видеть ту же карточку, что видела персона.

[Музыкант]: Итого на слух: лифт подаёт сет, персона берёт take или отказывает столу. Не заскриптовано = есть contrast+outsider+why. Заскриптовано = один top-K и система пишет «вспомнил» сама. Вердикт держит первое.

[Архитектор]: Консенсус по конструкции есть. Рекомендация: принять спецификацию C3; ADR не требуется, если API остаётся тонким фасадом над существующим RAG-портом. Отклонение — только если кто-то потребует machine-auto-emerge без персоны: это ломка слова владельца.

[Структурщик]: Словарь в вердикт: Lift, Cloud, QueryPlan, Slot{similar,contrast,outsider}, Emerge, RejectCloud, why, subconscious-provenance. C2→C3 ребро: **да, использует** class/lifecycle/importance как флаги, не как бюджет O. Принимаю.

[Математик]: Принимаю. Численные λ, τ, обучение — v2/C5. K-дефолты именованы, пересмотр по метрикам — не эта комната.

[Teamlead]: Вердикт комнаты — **да, спецификация C3 принята**. Связка на потом: реализация lift+DTO — Структурщик с Математиком; провод вызова — C6/C4 по принадлежности; LGTM будет по инвариантам авторства и |cloud|. Кто сдаст top-K без MMR и without why — BLOCK.

[Верстальщик]: Принимаю. Метки протокола и emerged ⊆ items — моя планка на ревью витрины следа.

[Музыкант]: Принимаю. Два аутсайдера и contrast живы — иначе снова автотюн.

| Лифт vs память | **Разделены.** Лифт = `buildSubconsciousCloud` (retrieval+fusion+MMR+слоты). Память/акт = судящее звено персоны: `emerge`+`why` или `reject_cloud`+`reason`. Лифт не пишет «персона вспомнила». |
| Форма облака | `Cloud = { cloudId, queryPlan, slots, items[] }`; item: id, provenance, snippetRef/summary, class/lifecycle/importance?, flags?, slot∈{similar,contrast,outsider}. \|items\|≤**10**. |
| Слоты и квоты v1 | **similar** ≤5 (после MMR); **contrast** ≤3; **outsider** =1..2 (дефолт 2). Пустой слот при no-hit — честная пустота, без padding. |
| Мультизапрос v1 | Закрытые оси: **Q_topic**, **Q_contrast** (парафраз/шаблон negation), **Q_dispute** (конфликт/опровержение). **Q_analogy — v2**. queryPlan логируется; reduced plan допустим и видим. |
| MMR / diversity | Обязателен на слоте similar (и при слиянии near-dup). Outsider: выбор из хвоста sim, id∉similar∪contrast, sim ниже порога-константы τ (значение — C5/v2). |
| Веса резонанса v1 | **Ординальные флаги**, не float-ranker: conflict, ownerQuote, pinned, classRank (C2), recencyBucket. Learned λ/τ/weights — **v2**. |
| Использование C2 | **Да (ребро C2→C3):** meta class/lifecycle/importance — признаки фильтра/ранга облака. **Нет:** облако ≠ selectOperational; бюджет B оперативной не применяется к cloud. |
| Корпус | Archive персоны (C1). O не корпус всплытия; **de-dup** `notAlreadyOperational(prov)`. Только своя A_p (cross-persona — v2). |
| Акт всплытия | Персона выбирает 0..N из items; **∀ emerged: why≠∅ ∧ id∈items**. Право **reject** всего cloud с reason; тогда emerged=∅. Секретарь/скрипт не выбирает за роль. |
| Провенанс в протоколе | Явная метка `subconscious` + provenance/id + who(persona) + why \| `cloud_rejected`+reason. Запрет sole-why из machine flag. |
| Живой носитель v1 | Один retrieval-порт (развитие `retrieveRagContext`) → backend archive; **не** второй параллельный RAG-стек. |
| v2 (именованные слоты) | analogy-query; калибровка λ/τ; learned rerank; serendipity>2/политики; cross-persona; auto pre-rerank только внутри lift с меткой в queryPlan и без отмены акта персоны. |
| Когда звать / метрики / extractor | **Не решено здесь** (C4 / C5 / C6). |

**Definition of Done (C3 — контракт, не полный прод-провод):**

1. Зафиксированы леммы Lift / Cloud / QueryPlan / Slot / Emerge / Reject и инварианты: \|items\|≤10, \|outsider\|≤2, emerged⊆items, why≠∅, rejected⇒emerged=∅.
2. Спека мультизапроса v1 (topic|contrast|dispute) + MMR на similar + serendipity-outsider + ординальные флаги (в т.ч. join C2-meta) + de-dup против O.
3. Норма протокола: метки subconscious-provenance и запрет авто-«вспомнил» от лифта.
4. Граница модулей: lift не judge; persona не штатно читает сырой archive в обход lift; один embedding/retrieval port.
5. Явный список v2-слотов (не реализовывать в DoD C3).
6. Вне DoD C3: cron/утренний вызов (C4), retrieval-recall и «утонуло» (C5), провод в extractor/yarn consilium code (C6), обучение весов.
