# Консилиум: В2 — Словарь состояний зонд-снимка и владелец словаря

**Повестка:** Каким закрытым словарём состояний живёт зонд-снимок и кто владелец словаря? Словарь + отображение органов + судьба «не состоялась» + владелец и акт расширения.

[Teamlead]: Открываю комнату M3. Три вопроса, один вердикт. Напоминаю: зубы и такт — не наши. Работаем только по словарю. Первый вопрос практический — берём ли пять состояний `net:diag` дословно или вводим свой словарь. Второй — судьба класса кода 2 («не состоялась»): в словарь или на отдельную ось. Третий — чей файл несёт словарь как источник истины и каков акт расширения. Гоним по порядку, без расползания.

[Математик]: Смотрю на пять состояний `net:diag`: `ok`, `degraded`, `down`, `unknown`, `partial`. Это измеримое множество с тестом — посылка комнаты говорит прямо. Класс кода 2 у зонда — это не наблюдение состояния сети, это результат самого акта зондирования: зонд не выполнился. Смешивать «сеть деградирует» и «зонд упал» в одной оси — это потеря различимости. Нельзя вывести из `partial` или `unknown`, было ли зондирование успешным. Значит нужна отдельная ось.

[Структурщик]: Согласен с Дыниным по осям, уточняю по словарю. Если берём `net:diag` дословно, граница пакета чёткая: снимок ссылается на внешний словарь, и любое расширение `net:diag` автоматически меняет допустимые значения снимка — это скрытая связь. Если вводим свой словарь снимка, граница закрытая: `net:diag` → словарь снимка через явное отображение, расширение возможно только актом внутри нашего манифеста. Для закрытой схемы (а вердикт M1 говорит именно об этом) второй вариант обязателен. Свой словарь, явное отображение.

[Музыкант]: Слышу вопрос про «не состоялась» как про потерю сигнала, а не про качество сигнала. Это разные вещи: один канал говорит о форме волны, другой — о том, дошла ли волна вообще. Если записать «не состоялась» как отдельное состояние в том же словаре — получим полифонию там, где нужна монофония. Предлагаю: поле `outcome` (булево или enum `executed`/`failed`) отдельно от поля `status` со словарём состояний сети. Тогда при `outcome=failed` поле `status` либо отсутствует, либо несёт явный sentinel.

[Архитектор]: Конструкция проясняется. Два поля: `status` — словарь сетевого состояния, `outcome` — факт исполнения зонда. Но нужно зафиксировать точку отображения. `net:diag` несёт `ok`, `degraded`, `down`, `unknown`, `partial` — это пять значений органа-источника. Словарь снимка либо совпадает с ними дословно, либо добавляет/сужает. Я вижу основание взять эти пять без изменения имён, но объявить их словарём снимка явно в нашем манифесте. Отображение тогда — тождественное: `net:diag.X → snapshot.status = X` для каждого из пяти. Расширение возможно только через изменение нашего манифеста, а не через изменение `net:diag`.

[Верстальщик]: С витрины: если `status` и `outcome` — два разных поля, это должно быть видно в схеме снимка без угадывания. Закрытая схема M1 это поддерживает. Для UI важно, что при `outcome=failed` поле `status` не рисует ложный цвет состояния сети — значит sentinel или отсутствие значения обязательны. Но это детали схемы, не словаря. Словарь `status` — пять значений, явно перечисленных в манифесте снимка.

[Teamlead]: Хорошо, первый круг дал конструкцию. Фиксирую рабочую гипотезу: словарь снимка — свой, пять значений совпадают с `net:diag` по именам, отображение тождественное, объявлены в манифесте снимка. «Не состоялась» — отдельная ось `outcome`, не шестое состояние. Второй круг: проверяем владельца словаря и акт расширения. Кто несёт манифест?

[Математик]: Владелец словаря — тот, чей файл является источником истины и чья подпись нужна для изменения. Словарь состояний снимка — часть закрытой схемы снимка, а схема снимка объявлена вердиктом M1 как принадлежащая дому `docs/audit/network`. Значит файл-манифест словаря живёт там же. Владелец файла — тот, кто ведёт этот дом. По структуре вердиктов M0–M2, владелец дома — архитектор схемы аудита, а не `net:diag`. `net:diag` — поставщик органа, не хозяин схемы записи.

[Структурщик]: Уточняю «акт расширения» через термин. Расширение словаря — это добавление нового значения к перечислению `status`. Акт должен быть именованным и оставлять след: нельзя просто добавить строку в файл. Предлагаю: акт расширения — ADR-запись в `docs/audit/network`, подписанная архитектором схемы, с обоснованием нового значения и правилом отображения для органа, который его порождает. Без ADR-записи новое значение не легитимно.

[Музыкант]: Есть практический момент: если `net:diag` добавит шестое состояние — например `congested` — без нашего ADR, снимок его не примет. Это правильно: орган не диктует схеме записи. Но нужно описать поведение при встрече неизвестного значения от органа: либо `unknown` как fallback, либо ошибка валидации. Это граничное условие словаря, и его надо зафиксировать в том же манифесте.

[Архитектор]: Граничное условие Курёхина важное. Формулирую правило: при получении значения от органа, которое не входит в словарь снимка, зонд-снимок записывает `status = unknown` и добавляет поле `raw_status` с оригинальным значением органа. Это сохраняет данные и не ломает закрытый словарь. `unknown` уже есть в пяти — специального шестого значения не нужно.

[Верстальщик]: `raw_status` — поле схемы снимка, а не словаря. Правильно держать их раздельно. Словарь — это перечисление допустимых значений `status`. `raw_status` — вспомогательное поле для отладки. В манифесте словаря его не должно быть; оно принадлежит схеме полей (M1 или M2 уже это закрыли или закроют отдельно).

[Teamlead]: Верно. `raw_status` — не наш вопрос сегодня, это детали схемы. Наш вопрос: словарь `status` закрыт пятью именами. Возвращаю фокус: владелец. Дынин сказал — дом `docs/audit/network`, архитектор схемы аудита. Нужно назвать точнее: чей манифест/файл?

[Математик]: Файл-источник истины — это схема снимка в `docs/audit/network`. Вердикт M1 установил, что схема полей закрыта. Словарь состояний — часть этой схемы. Владелец — архитектор, чья подпись стоит на вердикте M1. По нашим посылкам вердикт M1 ратифицирован — значит архитектор этого дома уже назначен де-факто.

[Музыкант]: Добавлю про акт расширения практически: новое значение словаря добавляется только при появлении нового органа или нового класса сигнала, которого пять существующих не покрывают. Это содержательный порог, а не процедурный. ADR фиксирует орган-источник, значение и правило отображения. Без органа-источника новое значение — мусор.

[Архитектор]: Итого по конструкции. Словарь снимка: пять значений — `ok`, `degraded`, `down`, `unknown`, `partial`. ## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| **Словарь состояний снимка** | Собственный закрытый словарь поля `status`: пять значений — `ok`, `degraded`, `down`, `unknown`, `partial`. Словарь объявлен в файле схемы снимка (`docs/audit/network/schema.*`), а не наследуется прямо из `net:diag`. |
| **Отображение органов на словарь** | `net:diag` → `status`: тождественное по именам для всех пяти значений. Значение органа, не входящее в словарь снимка, отображается в `status = unknown`; оригинальное значение органа при этом может быть сохранено в отдельном вспомогательном поле схемы (за пределами словаря). |
| **Судьба «проверка не состоялась»** | Отдельная ось записи — поле `outcome` с закрытым перечислением `executed` / `failed`. Это не шестое значение словаря `status`. При `outcome = failed` поле `status` в снимке отсутствует или явно не интерпретируется. |
| **Владелец словаря** | Архитектор дома `docs/audit/network` — тот, чья подпись стоит на вердикте M1. Источник истины — файл схемы снимка в `docs/audit/network`. |
| **Акт расширения** | ADR-запись в `docs/audit/network`, подписанная архитектором. Содержание ADR: орган-источник нового значения, само значение, правило отображения органа на словарь снимка. Расширение без органа-источника не легитимно. Изменение `net:diag` само по себе не расширяет словарь снимка. |
