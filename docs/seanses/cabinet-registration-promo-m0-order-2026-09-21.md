## Итоговое решение консилиума

### Граф зависимостей кандидатов

```
Лендинг (мини-задание) ──── независимо, вне графа

К1 (грант и дверь)
  │
  ├──→ К2 (связь и ключ)
  │        │
  │        └──→ К3 (порядок и отказ)
  │
  └──→ К4-форма (лицо, параллельно К2)
           │
           └── уточняется по коду ответа из К3
               (минимальная зависимость, не блокирующая)
```

**Рёбра и их причины:**

| Ребро | Причина |
|---|---|
| К1 → К2 | Клиент строится под конкретную дверь и поле гранта; без К1 нет ни маршрута, ни контракта запроса |
| К1 → К3 | Порядок гашения опирается на дверь и флаг регистрации, решённые в К1 |
| К2 → К3 | К3 вызывает клиент офиса, созданный в К2 |
| К3 → К4 (уточнение) | Финальные коды ответа из К3 подтверждают имя эндпоинта для формы |

**Не-рёбра:**

| Отсутствующее ребро | Причина отсутствия |
|---|---|
| К2 ↛ К4 | Форма не зависит от реализации клиента — только от имени эндпоинта кабинета |
| К4 ↛ К2 | Форма не строит клиент и не трогает его файлы |
| Лендинг ↛ К1..К4 | Правка одной строки `deploy/root-site/index.html:154` не зависит ни от одного кандидата |
