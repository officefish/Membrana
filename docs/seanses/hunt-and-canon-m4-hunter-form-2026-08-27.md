# Консилиум: M4 · предмет и форма ночного обходчика

**Повестка:** H1 — чем является ночной обходчик: измерением по дереву с детерминированным выходом или суждением модели; граница допустимости модели; носитель и исполнитель; судьба трёх job'ов; форма отказа при неизмеримости.

[Верстальщик]: С витрины и с фактуры 12.07 одно лицо: «отчёт-чеклист» без доступа к `apps/client/src` полтора месяца читался как работа. Это ложь формы. M3 уже закрыл эталон — восемь `--color-*` в `docs/DESIGN.md` и таблица сопряжения DaisyUI. Дрейф токенов на экране — это либо совпало с каноном числом, либо нет. Мнению модели про цвет, который ей не показали, на витрине места нет.

[Математик]: Формализую. Измерение `M: Tree → {pass, fail, refused}` детерминировано: один и тот же снимок дерева даёт один и тот же выход. Суждение модели — стохастическое отображение промпта без дерева в текст. Три job'а охоты сейчас — второе, при `MAX_CONTEXT = 24_000` и явном «нет доступа к файлам». Вероятность честного статанализа при нулевом входе равна нулю; «чеклист вместо замера» — не значение `M`, а маскировка отказа. Отказ в форме отчёта запрещён M2 — значит при невозможности замера выход обязан быть `refused`, не prose-report.

[Архитектор]: Конструкция. Ночной обходчик — не рецензент и не «умный PR». Это измеритель по дереву в том же роде, что `yarn verify:*` и зубы. Граница модуля: вход — снимок репозитория и манифест предметов замера; выход — машинный вердикт. Путь GitHub → офис → LLM → PR — форма, которая не выдерживает нагрузки «факт»: офис 400 здесь симптом, а несущий дефект — отсутствие дерева у job. LLM за этой границей не исполнитель замера.

[Музыкант]: С тракта слышу тот же антипаттерн, что «зелёный CI без звука»: цепочка Claude→DeepSeek поёт чеклист, а микрофон (дерево) не подключён. Охота, которая не читает файлы, — это студия без кабеля. Рядом уже живут зубы, которые меряют факт. Ночной обходчик должен звучать как прогон verify, а не как импровизация модели о коде за стеной.

[Структурщик]: Леммы. «Обходчик» ≠ «NightHuntService-промпт». «Job охоты» ≠ «суждение LLM». Публичный контракт обходчика — словарная статья: читает дерево, пишет детерминированный результат. Три имени `design-token-drift`, `services-api-contract-drift`, `monorepo-dependency-graph` сейчас — синонимы одного обмана: модель без входа. Слабая связанность: измеритель не импортирует офисный LLM-контур как единственный путь правды. Носитель замера — дерево плюс скрипты/манифест правил; не промпт в `NightHuntService`.

[Teamlead]: Положение: полтора месяца принимали отказ-в-отчёте за матч. Это BLOCK по ценности, не «почти работало». Предмет M3 не переоткрываем — эталон цвета уже есть. Решение комнаты должно закрыть форму: обходчик = измерение, не мнение. Связка на исполнение после вердикта — Математик (контракт выхода) + Структурщик (границы пакета/job) + Верстальщик только если verify токенов требует канон DESIGN как вход. LLM из исполнителя замера — вон.

[Верстальщик]: Граница «модель ещё допустима» с моей стороны узкая: не в ночном вердикте «дрейф/не дрейф». Модель может помочь человеку написать новый зуб или таблицу сопряжения днём, под LGTM. Ночной прогон, который красит PR и архив, обязан быть числом и списком нарушений против восьми `--color-*` и сопряжения — как `verify-tailwind-coverage`, не как эссе.

[Математик]: Граница формально: модель допустима вне образа `M`. То есть не в функции, чей выход есть статус охоты, exit code и артефакт для архива. Допустима как автор черновика нового предиката (человек/ревью вливает в `verify:*`), не как runtime-оракул. Инвариант: `∀ runs: M(tree) = M(tree)`. У LLM инварианта нет. Три job'а: переписываются в `M` или сносятся; сохранение «как LLM-opinion» запрещено одним правилом.

[Архитектор]: Носитель — манифест предметов замера (что меряем) плюс сам снимок дерева как среда. Исполнитель — класс детерминированных прогонов: `yarn verify:*`, зубы, CI-шаг на хосте с checkout, без обязательного офисного LLM. `SilenceWatchdog` (M1) сторожит молчание ожидания прогона — мы его не переоткрываем; он не заменяет измеритель. Офисный `POST /v1/night-hunt/run-all` как единственный путь к «истине охоты» — убрать из несущей конструкции.

[Музыкант]: Когда измерить не удалось — не «отчёт с чеклистом для ручной проверки». Это как отдать в эфир тишину под видом трека. Форма: явный отказ прогона — ненулевой exit, статус `refused`/`error` в факте прогона, без PR-тела «вот вам чеклист». Архиватор (M2) уже знает: не чеканить ночь жизни из протухшего. Здесь то же: не чеканить «работу охоты» из текста модели.

[Структурщик]: Правило по трём job'ам одной фразой: **переписываются в детерминированный измеритель по дереву, если предмет выразим предикатом над файлами; иначе сносятся; как LLM-job не сохраняются.** `design-token-drift` — выразим (M3 дал эталон) → переписать в verify. `monorepo-dependency-graph` — рядом уже зубы графа зависимостей → переписать/слить с verify-классом. `services-api-contract-drift` — если контракт в репо машиночитаем — verify; если нет стабильного носителя контракта в дереве — снос, а не «спросить DeepSeek».

[Teamlead]: Принимаю правило Ожегова как планку. Никакого «оставим job, но аккуратнее промпт». Промпт без дерева — тренировка в самообмане. Кто исполняет: не модель. Носитель и исполнитель должны быть названы в вердикте без дымки. Дальше спорим только уточнения границ, не род обходчика.

Тогда `status = refused`, `exit ≠ 0`, в sink факта прогона — причина-код (`no-tree` | `no-etalone` | `tool-error`), **без** markdown-отчёта успеха и **без** открытия PR «с чеклистом». ## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| Чем является ночной обходчик? | **Измерением по дереву с детерминированным выходом** `M: Tree → {pass, fail, refused}`. Не суждением языковой модели. |
| Где граница, за которой модель ещё допустима? | **Вне образа `M` и вне ночного артефакта статуса.** Модель не читает дерево «за» job, не пишет вердикт охоты, не открывает PR-имитацию замера. Допустима только днём как помощь человеку в *написании* нового verify-предиката (вливание — ревью/LGTM), не как runtime-исполнитель обхода. Гибрид «verify + LLM в одном ночном job» — запрещён. |
| Кто **носитель**? | **Снимок дерева репозитория** + **манифест детерминированных правил замера** (скрипты/предикаты; для токенов вход эталона — `docs/DESIGN.md` и жизнь обоих домов, без переоткрытия M3). |
| Кто **исполнитель**? | **Раннер класса `yarn verify:*` / зубы / CI-job с checkout дерева.** Не `NightHuntService` LLM-цепочка и не путь «офис → LLM» как несущий исполнитель замера. (Сторож молчания M1 — соседний контур, не исполнитель замера.) |
| Три существующие job'а | По правилу **rewrite-or-remove**: переписываются в детерминированный измеритель по дереву, **если** предмет выразим предикатом над файлами; **иначе сносятся**. **Как LLM-job не сохраняются** (ветка «оставить суждение модели» закрыта). Ориентир: `design-token-drift` → verify по канону M3; `monorepo-dependency-graph` → verify/зуб графа; `services-api-contract-drift` → verify при машиночитаемом контракте в дереве, иначе снос. |
| Когда измерить **не удалось** | **Явный отказ прогона:** статус `refused` (или эквивалент ошибки инструмента), **ненулевой exit code**, запись причины в факт прогона (`no-tree` \| `no-etalone` \| `tool-error` и т.п.). **Запрещено:** отказ в форме отчёта, PR/markdown-чеклист «для ручной проверки» под видом выполненной работы, чеканка «ночи жизни» из пустого замера (согласование с M2). |

**Definition of Done (только M4 / H1):**

1. В каноне/ADR комнаты зафиксировано: ночной обходчик = детерминированное `M` по дереву; носитель и исполнитель — как в таблице.
2. Три job'а либо имеют (или заведены задачи на) детерминированный verify-эквивалент, либо удалены из ночного манифеста; нулевое число LLM-opinion job'ов в ночном контуре.
3. Контракт неизмеримости: `refused` + ненулевой exit + факт причины; нет пути, где отсутствие дерева порождает «успешный» отчёт-чеклист/PR.
4. Путь «GitHub → office → LLM → PR» не является исполнителем ночного замера; несущий путь — checkout → verify/зубы → факт прогона.
5. Регрессия детерминизма: два прогона на одном SHA → тот же статус `M` (зуб на класс).
6. M1/M2/M3 не изменены этой комнатой; предмет токенов не переопределялся.
