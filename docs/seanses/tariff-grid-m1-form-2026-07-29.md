## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| Чем является объект «тарифная сетка» | **Versioned декларативный контракт** `TariffGridDocument`: **EntitlementRegistry** + **матрица SKU × entitlementId → EntitlementValue**. Не UI-таблица, не «набор квот», не пять подсистем. |
| Выбранная форма (альтернативы) | **C — контракт «право × тариф» с kind-discriminated union.** A «только квоты на тарифе» — отклонена (не выражает 3–5 роды). B «boolean-таблица прав» — отклонена (не выражает квоты/каталоги). D «пять отдельных истин» — отклонена (расхождение). |
| Как уживаются 5 родов | Один registry id + **закрытый kind** и payload: `quota{limit,unit}`, `catalog{catalogId}`, `instrument{enabled}`, `gated{enabled}` + preconditionId на определении права, `produce{enabled,scope?}`. Ячейка тарифа заполняет payload рода; не сводит всё к number/bool. |
| Источник истины (home) | **Server-side canon** контура office (тарифный модуль/конфиг). Клиент получает **wire DTO** и пользуется **pure resolve** (типы/хелперы в core или согласованном types-слое). Плагины/board/UI — потребители проекции, не авторы сетки. |
| Политика отсутствия | **Deny-by-default**: нет ячейки / mismatch kind / неизвестный id → not_entitled. Полнота: ∀ SKU ∀ registry id — ячейка (complete). |
| Чтение (resolve) | Pure `resolveEntitlement(grid, sku, id)` → entitled/not_entitled + payload + **unmetPreconditions[]** (условие не схлопывать в not_entitled). Троичность продуктового UX — M3. |
| Стык с существующим | Рельс `entitledTariffSkus` **не ломается**; M1 обобщает форму, M2 стыкует сценарии. AdminGuard ≠ tariff entitlement (разные оси). |
| Пример разделения смысла | «YAMNet 250/600» = **instrument.yamnet** + **dataset.sounds{catalogId}**, не одна клетка. Hot/cold storage — **два quota id**. User scenario slots — quota; «производить своё» — produce. |
| Precondition / produce / сеть | В форме — ссылки и флаги; реализация сети, пайплайна produce, провода в детекторы/палитру — **не M1**. |
| Монотонность тарифов | Желаемый инвариант sensor ≺ checkpoint ≺ observatory; не жёсткий закон формы v1. |
