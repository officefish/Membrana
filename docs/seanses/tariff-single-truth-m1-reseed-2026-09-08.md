# Консилиум: M1 (R) Пересев производных из матрицы

**Повестка:** Заседание «Тариф как единая правда» — M1 (R): как из релиза матрицы рождаются и обновляются производные (сетка → база кабинета → записи приборов), чтобы правда была одна.

**Участники:** Архитектор (Vesnin), Teamlead (Tarasov), Верстальщик (Rodchenko), Математик (Dynin), Музыкант (Kuryokhin), Структурщик (Ozhegov).

[Архитектор]: Конструкция M1 — четыре звена одной трубы: релиз матрицы (контейнер strategic-docs) → сетка (`tariff-grid.json`) → база кабинета (таблица `Tariff`) → запись прибора на сервере записей. Источник правды один; три нижних — производные. Форму гранул не трогаем (#2331, Б). Вопрос комнаты — кто зовёт пересев, как едет версия контракта, какие зубы и как переехать без остановки прода.

[Teamlead]: Планка: один глагол «пересев», одна команда на генерацию сетки, дальше — проекции по событию. Не плодим параллельных «ручных правок сетки» и «сидов базы мимо релиза». Связка на исполнение после вердикта: Математик (зубы/CI), Структурщик (границы пакетов и вызов), кабинет/records — носители проекций. BLOCK любому PR, который правит `tariff-grid.json` руками.

[Верстальщик]: С витрины кабинета: реестр квот и витрина тарифов уже читают пересечение сетки и базы. Оператору не нужен «экран пересева». Нужен честный статус расхождения, если зуб красный: «сетка/база не совпали с релизом» — данные, не декорация. Кнопок «поправить тариф в UI» на производных не рисуем — это нарушит единую правду.

[Математик]: Формализую. Пусть `R` — релиз матрицы с монотонной `contractVersion` (целое или semver-comparable). `G = reseed(R)`, `B = project_cabinet(G, v)`, `D_i = project_device(B, v)` для приборов. Инвариант: `version(G) = version(B) = version(D_i) = version(R)`. Предикат расхождения: любое `≠` по каноническому слепку квотных полей → fail. Запрет ручной правки: `G` и строки `B`/`D`, порождённые пересевом, не входят в domain ручного write.

[Музыкант]: С края тракта прибора: сегодня прибор о переходе тарифа не узнаёт (#2323). Значит «версия контракта до прибора» — это не косметика, а партитура: без неё edge играет по старой квоте, пока кабинет уже в новой. Событие разноски должно нести `contractVersion` явно; прибор (или хотя бы запись прибора на records) отличает «новая правда» от «старая».

[Структурщик]: Словарь строго: релиз ≠ сетка ≠ база кабинета ≠ запись прибора. Пересев — генерация производных командой, не «миграция руками». Граница пакетов: команда `yarn tariff:reseed` живёт у матрицы/docs-контура (как даёт #2331), читает релиз, пишет только сетку. Кабинет не импортирует гранулы напрямую. Records не читает сетку — только то, что разнёс кабинет. Слабая связанность: один поток вниз, без обратных «подкруток».

[Архитектор]: Цепочка вызова (а). Шаг 1: merge релиза матрицы в контейнере. Шаг 2: CI на merge зовёт `yarn tariff:reseed` → пересобирает сетку из релиза и зуб «сетка ≡ релиз». Шаг 3: деплой/старт кабинета (или явная follow-up команда проекции) применяет сетку к базе кабинета с той же `contractVersion`. Шаг 4: кабинет шлёт событие перехода/разноски на records → обновление записей приборов. Человек зовёт пересев только как ручной rerun той же команды при инциденте — не отдельный «ручной канон».

[Teamlead]: Кто зовёт — фиксирую порядком приоритета: (1) CI на merge релиза — основной; (2) человек по слову — тот же `yarn tariff:reseed`, без ветвления логики; (3) кабинет при старте — не пересобирает сетку из гранул, а сверяет/дотягивает базу кабинета к сетке образа и при расхождении краснеет или проецирует в сторону сетки. Кабинет при старте не является автором релиза. Принимаю эту иерархию как норму исполнения.

[Верстальщик]: На переходный период витрина не должна показывать «1 ГБ free» из базы против «512 МБ» из сетки без сигнала. Либо после проекции цифры совпадают, либо зуб/баннер расхождения в админ-контуре — не в пользовательской сказке. Пользовательская витрина читает уже согласованную проекцию; сырой конфликт трёх носителей ей не отдаём.

[Математик]: (б) Нумерация. `contractVersion` — атрибут релиза (паспорт/манифест релиза матрицы), монотонно растёт при любом изменении гранул, влияющем на производные. Сетка несёт то же поле. Событие кабинет→records: payload включает `contractVersion`, идентификаторы тарифов и квотные поля слепка. Запись прибора хранит `contractVersion` последнего применённого слепка. «Новая правда»: `v_incoming > v_stored`; «старая»: `≤` — идемпотентный no-op.

[Музыкант]: Прибор в поле может быть офлайн. Версия на записи прибора на сервере записей — обязательный носитель; сам MCU/edge получает факт при следующем контакте/конфиге, если когда-то научится (#2323 — сейчас дыра). M1 не обязан чинить UX прибора целиком, но обязан: records.device держит версию и квоты из события, иначе оркестр снова расходится.

[Структурщик]: Носители по слоям. Матрица/релиз — strategic-docs контейнер. Сетка — артефакт репо/образа (`docs/tariffs/tariff-grid.json` или преемник пути после reseed). База кабинета — таблица `Tariff` (+ метаданные версии контракта на уровне схемы или строки каталога). Запись прибора — records `Device` (квоты, каталог, политика — как сегодняшняя разноска). Запрещён второй канал «records читает сетку из файла».

[Архитектор]: (в) Зубы. Зуб 1: релиз ↔ сетка — владелец CI/команда reseed; краснеет pipeline; чинит пересборка, не ручной diff сетки. Зуб 2: сетка ↔ база кабинета — владелец кабинета (старт или job проекции); краснеет health/migrate gate; чинит повторная проекция из сетки. Зуб 3: база кабинета ↔ записи приборов — владелец разноски кабинета; счётчик «обновлено/не удалось» уже в фактуре; чинит retry разноски, не SQL на records в обход. Ручная правка производных — предикат отказа в CI (hash/canonical dump).

[Teamlead]: Запрет ручной правки — не code review «пожалуйста». Предикат: PR, трогающий сетку вне выхода `tariff:reseed`, — красный. PR, сидящий seed SQL в `Tariff` мимо проекции из сетки, — красный. Hotfix на проде правкой строки тарифа — инцидент с откатом в сторону релиза. Связка: Математик описывает canonical equality, Структурщик вешает гейт.

[Верстальщик]: Зуб для оператора/админа — только отображение статуса версии контракта и «проекция актуальна / отстаёт», без полей edit на квотах тарифа. Конструктивизм: tabular-nums версии, дата релиза, без «исправить на 1 ГБ» в форме. Иначе UI станет четвёртым носителем правды.

[Математик]: Canonical equality для зубьев: нормализовать единицы к байтам, сортировать ключи тарифов, сравнивать множество id тарифов и квотные скаляры, плюс `contractVersion`. Не сравнивать косметику markdown гранул. Зуб 1 уже обещан спринтом Б. Зуб 2: `∀ t ∈ Tariffs_B: slice(t) = G[t]` и покрытие id. Зуб 3: после успешной разноски `D.quota_* = B.quota_*` и `D.contractVersion = B.contractVersion`.

[Музыкант]: Эпизод переполнения в памяти процесса records (#2319) — не носитель тарифной правды. Не смешивать overflow hold с версией контракта. Версия контракта — про каталог/квоты; overflow — про эпизод. Иначе при пересеве «почистим память» и потеряем hold, или наоборот — зашьём тариф в эфемер.

[Структурщик]: Команда. Имя не плодим: `yarn tariff:reseed` — единственный генератор сетки из релиза (данность #2331). Отдельно (если ещё нет) — `tariff:project-cabinet` или расширение reseed-пайплайна: читать сетку → upsert базы кабинета. Не называть это «reseed матрицы». Глагол пересев в словаре повестки — про производные; матрица — вход. Вызов project — CI после reseed и/или кабинет при старте в режиме reconcile.

[Архитектор]: (г) Переходный период без остановки прода. Фаза 0: релиз матрицы отражает целевую правду (вкл. free 512 МБ, если так решено в гранулах — не мы здесь выбираем число). Фаза 1: CI reseed → сетка в образе; зуб 1 зелёный; прод ещё может нести старую базу. Фаза 2: rolling deploy кабинета с reconcile: база кабинета проецируется из сетки (free 1 ГБ → значение из сетки) под новой `contractVersion`; без ручного SQL. Фаза 3: массовая разноска события на все записи приборов с той же версией; retry по «не удалось». Фаза 4: зуб 2–3 в мониторинге; рукописный канон сетки снят.

[Teamlead]: Прод не останавливаем: reconcile онлайн, идемпотентный upsert, разноска со счётом. Окно риска — расхождение база/приборы на время фазы 3; митигация — версия контракта и повторная разноска, не maintenance night «всем лечь». Owner-порядок: сначала пайплайн reseed+зубы, потом project-cabinet, потом batch-device-sync. Не открываем M2–M5 в этом PR.

[Верстальщик]: На фазах 2–3 витрина должна брать числа из базы после проекции (или из API, уже согласованного), а не из «закэшированного 1 ГБ» в клиенте. Сброс кэша каталога тарифов при росте `contractVersion` — обязательный UX-инвариант, иначе оператор сутки видит старую правду.

[Математик]: Идемпотентность: `project(B, G, v)` при уже `B.version = v` и equality — no-op success. Разноска на device при `D.version ≥ v` — no-op. Это убирает thrash при рестартах кабинета. Для free 1 ГБ → 512 МБ: M1 только доставляет новое число-носитель; «что делать с уже занятым объёмом» — M2/M4, сюда не лезем.

[Музыкант]: Полевые приборы во время фазы 3: records уже с новой квотой, edge может ещё не знать. Отказы buffer-full-stop остаются контрактом records; партия не ломается, если сервер — источник отказа. Главное — не оставить records на старой 1 ГБ после того, как база кабинета уже 512 МБ: разноска приоритетнее «красивого UI на edge».

[Структурщик]: Что строить: (1) пайплайн CI merge релиза → `tariff:reseed` → артефакт сетки; (2) зуб equality релиз↔сетка; (3) проектор сетка→база кабинета с записью `contractVersion`; (4) расширение события разноски полем `contractVersion`; (5) хранение версии на записи прибора; (6) batch reconcile устройств; (7) гейт «сетка не рукописная». Что НЕ строить: форму гранул; UI редактора тарифов; records→grid reader; умную очистку; оплату; логику raise/lower (M3/M4); наборы (M5); функцию «доступная квота» (M2).

## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| (а) Цепочка пересева | **Релиз → сетка → база кабинета → записи приборов.** (1) Merge релиза матрицы в strategic-docs. (2) **CI на merge** вызывает `yarn tariff:reseed` → пишет сетку. (3) **Проекция** сетки в базу кабинета (`contractVersion` тот же): CI follow-up и/или **кабинет при старте = reconcile к сетке образа**, не чтение гранул. (4) Кабинет **событием разноски** обновляет записи приборов на сервере записей (существующий канал привязки/смены тарифа + batch на переезд). **Человек по слову** — только тот же `tariff:reseed` / rerun проекции при инциденте, без отдельной логики. |
| (а) Кто что зовёт | **CI** — рождение сетки из релиза (основной). **Человек** — ручной rerun той же команды. **Кабинет при старте** — сверка/дотяг базы кабинета к сетке, не автор релиза. **Кабинет (runtime)** — событие до records. Records сетку не читает. |
| (б) Версия контракта | **`contractVersion`** — монотонный атрибут **релиза**; копируется в сетку, в базу кабинета, в payload события разноски и в **запись прибора**. Прибор/records: `v_incoming > v_stored` → применить; иначе идемпотентный no-op. Не использовать `updatedAt` как версию. Edge сегодня может не слушать (#2323); **запись прибора обязана хранить версию** уже в M1. |
| (в) Зубы расхождения | **Зуб1 релиз↔сетка:** CI/reseed; краснеет pipeline; чинит пересборка. **Зуб2 сетка↔база кабинета:** кабинет reconcile/gate; чинит повторная проекция из сетки. **Зуб3 база↔записи приборов:** счётчик разноски; чинит retry события. Equality: canonical dump квотных полей + id тарифов + `contractVersion`. **Запрет ручной правки производных — предикат CI/гейта**, не просьба в review. |
| (г) Переходный период | Онлайн, без stop прода: reseed сетки → rolling cabinet reconcile (free 1 ГБ уходит значением из сетки/релиза, не ручным SQL) → batch-событие на все записи приборов с новой версией → мониторинг зубов 2–3. Lag только по трубе вниз; середину руками не правим. Поведение при переполнении уже занятого объёма — **не M1** (M2/M4). |
| Что строить | Пайплайн reseed+зуб1; проектор сетка→база+версия; поле версии в событии и на Device; batch disperse; гейт «сетка только из reseed»; идемпотентность project/disperse; сброс кэша витрины при новой версии. |
| Что НЕ строить | Форма гранул/шаблона (#2331 Б); «доступная квота»/право (M2); raise (M3); lower/холод (M4); наборы (M5); smart-cleanup; оплата; records→grid; UI-редактор квот; версия overflow-памяти процесса как тарифная правда. |
| Носители | **Матрица/релиз:** strategic-docs. **Сетка:** артефакт reseed в образе. **База кабинета:** кабинет. **Событие+версия:** кабинет→records. **Запись прибора:** сервер записей. **Прибор (edge):** later/#2323, не блокер M1. |

### Definition of Done (M1)

1. Merge релиза матрицы в CI выполняет `yarn tariff:reseed`; зуб **релиз ↔ сетка** краснеет pipeline при расхождении.
2. Гейт/policy: изменения сетки вне выхода reseed не проходят; seed SQL базы кабинета мимо проекции из сетки не проходит.
3. Проектор сетка → база кабинета пишет те же квотные поля и **`contractVersion`**; старт кабинета reconcile-ит к сетке образа идемпотентно.
4. Событие разноски кабинет → records несёт **`contractVersion`**; запись прибора хранит версию и квоты; apply идемпотентен.
5. Batch-переезд существующих приборов со счётом «обновлено/не удалось» и retry; прод без global stop.
6. После переезда: нет пользовательской витрины с конфликтом «1 ГБ vs сетка»; клиентский кэш каталога сбрасывается при росте версии.
7. В коде/доках словарь: релиз, сетка, база кабинета, запись прибора, пересев, версия контракта — без подмены синонимами-слоями.
8. Нет в поставке M1: логики M2–M5, формы гранул, reader сетки на records, ручных prod-SQL «поправить free».
