# Консилиум: M4 — понижение тарифа и холодное хранилище как носитель

**Повестка:** Q4 (прогон 2) — носитель холода, отбор избытка, ворота, неделя, откат и долг, судьба ячейки `storage.cold` по четырём читателям, удержание при падении лимита ниже занятого.

**Участники:** Teamlead (Tarasov), Архитектор (Vesnin), Математик (Dynin), Музыкант (Kuryokhin), Структурщик (Ozhegov), Верстальщик (Rodchenko).

**Порядок реплик:** Teamlead → Архитектор → Математик → Музыкант → Структурщик → Верстальщик

**Переопределения до первого употребления:** холод не есть удержание — это статус пробы на сервере записей со сроком; занято есть сумма размеров только тёплых проб; свободно по M2 есть `max(0, лимит − занято)`.

[Teamlead]: Планка прогона 2 жёсткая: держащееся из прогона 1 — данность, две поправки фактуры закрываем явно, M1–M3 не трогаем. Цель комнаты — один носитель холода, явный отбор избытка, ворота, неделя, откат, четыре читателя ячейки, удержание после понижения. Без второго носителя правды. Связка: Архитектор — форма, Математик — предикаты и отбор, Структурщик — двери и пакеты, Музыкант — сценарии доски, Верстальщик — витрина статуса.

[Архитектор]: Конструкция. Холод живёт на пробе сервера записей: два поля статуса и срока, не на коллекции и не на записи прибора. Удержание — отдельный контур прибора и клиента; смешивать нельзя. Момент: приём новых лимитов и отбор избытка — одна атомарная разноска на сервере записей, окна «лимит уже новый, отбор ещё нет» нет. Исполнитель отбора — сервер записей в ходе приёма лимитов, не кабинет и не прибор.

[Математик]: Формализую отбор. Пусть тёплые пробы прибора упорядочены по возрастанию времени создания. Копим префикс, пока сумма размеров ≤ L′ · (1 − σ), где L′ — новый лимит оси, σ = 0,10 — запас ниже порога стопа 0,95. Хвост — избыток, уходит в холод. Так после отбора заполнение тёплых ≤ 0,90, страж 0,95 сам не встаёт. Занято := сумма тёплых; свободно := max(0, L′ − занято). Холод в занято не входит.

[Музыкант]: С края тракта: сценарии доски сейчас читают любые пробы без оглядки. Холодная проба в цепочке сценария — фальшь партитуры. Ворота «нельзя в сценарий» ставим на сервере записей в модуле сценариев: холодная не выбирается и не стартует. Экспорт звука из холода оставляем — вывоз вещдока слышен и законен по T4.

[Структурщик]: Словарь дверей. Носитель ворот — сервер записей, слой проб и слой сценариев, не библиотека-клиент. Закрыты: правка, перенос, сценарии. Открыты: экспорт (обе двери), удаление человеком. Список проб обязан нести поле статуса в ответе, иначе библиотека не отличит тёплую от холодной. Второго словаря статуса на клиенте не заводим: один термин — один смысл.

[Верстальщик]: С витрины: оператор в библиотеке видит холодную пробу с явной меткой статуса и сроком; действия правка и перенос неактивны, экспорт и удаление — активны. Доска не предлагает холодные в палитре сценария. Кабинет после понижения уже показывает новый тариф; занятое по-прежнему не рисует — и не должен врать. Отдельной «страницы холода» не строим: статус — свойство строки пробы.

[Teamlead]: Фиксирую развилку удержания по поправке 2: сегодня понижение само поднимает удержание через заполнение ≥ 0,95. Вариант Математика с запасом 0,10 снимает авто-стоп после правильного отбора. Оставшийся хвост — снять уже взведённое удержание при завершённом отборе, иначе человек тащит чужой долг. Это работа в «строить», не запрет.

[Архитектор]: Согласен. Поведение удержания: после атомарного приёма лимитов с отбором сервер записей отдаёт занято только по тёплым; клиентский страж перечитывает и не активирует стоп, если заполнение < 0,95. Если удержание уже стояло до отбора — снимаем машинно по факту «отбор завершён и заполнение тёплых ниже порога», без права кабинета откатывать право тарифа. M3 про «снимает только человек» относится к эпизоду переполнения, не к ложному стопу от понижения.

[Математик]: Уточняю инвариант недели. Срок холода — метка времени на пробе, считает сервер записей. По истечении семи суток процесс сервера записей удаляет холодные пробы от имени компании. Норма 31.08 про «чистит только человек» — только про данные внутри тарифа, то есть тёплые; T5 закрывает холод. В холодную неделю занято = сумма тёплых; свободно = max(0, лимит − занято); холодные байты в обе величины не входят.

[Музыкант]: Откат по T8: обратное повышение внутри недели снимает статус холода с проб без потери байтов — пробы снова тёплые, срок обнуляется. Долг квоты не копим: квота не отрицательна, избыток был явным сценарием, не арифметикой ниже нуля. После отката сценарии снова могут брать эти пробы — ворота открываются статусом, не отдельной «амнистией» доски.

[Структурщик]: Ячейка `storage.cold` — не ось квоты. Судьба: уходит из сетки и матрицы как обещание лимита. Четыре читателя и предикаты: (1) класс памяти в `quota-ledger.ts` — вычеркнуть `'cold'` из закрытого союза; (2) пара сверки в `tariff-grid-check.mjs` — убрать ожидание ключа; (3) колонка продуктовых docs — убрать столбец холода; (4) скаляр `coldStorageQuotaMiB` — удалить ключ и текст причины. Рантайм-квоту по холоду не вводим.

[Верстальщик]: Продуктовая страница тарифов после снятия столбца не должна оставлять пустую дыру: сетка колонок пересобирается без холода, без «скоро». В библиотеке поле статуса в карточке/строке — короткий текст «в холоде» и дата конца срока, `tabular-nums`, без декора. Пустой холод не рисуем отдельным блоком.

[Teamlead]: Атомарность ещё раз, одной строкой: окна между новым лимитом и завершённым отбором нет — разноска лимитов на запись прибора и перевод хвоста проб в холод совершаются в одной процедуре приёма на сервере записей. Кабинет не считает отбор. Прибор не выбирает избыток.

[Архитектор]: Правило отбора — уточнение исполнителя. Сервер записей после записи новых лимитов на прибор: читает тёплые пробы оси, применяет префикс с запасом σ, помечает хвост статусом холода и сроком = now+7 суток. Системные наборы вне квоты не участвуют. Коллекция не становится «холодной» целиком — только пробы.

[Математик]: Предикат готовности отбора: после процедуры ∀ прибор: sum(size(тёплые)) ≤ L′ · 0,90 либо тёплых нет; ∀ проба избытка: статус=холод ∧ срок задан. Красный вход — sum(тёплые) > L′. Кто чинит — сервер записей. Страж удержания не является частью отбора.

[Музыкант]: Библиотека и доска «что видят»: библиотека видит все пробы мембраны, включая холодные, с полем статуса; доска видит для выбора в сценарий только тёплые. Это не два API правды, а фильтр двери сценариев и честный список проб. Иначе оператор теряет вывоз из холода.

[Структурщик]: Место ворот по дверям ствола. Список `:53` — отдаёт статус; загрузка `:68` — без изменения (отказ по свободному); экспорт `:120` и open-api `:97` — открыты для холодных; удаление `:151` — открыто; перенос `:164` и правка `:181` — отказ по статусу холод; сценарии `device-scenarios` — отказ включения холодной. Ворот на кабинете нет.

[Верстальщик]: Отказ дверей в UI: тост/reason «проба в холоде», без снятия строки из списка. Кнопки переноса и правки disabled с той же причиной. Экспорт доступен. Это конструкция факта, не новая модалка эпизода — окно полного буфера не подменяем.

[Teamlead]: Что не строим: отдельную ось квоты холода, колонку на строке тарифа, второй носитель статуса на клиенте, умную очистку, оплату/промо, пересев M1, функцию свободно M2, порядок событий M3, наборы M5. Что строим — ниже в решении списком. Проверки — с путём, одна краснота, один чинящий.

[Архитектор]: Носитель каждой части заранее: статус и срок — поля пробы; отбор — процедура приёма лимитов сервера записей; ворота — контроллеры/модули сервера записей; счёт недели и удаление по истечении — процесс сервера записей; занято/свободно — счётчик сервера записей только по тёплым; откат холода — та же процедура смены тарифа вверх внутри срока; ячейка сетки — документы и сверки, не рантайм; удержание — клиентский страж плюс снятие ложного стопа после отбора.

[Математик]: Поправка к ложному комментарию: `buffer-overflow-refusal.ts:99` утверждает «занято не больше лимита всегда» — при понижении до отбора это ложь, после отбора с занято=тёплые — снова истина. Предикат проверки: после приёма лимитов с отбором occupied_warm ≤ limit. Красный вход — occupied_warm > limit. Кто краснеет — тест сервера записей. Кто чинит — devices/samples на сервере записей.

[Музыкант]: Удаление по истечении срока — не «тихий сборщик» для тёплых. Только статус=холод и срок < now. Человек по-прежнему чистит тёплое внутри тарифа. Это согласует T5 и норму 31.08 без двусмысленности на слух оператора: неделя — плата компании за избыток, потом место освобождается.

[Структурщик]: Четыре предиката читателей ячейки, без дизъюнкций. (1) `quota-ledger.ts:31` — союз классов памяти не содержит `'cold'`; краснеет юнит контракта леджера; чинит cabinet domain. (2) `tariff-grid-check.mjs:180` — ключ холода отсутствует, сверка не ждёт пару; краснеет скрипт зуба сетки; чинит scripts/lib. (3) `product-docs-tariffs.mjs:9,16,169,182,198` — столбец холода не эмитится; краснеет сборка docs; чинит scripts/lib. (4) `tariff-scalars.json:15-16` — ключа `coldStorageQuotaMiB` нет; краснеет зуб скаляров; чинит docs/tariffs.

[Верстальщик]: Готовность UI одним именем на пункт: `coldStatusVisibleInSampleList` — список проб показывает статус. Не смешивать с тестом закрытых дверей. Закрытые двери — серверные предикаты; UI только отражает reason. Иначе снова слепим «строить» и «не строить».

[Teamlead]: Долг при откате: при обратном повышении внутри недели холод снимается, байты сохраняются, долга нет. При истечении срока до отката — пробы удалены, обратное повышение не воскрешает. Это судьба долга по T8: долг не начислялся; потери только после недели без отката.

[Архитектор]: Приём лимитов — существующий контур `devices.service.ts:174-197`; счёт занятого `:223-278` переводим на фильтр тёплых. Новых каналов кабинет→пробы не открываем. Разноска версии и права — как M3, без отката права. Холод не пишет кабинет.

[Математик]: Красные входы удержания. Путь `localGuard.ts:16-34` и `buffer-stop.ts:26,81-86`. Предикат после понижения с отбором: fill = occupied_warm/limit < 0,95 → страж не зовёт activate. Если отбор оставил бы fill ≥ 0,95 — красный (нарушение σ). Кто краснеет — тест клиентского стража на фикстуре понижения. Кто чинит — отбор на сервере, не порог стража. Порог 0,95 не меняем.

[Музыкант]: Ещё раз про открытые двери: экспорт холодной — да, обе двери; удаление человеком — да. Загрузка новой при свободно=0 — отказ как M2, не «в холод автоматически». Авто-перевод в холод только из процедуры понижения, не из текущей записи потока.
