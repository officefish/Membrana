# Консилиум: K2 — форма манифеста-отчёта `workspace-level`

**Повестка:** K2 — какова форма манифеста-отчёта, который `workspace-level` выдаёт по итогам гейта K4: что показывает, что в нём факт, куда ложится и как переживает обрыв сессии. Минимум три раздела (К-Rodchenko): влито в `main` / застряло почему поимённо / мусор найден поимённо. Отчёт верстает выход гейта (`baskets`/`status`/`reason[]`/`mainFill`), не пересчитывает `disposition`.

**Участники:** Teamlead (Vesnin), Структурщик (Ozhegov), Математик (Dynin), Музыкант (Kuryokhin), Верстальщик (Rodchenko).

**Порядок реплик:** Структурщик → Музыкант → Математик → Teamlead → Верстальщик

---

[Структурщик]: Начинаю с границы модуля. Манифест-отчёт — **представление** выхода гейта K4, не новый вычислитель. Публичный контракт: вход = артефакт гейта `{ status, reason[], baskets {L,R,U,T}, mainFill }`; выход = структурированный markdown/JSON-слепок с тремя обязательными разделами. Жить должен рядом с handoff-контуром, не внутри UI-стора и не в чат-памяти сессии.

[Музыкант]: Со стороны потока это как master-bus meter после сведения: не пересводим треки, а честно показываем, что доехало до шины. Если вечер видит только «3 ok / 2 fail» без имён — мусор и застрявшее прячутся, как клиппинг за усреднённым LUFS. Нужны поимённые дорожки: path, корзина, mainFill, stop-reason.

[Математик]: Контракт детерминирован: f(gate_output) → report. Без скрытого состояния, без повторного disposition. Факт = то, что воспроизводится из артефакта гейта байт-в-байт при повторной вёрстке. Любая фраза «кажется, надо решить владельцу» — либо вынесена в явную зону суждения, либо отсутствует. Счётчики как единственный слой — запрещены: они теряют инъективность path→строка.

[Teamlead]: Форма решения: отчёт — **вечерний артефакт уровня workspace**, шов к `HANDOFF.md` и вечернему ритуалу без переписывания их канона. K1/K4 не трогаем. K3 не проектируем — только оставляем точку расширения «фрейм прочитает тот же слепок». Вердикт комнаты обязан закрыть носитель + переживание обрыва + три раздела Rodchenko.

[Верстальщик]: Три раздела — несущая конструкция, не «вкладки по вкусу». (1) **Влито в main** — корзина R, mainFill=done, path поимённо. (2) **Застряло** — R с mainFill=failed|pending, U без карточки, плюс stop-reason/reason[] по каждому. (3) **Мусор найден** — корзина T поимённо. Иерархия: статус гейта и reason[] — в шапке; тело — списки; суждение владельца — отдельный приглушённый блок, если вообще нужен.

[Структурщик]: Носитель предлагаю так: файл-слепок в контуре handoff/вечернего артефакта (путь уровня workspace, не app-localStorage). Имя стабильное или с date-slug — на усмотрение ops-слоя, но **содержимое** собирается только из артефакта гейта. Связь: HANDOFF ссылается/включает отчёт как секцию или соседний файл; канон HANDOFF не переписываем — один шов «report accompanies handoff».

[Музыкант]: Переживание обрыва: если сессия умерла после гейта, отчёт всё равно собирается из лежащего gate-output. Это как render из session take, а не «я помню, что играли». Импровизация из чата — запрещена. Если gate-output нет — отчёт не выдумывается; статус «нет входа», пустые разделы с явной причиной.

[Математик]: Отображение выхода гейта на разделы, строго:
- `baskets.R` ∩ `mainFill=done` → раздел «Влито в main»;
- `baskets.R` ∩ `mainFill∈{failed,pending}` ∪ `baskets.U` (и иные non-done по норме M2) + элементы с stop-reason → «Застряло»;
- `baskets.T` → «Мусор найден»;
- `baskets.L` — не смешивать с «влито»: L в шапке/приложении как «вне контура mainFill» (факт корзины), без перекраски в R.
`status` + `reason[]` — только шапка отчёта, без пересчёта.

[Teamlead]: Согласен с картой корзин. Риск вечера: счётчики вместо имён = ложный green, мусор T не назван, U растворяется. Definition of Done комнаты — структура + носитель + правило обрыва; не код. Слово владельца — только там, где факт исчерпан (например выбор, что делать с застрявшим), и это не маскирует дырки в списках.

[Верстальщик]: Внутри каждого раздела строка-элемент минимум: `path` (или стабильный id сущности), `basket`, `mainFill` (если применимо), `stop-reason`/`reason` ссылка. Типографика отчёта (когда рисуем в UI позже): `tabular-nums` не нужен для path; списки — честные `<ul>`/markdown-list, без «три бейджа и всё ок». Empty state раздела: явная строка «(пусто)» — тоже факт, не молчание.

[Структурщик]: Словарь терминов отчёта = словарь гейта. Не вводить синонимы `trash`/`junk` рядом с T; не называть U «бэклог» в заголовке раздела. Заголовок раздела — по Rodchenko (человекочитаемо), внутри строки — канонические enum'ы M2. Публичный API сборщика: `buildWorkspaceLevelReport(gateOutput): ReportDocument` — чистая вёрстка, пакет/слой рядом с workspace-level, без импорта UI.

[Музыкант]: Латентность и объём не критичны: это post-gate, не realtime audio. Важнее целостность take. Если mainFill частично заполнен — не склеивать «почти влито» в done. Слуховой аналог: fade-out не считать hit. partial → раздел «Застряло» с mainFill=pending|failed как есть.

[Математик]: Факт vs суждение — разметка:
**Факт:** path, basket, status, reason[], mainFill, stop-reason, timestamp сборки, hash/idempotency ключ входа гейта (если есть в артефакте).
**Суждение:** отсутствует в теле трёх разделов по умолчанию; опциональный хвост «Вопросы владельцу» только как ссылки на застрявшие path без рекомендательного DSP/продуктового спина. Отчёт не говорит «надо смержить»; он говорит «не в main, mainFill=failed, reason=…».

[Teamlead]: Носитель фиксируем: **вечерний артефакт workspace-level**, стык с HANDOFF/ритуалом — «положен рядом / вложен ссылкой», без ревизии канона HANDOFF. Переживание обрыва: report = чистая функция от persisted gate-output; источник истины — диск/артефакт, не transcript. Принимаю три раздела как обязательный минимум; L — справочно в мета, не четвёртый «главный» раздел, чтобы не размыть Rodchenko-ось main/stuck/trash.

[Верстальщик]: Шапка отчёта (мета): `status`, `reason[]`, время сборки, указатель на входной артефакт гейта. Затем три раздела. Затем опционально «Корзина L (факт)» одним списком path — чтобы не потерять, но не конкурировать с «Влито». Визуально в markdown: `##` для трёх, `###` не плодить. Это конструкция, не журнал чата.

[Структурщик]: Зависимости: report-builder → читает только контракт M2-выхода; не тянет disposition-движок K1 и не зовёт gate runner. Слабая связанность: потребители (вечерний ритуал, позже K3-фреймы) читают ReportDocument, не лезут в сырые корзины в обход, *либо* сырой gate-output остаётся каноном, а report — presentation alias; предпочтение — **gate-output канон, report — детерминированный view**, чтобы не плодить два source of truth.

[Музыкант]: Если view расходится с каноном — это баг вёрстки, как неправильный routing bus. Регрессия: golden file gate-output → markdown/JSON report. Без этого обрыв сессии «переживают» словами, а не проверкой.

[Математик]: DoD на воспроизводимость: одинаковый gate-output ⇒ одинаковый report (стабильная сортировка path внутри раздела, стабильные заголовки). Timestamp сборки — единственное поле, которое может отличаться; для golden — исключать или нормализовать. Иначе «детерминизм» фиктивен.

[Teamlead]: Итожу к вердикту: да, форма принята. Отчёт — view над K4; три раздела; факты поимённо; носитель — вечерний артефакт со швом к HANDOFF; обрыв — через persisted gate-output + чистую сборку. K3 только читатель. Блокирую любые попытки в этом вердикте пересчитать baskets или переписать disposition.

[Верстальщик]: Принимаю. Риск счётчиков фиксируем в вердикте явно: вечер теряет имена T и U, false sense of completion. Пустые разделы видимы. Готовность к UI-слою позже не меняет markdown-контракт слепка.

[Структурщик]: Принимаю. Словарь и граница пакета зафиксированы; dual source of truth не вводим.

[Музыкант]: Принимаю. Слепок как render из take — ок.

[Математик]: Принимаю. f(gate_output)→report, golden-сортировка, факт/суждение разведены.

[Teamlead]: Принимаю. LGTM на форму решения K2; код не пишем — только вердикт.

[Верстальщик]: Ещё раз по пустому «Влито»: это не ошибка вёрстки, а валидный факт вечера. Не подменять empty state суждением «надо срочно что-то влить».

## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| Форма манифеста-отчёта | **Детерминированный view** (presentation) над persisted-выходом гейта K4; не вычислитель disposition/gate |
| Структура (минимум 3 раздела) | **(1) Влито в `main`** — path из R с `mainFill=done`, поимённо. **(2) Застряло** — path из R с `mainFill=failed\|pending`, U и прочие non-done по M2, у каждого reason/stop-reason. **(3) Мусор найден** — path из T, поимённо, названо |
| Шапка / мета | `status`, `reason[]`, указатель на входной gate-артефакт, время сборки; empty раздела = явная «(пусто)» |
| Корзина L | **Не** четвёртый главный раздел Rodchenko; справочный факт-список в мете/приложении, без перекраски в «влито» |
| Отображение K4 → разделы | R+done→(1); R+failed/pending ∪ U (+ stop-reason)→(2); T→(3); status/reason[]→шапка; L→мета. Без пересчёта baskets |
| Факт vs суждение | **Факт в теле:** path, basket, mainFill, status, reason[], stop-reason, ссылка на gate-артефакт. **Суждение:** не в трёх разделах; опциональный хвост «Вопросы владельцу» только как указатели на застрявшие path без предписаний |
| Носитель и место | **Вечерний артефакт `workspace-level`** (persisted файл/документ); шов к `HANDOFF.md`/вечернему ритуалу — ссылка или соседство, **канон HANDOFF не меняем** |
| Source of truth | Канон = **gate-output**; report = детерминированный view (`buildWorkspaceLevelReport`); не два канона |
| Переживание обрыва сессии | Сборка только из persisted gate-output; воспроизводима; без входа — отчёт не выдумывается («нет входа»). Стабильная сортировка path; timestamp нормализуем для сравнения |
| Счётчики | Запрещены как единственный слой; допустимы лишь как дополнение к поимённым спискам |
| K3 | Только будущий читатель того же слепка; рельсы не проектируем |
| Вердикт | **Принято** единогласно пятью ролями |

**Definition of Done (K2):**

1. В протоколе/вердикте зафиксированы три раздела Rodchenko + шапка + правило для L.
2. Явная таблица/правила отображения `baskets/status/reason/mainFill` → разделы без пересчёта disposition.
3. Разметка факт/суждение описана; суждение не маскирует дырки списков.
4. Носитель назван: вечерний артефакт workspace-level + шов к HANDOFF без переписи канона.
5. Свойство обрыва: report = f(persisted gate-output); запрет сборки из чата; поведение при отсутствии входа.
6. Зафиксирован риск счётчиков (потеря имён T/U, ложный green).
7. Нет кода, нет K3-раскладки, нет ревизии M1/M2/T1–T13 — только форма отчёта.
