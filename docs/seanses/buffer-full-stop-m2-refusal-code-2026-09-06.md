## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| **(а) Транспорт** | **Перейти на доменный отказ по конвенции кабинета: HTTP 200 + `{ ok: false, reason, … }`.** 413 как сигнал «буфер/хранилище полон» **не оставлять**. Почему: полный буфер — доменное ограничение складирования, не транспорт; 413 смешивает квоту с «тело слишком большое»; конвенция 12.08 уже так делает для тарифов; T16 (связь жива) лучше стыкуется с 200 JSON; ночь 6500×413 доказала, что голый статус без machine reason не останавливает прибор и не кормит окно. Транспортный 413 допустим **только** для реального лимита размера тела, без доменного `reason` квоты. |
| **(б) Машинный код и словарь** | Закрытый список `reason` (snake_case). **Базовый сценарий M2:** `device_buffer_full` — буфер прибора полон; `user_storage_full` — хранилище коллекций пользователя полно. **Место для прочих** — тот же union, литералы T15 **не назначаем** в этой комнате. Запрещены: HTTP-код как reason, общий `quota_exceeded` без субъекта, парсинг английского message. |
| **(в) Обязательные поля** | Помимо `ok` и `reason`: `buffer: { usedBytes, limitBytes }`, `userStorage: { usedBytes, limitBytes }` (те же оси, что `/quota`); `overflowPolicy: "stop" \| "smart_cleanup"` (сервер знает из M1); `overflowId` — opaque id **факта/эпизода** переполнения, стабильный на все отказы одного эпизода (однократность окна и сигнала vs 6500 ретраев). Человеческий message — не источник истины. |
| **(г) Носитель словаря** | **Единственный SOT — shared-пакет monorepo** (domain reject contract): union/enum `reason` + тип тела ответа. Читают: сервер записей, кабинет, прибор/клиент. **Пишет/чеканит литералы при отказе — сервер**; потребители — только импорт + exhaustiveness. Три копии строк — запрещены. |
| **Строить** | Контракт ответа загрузки пробы при квоте; shared-словарь; server mapper квота→Reject; тесты инвариантов (1)–(5). |
| **НЕ строить** | Остановку и память на приборе (M3); каналы после (M4); UI/кнопки окна (M5); тексты/коды прочих причин (T15); алгоритм умной очистки (T12); тарифы (#2297). |

**Definition of Done (только M2):**
- Загрузка пробы при превышении квоты буфера/хранилища возвращает **200**, тело с `ok: false` и `reason` ∈ {`device_buffer_full`, `user_storage_full`}.
- В теле присутствуют buffer/userStorage used+limit, `overflowPolicy`, `overflowId`.
- `device_buffer_full` и `user_storage_full` различимы тестом; не сводятся к одному коду.
- Словарь `reason` объявлен в **одном** shared-модуле; сервер и хотя бы один потребитель импортируют его (нет третьей локальной копии в PR).
- Регресс: ответ не опирается на 413 как на доменный сигнал квоты.
- В PR нет кода M3/M4/M5/T12/T15/#2297 «заодно».

# Заседание «Полный буфер: контракт остановки» — M2 (C) Код отказа и его словарь

**Объединяющее задание (одно на всё заседание):** превратить тезисы шторма 06.09 в исполнимый
контракт остановки при полном буфере — сервер, прибор, оператор, — чтобы ночь 05→06.09 не
повторилась и вещдоки в буфере не пострадали.

**Порядок M0 (ратифицирован владельцем 06.09):** M1 (P) политика → **M2 (C) код отказа** →
M3 (S) остановка на приборе → M4 (L) жизнь после → M5 (W) окно оператора. Предшественник —
M1; его вердикт — посылка этой комнаты.

## Данности (закрыто штормом, НЕ переоткрывать)

- Сигнал «полон» для прибора — отказ сервера с конкретным кодом ошибки; по коду прибор знает, что показать (T14).
- Другие причины отказа — тот же механизм, другие тексты; разбираются отдельно, позже; здесь — только базовый сценарий «буфер полон» (T15).
- При полном буфере связь не рвётся: ограничение только на складирование новых медиафайлов (T16).
- Окно оператора строится из ответа сервера, не из догадок прибора; в окне — свободное место по буферу и по коллекциям (T3, T4, T8).

## Вердикт M1 (посылка, не переоткрывать)

- Политика переполнения — поле в записи прибора на сервере записей, разносится из кабинета; клиентская настройка — зеркало.
- Умолчание fail-closed — `stop`; умная очистка выбираема только при полном наборе параметров, проверяет сервер.
- Следствие для этой комнаты: сервер знает режим прибора в момент отказа и может назвать его в ответе.

## Фактура (сверено в стволе da051639 и на проде 06.09)

- Сегодня при полном буфере сервер записей отвечает на загрузку пробы HTTP 413; текст различает «Buffer storage quota exceeded» и «User storage quota exceeded», но машинного кода причины нет ни у одного, чисел занято/лимит и режима в ответе нет; прибор по коду не отличит «буфер полон» от «хранилище полно» и от «слишком большое тело».
- Кабинет для доменных отказов держит конвенцию 12.08: транспортные 4xx только за транспорт, доменный отказ — 200 с полем `ok:false` и машинной причиной `reason` из закрытого списка (пример — тарифы: `unknown_target_tariff`, `same_tariff`, `self_gate_closed`).
- Ответ квоты прибора (`/quota`) уже несёт `buffer.usedBytes/limitBytes` и `userStorage.usedBytes/limitBytes` — числа для окна на сервере есть.
- Ночью прибор получил ~6500 одинаковых 413 за 11 часов и ни разу не остановился.
