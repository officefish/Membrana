## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| Место формы | Та же `LoginPage`, режим `login` \| `register`, переключатель «У меня уже есть вход» / «Создать учётную запись». Отдельный экран и router — нет (маршрутизатора в стволе нет). |
| Поля | Порядок: «Логин», «Пароль», «Код приглашения». Повтора пароля нет. `login.trim()`, `code.trim()`, пароль без trim. Пустые после trim — локально «Заполните все поля.» без fetch. |
| Вызов API | `registerRequest(login, password, code)` в `apps/cabinet/src/api/auth.ts` → `POST /v1/auth/register`, тело `{ login, password, code }`, успех 201 → `{ token }` (как login). Ошибки — `AuthApiError` со `status` и русской `message`. |
| Сессия после 201 | Расширение **вне M0-D**: `apps/cabinet/src/context/AuthContext.tsx` — метод `register(...)` по образцу `login` (request → `setStoredToken` → me). Со страницы `setStoredToken` напрямую — запрещён. |
| Фразы по статусу | Только HTTP-статус (не English message). 401: «Регистрация сейчас закрыта.» 403: «Регистрация не принята.» 429: «Слишком много попыток. Подождите 10 минут.» 503: «Сервис временно недоступен. Попробуйте ещё раз.» Иной статус: «Не удалось выполнить регистрацию. Попробуйте ещё раз.» Сеть: «Нет связи с сервером. # Заседание «Регистрация в кабинете по промокоду панели» — M4 (К4) Форма, фраза, частота, лендинг

**Объединяющее задание (одно на всё заседание):** спроектировать контракт «кабинет ↔ панель офиса» для регистрации по промокоду панели так, чтобы сессии A, B, C, D исполнили его параллельно в своих файловых границах, а владелец завёл второй кабинет на бесплатном тарифе.

**Порядок M0 (ратифицирован владельцем 21.09):** M1 грант и дверь → M2 связь и ключ → M3 порядок и отказ → **M4 форма**; лендинг — сразу. Сессия D стартует после C по контракту двери.

**M1, M2, M3 ратифицированы владельцем 21.09 — данности этой комнаты.** Для M4 важен только контракт двери сервера кабинета `POST /v1/auth/register` из M3 (протокол `docs/seanses/cabinet-registration-promo-m3-order-failure-2026-09-21.md`, карта двери, строки 208–216): тело запроса `{ login, password, code }` (поле `code` обязательно, сервер делает `trim`, пустой или длиннее 128 — отказ); ответы: **201** с телом сессии как у входа — успех; **401** «Registration is disabled» — регистрация выключена; **429** «Too many requests» — ограничитель 10 попыток за 600000 мс на адрес; **403** «Registration was not accepted» — любой отказ по коду, по логину или по длинам, причина наружу не различается (Q3, ADR-0005); **503** «Please try again later» — офис недоступен или ключ неверен, пользователь не создан, код не сгорел.
