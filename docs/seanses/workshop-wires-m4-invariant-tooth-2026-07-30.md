[Архитектор]: Предмет — зуб, не парковка и не выбор мастерских. Форма решения: инвариант обязан быть **машинно проверяемым** выходом глагола `orphans` (§4) и **не** совпадать с «весь репозиторий clean», пока знаменатель красный на 54 %. Конструкция: разделить **наследство** (снимок на дату вердикта) и **прирост** (δ после снимка). Зуб кусает прирост; абсолютный ноль — цель кампании, не стартовый предикат блока.

[Верстальщик]: С витрины оператора pre-push и CI отказ обязан читаться без легенды. Не «failed» серой прозой, а: `status`, `counted/denominator`, список прироста, отдельно «наследство N — не блок». Фальшь: один красный бейдж на 476 старых — дерево «всё горит», глаз выключает зуб. Пустота прироста — честный `clean_delta`, не прочерк.

[Музыкант]: На слух вещдок `network:tooth`: написали, не вшили — сутки красный в тишине, никто не услышал. Второй клиппинг — всегда красный без освобождения. Зуб «бесхозных нет» на 476/887 — это feedback на 0 dB в весь микс: либо mute, либо игнор. Нужен count-in: сразу meters по **новому** take, legacy — отдельная шина мониторинга, не master-kill.

[Структурщик]: Леммы, иначе синонимы. **Инвариант принадлежности** — машинный предикат над выходом `orphans`, не лозунг. **Носитель** — home зуба (хук/job/ритуал), не «слой ощущений». **Baseline** — версионированный снимок `{ orphans[], counted, denominator, frozenAt }` на момент включения. **Прирост** — orphan из текущего прогона, которого нет в baseline и который попадает в область проверки (delta push / полный знаменатель — разные locus). **Освобождение** — именованная метка с issuer, как у network/ADR, проверяемая зубом, не `SKIP_PREPUSH=1`.

[Teamlead]: Планка матча: не покрасить дерево и не выключить зуб. Ранний `orphans==0` как block — сдача тренировки: либо вечный красный, либо mute. Связка ясна: Математик — предикаты baseline/δ; Структурщик — home и врезка; Архитектор — граница «не назначаем мастерские». Мой вердикт по нагрузке: **рост блокируем сразу**, абсолютный clean — по событию владельца после парковки, не «потом как-нибудь».

[Математик]: Формализую без UI. Пусть `O(t) = orphans(t)` — множество из глагола §4, `B = O(t₀)` — baseline.  
`growth(t) ⇔ ∃ s: s ∈ O(t) \ B` (с учётом знаменателя §2: инструмент ∪ тест, тест наследует предмет).  
Инвариант **невозрастания**: `¬growth(t)` ⇔ `O(t) ⊆ B` (допустимо |O|↓ при парковке).  
Абсолютный: `clean(t) ⇔ status(t)="clean" ⇔ O(t)=∅`.  
Зуб фазы 1: `pass ⇔ ¬growth(t)` на области locus; `clean` — фаза 2, отдельный effect. Молчаливый pass при fail запрещён (как M7 зубов).

[Архитектор]: Носитель не один. **Строгий locus** — pre-push на **затронутых** путях (паттерн `kits-prepush-strict` + typecheck affected): дешево, кусает автора прироста. **Полный отчёт** — CI или ритуал дня: `has_orphans` по всему знаменателю, effect = report/warn, не kill push целиком. Вердикт не трогает глаголы прибора и не выбирает контейнеры-мастерские.

[Верстальщик]: Два locus — два честных индикатора, не один. Pre-push fail: «прирост orphan: path…». CI/ритуал: полоса «наследство 476 → тренд», без красной стены на merge, пока фаза 2 не включена. Обход, если есть, обязан оставить **видимый след** в том же отчёте (`bypass: reason`, кто), иначе витрина врёт «чисто».

[Музыкант]: Строгий зуб только на delta push — это insert-гейт на новой дорожке, не компрессор на всю ленту. Полный прогон раз в день/неделю — meter в control room. Если baseline не запинен как артефакт, «прирост» снова слышится на глаз — и мы в клиппинге споров. Baseline = master-tape, не устное «на 30.07 было ~476».

[Структурщик]: Home baseline — файл/артефакт в ops-контуре зуба (не размазывать по README домов). Имя леммы: `orphans-baseline` (или эквивалент в словаре workshop-wires), формат стыкуется с выходом `orphans`: множества сравнимы, не «число 476» без списка. Зуб читает baseline + текущий `orphans` + список affected paths из git range push. Освобождение — отдельная лемма `orphan-waiver` (path → issuer, ref, expiry?), проверяется до fail.

[Teamlead]: Условие включения фазы 1 (**¬growth**): **сразу** после вшивания зуба и записи baseline — иначе вещдок network повторится. Фаза 2 (`clean`): только по **явному решению владельца** или по факту «парковка наследства закрыта» (событие, не дата из воздуха). Не привязываю к магическому порогу «доля < X%» без владельца — порог без события снова выключат.

[Математик]: Уточняю область pre-push. Пусть `A` — affected paths пуша (и тесты, наследующие предмет затронутого инструмента — §2).  
Предикат блока: `fail ⇔ ∃ s ∈ A: belongs(s)=orphan ∧ s ∉ B ∧ s ∉ Waivers`.  
Эквивалентно запрету **нового** orphan в delta; файлы из B, лишь пойманные в A, **не** валят push (наследство).  
Полный locus: `report_growth = O(t)\B`, `report_legacy = O(t)∩B`; effect report.  
Инвариант фазы 2: `fail ⇔ O(t)\Waivers ≠ ∅`.

[Архитектор]: Поведение при красном (фаза 1): **block push** (как network:tooth и secret-gate), не merge-политику выдумываем здесь. Законно: припарковать (home|namespace — §1), вынести path из diff, взять waiver со следом, либо чинить belongs предмета. Незаконно как норма: `SKIP_PREPUSH=1` без следа — это глушение всей гребёнки, не обход зуба.

[Верстальщик]: При красном pre-push текст: что заблокировано (push), сколько прироста, top paths, «наследство не в блоке», одна строка «как законно: park | waiver | убрать из diff». Без нотации «просто SKIP». Для ритуала дня — тренд |O∩B| и |O\B|, tabular-nums, без декоративных светофоров «всё плохо».

[Музыкант]: Освобождение по образцу ADR-метки у network: без него канон иногда выглядит как orphan/нарушение и зуб либо врёт, либо выключен. Waiver — редкий solo с титрами (issuer), не ring modulator на весь хук. SKIP_PREPUSH оставлять как аварийный рубильник всей сцены — но след и стыд, не штатный pass orphan-зуба.

[Структурщик]: Обход именую раздельно. (1) **`orphan-waiver`** — штатный обход *этого* зуба, path-scoped, след в отчёте и в носителе waiver. (2) **`SKIP_PREPUSH=1`** — существующий рубильник *всего* pre-push; зуб не обязан его запретить (вне скоупа перестройки хука), но вердикт: **не** считать его освобождением инварианта принадлежности. Синоним «тихо зелёный» = нарушение нормы зуба.

[Teamlead]: Наследство против прироста — **да, различаем**, иначе матч проигран числами 30.07. Прирост меряется `O(t) \ B` (и в block-режиме ещё ∩ A). Парковка элемента из B уменьшает legacy — это законный progress, зуб не наказывает. Новый файл без home|namespace — fail. Связка на DoD: кто пишет baseline+зуб — после вердикта, не в этой комнате выбирать мастерские.

[Математик]: Порог доли (`|O|/denom < θ`) **отклоняю** как основной предикат: θ не мотивирован, 476/887 делает любой θ∈(0,0.5) либо лже-pass, либо вечный fail; «отсутствие роста» — единственный стабильный инвариант при ненулевом B. `orphans==0` оставляем как `I_abs`, включаемый отдельно. Счётчик `counted/denominator` из §4 — для отчёта и тренда, не для block-предиката фазы 1.

[Архитектор]: Цена альтернатив коротко. A0: block `clean` сразу — дерево 54 % красное → выключат. A1: только warn везде — зуб не зуб (вещдок «не вшит»). A2: ¬growth на affected + report full — кусает автора, не красит наследство, вшит в pre-push. Рекомендую A2; фаза 2 — отдельное решение владельца, не спрятанное в M4 как «с завтра clean».

[Верстальщик]: Согласен с A2 на витрине: warn-only без блока — снова фальшивый зелёный push. Нужен hard на приросте и soft на наследстве. Когда владелец включит I_abs — тот же зуб, другой mode/predicate, чтобы не плодить третий скрипт-синоним без словаря.

[Музыкант]: Режимность одного тракта (`mode: growth | absolute`) лучше двух разных «зубов» с похожими именами — иначе в миксе не слышно, какой fader открыт. Включение absolute — явный count-in владельца, не авто по календарю.

[Структурщик]: Тогда публичный контракт зуба: вход = `{ orphansReport, baseline, affected?, waivers, mode }`; выход = `{ pass|fail, effect, growth[], legacyCount, waived[], trace }`. Имена не «check-orphan-soft2». Регистрация в цепочке pre-push обязательна в DoD — уроки network:tooth.

[Teamlead]: Красный в growth-mode: BLOCK push. Красный в absolute (когда включён): BLOCK push же. CI-полный: при growth≠∅ можно держать **warn** или policy job, но не подменять pre-push — иначе снова «узнали руками». Рубильник SKIP — вне норм освобождения; в team evening при привычке — разбор, не фича.

[Математик]: Зафиксирую I_growth ещё раз в терминах §4:  
`I_growth(t) ⇔ (O(t) \ B \ W) = ∅` при mode=growth; на pre-push достаточно `(O(t)\B\W) ∩ A = ∅`, если полнота belongs на A гарантирована глаголом (orphan вне A не обязан сканироваться в hook — но full report ловит).  
`I_abs(t) ⇔ (O(t) \ W) = ∅`.  
Baseline B обновляется **только** явной операцией «перезаморозка» (owner/ритуал), не молча каждый push — иначе growth обнуляется читерски.

[Архитектор]: Перезаморозка baseline — отдельный privileged акт со следом, не side-effect зеленого push. Иначе инвариант вырождается. Граница M4: мы не описываем кампанию парковки 476 файлов; мы даём зуб, который не мешает парковке и не пускает 477-й.

[Верстальщик]: След waiver и freeze baseline — в машинном отчёте и короткой человекочитаемой строке. Капитан в конце дня видит: growth 0, legacy 476→450, waivers 2 — без открытия JSON руками. Это не UI продукта, это витрина ритуала/CI summary.

[Музыкант]: Если waiver без expiry и без issuer — снова бесконечный drone на одной ноте. Пусть issuer обязателен; expiry — по желанию владельца политики, но пустой issuer = невалидный waiver (fail closed).

[Структурщик]: Принимаю: `waiver = { path, issuer, ref?, note? }`; path нормализован к канону belongs. Проверка: path∈W и issuer∈ допустимых — иначе ignore entry. Не плодим namespace-синонимы «exception/ignore/skip-orphan».

## Итоговое решение консилиума

### Посылки (обязательный список)

1. **§1 (M1):** `belongs(s) → home | namespace | orphan`; `orphan` — честный третий исход.  
2. **§2 (M8):** знаменатель = инструменты ∪ тесты; тест наследует предмет.  
3. **§3 (M2):** дом и RootPolicy; не предмет выбора мастерских в M4.  
4. **§4 (M3):** глагол `orphans` → `{ status, orphans, counted, denominator }`; пустой молчаливый ответ запрещён.  
5. **Факт 30.07:** |знаменатель|=887; orphan-инструментов=476 (~54 %); ранний I_abs красит дерево.  
6. **Вещдок network:tooth:** не вшит → красный незаметен; без освобождения → вечный red или выключен.  
7. **Паттерн существующих зубов:** pre-push; strict на affected (`kits-prepush-strict`, typecheck affected).  
8. **Скоуп M4:** зуб и проверка; вне скоупа — парковка файлов, норма в foundation-доках, назначение мастерских, переопределение глаголов.

### Вердикт

| Вопрос | Решение |
|--------|---------|
| **Инвариант (предикат)** | **Двухфазно.** **I_growth (фаза 1, рабочий зуб):** `O(t) \ B \ W = ∅` (невозрастание orphan-множества относительно baseline B; waivers W). В терминах §4: не `status=="clean"`, а отсутствие **новых** элементов в `orphans` сверх B. **I_abs (фаза 2):** `status=="clean"` ⇔ `O(t)\W=∅` ⇔ `orphans==0` (с учётом W). Доля/порог θ — **не** основной предикат. |
| **Носитель проверки** | **Два locus, одна лемма зуба, mode:** (1) **pre-push** — строгий, область **affected** A: fail ⇔ `(O\B\W)∩A ≠ ∅` в mode=growth; (2) **CI и/или ритуал дня** — полный знаменатель, отчёт `growth[]` + `legacyCount`, без подмены pre-push. |
| **Условие включения** | **I_growth + вшивание в pre-push + запись baseline — сразу** после реализации (не «когда парковка кончится»). **I_abs** — только по **явному решению владельца** (или явному событию «наследство закрыто»), не по календарю и не автоматически. |
| **Поведение при красном** | **Block push** при fail предиката активного mode. Законно: припарковать (home\|namespace), убрать path из diff, валидный **orphan-waiver**, снизить legacy парковкой (не блок). Полный отчёт на CI/ритуале: finding/warn по наследству, не стена на 54 %. |
| **Обход и след** | Штатно: **`orphan-waiver`** `{path, issuer, ref?, note?}` — path-scoped, след в выходе зуба. **`SKIP_PREPUSH=1`** — рубильник всего хука; **не** освобождение инварианта принадлежности. Тихий pass запрещён. |
| **Наследство vs прирост** | **Да.** B = O(t₀) заморожен при включении; прирост = `O(t)\B`; наследство = `O(t)∩B`. Метрики: `g=\|O\B\W\|`, `ℓ=\|O∩B\|`. Перезаморозка B — **явный** акт со следом, не side-effect push. |
| **Освобождение** | **Нужно** (урок network:tooth / ADR-метки). Issuer обязателен; невалидный waiver не считается. Кто выдаёт — политика владельца/роли issuer; зуб только **проверяет** наличие и форму. |

**Рекомендация формы:** альтернатива A2 (growth-block на delta + full report), не A0 (clean сразу) и не A1 (только warn).

**Definition of Done (когда пойдёт в код, после ратификации):**

- [ ] Артефакт **baseline** сравнимых множеств с выходом `orphans`, frozenAt, след.  
- [ ] Зуб с `mode: growth | absolute`, контракт выхода `{ pass|fail, growth, legacyCount, waived, trace }`.  
- [ ] Вшивка в **pre-push** (не только script в package.json).  
- [ ] Full report в CI или дневном ритуале.
