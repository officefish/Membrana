[Верстальщик]: Начну с границы своей зоны: у меня нет ставки в самом сетевом коде, но политика «машина → легальный выход» должна быть читаемой данными, иначе её нельзя отобразить ни в каком контроле. Если она живёт неявно — в комментарии, в чьей-то голове, в ENV-переменной без схемы — ни зуб, ни UI не смогут с ней работать. Поэтому мой первый вопрос к комнате: нужен файл с фиксированной схемой, а не соглашение на словах.

[Музыкант]: Соглашусь с Родченко по структуре. Добавлю наблюдение из инвентаря 12.08: proxy-awareness сейчас — свойство файла, а не машины. `deepseek`, `media-bridge`, `linear-snapshot`, `server-storage-backend` — голые; RAG-эмбеддеры — proxy-aware, но только в office. Это значит, что никакой таблицы «машина → легальный выход» нет даже в зачатке: есть хаотичный набор файловых решений без единого носителя. Мы строим политику с нуля, а не наводим порядок в уже существующей.

[Архитектор]: Точная картина. Итак, конструкция: политике нужен один носитель — файл с фиксированной схемой, живущий в репо. Назовём его `network-policy.json` (или `.ts` с `as const` — для типизации). Схема: массив записей вида `{ machine, allowedExits, proxy | null, reason }`. Четыре известные машины из повестки: `dev` (локальный прокси), `office` (HTTPS_PROXY), `media-nl` (прямой легален), `cabinet` (через media). Файл — норма M2: не наблюдение, а декларация. Зуб читает этот файл и сверяет с ним исходники.

[Структурщик]: Уточню термины до кода. «Носитель» — это файл, у которого один владелец (M4 — Ожегов как кандидат-держатель), схема задокументирована, и он является единственным источником истины для зуба. Предлагаю: `packages/network-policy/policy.json` + экспортирующий `index.ts` — граница пакета соблюдена. Зуб импортирует только этот индекс, не лезет в `src/` никаких серверных пакетов напрямую. Иначе зуб сам нарушит слабую связанность.

[Teamlead]: Конструкция ясна, но нужно закрыть вопрос места зуба до деталей схемы. M4 говорит: гейт-событие — «правка серверных вызовов». Это значит pre-push или CI на правки серверных файлов — не отдельный шаг вручную. Pre-push быстрее даёт сигнал разработчику; CI — надёжнее как последний рубеж. Беру оба: pre-push для скорости, CI для надёжности. Канал находки — stdout с именами файлов и строк, без автоисправления. Ожегов — держатель.

[Математик]: Формализую предикат зуба. Голый `fetch` в серверном пакете — это: вызов `fetch(` (или `node-fetch`, `axios` без обвязки) в файле, путь которого соответствует `packages/*/src/**/*.ts` или `apps/*/src/server/**/*.ts`, при отсутствии импорта из `@membrana/proxy-client` (или иного согласованного proxy-обёртки) в том же файле. Грепабельный предикат: `grep -rn "fetch(" --include="*.ts" <server-dirs> | grep -v "proxy-client" | grep -v "// allow:"`. Точность — не стопроцентная (можно завернуть через переменную), но достаточна для практического зуба. Для повышения точности — AST-анализ, но это отдельная задача (#1425 явно запрещает чинить сейчас).

[Верстальщик]: Хочу уточнить про `// allow:` в выводе Дынина — это и есть форма легального исключения? Если да, то это неверно: комментарий в коде — молчание зуба через побег, а не данные с причиной. Родченко за то, чтобы исключение жило в политике (`network-policy.json`), а не в коде рядом с вызовом. Иначе ревьюер не знает, легален ли этот `fetch` или его просто забыли проверить.

[Музыкант]: Поддерживаю Родченко. Пример: `media-nl` ходит голым `fetch` легально — прямой выход, NL без фильтра. Если исключение — это комментарий в коде, то после рефактора его случайно удалят, и зуб молча зазеленеет там, где должен был кричать. Легальное исключение должно быть записью в `network-policy.json` с полем `allowedBarePackages: ["@membrana/media-linear-snapshot"]` и обязательным `reason`. Зуб сверяет пакет файла с этим списком до того, как поднять флаг.

[Архитектор]: Фиксирую схему носителя. Запись политики:
```json
{
  "machine": "media-nl",
  "allowedExits": ["direct"],
  "proxy": null,
  "allowedBarePackages": [
    { "package": "@membrana/media-linear-snapshot", "reason": "NL direct exit is legal, no filter" }
  ]
}
```
Запись без `allowedBarePackages` (или с пустым массивом) означает: все серверные пакеты на этой машине обязаны ходить через обёртку. Зуб читает `allowedBarePackages` и исключает их из находок. Добавление нового исключения требует PR в `network-policy.json` с `reason` — не молчаливого `// allow:` в коде.

[Структурщик]: Уточняю границу: `allowedBarePackages` — это список пакетных имён (NPM-package-name уровня `package.json#name`), а не путей к файлам. Зуб определяет, к какому пакету относится найденный файл, через ближайший `package.json` вверх по директории — стандартная навигация монорепо. Это устойчивее, чем glob по путям, и не ломается при переименовании директорий.

[Teamlead]: Хорошо. Теперь судьба легаси. Репо входит с четырьмя известными голыми вызовами: `deepseek`, `media-bridge`, `linear-snapshot`, `server-storage-backend`. Старт красным — нечестно: красим до того, как дали команде инструмент починки, и это заморозит репо. Полная амнистия молчанием — тоже плохо: зуб теряет смысл в первый же день. Прецедент eslint-храповика (#1264) — верная форма: фиксируем текущее число нарушений как потолок, любое новое нарушение — красный, любое устранение — понижает потолок. Легаси называется, не амнистируется.

[Математик]: Точнее: храповик — это файл `network-policy-violations-budget.json` с полем `"maxBareCallsCount": 4`. Зуб считает голые вызовы, сравнивает с бюджетом. Если текущее число > бюджета — красный. Если == или < — зелёный. Бюджет убывает только явным PR с `reason` (зафиксировали починку пакета из списка) или с `amnesty` (временная запись с датой истечения). Увеличить бюджет нельзя без PR в файл политики — это и есть храповик.

[Верстальщик]: Мне важно: как разработчик видит находку? Stdout зуба должен быть структурированным: имя файла, строка, имя пакета, и — ключевое — ссылка на политику. Формат:
```
BARE_FETCH: packages/office/deepseek/src/client.ts:42
  package: @membrana/deepseek
  policy: network-policy.json → machine:office → no allowedBarePackages entry
  fix: add proxy wrapper OR add allowedBarePackages entry with reason
```
Без этого разработчик не знает, куда смотреть. Находка называет, не чинит — соответствует ограничению #1425.

[Музыкант]: Добавлю: зуб должен явно отличать «пакет в амнистии» от «пакет легально исключён». Амнистия — временная, с датой; легальное исключение — постоянное, с причиной. В stdout это разные метки: `AMNESTY` vs `ALLOWED`. Иначе через полгода никто не поймёт, почему `linear-snapshot` зеленеет без обёртки.

[Архитектор]: Согласен. Схема исключения в `network-policy.json` несёт два вида записей в `allowedBarePackages`: `{ type: "permanent", package, reason }` и `{ type: "amnesty", package, reason, expiresAt }`. Зуб читает тип и выводит метку. По истечении `expiresAt` амнистия не автоматически умирает — зуб начинает считать пакет нарушением, а не молча игнорирует. Это работает как self-expiring whitelist.

[Структурщик]: Предлагаю уточнить место зуба в CI. Pre-push хук — скрипт в `scripts/check-bare-fetch.mjs`; запускается хуком `pre-push` через `husky` или аналог. CI шаг — тот же скрипт, вызываемый в `lint` job. Таким образом один скрипт, два места запуска. Держатель скрипта — Ожегов (M4). Скрипт не имеет зависимости от конкретных серверных пакетов: он читает `network-policy.json` и обходит файловую систему монорепо по предикату Дынина.

[Teamlead]: Хорошо. Фиксирую: единственная зависимость зуба — `network-policy.json`. Не hardcode списков, не `grep` с захардкоженными именами пакетов. Если завтра появится пятый серверный пакет — зуб его поймает автоматически, потому что предикат работает по директориям, а не по именам. Исключение требует явной записи в политике. Это архитектурно чисто.

[Математик]: Один риск хочу назвать: `fetch` через переменную — `const fn = fetch; fn(url)` — статический grep не поймает. AST-анализ поймал бы, но это дорого. Предлагаю не пытаться поймать всё: зуб ловит очевидные случаи, которые и являются 95% реальных нарушений (как показывает инвентарь 12.08 — все четыре голых — прямые вызовы `fetch(` или импорты без обёртки). Документируем ограничение явно в `README` зуба: «AST-полнота — отдельная задача».

[Верстальщик]: Принимаю. Документированное ограничение лучше, чем ложное ощущение полноты. Важно, чтобы `README` зуба был частью DoD — иначе следующий разработчик решит, что зуб покрывает всё, и не будет осторожен с косвенными вызовами.

[Музыкант]: Возвращаюсь к `cabinet` — он ходит через `media`. Это значит, что у `cabinet` в политике `allowedExits` — не `direct`, а `via:media-nl`. Голый `fetch` из `cabinet` нарушает политику вдвойне: и по машине, и по маршруту. Зуб должен ловить его так же, как и любой другой серверный пакет без обёртки. Маршрутизация — чужая комната (M6), но факт нарушения — наша.

[Архитектор]: Точно. Зуб не знает о маршрутизации — он знает только: есть ли у пакета легальная обёртка или легальное исключение в политике. Маршрут внутри обёртки — дело M6. Это чистое разделение ответственности: зуб проверяет наличие обёртки, не её внутренности.

[Структурщик]: Добавлю: `network-policy.json` не содержит маршрутов и не дублирует M6. Он содержит только `{ machine, allowedExits, proxy | null, allowedBarePackages }`. Поле `allowedExits` — декларативное, для читаемости и будущих проверок; зуб M7 его не использует. Зуб M7 смотрит только на `allowedBarePackages`. Разделение чистое: политика машины как данные, зуб как проверка одного аспекта этих данных.

[Teamlead]: Тогда финальный образ: `network-policy.json` — носитель политики машины. `scripts/check-bare-fetch.mjs` — зуб, читает политику, обходит монорепо, выдаёт находки. `network-policy-violations-budget.json` — храповик для легаси. Pre-push + CI — два места запуска одного скрипта. Все четыре голых из инвентаря 12.08 идут в бюджет `maxBareCallsCount: 4`, не в амнистию и не в `allowedBarePackages` — они нарушения, просто отложенные. Media NL идёт в `allowedBarePackages` с `type: permanent`.

[Математик]: Формализую предикат бюджета: пусть `V` — множество файлов с голым fetch, не покрытых `allowedBarePackages`. `|V| <= maxBareCallsCount` → зелёный. `|V| > maxBareCallsCount` → красный с выводом `|V| - maxBareCallsCount` новых нарушений. Снижение бюджета — только PR. Увеличение — только PR с обоснованием (добавление `amnesty`-записи повышает бюджет через политику, а не через прямую правку числа).

[Верстальщик]: Уточню: `amnesty`-запись в `allowedBarePackages` исключает пакет из множества `V` до истечения `expiresAt`. Это значит, что бюджет и амнистия — разные механизмы. Бюджет — для неназванных нарушений (легаси, которое ещё не получило ни постоянного исключения, ни амнистии). Амнистия — для поимённо известных с временным освобождением. Это важно для вывода: нарушение в бюджете выводится с меткой `LEGACY`, амнистия — с меткой `AMNESTY`.

[Музыкант]: Тогда полная таксономия меток в stdout:
- `BARE_FETCH / LEGACY` — в бюджете, не поимённо исключён
- `BARE_FETCH / AMNESTY` — поимённо, временно, с датой
- `BARE_FETCH / ALLOWED` — поимённо, постоянно, с reason
- `BARE_FETCH / VIOLATION` — новое нарушение сверх бюджета и без исключения

Только последнее делает зуб красным. Остальные — информационный вывод.

[Архитектор]: Принимаю таксономию. Добавлю: `ALLOWED` не выводится как находка — пакет вообще не попадает в отчёт зуба. Выводятся только `LEGACY`, `AMNESTY` (информационно, статус зелёный) и `VIOLATION` (красный). Это соответствует принципу: зуб называет проблему, не шумит по поводу чистого кода.

[Структурщик]: Финальная граница пакета: `packages/network-policy/` содержит `policy.json`, `violations-budget.json`, `index.ts` (экспорт типов схемы). Скрипт зуба — `scripts/check-bare-fetch.mjs`, импортирует типы из `@membrana/network-policy`. Серверные пакеты не импортируют `network-policy` — только зуб читает его. Однонаправленная зависимость, никакого обратного импорта.

[Teamlead]: Все четыре вопроса закрыты. Жду сводку от Ожегова по DoD — он держатель зуба по M4.

[Математик]: До DoD — один технический вопрос: предикат серверного файла. Как зуб отличает серверный файл от клиентского? По `package.json` ближайшего пакета — поле `membrana.packageKind: "server"` (или аналог, уже заведённый в конвенции монорепо). Если такого поля нет — зуб смотрит на путь: `apps/*/server/**`, `packages/services/**`, `background-*`. Уточнение нужно до написания скрипта. Если конвенция `membrana.packageKind` уже есть в репо (посылка M5) — используем её, не изобретаем glob.

[Верстальщик]: Поддерживаю: лучше опереться на существующую конвенцию из M5 («слои дома»), чем вводить новый glob. Если M5 зафиксировал серверный слой — зуб читает его манифест, не дублирует логику.

[Музыкант]: Согласен. И последнее по форме исключений: `reason` в `allowedBarePackages` — обязательное поле, не nullable. Схема TypeScript (`policy.ts`) делает его `string`, не `string | undefined`. Это не эстетика — это то, что делает исключение проверяемым: нет `reason` — не пройдёт JSON-валидацию при PR.

[Архитектор]: Принимаю. Схема валидируется при старте зуба (JSON Schema или Zod — на усмотрение держателя), и невалидная политика — тоже красный, отдельная категория ошибки зуба: `POLICY_INVALID`. Зуб не работает на неизвестной политике.

[Структурщик]: Финальная точка по слабой связанности: зуб не знает о конкретных пакетах монорепо. Он знает схему политики и умеет обходить файловую систему. Любой новый серверный пакет попадает под зуб автоматически — регистрировать его в зубе не нужно. Это и есть правильная слабая связанность: зуб зависит от схемы, не от перечня.

## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| **Носитель политики** | Файл `packages/network-policy/policy.json` со схемой `{ machine, allowedExits, proxy\|null, allowedBarePackages[] }`. Экспортируется через `packages/network-policy/index.ts`. Единственный источник истины для зуба. |
| **Зуб и его место** | Скрипт `scripts/check-bare-fetch.mjs`. Запускается в двух местах: pre-push хук (husky) и CI `lint` job. Определяет серверные файлы через конвенцию M5 (`membrana.packageKind: "server"` в `package.json`) или fallback-glob. Предикат: наличие `fetch(` (и аналогов) без импорта proxy-обёртки, в файле серверного пакета, не покрытом `allowedBarePackages`. |
| **Форма находки** | Stdout: `BARE_FETCH / VIOLATION` (красный), `BARE_FETCH / LEGACY` (зелёный, в бюджете), `BARE_FETCH / AMNESTY` (зелёный, временное исключение с `expiresAt`). `ALLOWED` — не выводится. Невалидная политика → `POLICY_INVALID`, красный. Без автоисправления. |
| **Форма легальных исключений** | Запись в `allowedBarePackages` с обязательными полями `type` (`permanent`\|`amnesty`), `package`, `reason` (non-nullable), опционально `expiresAt`. Пример: `media-linear-snapshot` получает `type: permanent, reason: "NL direct exit is legal, no filter"`. Комментарий в коде (`// allow:`) — не легальная форма исключения. |
| **Судьба легаси** | Warn-храповик: `network-policy-violations-budget.json` с `"maxBareCallsCount": 4`. Четыре известных голых вызова (deepseek, media-bridge, linear-snapshot, server-storage-backend) входят в бюджет как `LEGACY` — названы, не амнистированы. Новое нарушение сверх бюджета → `VIOLATION`, красный. Снижение бюджета — только PR с доказательством устранения. Увеличение — через `amnesty`-запись в политике, не через прямую правку числа. |
| **Держатель** | Ожегов (M4, кандидат подтверждён). |
