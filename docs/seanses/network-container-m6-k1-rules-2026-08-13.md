[Teamlead]: Планка ясная: один вердикт, без «и ещё починим сеть». #1425 не открываем. Связка на выходе — носитель + поля + зуб + миграция K1 без смены поведения кода. Кто крутит зуб — не наша комната: M4, кандидат Ожегов. Жду от Архитектора форму, от Структурщика — путь файла, от Математика — предикат зуба.

[Музыкант]: Слышу K1 как маршрутный патч, не как партитуру ленты. «Office не ходит в Linear — ходит через media-VPS» — это via-норма, сегодня спрятанная прозой в `media-snapshot.client`. Если оставить её только в коде, зуб кусает воздух: сравнивать не с чем. Норма должна звучать отдельно от исполнения, как партия отдельно от микрофона.

[Математик]: Формализую. Пусть R — множество правил, S — множество снимков ленты (наблюдения). Предикат нарушения: ∃s∈S, ∃r∈R: matches(s,r) ∧ verdict(r)∈{forbidden} ∨ (verdict(r)=via ∧ actual_path(s)≠via_path(r)). Правило не элемент S (M1, M2). Носитель R — отдельная структура данных. Зуб = вычисление этого предиката плюс, опционально, статический гейт на дифф вызовов. Оба — разные моменты одного инварианта.

[Структурщик]: Лемма пути. M5 зафиксировал двухслойное хранение: лента + `registry/`, README — карта дома. Правило — не единица ленты → не `events.jsonl` и не снимок. Дом контейнера network — `docs/audit/network/`. Предлагаю носитель: `docs/audit/network/registry/egress-rules.json` (или `.jsonl` append-only по id правила, но не лента наблюдений). Имя `egress-rules` — определение через функцию: исходящие нормы направления. Синоним «infra-policy» внутри network-дома плодить не будем — второй реестр мощностей запрещён BRIEF.

[Верстальщик]: С витрины мне нужен не UI, а честная форма данных: закрытые поля, чтобы ночной отчёт и triage могли показать «какое правило, какой вердикт, какой via» без парсинга прозы. Поля как типографика смысла: источник-зона, назначение-класс, вердикт, via-узел, ссылка на прецедент. Без свободного текста как единственного носителя нормы.

[Архитектор]: Согласен с путём Структурщика. Canon-док отдельный — лишняя сущность: норма направления — данные registry network-дома, не глава WHITE_PAPER. Файл правил в `docs/audit/network/registry/` — ровно слой нормы. Поля фиксирую закрытым словарём: `rule_id`, `class` (здесь K1), `source_zone`, `dest_class`, `verdict` ∈ {allowed, forbidden, via}, `via_node` (обязателен при via, иначе null), `precedent_ref`, `status` ∈ {active, deprecated}. Проза в description — опциональный комментарий, не источник истины.

[Teamlead]: Форма принята как рабочая гипотеза. Миграция K1: акт = перенос смысла из прозы `media-snapshot.client` в запись registry **без** изменения runtime-поведения клиента. Код не «починяем» и не подключаем к файлу в этом акте — только слово нормы встаёт на место. Иначе влезем в #1425. DoD миграции — diff поведения нулевой, diff носителя — одна запись K1.

[Музыкант]: Via — ключевая нота K1, не forbidden в лоб. Если зуб умеет только allowed/forbidden, партия потеряет медиатор media-VPS. Это слышно уже в материале такта 1 и дополнении 12.08.

[Математик]: Уточняю моменты зуба. Момент T_night: такт 01:00 (M4) — на входе снимки ленты за окно, на выходе 0..n находок в канал night-report/night-triage. Момент T_gate: гейт-событие M4 «правка серверных вызовов» — статический предикат: дифф затрагивает outbound call sites, сопоставить с R; при конфликте с active-правилом — находка/блок по контракту гейта, не «починить сеть». Оба момента нужны: T_night ловит факт в рантайме-наблюдении, T_gate — дрейф нормы в коде до продакшена. Исполнитель зуба вне скоупа (M4).
