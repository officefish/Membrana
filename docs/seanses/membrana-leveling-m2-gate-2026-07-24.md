[Верстальщик]: С UI-стороны гейт — это не экран «красоты», а честный статус-блок вечера: пути сгруппированы по `disposition`, мусор назван поимённо, незавершёнка — отдельной карточкой. Пользователь не должен гадать, «почему ритуал красный». Конструктивизм: состояние = сообщение. Форму манифеста-отчёта не рисую — шов к K2; мне важно, что гейт отдаёт читаемые корзины: live / ready / unfinished / trash.

[Музыкант]: На слух аналогия простая: нельзя «свести микс», пока в сессии висят безымянные треки-мусор и недописанные дубли. Гейт — pre-master check. `trash` без имени = клиппинг процесса: останавливаем. `unfinished` — не «заглушить компрессором» WIP-коммитом, а положить на полку с этикеткой. Обе половины T10: убрать щелчки И долить готовое в `main` — иначе утро начинается с дырки в мастер-шине.

[Teamlead]: Рамка по ARCHITECTURE и ритму дня. Вход гейта — снимок dirty-путей плюс гранула M1 `disposition(path, ctx) → live | ready | unfinished | trash`. Гейт **не** пересчитывает disposition и **не** меняет K1. Он только маршрутизирует. Приоритет: голова-гейт (решение «что делать с каждым состоянием») важнее хвоста-сантехники (`main-fill` как механизм — шов K2/K3). Вечерний триггер: после дневной работы, до/в контуре evening-ритуала — не утренний «разбор завалов».

[Математик]: Формализую без UI. Пусть \(S = \{(p_i, d_i)\}\) — конечный снимок. Индикаторы: \(T = \{p \mid d=\mathrm{trash}\}\), \(U = \{p \mid d=\mathrm{unfinished}\}\), \(R = \{p \mid d=\mathrm{ready}\}\), \(L = \{p \mid d=\mathrm{live}\}\). Остановка: \(\exists p\in T:\ p\ \text{не поименован в акте именования}\). Прохождение требует конъюнкции: именование всех \(T\), регистрация всех \(U\), и \(\mathrm{main\text{-}fill}(R)\) доведён (или \(R=\emptyset\) с явным no-op). Одна дизъюнкция вместо «и» ломает T10 численно: гейт «наполовину» = ложный true.

[Структурщик]: Словарь пакета/ритуала: гейт — отдельная процедура-потребитель контракта M1, не новый классификатор. Публичный смысл имён: `live` пропускаем (R2), `ready` → очередь `main-fill`, `unfinished` → карточка реестра, `trash` → убрать или назвать. Запрет: WIP-коммит как суррогат регистрации — обход фасада реестра, `нарушена слабая связанность` процесса с `docs/tasks/registry`. Шов к K2 — форма отчёта; к K3 — рельсы исполнения `main-fill`. Здесь только имена швов.

[Верстальщик]: Минимальный UX регистрации unfinished: карточка должна быть видима в том же вечернем контуре, что и красный гейт — иначе «зарегистрировал в никуда». Поля на экране — следствие контракта, не наоборот: id/путь, статус unfinished, почему не ready, next step. Без прогресс-баров «для души» — tabular список и статус-бейдж по DESIGN.

[Музыкант]: Риск однобокости: только уборка без main-fill — готовые дубли так и лежат off-line, «студия чистая, релиза нет». Только main-fill без обнаружения — мусор уезжает под коммитами, как hum в земле: потом не отловишь. Обе половины обязательны, иначе гейт врёт уху команды.

[Teamlead]: Условие остановки фиксирую нормативно (R2/T11): **неназванный trash** останавливает гейт; статус не «зелёный». «Назвать» = явный акт в выходе гейта (поимённый список path + disposition trash + действие: удалить / ignore-with-reason / move-out-of-worktree — конкретная сантехника не K4). Пока хоть один dirty-trash без строки в акте — STOP. Live не останавливает (R2): это текущая работа, не мусор.

[Математик]: Карточка unfinished — минимальный кортеж, чтобы незавершёнка была легитимной, а не спрятанной: (1) стабильный id ссылки на path или набор path; (2) метка состояния `unfinished` (не `ready`); (3) краткое why-not-ready (одна строка-предикат человеческий); (4) next-action или owner/persona; (5) связь с вечерним снимком/датой гейта. Без (1)+(2) карточка = пустой звук: тест на «зарегистрировано» не отличить от отсутствия. WIP-commit hash **не** входит в контракт как замена.

[Структурщик]: Реестр — единственная точка легитимации unfinished. Не stash, не «临时ный» бранч, не orphan-файл вне словаря. Гейт читает disposition, пишет/требует запись карточки через фасад реестра задач (или согласованный unfinished-registry, если отделим — но один термин). main-fill для ready — вызов известного шва, не inline merge-логика внутри гейта: гейт оркестрирует факт «доляно / пусто / blocked», не реализует git-политику.

[Верстальщик]: Презентация STOP: не модалка-ужас, а блокирующий summary: «N trash без имени» списком path. Pass — две галочки половины: Detect OK, Main-fill OK. Если Detect OK и Main-fill skip при R=∅ — вторую половину показать как «no-op, очередь пуста», чтобы не путать с провалом.

[Музыкант]: Триггер — вечер. Утром гейт как «открыть сессию» не ставим: иначе live превратится в ложный trash-паникой. Приоритет Kuryokhin: сначала решение по корзинам (голова), потом лить ready (хвост). Импровизация «закоммичу как wip и сплю» — запрещённый джем, ломает T7.

[Teamlead]: Процедура гейта по шагам, черновик вердикта: (1) снять dirty paths; (2) для каждого получить disposition из M1; (3) partition по четырём состояниям; (4) live → skip; (5) trash → require named act; (6) unfinished → require registry card; (7) ready → enqueue main-fill; (8) evaluate stop/pass. Pass только если trash все названы И unfinished все в карточках И main-fill половины закрыта. Иначе STOP с причиной.

[Математик]: Предикат прохождения:  
\(\mathrm{Pass}(S) \iff \mathrm{Named}(T) \land \mathrm{Registered}(U) \land \mathrm{Filled}(R)\),  
где \(\mathrm{Filled}(\emptyset)=\mathrm{true}\) (no-op), \(\mathrm{Filled}(R\neq\emptyset)=\) успешный main-fill по контракту шва.  
\(\mathrm{Stop} \iff \lnot \mathrm{Named}(T)\) — достаточное условие красного; также stop при отсутствии Registered/Filled, с **разными кодами причины**, чтобы не смешивать «мусор» и «не долили». Неназванный trash — hard-stop первого приоритета (T11).

[Структурщик]: Граница модулей ритуала: `disposition` — чистая гранула M1; `gate-no-sleep` — оркестратор вечера; `main-fill` — отдельный шов (K2/K3); registry card — запись в task continuum. Никаких прямых «гейт импортирует внутренности git-plumbing UI». Отчёт о прогоне — шов K2: гейт обязан уметь сказать pass/stop + списки, форма манифеста не здесь.

[Верстальщик]: Итого для DoD визуала (только обязательство K4, не K2): в протоколе/выходе гейта четыре корзины и явный STOP-reason. Если позже K2 завернёт это в манифест — наши корзины остаются стабильным смыслом строк.

[Музыкант]: Принимаю жёсткий stop на неназванном trash: лучше сорванный evening, чем утро в шумах. Карточка unfinished — как mark на партитуре «взять с места»; WIP-коммит — как затереть take номером без take-list.

[Teamlead]: Консенсус собираю. K4 не открывает K1. Обе половины T10 — норма вердикта. Владельцы после комнаты: процедура и предикаты — норма команды; реализация скрипта — вне этой комнаты (запрет писать код). Швы K2/K3 только названы. Голосуем принятие процедуры ниже.

[Математик]: Принимаю. Добавляю в DoD K4: проверяемые утверждения «для фикстурного S с одним unnamed trash → Stop»; «S с only ready → Pass iff main-fill ok»; «unfinished без карточки → Stop»; «WIP-commit не удовлетворяет Registered(U)». Без кода — как спецификация оракула.

[Структурщик]: Принимаю. Словарь: `gate-no-sleep`, акт `Named(trash)`, `Registered(unfinished)` через реестр, `main-fill(ready)`. Синоним «WIP закрыл гейт» — вне нормы. Слабая связанность с M1: только чтение disposition.

[Верстальщик]: Принимаю. Четыре корзины + STOP/PASS и две половины в статусе — достаточно для честного вечернего кадра.

[Музыкант]: Принимаю. Голова-гейт вечером, хвост main-fill обязателен, мусор поимённо.

[Teamlead]: Принимаю. Вердикт фиксируем таблицей. LGTM на форму решения K4 при условии списка посылок и DoD только K4.

[Математик]: Ещё раз: live не входит в stop-множество. Смешение live и trash — регресс M1, не зона гейта. Гейт доверяет d_i.

[Структурщик]: Финально: вход типа `{ path: Path; disposition: Disposition }[]` + ctx снимка; выход: `{ status: pass|stop; reason[]; baskets; mainFill: done|noop|failed|pending }`. Контракт достаточен соседним комнатам без переопределения disposition.

| Вопрос | Решение |
|--------|---------|
| Что такое гейт K4 | Оркестратор вечера над снимком `{path, disposition}[]`; **не** классификатор; **не** пересчёт M1 |
| Вход | Снимок dirty-путей + `disposition` из M1 (+ ctx снимка/даты для трассировки) |
| Действие `live` | Пропустить (R2); не stop; не main-fill; не карточка unfinished |
| Действие `ready` | Поставить в очередь / вызвать шов `main-fill`; пустой \(R\) → `mainFill = noop` (половина считается закрытой) |
| Действие `unfinished` | Зарегистрировать **явной карточкой** в реестре; WIP-коммит **не** заменяет регистрацию |
| Действие `trash` | Убрать и/или **поименовать** в акте гейта; без строки именования — path считается неназванным |
| Что ОСТАНАВЛИВАЕТ | Hard-stop: \(\exists\) trash без Named-акта (T11). Также stop (с иным reason-code): unfinished без карточки; ready без успешного main-fill (когда \(R\neq\emptyset\)) |
| Условие прохождения | \(\mathrm{Named}(T) \land \mathrm{Registered}(U) \land \mathrm{Filled}(R)\) — **конъюнкция** обеих половин T10 (обнаружение + main-fill) |
| Минимальный контракт карточки unfinished | (1) id/ссылка на path(и); (2) state=`unfinished`; (3) why-not-ready; (4) next-action или owner/persona; (5) привязка к снимку/дате гейта |
| Триггер / приоритет | Вечерний ритм; голова-гейт (маршрутизация состояний) важнее хвоста (`main-fill` plumbing, отчёт) — швы **K2** (манифест-отчёт), **K3** (рельсы fill) только названы |
| Риск «только уборка» | Ready застревает вне main → ложный «чистый» вечер, утром нет поставки |
| Риск «только main-fill» | Неназванный trash копится / уезжает под коммитами → обман гейта, долг |

### Процедура гейта (нормативная)

1. Снять dirty-paths рабочего снимка.  
2. Для каждого path получить `d = disposition(path, ctx)` (M1).  
3. Построить корзины \(L,R,U,T\).  
4. \(L\): no-op.  
5. \(T\): сформировать акт именования (path + действие утилизации/ignore-with-reason); если акт неполный → **STOP** (`unnamed-trash`).  
6. \(U\): для каждого path обеспечить карточку реестра по минимальному контракту; иначе **STOP** (`unregistered-unfinished`).  
7. \(R\): выполнить/подтвердить `main-fill`; при неуспехе **STOP** (`main-fill-failed`); при \(R=\emptyset\) → noop.  
8. Если нет stop-причин → **PASS** (Detect OK ∧ Main-fill OK).  
9. Выход гейта: status, reason[], baskets, mainFill ∈ {done, noop, failed, pending} — потребление формой отчёта = шов K2.

**Definition of Done (только K4):**

- В протоколе зафиксированы: процедура 1–9, предикат Pass/Stop, контракт карточки unfinished, обе половины T10, вечерний триггер, швы K2/K3 без их проектирования.  
- Секция «Список посылок» заполнена входами факт/норма без выводов комнаты.  
- Оракульные сценарии специфицированы: unnamed trash → stop; unfinished без карточки → stop; WIP-commit ≠ Registered; only-ready → pass iff main-fill done/noop; live не стопорит.  
- Нет кода скриптов; нет переопределения disposition; нет манифеста K2 и рельсов K3 в DoD.  
- Все пять ролей явно приняли вердикт.
