## Итоговое решение консилиума: I1

### Пропозиция

Материал `static.mmbrn.tech` идентифицируется на трёх независимых уровнях: байтовое тождество (`sha256` при принятом предположении о коллизионной устойчивости SHA-256), record-тождество (неизменяемый `id` строки реестра) и lineage-тождество (root линии). Реестр `registry.jsonl` — единственный источник истины о регистрации и истории; байты — независимый предмет, верифицирующий заявленные `sha256` и `bytes` при доступе. Canonical-адрес линии: `"urn:mmbrn:static:" + rootId`.

---

### Таблица полей и инвариантов

| Поле / derived | Обяз. | Тип / ограничение | Роль | Инвариант |
|---|---|---|---|---|
| `id` | да | строка, уникальна в реестре | record identity | не мутирует; любое изменение поля создаёт новый `id` |
| `sha256` | да | hex-строка | байтовое тождество | фиксирован для данной записи; при принятом предположении КУ SHA-256 идентифицирует конкретные байты |
| `bytes` | да | положительное целое | размер конкретных байтов записи | верифицируется при доступе; изменение требует новой записи |
| `addedAt` | да | дата `YYYY-MM-DD…` | момент регистрации | не мутирует |
| `source` | да | строка | провенанс байтов | повторяется при адресной поправке; фиксируется заново при редакции |
| `location.kind` | да | `local` / `affine` / `url` / `archivarius` | тип адреса | только допустимые значения; `sensitive` не является kind |
| `location.ref` | да | непустая строка | адрес байтов | заявление реестра; достижимость — внешнее состояние склада |
| `supersedes` | нет | `id` предыдущей записи | явная lineage-связь | при наличии определяет effective predecessor |
| `about` | нет | строка | описание материала | изменение создаёт новый `id`; не меняет sha256 и lineage |
| `measured` | нет | объект | дополнительные метрики | изменение создаёт новый `id`; не меняет sha256 и lineage |
| `sensitive.reason` | нет | строка | причина чувствительности | отдельное поле; не заменяет допустимый `location.kind` и непустой ref |
| `root` *(derived)* | — | `id` первой записи линии | lineage identity | запись с `ep = ⊥`; не поле EvidenceRecord |
| `canonicalRef` *(derived)* | — | `"urn:mmbrn:static:" + rootId` | канонический адрес линии | инъективен; неизменен пока линия существует; не поле EvidenceRecord |

**Уникальность record `id`** — принимаемый инвариант M2.

**ep:** `ep: R → Id(R) ∪ {⊥}` — возвращает `id` effective predecessor либо `⊥`.

**Root и tip:** root — запись, где `ep = ⊥`; tip — `id`, отсутствующий среди всех значений `ep` по реестру (включая вычисленные legacy-значения). Это разные роли и критерии. В линии длины больше 1 root и tip — разные записи. Множества roots и tips равночисленны, их определения не тождественны.

### Таблица шести случаев

| Случай | Байты | Запись | Линия |
|---|---|---|---|
| **PDF (первичная регистрация)** | sha256 фиксирует конкретные байты; bytes — измеренный размер | новый `id`; `addedAt`, `source`, `location` заполнены; `supersedes` отсутствует | новая линия; запись с `ep = ⊥` является её записью без предшественника; `canonicalRef = "urn:mmbrn:static:" + id этой записи` |

| **Редакция (изменённые байты)** | sha256 отличается от предыдущей записи; bytes измерен заново (численно может совпасть с прежним) | новый `id`; `supersedes` указывает на предыдущую запись; `source` фиксируется честно заново | линия продолжается: root и canonicalRef сохраняются; новая запись становится tip |
| **Архив / компонент-член** | архив: один sha256 целиком; компонент: отдельный sha256 при самостоятельном поступлении | архив: одна запись; компонент получает запись при независимом поступлении или предоставлении M6 | две независимые линии с разными root и canonicalRef |
| **Перенос (смена location, байты неизменны)** | sha256 и bytes те же | новый `id`; `location` обновлён; `supersedes` на предыдущую запись; sha256 и source повторяются | линия продолжается; root и canonicalRef неизменны; новый `id` становится tip |
| **Sensitive** | байты могут находиться вне репозитория | `location.kind` — один из допустимых значений; `location.ref` — непустой, хранится в записи реестра; `sensitive.reason` — отдельное поле | линия строится по общим правилам; root и canonicalRef определяются стандартно |

**Доказательство инвариантов по столбцам:**

- *Байты*: sha256 и bytes фиксируются при создании записи и не мутируют в той же строке. При редакции sha256 обязан отличаться (иные байты). При адресной поправке и переносе sha256 совпадает (байты не изменились). При дубле sha256 может совпадать у двух разных record.
- *Запись*: любое изменение любого поля порождает новый `id` и новую append-only строку; старая строка остаётся историей. `supersedes` связывает новую строку с предыдущей явно (или вычисляется для legacy).
- *Линия*: `ep` определена однозначно для каждой записи. Линия — конечная связная последовательность без цикла, fork и merge. Root неизменен пока линия существует. Canonicalref производен от root и неизменен вместе с ним.
