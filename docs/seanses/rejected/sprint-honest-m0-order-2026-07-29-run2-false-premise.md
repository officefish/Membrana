# Консилиум: M0 — порядок разбора «честные исполнители спринта»

**Повестка:** Каков порядок разбора девяти кандидат-вопросов (DAG зависимостей) о честных исполнителях спринта? Единственный вердикт M0 — упорядоченный список с зависимостями; существо девяти комнат здесь не вердиктится. Ратифицирует владелец.

**Участники:** Teamlead (Tarasov), Архитектор (Vesnin), Структурщик (Ozhegov), Математик (Dynin), Музыкант (Kuryokhin), Верстальщик (Rodchenko).

**Порядок реплик:** Архитектор → Верстальщик → Музыкант → Математик → Структурщик → Teamlead

**Допущение комнаты (явное):** полный бриф с именами девяти кандидатов в переданный контекст не попал. Роли фиксируют **рабочий словарь из девяти лемм** по домену «честные исполнители спринта» и канону исполнения (реестр задач, LGTM, контур Ангелины, «матч ≠ тренировка»). Если у владельца иной состав девяти — ратификация M0 правит **имена узлов**, не метод рёбер. Рабочие имена: **E** состав/кто исполнитель; **H** контракт честности; **A** артефакт сдачи; **D** DoD / матч vs тренировка; **C** цепочка приёмки; **R** связь с реестром задач; **X** стык с контуром исполнения (Ангелина); **M** метрики и сигналы нечестности; **T** зубы (что будет при ложном закрытии).

---

[Архитектор]: Конструкция M0 — граф вопросов, не регламент спринта и не UI доски. Граница комнаты: упорядочить девять кандидатов; не проектировать `acceptedBy`, карточки реестра и санкции по существу. Цена спешки: если T или M объявить «сразу в код» до E и H — получим пустые гейты и два источника правды о «кто закрыл». Фундамент вижу в **E** (кому вообще приписываем исполнение) и **H** (что значит «честно»). Терминал — тот, чья область требует всех родов факта исполнения и проверки. Нужен DAG, не ADR по спринту.

[Верстальщик]: С витрины потребителя вердикта (капитан, вечерний разбор, карточка задачи, day-memo): без **E** неясно, чьи бейджи «вёл / принял»; без **H** и **D** зелёный CI рисует фальшивое «сдано»; без **A** полоса артефакта — декор. Рисую девять узлов, жду рёбра. Layout доски и аватары персонажей не проектирую — только что обязано быть определено раньше, чтобы витрина имела предмет.

[Музыкант]: По тракту сигнала: сначала *кто на шинах* (E — исполнители), потом *что считается честным take* (H), потом *какой файл/PR — master-tape сдачи* (A), потом *матч или только тренировка* (D), *кто ставит LGTM/приёмку* (C), *как это ложится в registry* (R), *как стыкуется с контуром ведущей* (X), *метры лжи и тишины* (M), и в конце *зубы гейта* (T). Не путать исполнительный порядок PR спринта с графом *решений* M0.

[Математик]: Предикат ребра фиксирую как в bridge/memory/tariff M0: ребро A→B ⇔ область определения вопроса B содержит переменную, которую задаёт ответ A. Не runtime-порядок скриптов и не «удобно обсуждать рядом». Кандидаты V={E,H,A,D,C,R,X,M,T}. Ищу минимальный DAG без циклов; обратный ранг = ребро из терминала в фундамент (например T→E как жёсткое «сначала санкции»).

[Структурщик]: Леммы «зависит» не смешиваем. **Контрактная** — без вердикта a у b нет области определения. **Фактурная** — b ждёт файл/PR в main. В M0 только контрактные. Имена — словарные статьи допущения: состав исполнителей; контракт честности; артефакт сдачи; DoD/матч-тренировка; цепочка приёмки; связь с реестром; стык с контуром исполнения; метрики/сигналы; зубы. Синонимы «ответственный / owner / leadPersona / agent» — предмет комнаты E/C, не M0.

[Teamlead]: Положение: M0 только про порядок. Планка — направленный граф, фундамент, терминал, риск обратного ранга, список посылок. Связка: Математик — предикат и проверка рёбер; Структурщик — леммы; Архитектор — границы формы. Не вердиктим девять кандидатов по существу. Обратный ранг — если зубы или метрики встанут до «кто» и «что честно»: получим пустые штрафы и два источника «кто сдал матч». Матч этой комнаты — упорядоченный список с зависимостями, не «удобный спринт про честность».

[Архитектор]: Рекомендация формы: **E** — фундамент (без носителя исполнения остальные комнаты говорят в пустоту). **H** сразу после E: честность без субъекта — абстракция. **A** и **D** опираются на H: артефакт и планка матча требуют словаря честного закрытия. **C** собирает E+A+D. **R** и **X** — проекции в уже существующие homes (реестр, контур), не вторые источники истины. **M** измеряет то, что уже определено. **T** — терминал: санкция без всех переменных — декоративный кнут.

[Верстальщик]: С витрины вечернего разбора: бейдж «закрыто» без D даёт фальшивый зелёный; бейдж persona без E — фальшивое присутствие (прецедент M1 мостика). Значит E и D контрактно раньше любой витрины статуса. **M** на витрине — полоса счётчиков; без H/A/C это декор-счётчики, как в memory C5 до C1. Терминалом витрины согласен: **T** читается после того, как ясны предметы наказания и метра.

[Музыкант]: На слух **X** (контур Ангелины) — это не solo и не сирена: ведущая держит поток, не ставит LGTM за Тарасова. Значит X контрактно *после* C (цепочка приёмки) и R (реестр): иначе вшьём в контур то, чего ещё нет в словаре приёмки. **M** — meters на шине исполнения, не новый эффект. **T** — gate на master bus; рано ставить — клиппинг доверия.

[Математик]: Черновик обязательных рёбер: E→H (честность *кого*); H→A (артефакт *как доказательство* честности); H→D ∧ A→D (DoD ссылается на контракт и на то, *что* сдано); E→C ∧ A→C ∧ D→C (приёмка: кто, что, по какой планке); E→R ∧ A→R ∧ C→R (реестр хранит связку task–persona–артефакт–статус приёмки). Проверяю циклы: пока ациклично.

[Структурщик]: Лемма **R**: home карточки/`registry.json` / `leadPersona` / `acceptedBy` — потребители словаря, не авторы. Лемма **X**: контур исполнения — оркестрация потока (Ангелина), не вторая приёмка. Ребро C→X и R→X — контрактные: без цепочки и реестра контуру нечего оркестрировать в этом домене. Не провожу X→C: ведущая не задаёт норму LGTM.

[Teamlead]: Держим планку: не сливаем C и X в один узел «кто-то принял». У меня вердикт LGTM|BLOCK; у контура — ритм и журнал. Обратный ранг C↔X разрушит комбинацию. Дальше — M и T. M без сигналов «ложное закрытие / сданная тренировка» — пустой прибор. T без M можно описать нормативно, но область T всё равно содержит переменные M, если зубы завязаны на сигнал — это ребро M→T, не наоборот.

[Архитектор]: Варианты терминала: (α) T — зубы; (β) X — «сначала вшить в контур». Цена β: контур станет местом изобретения санкций и метрик — нарушит границу «Ангелина не советующая». Цена α: T ждёт все роды факта — длиннее, но форма чистая. Рекомендую α: терминал **T**. **M** — предтерминал: измерительная обвязка над E…X, как C5 над C1–C4 в memory.

[Верстальщик]: Согласен с терминалом T. На витрине капитана порядок подключения читается так: сначала «кто и по какой планке», потом «где в реестре и в дне», потом «что видно на метрах», потом «что будет, если соврали». План «как нарисуем доску спринта» — *не* девятый кандидат и не терминал: это фактура после M0, иначе снова декор.

[Музыкант]: Стык R и X: registry — партитура слотов; контур — count-in дня. Оба слушают одну шину факта исполнения (E/H/A/D/C), не пишут каждый свою. Ребро R→X оставляю: прогрев/ведение дня читает реестр, а не наоборот. X→R не провожу — иначе journal ведущей станет источником статуса задачи.

[Математик]: Дополняю рёбра: C→X, R→X; H→M, A→M, C→M, R→M, X→M (метры над уже определёнными событиями); E→M тоже: «чья нечестность» требует состава. На T: E→T, H→T, A→T, D→T, C→T, R→T, X→T, M→T — терминал собирает все. Минимально достаточный набор на T: H→T, D→T, C→T, M→T; остальные — если формулировка зубов ссылается на артефакт/реестр/контур. Циклов нет. Обратных T→* и M→E нет.

[Структурщик]: Словарь рёбер, чтобы не поплыли синонимы. **E→H**: субъект до предиката. **H→A**: доказательство подчинено контракту, не «любой PR». **A→D** и **H→D**: планка матча сравнивает артефакт с нормой. **D→C**: приёмка ссылается на DoD. **C→R**: статус в реестре — проекция приёмки, не наоборот (запрет двух истин). **R→X**: контур читает реестр. **\*→M→T**: сначала сигнал, потом санкция. Ребро D→M: метрика «тренировка сдана как матч» требует определения D.

[Teamlead]: Проверка на «удобный спринт»: линейно E→H→A→D→C→R→X→M→T — похоже на учебник, но рёбра не запрещают параллель A∥ после H и уточнение D после A. Линейный представитель — для очереди комнат, не запрет параллельных контрактов. Риск: комната R до C — впишем в registry статусы без нормы приёмки. Блокирую R≺C в линейном порядке заседания.

[Архитектор]: Линейный порядок заседания как топологическая сортировка с дисциплиной: E, H, A, D, C, R, X, M, T. Допускаю уточнение: A и D оба после H; если D требует только H без A — слабо; на практике DoD «матч» смотрит на артефакт ценности — A→D оставляем. I (план интеграции в код) *нет* среди девяти — и не добавляем контрабандой: интеграция = фактура после вердиктов существа, как в tariff после F… 

[Верстальщик]: Линейный E…T с витрины ок: капитан не видит «зубы» раньше «кто». Честная пустота на промежуточных вердиктах: пока нет C, витрина статуса задачи = `n/a (no acceptance chain)`, не серый «наверное ок». Это требование к *будущим* комнатам, не layout сейчас.

[Музыкант]: Слышу дыру: нет отдельного кандидата «анти-паттерны / бестиарий ложного закрытия». Это не повод плодить 10-й узел в M0: анти-паттерны — наполнение H, D и M (предикат, планка, сигнал). Иначе снова синоним-слой. На слух ок.

[Математик]: Предикат «минимальный DAG» (обязательные рёбра):  
E→H; H→A; H→D; A→D; E→C; A→C; D→C; E→R; A→R; C→R; C→X; R→X; H→M; A→M; D→M; C→M; R→M; X→M; E→M; H→T; D→T; C→T; M→T; A→T; R→T; X→T; E→T.  
Сокращённый каркас (несводимые): E→H→A→D→C→R→X→M→T плюс E→C, E→R, E→M, E→T, H→D, H→M, H→T, A→C, A→R, A→M, A→T, D→M, D→T, C→M, C→T, R→M, R→T, X→M, X→T.  
Обратные и запретные: T→*; M→E; M→H как «метр задаёт норму»; X→C; R→C; D→H.

[Структурщик]: Запрет двух источников истины — посылка в граф: R и X **проекции**, C и H/D — **норма**. Ребро «R задаёт, что честно» не проводим. Фактурные «уже есть registry.json / PROMPT_ANGELINA» в M0 не входят: наличие файла не создаёт контрактного ребра. Если владелец переименует девять лемм — сохраняем типы узлов: субъект → норма → доказательство → планка → приёмка → homes → оркестрация → прибор → санкция.

[Teamlead]: Сверка с планкой. Фундамент: **E**. Терминал: **T**. Линейный представитель: **E → H → A → D → C → R → X → M → T**. Риск обратного ранга назван: T/M/R/X раньше E/H/C. Связка на ратификацию: Математик — таблица рёбер; Структурщик — леммы в протокол; Архитектор — граница «без существа». Существо комнат — после слова капитана по порядку. Вердикт комнаты готов к фиксации, если нет цикла и нет десятого узла «заодно UI».

[Архитектор]: Граница формы соблюдена: девять узлов, один DAG, без SKU-эквивалента «какие поля в registry». Цена допущения имён: владелец может заменить ярлыки; тогда M0-bis только на переименование + проверка рёбер предикатом Математика, не новый консилиум с нуля. Рекомендация: принять DAG; ADR не нужен.

[Верстальщик]: Принимаю линейный представитель и терминал T. С витрины следующих комнат: каждая комната обязана оставить честные метки статуса для потребителя (капитан/мемо), без фальшивого «исполнитель есть» до E. DoD витрины — не предмет M0, только посылка к D/C.

[Музыкант]: Принимаю. На слух тракт не клиппит: сначала люди и норма, потом take и планка матча, потом приёмка и homes, потом meters и gate. X не сирена — после C и R. T в конце.

[Математик]: Принимаю. Инвариант ацикличности выполнен; фундамент E: indegree 0 в каркасе; терминал T: outdegree 0. Предикат ребра единообразен с memory/bridge/tariff M0. Список условных рёбер: A→D — если DoD ссылается на форму артефакта (принято как да); M→T — если зубы триггерятся сигналом (принято как да); X→M — если контур эмитит события дня в прибор (принято как да). Снятие — только явной ратификацией владельца.

[Структурщик]: Принимаю. Леммы и запрет смешения контракт/фактура зафиксированы. Публичные имена девяти — словарные статьи протокола; жирные id файлов внутрь вердикта-порядка не тащим.

[Teamlead]: Принимаю. Положение сыграно: порядок есть, существо не трогали. Решение — DAG и линейный представитель ниже. Дальше — слово капитана на ратификацию имён узлов и очереди комнат. Без ратификации в код «зубов спринта» не идём.

[Архитектор]: Финальная конструкция: один источник нормы честности (H/D/C), homes (R/X) только проекции, M обвязка, T терминал. Модули кода вне M0. Форма закрыта.

[Верстальщик]: Финально с витрины: девять узлов читаются слева направо как «кто → норма → proof → планка → приёмка → реестр → день → метры → зубы». Принимаю.

[Музыкант]: Финально по тракту: master-tape факта до gate. Принимаю.

[Математик]: Финально: DAG ниже; циклов 0; обратный ранг 0 в принятом множестве. Принимаю.

[Структурщик]: Финально: словарь девяти и рёбра согласованы. Принимаю.

[Teamlead]: Матч M0 — порядок. LGTM на протокол порядка. Существо — следующие девять комнат по очереди после ратификации капитана.

| Вопрос | Решение |
|--------|---------|
| Предмет M0 | Только **порядок** разбора девяти кандидатов (DAG + линейный представитель + посылки). Существо не вердиктится. |
| Допущение имён | Бриф с каноническими именами в контекст не попал; принят **рабочий словарь E…T**. Владелец ратифицирует имена; смена ярлыков → M0-bis на рёбра, не обнуление метода. |
| Фундамент | **E** — состав / кто исполнитель спринта |
| Терминал | **T** — зубы (последствия ложного закрытия) |
| Линейный представитель | **E → H → A → D → C → R → X → M → T** |
| Смысл позиций (простым текстом) | 1) кто исполнитель → 2) контракт честности → 3) артефакт сдачи → 4) DoD / матч vs тренировка → 5) цепочка приёмки → 6) связь с реестром задач → 7) стык с контуром исполнения → 8) метрики и сигналы → 9) зубы |
| Минимальный DAG (несводимый каркас) | **E→H**; **H→A**; **H→D**; **A→D**; **E→C**; **A→C**; **D→C**; **E→R**; **A→R**; **C→R**; **C→X**; **R→X**; **H→M**; **A→M**; **D→M**; **C→M**; **R→M**; **X→M**; **E→M**; **H→T**; **D→T**; **C→T**; **M→T**; плюс **A→T**; **R→T**; **X→T**; **E→T** (если формулировка T ссылается на них) |
