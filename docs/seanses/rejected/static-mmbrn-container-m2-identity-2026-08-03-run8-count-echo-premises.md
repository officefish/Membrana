## Итоговое решение консилиума

### Пропозиция-контракт M2

Каждый материал контейнера `static.mmbrn.tech` получает **ровно одну запись** в append-only реестре `docs/evidence/registry.jsonl`. Запись неизменяема после добавления. Любое изменение любого поля — `location`, `about`, `measured`, `source` или иного — создаёт **новую запись** с новым `id` и полем `supersedes`, указывающим на прямого predecessor; старая строка остаётся историей без мутации.

Каждый материал несёт три независимых тождества: **байтовое** (`sha256` конкретной последовательности байтов), **record** (неизменяемый `id` конкретной строки реестра), **lineage** (root = `id` первой записи цепочки). Значение root численно совпадает с record `id` первой записи, но это три разных предмета: байтовая последовательность, строка реестра и логическая цепочка — не одно и то же.

Логическая линия — линейная ациклическая цепь записей `r0..rk`; predecessor `r0` отсутствует; predecessor `ri` (`i ≥ 1`) = явный `supersedes` этой записи. Только для четырёх поимённых legacy-записей (`ozon-receipt-3765-field-kit-r2`, `day-memo-2026-07-28-r2`, `bpla-guidance-methodology-partner-r2`, `bpla-guidance-methodology-partner-r3`) без поля `supersedes` predecessor определяется позиционно: существующий `<root>-rM` с максимальным `M < N` либо запись `<root>`. Для всех прочих записей без `supersedes` predecessor отсутствует. Fork, merge, циклы и порядок по `addedAt` запрещены; все новые поправки обязаны нести явный `supersedes`.

Стабильный канонический адрес линии: `canonicalRef = "urn:mmbrn:static:" + rootId`. Он отличен от `id` поправочной записи и от физического `location`; сохраняется при смене склада и движка; не является публичным URL и не предрешает доступность или права.

Составной формат (архив, PDF со встроенными объектами) регистрируется **целиком как одна запись**. Член архива или встроенный объект PDF получает отдельную запись только если: (а) он независимо поступил как материал, либо (б) M6 предоставил его как материал. M2 не назначает извлечение, хранение производных или отдельный компонентный `sha256`.

`source` — происхождение самих байтов или материала, не автор операции регистрации, адресной поправки или иной операции.

Чувствительный материал: запись реестра обязательно содержит валидный `location.kind` (один из `local`, `affine`, `url`, `archivarius`) и непустой `location.ref`; отдельное поле `sensitive.reason` несёт причину чувствительности. Байты могут физически находиться вне репозитория — это M4. Видимость `ref` — M3. Реестр честно фиксирует факт существования материала, `sha256`, `source` и `sensitive.reason` независимо от физической достижимости байтов.

Реестр `docs/evidence/registry.jsonl` — **единственный источник истины** о регистрации, record/lineage identity, заявленных полях и истории. Байты — независимый предмет: при доступе они верифицируют заявленные `sha256` и `bytes`, но не восстанавливаются из JSONL автоматически и не заменяют реестр. `location` — заявление реестра; достижимость — внешнее состояние склада.

### Таблица полей и инвариантов

| Поле | Уровень | Роль | Инвариант |
|------|---------|------|-----------|
| `id` | Record | Уникальный идентификатор строки реестра | Неизменяем после записи; уникален в реестре |
| `sha256` | Bytes | Криптографический отпечаток байтовой последовательности | Меняется только если меняются байты; совпадает у дублей |
| `bytes` | Bytes | Размер байтовой последовательности | Положительный целый; валидатор требует |
| `addedAt` | Record | Дата добавления строки | Формат `YYYY-MM-DD…`; не определяет порядок в линии |
| `source` | Bytes | Происхождение байтов или материала | Не автор операции; повторяется при адресной поправке; фиксируется заново при новой редакции |
| `location.kind` | Record | Тип склада | Только `local` / `affine` / `url` / `archivarius` |
| `location.ref` | Record | Адрес на складе | Непустой; хранится в реестре даже для sensitive |
| `supersedes` | Record | Ссылка на прямого predecessor | Обязателен для всех новых поправок; `id` предшествующей записи |
| `sensitive.reason` | Record | Причина чувствительности | Отдельное поле; не заменяет `location` |
| `about` | Record | Описание материала | Опциональное; изменение создаёт новую запись |
| `measured` | Record | Измеренные характеристики | Опциональное; изменение создаёт новую запись |
| `root` (lineage) | Lineage | `id` первой записи линии | `root = id(r0)`; не меняется при поправках |
| `canonicalRef` (lineage) | Lineage | Стабильный адрес линии | `"urn:mmbrn:static:" + rootId`; инъективен; не публичный URL |

### Разбор шести случаев

| Случай | Байты | Запись | Линия |
|--------|-------|--------|-------|
| **Простой PDF** | sha256 фиксирует конкретную последовательность байтов PDF; меняется при любом изменении содержимого | Новая запись при поступлении: новый `id`, `sha256`, `source`, `location`, `addedAt`; одноэлементная линия: значение root равно этому `id` | Новая линия: root = этот `id`; `canonicalRef = "urn:mmbrn:static:" + id`; три уровня разные, значение root совпадает с record `id` численно |
| **Байтовый дубль под другим именем** | Те же (sha256 совпадает с существующей записью) | Новая (новый `id`; реестр фиксирует оба; автоматического слияния нет — находка для человека) | Новая (новый root, новый `canonicalRef`; независимая линия) |
| **Новая редакция содержания** | Иные (sha256 меняется: байты другие) | Новая (новый `id`, новый `sha256`, `supersedes` на прежнюю, `source` фиксируется заново) | Та же (root не изменился; `canonicalRef` сохранён; цепочка predecessor ведёт к тому же r0) |
| **Архив и его член** | Архив: sha256 всего архива. Член: sha256 члена (только если член поступил отдельно или M6 предоставил) | Архив: одна запись целиком. Член: своя запись только при независимом поступлении или предоставлении M6; иначе записи члена нет | Архив: своя линия. Член (если зарегистрирован): независимая линия; связь семантическая, не через `supersedes` |
| **Перемещение байтов между складами** | Те же (sha256 не меняется; байты не изменились) | Новая (новый `id`, новый `location`, `supersedes` на прежнюю; `source` повторяется) | Та же (root не изменился; `canonicalRef` сохранён) |
| **Чувствительный материал без публичного локатора** | Те же (sha256 зафиксирован в реестре; байты физически вне репозитория — M4) | Новая запись с допустимым `location.kind` и непустым `location.ref` (честно непереносимый адрес); `sensitive.reason` обязателен | Та же логика линии: root, `canonicalRef`; видимость ref — M3; физический склад — M4 |

*Что остаётся тем же, что меняется, и доказательство:*

- **Байты** остаются теми же ↔ `sha256` совпадает. Меняются ↔ `sha256` меняется. Доказательство: криптографическая коллизионная устойчивость SHA-256.
- **Запись** остаётся той же ↔ `id` не изменился (невозможно при append-only: новая запись всегда новый `id`). Меняется при любом изменении любого поля. Доказательство: append-only инвариант реестра.
- **Линия** остаётся той же ↔ root не изменился (`canonicalRef` тот же). Меняется только при первичной регистрации нового материала. Доказательство: root = `id(r0)`, r0 не мутирует; `canonicalRef` = функция от root.
