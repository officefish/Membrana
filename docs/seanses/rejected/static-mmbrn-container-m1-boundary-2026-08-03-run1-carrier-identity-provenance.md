[Архитектор]: Положительная граница: контейнер принимает **документальные файлы внешнего происхождения с зафиксированным содержимым** — то, что было создано вне Membrana и поступает на хранение как факт. Отрицательная граница: контейнер не принимает артефакты, порождённые внутри системы (производные), конфигурационные файлы инфраструктуры, стратегические редактируемые документы (это Panel), живые рабочие заметки движка.

[Музыкант]: Ещё один вопрос для границы: архив исходных данных исследования — это набор файлов, возможно, с внутренней структурой. Он внешнего происхождения и зафиксирован в момент приёма. Значит, он попадает в положительную границу как единый канонический объект, даже если внутри него много файлов. Контейнер не раскрывает его внутреннюю структуру — только хранит.

[Структурщик]: Соглашусь. Архив — это атомарный канонический объект с точки зрения контейнера: он принят целиком, не изменяется, его содержимое не трактуется контейнером. Разворачивание архива — это уже действие движка, порождающее производные. Это важно для инварианта смены движка: движок меняется, архив остаётся.

[Математик]: Формализую критерий принятия. Артефакт принимается контейнером, если выполнены два условия: (1) происхождение внешнее — создан вне Membrana до момента приёма; (2) содержимое фиксированное — не предназначено для редактирования внутри системы. Если хотя бы одно условие не выполнено — артефакт не является каноническим объектом контейнера.

[Teamlead]: Переходим к разделению обязанностей контейнера и движка. Это принципиально для инварианта смены Affine.

[Верстальщик]: С точки зрения человека, работающего с движком: движок — это интерфейс удобной работы. Он показывает, ищет, даёт превью, создаёт страницы с ссылками. Контейнер — это хранилище факта. Движок не владеет оригиналом: он обращается к контейнеру. Если движок сменить, оригиналы должны остаться. Страница Affine — это состояние движка, не содержимое контейнера.

[Архитектор]: Разделение обязанностей формально. Контейнер обязан: принять оригинал, зафиксировать его неизменяемость, предоставить доступ к нему. Контейнер не обязан: отображать, индексировать для поиска, создавать превью — это функции движка. Движок обязан: обеспечивать удобную человеческую работу с контейнером. Движок не вправе: изменять канонические объекты, определять, что является каноническим объектом, и хранить единственную копию оригинала.

[Музыкант]: Ключевой инвариант смены движка: после замены Affine на любой другой движок все канонические объекты контейнера должны быть доступны без потерь. Производные могут быть пересчитаны. Записи управления должны быть перенесены или пересозданы. Состояния старого движка (страницы Affine, служебные изображения движка) — теряются, и это допустимо, потому что они не являются содержимым контейнера.

[Структурщик]: Важное следствие: запись индекса `docs/evidence` — это запись управления, а не канонический объект. Она описывает оригиналы, указывает на них, изменяется при добавлении новых объектов. Это соответствует тому, что `docs/evidence` уже различает индекс как суть и склад как сменную деталь. Индекс — запись управления; склад под контейнером — место хранения канонических объектов.

[Математик]: Уточню: запись управления — это изменяемая, и это не дефект, а признак. Она обязана изменяться при добавлении оригиналов, изменении метаданных, обновлении ссылок. Неизменяемость — только свойство канонического объекта. Производное представление — пересчитываемо, но в конкретный момент времени фиксировано. Три разных режима изменяемости.

[Архитектор]: Скан чека: аналогично. Внешнего происхождения — создан сканером до приёма системой. Содержимое зафиксировано — это изображение физического документа. Предназначен для хранения как факт. **Канонический объект** контейнера.

## Итоговое решение консилиума

### Пропозиция-контракт M1

`static.mmbrn.tech` — неизменяемый контейнер документальных файлов внешнего происхождения. Контракт устанавливает:

**Положительная граница (принимаются):**
Документальные файлы внешнего происхождения с зафиксированным содержимым — PDF, сканы, архивы данных, иные внешние материалы, — поступившие на хранение как факт до или в момент приёма.

**Отрицательная граница (отвергаются):**
Артефакты внутреннего производства (производные: превью, OCR, транскрипты); редактируемые стратегические документы (принадлежат Panel); конфигурационные и инфраструктурные файлы; рабочие состояния движков (страницы Affine и аналоги).

**Различие трёх типов:**

| Тип | Определение | Изменяемость |
|---|---|---|
| Канонический объект | Внешнего происхождения, зафиксирован при приёме | Неизменяем после приёма — абсолютный инвариант |
| Производное представление | Детерминированно выводится из канонического объекта внутри системы | Пересчитываемо; при смене алгоритма пересоздаётся |
| Запись управления | Изменяемые атрибуты и индексные записи, описывающие объект | Изменяема; обновляется при добавлении объектов и правке метаданных |
| Состояние движка | Артефакт, созданный и принадлежащий движку | Жизненный цикл движка; не актив контейнера |

**Разделение обязанностей:**

| Контейнер обязан | Движок (в т.ч. Affine) обязан | Движок не вправе |
|---|---|---|
| Принять оригинал | Обеспечивать удобную работу с контейнером | Изменять канонические объекты |
| Зафиксировать неизменяемость | Порождать производные по запросу | Определять, что является каноническим объектом |
| Предоставить доступ к оригиналу | Управлять своим состоянием отдельно от контейнера | Хранить единственную копию оригинала |

**Инварианты смены движка:**
1. Все канонические объекты доступны после смены без потерь.
2. Производные могут быть пересчитаны новым движком.
3. Записи управления переносятся или пересоздаются.
4. Состояния старого движка не являются активами контейнера; их потеря не нарушает контракт.

**Таблица шести примеров:**

| Пример | Класс | Основание |
|---|---|---|
| Исходный PDF доклада | Канонический объект | Внешнего происхождения, содержимое зафиксировано, принят на хранение как факт |
| Скан чека | Канонический объект | Внешнего происхождения (создан сканером до приёма), содержимое зафиксировано |
| Архив исходных данных исследования | Канонический объект | Внешнего происхождения, атомарный при приёме, контейнер не интерпретирует содержимое |
| Превью или OCR | Производное представление | Порождено из канонического объекта внутри системы, пересчитываемо |
| Запись индекса `docs/evidence` | Запись управления | Изменяемая, описывает объекты, не является их содержимым |
| Страница Affine | Состояние движка | Создана движком, принадлежит движку, жизненный цикл определяется движком |

**Нецели (явно зафиксированы):**
- Стратегический редактор остаётся отдельным продуктом Panel; стратегические документы не входят в контейнер.
- Код, DNS и прод в M1 не затрагиваются.
- Affine не определяет контейнер; его смена не изменяет контракт.
