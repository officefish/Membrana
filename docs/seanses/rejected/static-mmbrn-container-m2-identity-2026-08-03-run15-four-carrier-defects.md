## Итоговое решение консилиума

### Вердикт I1 (единая пропозиция)

Каждый материал `static.mmbrn.tech` при поступлении получает начальную запись в `registry.jsonl`; последующие состояния той же линии получают новые append-only записи. Контракт тождества трёхуровневый и неразрывный: байтовое тождество определяет `sha256` (контрактно, при принятом предположении коллизионной устойчивости SHA-256); record-тождество определяет неизменяемый `id`; lineage-тождество определяет root — `id` первой записи без effective predecessor. Единственный стабильный внешний адрес линии: `canonicalRef = "urn:mmbrn:static:" + rootId`. Реестр — единственный источник истины о регистрации, record identity, lineage и истории; байты — независимый предмет верификации, не производная реестра.

### Таблица полей и инвариантов `EvidenceRecord`

| Поле | Обязательность | Роль | Инвариант |
|---|---|---|---|
| `id` | обязательное | record identity | Уникален в реестре; назначается при создании записи; не изменяется никогда; любое изменение любого поля создаёт новую запись с новым `id` |
| `sha256` | обязательное | байтовое тождество | Контрактный идентификатор байтов при принятой коллизионной устойчивости SHA-256; неизменяем для данной записи; у новой редакции обязан отличаться; адресная поправка сохраняет тот же `sha256` |
| `bytes` | обязательное | размер байтов | Положительное целое; измеренный размер конкретных байтов; верифицируется при доступе; при адресной поправке повторяется; при новой редакции перемеряется и фиксируется заново (численно может совпасть с предыдущим); изменение байтов требует новой записи |
| `addedAt` | обязательное | дата регистрации | Дата добавления записи в реестр формата `YYYY-MM-DD…`; не дата создания байтов |
| `source` | обязательное | провенанс байтов | Откуда пришли байты, не кто выполнил операцию; при адресной поправке повторяется; при новой редакции фиксируется заново |
| `location.kind` | обязательное | тип адреса | Только: `local`, `affine`, `url`, `archivarius`; `sensitive` не является kind |
| `location.ref` | обязательное | адрес байтов | Непустая строка при любом kind; заявление реестра о местонахождении; достижимость — внешнее состояние склада |
| `supersedes` | условное | effective predecessor | `id` предыдущей записи в линии; обязателен для всех новых записей-поправок и редакций; у первой записи линии отсутствует |
| `about` | опциональное | описание | Изменение создаёт новый `id`; не меняет `sha256` и root; record identity меняется |
| `measured` | опциональное | измерения | Изменение создаёт новый `id`; не меняет `sha256` и root; record identity меняется |
| `sensitive.reason` | условное | причина чувствительности | Обязателен при чувствительном материале; `location` остаётся валидным с допустимым kind и непустым ref |

### Семантика линии

Функция effective predecessor: `ep: R → Id(R) ∪ {⊥}`

- Для записи с явным `supersedes`: `ep(r) = supersedes`
- Для четырёх legacy-записей без `supersedes` (`ozon-receipt-3765-field-kit-r2`, `day-memo-2026-07-28-r2`, `bpla-guidance-methodology-partner-r2`, `bpla-guidance-methodology-partner-r3`): `ep(r)` = id существующей максимальной меньшей ревизии той же базовой линии, либо id base-записи
- Для всех прочих записей без `supersedes`: `ep(r) = ⊥`

**Root** — запись, где `ep(r) = ⊥`.
**Tip** — `id`, отсутствующий среди всех значений `ep` по всему реестру (включая вычисленные legacy-связи).
В линии длины 1 обе роли исполняет одна запись. В линии длины больше 1 — гарантированно разные записи. Множества roots и tips равночисленны, но их определения различны и не отождествляются.

**Три legacy-линии (определены точно):**

| Линия | Root (base) | Промежуточные | Tip |
|---|---|---|---|
| ozon-field-kit | `ozon-receipt-3765-field-kit` | — | `ozon-receipt-3765-field-kit-r2` |
| day-memo | `day-memo-2026-07-28` | — | `day-memo-2026-07-28-r2` |
| bpla-guidance | `bpla-guidance-methodology-partner` | `bpla-guidance-methodology-partner-r2` | `bpla-guidance-methodology-partner-r3` |
