## Итоговое решение консилиума

### Пропозиция-контракт B1

**`static.mmbrn.tech` является контейнером неизменяемых внешних артефактов Membrana, который принимает канонические объекты (оригиналы с фиксированным содержанием и внешним происхождением), явно включённые хранимые производные и контейнерные записи управления; отвергает вычисляемые на лету производные, состояния движков, код, инфраструктурные конфигурации и стратегические редакторские документы; при смене любого движка сохраняет все три принимаемых класса без исключения, не теряя ни одной контейнерной записи управления до решения M2.**

### Положительная граница (принимается)

| Класс | Критерий |
|---|---|
| Канонический объект (оригинал) | Завершённый артефакт фиксированного содержания с внешним происхождением; после фиксации изменение содержания создаёт новый объект |
| Хранимое производное (`D_stored`) | Производное от оригинала, явно включённое в контейнер решением (не вычисляемое на лету) |
| Запись управления (`M`) | Контейнерный реестр (`docs/evidence`); не является производной от оригиналов и не является состоянием движка; семантика не восстанавливается из байтов оригиналов |

### Отрицательная граница (отвергается)

| Класс | Примеры |
|---|---|
| Вычисляемое производное (`D_computed`) | OCR, превью — до явного включения |
| Состояние движка (`E`) | Страницы Affine, внутренние рабочие артефакты любого движка |
| Код и инфраструктура | Репозитории, DNS-конфигурации, деплой-артефакты |
| Стратегические редакторские документы | Принадлежат Panel, отдельному продукту |

| Пример | Класс | Обоснование |
|---|---|---|
| Исходный PDF доклада | Канонический объект (`O`) | Завершённый внешний артефакт фиксированного содержания |

### Инварианты смены движка

1. При замене любого человеческого движка (включая Affine) контейнер сохраняет весь `O ∪ D_stored ∪ M` без исключения.
2. Состояние движка (`E`) может быть утрачено при смене — это допустимо по определению класса.
3. Запись управления `docs/evidence` принадлежит `M`, а не `E`: её потеря недопустима и не объявляется допустимой до решения M2.
4. Наличие объекта в Affine не является основанием для его принадлежности контейнеру.
