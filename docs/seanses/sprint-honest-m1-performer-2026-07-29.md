# Консилиум: честный исполнитель спринта — машинная сущность и предикат «назначен ≠ участвовал»

**Повестка:** Чем «честный исполнитель спринта» является *машинно* (не метафора, не роль в UI) и какой предикат отличает **назначенного** от **участвовавшего**. Вне скоупа: код приложения, разметка задач по зонам ответственности, LGTM на дифф.

**Участники:** Teamlead (Tarasov), Архитектор (Vesnin), Структурщик (Ozhegov), Математик (Dynin), Музыкант (Kuryokhin), Верстальщик (Rodchenko).

**Порядок реплик:** Музыкант → Teamlead → Структурщик → Архитектор → Математик → Верстальщик

[Музыкант]: На слух вопрос не про «кто в титрах», а про take: кто реально сыграл партию спринта. Назначенный — это имя на пюпитре; участвовавший — тот, чей звук есть на ленте. Машинно нужен носитель следа исполнения, не label в карточке. Иначе снова mono-take: объявили Курёхина — а в миксе тишина.

[Teamlead]: Положение: матч проигрывается, когда «исполнитель» = строка в брифе, а связка не оставила квитанции. Не про зоны и не про код — про честность закрытия спринта. Решение комнаты: зафиксировать *что считается исполнителем* как проверяемый объект и предикат assigned vs participated. Без «почти участвовал».

[Структурщик]: Леммы, иначе синонимы. **Назначение (assignment)** — запись связи sprintId → personaId (или agent-slot) до/на старте окна. **Участие (participation)** — наличие адресуемого следа исполнения, привязанного к тому же sprintId. **Исполнитель спринта** — не роль и не leadPersona карточки задачи, а субъект, для которого participation = true. Карточка реестра задач — другой словарь; сюда её не тащим.

[Архитектор]: Конструкция: два слоя, не один ярлык. Слой A — план (кто *должен*). Слой B — факт (кто *оставил след*). Смешивать их в одном поле «executor» — декорация без несущей. Граница: assignment живёт в плане спринта; participation — в журнале исполнения спринта. Цена альтернативы «один enum на всё» — ложь витрины при любом no-show.

[Математик]: Формализую без UI. Пусть S — идентификатор спринта, P — множество persona id (закрытый алфавит канона).  
`assigned(S, p) ⇔ ∃ запись плана: (S, p) ∈ Assignments`.  
`participated(S, p) ⇔ ∃ след e ∈ Evidence(S): subject(e)=p ∧ qualifies(e)`.  
Исполнитель честный: не синоним assigned. Носитель — предикат над Evidence, не строка в markdown «кто вёл».

[Верстальщик]: С витрины капитана: «Исполнитель: Ozhegov» при пустом следе — фальшивое присутствие, как на мостике без callable. Требую два честных индикатора рядом, не один бейдж: *назначен* / *участвовал*. Пустота участия видна: `participated: none`, не прочерк «—» без смысла. Layout не рисую — только контракт меток.

[Музыкант]: Evidence на слух — не «был в комнате», а take с таймкодом: жест, протокол, артефакт закрытия, запись в op-log спринта. Ambient presence (просто открыл чат) — room tone, не партия. Иначе Фаррелл на каждом такте станет «участником» без take — клиппинг смысла.

[Teamlead]: Планка: assigned без participated — это **не сыгранный матч**, даже если CI зелёный у «чьей-то» ветки. Участвовавший без assignment — допустим как *фактический* исполнитель, но не маскируется под план: связка честно числится post-factum или как support-след. Вердикт потом; сначала зуб на предикат.

[Структурщик]: Ещё леммы. **Evidence (след)** — иммутабельная запись с полями: `sprintId`, `subject` (persona|agentSlot), `kind` (закрытый enum), `at`, `ref` (путь/id артефакта), опционально `provenance`. **Sprint executor record** — не человек и не git-branch, а проекция: `{ assigned: P[], participated: P[] }` + ссылки на evidence ids. Ветки персонажей в git — исторический шум; в предикат не входят.

[Архитектор]: Форма решения: «честный исполнитель спринта» машинно = **функция от журнала Evidence и плана Assignments**, не сущность в `registry.json` задач. Реестр задач отвечает «кто lead на карточке»; спринт-исполнение — отдельный home (журнал/квитанция окна спринта). Иначе снова синоним-слой: task.leadPersona ≈ sprint.executor.

[Математик]: Уточняю `qualifies(e)`. Минимальный v1 — дизъюнкция по kind с жёстким якорем на S:  
`qualifies(e) ⇔ kind(e) ∈ K_exec ∧ ref_resolvable(e) ∧ time_in_window(e, S)`  
(или explicit link sprintId). K_exec — закрытый набор: не «любой комментарий». Кандидаты в K_exec обсудим; пустое K_exec запрещено (иначе participated ≡ false всегда — честно, но бесполезно).

[Верстальщик]: Для читателя протокола спринта полоса «кто играл» строится только из participated. Assigned, не вошедшие в participated — отдельная полоса «не вышли на лёд» / no-show. Сливать в одну фамилию — декор. Честная пустота обеих полос допустима: спринт без плана и без следов = void, не «команда целиком».

[Музыкант]: Опасный вид клиппинга: один громкий take в конце окна перекрывает молчание всего спринта — recency как единственный fader. Предикат участия не должен быть «последний, кто написал done». Нужен хотя бы один квалифицирующий след *в окне*, не обязательно финальный аккорд.

[Teamlead]: Согласен. Участие — факт работы в матче, не право сорвать финальный свисток. Назначенный, молчавший до close и вписавший имя в summary — BLOCK по честности, даже если текст красивый. Связка: Математик держит qualifies; Структурщик — home следов; витрина — Верстальщик.

[Структурщик]: Home (логическая, без привязки к apps): план спринта `Assignments(S)` и лента `Evidence(S)` — разные контейнеры одного контура «sprint-execution», не ветки задачника. Связь с task registry — только optional ref «закрывали карточки X», не определение исполнителя. Имя поля `executor` в одном месте запрещаю: только `assigned[]` и `participated[]`.

[Архитектор]: Вариант с ценой. V1: participated выводится **только** из evidence (append-only). V2 (дороже): ручной override владельца с меткой `owner_asserted` — редко, виден, не затирает evidence. Рекомендация: V1 обязателен; override — отдельный kind, не молчаливая правка списка. Иначе предикат снова станет вкусом.

[Математик]: Предикаты различия:  
`only_assigned(S,p) ⇔ assigned(S,p) ∧ ¬participated(S,p)`  
`only_participated(S,p) ⇔ ¬assigned(S,p) ∧ participated(S,p)`  
`honest_pair(S,p) ⇔ assigned(S,p) ∧ participated(S,p)`  
«Честный исполнитель» в узком смысле для отчёта плана: `honest_pair`. «Фактический исполнитель»: `participated`. Машинный тип ответа — множества, не скаляр «один герой».

[Верстальщик]: Скаляр «один герой» на афише — конструктивизму враг. Карточка спринта: таблица p × {assigned, participated} или две колонки id. Акцент — на only_assigned (риск) и only_participated (внеплан). Не иконка звезды «MVP спринта» без данных.

[Музыкант]: K_exec на слух, черновик для Математика: (1) принятый артефакт закрытия с acceptedBy=p и sprintId; (2) именованная реплика/жест в протоколе окна с subject=p; (3) machine receipt шага процедуры спринта с actor=p. Не K_exec: присутствие в CC, эмодзи, «я на связи». Ирония к магической кнопке Done без ref.

[Teamlead]: K_exec принимаю как направление, не как меню на вкус. Правило нагрузки: нет ни одного qualifies — participated пуст — спринт **не имеет** фактического исполнителя, даже если assigned полон. Это не трагедия витрины, это диагноз. Кто «должен был» — полоса no-show для разбора, не подстановка в исполнители.

[Структурщик]: Словарь статуса спринта по исполнителям (закрытый enum, не prose):  
`unplanned` — assigned∅ ∧ participated∅  
`planned_silent` — assigned≠∅ ∧ participated∅  
`shadow_work` — assigned∅ ∧ participated≠∅  
`aligned` — ∃p honest_pair (и остальное приложимо)  
`mixed` — есть и only_assigned, и participated  
Имена — словарные статьи отчёта, не mood.

[Архитектор]: Граница с Ангелиной и контуром исполнения: она может оркестрировать и ставить acceptedBy на артефакт — это evidence kind, если контракт так сказан. Но «ведущая дня» ≠ автоматический participated каждого спринта. Участие персонажа только через qualifies с subject=id персоны, не через «день шёл».

[Математик]: Инвариант честности отчёта:  
`report.executors_factual(S) = { p | participated(S,p) }`  
`report.executors_planned(S) = { p | assigned(S,p) }`  
Запрещено: `executors := assigned` как default.  
Предикат «есть честный исполнитель плана»: `∃p honest_pair(S,p)`.  
Предикат «план соврал»: `assigned≠∅ ∧ participated=∅` ≡ planned_silent.

[Верстальщик]: В summary для капитана три строки, читаемые без легенды: план → факт → расхождение (only_assigned / only_participated). Цветом не спасать: planned_silent = явный warning-текст, не зелёный «спринт закрыт» из одного checkbox.

[Музыкант]: Ещё анти-паттерн: «участвовал структурщик, потому что задача ozhegov в registry». Это разметка зоны — вне повестки и вне qualifies. След обязан указывать sprint window, не label карточки. Иначе again: партия с чужого пюпитра записана на нашего солиста.

[Teamlead]: Фиксирую запрет в вердикте: leadPersona/supportPersonas задачи **не** имплицируют participated спринта. Назначение на спринт — отдельный акт плана окна. Кто взял task-label — ещё не сыграл спринт-матч. Пас важнее фамилии на майке.

[Структурщик]: Акт назначения машинно: append в Assignments с `at`, `by` (кто назначил), `subjects[]`, `sprintId`, optional `role_in_sprint` (lead|support) — но role_in_sprint **не** заменяет participation. Удаление assignment в v1 — не mute: только supersede новой записью, чтобы no-show считался относительно финального плана окна.

[Архитектор]: Срок окна S: полуинтервал времени + id. Evidence вне окна не qualifies, если нет явного `relatesToSprint=S` (исключение для close-квитанции с лагом — тогда kind `late_close` и флаг late, не тихая подмена at). Иначе вечный post-hoc вписанный исполнитель.

[Математик]: Late: `qualifies_late(e)` отдельно; в v1 можно `participated` = qualifies ∨ (qualifies_late ∧ within_grace). Grace — параметр окна, не «когда вспомнили». Без grace late не кормит participated — только журнал оговорок. Численно: булева алгебра над конечными множествами, без score «насколько участвовал» в v1 (ordinal later, не сейчас).

[Верстальщик]: Score «80% участия» — декор-метрика без контракта; в v1 не показываем. Только множества и статусы enum Структурщика. Пустой fact при полном plan — одна честная плашка, не прогресс-бар из назначений.

[Музыкант]: Итог на слух: честный исполнитель — не персонаж и не ветка, а **p, для которого лента спринта держит qualifies-take**. Отличие assigned/participated — два предиката, четыре комбинации, ноль магии Done. Кто только на афише — no-show; кто только в ленте — shadow_work, тоже правда.

[Teamlead]: Вердикт комнаты собираю. Машинно: объект SprintExecution = Assignments ⊕ Evidence → проекция assigned/participated + status enum. Предикат различия — formal Dynin. Не код продукта, не зоны задач. DoD — документ-канон + место home в процедуре спринта, когда владельцу нужно внедрение; сегодня — решение о смысле.

[Структурщик]: Принимаю. Леммы в канон: Assignment, Evidence, qualifies/K_exec, four predicates, status enum, запрет executor-скаляра и запрет импликации из task registry. API-имена потом; словарь — сейчас.

[Архитектор]: Принимаю. Форма: два слоя план/факт; home отдельно от registry задач; V1 без mute assignment; override только owner_asserted. ADR не обязателен, если канон процедуры спринта впишет абзац; при споре homes — короткий ADR.

[Математик]: Принимаю. Носитель истины — предикаты на Assignments и Evidence; «честный исполнитель» ≠ assigned; factual = participated; honest_pair для сверки плана.

[Верстальщик]: Принимаю. Витрина: две полосы + расхождение + enum статуса; без героя-скаляра и без фальшивого зелёного при planned_silent.

## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| Чем «честный исполнитель спринта» является **машинно** | Не persona, не git-branch, не `leadPersona` задачи. Это **проекция** `SprintExecution(S)`: из **плана** `Assignments(S)` и **ленты** `Evidence(S)` строятся множества `assigned(S)`, `participated(S)` и status-enum. «Исполнитель» в отчёте — элемент этих множеств, не скалярное поле `executor`. |
| Предикат **назначен** | `assigned(S,p) ⇔ ∃ запись в Assignments: sprintId=S ∧ p ∈ subjects` (финальный план окна с учётом supersede, не mute). |
| Предикат **участвовал** | `participated(S,p) ⇔ ∃ e ∈ Evidence(S): subject(e)=p ∧ qualifies(e)`, где `qualifies` = kind ∈ K_exec ∧ ref разрешим ∧ (время в окне S ∨ явная связь + правило late/grace). |
| Чем отличаются | Четыре комбинации: `honest_pair` / `only_assigned` (no-show) / `only_participated` (shadow_work) / ни то ни другое. **Фактический** исполнитель = `participated`. **Честное исполнение плана** = ∃ `honest_pair`. План без факта = `planned_silent`, не подстановка assigned в executors. |
| Что **не** является участием (явно) | Label/зона задачи, ветка персонажа, presence/CC, эмодзи, финальный self-insert в summary без qualifies-ref, автоматическое «день вёл X». |
| K_exec (v1, направление) | Закрытый enum следов: квитанция/артефакт закрытия с subject+sprintId; протокол/жест окна с subject; machine receipt шага процедуры спринта с actor. Уточнение состава K_exec — при внедрении home, не размывать presence. |
| Статус спринта по исполнителям | `unplanned` \| `planned_silent` \| `shadow_work` \| `aligned` \| `mixed` (определения Структурщика выше). |
| Связь с task registry | **Нет импликации.** Карточка задачи ≠ assignment/participation спринта. Optional ref «какие task id закрывали» — приложение, не определение. |
| Override | Только явный kind `owner_asserted` (V2); V1 — append-only evidence + supersede plan. |
| Вне скоупа этого вердикта | Код apps/packages, разметка задач по зонам, CI/LGTM на дифф, score «процент участия». |

**Definition of Done (если капитан велит внедрить канон):**

1. Абзац/секция в каноне процедуры спринта (или short ADR): леммы Assignment, Evidence, qualifies, четыре предиката, status enum, запрет скаляра `executor` и запрет вывода participation из task registry / зон.
2. Логические homes: где живут Assignments(S) и Evidence(S) (пути/реестр процедуры — по Архитектору+Структурщику).
3. Закрытый список K_exec v1 + правило late/grace (Математик).
4. Контракт витрины/отчёта: plan / fact / diff; `planned_silent` не маскируется «успехом» (Верстальщик).
5. Зуб или ручная приёмка: фикстура S с only_assigned и only_participated даёт ожидаемые множества (не «зелёный» от assigned).

**Решение одной строкой:**  
**Да** — машинно исполнитель спринта = субъект в проекции plan⊕evidence; предикат различия — `assigned` vs `participated` (qualifies-след), не назначение и не зона задачи.

## Список посылок
1. **норма** — Повестка владельца: ответ не про код приложения и не про разметку задач по зонам ответственности.

5. **норма** — Ангелина — ведущая контура исполнения, не советующий голос; `acceptedBy` — след приёмки артефакта после `isValid`, не членство «во всём дне».  
6. **норма** — Планка Teamlead: сдан матч (ценность/факт у владельца), а не тренировка (объявление, зелёный CI, красивое summary).  
7. **факт** — Прецедент cast/мостика в журналах команды: объявленный без вызываемого носителя = фальшивое присутствие, не участие.  
8. **норма** — Словарь команды: один ярлык на план и факт — запрещённый синоним-слой (разводить леммы до реализации).  
9. **норма** — Presence/«на связи» без адресуемого take не считается партией (линия evidence vs room tone из прошлых разборов контура).
