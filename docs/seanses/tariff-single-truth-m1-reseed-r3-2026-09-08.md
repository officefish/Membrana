## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| (а) Цепочка пересева и вызов | **Пересев** = релиз → сетка → база кабинета → записи приборов. Шаги: (1) после влития Б `yarn tariff:reseed` пишет сетку из релиза; (2) `yarn tariff:grid` подтверждает зуб 1; (3) кабинет обновляет строки `Tariff` из сетки (замена авторов seed/scalars); (4) **разноска** `membrane-context-fanout` доводит поля до `Device` на сервере записей. **Кто зовёт:** человек по слову или CI на мердж релиза — шаги 1–3 и инициированный проход разноски; **кабинет при старте** только читает сетку в память процесса (`tariff-grid-source`, один раз за процесс), не пересевает. |
| (б) Версия контракта | Носитель — **то же** поле `version` сетки (`tariff-grid.json`, сейчас `1`), не новое имя. Путь: релиз нумерует версию → сетка несёт `version` → база кабинета хранит/прокидывает версию контракта в событии перехода → разноска кладёт её в **новое поле записи прибора** на сервере записей. Прибор отличает «новая правда» от «старая» по этому полю. `updatedAt` у Device нет — не использовать. Имя поля в коде допустимо рядом с термином «версия контракта»; в стволе символа ещё нет (план). |
| (в) Ровно три зуба | **Зуб 1. Релиз ↔ сетка.** Файл-предмет: релиз matrix + `docs/tariffs/tariff-grid.json`; команда `yarn tariff:grid` (расширение «сетка = релиз» после Б). Предикат: слепок сетки равен релизу. Краснеет: CI/команда grid. Чинит: `tariff:reseed`, не ручная правка сетки. Красный вход: порча/ручная правка `tariff-grid.json`. **Зуб 2. Сетка ↔ база Tariff.** Файл-предмет: `tariff-grid.json` + cabinet `schema.prisma` Tariff. Предикат пар: `userStorageQuotaBytes ↔ storage.hot`, `bufferQuotaBytes ↔ storage.buffer`, `maxNodesPerMembrane ↔ nodes.max`, `maxUserWorkspaces ↔ workspaces.user.max`; `storage.cold` — колонки нет, в зуб не входит. Краснеет: тест/команда сверки кабинета. Чинит: пересев базы из сетки. Красный вход: ручной UPDATE Tariff / возврат scalars. **Зуб 3. База ↔ записи приборов.** Файл-предмет: cabinet Tariff (+ Membrane.bufferPolicy при политике) ↔ media `schema.prisma` Device; сверка полей, **не** счётчик fanout. Пары: `Tariff.userStorageQuotaBytes ↔ Device.userStorageQuotaBytes`, `Tariff.bufferQuotaBytes ↔ Device.bufferQuotaBytes`, `Tariff.maxUserWorkspaces ↔ Device.maxUserWorkspaces`, каталог наборов ↔ `Device.datasetCatalogId`, версия контракта ↔ новое поле Device. **`maxNodesPerMembrane` у Device нет** — в зуб 3 не входит, остаётся только в базе кабинета. **Политика переполнения** входит в зуб 3 как `Membrane.bufferPolicy` (кабинет) ↔ поле политики на Device (сервер записей), не как поле Tariff. Краснеет: тест сверки D↔B. Чинит: разноска/пересев, не ручной PATCH в обход. Красный вход: порча строки Device или ручная правка квот на сервере записей. Запрет ручной правки производных = красный зуб при drift. |
| (г) Переезд без остановки прода | Сетка → слепок релиза после Б. База: **вывести из строя** `seed.mjs`+`tariff-scalars.json` как авторов квот (повторный сид больше не переписывает free на 512 из scalars); строки free/checkpoint/observatory получают числа из релиза; **удалить** мёртвый `ensureFreeTariff()`. ### Вызов цепочки (не DoD)

1. Влить Б (#2331) — появляется релиз и `yarn tariff:reseed` (план).
2. CI или человек на мердж релиза: `yarn tariff:reseed` → `yarn tariff:grid` → обновление базы кабинета из сетки → разноска на записи приборов (вкл. версию контракта).
3. Выкатка кабинета: процесс при старте читает новую сетку в память.
4. Runbook человека/CI живёт здесь и в docs задачи — **не** в Definition of Done.

## Definition of Done

1. **Зуб 1:** команда `yarn tariff:grid` — красный, если `docs/tariffs/tariff-grid.json` ≠ слепок релиза (после влития Б: релиз в `docs/containers/strategic-docs/releases/tariff-matrix/`).
2. **Зуб 2:** тест/команда сверки кабинета (файл теста в `packages/background-cabinet`, имя с `tariff`+grid/base) — красный, если нарушена любая пара `Tariff.userStorageQuotaBytes↔storage.hot`, `bufferQuotaBytes↔storage.buffer`, `maxNodesPerMembrane↔nodes.max`, `maxUserWorkspaces↔workspaces.user.max`.
3. **Зуб 3:** тест сверки полей (кабинетный либо script-уровень, читает Tariff/Membrane и Device) — красный при drift пар `userStorageQuotaBytes`, `bufferQuotaBytes`, `maxUserWorkspaces`, `datasetCatalogId`, версии контракта, `Membrane.bufferPolicy↔` политика на Device; **не** красный от одного счётчика fanout «не удалось».
4. **Запрет ручной правки:** тот же вход зуба 1 — красный при ручной порче `tariff-grid.json` без reseed.
5. **Версия:** тест пути разноски — красный, если поле версии контракта на Device ≠ `version` сетки после пересева.
6. **Посев:** `packages/background-cabinet/prisma/seed.mjs` не читает `docs/tariffs/tariff-scalars.json` как источник квот — предикат: grep/тест на отсутствие импорта/чтения scalars в seed; красный, если seed снова пишет квоты из scalars.
7. **ensureFreeTariff:** символ `ensureFreeTariff` отсутствует в `packages/background-cabinet` — `rg ensureFreeTariff packages/background-cabinet` пуст; красный при наличии.
8. **Снятие второго переключателя:** `rg TARIFF_GRID_MODE packages/` пуст после переезда; `scripts/lib/tariff-cutover.mjs` не импортирует `tariff-scalars` — красный при импорте scalars или при чтении `TARIFF_GRID_MODE` в runtime кабинета.
9. **Момент сетки в процессе:** тест/предикат кабинета — сетка загружается из файла источника при старте процесса (`domain/tariff-grid-source.ts`); красный, если повторное чтение файла в рантайме без рестарта ожидается как единственный путь обновления (контракт: один load за процесс).
