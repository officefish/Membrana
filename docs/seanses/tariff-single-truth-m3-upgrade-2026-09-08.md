# Консилиум: M3 (U) Повышение тарифа — единая правда без второй починки

**Повестка:** Q3 — порядок событий при повышении, носитель «прибор принял», судьба удержания, окно синхронизации (T11), отказ разноски и гонки версий; границы M1/M2/M4/M5.

**Участники:** Teamlead (Tarasov), Архитектор (Vesnin), Структурщик (Ozhegov), Математик (Dynin), Музыкант (Kuryokhin), Верстальщик (Rodchenko).

[Структурщик]: Словарь на стол. **Право** — строка в базе кабинета (`Tariff` + `TariffChangeLog`). **Лимит** — числа на **записи прибора** на сервере записей. **Разноска** — звено база → сервер записей. **Версия контракта** — поле с M1, не счётчик доставки. **Удержание** — `DeviceOverflowHold` на приборе. **Окно синхронизации** — промежуток «право записано, лимиты/прибор ещё не сошлись». Второго носителя правды не плодим.

[Верстальщик]: С витрины сегодня ложь: мембрана рисует новый тариф сразу после `POST`, а прибор ещё на старых числах и, часто, в удержании. T7 прямо: успех не раньше прибора. Значит UI обязан различать «право записано» и «прибор принял» — два честных блока, не один зелёный тост по счётчику разноски.

[Teamlead]: Планка M3: повышение без ручной починки и без второй правды. Четыре зуба — (а) порядок и носитель «принял», (б) удержание, (в) окно T11, (г) отказ/гонки. Посылки M1/M2 не переоткрываем. Кто тянет «release от тарифа» без данности эпика — получит BLOCK. Начинаем с носителей, не с кнопок.

[Архитектор]: Конструкция сверху вниз. Событие 1: право в кабинете (транзакция + `TariffChangeLog`). Событие 2: разноска лимитов **с версией** на запись прибора (M1). Событие 3: факт «прибор принял» — отдельно от счётчика доставки. T7 закрыт штормом: прибор получает переход **событием с версией**, не сам перечитывает квоту как источник перехода. `/quota` остаётся каналом объёма (M2), не носителем факта смены.

[Математик]: Формализую. Пусть `V` — монотонная версия контракта. Инвариант записи прибора: `apply(v_in)` только если `v_in > v_device`, иначе no-op. Тогда две разноски в обратном порядке не откатывают тариф: поздний устаревший пакет отбрасывается. Зуб M1 «равенство Tariff ↔ Device» — предикат `v_right = v_device_record` после успешного применения, не `updated − failed`.

[Музыкант]: С края тракта: после стопа прибор уже дышит heartbeat и `/quota` ≥ 1/мин — это жизнь, не партитура перехода. Путать опрос квоты с событием смены тарифа — как принять шум барабана за сигнал дирижёра. Событие с версией — отдельная нота; квота — уровень громкости после неё.

[Структурщик]: Носитель «прибор принял» на приборе: обработка события перехода, сравнение `version` с последней известной, запись `lastContractVersion` локально. Путь в кабинет: не счётчик `syncAllNodes`, а **сообщённая прибором версия** в состоянии узла (канал жизни уже жив после стопа) либо паритет полей на сервере записей после того, как прибор подтвердил применение — один контур, без второго кэша «успехов».

[Верстальщик]: Окно оператора по M2 — **снимок эпизода**, без второго запроса квоты. После повышения снимок остаётся со **старыми** числами отказа; плашка удержания не «зеленеет» от витрины тарифа. Кнопка «сменить тариф» — ушла в кабинет; возврат не авто-закрывает модалку. Честная строка статуса узла: «жив · не пишет · удержание» + отдельно «право новое · ждём прибор» если ещё окно синхронизации.

[Teamlead]: Удержание. Данность эпика: `release` только `'human' | 'cleanup'`, авто по месту — нет. Смена тарифа — действие в кабинете, но **не** третий reason и не тихий `release`. Держим до «Возобновить». Иначе получим авто-возобновление через чёрный ход «человек сходил на мембрану». Это не жалость — это та же планка, что запретила auto по свободному месту.

[Архитектор]: Согласен с удержанием. Цена альтернативы `release('tariff')`: смешиваем контур оплаты/права с контуром стопа записи; окно-снимок лжёт; M4/полный буфер придётся переписывать. Форма: повышение расширяет лимит на записи прибора, но **решение снова писать** — только явная кнопка на приборе. Кабинет не шлёт «снять удержание».

[Математик]: Окно синхронизации T11. Обозначим `t0` = commit права, `t1` = запись лимитов+версии на сервере записей (конец разноски по прибору), `t2` = прибор применил событие. На `[t0, t1)`: `/quota` ещё старый (запись не обновлена). На `[t1, t2)`: `/quota` уже новый, прибор локально ещё считает старый лимит до события. Витрина права — новое с `t0`, но флаг «сошлось» — только с `t2`. Закрывает окно **прибор** фактом применения версии; длительность не потолок UX-таймера, а «пока не t2 или пока разноска не дотянута».

[Музыкант]: На `[t1,t2)` полевой контур опасен только если прибор сам начинает писать по новой квоте, угадав её из `/quota`. T7 как раз запрещает считать опрос источником перехода. Пока события нет — прибор не меняет локальный контракт лимита. Удержание при этом всё равно стоит: даже новый лимит не поёт, пока человек не нажмёт «Возобновить».

[Структурщик]: Отказ разноски. Факт ствола: право уже в `TariffChangeLog`, `failed > 0`, повтора нет — дыра. Словарь: не «компенсация отката права» (второй правды и ложного «как будто не выбирал»). Норма M3: **право ждёт** — право остаётся; разноска **повторяется** до паритета полей версии/лимитов на записи прибора (зуб M1). Откат права при `failed` — запрещён здесь: это другая правда о выборе владельца.

[Верстальщик]: Витрина мембраны после POST: показать **право** (имя/ранг нового тарифа) сразу — это факт базы, M2 «витрина = право». Рядом не «успех на N узлов», а статус синхронизации: «лимиты на сервере записей: ждем / сошлись» по паритету версий, и «прибор принял: да/нет» по факту с прибора. Счётчик разноски в ответе — телеметрия доставки для отладки, не зелёная галочка оператору.

[Teamlead]: Гонки. Транзакция `tariff_moved_concurrently` уже режет два commit права. Две разноски подряд — риск обратного порядка на сети. Защита одна: версия на записи прибора и правило «только вперёд» (Математик). Не строим очередь с ручным reconcile-словом — строим монотонный apply. Принял: повтор разноски + monotonic version. Откат права — вне M3.

[Архитектор]: Носители по слоям. Кабинет: право, `TariffChangeLog`, постановка разноски, чтение паритета и «прибор принял», витрина права. Сервер записей: запись прибора (лимиты + версия контракта), `/quota` как чтение записи, приём PATCH разноски с отказом устаревшей версии. Прибор: приём события с версией, локальный lastVersion, удержание без release от тарифа, репорт принятой версии, окно/плашка-снимок. Не строить: второй кэш тарифа в UI, release('tariff'), success по fanout-счётчику, откат права.

[Математик]: Предикат паритета: `deviceRecord.contractVersion == membraneTariff.version` и равенство полей лимитов (зуб 3 M1). Предикат «прибор принял»: `reportedAppliedVersion == membraneTariff.version`. Красный вход: после POST и успешного PATCH запись имеет version N, а reported N−1 — окно открыто. Красный вход гонки: PATCH с version N−1 после N — запись остаётся N.

[Музыкант]: Событие перехода на прибор — короткий контракт: `{ contractVersion, limits-ref или лимиты }`. Не тащить в него наборы (M5) и не холод (M4). Если событие потеряно — право всё же на сервере; повторная разноска и/или повтор события по версии, не «прибор сам догадался из /quota». Опрос квоты после apply только сверяет объём, не открывает тариф.

[Структурщик]: Уточняю границу с M1: версию как носитель и пересев не проектируем заново — берём поле `version` сетки/Tariff/записи прибора как **посылку**. M3 лишь включает версию в полезную нагрузку разноски и в событие прибору и задаёт monotonic apply. Слабая связанность: кабинет не читает локальный hold прибора; hold не читает TariffChangeLog.

[Верстальщик]: После повышения, пока удержание: модалка/плашка — старый снимок (used/limit отказа), reason тот же, primary «Возобновить» на приборе, не «уже можно, тариф вырос». Допустима нейтральная строка «право мембраны обновлено» без новых цифр квоты в снимке — цифры снимка не переписываем из витрины. Иначе второй запрос квоты в окно — нарушение M2.

[Teamlead]: Сводка (б): удержание держится до «Возобновить»; смена тарифа ≠ release. Окно и плашка — снимок старых чисел. (а): право → разноска с версией → событие прибору → репорт/паритет в кабинет. (г): право ждёт + повтор разноски; monotonic version. Дальше — DoD-предикаты, без регламента в DoD.

[Архитектор]: T11 в одном абзаце. Прибор в окне считает лимитом **последний принятый контракт** (до t2 — старый). Витрина показывает **право** с t0 и **статус окна**, не «лимиты уже везде». `/quota` отвечает **записью прибора** на сервере записей (после t1 — новые лимиты). Окно длится от t0 до t2 по каждому прибору; закрывает прибор применением версии; при failed разноски t1 не наступает — тянем повтор, право не откатываем.

[Математик]: Не вводим ε-таймаут как определение закрытия окна: время — наблюдаемая величина, не носитель истины. Носитель закрытия — равенство версий (принятая = право). Если прибор мёртв, окно формально открыто; кабинет честно показывает «не принял», без фальшивого success — это согласуется с T7.

[Музыкант]: Полевой риск «две правды на слух»: оператор в кабинете видит новый тариф, на приборе — старый стоп. Мой голос: лучше горькая плашка «ждём прибор», чем сладкий success. Запись не стартует сама ни от тарифа, ни от роста freely-места — только human resume. Принимаю.

[Структурщик]: Что строить: (1) version в PATCH разноски и monotonic на сервере записей; (2) событие перехода с version на прибор; (3) reportedAppliedVersion в состоянии узла; (4) повтор разноски при failed без отката права; (5) UI: право ≠ принято. Что не строить: release от тарифа; success по счётчику; компенсационный rollback права; второй кэш лимитов в кабинете; умную очистку и наборы (чужие комнаты).

[Верстальщик]: DoD-видимое: карточка узла после повышения — три честных слоя: право мембраны / паритет записи / принял прибор. Пока паритет или accepted ложны — нет badge success на тарифе. a11y: статус текстом, не одним цветом. Принимаю форму.

[Архитектор]: Принимаю. Одна правда: матрица/право в кабинете; лимиты — производная на записи прибора; прибор — потребитель события версии. Второго носителя нет.

[Математик]: Принимаю. Инварианты V↑ only, паритет полей, accepted := reported==right.

## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| **(а) Порядок событий** | 1) **Право** в базе кабинета: транзакция `selectTariff` / `applySelfAtomically` + строка `TariffChangeLog`. 2) **Разноска** лимитов **с версией контракта** на **запись прибора** (сервер записей, `syncMembraneContext` + поле version с M1). 3) **Факт «прибор принял»**: прибор применяет **событие перехода с версией** (T7), сравнивая с последней известной; не считает источником перехода опрос `/quota`. |
| **(а) Носитель «прибор принял»** | **Событие с версией контракта** на приборе (T7). `/quota` — канал объёма (M2) и жизни после стопа; может нести version для сверки, но **не** заменяет событие перехода. |
| **(а) Как кабинет узнаёт** | Не счётчиком разноски (`updated`/`failed`). По **паритету** `Tariff.version`/лимиты ↔ запись прибора (зуб M1) **и** по **reportedAppliedVersion** из состояния узла (канал жизни). Счётчик разноски — только доставка PATCH. |
| **(б) Удержание** | Смена тарифа **не** `release` и **не** новая reason. Удержание держится до **«Возобновить»** (`release('human')`) или `release('cleanup')`. Данность «нет авто по месту» не обходим. |
| **(б) Окно и плашка** | Остаются **снимком эпизода** (M2): **старые** числа отказа. Не подмешивать новые лимиты из витрины/квоты. Допустима нейтральная пометка «право обновлено», без пересчёта снимка. |
| **(в) Окно синхронизации T11** | **Прибор считает лимитом** последний **принятый** контракт (до apply — старый). **Витрина** — **право** с момента commit + статус окна (не «успех везде»). **`/quota`** — лимиты **записи прибора** (после успешной разноски — новые). Длительность: до apply версии на приборе (и до паритета записи, если разноска failed). **Закрывает прибор** фактом применения; кабинет только отображает. |
