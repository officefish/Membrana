# Консилиум: Вторая дверь — шов выбора спринта

**Повестка:** Где проходит выбор между спринтом с честными исполнителями и форматом без персон; кто и когда выбирает; как задача честно несёт «персональной ответственности нет» и что мешает этому стать лазейкой. Формат membrana-flow **не** проектируется — только шов выбора. Вход: M1–M6, M8. Вопрос 9 (судьба 214 карточек) **не** решать.

[Математик]: Формализую шов, не flow. Пусть режим спринта \(m \in \{\mathtt{honest}, \mathtt{no\_persona}\}\). Выбор — акт \(choose(S, m, actor, proof)\), где \(S\) — id окна/спринта, \(proof\) — машинно читаемый носитель. Инвариант лазейки: \(\mathtt{no\_persona} \Rightarrow \neg\exists p: responsible(S,p)\) **и** гейт не требует non-empty persona. Обратное: без легального \(m=\mathtt{no\_persona}\) формальный ответственный возвращается (вещдок: 214/214). Предикат двери ≠ кнопка skip: \(open(m) \Leftrightarrow predicate(m) = true\) с явной причиной при отказе.

[Структурщик]: Леммы, иначе синонимы. **Шов выбора (choice seam)** — точка фиксации режима *до* старта исполнения, не UI-тогл mid-flight. **Режим honest** — действует контракт M1–M6 (assigned ≠ participated, следы, аудитор). **Режим no_persona** — режим *без* персональной ответственности; не «honest с пустым leadPersona». **Носитель выбора** — запись на S: `{mode, chosenBy, chosenAt, reasonCode}`. Не смешивать с leadPersona карточки задачи и не проектировать membrana-flow как пакет.

[Teamlead]: Планка матча узкая: только шов, не flow и не вопрос 9. Положение: без двери — чёрный ход (214/214); дверь без предиката — skip честности. Решение по нагрузке: выбирает **тот, кто открывает окно спринта** (капитан или делегат с мандатом), **до** assign. Связка на вердикт: Математик — предикаты open/deny; Структурщик — лемма носителя; Архитектор — граница «что не flow». Приём «легальное нет с причиной» — уже трижды за два дня: берём как зуб шва, не как вежливость.

[Верстальщик]: С витрины капитана и агента режим обязан читаться без легенды: бейдж `honest` | `no_persona`, не прочерк и не тот же «Исполнитель: Ozhegov». При `no_persona` — явная строка «персональной ответственности нет» + reasonCode, не пустой слот. Фальшь: карточка рисует ответственного при mode=no_persona, или наоборот — «без персон» при заполненном leadPersona. Layout flow не рисую; требую в контракте шва два честных состояния и запрет третьего «как получится».

[Архитектор]: Конструкция: шов — **enum режима на границе спринта**, не ветка внутри honest-контура и не новый пакет flow. Два режима — две формы ответственности; смешение в одном S без смены mode — запрещено. Цена «всегда honest»: формальный responsible чёрным ходом (факт реестра). Цена «дверь без предиката»: skip. Рекомендация: mode фиксируется до M1-assign; смена mid-sprint = новый S или явный re-choose с аудитом. membrana-flow — за скобкой формы.

[Музыкант]: На слух это count-in до take, не смена пресета в середине партии. Honest — на шине именные дорожки и следы M1; no_persona — bus без солиста, но **не mute метки режима**. Клиппинг доверия: объявили «без персон», а в миксе 214 ответственных — фальшь. Легальное «нет» с причиной — как red light на пульте: три раза за два дня уже слышали, значит зуб живой. Flow-аранжировку не пишем — только где стоит переключатель до записи.

[Математик]: Предикат допуска no_persona: `canNoPersona(S) ⇔ preconditions_np(S)=∅ ∧ actor∈Choosers ∧ ¬started(S)`. Минимальный набор preconditions (не flow): (1) reasonCode ∈ закрытого словаря; (2) нет активного assign honest на S; (3) носитель mode пуст или явно перевыбирается с proof. Отказ: `deny(reason)` — тотально, без silent pass. Инвариант анти-лазейки: `mode=no_persona ⇒ gate_persona_nonempty ≔ off` **на этом S**; иначе mode противоречив и `invalid`.

[Структурщик]: Словарь reasonCode (закрытый, без «прочее» как дыры): как минимум `batch_migration`, `tooling_only`, `owner_explicit_waiver`, `no_human_persona_slot`. Каждый code — словарная статья: когда применим / когда нет. Носитель home — артефакт плана спринта (не поле карточки задачи #9). Запрет: выводить mode из пустоты leadPersona; пустота ≠ no_persona (M1: участие не из реестра).

[Teamlead]: Кто выбирает — фиксирую жёстко: **владелец окна** (капитан) или **Ангелина как модератор только с явным мандатом капитана на этот S**. Исполнитель, аудитор, тимлид-как-игрок — **не** выбирают mode в свою пользу. Когда: **T0 = до** контракта M2 и до assign M1. После started(S) — только STOP + новый шов, не «передумали». Это нагрузка: проще сразу честно, чем латать mid-flight.

[Верстальщик]: Отказ двери на витрине — как легальное «нет»: не серый disabled без текста, а `denied: <reasonCode>` одной строкой. Успех no_persona — не праздник «облегчения», а спокойный бейдж + reason; иначе кнопка skip снова станет желанной. Для honest — два индикатора M1 (назначен/участвовал) остаются; для no_persona их **нет**, вместо них одна честная пустота с подписью режима.

[Архитектор]: Граница с M8 (память): шов пишет в план `mode`+`reasonCode`; журнал персоны от *исполнения* при no_persona **не** требует performer-записи — но факт выбора mode пишется в **системный** след S (не в character/*). Иначе «без ответственности» сотрёт и след выбора. Вопрос 9 не трогаем: гейт non-empty на карточках — отдельный контур; шов лишь требует, чтобы mode и гейт не лгали друг другу на одном S.

[Музыкант]: Связка с аудитом Фаррелла на M0: память раньше двери — уже сыграно; сегодня дверь не должна снова стать тихим bypass. На слух анти-лазейка = **обязательный reason + нельзя включить no_persona после первого take**. Если take уже пошёл under honest — смена режима = фальшивый punch-in. Второе: no_persona не отменяет серверные зубы процесса (гейты CI, ship) — отменяет только персональную связку M1–M5.

[Математик]: Разделяю предикаты. `persona_gate(S)` — non-empty responsible (нынешний факт 214/214). `honesty_gate(S)` — assigned/participated/следы (M1+). При `mode=honest`: оба релевантны по контракту спринта. При `mode=no_persona`: `persona_gate` снят **явно**, `honesty_gate` не маскируется под pass — он **out of scope**, статус `na(mode)`, не green. Иначе skip честности = false green. Формула: `report(S).honesty ∈ {pass, fail, na}`; `na` только если mode=no_persona.

[Структурщик]: Лемма **na ≠ pass**. Статус `na(mode)` — отдельное значение в отчёте шва/аудита, не alias true. Home отчёта режима — рядом с планом S (файл/запись плана), не в leadPersona. Зависимость: M1 определяет, *что* стало na; шов определяет, *когда* na законен. Цикл: mode → область M1; нельзя M1 «угадывать» mode из пустых полей.

[Teamlead]: Возражение «всегда оставлять honest» — проигрыш матча на 214 чёрных ходах. Возражение «свободный togl» — проигрыш на skip. Держим середину: дверь узкая, reason обязателен, актор ограничен, момент T0. Легальное нет — третий исход choose: `applied | denied | invalid_state`. invalid_state = попытка mid-sprint или mode↔assign конфликт. Связка приёмки шва: Математик (предикаты) + Структурщик (носитель) + Архитектор (граница flow).

[Верстальщик]: Три исхода choose на витрине оператора: applied (бейдж режима), denied (reason), invalid_state (предупреждение «сначала STOP»). Не рисую flow UI. Капитан должен за 1 взгляд видеть: *какой режим у текущего S* и *почему no_persona, если он*. Скрытый default honest без записи mode — тоже фальшь: mode обязан быть **явным** always, default не «молча honest в голове агента».

[Архитектор]: Default: при отсутствии записи mode на S → **не** подразумевать no_persona; для нового контура честных спринт-окон default = `honest` **с явной записью** при open(S). Исторические 214 — вне шва (вопрос 9). Форма open(S): всегда пишет mode. Так чёрный ход «забыли mode, но leadPersona заполнен» становится invalid, а не тихим honest.

[Музыкант]: Default honest с явной записью — правильный count-in: тишина на ленте не равна «без солиста». Ещё анти-лазейка на слух: запрет пачки «все задачи дня = no_persona» одним reason без перечня S — иначе reason превращается в абонемент skip. Один choose — один S (или явный batch-id с тем же reasonCode и списком S[], auditable).

[Математик]: Уточняю batch: `choose(batch, m, actor, proof)` допустим iff \(\forall S\in batch: \neg started(S)\) и proof.reasonCode один, и |batch| ограничен политикой (число или явный owner_waiver). Предикат лазейки: \(\exists S: mode(S)=no\_persona \land honesty\_report(S)=pass\) → invalid (na обязателен). Счётчик: доля no_persona за окно времени — метрика, не блок; блок только по предикатам шва.

[Структурщик]: Имена полей носителя (словарно): `sprintMode: 'honest' | 'no_persona'`; `modeChosenBy: actorId`; `modeChosenAt: ts`; `modeReasonCode: enum`; `modeProofRef?: id`. Не `leadPersona=null` как сигнал. Связь с M6 (модерация): ведущая может *запросить* choose у капитана, не подписать mode сама без мандата. Изоляция M5: аудитор не author mode.

[Teamlead]: Мандат: если Ангелина выбирает mode — в proof лежит `mandateRef` капитана на интервал/батч. Без mandateRef её choose → denied. Исполнитель, «удобно без ответственности» — denied всегда. Это не бюрократия, это край: иначе дверь = лазейка для того, кому честность дороже всего давит.

[Верстальщик]: На карточке/плане спринта (не task registry #9): блок режима выше списка assign. Честная пустота assign при no_persona; при honest — M1-индикаторы. Запретный декор: иконка «user» при no_persona. a11y: текст режима не только цветом.

[Архитектор]: Цена альтернатив короче: (A) нет двери → 214 чёрный ход; (B) дверь-кнопка → skip; (C) шов с предикатом, T0, reason, na≠pass, явный default honest — берём C. Вне скоупа: протокол membrana-flow, миграция 214, UI кабинета продукта. ADR не обязателен, если вердикт ляжет в meeting-док шва; при споре с панельными процедурами — короткая отсылка в procedures, не новый пакет.
