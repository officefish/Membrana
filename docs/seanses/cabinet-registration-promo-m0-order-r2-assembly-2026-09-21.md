## Решение комнаты (без изменений; протокол, строки 160–186)

| Вопрос | Решение |
|---|---|
| Порядок кандидатов | Граф: кандидат 1 → кандидат 2 → кандидат 3 → кандидат 4. |
| Ребро 1 → 2 | Форма запроса кабинета к офису (вид гранта и форма двери офиса) определяет, что именно кабинет запрашивает и как предъявляет ключ. |
| Ребро 2 → 3 | Клиент офиса и пара «адрес + ключ» — инструмент, которым служба регистрации кабинета оборачивает гашение кода в транзакцию. |
| Ребро 3 → 4 | Тело двери регистрации сервера и правило «одна фраза ошибки без причины» определяют форму и тексты браузерной формы. |
| Не-ребро 1 → 3 | Прямое чтение вида гранта в комнате 3 избыточно: грант доходит через подпись клиента офиса (комната 2). |
| Не-ребро 1 → 4 | Форма регистрации не читает вид гранта напрямую; словари 1 (грант/лимит) и 4 (логин/пароль/код) разные. |
| Не-ребро 2 → 4 | Ключ офиса в браузер не попадает (каталога `apps/cabinet/src/services/` в стволе нет). |
| Не-рёбра 4 → 1, 4 → 2, 4 → 3 | Интерфейс не диктует серверу контракт офиса. Единственное ребро, где интерфейс получает от сервера — 3 → 4. |
| Сессии и границы файлов | **Сессия A (кандидат 1):** `packages/background-office/src/modules/panel-users/panel-users-core.ts`, `panel-users.controller.ts`, `scripts/_ssh-panel-smoke.mjs`. **Сессия B (кандидат 2):** новый модуль клиента офиса внутри `packages/background-cabinet/src/modules/` + собственный файл-схема пары «адрес + ключ офиса» (например `packages/background-cabinet/src/config/office-client.env.ts`), `deploy/generate-cabinet-env.sh`. **Сессия C (кандидат 3):** `packages/background-cabinet/src/modules/auth/auth.controller.ts:21`, `packages/background-cabinet/src/modules/auth/auth.service.ts:15`, `packages/background-cabinet/src/config/env.schema.ts:37,47`, тесты `auth`. **Сессия D (кандидат 4, четвёртая в очередь):** `apps/cabinet/src/pages/LoginPage.tsx:79`, `apps/cabinet/src/api/auth.ts`, `deploy/root-site/index.html:154`. |
| Разведённый общий файл | `packages/background-cabinet/src/config/env.schema.ts` — принадлежит сессии C (там уже есть флаг `ALLOW_REGISTRATION`). Сессия B не трогает этот файл и заводит свой отдельный. |
| Дверь `auth.controller.ts:21` | Отнесена к сессии C. |
| Параллельность | Три сессии A, B, C — параллельно: их файловые наборы дизъюнктны, связи 1→2 и 2→3 — «снято очерёдностью», не общий файл. Сессия D — четвёртая, стартует по контракту после C; её файлы тоже дизъюнктны с A/B/C. |
| Идёт сразу в задание | Правило «каждый путь файла — ровно одной сессии»; закрепление `auth.controller.ts:21` за C; закрепление `env.schema.ts` за C и запрет для B трогать этот файл; граф рёбер и не-рёбер; план A/B/C параллельно, D после C. |
| Решается в комнатах | Комната 1 — вид гранта и форма двери офиса. Комната 2 — кто выдаёт и хранит адрес и ключ офиса, отличие от ключа пусковика ночной охоты, место клиента офиса. Комната 3 — порядок гашения кода и создания пользователя, ответ при недоступном офисе, тесты гонки. Комната 4 — форма, фраза ошибки, частота, правда на лендинге. |

**Определение готовности (Q0):** в задание вынесены план сессий A/B/C (параллель) и D (после C); граф рёбер 1→2, 2→3, 3→4 и не-рёбер 1→3, 1→4, 2→4, 4→1, 4→2, 4→3; правило единственной сессии на путь файла; закрепление `auth.controller.ts:21` за C; разведение `env.schema.ts` на C и отдельный файл пары «адрес + ключ офиса» под B; перечень четырёх комнат с формулировкой предмета без содержания; приёмка второго кабинета владельца на `free-v1` (`membrane.service.ts:157`) — сквозная проверка, не сессия.

**Отступление от Q0, названное в комнате открыто:** вопрос просил три сессии, комната дала три параллельных и четвёртую после C — [Teamlead], стр. 74: «Четвёртый кандидат идёт после третьего — это уже четвёртая сессия, если считать отдельно»; стр. 86: «D — четвёртая по времени (после C), но её файлы не пересекаются с D — значит её можно завести отдельной сессией, не блокируя A/B/C»; [Архитектор], стр. 92: «D ставится четвёртой сессией в очередь и стартует после C по контракту, при этом её файловый набор ни с кем не пересекается». Решение о числе сессий — за владельцем при ратификации.
