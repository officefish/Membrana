# WORKTREE_TEMPLATE — шаблон карточки рабочего дерева

> Карточка `WORKTREE.md` лежит в **корне дерева** и в ствол не едет: `.gitignore`
> держит `/WORKTREE.md` и `/.worktree-owner` как per-tree файлы (#717). В ствол едет
> только этот шаблон. Словарь классов — [`WORKTREE_CLASSES.md`](../WORKTREE_CLASSES.md);
> носитель кода — [`scripts/lib/classify-worktree.mjs`](../../scripts/lib/classify-worktree.mjs)
> (`parseWorktreeCard` → `classifyWorktree`). Поля ниже взяты **из кода**, не из головы;
> тест [`scripts/worktree-template.test.mjs`](../../scripts/worktree-template.test.mjs)
> прогоняет этот файл через тот же парсер.

## Как пользоваться

1. Скопировать блок ниже в `<корень дерева>/WORKTREE.md`.
2. Заполнить поля. Поле `kind` — ровно одно слово: `canon` или `sprint`. Для `sprint`
   строку `canonName` удалить: парсер берёт любое непустое значение как имя канона.
3. Проверить: `yarn repo:clean` (сухой прогон) должен показать дерево классом
   `canon` или `sprint-*`, а не `unregistered`.

```markdown
# WORKTREE — карточка дерева

| Поле | Значение |
|---|---|
| kind | выбрать одно: canon или sprint |
| canonName | только для canon (main · tooling · product · codex · cursor); для sprint строку удалить |
| Дерево | имя каталога дерева |
| Назначение | зачем дерево: спринт/PR/блок коворка/сессия |
| Ветка | ветка дерева |
| Базовая ветка | main (спринт всегда уходит в собственную ветку) |
| Владелец | чья сессия / агент — кого спрашивать перед сносом |
| Статус | PR #N MERGED/OPEN/CLOSED · нет PR · хвосты (грязь, незапушенное) |
| Последняя работа | дата последнего коммита или живой работы, ДД.ММ.ГГГГ |
| gc | запрещён (`gc.auto 0`); gc только в main-checkout |
| install | свой `yarn install` в этом дереве, node_modules не шарится |

> Спринт-дерево живёт, пока живёт PR его ветки. Снос — только
> `yarn repo:clean --execute --worktrees --report <файл>` по классу `sprint-closed`
> (ADR-0020, контролируемый снос). Raw `git worktree remove` запрещён.
```

## Что читает инструмент, а что — человек

`parseWorktreeCard` разбирает строки вида `| Поле | Значение |` (терпит и plain-строки
`kind: sprint`). Имя поля сравнивается без учёта регистра.

| Поле | Кто читает | Что с ним делает код |
|---|---|---|
| `kind` | машина | единственный различитель. Значения: `canon`, `sprint`. **Любое другое** (`long-lived`, `canon \| sprint`, пусто) → карточка считается отсутствующей → класс `unregistered`. Поэтому незаполненная копия шаблона дерево не регистрирует — это намеренно. |
| `canonName` | машина | только пояснение в причинах вердикта (`карточка kind=canon (tooling)`); код его **не проверяет** по закрытому множеству `CANON_NAMES`. Проверка на человеке. |
| `Базовая ветка` / `base` | машина | берётся первое слово (поэтому `main (спринт …)` — валидно); используется синхроном базы (`worktree:sync`), на lifecycle не влияет |
| `Владелец` / `owner` | машина + человек | попадает в карточку как есть; на класс не влияет, нужен человеку — кого спрашивать |
| `Дерево`, `Назначение`, `Ветка`, `Статус`, `Последняя работа`, `gc`, `install` | человек | код игнорирует; это ответ на «чьё это и живо ли», который иначе восстанавливают из содержимого дерева |

Что делает `classifyWorktree` дальше (по коду):

- `kind=canon` → класс `canon`, сносу не подлежит **никогда**, состояние PR не смотрится.
- `kind=sprint` → смотрится PR ветки: detached HEAD или недоступный `gh` → `unknown`
  (не сносить); PR MERGED/CLOSED ∧ нет грязи ∧ нет незапушенного → `sprint-closed`
  (единственный класс, который `repo:clean --execute --worktrees` сносит); иначе `sprint-open`.
- нет карточки / `kind` не распознан → `unregistered`.

## Почему дерево без карточки не сносится

`unregistered` — это **отказ инструмента, а не сбой**: у дерева нет различителя
`canon`/`sprint`, и инструмент не знает, можно ли его судить по состоянию PR.
Он печатает «разбор человеку» и идёт дальше. Цена такого отказа — ручной разбор
каждого дерева (17.09: 43 отказа из 65 деревьев). Карточка убирает разбор, но
ставить её можно только по фактам: ветка дерева, её PR, дата последнего коммита,
`.worktree-owner`, реестр коворка, карточка сессии. Где хозяин не определяется,
карточку не выдумывать — оставить дерево владельцу.

**`canon` — необратимая сторона.** Ошибочный `kind=canon` навсегда выведет мёртвое
дерево из-под уборки: класс `canon` не смотрит ни PR, ни хвосты. Канон закрыт и
перечислим: `main`, `tooling`, `product`, `codex`, `cursor` (`CANON_NAMES`). Всё
остальное — `sprint`; ошибка в `sprint` обратима (дерево с живой работой инструмент
всё равно не тронет: грязь и незапушенное держат его в `sprint-open`).

**Дырка словаря.** Долгоживущее оснащённое дерево сессии, которое не входит в канон
(например, `Membrana-installstate`: `kind: long-lived`), в словаре не представлено:
`sprint` подставит его под снос после мерджа PR, `canon` нарушит закрытость множества.
Сегодня такое дерево честно остаётся `unregistered` — это решение владельца, не карточки.

## Смежное

- `.worktree-owner` — advisory-замок «имя сессии · дата»; классификация его не читает,
  но это первый источник хозяина при выдаче карточки.
- Реестр выдачи карточек: [`docs/evidence/worktree-cards-2026-09-17.md`](../evidence/worktree-cards-2026-09-17.md).
- Норма сноса: [ADR-0020](../adr/ADR-0020-worktree-removal-is-controlled-demolition.md) — только
  `yarn repo:clean --execute --worktrees`; прецедент 06.08 (2152 файла сквозь junction).
