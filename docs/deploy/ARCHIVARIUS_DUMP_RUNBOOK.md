# Рунбук: первый дамп тома архивариуса на VDS

| Поле | Значение |
|------|----------|
| **Состояние** | сухой прогон снят на стенде, ждёт первого прогона на VDS |
| **Зубы** | 32 из 32 без докера (`scripts/mongo-dump-policy.test.mjs`, `scripts/archivarius-dump.test.mjs`) |
| **Живой прогон стенда** | снят 08.08 на `mongo:7` (сервер 7.0.39), синтетика 5000 спанов, три ветки отказа — [вещдок](../../deploy/archivarius-backup/README.md#вещдок-прогона); нашёл три дефекта, все закрыты |
| **Прогон на VDS** | **не делался** — это и есть жест ниже |
| **Жест** | владельца, не агента |

Четыре строки вместо одной нарочно. «Готовый рунбук» соврал бы: на боевом томе команды не
ходили ни разу. «Черновик» обесценил бы: стенд прогнан живьём и нашёл три настоящих дефекта.
Состояние названо словарной статьёй, а не самооценкой.

> **Это ДАМП, не бэкап.** Проверка отката — карточка `archivarius-mongo-restore-drill`
> ([#1809](https://github.com/officefish/Membrana/issues/1809)). Пока она открыта, всё, что даёт
> этот рунбук, — артефакт, о котором никто не знает, восстановится он или нет. Так и надо
> говорить в отчётах: не «мы застрахованы», а «копия снимается».

## Условия отмены — читать ДО первой команды

Смысл раздела: остановиться до начала, а не обнаружить проблему на середине.

**Предусловия.** Не выполнено хоть одно — не начинать.

- `docker compose ps` показывает `archivarius-mongo` в состоянии `healthy`;
- свободного места на диске **не меньше двойного размера тома** (`docker system df -v`) — дамп
  пишется рядом, а не вместо;
- каталог `var/backups/archivarius` принадлежит пользователю развёртывания: `chown` на него,
  `chmod 0750`. Это ловушка, которой нет локально: там всё пишется из-под одного uid;
- у Mongo сейчас нет аутентификации ([#1753](https://github.com/officefish/Membrana/issues/1753)).
  Если пароль, TLS или replset уже появились — **остановиться**: путь подключения другой,
  и рунбук чинится раньше прогона.

**Что считается провалом.** Любое из этого — стоп, а не «попробуем ещё раз».

| Признак | Что это значит |
|---------|----------------|
| `yarn backup:dump` вернул не 0 | дамп не снят; в каталоге лежит `partial--*` со `stderr`-хвостом в манифесте — читать его, а не гадать |
| в каталоге нет `<имя>.manifest.json` | снятие оборвалось до записи описи; артефакт не является копией |
| `dbInventory` пуст или не содержит `spans` | снят пустой дамп живой базы — худший из исходов, он выглядит как успех |
| размер артефакта резко меньше ожидаемого от объёма тома | обрыв потока; сверять с `docker system df -v` |

**Точка невозврата.** Её здесь нет — и это свойство рунбука, а не случайность. До шага 4
включительно откат тривиален: `rm -rf var/backups/archivarius`, состояние базы не менялось ни
одной командой. Единственный шаг, который удаляет данные, — `backup:prune --apply`, и он в этот
прогон **не входит**. Ctrl-C безопасен на любом шаге: незавершённый дамп остаётся под именем
`.in-progress--*`, вне схемы имён, ротация его не видит.

## Шаги

```bash
cd /opt/membrana                       # каталог развёртывания
export ARCHIVARIUS_DUMP_DIR=/opt/membrana/var/backups/archivarius

# 1. Убедиться, что база жива
docker compose -f packages/background-office/docker-compose.yml \
               -f deploy/background-office.prod.compose.yml ps archivarius-mongo

# 2. Подготовить каталог с правами
install -d -m 0750 -o "$(id -un)" -g "$(id -gn)" "$ARCHIVARIUS_DUMP_DIR"

# 3. Снять первый дамп
ARCHIVARIUS_COMPOSE_FILES=packages/background-office/docker-compose.yml,deploy/background-office.prod.compose.yml \
  yarn backup:dump

# 4. Прочитать опись и убедиться, что она про эту базу
ARCHIVARIUS_DUMP_DIR="$ARCHIVARIUS_DUMP_DIR" yarn backup:list

# 5. Посмотреть план ротации — БЕЗ удаления. --apply на первом прогоне не запускать:
#    удалять нечего, а привычка к --apply опаснее одного лишнего файла.
ARCHIVARIUS_DUMP_DIR="$ARCHIVARIUS_DUMP_DIR" yarn backup:prune
```

## Что записать после прогона

Прогон не считается снятым, пока эти пять величин не перенесены в «Вещдок прогона» в
[`deploy/archivarius-backup/README.md`](../../deploy/archivarius-backup/README.md):

1. дата и время;
2. `mongoVersion` из манифеста;
3. `sizeBytes` артефакта;
4. число документов в `dbInventory` — и сходится ли оно с ожидаемым порядком (≈106К спанов);
5. вывод шага 5 целиком.

## Автоматизация — не здесь

Таймер в этот документ не входит и войти не может: **нельзя ставить на расписание жест,
который ни разу не сделан рукой.** Порядок обязателен именно такой:

1. первый ручной прогон по этому рунбуку → снимается строка «живой прогон»;
2. ручной откат из свежего дампа → закрывается [#1809](https://github.com/officefish/Membrana/issues/1809);
3. и только затем отдельная задача с systemd-юнитом, где вещдоком служат первые два шага.

Причина разделения названа резчиком отдельно: втащив юнит сюда, рунбук перестаёт быть жестом
владельца и становится конфигом демона. Это два разных дома, и смешивать их не надо.
