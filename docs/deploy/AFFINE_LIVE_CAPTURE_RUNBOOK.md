## Почему два захода, а не один

Извлекатель ест слепок жёсткой схемы `affine-inventory-source/1`: точные множества
объектов базы и экспорта, хеши, размеры, связи и гранты. Чтобы собрать такой слепок,
нужно знать **устройство базы Affine** — а оно задано вышестоящим проектом, не нами.

Писать запросы по памяти о чужой схеме — это ровно тот антипаттерн, что пойман утром
14.08 на посылках дня: предсказанное имя вместо фактического. Поэтому первый заход
ничего не извлекает, а **спрашивает базу о ней самой**.

## Заход 1 — разведка устройства (безопасный, без содержимого)

Цель: узнать фактическую схему и форму тома. Наружу уезжает **только структура** —
имена таблиц и колонок, счётчики строк, форма путей. Ни одного документа, ни одного
значения пользовательских данных, ни одного секрета.

Все команды идут через `node scripts/_ssh-office-exec.mjs '<команда>'` (позиционным
аргументом; `--script` принимает только файл).

| # | Что спрашиваем | Команда на хосте |
|---|----------------|------------------|
| 1 | живы ли контейнеры | `docker ps --format '{{.Names}}\t{{.Status}}'` |
| 2 | перечень таблиц | `docker exec affine_postgres psql -At -U $DB_USERNAME -d affine -c "select table_name from information_schema.tables where table_schema='public' order by 1"` |
| 3 | колонки и типы | `… -c "select table_name, column_name, data_type, is_nullable from information_schema.columns where table_schema='public' order by 1,2"` |
| 4 | внешние ключи (связи) | `… -c "select tc.table_name, kcu.column_name, ccu.table_name as ref_table from information_schema.table_constraints tc join information_schema.key_column_usage kcu using (constraint_name) join information_schema.constraint_column_usage ccu using (constraint_name) where tc.constraint_type='FOREIGN KEY' order by 1,2"` |
| 5 | объём по таблицам | `… -c "select relname, n_live_tup from pg_stat_user_tables order by n_live_tup desc"` |
| 6 | форма тома | `find /opt/membrana-affine/storage -type f \| wc -l` и `du -sh /opt/membrana-affine/storage` |
| 7 | форма путей (без имён файлов) | `find /opt/membrana-affine/storage -type f \| sed 's#/[^/]*$##' \| sort -u \| head -20` |

Пароль не передаётся: в `compose.yml` у Postgres стоит `POSTGRES_HOST_AUTH_METHOD: trust`,
локальное подключение внутри контейнера идёт без него. Имя пользователя берётся из `.env`
на хосте и в вывод не печатается.

**Выход захода 1:** описание схемы. Кладётся в `scripts/cache/affine-inventory/`
(вне Git, каталог игнорируется). В репозиторий уезжает только вывод-структура,
если он понадобится ревьюерам, — и только после вычитки на предмет чужих данных.

## Результат захода 1 (исполнен 2026-08-14)

Схема снята фактически, догадок не осталось. Идентификаторы пространств заменены
метками `ws-1..ws-3`; соответствие живёт только в локальном кеше вне Git.

**Носители описи (имена и колонки — с живого сервера):**

| Таблица | Строк | Ключ | Что несёт |
|---------|-------|------|-----------|
| `workspaces` | 3 | `id` | пространства: `name`, `created_at`, `avatar_key` |
| `workspace_pages` | 82 | `(workspace_id, page_id)` | страницы: `title`, `mode`, `blocked`, `published_at` |
| `snapshots` | 91 | `(workspace_id, guid)` | **содержимое документов**: `blob`/`state` (bytea), `size`, `created_at/updated_at`, `created_by/updated_by` |
| `blobs` | 57 | `(workspace_id, key)` | вложения: `size`, `mime`, `status`, `created_at`, `deleted_at` |
| `doc_blob_refs` | 63 | `(workspace_id, doc_id, blob_key)` | **связи** документ ↔ вложение |
| `doc_grants` | 91 | `(workspace_id, doc_id)` | **права**: `principal_type`, `principal_id`, `role` |
| `workspace_members` | 3 | `(workspace_id, user_id)` | участники |

**Раскладка по пространствам:** ws-1 — 73 страницы / 76 снимков / 19 вложений;
ws-2 — 3 / 6 / 19; ws-3 — 6 / 9 / 19. Суммы: **82 страницы**, **91 снимок**,
**57 вложений**, 91 запись прав.

**Базовые счётчики промпта обрели носителей.** «82 страницы» = `workspace_pages`,
«57 ассетов» = `blobs`. Это НЕ превращает их в доказательство полноты (запрет промпта
в силе), но теперь известно, откуда они берутся и чем проверяются.

**Разобрано расхождение база↔том.** Том несёт 114 файлов при 57 вложениях в базе —
ровно вдвое. Причина: на каждое вложение на диске лежат **два** файла — сами байты и
спутник `.json` с метаданными (57 + 57 = 114). Дополнительно: во всех трёх
пространствах лежит **один и тот же набор из 19 ключей** (19 × 3 = 57 строк базы,
38 уникальных имён × 3 каталога = 114 файлов). Расхождение мнимое, но именно такие
вещи и обязана ловить сверка точных множеств.

**Точка согласованности доступна:** `pg_current_wal_lsn` отвечает.

**Важное для объёма работ.** Содержимое документов лежит **в базе** (`snapshots.blob`,
bytea), а не в томе; том несёт только вложения. Схема слепка требует настоящих байтов
для каждого объекта — значит снятие выгрузит на локальный диск и документы из базы, и
вложения из тома. Весь корпус (2.7 МБ тома + снимки) окажется в игнорируемом кеше.

## Заход 2 — снятие слепка (запросы выведены из фактической схемы)

**Порядок извлечения** (одна транзакция `REPEATABLE READ`, только `SELECT`):

1. `pg_export_snapshot()` → `fences.database.marker`; тем же чтением — `pg_current_wal_lsn()`.
2. `databaseObjects`: объединение двух видов —
   - вид `page`: из `snapshots` ⋈ `workspace_pages` по `(workspace_id, guid=page_id)`;
     `id` = `workspace_id/guid`, `ts` = `created_at/updated_at`, `hash` = SHA-256 от `blob`;
   - вид `asset`: из `blobs`; `id` = `workspace_id/key`, `ts` = `created_at`,
     `hash` = SHA-256 от байтов файла тома (считается на месте, не берётся на веру).
3. `rels`: из `doc_blob_refs` — для документа список `asset:<ws>/<blob_key>` и наоборот.
4. `grants`: из `doc_grants` — строка `workspace:<ws>:<role>`; **личности не выгружаются**
   (`principal_id` заменяется ролью — промпт прямо запрещает гранты с личностями).
5. `exportObjects`: те же объекты + `byteSize` и `contentPath` в связке —
   документы выгружаются из `snapshots.blob` в файлы, вложения копируются из тома.
6. Перечень тома с хешами снимается **до и после** шага 5; расхождение = FAIL.

**Пломбы (fences).** Слепок обязан доказать, что база и том прочитаны в одной точке:

- *пломба базы* — всё чтение идёт одной транзакцией `REPEATABLE READ`, идентичность
  точки берётся из `pg_export_snapshot()`; она и есть `fences.database.marker`;
- *пломба экспорта* — сразу после чтения базы снимается перечень файлов тома с хешами;
  маркером служит SHA-256 канонического перечня. Перечень снимается **дважды**, до и
  после; расхождение = том менялся во время съёмки = FAIL, слепок негоден.

**Пломбы (fences).** Слепок обязан доказать, что база и том прочитаны в одной точке:

- *пломба базы* — всё чтение идёт одной транзакцией `REPEATABLE READ`, идентичность
  точки берётся из `pg_export_snapshot()`; она и есть `fences.database.marker`;
- *пломба экспорта* — сразу после чтения базы снимается перечень файлов тома с хешами;
  маркером служит SHA-256 канонического перечня. Перечень снимается **дважды**, до и
  после; расхождение = том менялся во время съёмки = FAIL, слепок негоден.

**Содержимое.** Схема слепка требует `contentPath` и пересчитывает хеши и размеры сама —
значит в связку входят настоящие байты объектов. Они остаются на диске **вне Git**
(`scripts/cache/affine-inventory/`), в репозиторий не попадают ни при каких условиях.

**Проверка детерминизма.** `affine:inventory` запускается на одной связке **дважды** в
две новые директории; `manifest.json` и `manifest.sha256` сравниваются побайтово.
Расхождение = FAIL.

**Итог фазы.** Отчёт-вещдок: идентичность слепка, время, описатели пломб, счётчики по
видам, пломба, отпечаток команды и версии, оператор, вердикт `PASS`/`FAIL`. Промежуточного
зелёного нет. Счётчики `82 страницы / 57 ассетов` доказательством полноты не считаются
никогда — только точное совпадение множеств.

## Границы (из промпта фазы, дословно по смыслу)

- Никакой записи в бой: ни импорта, ни синхронизации, ни публикации, ни регидрации, ни удаления.
- Заморозка публикации Affine не обходится.
- DNS, Caddy, панель, политика доступа и целевое хранилище не трогаются.
- В Git не уезжают: сырые байты, секреты, гранты с личностями, пути источника, ссылки.
- При FAIL или неполном вещдоке следующая фаза (`static-mmbrn-disposition-ledger`) **не открывается**.
