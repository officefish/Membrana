## Ловушки, стоившие времени 08–09.08 — не наступать снова

- **Запечатанную запись журнала прогонов править нельзя.** Попытка «поправить отметку по
  факту» ломает `ledger.leafHash`, и `procedure-run:journal check` показывает порчу.
  Глаголов два — `append` и `amend`, оба дописывают поверх. Неверная отметка чинится
  **порядком строк** (внутри `runId` растёт `sequence`), а не рукой.
- **Конфликт append-only журналов разрешается СОЮЗОМ, а не выбором стороны.** За два дня
  повторилось на шести файлах: `op-log` персон, архив персоны, лента прогонов, история
  сети. Выбор стороны молча стирает чужой день.
- **Ветку заводить ДО первой правки.** 08.08 работа началась поверх ветки живого PR;
  переносить пришлось копированием файлов — дописывать в отревьюенный PR запрещено,
  вердикт привязан к SHA.
- **Переключение ветки теряет owner-choice.** Состояние утренних гейтов лежит файлом в
  репозитории: сменив ветку, гейт снова показал вчерашний выбор, и слово владельца
  пришлось записывать второй раз.
- **Нулевой байт делает файл бинарным для git.** 09.08 ядро политики ушло в PR как
  `Bin 0 -> 13003 bytes`: 224 строки были ревьюеру не видны, зубы со стороны выглядели
  тестирующими пустоту. Локально всё зелено — увидел только тот, кто смотрел дифф.
  Класс тот же, против которого писался спринт: артефакт есть, размер ненулевой,
  содержимого никто не проверял.
- **Отметки следов брать из источника, а не из головы.** За два дня трижды поставил время
  из будущего либо мимо факта; каждый раз правил по `op-log` и `date -u`.
