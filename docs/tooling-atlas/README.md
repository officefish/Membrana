# docs/tooling-atlas — атлас контейнеров (общая документация по туллингу)

**Контейнер контейнеров** (`plane=meta`). Его группа — сами контейнеры проекта вместе
с их мастерскими. Он не хранит собственных описаний, а **агрегирует** документацию
из каждого контейнера в единый производный индекс. Реализация паттерна
[`GROUP_CONTAINERIZATION`](../patterns/GROUP_CONTAINERIZATION.md); оснастка — паттерн
[`HOME_WORKSHOP`](../patterns/HOME_WORKSHOP.md).

## Плоскости индекса (domain / report / meta)

Атлас **не** сплющивает предмет и отчёт в один ряд без метки. В индексе различают:

| `plane` | Смысл | Примеры `home` |
|---------|--------|----------------|
| **domain** | предметный дом группы | `docs/tasks`, `docs/procedures`, `docs/precedents` |
| **report** | слот плоскости отчётов [`docs/audit/`](../audit/README.md) | `docs/audit/git`, `docs/audit/tasks`, `docs/audit/llm-calls`, … |
| **meta** | этот атлас | `docs/tooling-atlas` |

Важно: [`docs/tasks`](../tasks/) (задания) ≠ [`docs/audit/tasks`](../audit/tasks/)
(отчёты **про** задания, `role: derivative`). Ссылки в `registry/ATLAS.md` и Mintlify
ведут на **`home`** (каталог контейнера), не на хвост `worksOn` (`registry.json` /
`registry/`). Движок — спринт [`atlas-report-plane`](../prompts/ATLAS_REPORT_PLANE_PROMPT.md)
(#1097); колонки `role`/`plane` — фаза W2.

## Что это и чем НЕ является

- **Это** — «одно окно» по туллингу-контейнерам: какие дома есть, на какой плоскости,
  primary/derivative, **входной глагол командой**, глаголы мастерской, кит, **пример вызова
  с датой замера**, проекция неймспейсов.
- **Это НЕ** копия документации контейнеров. **Источник истины остаётся в каждом
  контейнере** (его `README.md` + `workshop.manifest.json`); атлас лишь собирает индекс.
  Копий нет — иначе эхо-дрейф (тот самый, против которого паттерн).

## Обнаружение — README и `RootPolicy`, не манифест

```text
D_home(c)      ⇔ ∃ README.md в c  ∧  path(c) ⊨ RootPolicy
D_workshop(c)  ⇔ D_home(c) ∧ ∃ workshop.manifest.json
```

Так велит [`CONTRACT.md §3`](../meeting/workshop-wires/CONTRACT.md) заседания `workshop-wires`.
До 31.07 код искал дома **по наличию манифеста**, тогда как шапка индекса объявляла источником
README, — §3 назвал это нечестным. После правки: домов **43**, мастерских по-прежнему **13**.
Ни одного манифеста «для зелени» не заведено.

`RootPolicy` двухклассовая ([`AMENDMENT_S3`](../meeting/workshop-wires/AMENDMENT_S3.md)):
поддерево `docs/` до второго уровня ∨ поимённый allowlist корневых контейнеров (сегодня —
`scripts`). Носитель — `ROOT_CONTAINER_ALLOWLIST` в `scripts/lib/validate-workshop.mjs`.

**Три вида записи, а не один.** Мастерская · **дом без мастерской** · проекция неймспейса.
Дом без мастерской — законное состояние, а не дефект: мастерская есть подтип дома, а не
обязанность каждого дома.

## Примеры вызова — поле `usage` манифеста

Поправка к Ф1 от 31.07 ([`AMENDMENT_F1`](../meeting/home-workshop/AMENDMENT_F1.md)): рядом с
`verbs` живёт необязательное `usage` — `what` (что даёт вызов), `sample` (живой кусок вывода),
`measuredAt` (дата прогона). Атлас их **агрегирует дословно**; собственных описаний
инструментов не пишет.

**Возраст показывается, свежесть не обещается.** Сверить `sample` с реальностью машинно
нельзя, поэтому рядом стоит дата — читатель видит снимок и его возраст. Заполнение идёт
поштучно; незаполненные мастерские названы в индексе **поимённо**, а не долей.

## Таксономия — контейнер контейнеров (мета-уровень)

Как `docs/procedures/` — контейнер контейнеров (его элементы сами контейнеры), так и
атлас: его **элемент = целый контейнер**. Разница: процедурный дом группирует процедуры,
атлас группирует **все дома вообще** (включая процедурный и, рекурсивно, себя).

## Контракт (что писать / что коммитить)

| Орган | Что | Форма |
|-------|-----|-------|
| **Элемент** | один контейнер = его `README.md` + `workshop.manifest.json` (живут В контейнере, не здесь) | внешний источник |
| **Реестр** | производный индекс всех контейнеров (overwrite, Meta) | `registry/ATLAS.md` — пересобирается |
| **Витрина** | mintlify-страница общей документации по туллингу | `apps/docs-harness/tooling/containers.mdx` — генерится |
| **Инструмент** | осмотр/декомпозиция/рассмотрение + пересбор индекса и витрины | `yarn tooling:atlas` |

**Источник истины — README + манифест каждого контейнера.** `registry/ATLAS.md` и
mintlify-страница руками не правятся (дрейф ловит `--check`).

## Мастерская (предоставляет информацию о контейнерах)

[`workshop.manifest.json`](./workshop.manifest.json) — три глагола:

- **`audit`** (`--audit`): инвентарь контейнеров + здоровье их мастерских (валиден ли
  манифест, есть ли README, каких глаголов не хватает).
- **`decompose`** (`--decompose --by family|plane|holder|kit`): раскладка (в т.ч.
  `--by plane` → report / domain / meta). Список = `home`. Цель — не смешивать
  слот `docs/audit/tasks` с домом `docs/tasks`.
- **`inspectElement`** (`--inspect <home>`): один контейнер вглубь — адрес по **`home`**,
  манифест, глаголы, выжимка README.

## Витрина mintlify

`yarn tooling:atlas --render` пересобирает и `registry/ATLAS.md`, и mintlify-страницу
`apps/docs-harness/tooling/containers.mdx` (группа «Tooling» в harness `docs.json`).
Оба — производные. Product site (`apps/docs`) больше не содержит tooling.

## Дрейф — три разницы, не одна

`--check` считает и называет по отдельности:

| разница | что значит | чем чинится |
|---|---|---|
| `Δ` обнаружение ↔ индекс | дом найден обходом, но в индекс не попал (или наоборот) | `--render` |
| `Δ` манифесты ↔ записи мастерских | манифест лежит, записи нет | `--render` |
| `Δ` реестр ↔ проекция | правило есть в `REGISTRY.json`, но не в проекции | **сначала проверить читаемость реестра** |

Плоское сравнение отвечало «пересобери» на любой вопрос; §3 признал его недостаточным.
Починка у разниц разная, поэтому род и адрес называются, а не схлопываются в «дрейф».

Нечитаемый реестр отделён от пустого: «правил ноль» — состояние, `unreadable` — отказ
источника истины. При этом битый реестр **не роняет** индекс контейнеров: запись членства к
нему отношения не имеет.

## Границы

- Атлас индексирует **дома** — каталоги с `README.md` под `RootPolicy`. Дом без мастерской
  входит в индекс третьим видом записи, а не ждёт «включения позже».
- Только агрегация и чтение; собственных описаний контейнеров атлас не держит. `what` и
  `sample` берутся из манифеста дословно.
- **Свежесть примеров машинно не проверяется** и не обещается — показывается только дата
  замера. Устаревший пример разбирает человек, а не отказ машины.
- Каталог-UI сверх mintlify-страницы — вне области.
