# Плагин «Тембровый тест (MFCC)» — `mfcc-analyzer-test`

Модуль-хозяин: `microphone`. Статус: **draft** — прибор разведки, не продукт.

## Зачем существует

Слово владельца (шторм `storm-mfcc-mic-plugins-2026-07-31`): «нам плагины нужны просто чтобы
выявить потенциал MFCC как таковой». Оператора в задаче ещё нет — поэтому здесь нет
телеметрии, выгрузки и истории прогонов.

## Что делает

Серия замеров против коридоров калибровки, по аналогии с пороговым детектором на быстром
преобразовании: заданное число замеров через выбранный промежуток, три уровня строгости,
вердикт по доле прошедших замеров.

Отличие от образца: у порогового детектора три метрики, здесь двадцать четыре кепстральных
коэффициента, из которых **судятся четыре** — только они различали классы на корпусе.

## Границы, которые нельзя перейти

- **Пресет приходит калибровкой и человеком не правится.** Ворота, отпечаток настроек и
  список судимых меняются через git после `yarn calibrate:mfcc`, а не через экран. Дать
  тронуть коридоры значит обнулить смысл калибровки.
- **Отпечаток настроек несущий.** Вектор, снятый при других настройках свёртки, с воротами
  несравним; плагин обязан считать кадры именно при `mel40-c24-buf4096` и отказать иначе.
- **Считалка инъецируется.** Плагин не знает, как считаются коэффициенты. Библиотека `meyda`
  принадлежит клиенту, за периметр ядра `@membrana/mfcc-analyzer-service` её имя не выходит.

### Провенанс библиотеки

| поле | значение |
|---|---|
| библиотека | `meyda ^5.6.3` |
| где объявлена | `apps/client/package.json` → `dependencies` |
| почему у клиента, а не у ядра | ядро держит `MfccExtractor` инъецируемым нарочно: «замена библиотеки на другую или на собственный DCT не требует правок вне ядра». Ревью P1 от 31.07 вынесло `meyda` из зависимостей пакета — она раздувала бы бандл всем потребителям ядра, включая тех, кому не нужна. Клиент — инъектор, значит библиотека его |
| приговор | структурщик, разбор блока включения 31.07: «законно, с условием — в `dependencies` клиента, не в `devDependencies` корня, потому что это рантайм-зависимость прибора, а не тулинг» |
| решение владельца | 31.07 вечером: оставить в клиенте. Чистый третий путь — отдельный пакет-переходник; вернуться к нему, когда появится второй потребитель |

**Настройки задаются свойствами объекта, а не аргументом вызова** — проверено на живом пакете
31.07, вещдок в `packages/services/mfcc-analyzer/src/types.ts`. Считалка держит СОБСТВЕННЫЙ
экземпляр настроек: общий объект — общее состояние, и второй потребитель молча перебил бы
первому число фильтров.

## Чего этот прибор СЕГОДНЯ не может

- Ворота — **первая прикидка**. Корпус 120 чужих записей, тракт записи склеен с меткой класса
  по построению; вердикт первого боевого прогона `undecided_corpus_bias`.
- Три обстановки владельца (строгий — дрон · средний — модели и ветер · мягкий — цель под
  моторами и стрельбой) **не откалиброваны**: смесей цели с помехой в корпусе нет. Поэтому
  уверенность отчёта не может быть высокой, и зелёного вердикта на экране не бывает.
- Порог немого кадра калибровкой не даётся — снимается на тишине своего тракта кнопкой
  «Замерить тишину». Пока не замерен, защиты от тишины нет: кадр из околонулевых
  коэффициентов проходит любой коридор, включающий ноль.

Приедет датасет на 600 звуков — перекалибровка обязательна, затем обновление `presets.ts`
отдельным PR.

## Состав

| файл | предмет |
|---|---|
| `types.ts` | контракт: пресет, конфиг, судьба замера, итог серии |
| `presets.ts` | пресет первой прикидки — 24 коридора, судимые `[0,1,2,3]` |
| `mfccPluginState.ts` | состояние и команды; смена настройки отменяет идущий сбор |
| `mfccAnalyzerPlugin.ts` | жизненный цикл, судейство замера и серии, замер тишины |
| `detectMagnitudeThreshold.ts` | порог немого кадра по выборке тишины |
| `buildMfccTestReport.ts` | отчёт: вердикт, уверенность словом, оговорки |
| `MfccTestPanel.tsx` | экран |
| `components/` | клетки хода серии, строка коридора, карточка вердикта |
| `mfccExtractor.ts` | считалка при настройках отпечатка, свой экземпляр настроек |
| `mfccAnalyzerTestPlugin.ts` | фабрика в форме реестра |

Спринт: `docs/sprint/cut/mfcc-plugin-sprint.json` (семь блоков, гейт 7/7).
Калибровка: `yarn calibrate:mfcc` → `data/detectors-benchmark/v0.2/reports/`.
