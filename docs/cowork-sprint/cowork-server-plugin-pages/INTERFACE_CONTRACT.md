# Interface Contract — почва под плагины серверных страниц

> Артефакт фазы 3 коворка `cowork-server-plugin-pages`. Протокол консилиума:
> [`docs/discussions/cowork-sprint-cowork-server-plugin-pages-interface-consilium.md`](../../discussions/cowork-sprint-cowork-server-plugin-pages-interface-consilium.md).
>
> Блоки по этому контракту **не переписываются**. Всё, что ниже названо адаптером, пишется
> поверх мёржа трёх блоков на интеграционной ветке (регламент, фаза 4).

## Глоссарий стыка — одинаковые слова на границах

| Слово | Значит ровно это | Не значит |
|---|---|---|
| **дом** | имя из `HOME_REGISTRY`, за которым стоит Nest-модуль с реализацией `IPluginHost` | место, где лежат результаты (их дом — `PLUGIN_RESULTS_DB`, это другой предмет) |
| **жилец** | плагин, зарегистрированный в доме | плагин, отображаемый на странице: рисуется только род `showcase` |
| **включённость** | состояние жильца в реестре дома | поле манифеста (M5′: манифест — пять полей) |
| **форма показа** | `displayForm` манифеста — чем жилец **хочет** рисоваться | что страница **умеет** нарисовать: это `SUPPORTED_FORMS` страницы |
| **задание** | набор адресов записей ленты, поданных плагину | сами записи и тем более звук |
| **виджет** | результат жильца ПОД основным блоком | панель настроек: она только в правом сайдбаре (канон §3) |

## Шов A ↔ C — имя дома

| Сторона | Даёт / берёт | Инвариант |
|---|---|---|
| A | `HOME_REGISTRY['background-cabinet/journal']`, тип `HomeName`, `isHomeName` | юнион ровно из двух имён; снятое имя не проходит ни типом, ни валидатором |
| C | реализацию с `mountTargetId === 'background-cabinet/journal'` | чужой `mountTarget` отвергается при регистрации |

**Адаптер И-1.** Стаб `contracts.stub.ts` удаляется целиком; импорты модуля журнала
переводятся на `@membrana/plugin-contracts`. Строка зависимости добавляется в
`packages/background-cabinet/package.json` — точка сборки, вносит интеграция.
Локальный кросс-пакетный typecheck в worktree с общим `node_modules` недостоверен —
проверка делегируется CI.

## Шов A ↔ background-office — снятое имя

Вне зон всех трёх блоков, но ломается от блока A. Замерено: **4 ошибки типов**.

**Адаптер И-2.** В `packages/background-office/src/modules/plugin-results/plugin-results.dto.ts`
заменить снятое имя на `background-cabinet/journal` в `HOME_NAMES` — зуб полноты юниона сойдётся
сам, две производные ошибки контроллера уйдут следом.

**Адаптер И-3.** В `packages/background-media/src/modules/collections/plugin-host.service.test.ts`
заменить снятое имя на другое существующее чужое. Зуб зелёный и сейчас, но проверяет уже не то,
что назван проверять: «дом чужой» подменилось на «имени нет вовсе». Зелёный зуб с уехавшим
смыслом опаснее красного — красный виден.

## Шов C → B — список жильцов и их состояние

**Адаптер И-4 (расширение модуля, класс 1).** Дом получает читателя состояния:

```ts
getPluginStates(): ReadonlyArray<{ manifest: PluginManifest; enabled: boolean }>
```

Почему читатель, а не поле в манифесте: `enabled` — операция реестра (M5′), в пять полей
манифеста он не входит. Почему вообще нужен: без него `setPluginEnabled` пишет в состояние,
которое снаружи не прочесть, и галочке сайдбара неоткуда взять положение.

**Владелец включённости — дом.** Единственный. `PagePluginsState.enabled` блока B после
интеграции есть **отражение** ответа дома, а не второй источник истины: страница показывает,
что ответил дом, и просит его переключить. Инварианты ядра B при этом сохраняются полностью —
выключение активного гасит виджет и сворачивание независимо от того, откуда пришло состояние.

**Адаптер И-5 — реестр рисовалок кабинета.** Манифест функций не несёт, поэтому:

```ts
type CabinetRenderer = {
  name: string;
  renderWidget: () => ReactNode;
  renderSettings?: () => ReactNode;
};
const CABINET_RENDERERS: Record<string, CabinetRenderer>;

// манифест + рисовалка → жилец страницы
function toPagePlugin(m: PluginManifest, r: CabinetRenderer): CabinetPagePlugin;
```

Правила отображения — закрытый список:

| Случай | Что делает страница |
|---|---|
| род `showcase`, рисовалка есть | полноценный жилец: `form ← displayForm`, `description ← description` |
| род `showcase`, рисовалки нет | **виден в сайдбаре, помечен словами** «нечем нарисовать». Прятать нельзя: зарегистрированный, но невидимый жилец — призрак (Т4) |
| род `handler` или `report` | на странице **не показывается**: рисоваться нечем, и обещать виджет, которого не будет, нельзя |
| `displayForm` вне `SUPPORTED_FORMS` | виден, помечен «форма не поддерживается» — механизм блока B уже это умеет |

## Шов B → C — какие формы умеет страница

`SUPPORTED_FORMS` блока B (`row · table · histogram · time-series`) есть **единственный**
ответ на пункт 2 раздела «Чего здесь ещё нет» в `MODULE_INTERFACE.md`. Модуль список **не
копирует**, а ссылается: две копии разъедутся молча. `zone-map` и лазейка `x-…` остаются
законными формами манифеста, страницей не рисуемыми.

## Инварианты потока данных

| Инвариант | Формулировка |
|---|---|
| владелец времени | дом. Страница состояния не кэширует между перезагрузками: после перезагрузки положение галочек берётся у дома |
| порядок | регистрация → показ в сайдбаре → включение → активация → виджет. Активировать выключенного нельзя; сворачивать основной блок без виджета нельзя |
| единицы | лента отдаётся **записями**, не звуком. У рода `track` есть `sampleId`; `deviceId` в элементе ленты отсутствует и приходит контекстом запроса |
| отказ раньше работы | негодное задание отвергается ДО вызова плагина, причиной из закрытого списка (`empty-task · entry-not-found · audio-not-here`), а не пустым результатом |
| чужое неотличимо от несуществующего | запись другого пользователя даёт `entry-not-found`, а не «нет доступа» |
| нет призраков | ни одно зарегистрированное имя не исчезает из виду молча — ни снятый дом, ни нерисуемый жилец |

## Интеграционный smoke — один сценарий через все швы

1. Зарегистрировать в доме журнала `showcase`-манифест с домом `background-cabinet/journal`
   и формой `row` → регистрация принята **(шов A↔C: имя дома настоящее, не стаб)**.
2. Тот же манифест с чужим `mountTarget` → отказ при регистрации.
3. `getPluginStates()` возвращает жильца включённым **(шов C→B: состояние читается)**.
4. Страница журнала показывает его в правом сайдбаре с включённой галочкой **(И-5)**.
5. Выключить со страницы → дом на `notify` его больше не зовёт, `request` бросает **(владелец один)**.
6. Включить, активировать → виджет нарисован ПОД основным блоком, настройки — только в сайдбаре.
7. Манифест с формой `zone-map` → жилец виден, помечен «форма не поддерживается»,
   регистрацию сохраняет **(шов B→C)**.
8. `yarn typecheck` по `background-office` зелёный **(швы И-2, И-3)**.

## Находка интеграции — граница ESM/CommonJS, которую прятал стаб

Вскрылась не на консилиуме, а при первой же сборке: `@membrana/plugin-contracts` — ESM-пакет,
а `background-cabinet` собирается в CommonJS. `require` до контрактов не дотягивается.

**Почему её не было видно в фазе 2.** Зона блока C не включала `package.json`, поэтому блок
честно построил стаб контрактов в своей зоне — и стаб был CommonJS. То есть стаб прятал ровно тот
шов, ради которого зона и нарезана. Это **дефект резки brief**, а не блока: дай C строку
зависимости, граница вскрылась бы в изоляции. Фиксируется здесь и в `RETROSPECTIVE.md`.

**Как закрыто — двумя уже решёнными в доме способами, без третьего:**

| Что | Как | Образец |
|---|---|---|
| типы | обычный импорт с `with { 'resolution-mode': 'import' }` | `background-office` |
| значения | динамический `import()` за швом `loadContracts()`, готовность через `onModuleInit` | `background-media` |

Следствие для дома журнала: до инициализации регистрация отвечает `ServiceUnavailable`, а не
пропускает молча. Проверено зубом.

**Отличие от media:** media держит ПОСТОЯННЫЙ локальный слепок типов
(`plugin-host.types.ts`), то есть свой стаб не снимала никогда. Журнал типы не дублирует —
берёт из пакета. Дублирование типов и есть тот самый разъезд двух копий, от которого контракт
предостерегает выше.

## Проверено при интеграции — риск миграции пуст по факту

`runAddressSchema.mountTarget` собран из `HOME_NAMES`, поэтому адаптер И-2 меняет проверку уже
СОХРАНЁННЫХ записей прогонов: запись со снятым именем перестала бы читаться. Замерено: все четыре
зарегистрированных манифеста метят в `background-media/collections`, записи со снятым именем
появиться не могли. Риск реален по устройству и пуст по факту — названо, а не умолчано.

## Что контракт НЕ решает

Класс правки при снятии имени дома и адресация прогона журнала (`RunAddress.collectionId`) —
предмет владельца словаря, вынесены протоколом. Интеграцию они не блокируют.
