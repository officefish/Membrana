## Что я готов отдать

| Блоку | Что | Форма | Инварианты |
|---|---|---|---|
| `experience-loop` | **вердикт исполнения по каждому блоку плана** — исход, который C сопоставит со своим предсказанием | `GateReport = { planId, checkedBlocks: number, corpusSize: number, exitCode: 0\|1\|2, blocks: [{ blockId, personaId, verdict, evidenceRefs: string[], reason: string }], findings: [{ toothId, blockId, reason }] }` | `verdict` — ровно один из семи закрытых (`honest_pair` · `refused_with_reason` · `plan_lied` · `wrong_performer` · `stale_trace` · `unresolvable_ref` · `no_corpus`) · `reason` **никогда не пустой**: отказ легален только с причиной · `exitCode = 0 ⟺ нет остановок ∧ нет ошибок входа ∧ corpusSize > 0 ∧ checkedBlocks > 0` · отчёт **не содержит** строки «нарушений 0» при `corpusSize = 0` |

|---|---|---|

Сопоставление следа с блоком — **только** по `blockId` | Сопоставление по пути, зоне кода или имени ветки воспроизводит прямой запрет M1 «выводить участие из зон» |
| **идентификатор персоны** | `personaId` = `id` из `docs/virtual-team/voices.registry.json`. Два «зелёных» блока с разным пониманием timeline дают мусор на стыке — регламент, Phase 3 |

## Риски шва, названные заранее (для Phase 3)

1. **Дом ленты следов не существует.** M4 назвал дом («лента вещдоков окна»), носителя в
   репозитории нет. Если A и C независимо придумают по своей ленте, на интеграции будет три.
   Моя позиция: лента — вход гейта, а не его собственность; готов принять чужую форму адаптером
   в `plan-reader`-подобном шве.
2. **Окно спринта.** Скрытая посылка M1, названная аудитором: ни `sprintId`, ни окна в реестре
   нет — только `createdAt`/`archivedAt` карточки. Я требую окно от плана; если A решит, что
   окно живёт не в плане, шов A→B меняется в одной функции.
3. **`revisionAt` может отсутствовать** в чужой форме плана: тогда протухание не вычисляется, и
   гейт обязан сказать это ошибкой входа. Считать «всё свежее» — молчаливая лазейка, ровно
   запрещённый перенос согласия на изменённый контракт.
4. **`refused_with_reason` — потенциальная лазейка**: если список причин второй двери окажется
   открытым, режим «без персональной ответственности» станет тихой кнопкой «пропустить
   честность». Гейт держит только форму (причина обязательна и из списка); закрытость самого
   списка — не мой предмет, и на Phase 3 я её потребую.

### Уточнения предиката, которые меняют мои обещания соседям

| № | Уточнение | Почему так, а не как в Phase 1 |
|---|---|---|
| Д-1 | **Пустой корпус перебивает вторую дверь**: при `corpusSize = 0` вердикт `no_corpus` получают **все** блоки плана, включая объявленные `no_personal_responsibility` | Иначе при пустой ленте отчёт печатает «не применимо» над несуществующим предметом, а инвариант `code = 0 ⟺ … ∧ corpusSize > 0` даёт код `1` **без единой остановки** — то есть ненулевой код без диагноза. Так `1` перестал бы значить «проверка сказала нет» |
| Д-2 | **Лестница вердиктов зафиксирована в одном порядке**: `refused_with_reason` → `plan_lied` → `wrong_performer` → `stale_trace` → `unresolvable_ref` → `honest_pair` | В Phase 1 порядок проверки назван не был, а он наблюдаем: след может быть одновременно чужим и протухшим. Неназванный порядок = вердикт зависит от реализации |
| Д-3 | **`context_run` раньше `contract_signature` — не восьмой вердикт, а ДИСКВАЛИФИКАЦИЯ следа** (`eg-run-before-signature`): след убирается из множества вещдоков, дальше работает лестница Д-2 — обычно `plan_lied`, то есть остановка | §7 концепта требовал здесь «остановку, а не находку», но восьмой вердикт был бы **новым словом**, а впихивание случая в один из семи — ложным диагнозом. Дисквалификация даёт остановку механически и не двигает границу «находка↔остановка». Честная цена: если у блока есть **другой** валидный след того же исполнителя (например, подпись в окне), блок остаётся `honest_pair` с названной дисквалификацией — отрицать подпись как вещдок значило бы вычеркнуть род из списка |
| Д-4 | Подпись для сравнения порядка ищется по **всей ленте блока**, а не только внутри окна | Подпись, доехавшая после закрытия окна, всё равно означает, что в момент прогона согласия не было. Иначе дисквалификация никогда не срабатывает |
| Д-5 | Порядковая находка `eg-order-review-early` **не выносится, если подписи в ленте нет вовсе** | Носителя рода `contract_signature` сегодня не существует; вменять исполнителю отсутствие носителя — это выдумать носитель |
| Д-6 | Следы **раньше** окна (`at < from`) не дают находки — только не входят в вещдоки; находку `eg-late-close` получает лишь `at ≥ to` | «Late close» описывает позднее закрытие; раннее — чужое окно, и своего имени в Phase 1 не получало |
| Д-7 | В `GateReport` добавлены два поля: `disqualified[]` и `inputErrors[]`; `findings[]` остаётся закрытым списком четырёх | `experience-loop` иначе не отличит «остановку по дисквалификации» от «остановки по отсутствию следа», а «проверка не состоялась» приедет к нему как пустой отчёт |

### Что теперь фактически отдаётся (форма проверена стабом-приёмником)

`GateReport = { planId, now, checkedBlocks, corpusSize, exitCode, blocks[{ blockId, personaId,
verdict, evidenceRefs, reason, stopped }], findings[{ toothId, blockId, reason }],
disqualified[{ toothId, blockId, traceId, reason }], inputErrors[{ code, subject, detail }] }`.

`stub-experience-sink.mjs` гоняется по **каждой** фикстуре и валит прогон, если вердикт вне семи,
`reason` пуст, `personaId` отсутствует или признак `stopped` разошёлся с таблицей класса.

### Форма следа, которую я требую от ленты (вход, не собственность)

`{ traceId, blockId, kind, subject, at, ref, relatesToSprint? }` — все поля кроме последнего
обязательны; `kind` из четырёх; `subject` из реестра голосов; `at` ISO-8601. Отсутствие поля,
неизвестный род, неразбираемое время и персона вне реестра — **ошибки входа**, код `2`.
Форма односторонняя: на Phase 3 адаптируется в шве, как и план.

### Новые риски шва, увиденные на сборке

1. **`corpusSize` при ошибке входа**: сейчас в отчёт попадает число **валидных** записей, а
   невалидные видны только списком ошибок. Знаменатель «сколько записей отвергнуто» ленте
   принадлежит, не гейту — на Phase 3 попрошу у носителя ленты общее число записей.
2. **Сопоставление следа с блоком только по `blockId`** держится на том, что лента вообще несёт
   `blockId`. Если чужая лента опознаёт работу иначе (по пути, ветке, задаче), шов не
   адаптируется — это прямой запрет M1, и я его не обойду адаптером, а объявлю блокером.
3. **`refused_with_reason` не требует ни одного следа** — при плане, где все блоки во второй
   двери, гейт зелен при непустом корпусе. Это правильно по M7 и одновременно единственная
   оставшаяся дверь мимо честности; счётчик «вторая дверь N» напечатан в итоге намеренно, чтобы
   доля таких блоков была видна невооружённым глазом.
