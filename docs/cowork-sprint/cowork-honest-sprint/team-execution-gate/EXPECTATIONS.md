## Инварианты стыка, называю явно

| Инвариант | Моё решение | Почему так |
|---|---|---|
| **идентификатор блока** | `blockId`, слаг `^[a-z0-9][a-z0-9-]{2,63}$` (та же форма, что `ID_RE` в `scripts/lib/evidence-index.mjs` — беру готовое). Сопоставление следа с блоком — **только** по `blockId` | Сопоставление по пути, зоне кода или имени ветки воспроизводит прямой запрет M1 «выводить участие из зон» |
| **идентификатор персоны** | `personaId` = `id` из `docs/virtual-team/voices.registry.json`. Человеческое имя (`human`), модель, `Co-Authored-By`, ник агента — **не** идентификаторы | Реестр голосов — единственный носитель, где «объявленный обязан быть вызываемым» проверяется машиной (`yarn verify:voices`). `Co-Authored-By` одинаков у всех агентов: различающей силы ноль. Персона вне реестра → ошибка входа, а не «неизвестный исполнитель» |
| **владелец времени** | окно `[from, to)` и `revisionAt` — **план**; метка `at` — **след** (кто произвёл акт, тот ставит момент); гейт **не владеет временем**, `Date.now()` в предикатах запрещён, `--now` живёт только в шапке отчёта | Иначе один и тот же вход в другой час даёт другой вердикт. Два «зелёных» блока с разным пониманием timeline дают мусор на стыке — регламент, Phase 3 |
| **порядок событий** | канонический: `contract_signature ≺ session_prep ≺ context_run ≺ review_pass`. Нарушение — находка, **кроме** `context_run` раньше `contract_signature`: это остановка | Старт возможен только при «назначен **и** принял» (M2); «работавший без назначения API не получает» (M4) |
| **единица объёма** | гейт объёма **не считает** и в него не заглядывает: единица объёма — предмет `cut-contract` (изменённые строки, константа `OVERSIZED_CHANGED_LINES`) | Две независимых меры объёма в одном контуре — гарантированное расхождение на шве. Мой предикат от объёма не зависит вовсе |
| **пустой корпус** | `corpusSize = 0` → вердикт `no_corpus` на каждый блок, код `1`, строки «нарушений 0» в отчёте нет ни при каких условиях | Ратифицированный вердикт M5, 30.07: «чисто» при пустом корпусе — это «корпуса нет». На этом же классе 30.07 был пойман `meeting:audit` |
| **закрытость родов следа** | четыре рода, `kind` вне списка → `E_TRACE_KIND_UNKNOWN`, код `2`, вердиктов нет | Тихое игнорирование даёт ложный красный, тихий приём — обход гейта **новым словом** |

## Риски шва, названные заранее (для Phase 3)

1. **Дом ленты следов не существует.** M4 назвал дом («лента вещдоков окна»), носителя в
   репозитории нет. Если A и C независимо придумают по своей ленте, на интеграции будет три.
   Моя позиция: лента — вход гейта, а не его собственность; готов принять чужую форму адаптером
   в `plan-reader`-подобном шве.
2. **Окно спринта.** Скрытая посылка M1, названная аудитором: ни `sprintId`, ни окна в реестре
   нет — только `createdAt`/`archivedAt` карточки. Я требую окно от плана; если A решит, что
   окно живёт не в плане, шов A→B меняется в одной функции.
3. **`revisionAt` может отсутствовать** в чужой форме плана: тогда протухание не вычисляется, и
   гейт обязан сказать это ошибкой входа. Считать «всё свежее» — молчаливая лазейка, ровно
   запрещённый перенос согласия на изменённый контракт.
4. **`refused_with_reason` — потенциальная лазейка**: если список причин второй двери окажется
   открытым, режим «без персональной ответственности» станет тихой кнопкой «пропустить
   честность». Гейт держит только форму (причина обязательна и из списка); закрытость самого
   списка — не мой предмет, и на Phase 3 я её потребую.
