## 1. Блок изнутри: одна запись, два автора, две мерки

Блок строит **обучение на исходах — после работы**. Предмет — не отчёт и не витрина, а
**четвёртый род записи памяти**: «моё предсказание ↔ его исход».

```
ПЕРЕД работой                          ПОСЛЕ работы
  предсказание (immutable)   ──────▶     исход (по следам)
  тимлид: «эта нарезка влезет»           changedLines сегментов ревью
  ведущая: «этап не пройден»             изменилось ли что-то после остановки
                    │                             │
                    └──────── сопоставление ──────┘
                                   │
                    ┌──────────────┴──────────────┐
              cutAccuracy (бинарный сигнал)   falseStopRate (не бинарный)
                    └──────────────┬──────────────┘
                                   ▼
                      номинация 5–7 удачных прогонов
                        (только НОМИНАЦИЯ, канон — человек)
```

Три слоя, и всё, что ниже, не имеет права заводить свои значения слов «предсказание»,
«исход», «остановка», «объём»:

```
forecast-record  (схема рода: что вообще является записью этого рода)
   ↓ записи
метрики          (две чистые функции + закрытый алфавит ПРИЧИН ОТСУТСТВИЯ)
   ↓ значения
номинация        (детерминированный отбор 5–7 прогонов; в канон не пишет)
```

**Два автора — не деталь реализации, а причина, по которой род один, а мерок две.** Тимлид
учится «как декомпозировать», ведущая — «как останавливать». Обе учатся об одном и том же:
о качестве собственного предсказания. Разная у них только форма сигнала обратной связи, и
именно поэтому мерка не может быть одна: одна мерка на два сигнала — это либо бинаризация
доли (потеря), либо усреднение бинарного (подгон).

## 2. Чем род «предсказание ↔ исход» отличается от трёх известных

Живой архив памяти сегодня однороден по предмету — вещдок из `docs/virtual-team/memory/archive/*.jsonl`:
**1166 записей `class: position`, 160 `class: routine`, все `kind: verbatim`**. Записей об
исполнении и о предсказании — **ноль**.

| | `position` (позиция) | `execution` (след исполнения, M8) | оценка чужого (ревью/фидбек) | **`forecast` (этот блок)** |
|---|---|---|---|---|
| Кто автор | персона | персона-держатель контракта | персона-ревьюер | персона |
| **Кого судит запись** | предмет спора | работу (судит приёмка/DoD) | **другого** | **самого автора** |
| Что в записи | цитата реплики + комната | акт · результат · след | вердикт о чужом выходе | **предсказание + исход + сопоставление** |
| Момент рождения | комната/консилиум | закрытие окна | ревью чужого выхода | **два момента в одной записи** |
| Может выйти плохой | нет (позиция не «промах», она несогласная) | да, но плохо о **работе**, не о суждении автора | да, но плохо о **чужой** работе | **да — плохо о самом авторе** |
| Учит автора | нет | нет | нет | **да** |

Несущее отличие формулируется одной фразой: **три известных рода отвечают на «что было», а
четвёртый — на «насколько я умею предсказывать».** Отсюда три следствия конструкции:

1. **В записи обязательны ДВА момента времени** (`predictedAt`, `observedAt`) и порядок между
   ними. Ни один из трёх известных родов двух моментов не несёт — им достаточно одного.
2. **Предсказание неизменяемо после фиксации.** Это единственная защита рода: автор, который
   правит своё предсказание, увидев исход, всегда прав, и запись перестаёт учить. Инвариант
   `predictedAt < observedAt` + append-only — не гигиена, а условие существования рода.
3. **Обе стороны сопоставления принадлежат автору, но берутся из следов, а не из его слов.**
   Поэтому род не требует чужой оценки — и именно поэтому его метрики могут выйти плохими
   (см. §4.4). Род «оценка чужого» этим свойством не обладает по построению: чужую оценку
   можно оспорить, но нельзя проверить следом.

Формально род не ломает архитектуру памяти (граница M8: «меняется предмет, не трубы»): дом тот
же `archive/<persona>.jsonl`, дискриминатор — существующее поле `class` со новым значением
`forecast`. Расхождение вердикта M8 (`kind: execution`) с живой формой (`kind: verbatim` +
`class: position`) я **не решаю односторонне** — это шов, вынесен в `EXPECTATIONS.md`.

## 3. Поля записи

Одна схема, два подвида через дискриминатор `subject`. Один подвид — один автор — одна мерка.

```
ForecastRecord = {
  id           : string        // <personaId>-<sprintId>-<subject>-<seq>, стабилен и адресуем
  class        : 'forecast'    // ЧЕТВЁРТЫЙ род; дискриминатор рода в живом архиве
  subject      : 'cut' | 'stop'  // 'cut' → тимлид/нарезка · 'stop' → ведущая/остановки
  personaId    : PersonaId     // держатель предсказания (§7)
  sprintId     : string        // окно, к которому предсказание относится
  predicted    : Predicted     // ПРЕДСКАЗАНИЕ — зафиксировано ДО работы, immutable
  predictedAt  : ISO           // из данных, не из моих часов
  ratifiedBy   : 'owner' | { none: причина }   // для 'cut' обязательна: план нарезки ратифицируется
  observed     : Observed | { none: причина }  // ИСХОД — из следов, ПОСЛЕ работы
  observedAt   : ISO | null
  outcome      : Outcome       // производное сопоставление, закрытый алфавит
  evidence     : Ref[]         // { path | sha | pr | card | artifact } — адресуемые, не проза
  provenance   : { planRef, traceRef, sessionId? }  // сессия — транспорт, не автор (M8)
}

Ref     = { type: 'path'|'sha'|'pr'|'card'|'artifact', value: string }
Outcome = 'hit' | 'miss' | 'not-observed'          // 'почти' не существует (M3)
```

`subject: 'cut'` — предсказание тимлида о нарезке:

```
Predicted = { blocks: [ { cutBlockId, contextPersonaId, claim: 'fits' | 'does-not-fit' } ] }
Observed  = { blocks: [ { cutBlockId, changedLines: int, verdict: 'fitted' | 'overflowed' } ] }
```

`subject: 'stop'` — предсказание ведущей об остановке этапа:

```
Predicted = { stopId, stageId, objectRef: Ref, claim: 'stage-not-passed' }
Observed  = { resolvedAt: ISO|null, changes: Ref[], useful: boolean|null }
```

Решения по полям, которые стоит обосновать:

- **`claim` — перечисление, а не число.** Тимлид не предсказывает «387 строк»: мерка ревью
  бинарна, и предсказание обязано быть в той же шкале, в которой придёт исход. Число строк
  живёт только в `observed` — оно наблюдение, а не заявка.
- **`claim: 'does-not-fit'` существует.** Это легальное «нет с причиной»: тимлид вправе
  объявить блок заведомо переполненным (например, вынужденная миграция), и такое объявление
  тоже проверяется исходом. Без этой ветки честное «не влезет» пришлось бы прятать в пустое
  поле, а пустое поле — не отказ.
- **`ratifiedBy` — поле записи, а не факт снаружи.** План нарезки ратифицирует владелец (шторм);
  нератифицированное предсказание в мерку не входит (§4.3), и причина этого обязана быть
  видна в самой записи, иначе метрика молча считается по неполному множеству.
- **`objectRef` у остановки обязателен.** «Остановила этап» без названного объекта нельзя
  сопоставить с изменением — предикат полезности не вычислим. Остановка без `objectRef` —
  дефект записи, а не запись с неизвестным исходом.
- **`sessionId` — только в `provenance`.** Персона держит предсказание, сессия его набирает
  (M8: «сессия — транспорт, не субъект журнала персоны»).
- **Отсутствие всюду выражено формой `{ none: причина }`, а не `null`-ом и не пропуском поля.**
  Приём взят из живого `case-store.mjs` (`isLegalNo`): отказ обязан быть читаемым, а пустота —
  неразличима от забывчивости.

## 4. Две метрики

### 4.1 `cutAccuracy` — точность нарезки (тимлид, сигнал бинарен)

Мерка **не изобретается**: блок обязан поместиться в **одну проверку код-ревью**. Это уже
работающая мерка — ревью каждый день печатает `oversized`, но задним числом, как жалобу. Здесь
то же число становится условием до работы. Одно число, другой момент.

```
threshold                        = 400 изменённых строк      // мерка ревью, параметром
changedLines(b)                  = Σ (insertions + deletions) сегментов ревью, привязанных к b
observed(b)                      = changedLines(b) > threshold ? 'overflowed' : 'fitted'
hit(b)                           ⇔ (claim=fits ∧ fitted) ∨ (claim=does-not-fit ∧ overflowed)
cutAccuracy(S) = |{ b : hit(b) }| / |{ b : observed(b) определён }|
```

- Сигнал **бинарен на блок**; мерка на прогон — доля по блокам. При одном блоке доля
  вырождается в 0/1, и это честно: она не притворяется непрерывной.
- **Два направления промаха названы**: `overflow` (обещал «влезет» — переполнился) и `over-cut`
  (объявил «не влезет» — влез). Оба — `miss`. Веса направлениям не даю: владелец их не называл
  (`//provisional` не нужен — просто веса нет, доля одна).
- **Числитель и знаменатель печатаются рядом с долей всегда.** Доля без счётчиков скрывает
  ровно то же, что скрывает `?? 0`.
- Блоки без наблюдаемого исхода в знаменатель **не входят**, но выводятся строкой
  `без исхода: k`. Иначе промах прячется в «ещё не доехало до ревью».
- **Привязка сегмента ревью к `cutBlockId` требуется явно** и по путям файлов не угадывается.
  Нет привязки → исход не определён с причиной `no-attribution`, а не 0.

### 4.2 `falseStopRate` — доля ложных остановок (ведущая, сигнал не бинарен)

Мерка названа отдельно, потому что сигнал у ведущей не бинарен: остановка не «влезла/не влезла»,
она **полезна ⟺ после неё что-то изменилось**.

```
useful(s)      ⇔ ∃ c ∈ changes(s.objectRef) : s.stoppedAt < c.at ≤ s.resolvedAt
resolved(s)    ⇔ s.resolvedAt ≠ null
falseStopRate  = |{ s : resolved(s) ∧ ¬useful(s) }| / |{ s : resolved(s) }|
```

- `changes(objectRef)` берётся **из ленты вещдоков окна**, не из слова ведущей. Изменением
  считается адресуемое событие на названном объекте: новый `Ref`, новая версия контракта, новый
  SHA, смена статуса. Неадресуемое «что-то поправили» изменением **не является** — иначе
  предикат становится вежливостью.
- Направление: ниже — лучше. `0%` при непустом знаменателе — легитимный отличный результат.
  `0%` при пустом знаменателе — **запрещено** (§4.3).
- Неразрешённые остановки в знаменатель не входят и печатаются строкой `не разрешены: k`.
  Без этой строки ложные остановки навсегда прячутся в «ещё в работе».
- Остановка, разрешённая **без прохождения этапа** (этап отменён/переделан), — `useful`: отмена
  и есть изменение. Ложной является только остановка, после которой этап прошёл, а объект
  остался тем же.

### 4.3 Что означает ОТСУТСТВИЕ метрики

Ратифицированный запрет (вердикт M5, 30.07): **«чисто» при пустом корпусе — это «корпуса нет»**.
Ноль записей опыта ≠ «учиться нечему»; ноль остановок ≠ «ложных нет». На этом классе сегодня
поймали `meeting:audit`: «нарушений 0» получено на нуле найденных протоколов.

Поэтому у метрики три состояния, не два, и третье — **именованное**:

```
Metric = { defined: true, value, numerator, denominator, pair }
       | { defined: false, reason: AbsenceReason }      // значения НЕТ вообще

defined ⇔ denominator > 0
```

Закрытый алфавит причин отсутствия:

| Метрика | Причина | Что означает |
|---|---|---|
| `cutAccuracy` | `no-cut-forecast` | предсказания нарезки нет — тимлид не резал или не записал |
| | `no-observed-outcome` | нарезка есть, ревью до блоков не дошло |
| | `forecast-not-ratified` | план не ратифицирован владельцем — предсказание нелегитимно |
| | `no-attribution` | сегменты ревью не привязаны к `cutBlockId` |
| `falseStopRate` | `no-stops-recorded` | остановок ноль — **не «ложных нет»** |
| | `stops-unresolved` | все остановки не разрешены — исход ещё не наблюдаем |
| | `no-lead-appointed` | окно шло «без ведения» (M6) — за матч не выдаётся |

Правила вывода, проверяемые машинно:

1. **Рядом с `defined: false` процент не печатается никогда.** Ни `0%`, ни `—%`, ни `n/a` в
   графе значения: строка читается «не определена: ноль остановок за окно».
2. **`?? 0` и `|| 0` в коде метрик запрещены** — тест на это ставится в Phase 2.
3. Отчёт при **обеих** неопределённых метриках обязан сказать «корпуса опыта нет» — не «всё
   хорошо» и не молчание.

### 4.4 Почему обе метрики могут выйти плохими

Метрика, которая не может выйти плохой, — не метрика. Проверяю каждую на два способа
сжульничать и называю **пару**, которая закрывает лазейку (норма «объёмная величина в
одиночку не выводится», унаследована из `cowork-execution-registry`):

| Метрика | Как сжульничать | Почему не выйдет | Обязательная пара в выводе |
|---|---|---|---|
| `cutAccuracy` | не фиксировать предсказание | `no-cut-forecast`, а не 100% | `blocksCount` |
| | объявить всё «не влезет» и всегда попадать | видно в паре: доля реально переполнившихся | `overflowRate` |
| | резать на один огромный блок | `blocksCount = 1` рядом с долей | `blocksCount` |
| | переписать предсказание после исхода | `predictedAt < observedAt` + append-only | — |
| `falseStopRate` | не останавливаться вовсе | `no-stops-recorded`, а не 0% | `stopsCount` |
| | останавливать только на очевидном | полезность считается по следам, не её словом | `stopsCount` |
| | держать сомнительные остановки открытыми | строка `не разрешены: k` рядом с долей | `unresolvedCount` |
| | подтвердить полезность своей же записью | `changes` — только лента вещдоков окна | — |

Ни одна из двух не требует чужой оценки: обе — чистые функции от следов. И ни одна не спасается
пустотой: пустота даёт **именованное отсутствие**, которое хуже плохого числа, потому что
называет отсутствие корпуса.

## 5. Отбор 5–7 прогонов: правило и почему именно столько

### 5.1 Отбор только НОМИНИРУЕТ

Инструмент производит **снимок номинаций** (`docs/sprint/experience/RUN_NOMINATIONS.md`), а
запись в канон делает человек по слову владельца — норма живого снимка
`docs/cases/registry/NOMINATIONS.md` / `yarn case:generalize`: «Только номинация — в канон запись
делает человек по слову владельца». Инструмент, сам пишущий кейс, ломает норму, поэтому
`nominateRuns` **возвращает данные и не имеет права записи в `docs/cases/**`** — это проверяется
тем, что функция чистая и файлов не пишет вовсе; снимок рендерит отдельный CLI-шаг.

Структура снимка повторяет живую: **`ready` (годны) и `waiting` (повторяемы, но вещдоки не
разрешаются)**, у каждого `waiting` — причина, легальное «нет».

### 5.2 Единица отбора — прогон, а не запись

Потребителей два, и путать их нельзя:

| Потребитель | Что читает | Чему учит |
|---|---|---|
| память персоны | **все** записи рода, включая промахи | собственная ошибка |
| пред-спринтовый фрейм тимлида | **5–7 удачных прогонов** | образец нарезки |

Перед спринтом читают **образец**, а не коллекцию промахов, — поэтому номинируются прогоны,
точные по своей мерке. Промахи из памяти не исчезают: они и так лежат в журнале персоны и
всплывают как незакрытый хвост. Единица отбора — **прогон** (окно спринта), потому что образец
нарезки — это целый план из нескольких блоков, а не одна строка о блоке.

### 5.3 Правило допуска и порядок

Допуск (все условия обязательны, иначе `waiting` с причиной):

1. предсказание зафиксировано **до** работы и (для `cut`) ратифицировано владельцем;
2. исход наблюдаем по следам: `observed` определён, `evidence` **разрешаются**;
3. точность по своей мерке: `cut` — `cutAccuracy = 1` (все блоки совпали);
   `stop` — `falseStopRate ≤ 0.2` `//provisional` (владелец числа не называл);
4. содержательность: `blocksCount ≥ 2` для `cut`, `stopsCount ≥ 2` для `stop` — прогон на одном
   блоке доказывает не правило, а совпадение.

Порядок — лексикографический по ключам, все ключи из следов, никакого LLM и никакого
`Math.random`:

```
1) точность своей мерки          ↓ (у 'stop' — 1 − falseStopRate)
2) содержательность               ↓ (blocksCount / stopsCount)
3) свежесть по данным             ↓ (observedAt из записи, не «сейчас»)
4) id                             ↑ (устойчивый tie-break, полный детерминизм)
```

### 5.4 Почему 5–7, и почему это окно, а не квота

- **Нижняя граница 5.** Один-два прогона читаются как правило, и пред-спринтовый фрейм наследует
  случайность одной удачной нарезки. Пять — множество, в котором видна **повторяемость**
  (`repeatable` — уже вход номинации в живом `case-store`) и разброс по объёму и по профильному
  контексту.
- **Верхняя граница 7.** Это чтение **перед** спринтом, в холодном контексте, и оно конкурирует
  за тот же бюджет, что и сам бриф: проекция памяти уже живёт с бюджетом (гард 25K). Семь
  прогонов с записями и следами — то, что читается целиком, а не просматривается. Восьмой
  выталкивает бриф.
- **Это окно достаточности, а не квота.** Если годных меньше пяти — номинируется меньше, и
  снимок обязан сказать `корпус тонкий: N из 5`. **Добор неточными прогонами до пяти запрещён** —
  это тот же ратифицированный запрет, применённый к отбору: тонкий корпус нельзя выдавать за
  «лучшее», как ноль остановок нельзя выдавать за «чисто».

## 6. Детерминизм

- **Никаких `Date.now()` и `Math.random()`** — ни в метриках, ни в отборе, ни в рендере.
- Время — **параметр**: `now` передаётся вызывающим; вся хронология берётся из данных
  (`predictedAt`, `observedAt`, `stoppedAt`, `resolvedAt`).
- Сортировка стабильна и полностью определена (последний ключ — `id`): тот же вход → тот же
  снимок бит-в-бит.
- Метрики — чистые функции: без сети, без `gh`, без `git` внутри. Сбор `changedLines` — снаружи,
  в тонкой обёртке; в тестах — фикстуры.

## 9. Чего блок сознательно НЕ делает

- **Не пишет кейс в канон** и не трогает `docs/cases/**` — только номинирует.
- Не определяет форму плана нарезки и форму журнала остановок соседей — живёт на стабах
  (`EXPECTATIONS.md`); формы придуманы **односторонне**.
- Не решает расхождение `kind`/`class` как дискриминатора рода в архиве памяти — шов Phase 3.
- Не вшивает эмит в закрытие окна, в `.husky/**`, в ритуалы и в `package.json` — провода это
  адаптеры интеграции.
- Не судит существо продукта и не ставит LGTM: род измеряет **предсказание**, а не работу
  (граница M6: ведение ≠ надзор по существу).
- Не назначает и не выводит исполнителя — участие берётся из ленты вещдоков соседа (M1).
- Не изобретает порог `oversized` и не правит `scripts/lib/day-work-diff.mjs`: значение 400
  импортируется как **дефолт параметра**, файл вне моей зоны и не меняется.
- **Не строит всплытие подсознания** (#1368) и не заводит слот аудитора спринта — названы
  штормом за границей коворка.
- **Пробел, зафиксированный честно:** `COWORK_SPRINT_BRIEF.md` спринта `cowork-honest-sprint` на
  ветке блока отсутствует (в `docs/cowork-sprint/cowork-honest-sprint/` только
  `team-experience-loop/AGENT_PROMPT.md`), поэтому дедлайн интеграции и точная формулировка
  интеграционного smoke мне неизвестны. Файловая зона, BASE_SHA и собственный DoD взяты из
  `AGENT_PROMPT.md`. Заявлено координатору как блокер, обходом не лечится.
