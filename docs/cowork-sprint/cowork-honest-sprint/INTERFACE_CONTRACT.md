## 0. Что изоляция дала бесплатно — три совпадения без сговора

Прежде чем перечислять расхождения, стоит назвать то, что сошлось. Блоки друг друга не читали,
и совпадение здесь — не удача, а признак того, что мерка взята из репозитория, а не выдумана.

| Инвариант | A | B | C | Итог |
|---|---|---|---|---|
| **единица объёма** | изменённые строки = `insertions + deletions`, порог импортом из `day-work-diff.mjs` | объёма не считает вовсе, единица — предмет A | то же, что A, порог импортом, в функцию параметром | **полное совпадение**, включая отказ B заводить вторую меру |
| **владелец времени** | `ratification.at` ставит владелец; ядро — только читатель, `Date.now()` нет | окно и `revisionAt` — план, `at` — след, гейт временем **не владеет** | владелец времени — **данные**, `now` параметром | **полное совпадение**: ни один блок не назначил себя источником времени |
| **пустой корпус** | «нечитаемо» отдаётся вердиктом, не пустотой | `no_corpus` на каждый блок, строки «нарушений 0» нет никогда | `defined:false` + причина; рядом не печатается ни одна цифра | **полное совпадение** — ратифицированный M5 понят одинаково |

Три блока независимо запретили себе одно и то же. Это и есть та концептуальная чистота, ради
которой формат держит изоляцию.

## 1. Шов A→B: план нарезки → гейт исполнения

**Направление одностороннее.** Гейт в план не пишет: иначе судил бы собственный вход (позиция B,
принята).

### Согласованная форма (`NormalizedPlan` на входе гейта)

```
{ sprintId, taskId, mode, cutBy, ratification: { by, at, digest },
  window: { from, to },            // ДОБАВЛЯЕТСЯ — см. G1
  blocks: [ { blockId, persona, context, zone[], estimate: { changedLines },
              passes?: [ { passId, seam, estimateChangedLines } ],   // ратификация №4
              revisionAt,          // ДОБАВЛЯЕТСЯ — см. G1
              unassignedReason? } ] }
```

Поставщик — `assignedBlocks(plan)` блока A, расширенный `window`/`revisionAt`. Читатель — `readPlan()`
блока B, единственное место, где форма плана известна.

### Расхождения и их разрешение

| # | Расхождение | Решение контракта |
|---|---|---|
| **G1** | **План не несёт `window {from,to}` и `revisionAt`.** B требует оба и, при отсутствии, обязан отдать ошибку входа — считать «всё свежее» значило бы тихо разрешить перенос согласия на изменённый контракт (запрет M2) | Поведение B **правильное и остаётся**. Поля добавляются в схему плана: адаптер их **не изобретает**. Окно — полуинтервал `[from, to)`, ISO-8601 UTC; `revisionAt` монотонно неубывающая. Без них гейт честно молчит |
| **G2** | Литералы режима: A даёт `explicit-honest` / **`membrana-flow`**, B ждёт `explicit_honest` / `no_personal_responsibility` | **Слово владельца выигрывает:** канон — `explicit-honest` · `membrana-flow`. Нормализатор литералов в адаптере, односторонне в сторону A. Молчание = `explicit-honest` (согласовано обоими) |
| **G3** | Причина отказа: A — `unassignedReason` на блоке, B — `reason` | Канон — `unassignedReason` (дом поля у автора плана). Переименование в адаптере |
| **G4** | Ключ документа: A — `sprintId`, B — `planId` | Канон — `sprintId`; `planId` в `NormalizedPlan` = `sprintId` |
| **G5** | A разводит **`persona`** и **`context`** в два поля; B знает только `assigned` | **Ограничение v1 названо честно:** в текущем шве `context` обязан **равняться** `persona`. Гейт сверяет след с одним идентификатором, и различать «чей профиль» он не умеет. План, где они различаются, из области текущего гейта **выходит** — это вопрос владельцу (см. §6), а не адаптер. Два поля в плане **сохраняются**: они несут смысл и понадобятся, когда гейт научится сверять род `context_run` с `context`, а остальные три — с `persona` |
| **G6** | `ratified` | Адаптер зовёт `planRatified(plan)` блока A — предикат, а не поле. Дайджест сохраняет силу: правка тела после согласия сбрасывает ратификацию, и гейт видит `ratified: false` → вердиктов не выносит вовсе |

## 2. Шов A→C: план нарезки → петля опыта

### Согласованная форма (вход `computeCutAccuracy`)

```
{ sprintId, authorPersonaId, ratifiedBy: 'owner' | { none: причина }, predictedAt,
  blocks: [ { blockId, contextPersonaId, claim: 'fits' | 'does-not-fit',
              predictedChangedLines, threshold } ] }
```

| # | Расхождение | Решение контракта |
|---|---|---|
| **G7** | C ждёт `claim: 'fits' \| 'does-not-fit'` (перечисление), A даёт `estimate.changedLines` (число) | Число богаче; адаптер вычисляет `claim` **тем же предикатом**, что импортируют оба: `isSegmentOversized(estimate.changedLines) ? 'does-not-fit' : 'fits'`. Расхождение исключено конструкцией — предикат один, и оба его уже импортируют |
| **G8** | C ждёт `createdAt` как свой `predictedAt`; A такого поля не отдаёт | Канон: **`predictedAt = ratification.at`.** Предсказание становится обязывающим **в момент ратификации**, а не черновика: неретифицированный набросок предсказанием не является. Решение усиливает обе стороны и совпадает с правилом C «нератифицированный план в мерку не входит» |
| **G9** | Имя ключа блока: A — `blockId`, C — `cutBlockId` | Канон — **`blockId`** (дом поля у автора плана). Довод C принят **в глоссарий**, а не в имя: омоним «блок нарезки ≠ блок коворка» снимается §4, где слово «блок» определено однозначно |
| **G10** | C предположил `authorPersonaId: 'tarasov'` | **Предположение C верно, а бриф координатора врал.** Реестр голосов: `tarasov` — `kind: teamlead` (слово капитана 27.07), `vesnin` — `kind: architect`, «не тимлид с 27.07». В брифе и в таблице ролей ACTIVE стояло «Тимлид (Веснин)» — **ошибка координатора**, исправляется. Блок, читавший реестр, оказался прав против координатора, читавшего свою память |

## 3. Шов B→C: вердикт исполнения → петля опыта. **ЧАСТИЧНО НЕСВОДИМ**

### Что сводится

| Что | Форма | Статус |
|---|---|---|
| вердикт исполнения по блоку | `GateReport.blocks[{ blockId, personaId, verdict, evidenceRefs, reason, stopped }]` | **сходится** — C принимает признак `stopped` и не вправе его переопределять (условие B, принято) |
| дисквалификации и ошибки входа | `disqualified[]`, `inputErrors[]` | **сходится** — введены B в Phase 2 именно чтобы C отличал остановку по дисквалификации от остановки по отсутствию следа |
| знаменатели | `corpusSize`, `checkedBlocks` | **сходится**; хвост B (общее число отвергнутых записей принадлежит ленте) переходит в §6 |

### Что НЕ сводится: три входа C без производителя

| # | Вход C | Кого C считал производителем | Что ответил производитель |
|---|---|---|---|
| **N1** | привязка сегментов ревью к блоку + `changedLines` | `execution-gate` | **B отказывается по существу:** «гейт объёма не считает и в него не заглядывает; две независимых меры объёма в одном контуре — гарантированное расхождение». Отказ **правильный**. При этом того же самого ждёт от B и блок A (`actualChangedLines(blockId)`) |
| **N2** | **журнал остановок ведущей** | `execution-gate` | B производит **остановки гейта** — другую сущность. Слово «остановка» столкнулось: `gateStop` (класс вердикта) ≠ `leadStop` (процедурный стоп Ангелины). Носителя `leadStop` не существует |
| **N3** | лента вещдоков окна + признак «окно без ведения» | `execution-gate` | **B считает ленту своим ВХОДОМ, не собственностью:** «лента — вход гейта, а не его собственность». То есть ленты не имеет никто: M4 назвал дом, носителя в репозитории нет |

### Корень: дефект резки, а не спор блоков

Я нарезал A/B/C **по моментам** — до работы, по ходу, после. Но **носители** (лента вещдоков,
журнал остановок ведущей, привязка сегмента ревью к блоку) не были назначены никому: я молча
предполагал, что их возьмёт B. B отказался — и отказался **по существу**, а не из лени: владеть
своим входом значит судить свой вход, а считать вторую меру объёма значит гарантировать
расхождение на шве.

**Ни один блок не виноват.** Это второй дефект моей нарезки за день, и он крупнее первого:
переполнение объёма было промахом оценки, а это — **пропущенная ответственность**.

### Разрешение, позволяющее интеграции идти без лжи

Формат запрещает лечить это адаптером-догадкой. Но останавливать интеграцию не нужно, потому что
**C уже умеет честно не знать**: его алфавит причин отсутствия покрывает ровно эти три случая.

| Вход | Поведение на интеграции | Что печатается |
|---|---|---|
| N1 отсутствует | `cutAccuracy` не определена | `no-attribution` — «привязки нет», не ноль |
| N2 отсутствует | `falseStopRate` не определена | `no-stops-recorded` — «остановок не записано», не «ложных нет» |
| N3 отсутствует | полезность остановки невычислима | `no-lead-appointed` / отсутствие ленты названо причиной |

Интеграция собирается, smoke зелёный, **и ни одна метрика не врёт**. Отсутствие носителя
проявляется как честное «не определено» вместо выдуманного процента. Это и есть проверка того,
что блоки построены правильно: **дырка в резке не превратилась в ложную цифру.**

**Эскалация владельцу (S-C2) — §6, вопрос 1.** Достраивать носители четвёртым компонентом или
сузить петлю опыта до одной метрики — решение владельца, не команд и не координатора.

## 4. Глоссарий стыка — термин есть граница

| Термин | Значение в контракте | Чем НЕ является |
|---|---|---|
| **блок** | блок **нарезки** внутри окна спринта, ключ `blockId` | не блок коворка (`cut-contract`/`execution-gate`/`experience-loop`) — те называются полным словом «блок коворка» |
| **проход** | единица применения порога 400 (ратификация владельца №4): фундаментный блок легально едет N проходами по названным швам | не «часть блока, которую удобно читать»: швы объявляются в плане до работы и ратифицируются |
| **персона** | `personaId` из `docs/virtual-team/voices.registry.json` — единственный носитель, где «объявленный обязан быть вызываемым» проверяется машиной | не человеческое имя, не модель, не `Co-Authored-By` (одинаков у всех агентов — различающей силы ноль), не `sessionId` |
| **контекст** | профильный контекст, через который идёт блок; отдельное поле плана | не синоним персоны, хотя в v1 шва обязан ей равняться (G5) |
| **назначен / участвовал** | две стороны честной пары; на швах употребляются **только** с уточнением | слово «исполнитель» без уточнения на швах **запрещено** — заседание развело их прямо, склейка вернёт болезнь |
| **`gateStop`** | класс вердикта `execution-gate`: проверка сказала «ответственность подтвердить нельзя» | не процедурная остановка ведущей |
| **`leadStop`** | процедурный стоп ведущей на этапе спринта; предмет метрики «доля ложных остановок» | не вердикт гейта. **Носителя сегодня не существует** (N2) |
| **лента вещдоков окна** | вход контура, адресуемые записи актов | не собственность гейта и не собственность петли опыта |
| **прогноз объёма** | `estimate.changedLines` на проход, единица — `insertions + deletions` | не файлы, не коммиты, не токены, не story points |
| **`//provisional`** | значение, которого владелец не называл | не «пока не сделали» |

## 5. Интеграционный smoke — один сценарий через все швы

Уточняет набросок брифа по итогам консилиума. Зелёный означает «данные прошли швы», а не
«механизм честен» — честность проверяют зубы блоков.

| # | Шаг | Ожидание |
|---|---|---|
| 1 | Ратифицированный план из двух блоков: первый влезает в проход, второй переполнен | `cutVerdict = findings`, находка `block_oversized` **на проходе**, адрес и причина названы |
| 2 | Тот же план **без** `window`/`revisionAt` → в гейт | **ошибка входа**, код `2`, вердиктов ноль. Гейт не считает «всё свежее» |
| 3 | План с полями окна и ревизии + лента из одного следа: у второго блока вещдока нет | `honest_pair` + **`plan_lied`**, код `1`, `stopped = true` у второго |
| 4 | Пустая лента при том же плане | `no_corpus` на **оба** блока, код `1`, строки «нарушений 0` в отчёте **нет** |
| 5 | Выход шага 3 → петля опыта, привязки сегментов ревью **нет** (N1) | `cutAccuracy` = `defined:false`, причина `no-attribution`; **ни одного процента в выводе** |
| 6 | Журнала остановок ведущей нет (N2) | `falseStopRate` = `defined:false`, причина `no-stops-recorded`; не «ложных нет» |
| 7 | Номинация прогона при отсутствующих метриках | прогон **не** номинируется как образцовый; корпус честно `thin: «корпус тонкий: 0 из 5»`, добора нет |

**Шаги 5–7 — главные.** Они проверяют не работу, а **отказ врать при дырке в резке**.

## 7. Список адаптеров — что пишется на интеграции

Блоки **не переписываются**. Несогласованность гасится адаптерами на швах; стабы в интеграционную
ветку не мёржатся, стаб, доживший до прода, — дефект интеграции.

| # | Адаптер | Предмет | Шов |
|---|---|---|---|
| 1 | `plan→gate` | переименования `sprintId→planId`, `unassignedReason→reason`; нормализатор литералов режима в сторону слова владельца; `ratified` через `planRatified()`; **проброс** `window`/`revisionAt` без подстановки значений | A→B |
| 2 | `plan→forecast` | `claim` из числа **общим предикатом** `isSegmentOversized`; `predictedAt = ratification.at`; `blockId` без переименования | A→C |
| 3 | `gateReport→forecast` | вердикт, `stopped`, `disqualified`, `inputErrors`, знаменатели — сквозняком; **объём НЕ трогается** (отказ B уважается) | B→C |
| 4 | схема плана: `window`, `revisionAt`, `passes[]` | расширение формы, не переписывание блока | A |
| 5 | **носители N1–N3** | **не пишется до решения владельца** (§6.1). До тех пор отсутствие проявляется честными причинами C | — |

**Метрика качества резки — в `RETROSPECTIVE.md`:** блоков переписано **0**; стыков адаптировано
**3**; расширений схемы **1**; **дырок резки — 1 крупная (N1–N3, пропущенная ответственность за
носители)** и **1 промах оценки объёма 3/3**. Обе — авторства координатора, не блоков.
