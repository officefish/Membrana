## 1. Что здесь строится и против чего

Заседание построило **сертификацию**: персона умеет заверить блок профильным взглядом.
Оно не построило **нарезку** — акт «разделить работу и назвать, чей это контекст»
отсутствует во всех десяти вердиктах. Следствие названо в шторме прямо: пока нарезки нет,
участие персоны — подпись под тем, что сессия сделала бы и так.

Блок `cut-contract` строит **один предмет**: документ нарезки, который можно проверить
машиной **до** начала работы, и предикат, который выносит по нему findings.

Отрицательное определение важнее положительного. Блок **не** строит:
ленту вещдоков исполнения, акты персоны, память об исходах, панель, автонарезку.
Нарезку делает **тимлид** (слово владельца: он не программирует, но определяет, чей это
контекст и какой у блока объём). Здесь строится не резчик, а **форма его решения и зуб на неё**.

Смысл границы: если бы блок сам предлагал нарезку, он немедленно стал бы органом,
который сам себя и проверяет, — тот самый класс дефекта, из-за которого заседание
запретило исполнителю формулировать критерий сделанного.

## 2. Форма плана

**План нарезки — отдельный машиночитаемый документ, не поле в карточке.**

Решение принято против двух альтернатив, и обе отвергнуты по вещдоку:

- *«поле в `docs/tasks/registry.json`»* — заседание отвергло дом-в-карточке прямым
  вердиктом: «карточка ≠ окно, а поле ответственного уже врало». 214 карточек несут
  `leadPersona`, гейт проверяет ровно непустоту, проверка проходит в 100 % случаев.
  Складывать туда ещё и нарезку — расширять ту же ложь.
- *«markdown-чеклист в промпте задачи»* — акт ратификации перестаёт быть предикатом:
  «ратифицирован» пришлось бы искать глазами в прозе.

Плюс запрет самого коворка: общие корневые файлы в изолированной фазе не трогает никто.
План живёт **в моей зоне**: `docs/sprint/cut/<sprintId>.json` (имя и путь — `//provisional`,
владелец их не называл).

Форма — JSON, а не YAML/frontmatter: детерминированная канонизация нужна для дайджеста
ратификации (§5), а у markdown-обёртки её нет. Прецедент в дереве — `morning-gates-state.json`,
`docs/virtual-team/voices.registry.json`, тарифная сетка.

### Скелет (имена полей — `//provisional`, семантика — из вердиктов и шторма)

```jsonc
{
  "schema": "sprint-cut/1",              //provisional
  "sprintId": "…",
  "taskId": "…",                          // ссылка на карточку реестра, НЕ валидируется здесь (§8)
  "mode": "explicit-honest",              // закрытый выбор из двух, вердикт M8; молчание не режим
  "cutBy": "tarasov",                     // режет тимлид (слово владельца)
  "ratification": { "by": "owner", "at": "2026-07-30T12:00:00+03:00", "digest": "<sha256>" },
  "blocks": [
    {
      "blockId": "mfcc-window",           // человекочитаемый слаг, уникален в плане
      "persona": "kuryokhin",             // id из реестра голосов — кто ответственный
      "context": "kuryokhin",             // id из реестра голосов — ЧЕРЕЗ КАКОЙ контекст идёт блок
      "zone": ["packages/detection-*/src/mfcc/**"],
      "estimate": { "changedLines": 180 } // прогноз тимлида, единица — изменённые строки
    }
  ]
}
```

## 3. Откуда берутся поля — у каждого назван автор

Поле без названного автора — это поле, которое потом заполнит кто угодно, и мы получим
второй `leadPersona`. Поэтому автор — часть определения поля, а не комментарий к нему.

| Поле | Автор (кто вправе записать) | Источник значения |
|---|---|---|
| `sprintId`, `taskId` | тимлид при нарезке | id спринта / карточки реестра |
| `mode` | **только капитан**, до старта и до назначения (вердикт M8) | закрытый список из двух |
| `cutBy` | тимлид (сам за себя) | id из реестра голосов |
| `blockId` | тимлид | слаг, придуман при резке |
| `persona` | тимлид | **закрытый список** — `id` из `docs/virtual-team/voices.registry.json` |
| `context` | тимлид | тот же закрытый список |
| `zone` | тимлид | пути/глобы репозитория |
| `estimate.changedLines` | тимлид | его прогноз объёма |
| `ratification` | **только владелец** (аудит нарезки уходит ему в ратификацию) | его слово + дайджест плана |

**Персона и контекст — два разных поля, и совпадение не подразумевается молча.**
Владелец назвал в чеклисте оба: «кто ответственный **и** через какой контекст». Обычно это
один и тот же id, и тогда он **пишется дважды явно**. Пустой `context`, «унаследованный» от
`persona`, был бы выведенным значением — ровно тот класс, который заседание запретило
(«выводить участие из реестра задач и из зон кода запрещено»). Различие несёт и смысл:
персона — **держатель контракта**, контекст — **профильный взгляд, которым блок заверяется**;
это разные акты, и они разъезжаются, как только блок ведёт один, а заверяет другой.

**Идентификатор персоны — `id` реестра голосов, не человеческое имя и не имя модели.**
Вещдок необходимости: в живом реестре задач встречается `leadPersona: "musician"`, тогда как
id голоса — `kuryokhin`; поле не валидируется, поэтому расходится молча. Зуб резолвит
`persona`/`context`/`cutBy` по реестру и даёт находку на любой id вне него.

## 4. Компактность — считается чужой меркой, намеренно

**Единица объёма — изменённые строки** (`insertions + deletions`), та же, которой считает
`changedLinesFromShortstat` в `scripts/lib/day-work-diff.mjs`.

Порог **импортируется**: `OVERSIZED_CHANGED_LINES` из того же модуля. Число 400 у себя не
переобъявляется — иначе порог начнёт расходиться с ревью молча, и мы получим план, который
«влез» по своей мерке и «oversized» по ревьюшной.

Больше того: импортируется не только константа, но и **предикат** `isSegmentOversized`.
Причина конкретная — граница строгая (`> 400`, не `>= 400`). Скопировать число и написать
своё сравнение значит оставить возможность разъехаться на единицу и получить блок ровно в
400 строк, который у меня зелёный, а у ревью красный. Одна мерка — значит один носитель
мерки.

Смысл переноса, слово владельца: мерка уже работает, но **задним числом, как жалоба** —
ревью печатает «oversized» после того, как работа сделана. Здесь та же цифра становится
**условием до работы**. Одно число, другой момент.

**Переполнение — не сбой, а управленческое решение.** Поэтому находка `block_oversized`
несёт адрес (`blockId`) и цифры «прогноз против порога», а не совет «разрежьте мельче»:
тихая перерезка исполнителем и молчаливое разрастание запрещены, решение принимает тимлид,
извещая владельца.

Прогноз и факт **обязаны быть в одной единице** — иначе бинарный сигнал обучения тимлида
(«влез / переполнился») теряет смысл: сравнивать нечего.

## 5. «Ратифицирован» — предикат, а не отметка

Неретифицированный план — не план. Значит «ратифицирован» обязано быть проверяемым, и
проверка обязана **портиться при правке плана после согласия**.

```
planRatified(plan) ⟺ ratification.by === 'owner'
                   ∧ ratification.digest === sha256(canonicalBody(plan))
                   ∧ ratification.at — валидный ISO-8601 со смещением
```

`canonicalBody(plan)` — канонизация плана **без** самого узла `ratification` (иначе дайджест
ссылался бы на себя). Алгоритм и правила канонизации — `//provisional`.

Почему дайджест, а не булев `ownerRatified: true`:

1. **Прецедент в дереве.** Утренние гейты держат владельцевы согласия ровно так:
   `frozenDigest` на снимок топ-3 и `draftDigest` + `ownerAck` на черновик ласточки.
   Подмена снимка закрывает гейт (`morning-gates.mjs`). Форма не изобретается — берётся.
2. **Вердикт заседания прямой:** «перенос согласия на изменённый контракт запрещён».
   Булев флаг переносится сам собой: правишь блоки — флаг остаётся `true`. Дайджест — нет.
3. Ратификация владельца — согласие **на конкретный текст**, а не на имя документа.

`ratification.by` — закрытый список из одного значения: `owner`. План, «ратифицированный»
тимлидом, не ратифицирован: аудит нарезки уходит владельцу, самоаудита ни у кого не возникает.

## 6. Владелец времени

Каждая метка «когда» имеет **ровно одного** писателя, и он назван в определении поля.

- `ratification.at` — акт **владельца**; записывает тот, кто фиксирует его слово в файл.
  **Зуб не пишет `at` никогда** и не подставляет `now()` вместо отсутствующего.
- Времена вещдоков исполнения — не моё поле; их владелец у соседа (§ EXPECTATIONS).

Правило, из которого это вытекает: **читатель времени не бывает его источником.** Если зуб
подставит текущее время «по умолчанию», отсутствие ратификации станет неотличимо от
ратификации, а гейт — зелёным на пустоте. Практическое следствие: в чистом ядре нет
`Date.now()`; день/время подаются снаружи — как `today` в `morning-gates.mjs`.

## 7. Findings — почему ровно шесть

Findings названы координатором в мастер-промпте; здесь — почему набор полон и почему в нём нет
седьмого. Каждая находка = один способ для документа **перестать быть контрактом**:

| # | `toothId` (`//provisional`) | Смысл | Почему без неё нельзя |
|---|---|---|---|
| 1 | `cut_shape` | документ не читается как план | без проверки формы остальные пять сообщают чепуху на мусоре или падают; падение в цепочке = молчаливая зелёнка |
| 2 | `block_oversized` | прогноз выше порога одной проверки ревью | это и есть перенос мерки «до работы» — предмет блока |
| 3 | `performer_unnamed` | нет персоны или id вне реестра | план не говорит, чей блок; «непустота поля» уже показала, что мало проверять непустоту |
| 4 | `context_unnamed` | не сказано, через какой контекст идёт блок | ровно та функция, которой нет во всех десяти вердиктах; без адреса контекста сертификации некуда встать |
| 5 | `zones_overlap` | два блока пишут в один путь | тогда это не нарезка: параллельная работа коллизит (прецедент 2026-07-09 — чужая сессия увела ветку) |
| 6 | `plan_unratified` | нет отметки владельца или дайджест разъехался | неретифицированный план — не план |

Набор читается как **1 + 4 + 1**: одна находка на читаемость документа, по одной на каждое
несущее поле блока (объём · исполнитель · контекст · зона) и одна на легитимность плана целиком.
Пятого несущего поля у блока нет — поэтому набор закрыт.

Форма находки берётся из дерева, а не сочиняется: `{ toothId, where, reason }` — как в
`scripts/lib/tariff-grid-check.mjs` (норма M7 тарифного заседания). `where` — адрес
(`blocks.<blockId>.<field>`), `reason` — человеческая причина. Имя, адрес, причина: находка
без адреса заставляет читателя искать, а находка без причины — угадывать.

**Вердикт из закрытого списка** (литералы — `//provisional`):
`contract` — находок нет · `findings` — есть хотя бы одна · `unreadable` — сломана форма,
остальные проверки не выполнялись. Третий вердикт существует, чтобы «ноль находок» на нечитаемом
документе не выглядело зелёным: это ложный зелёный того же класса, что «нарушений 0» на нуле
предметов — вещдок есть, машинный аудит заседания выдал его в тот же день.

**Отказ — легальный, но с причиной.** Пустое поле и отказ — разные вещи.
`mode: "no-personal-responsibility"` (вторая дверь, вердикт M8) разрешает `persona: null`,
но **только** вместе с причиной из закрытого списка; отчёт по такому блоку даёт «не применимо»,
а не «пройдено». Молчание режимом не является: план без `mode` читается как `explicit-honest`,
и там пустая персона — находка. Закрытый список причин — `//provisional`, владелец его не называл.

## 8. Что сознательно НЕ проверяется

Названо явно, чтобы отсутствие не читалось как забывчивость:

- **`taskId` не резолвится в `docs/tasks/registry.json`.** Реестр — общий корневой файл,
  изолированная фаза его не трогает; кросс-файловая сшивка — работа интеграции.
- **Не проверяется, что `zone` существует в дереве.** План пишется до работы: каталогов
  ещё нет, и «зона не найдена» была бы ложной находкой по построению.
- **Не проверяется разделение резчика и исполнителя** (`cutBy` ≠ `persona`). Идея грунтована
  вердиктом («критерий формулирует не исполнитель»), но седьмую находку в DoD никто не
  называл; ввожу её только по слову владельца или координатора. Записана как открытый вопрос,
  не как тихий пропуск.
- **Не проверяется качество нарезки** — только её форма и легитимность. Судить, удачно ли
  разрезано, — акт владельца при ратификации и петля обучения тимлида; ни то, ни другое в
  этом блоке не строится.

## 9. Свой DoD и как он проверяется без соседей

`node scripts/sprint-cut-check.mjs --plan <fixture>` — зелёный на валидной фикстуре, красный
на каждой из шести кривых (по одной фикстуре на находку, `docs/sprint/cut/fixtures/**`).

Чистое ядро (`scripts/lib/sprint-cut/**`) — предикаты от значения: без `fs`, без сети, без
часов; ФС и вывод — в CLI. Реестр голосов подаётся в ядро как значение (CLI читает файл,
тесты — фикстуру), поэтому тесты детерминированы и не зависят от живого реестра.

Тест — `scripts/sprint-cut-check.test.mjs`: он в корневом прогоне. Тест внутри пакета с узким
`include` не побежит — грабля из `AGENTS.md`, и мёртвый зуб хуже отсутствующего.

## 10. Открытые вопросы (не решать за владельца)

1. Путь и имя документа плана (`docs/sprint/cut/<sprintId>.json`) — `//provisional`.
2. Закрытый список причин для второй двери — `//provisional`.
3. Седьмая находка «резчик ≠ исполнитель» — вводить ли (§8).
4. Один план на спринт или один на задачу-этап — принято «на спринт», `//provisional`.
5. Кто физически записывает `ratification` со слов владельца: ведущая или тимлид. Владелец
   времени назван (владелец), писатель файла — нет.
