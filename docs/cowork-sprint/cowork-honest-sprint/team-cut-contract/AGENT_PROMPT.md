## Что строит блок

**Нарезка как контракт до работы.** План спринта машиночитаем: список блоков, у каждого —
исполнитель (персона), **через какой контекст** он идёт, файловая зона, оценка объёма. План
**ратифицируется владельцем**; неретифицированный план — не план.

**Зачем это существует.** Заседание `sprint-honest-performers` построило сертификацию (персона
умеет заверить блок профильным взглядом) и **не построило нарезку**: акт «разделить работу и
назвать, чей это контекст» отсутствует во всех десяти вердиктах. Пока нарезки нет, участие
персоны — подпись под тем, что сессия сделала бы и так.

Общие корневые файлы (`package.json`, `docs/tasks/registry.json`, `AGENTS.md`, `docs/HANDOFF.md`)
**не трогать** — провода вносятся на интеграции. В фазе 2 запускайся через `node scripts/...`,
а не через `yarn`.

## Hard rules

- **НЕ читать** ветки `cowork/cowork-honest-sprint/execution-gate` и `…/experience-loop`, их
  `EXPECTATIONS.md` и их файлы. Никаких интерфейсных договорённостей до Phase 3.
- Об интерфейсах думать **односторонне**: веди `EXPECTATIONS.md` (что хочу от соседей / что готов
  отдать) и строй **исполняемые стабы** соседей строго в своей зоне.
- **Мерку компактности НЕ изобретать.** Блок обязан помещаться в одну проверку код-ревью;
  константа `OVERSIZED_CHANGED_LINES` **импортируется** из `scripts/lib/day-work-diff.mjs`.
  Переобъявить число 400 у себя — дефект: тогда порог начнёт расходиться с ревью молча.
  Чтение существующего кода репозитория изоляцию не нарушает.
- **Только предикаты, никаких «стараться».** Вердикт из закрытого списка, finding с именем
  (`toothId`), отказ — легальным «нет с причиной», а не пустым полем.
- Значение, которого владелец не называл, помечается `//provisional` и решением не считается.
- Тест ставить в `scripts/*.test.mjs` — он в корневом прогоне. Тест внутри пакета с узким
  `include` **не побежит** (грабли в `AGENTS.md`).
- Коммиты — поимённо, `git add -A` не использовать.

## Собственный DoD (проверяется без соседей, на стабах)

`node scripts/sprint-cut-check.mjs --plan <fixture>` выносит **именованные** findings:

| finding | когда |
|---|---|
| shape | план не той формы |
| блок переполнен | оценка объёма выше порога одной проверки ревью |
| исполнитель не назван | у блока нет персоны |
| контекст не назван | не сказано, через какой профильный контекст идёт блок |
| зоны блоков пересекаются | два блока пишут в один путь |
| план не ратифицирован | нет отметки владельца |

Зелёный на валидной фикстуре, **красный на каждой из шести кривых** — по одной фикстуре на
finding. Тесты проходят без кода соседей.

## Phase 1 — что сдать

   **идентификатор блока**, **идентификатор персоны**, **владелец времени** (кто ставит «когда»).

точке интеграции.
