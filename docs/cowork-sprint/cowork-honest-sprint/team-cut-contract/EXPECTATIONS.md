## Инварианты, которые называю явно

Эти четыре — предмет стыка. Если сосед понимает их иначе, два «зелёных» блока дадут мусор
на шве, и это не увидит ни один локальный тест.

| Инвариант | Моё значение | Почему так |
|---|---|---|
| **Единица объёма** | **изменённые строки** = `insertions + deletions`, как считает `changedLinesFromShortstat` в `scripts/lib/day-work-diff.mjs`. Порог — импортируемый `OVERSIZED_CHANGED_LINES` (и предикат `isSegmentOversized`, чтобы не разъехалась строгость границы) | одна мерка на прогноз и на факт; иначе бинарный сигнал «влез / переполнился» не вычисляется. Файлы, коммиты, часы, story points единицей **не** являются |
| **Идентификатор блока** | `blockId` — человекочитаемый слаг, уникален внутри плана, **стабилен после ратификации**. Он же — ключ соединения с вещдоками исполнения | индекс в массиве или порядковый номер сдвигается при перерезке и молча переадресует чужие ссылки. Переименование `blockId` = новая версия плана и новая ратификация, не правка |
| **Идентификатор персоны** | `id` из `docs/virtual-team/voices.registry.json` (`tarasov`, `vesnin`, `ozhegov`, `dynin`, `kuryokhin`, `rodchenko`, `angelina`, `farrell`). **Не** человеческое имя, **не** имя модели, **не** роль-синоним | вещдок расхождения: в реестре задач живёт `leadPersona: "musician"`, тогда как id голоса — `kuryokhin`; поле не валидируется и расходится молча. `persona` и `context` — два отдельных поля из этого же списка, совпадение пишется явно, не подразумевается |
| **Владелец времени** | `ratification.at` ставит **владелец** (его акт), ISO-8601 со смещением, ровно один писатель. Мой зуб — **только читатель** времени: `Date.now()` в ядре нет, отсутствующее время не подставляется. Времена вещдоков исполнения — **не мои**, их владелец у соседа | «читатель времени не бывает его источником»: подстановка `now()` делает отсутствие ратификации неотличимым от ратификации — гейт зеленеет на пустоте |

## Что мне нужно от соседей

| От блока | Что | Форма (сигнатура/схема) | Инварианты (единицы, частоты, порядок, владелец времени) |
|---|---|---|---|
| `execution-gate` | **Чтение** факта участия по блоку: состоялся ли прогон и кто держатель | читатель, а не запись: `actsForBlock(blockId) → readonly Act[]`, где `Act = { blockId, personaId, kind, at, evidenceRef }`. Форма — `//provisional`, важна не подпись, а наличие читателя по `blockId` | ключ соединения — **мой `blockId`**, персона — **id реестра голосов**; `at` ставит автор акта, я его только читаю; порядок актов — по `at` возрастающе; пустой ответ = «вещдоков нет», а **не** «чисто» |
| `execution-gate` | **Фактический объём** блока по завершении: сколько изменённых строк вышло | `actualChangedLines(blockId) → number \| null` | **та же единица**, что мой прогноз (`insertions + deletions`). Иная единица делает сравнение «нарезка ↔ результат» невычислимым. `null` = «факта нет», не ноль |
| `execution-gate` | Признание моего плана источником стороны **«назначен»** — гейт не выводит назначение из карточки реестра и не заводит своё скалярное поле «исполнитель» | ссылка на `blockId` + `sprintId` моего плана | заседание запретило выводить участие из реестра задач и из зон кода; скалярного поля «исполнитель» не существует |
| `experience-loop` | Приёмник **записи о собственном предсказании и его исходе** (четвёртый род записи по шторму): прогноз тимлида против факта | я отдаю значение, он владеет записью в память: `{ sprintId, blockId, personaId, predictedChangedLines, actualChangedLines, fit: 'fitted' \| 'overflowed', threshold }` — имена `//provisional` | сигнал **бинарен**: влез либо переполнился; порог в записи назван числом, чтобы запись осталась читаемой после смены порога; время исхода — не моё, ставит владелец записи |
| `experience-loop` | Согласие, что 5–7 лучших прогонов читаются **перед** нарезкой, а не после | не требует моего кода в Phase 2 | у механики всплытия появился названный потребитель — пред-спринтовый фрейм тимлида; здесь только фиксирую ожидание |
| оба | Единый глоссарий стыка: **блок · персона · контекст · зона · прогноз объёма** | таблица терминов в `INTERFACE_CONTRACT.md` (Phase 3) | «исполнитель» на швах не употребляется без уточнения `назначен` / `участвовал` — заседание развело их прямо, и склейка обратно вернёт болезнь |

**Чего я от соседей НЕ хочу** (называю, чтобы не получить на интеграции):

- никто не пишет в мой план — ни строки, ни отметки; ратификация принадлежит владельцу;
- никто не выводит `persona`/`context` из зон кода, авторства коммитов или карточки реестра;
- никто не подставляет свой порог компактности: носитель мерки один — `day-work-diff.mjs`.

## Что изменилось в форме против Phase 1 (соседям важно)

1. **Литерал второй двери — `membrana-flow`**, не `no-personal-responsibility` (как стояло в
   CONCEPT §7). Взято слово владельца из `OWNER_ANSWERS.md` §2. Закрытый список режимов:
   `explicit-honest` · `membrana-flow`. Молчание режимом не является: план без `mode` читается
   как `explicit-honest`, и там пустая персона — находка (тест на это есть).
2. **Причина отказа живёт в блоке**, поле `unassignedReason` (`//provisional` — владелец назвал
   состав списка, но не имя поля). В `membrana-flow` легальный отказ покрывает **оба** поля:
   `persona: null` и `context: null` — заверять некому, поэтому отчёт по блоку даёт «не применимо».
   Отказ без причины из четвёрки = находка `performer_unnamed`, не молчаливая зелёнка.
3. **`cutFindings(plan, { voices })`: `voices` — массив id** (`readonly string[]`), не объект
   реестра. CLI читает файл и отдаёт значение (`voiceIdsFrom`), ядро файлов не касается.
   **Реестр не подан → вердикт `unreadable`** с находкой `cut_shape` по адресу `(вход)`:
   проверить принадлежность id нечем, и это не повод зеленеть.
4. **Плохой `cutBy` — это `cut_shape`, а не седьмая находка.** Список зубов остался закрытым
   на шести: id резчика вне реестра — дефект формы документа, а не отдельный род болезни.
   Седьмая находка «резчик ≠ исполнитель» по-прежнему не построена (жду слова).
5. **Коды возврата CLI перестали быть `//provisional`:** `0` — `contract`; `1` — `findings`
   **и** `unreadable` (оба красные); `2` — инструментальная ошибка (файла нет, JSON битый,
   ратификация не записана). Вердикт печатается всегда.
6. **`ratification.at` требует смещения**: ISO-8601 без зоны отвергается (`2026-07-30T12:00:00` —
   не момент, а намёк). Часов в ядре нет; `ratifyPlan` без `at` отказывает **с причиной**.
7. **Предел зуба зон назван честно:** пересечение считается по литеральному префиксу глоба до
   первого `*` (равенство и вложение посегментно). `{a,b}` и `..` не раскрываются — это
   признанный предел, а не обещание полноты. Ловится реальный класс: `scripts/lib/x/**` против
   `scripts/lib/x/stubs/**`.
8. **`assignedBlocks` отдаёт и `mode`/`unassignedReason`** — иначе `execution-gate` не отличит
   «персона не названа» от «отказ по причине `no_profile_owner`» и потребует след с того, с кого
   спрашивать нечего.

## Что подтверждено кодом (а не обещано)

- порог **импортирован**: `OVERSIZED_CHANGED_LINES` + `isSegmentOversized` из
  `scripts/lib/day-work-diff.mjs`; тест грепает мой же исходник на переобъявление `400` и
  проверяет строгость границы (400 влезает, 401 нет);
- ядро чисто: тест грепает `node:fs`/`node:http`/`fetch(`/`Date.now(`/`new Date(`/`Math.random(`
  по трём модулям ядра. Единственный встроенный модуль в ядре — `node:crypto` (sha256
  детерминирован; это не ФС, не сеть и не часы);
- `node:child_process`, который тянет за собой импорт `day-work-diff.mjs`, — транзитивный и
  бездействующий: ни одна моя функция его не вызывает. Импорт мерки обязателен по брифу,
  поэтому факт называю, а не прячу;
- стабы соседей исполняемые и живут только в моей зоне: `actsForBlock` (порядок по `at`,
  пустой ответ = «вещдоков нет»), `actualChangedLines` (`null` = «факта нет», не ноль),
  приёмник исхода (`fitted`/`overflowed`, порог числом в записи, времени исхода в записи нет).
