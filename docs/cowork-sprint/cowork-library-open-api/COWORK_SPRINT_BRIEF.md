## Вход

Заседание [`docs/meeting/library-open-api/EPIC.md`](../../meeting/library-open-api/EPIC.md)
(влито `4eba2c77`), редакция 3 после двух аудитов. Прочитано целиком до нарезки.

Резка идёт по **графу заседания**, а не по удобству: `(1) ось владения → (2) форма контракта
→ (3) срок ключа ∥ (4) границы выемки`. Блоки — это (1), (2) и (3).

**(4) границы выемки в спринт НЕ входит.** Эпик сам называет квоту нормой к вводу, а не
действующей границей: счётчика выдач и предела частоты в стволе не существует, то есть предел
фактически бесконечен. Брать блок, у которого носитель ещё не решён, значило бы резать по
воображаемому шву.

## Problem (общая разработка)

Партнёры попросили «публичное API библиотеки». Шторм переименовал предмет: **открытое, а не
публичное** — пользователь берёт СВОИ треки по авторизации. Вопрос оказался не в маршрутах: у
media нет оси пользователя. Разработка отвечает не «какие ручки сделать», а **чем система
знает, чей это трек, и чем она удерживает границы**.

Сквозная нить заседания, общая для всех трёх блоков: **у каждой границы должен быть носитель,
умеющий отказать.**

## Известный шов — намеренно НЕ согласован заранее

**Имя временного поля ключа в JSON-списке.** M2 назвал рабочее `trackUrl`; лемма M4 записала
`temporaryKey?`. Ни одна комната не назначала имя окончательно и ни одна не знала о варианте
соседа.

**Назначать заранее запрещено — это и есть работа Interface Consilium.** Каждый блок
объявляет своё ожидание в `EXPECTATIONS.md` односторонне:

- **contract** — как поле называется в спецификации и сериализаторе;
- **key-ttl** — как называется то, что несёт срок и сам ключ;
- **ownership** — нужно ли ему это поле вообще (вероятно нет — ось владения ключа не касается).

Сводим на вскрытии. Если ожидания разойдутся — это ожидаемый исход формата, а не сбой.

## Constraints / Out of scope

- **Out of scope:** M4 (границы выемки, квота выдачи на мембрану) — норма к вводу, носителя в
  стволе нет.
- Media в рантайме **в кабинет не ходит** — поле пишется однократно при привязке.
- Наружу **не едут** `storageRef` (внутренний путь хранилища) и `notes` (пометки человека).
- Слоя трансляции путей нет — контракт сохраняет внутренние пути осознанным решением M2
  (расхождение с Т1 шторма названо в эпике явно).
- Цены, названные заседанием и НЕ лечимые этим спринтом: документированные ночи копируются;
  приёмный лоток под общим выключателем срока; утёкшая связка гасится только ротацией.

## Интеграционный smoke (набросок — уточняется контрактом Phase 3)

Один сценарий через все три шва:

1. Прибор **с** мембраной, авторизованный запрос списка → ось владения (ownership) отбирает
   его треки → контракт (contract) отдаёт страницу `items/total/page/limit` с одиннадцатью
   полями и временным полем ключа → срок этого ключа подставлен константой (key-ttl), когда
   ttl не задан.
2. Прибор **без** мембраны → **пустая страница**, не ошибка.
3. Операция, требующая владельца, на приборе без мембраны → **именованная ошибка**, не догадка.
4. Чужой прибор → `403`; несуществующий → `404`.
5. Читатель считает полноту по инварианту; поля `hasMore` в ответе нет.
6. `storageRef` и `notes` в теле ответа отсутствуют.
