## Что этот блок такое

`library-ownership` — **ось выборки**, а не ещё одна охрана маршрута. Он отвечает ровно на
один вопрос: **чей это трек** — и делает это единственным законным способом: читает
`Device.membraneId`. Всё остальное, что оказывается в области видимости на реальном вызове
(`deviceId` из пути, `collectionId` из пути), для него — **шум, из которого владельца выводить
запрещено**.

Блок **не владеет**: маршрутами, DTO наружу, генератором ключа, сроком ключа, квотой выдачи,
пагинационной обёрткой контракта. Это M2/M3/M4. Блок владеет предикатом владения, областью
выборки по этой оси и **именованным отказом**, когда владельца нет.

## Единица владения

Вердикт M1 дословно: единица владения — **`Device.membraneId`**, не `deviceId` (это адресация)
и не `collectionId` (это группировка).

Сверено в стволе 02.09: поле уже существует —
`packages/background-media/prisma/schema.prisma`, `Device.membraneId String? @db.Uuid` с
`@@index([membraneId])`; пишется в `devices.service.ts` (`register`, `syncMembraneContext`)
однократно при регистрации/привязке из `DeviceMembraneContext`. **Работа блока — не завести
поле, а построить на нём ось выборки.** Схему блок не трогает ни строкой.

Цепочка `User → Membrane → Device → Collection → Sample` разорвана посередине намеренно:
первые два звена живут в кабинете, последние три — в media. Media в рантайме в кабинет **не
ходит**; она читает уже записанный слепок звена. Отсюда главное свойство блока: **он
синхронный и локальный** — ни сетевого вызова, ни ожидания, ни деградации «кабинет недоступен».

## Три состояния и три разных ответа

Прибор без мембраны — **законное состояние**, а не ошибка данных (`membraneId` объявлен
`String?` осознанно). Поэтому один вход даёт три разных исхода, и смешивать их нельзя:

| Состояние прибора | Выборка по оси владения | Операция, требующая владельца |
|---|---|---|
| `membraneId` заполнен | треки его мембраны | выполняется |
| `membraneId` пуст (`null`, `undefined`, пробелы) | **пустое множество**, не отказ | **именованная ошибка** `OWNERSHIP_MEMBRANE_ABSENT` |
| владелец «выведен» из `deviceId`/`collectionId` | — | **этого исхода не существует**: угадывать дверь не вправе |

Асимметрия второй строки — суть вердикта M1, а не недосмотр. **Читать** у прибора без мембраны
законно: он просто ничего не показывает по этой оси. **Действовать** от имени владельца,
которого нет, — нельзя, и молчаливый `null` тут хуже отказа, потому что вызывающий примет его
за «ничего не нашлось».

Нормализация пустоты **fail-closed**: строка из пробелов — это отсутствие владельца, а не
владелец с именем `"   "`. Никакой другой источник (`deviceId`, `collectionId`, «последняя
известная мембрана», «единственная мембрана в базе») подстановкой не служит.

## Устройство

Четыре слоя, каждый следующий видит только предыдущий:

1. **Ось** (`ownership-axis.ts`) — чистая функция `resolveDeviceOwnership({ id, membraneId })`
   → `OwnershipAxis`: либо `{ kind: 'membrane', membraneId, deviceId, derivedFrom }`, либо
   `{ kind: 'absent', deviceId }`. Вход — **узкая проекция прибора из двух полей**: то, чего
   нет на входе, нельзя случайно использовать. Результат заморожен (`Object.freeze`).
2. **Провенанс** — каждая ось владения несёт поле `derivedFrom: 'device.membraneId'`, и
   `assertOwnershipProvenance` роняет ось с другим происхождением
   (`OWNERSHIP_PROVENANCE_VIOLATION`). Это не подпись и не защита от злого умысла: это
   исполняемая декларация «откуда взят ответ», которую нельзя забыть обновить при копипасте.
3. **Область** (`ownership-scope.ts`) — `selectionForAxis(axis, window?)` → либо
   `{ kind: 'query', filter: { membraneId, createdFrom?, createdTo? } }`, либо `{ kind: 'none' }`.
   `none` — это не «пустой фильтр», который в хранилище раскроется в «всё»: это отдельный
   разряд, и до хранилища он не доходит.
4. **Сервис** (`library-ownership.service.ts`) — над **портом чтения**
   (`OwnershipSampleReader`), не над Prisma. На `none` сервис возвращает пустую страницу,
   **не обратившись к читателю ни разу**; `requireMembraneOwner(device, operation)` возвращает
   `membraneId` или бросает `MembraneOwnerRequiredError`.

Порт узкий намеренно: `count(filter)` и `findPage(filter, { skip, take })` над строкой
`{ id, deviceId, collectionId, createdAt }`. **Полезной нагрузки в проекции нет** — ни
`storageRef`, ни `notes`, ни поля временного ключа. Ось владения отвечает «чьё и какие», а не
«чем это открыть».

Адаптер `PrismaOwnershipSampleReader` типизирован **структурно** (`OwnershipPrismaLike`) и не
импортирует сгенерированный клиент: блок собирается и проверяется там, где `prisma generate`
ещё не гонялся. Он строит `where: { device: { membraneId } }` — соединение по мембране, а не
`where: { deviceId }`.

## Как доказывается запрет угадывания (DoD 4)

Запрет «выводить владельца из `deviceId`/`collectionId`» — это утверждение **об отсутствии**
кода, а отсутствие обычным тестом не показывается. Поэтому запрет проверяется **порчей**:

- `conformance/ownership-conformance.ts` — исполняемый набор из восьми случаев над
  произвольной реализацией `(ctx: { device, collectionId? }) => OwnershipAxis`. Контекст
  намеренно шире узкой проекции: на реальном вызове `/v1/devices/:deviceId/collections/:collectionId/samples`
  оба соблазна лежат под рукой, и набор обязан ловить их именно там, где они доступны.
- `conformance/corrupt-resolvers.ts` — пять испорченных реализаций: владелец всегда из
  `deviceId`; `deviceId` подставляется, когда мембраны нет (самая правдоподобная ошибка);
  владелец всегда из `collectionId`; `collectionId` как запасной; сквозной пропуск пробельной
  мембраны.
- Зуб `ownership-corruption.test.ts` утверждает две вещи: честная реализация даёт **ноль**
  провалов, и **каждая** порча роняет **поимённо названные** случаи. Если однажды набор
  ослабнет, порча пройдёт — и красным станет сам зуб.

Это ручная мутационная проверка: она удостоверяет не то, что код сегодня правильный, а то, что
**зубы способны отличить правильный от неправильного**.

## Собственный DoD

Проходит на стабах, без кода соседей:

1. прибор с мембраной → его треки (фильтр по `membraneId`, страница, `total`);
2. прибор без мембраны → **пустое множество, не ошибка**, и читатель не вызван ни разу;
3. операция, требующая владельца, на приборе без мембраны → `MembraneOwnerRequiredError`
   с кодом `OWNERSHIP_MEMBRANE_ABSENT`, несущая `deviceId` и имя операции (не `null`, не молчание);
4. порча из `deviceId`/`collectionId` роняет поимённо названные зубы; честная реализация — ноль
   провалов;
5. адаптер строит соединение по `device.membraneId` и не строит фильтр по `deviceId`/`collectionId`;
6. ни один файл блока не импортирует код соседних блоков и не ходит в сеть.
