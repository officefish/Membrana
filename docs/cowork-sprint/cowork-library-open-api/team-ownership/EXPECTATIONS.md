# Expectations — Block `ownership`

Односторонний документ. Здесь только **мои** требования и **мои** предложения; ни одна строка не
утверждает, что сосед так сделал или согласился. Чужие `EXPECTATIONS.md` не читались, чужие
ветки не читались, интерфейсы ни с кем не согласовывались. Формы ниже — то, что мои стабы
воспроизводят у себя до Interface Consilium.

## Что мне нужно от соседей

| От блока | Что мне нужно | Форма (моя односторонняя запись) | Инварианты, на которые я опираюсь |
|---|---|---|---|
| `contract` (M2, дверь наружу) | Чтобы на вызов приходила **проекция прибора из двух полей** — `{ id, membraneId }`, — а не весь `Device` и не только `deviceId` из пути | `DeviceOwnershipRow = { readonly id: string; readonly membraneId: string \| null \| undefined }` | `membraneId` — ровно то, что кабинет записал при привязке; дверь его не подставляет, не достраивает и не берёт из пути |
| `contract` (M2) | Чтобы **отказ «владельца нет» доехал наружу отдельным разрядом**, а не слился с «ничего не нашлось» | Ловится `MembraneOwnerRequiredError` (`code === 'OWNERSHIP_MEMBRANE_ABSENT'`), отображается **не** в `404` и **не** в `403` — предлагаю `409 Conflict` | M2 сам развёл `404` (нет такого) и `403` (закрыто) осознанно; «есть, но владельца нет» — третье состояние, и слить его с любым из двух значит соврать партнёру |
| `contract` (M2) | Чтобы **пустая страница по оси владения не превращалась в ошибку** на выходе двери | `{ items: [], total: 0, page, limit }` | Прибор без мембраны — законное состояние (M1); на **выборке** он даёт пустоту, а не отказ |
| `key-ttl` (M3/M4, ключ и срок) | Чтобы масштаб выключателя и квоты был **мембраной**, и мембрану он брал **у меня**, а не выводил сам | `requireMembraneOwner(device, operation): string` — возвращает `membraneId` или бросает | M3 объявил масштаб выключателя мембраной, M4 — квоту на `membraneId`; обе величины считаются по той же оси, иначе выключатель и выборка разойдутся |
| `key-ttl` (M3/M4) | Чтобы ключ **не выдавался** прибору без мембраны | Вызов `requireMembraneOwner` **до** генерации ключа; исключение не гасится в `catch` | Квота считается на мембрану; без мембраны счётчику некуда писать, и «бесконечная квота» получилась бы не по решению, а по недосмотру |

## Что я готов отдать

| Блоку | Что | Форма | Инварианты, которые я держу |
|---|---|---|---|
| `contract` (M2) | Разрешение владения | `resolveDeviceOwnership(device) → OwnershipAxis` = `{ kind: 'membrane', membraneId, deviceId, derivedFrom: 'device.membraneId' }` \| `{ kind: 'absent', deviceId }` | Чистая, синхронная, замороженный результат; читает **только** `membraneId`; пробельная строка — отсутствие владельца, а не владелец |
| `contract` (M2) | Выборка треков по оси владения | `listOwnedSamples(device, { page, limit, createdFrom?, createdTo? }) → { items, total, page, limit, scope: 'membrane' \| 'empty' }` | Прибор без мембраны → `items: []`, `total: 0`, `scope: 'empty'`, **и читатель хранилища не вызван ни разу**; фильтр — соединение по `device.membraneId`, никогда по `deviceId`/`collectionId` |
| `contract` (M2) | Проекция строки — **идентичность и область, без нагрузки** | `{ id, deviceId, collectionId, createdAt }` | В проекции нет `storageRef`, нет `notes` и **нет поля временного ключа**: ось владения не носитель ключа (см. «Известный шов») |
| `key-ttl` (M3/M4) | Владелец под операцию | `requireMembraneOwner(device, operation) → membraneId`, иначе `MembraneOwnerRequiredError { code: 'OWNERSHIP_MEMBRANE_ABSENT', deviceId, operation }` | Никогда не возвращает `null` и никогда не молчит; имя операции едет в ошибке, чтобы отказ был читаем на стороне вызывающего |
| `key-ttl` (M3/M4) | Ключ мембранного масштаба для квоты и выключателя | `membraneId` из той же оси | Одна величина на выборку, квоту и срок — расхождения между ними по построению нет |
| всем (интеграция) | Исполняемая проверка запрета угадывания | `runOwnershipConformance(resolve) → ConformanceFailure[]` + шесть испорченных реализаций | Любой чужой резолвер владения можно прогнать через тот же набор; порча из `deviceId`/`collectionId` роняет поимённо названные случаи |

## Известный шов — моё одностороннее ожидание (не назначение)

Имя временного поля ключа в JSON-списке расходится между протоколами: вердикт M2 назвал рабочее
`trackUrl`, лемма M4 записала `temporaryKey?`. **Я это имя не назначаю** — это не мой предмет и
назначать его в одиночку было бы ровно тем сговором, которого формат избегает.

Моё ожидание по существу: **оси владения это поле не нужно ни под каким именем.** Ось отвечает
«чей трек и какие треки», а поле ключа отвечает «чем его открыть» — это M3 (генератор, срок) и
M2 (форма наружу). Поэтому:

- моя проекция строки — `{ id, deviceId, collectionId, createdAt }`, и поля ключа в ней нет
  **намеренно**, а не по забывчивости;
- ключ навешивается **после** оси, на слое двери, поверх уже отобранных мной строк;
- любое из двух имён (или третье) я приму без единой правки в своём коде — шов проходит не
  через меня;
- **если** на интеграции окажется, что ключ надо навешивать внутри выборки (например, чтобы
  считать квоту выдач M4 по фактически отданным ссылкам), то это уже не переименование поля,
  а перенос ответственности через границу блока: тогда прошу решать это контрактом Phase 3
  явно, а не молчаливым добавлением поля в мою проекцию.

## Мои инварианты

1. Единица владения — `Device.membraneId`. `deviceId` — адресация, `collectionId` — группировка;
   владельцем ни то, ни другое не служит **никогда**, в том числе как запасной вариант.
2. Отсутствие мембраны — законное состояние, а не порча данных.
3. Асимметрия: **выборка** без владельца → пустое множество; **операция**, требующая владельца,
   без владельца → именованная ошибка. Смешение этих двух исходов — дефект.
4. Пустота нормализуется fail-closed: `null`, `undefined`, `''`, строка из пробелов — всё это
   отсутствие владельца.
5. Ось синхронна и локальна: ни сетевого вызова, ни обращения в кабинет, ни чтения файловой
   системы. «Кабинет недоступен» на неё не влияет по построению.
6. Каждая ось несёт `derivedFrom: 'device.membraneId'`; ось с иным происхождением роняется
   (`OWNERSHIP_PROVENANCE_VIOLATION`).
7. Пустая область (`{ kind: 'none' }`) — отдельный разряд, до хранилища не доходящий. Пустого
   фильтра, раскрывающегося в «всё», в блоке нет.
8. Блок не пишет в `Device.membraneId` и не трогает `schema.prisma`.

## Что я прошу у координатора на интеграции

Не договорённость с соседями, а работа сборки — то, чего блок по правилам изоляции сделать не мог:

1. Строка в `app.module.ts`: `LibraryOwnershipModule.withReader({ provide: OWNERSHIP_SAMPLE_READER, inject: [PrismaService], useFactory: (prisma) => new PrismaOwnershipSampleReader(prisma) })`.
2. Удалить или исключить из сборки `stubs/in-memory-sample-reader.stub.ts` и
   `conformance/corrupt-resolvers.ts` — либо оставить их только для тестов. Набор случаев
   `conformance/ownership-conformance.ts` при этом **стоит сохранить**: через него можно
   прогнать любой чужой резолвер владения, если он где-то появится.
3. Отображение `MembraneOwnerRequiredError` в HTTP-статус — предмет двери (M2). Моё
   одностороннее предложение: `409`, не `404` и не `403`.
4. `packages/background-media/generated/prisma` в дереве отсутствует; типизация пакета от этого
   красная вне зоны блока. Перед интеграционным прогоном нужен `prisma generate` — правка не моя.
