# Состояния — списком, не поштучно (`yarn task:states`)

Инструмент контракта мастерской задач (#1322, карточка `tw-state-batch-norm`).

## Зачем

Вещдок 26.07: цикл `gh issue view` по 13 номерам встал на пятиминутном таймауте и не
доехал до конца — живость топ-10 хендофа осталась непроверенной. Батч-запрос по тем же
номерам отрабатывает **одним вызовом** GraphQL (алиасы, `issueOrPullRequest` — номера
issue и PR живут в одном пространстве).

## Как

```bash
yarn task:states 1310 1316 1318        # таблица: #номер → состояние
yarn task:states 1310 --json           # {"unknown":false,"states":{"1310":"CLOSED"},"missing":[]}
```

Exit-коды: `0` — состояния получены (ненайденный номер — строка `НЕ НАЙДЕН`, не провал);
`1` — usage; `2` — **honest unknown**: сеть/прокси не ответили за явный таймаут —
состояния НЕ известны, отсутствие ответа не является состоянием.

## Норма

Поштучный `gh issue view` / `gh pr view` в цикле по списку номеров — запрещённая форма
(грабля в [`AGENTS.md`](../../AGENTS.md)). Программный доступ — `fetchStatesBatch` из
[`scripts/lib/task-states-batch.mjs`](../../scripts/lib/task-states-batch.mjs): один вызов
на пачку до 50 номеров, явный таймаут, honest unknown на сеть.
