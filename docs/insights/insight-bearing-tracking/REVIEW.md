# Insight Review: INSIGHT: Наземная пеленгация цели: угловой трек без дальности + временная фильтрация детекций

[Teamlead]: Инсайт имеет высокий стратегический потенциал — переход от бинарной детекции «есть/нет цель» к непрерывному угловому сопровождению принципиально меняет продуктовую ценность ансамбля микрофонов. Однако внедрение требует архитектурного решения: фильтр состояния — это новый сервис или плагин в шине? Обязательна синхронизация постов (NTP/PTP). Готовность к двум микрофонам в поле — да, стенд собран. Оценка: 8/10, но не раньше фазы B после MVP.

[Структурщик]: С архитектурной точки зрения вижу две задачи: (1) контракт углового трека (azimuth/elevation/ts/confidence/quality) как shared type в монорепо; (2) связка «пост → трекер» через шину плагинов или отдельный сервис `packages/services/bearing-tracker`. Синхронизация часов между постами — риск потери слабой связности, если не выделить сервис синхронизации. Вето на прямые импорты между плагинами детекции и трекером. Предлагаю deferred до этапа «неделя после MVP»: сначала зафиксируем контракты текущих детекторов.

[Математик]: Математика ясна и укладывается в чистые функции. Ключевые блоки: (1) оценка пеленга по разности фаз/времени прихода (TDOA) между разнесёнными микрофонами — классическая гиперболическая геометрия; (2) EKF/UKF для углового трека с адаптивной оценкой ковариации шума через невязки (по образцу документа партнёра). Проблема 360° решается через представление угла как комплексного числа или sin/cos в состоянии фильтра. Адаптивную ковариацию можно сделать через скользящее окно инноваций — чистая функция без фреймворков. Оценка: 7/10 — математика готова, но нужен эталонный бенчмарк на реальных записях.

[Музыкант]: Идея синергирует с нашим аудиопотоком — получим не только «есть сигнал», но и «источник движется по азимуту 47°». Для музыканта ценно: угловой трек открывает возможность стерео/пространственной обработки на основе отслеживания источника — эффекты, панорамирование, пространственная звуковая сцена. Web Audio API позволяет получать разность фаз через анализатор (AnalyserNode.getByteFrequencyData), но точность будет низкой — для TDOA нужен сырой буфер сэмплов (Audio Worklet). Edge recording уже есть — используем накопленные 2× ECM8000 + Scarlett Solo. Риск: качество синхронизации через USB (разные буферы). Оценка: 7/10.

[Верстальщик]: Для фронта интересен вывод трека: (1) визуализация «радара» с движущейся меткой цели по азимуту/углу места; (2) индикатор уверенности трека; (3) история треков за сессию. Угловой трек лучше бинарного «зелёный/красный» — пользователь видит, что система «сопровождает», а не просто «видит/не видит». Компоненты: `<BearingRadar>` с SVG, `<TrackHistory>` с Canvas, `<ConfidenceIndicator>`. Адаптив под мобильные и настольные экраны. Риск: переусложнение UI до MVP. Оценка: 6/10 — внедрять на этапе UI-итерации после стабильного MVP.
