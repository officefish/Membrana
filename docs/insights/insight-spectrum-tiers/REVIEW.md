# Insight Review: «Второй тариф: MFCC-спектр + нейроанализ спектрограмм машинным зрением»

---

[Teamlead]: Идея структурно зрелая: два некоррелированных слоя распознавания (MFCC + CNN по спектрограмме) дают реальное улучшение ансамбля, а тарифная граница решает одновременно продуктовую задачу (monetization) и архитектурную (фильтрация узлов). Однако scope нуждается в уточнении: server-first для CNN-инференса — решение, но требует оценки latency для real-time сценариев. Метка тарифа в манифесте узла — верный паттерн, уже частично заложен в эпиках #302–307. Рекомендую статус «adopted» с разбивкой на два эпика: (1) инфраструктура тарифной фильтрации (критическая зависимость от кабинета), (2) новые узлы распознавания. Полевой материал с 22.07 — окно для первых прогонов, не упустить.

[Структурщик]: MFCC-узел как плагин модуля «Микрофон» — вписывается в текущую архитектуру плагинов. Проблема: MFCC требует цепочку FFT → mel-фильтры → log → DCT. Сейчас FFT уже есть в математическом ядре, но mel-фильтры и DCT — новые зависимости. Нужно либо расширять core/math, либо делать выделенный сервис в packages/services/. Нейроузел (CNN на спектрограмме) — строго server-first: модель ONNX/TorchScript на backend, клиент шлёт спектрограмму или сырой буфер. Это добавляет latency и требует нового сервиса inference-service. Риск: слабая связанность между плагинами может нарушиться, если MFCC-узел потянет зависимости от сервиса. Манифест узла с полем `tier` — минимальное изменение схемы, но нужно синхронизировать с кабинетом (#302–307). Оценка внедрения: 3–4 недели до рабочего прототипа.

[Математик]: MFCC — классический, хорошо изученный признак. Для Membrana оптимально: 13–20 коэффициентов, окно 1024, hop 512, 40 mel-фильтров. Чистая функция: вход Float32Array (буфер сэмплов), выход Float32Array[13]. Никаких побочных эффектов. DCT-II — O(n²) для малых n (13–20) — допустимо на клиенте. Спектрограмма для CNN: log-mel spectrogram как 2D-тензор (128×128 или 256×256). Вопрос: где выполнять STFT для спектрограммы? Если на клиенте — дублирование с MFCC-конвейером. Если на сервере — нужно передавать сырой PCM, что увеличивает трафик. Рекомендую: STFT на клиенте, mel-фильтрация на клиенте, передача log-mel-спектрограммы на сервер (≈ 128×128×4 = 65 KB на фрейм). Для real-time это приемлемо при частоте 1–2 Гц. Риск: спектрограмма может быть сжата сильнее (PNG/WebP для изображения — но это вне математического ядра и потенциально снижает точность). Из research: комбинация признаков не всегда даёт прирост (источник) — нужна валидация на полевом материале до продакшена.

[Музыкант]: MFCC — разумное расширение спектрального анализа. Для Membrana как аудио-инструмента важно: MFCC даёт компактный «тембральный портрет» цели, чего чистый спектр не даёт. Нейроанализ спектрограмм — интересно, но server-first ломает идею автономного устройства. Если полевое железо (чек 19.07) работает с edge processing, то инференс CNN должен быть на устройстве. TorchScript Mobile или ONNX Runtime для ARM — вопрос для отдельного исследования. 24 bit / 48 kHz для MFCC — избыточно: 16 bit / 22 kHz достаточно для MFCC-анализа (речевой диапазон до 8–11 кГц). Для спектрограммы — возможно 24 bit для динамического диапазона. Риск latency: STFT на клиенте + MFCC + передача спектрограммы на сервер — может превысить допустимые 500 мс для real-time. Рекомендую: для первого релиза — только MFCC-узел на клиенте (прототип за 1–2 недели), нейроузел — как отдельная задача после тестирования полевого материала.

[Верстальщик]: Тарифная фильтрация палитры узлов — UI-задача. Сейчас узел добавляется из палитры (basn-паттерн). Нужен фильтр по `tier` в манифесте узла: если тариф пользователя < tier узла → узел скрыт или показан с lock-иконкой и ссылкой на upgrade. Это требует: (1) получения текущего тарифа из кабинета (#302–307); (2) хранения/кеширования tier-манифеста; (3) фильтрации в компоненте NodePalette. Дизайн по DESIGN.md: lock-состояние уже описано для премиум-функций? Если нет — нужен новый компонент TierLock. Адаптив: на мобильных палитра узлов — drawer или bottom sheet. Риск: если кабинет ещё не готов (#302–307 не реализован), UI-фильтрация работать не будет. MVP-решение: статический список `tier` в конфиге, без интеграции с кабинетом. Оценка: 3–5 дней на фильтрацию, включая lock-состояние.
