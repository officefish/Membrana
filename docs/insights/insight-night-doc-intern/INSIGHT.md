## Проблема / наблюдение

Документация харнесса (harness.mmbrn.tech/tooling/containers, README, docs-каноны)
пишется изнутри — авторы знают систему и не видят, где док молчит, врёт или избыточен.
Внешние вещдоки 27–28.07: Плотва (внешний ИИ) на холодном чтении не смогла получить
README через веб-интерфейс (находка discoverability), а её критика «отчёт — памятник
ушедшему» родилась именно из внешнего мотива и попала точнее внутренних аудитов.
Письмо Яны (28.07, «правильный человек» по Азимову): ценность — у носителя ракурса,
невидимого «сверху»; формула владельца: «система по её движению делает выводы о себе».

## Гипотеза

Если ночной агент-«интерн» с ротируемым мотивом (цель из мастерских контейнеров:
«зарегистрируй задачу», «подними мастерскую вещдоков», «зачекань кристалл») проходит
систему ДВАЖДЫ — (1) слепо, только по документации, с журналом траектории (что искал →
нашёл → застрял → какой вывод сделал, включая ошибочные) и (2) глубоко, по коду, — то
дельта двух проходов даёт поимённую карту дыр документации: где молчит (застрял слепым),
где врёт (уверенный вывод опровергнут кодом), где избыточна (не понадобилась). Выход —
патчи к докам + утренний разбор. Ночь начинает работать на день (night-coding контур).

## Scope (черновик)

- In scope: роль интерна с мотивом; журнал траектории (две ленты); дельта-отчёт; патчи-предложения к докам PR-ом; ротация мотивов по контейнерам; ночной профиль разрешений (membrana-always-yes), изолированный worktree; read-only слепая фаза (только docs).
- Out of scope: правка кода системы по находкам (только доки); автономный мердж патчей (утренний разбор + слово владельца); прогон до 01.08 на слабом фолбэке — только пилот одного мотива.

## Вопросы для research (Q1–Q3)

- **Q1 (Landscape):** Какие существуют практики и инструменты оценки документации «холодным читателем» (docs usability testing, blind walkthrough, doc-driven onboarding audits) у команд разработки в 2024–2026 — и что из этого автоматизировано агентами?
- **Q2 (Fit):** Как формализуют «журнал траектории» пользователя документации (search path, dead ends, wrong-conclusion tracking) — какие форматы логов и метрики (time-to-first-success, wrong-turn rate) устоялись?
- **Q3 (Risk):** Известные ловушки doc-generation агентами: чем грозит автопатч документации без человеческого гейта, как отличают «док врёт» от «читатель не туда пошёл», и какие гейты ставят на предложения правок?
