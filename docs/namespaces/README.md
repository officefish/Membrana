# Реестр неймспейсов

Единственный источник истины о членстве в неймспейсе. Заведён 31.07 по
[`CONTRACT.md §1`](../meeting/workshop-wires/CONTRACT.md) заседания `workshop-wires`.

**Неймспейс — не дом.** Дом отвечает глаголами и несёт `workshop.manifest.json`; неймспейс
отвечает смыслом правила и стабильностью `id`, глаголов не имеет и не обязан. Различение
машинное, по типу носителя, а не по интонации README:

```text
isHome(x)      ⇔ workshop.manifest.json с паттерном дома
isNamespace(x) ⇔ запись в этом реестре
```

## Форма записи

| поле | обязательность | содержание |
|---|---|---|
| `id` | да | `[a-z][a-z0-9-]*`, уникален в реестре |
| `title` | да | человекочитаемое имя |
| `holder` | **да** | `{ persona }` **XOR** `{ ownerRef }` |
| `membership` | да | `{ kind, value }`, `kind` ∈ `pathPrefix` · `namePrefix` · `pathGlob` · `explicitList` |
| `containerKind` | нет | `plain` · `bidi` — пометка двумерного контейнера |
| `verbs`, `worksOn`, `kit`, `roots` | **запрещены** | признаки дома |

Держатель — строгий XOR. Пустой держатель делает запись невалидной; два держателя тоже:
«отвечают оба» на практике значит «не отвечает никто».

## Запреты

- Неймспейс без держателя.
- Имена-свалки: `misc`, `other`, `tmp`, «всё сиротское».
- **Второй источник истины членства.** Строка справочника членством не является: атлас —
  потребитель-агрегатор, вход `derive`, проекция отдельной секцией.
- Перечень кластеров вместо правила образования. `explicitList` — исключение для точечных
  случаев, а не способ обойти требование правила.

## Почему реестр сегодня пуст

Пустой реестр **не значит «всё припарковано»**. На замер 30.07 сиротами числятся 476
носителей; правило образования для них ещё не написано, и выдумывать неймспейсы, которых
заседание не ратифицировало, значило бы заменить правило перечнем — прямой запрет §1.

Пустота здесь — честное состояние: носитель формы есть, содержания пока нет. Инструменты
обязаны говорить об этом прямо, а не отдавать пустой список молча.

## Как завести неймспейс

1. Правило образования формулируется как `membership`, а не как перечень файлов.
2. Держатель называется поимённо — `persona` из [`voices.registry.json`](../virtual-team/voices.registry.json)
   либо `ownerRef` на решение владельца.
3. Запись добавляется в `REGISTRY.json`; проверка — `checkRegistry` из
   [`scripts/lib/belongs.mjs`](../../scripts/lib/belongs.mjs).
4. Справочник подхватывает запись проекцией. Руками в справочник не пишут.
