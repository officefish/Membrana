# Контейнер `network` — сетевое окружение и характер отказов

> Дом: `docs/network/` · мастерская: `scripts/network/` · issue [#1449](https://github.com/officefish/Membrana/issues/1449)
> Спроектирован заседанием `network-container-form` 29.07 (36 реплик).

## Зачем он есть

Двое суток диагноз звучал так: «на office-VDS нет исходящего маршрута к LLM, сетевой
фильтр хостера, нужен туннель через media-VPS в Нидерландах». Под это был заведён эпик,
намечена работа на неделю.

Живой замер прода 29.07 показал обратное:

```
HTTPS_PROXY в контейнере office    есть
TCP до прокси                      OPEN
openrouter через ProxyAgent        HTTP 200
GitHub напрямую                    HTTP 200
```

**Сеть работала всё это время.** А отказы были такие:

| провайдер | настоящая причина |
|---|---|
| grok | `404: Grok 4 Fast is deprecated` — модель снята |
| gemini | `404: No endpoints found` — модель снята |
| perplexity | `402: can only afford 3505 tokens` — кончился лимит ключа |
| deepseek | `DEEPSEEK_API_KEY missing` — ключа нет в контейнере |

Код метил **любой** неуспех как `net`. Диагностика честно читала «30 из 30 — net на всех
четырёх провайдерах» и делала единственно логичный вывод: сети нет.

**Контейнер существует, чтобы это не повторилось.** Его предмет — не проложить маршрут
(маршрут есть), а не дать классификатору соврать про причину и рассказать агенту о
сетевом мире заранее.

## Мастерская

**Новому агенту:** [`HOWTO_REPORT_STATE.md`](HOWTO_REPORT_STATE.md) — как отдать
состояние сети тремя командами, не читая код и не гадая.

| команда | что делает |
|---|---|
| `yarn network:probe` | бьёт по звеньям **обоими путями** — прямым и через прокси |
| `yarn network:snapshot` | пишет снимок, витрину и строку истории |
| `yarn network:preflight` | предполётная проверка: JSON + код возврата |
| `yarn network:tooth` | зуб: словарь закрыт, снимок свеж, нет голого `fetch` |

Голый `fetch` — находка везде, кроме каналов, чья прямота **ратифицирована решением**.
Такой канал помечается рядом с вызовом строкой `network-tooth:allow-bare-fetch ADR-NNNN`;
зуб проверяет, что названный ADR существует, и печатает освобождённые файлы отдельной
строкой. Метка на несуществующий ADR — находка: иначе она станет способом заглушить зуб.

Коды возврата `preflight` — агент ветвится по числу, а не по тексту:

`0` всё зелено · `10` транспорт (**вот это сеть**) · `20` ключи · `30` доступ, деньги,
модель · `40` не опознано · `2` инструментальная ошибка.

## Главное правило

**Если сервер ответил HTTP-статусом — транспорт работает.**

Сетью считаются ровно шесть исходов: `dns_fail`, `tcp_fail`, `tls_fail`, `timeout_idle`,
`proxy_intercept`, `provider_unreachable_http`. Всё остальное — `403` гео, `404` снятая
модель, `402` кончившиеся деньги, `401` непринятый ключ — **не сеть**, и лечится не
туннелем.

Неопознанное идёт в `unknown_protocol` и остаётся честным незнанием. Дописывать его в
транспорт молча — запрещено: именно так и рождается ложный диагноз.

## Что агент должен знать до первого вызова

1. Голый `fetch` в Node **не читает** `HTTPS_PROXY`. Нужен `undici` + `ProxyAgent` или
   общий хелпер `packages/background-office/src/lib/proxy-fetch.ts`. Грабля повторялась
   дважды: Linear и night-hunt. `deepseek.service` в этот счёт **не входит** — его прямой
   путь ратифицирован ADR-0007: ценность канала именно в независимости от прокси, и
   «починка» этого вызова сломала бы решение, а не грабли.
2. Одна цель ведёт себя по-разному в зависимости от пути: openrouter напрямую отдаёт
   `403`, через прокси — `200`. Поэтому зонд всегда ходит обоими путями.
3. office **запрещено** ходить в `api.linear.app` (правило K1): live pull идёт
   `media-NL → linear-snapshot@1`.
4. Voyage отдаёт HTML-заглушку и напрямую, и через прокси — отдельный узел, туннелем
   не лечится.

Свежий снимок этого мира — `env.snapshot.md`, машиночитаемый — `env.snapshot.json`,
готовый блок для промпта — `yarn network:preflight --emit-agent-block`.

## Границы

- **Туннель здесь не проектируется.** Замер показал, что он не нужен. Если когда-нибудь
  понадобится — это отдельная работа с отдельным вещдоком.
- Не второй реестр мощностей: балансы, аренда и модели оплаты живут в
  `docs/security/infra-policy.json` (#1393). Здесь — маршруты и характер отказов.
- Не аудит вызовов моделей: это `docs/audit/llm-calls`.
- Ключи и значения токенов сюда не пишутся никогда — только имена переменных и признак
  наличия.
- Зонды ходят **без ключей**: их дело — характер отказа, а не работа аккаунта. Поэтому
  профиль может объявить `reachableStatuses` — статусы, которые для зонда означают
  «дошли» (например `401` на корне DeepSeek).
