## Тезисы (каждый подтверждён владельцем)

| № | Тезис |
|---|---|
| Т1 | Прибор прежде всего детектор. Доска запускает разные сценарии; постоянная запись на сервер — один из них и не обязательна. |
| Т2 | Запись живёт сессиями с выборкой: сервер задаёт длительность сессии и объём выборки; по итогам сессии из буфера отбирается заданное число записей по одному из трёх существующих критериев (`loudness-over-floor` · `spectral-variety` · `drone-likeness`); выборка кладётся в библиотеку. Пример: 4 ч, 200 записей, самые громкие. |
| Т3 | Политика сессий у каждого прибора своя, задаёт пользователь в кабинете; под одной мембраной будет несколько приборов, все работают с одним сервером. |
| Т4 | После сессии буфер освобождается: остаток после выборки удаляется, в холодный архив не уходит. |
| Т5 | Библиотека живёт кольцом: нет места для выборки новой сессии — удаляются самые старые; память библиотеки докупается как дополнительная услуга. |
| Т6 | Сейчас запись нужна для формирования баз звуков будущих детекторов; детекция дрона — особый сценарий, когда-нибудь основной (в журнал — только звуки дронов по мнению прибора). |
| Т7 | Выборка сессии — отдельная папка в библиотеке (прибор, время, «N из M», критерий); кольцо удаляет только такие папки целиком, наборы пользователя и вынесенные записи не трогает; политика сессий — по образцу политики буфера (#2308): у прибора своя, мембрана может задать общую. |

## Вне предмета (слово владельца)

Подъём прибора без человека — автовход, автозапуск Студии и последнего сценария, перезагрузка упавшего окна, продление связки, сообщение о молчании — «не предмет этого шторма»; задачи магистрали по карте дежурства.
