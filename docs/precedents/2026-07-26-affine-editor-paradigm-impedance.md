# Прецедент 2026-07-26: Affine — нога публикации против инструмента для человеческих рук

<!-- Автор: Claude Code (Opus 5), сессия мостика 26.07, по слову капитана «это можно проанализировать через сессию и сохранить в прецедент». -->

## Что случилось

За трое суток (24–26.07) построена нога публикации из репозитория в самоподнятый Affine:
контейнер стратегических документов, гранулы, генератор, деплой за Caddy на своём домене,
CLI импорта и синхронизации. Работа большая и в основном сделана.

Но **26.07 та же нога чинилась пять раз за одни сутки**:

| PR | Что чинили |
|---|---|
| #1218 | CLI импорта/синхронизации и гранулы политики поверхности |
| #1228 | проводка реестра ввода-вывода для функциональных гранул при синхронизации |
| #1241 | CLI публикации мастерской + push под Windows |
| #1250 | push через **сессионную куку** для socket.io |
| #1257 | маршрутизация по воркспейсам + пары «содержимое/мета» |

Свидетельство капитана в тот же вечер: агент, который это вёл, **«выдохся» на импорте
документов**. Свидетельство помечено как свидетельство — это не измерение, но оно совпадает
с измеримым: пять правок одной ноги за сутки.

## Разбор

| Признак | Что означает |
|---|---|
| upsert по **заголовку**, не по идентификатору | сущность адресуется человекочитаемым именем — так делают там, где записи ведёт человек |
| папки расставляются руками, «API папок нет» | часть операций принципиально вне машины |
| push через **сессионную куку и socket.io** | программный доступ достигается эмуляцией браузера: машина притворяется человеком |
| круговой прогон теряет HTML-таблицы | модель документа не обязана сохранять то, что не её |
| импорт неудобен агенту (свидетельство) | интерфейс рассчитан на руку с мышью |

## Корень

**Импеданс парадигм, а не дефект реализации.** Инструмент устроен так: документ ведёт
человек, машина хранит. У нас обратное: машина собирает документ из гранул, человек читает.
Пока направление противоположно, каждая интеграция оплачивается новой починкой.

Ошибка выбора при этом обычная и не глупая: инструмент подбирали **по классу** — «редактор
документов, самоподнятый, свой домен», — и по классу он подходит. Не совпал **способ
работы**, а его по описанию не видно, он проявляется на первом же программном прогоне.

## Почему решение откладывалось

Счёт приходил частями: каждая отдельная починка выглядела оправданной и небольшой, а сумма
за трое суток — нет. Плюс вложенный труд создаёт тягу продолжать — 108 отслеживаемых файлов
и около двух с половиной тысяч строк движков жалко бросать. **Потраченное не является
доводом**: считать надо будущие расходы, а не прошлые.

## Решение капитана (26.07)

Affine — не прибор. Редактирование не используем: «я как будто вообще
не хочу ничего редактировать без генераторов». Прибор — собственная панель, где нет чужих
ограничений на тип блока и возможен разговор с агентом над отдельным элементом.

Гранулы, паспорта и генераторы от Affine **не зависят** и остаются при любом исходе.

## Профилактика

Перед интеграцией внешнего инструмента проверять **способ работы, а не класс**: кто ведёт
документ — человек или машина. Четыре признака чужой парадигмы, каждый виден на первом
прогоне и стоит минут:

1. сущность адресуется человекочитаемым именем, а не идентификатором;
2. часть операций объявлена «делается в интерфейсе»;
3. программный доступ идёт через эмуляцию сессии браузера;
4. круговой прогон теряет структуру.

**Два и более признака — витрина, а не прибор.** Программную ногу к такому инструменту не
строим: берём как поверхность чтения либо не берём вовсе.

Отдельная норма счёта: **усилие агента — статья расхода**. Поверхность, съедающая агента на
каждой публикации, — налог с каждого прогона, а не разовая трата.
