# Роды акта плана — зеркало закрытого списка

**Источник истины — код:** [`scripts/lib/sprint-cut/act-kinds.mjs`](../../../scripts/lib/sprint-cut/act-kinds.mjs).
Этот файл — зеркало для человека; расхождение зеркала с enum ловится зубом в
[`scripts/sprint-cut-acts.test.mjs`](../../../scripts/sprint-cut-acts.test.mjs).

## Зачем отдельная ось, а не пятый род следа исполнения

Роды исполнения (`contract_signature`, `session_prep`, `context_run`, `review_pass`) закрыты
**по построению**: у окна работы четыре момента, в каждом ровно один акт, который исполнитель
не может произвести, не будучи им. Форма следа исполнения требует `blockId`.

**Акт нарезки блоку не принадлежит.** Он про план целиком и происходит **до** окна. Втиснуть
его в ленту исполнения значило бы соврать формой: `blockId` пришлось бы выдумать либо занулить,
и оба варианта портят предикаты соседей. Пятый род потребовал бы пятого момента окна, а
моментов четыре.

Поэтому у плана своя ось со своими тремя моментами.

## Три рода. Список закрыт

| Род | Момент плана | Что означает |
|---|---|---|
| `cut_context_run` | до нарезки | резчик прогнал **свой** профильный контекст, прежде чем резать |
| `cut_act` | нарезка | план такой-то версии написан |
| `recut_act` | перерезка | план изменён в работе, прежнее согласие снято |

`cut_context_run` и `cut_act` — по одному разу на версию плана. `recut_act` законно повторяется:
перерезок может быть сколько угодно, каждая — новая версия и новая ратификация.

**Род вне списка — ошибка входа** `E_ACT_KIND_UNKNOWN`, а не «прочее» и не слабый след.
Открытый список означал бы обход проверки новым словом — ровно то, от чего закрыт список родов
исполнения.

## Форма записи

```json
{
  "kind": "cut_context_run",
  "sprintId": "cut-act-trace",
  "subject": "tarasov",
  "at": "2026-08-01T10:00:00Z",
  "ref": "docs/discussions/cut-act-trace-tarasov.md",
  "planDigest": null
}
```

Несущие поля — `kind`, `sprintId`, `subject`, `at`; пустое несущее поле есть отказ **с
причиной**, а не молчаливый пропуск. `ref` и `planDigest` необязательны и при отсутствии
честно равны `null`, а не выдуманной строке.

Носитель ленты: `docs/sprint/cut/trail/<sprintId>.jsonl`, append-only.

## Седьмой зуб нарезки

`cutter_context_missing` — введён **актом владельца 01.08**. Перечень находок нарезки стал из
семи и **остался закрытым**.

Правило: резчик подписал план (`cutBy`), но в ленте актов нет `cut_context_run` для этого
спринта и этого субъекта → находка.

- **Ленты нет вовсе** (`acts === undefined`) — проверка **не выполняется**, а не «проходит»:
  чистые вызовы ядра без ленты не начинают зеленеть молча.
- **Лента пуста** (`[]`) — это уже «не прогонял»: отсутствие вещдока не есть вещдок отсутствия
  наоборот, и именно так болезнь и выглядела — надпись без следа.
- **`cut_act` прогоном не считается:** подпись не заменяет прогон. Ровно это и было дефектом.

## Вещдоки, ради которых ось заведена

**30.07, долг `#sprint-cut-act-has-no-trace`.** Первый боевой спринт `mfcc-compare-sprint`: план
v1 написала сессия и проставила `cutBy=tarasov` **без прогона контекста тимлида**. Поймал
владелец словами «не вижу, что ты вызвал спринт через скилл» — не механизм.

**01.08, прогон `meeting-gates-teeth`.** Председатель написал `cutBy: "tarasov"` рукой; никто не
спросил, прогонялся ли контекст. Затем перерезал план v1→v2, и перерезка не оставила следа
нигде, кроме смены дайджеста.
