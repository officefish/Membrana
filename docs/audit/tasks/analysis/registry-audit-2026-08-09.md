## Почему обычный `tasks:audit` этот пласт не берёт

Из 92 карточек GitHub Issue есть только у **шести**. `tasks:audit` судит по состоянию
иссью, поэтому механически он достаёт из этого пласта ровно 5 штук — и все пять
принадлежат одному зонтику #47. Остальные 87 судятся исключительно по свидетельству
в `origin/main`: коммиты, файлы, экспортированные символы, yarn-скрипты, тексты доков.

## Корзина 4 — решение владельца

**Отменено словом владельца 09.08 (3).** В `archiveNotes` честная формулировка
«ОТМЕНЕНО, не сделано: причина + условие переоткрытия»:

- `ucv2-2-freeze-async-tracks` — pause-shim не строился, потребность закрыта архитектурно
  эпиком `device-board-async-pipeline-v1`. Отмена разблокировала родителя
  `usercase-mvp-v2-groups-async` — он архивирован следом;
- `neural-tier-1b-contract` — контракт `NeuralDetector` не заведён, цель эшелона 1.B
  закрыта другим маршрутом (ND1–ND3, PR #266/#268, живой fusion #417);
- `cg3-flaky-metrics-week` — решение, ради которого собирались метрики, принято иначе
  (ADR-0018), источники флейки закрыты PR #247 и #297.

Отмена — не тихое закрытие: у каждой в notes записано, при каком условии карточка
возвращается.

**UNCLEAR — приёмка вне репозитория (2).** Судить по свидетельству в main нельзя
по устройству задачи, нужно слово владельца:

- `oc-proxy-s1-opencode-install` — установка стороннего CLI на машину владельца.
  Косвенно за: весь контур `.opencode/**` построен, два операторских спринта закрыты.
  Вывода `opencode --version` в main нет и быть не может;
- `oc-proxy-s2-freemodel-keys` — ключ лежит в gitignored `.env.llm-proxy`. Косвенно
  против: `.env.llm-proxy.example` держит FreeModel опциональным fallback («часто
  502/503, держите OpenRouter как primary»), M3A от 23.07 постановил «FreeModel не в
  overlay UI v1, ключ может лежать unused». Если ключ не получен — карточке место в
  CANCELLED со ссылкой на M3A, а не в DONE.

Решение владельца по обеим: оставить active до личной проверки.

- **Схема не различает эпик и ребёнка эпика.** 60 из 76 карточек помечены `kind: epic`,

  по коммиту, офлайн-режим опирается на пустое поле. Чинится `yarn tasks:sync-issues`.

  `docs/actions/device-board/smoke/` и `docs/device-board-scripts/`.

  ссылается на несуществующий `docs/FROZEN_DETECTION_BACKLOG.md`. Та же находка была
