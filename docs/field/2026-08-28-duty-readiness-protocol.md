# Дежурство 2026-08-28 — готовность приборов до живого прогона

> Сегодняшний статус: подготовка. Живой прогон на Firebat и закрытие #2113 — в пятницу,
> руками владельца. Прод и узел этим документом не трогаются.

## 1. Замер журнала #2113

Цель пятничного прогона: на живой ленте `>=2500` доказать число "после" против замера
23.08: количество запросов на одну пробу не растёт с длиной ленты, задержка базы остаётся
в сотнях миллисекунд.

Команда:

```powershell
$env:CABINET_TOKEN = "<token>"
yarn journal:measure-live `
  --api https://cabinet.membrana.space `
  --media-device-id "<mediaDeviceId Firebat>" `
  --min-items 2500 `
  --sample-window-ms 7000 `
  --report-md
```

Что копировать в Issue #2113: весь markdown-блок из stdout. В нём уже есть baseline из
`docs/field/2026-08-23-night-duty-journal-congestion.md`: около 48 запросов и 115 тыс. строк
на пробу при ленте около 2400, задержки базы 3863 / 8108 / 8211 мс под нагрузкой.

Приёмка в пятницу:

| Поле | PASS |
|---|---|
| Feed length | `>=2500` |
| New items | `>=1` за окно замера |
| Requests per observed sample | мало и не зависит от длины ленты; штатно `1` |
| DB latency | среднее меньше 1000 мс; целевой род — сотни миллисекунд |
| Warnings | `none`; иначе Issue не закрывать, а читать named warning |

## 2. Предикат готовности узла #2049

Команда на Firebat:

```powershell
yarn node:duty-ready
```

Ожидаемый вид перед дежурством:

```text
да  · сон и гибернация выключены — ...
да  · автовход есть — ...
да  · служба узла стартует при входе — ...
node:duty-ready — узел к дежурству готов
```

Exit code обязан быть `0` только при трёх "да". Любое "НЕТ" — дежурство не готово:
повернуть названный Windows-переключатель руками и повторить команду. Автопочинки у
предиката нет.

## 3. Smoke первого трека Firebat

Протокол smoke лежит отдельно: `docs/actions/device-board/smoke/FIREBAT_FIRST_TRACK_48K_SMOKE.md`.

Короткий смысл: после свежего запуска сценария первый трек либо принят как `48000 Hz`, либо
capture падает fail-closed с `WEB_AUDIO_SAMPLE_RATE_UNAVAILABLE`. Запись `44100 Hz` не является
допустимым исходом даже если следующие треки идут в 48 kHz.
