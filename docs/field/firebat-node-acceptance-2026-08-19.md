# Приёмка: узел как устройство — firebat-node-device (19.08.2026)

> Судья — Тарасов (тимлид), контекст-прогон и вердикт в `docs/discussions/firebat-node-device-b7.md`.
> Читается как документ, не как лог: что обещано нарезкой · что предъявлено · чем подтверждено.

## Что обещано (нота блока b7 в ратифицированной нарезке)

1. После перезагрузки узел сам поднимает канал (poller службой).
2. С сервера задание «снять пробу» → запись принята media с измерением; id записи в документе.
3. Служебного токена на узле нет — только ключ узла.
4. Усиление — из спутника b6.

## Что поймано деплоем (названо, не спрятано)

- Образ media не собирался из ствола: `.dockerignore` не пускал `wav-decode`/`mfcc-analyzer`, Dockerfile не строил пакеты плагинной основы и не клал их `dist` в runtime (симлинки `node_modules/@membrana/*` в образе висячие) — PR #2008.
- Три сервиса (мост Б, ключ узла, очередь — два из них мои) падали на старте Nest: неинжектируемые параметры конструкторов без `@Optional` → **restart-loop прода ~8 минут** 19.08 16:53–17:01 МСК. Зубы строили сервисы напрямую и этого не видели; e2e-подъёма приложения в CI нет — кандидат в тулинг.
- `prisma migrate deploy` печатает «9 migrations found» при 10 каталогах (считает без `migration_lock.toml`) — ложная тревога, таблица `NodeKey` применена (проверено `_prisma_migrations`).

## Вердикт

Ставит Тарасов по контексту — см. `docs/discussions/firebat-node-device-b7.md`. Предмет вердикта: **приложение узла само держит исходящий канал к серверу под отзываемым ключом, задание с сервера превращается в принятую запись без служебного токена** — доказано на проде с ноутбука-заместителя узла. Два пункта (перезагрузка Firebat, ручка GAIN) — за руками владельца, вещдок допишется строкой в эту таблицу.
