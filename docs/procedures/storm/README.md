# Процедура: storm — шторм

**Определение.** Шторм — дивергентная процедура рождения тезисов: владелец
называет ещё не сведённый предмет, Ангелина ведёт живой конспект, участники
дают реплики, а выходом становится подтверждённый набор тезисов и явная
развилка. Шторм не принимает сходящийся вердикт вместо заседания и не
подменяет исполнимую задачу.

**Держатель:** Ангелина (`leadPersona` манифеста).

## Определение ↔ прогон

Этот каталог — **определение** процедуры. Прогоны живут в `docs/storm/<id>/`:
обычно `THESES.md`, `REPORT.md` и журнал хвостов. Прогон без предмета, без
подтверждённых тезисов или без явной развилки не считается закрытым.

## Движки и канон

Канон процедуры: [`STORM_REGULATION.md`](../../STORM_REGULATION.md).
Операционная дверь Ангелины:
[`STORM_PROCEDURE.md`](../../virtual-team/angelina/STORM_PROCEDURE.md). Место в
ряду форматов: [`FORMATS.md`](../../FORMATS.md). Детерминированные зубы живут в
`scripts/lib/storm-lifecycle.mjs`, `scripts/lib/storm-codex.mjs` и
`scripts/lib/storm-breath.mjs`; тесты рядом с ними проверяют правила выхода и
счётчик вдохов.

## Портфолио

`portfolio` в манифесте показывает не все исторические шторма, а минимальный
видимый набор носителей: закон, операционную процедуру и один живой отчёт
прогона. Мастерская процедурного контейнера читает это поле напрямую и честно
показывает отсутствие портфолио у остальных процедур.
