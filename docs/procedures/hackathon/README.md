# Процедура: hackathon — эстафета четырёх передач

**Определение.** `hackathon` — маршрут разработки для осевой фичи, которая
уже разрезана на последовательную эстафету. Его отличает не календарь сам по
себе, а форма передачи: каждый этап H1-H4 оставляет
`stage-completion-checklist`, пригодный следующему этапу без пересказа из чата.

**Держатель:** Vesnin (`leadPersona` манифеста).

## Определение и прогоны

Этот каталог — **определение** процедуры. Прожитые прогоны живут в задачах,
активных файлах и архиве хакатона:

- `docs/tasks/registry.json`: `device-board-hackathon-1` и дочерние карточки
  `db-h1*`, `db-h2*`, `db-h3*`, `db-h4-alarm-close`;
- `docs/HACKATHON_REGULATION.md`: регламент v0.1 первого хакатона;
- `docs/HACKATHON_ACTIVE.md`, `docs/HACKATHON_LOG_DAY_N.md` и
  `docs/archive/hackathon/**` — носители конкретного прогона, если они есть.

## Жизненный цикл

```
brief + interview
  -> open active
  -> H1 foundation checklist
  -> H2 runtime checklist
  -> H3 extension checklist
  -> H4 close checklist + final audit
  -> closure + return to ordinary rhythm
```

## Четыре передачи против 3-5 дней

Старый регламент описывает календарную длительность первого кейса: 3-5 дней.
Матрица разработки назначила более сильную форму: ровно четыре естественные
передачи H1-H4. Это не конфликт мер, а уточнение несущей оси.

- **День** — ресурс планирования; он может растянуться или сжаться.
- **Передача** — структурный этап; она обязана оставить чеклист для следующего
  этапа.

Если естественных передач больше четырёх, это уже не `hackathon`: маршрут нужно
переназвать через матрицу. Если работа длинная и не требует непрерывной
эстафеты, это кандидат в `marathon`, а не хакатон.

## Обязательные фреймы

| Фрейм | Держатель | Выход |
|-------|-----------|-------|
| `brief` | vesnin | замороженный brief, out of scope и stop rules |
| `interview` | angelina | протокол вопросов владельцу до старта |
| `open` | vesnin | active-файл, ветка, список H1-H4 |
| `h1-foundation` | vesnin | контракт/каркас, готовый к H2 |
| `h2-runtime` | ozhegov | исполнимый путь, готовый к расширению |
| `h3-extension` | ozhegov | расширения без слома H1/H2 |
| `h4-close` | vesnin | обязательный сценарий, финальный smoke, список долгов |
| `closure` | vesnin | CLOSURE, архив задач, возврат к ритму дня |

Каждый H-фрейм пишет один `stage-completion-checklist`: changed artifact,
verification command/result, known gaps, next-stage input.

## Гейты

1. **Owner brief gate.** Без утверждённого brief и interview хакатон не
   открывается.
2. **Stage handoff gate.** Следующий H-этап не начинается без чеклиста
   предыдущего.
3. **Final audit gate.** H4 не закрывается без итогового smoke и списка
   отложенного.

## Что не входит

- `EXECUTION_PROCEDURE` не назначается здесь. Этот маршрут даёт образец формы
  для будущего заседания, но не подменяет общий интерфейс.
- `marathon` не строится из хакатона: у него другая дисциплина нагрузки.
- `competition` не наследуется: у хакатона нет трёх конкурирующих решений,
  scorecard и победителя.
