# Процедура: adr

**Определение.** `adr` — процедура фиксации архитектурного решения ниже
консилиум-гейта: когда полный consilium избыточен, но решение должно быть
записано, грунтовано наблюдаемым состоянием и принято только после LGTM
владельца.

**Держатель:** Vesnin (`leadPersona` манифеста).

## Определение и прогоны

Этот каталог описывает процесс. Сами записи ADR живут в канон-каталоге
`docs/adr/`, а не внутри контейнера процедуры.

## Границы

- `docs/adr/README.md` и `docs/adr/ADR_TEMPLATE.md` остаются домом записей и
  шаблона.
- Контейнер `docs/procedures/adr/` не мигрирует существующие ADR внутрь себя.
- Новый core-контракт, новый пакет, новый узел палитры или L-эпик идут через
  consilium, не через ADR.

## Минимальный ход

1. Взять следующий номер и создать запись из `docs/adr/ADR_TEMPLATE.md`.
2. Заполнить контекст, наблюдаемое состояние, решения с границами, DoD и out of
   scope.
3. Оставить статус `DRAFT` до LGTM владельца.
4. После LGTM перевести в `ACCEPTED` или при замене в `SUPERSEDED-by-ADR-NNNN`.
5. Обновить реестр в `docs/adr/README.md`.
