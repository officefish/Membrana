# Отчёт о выводе EXECUTION_PROCEDURE

## Вердикт

Кандидаты из `docs/procedures/hackathon/FORM_REPORT.md` подтвердились не
полностью. Общим оказался не хакатонный рисунок, а более узкая форма: вход,
ход, gates, держатели кадров, режим, дом, портфолио и прецеденты.

## Что не выдержало проверку как обязательное в исходном виде

| Кандидат | На чём сломался | Решение |
|---|---|---|
| `preflight` | `one-shot`, `containerization` | Частная полоса: у маршрута может быть вход без отдельного preflight. |
| `post` | `one-shot`, `containerization` | Частный хвост: не каждый маршрут имеет отдельную фазу после исполнения. |
| `portfolio.present` | `one-shot`, `day-sprint`, `containerization` | Обязательно само поле `portfolio`, но допустимо честное `missing`. |
| `home.path` | `one-shot`, `membrana-local-sprint`, `hackathon`, `day-sprint` | Обязателен ответ `home`; `home.none` легален и часто точнее. |
| H-этапы и handoff checklist | `cowork`, `competition`, `night-sprint` | Частное хакатона; иначе интерфейс навязывает эстафету. |
| scorecard / winner | `cowork`, `hackathon`, `night-sprint` | Частное competition: у cowork нет победителя, у hackathon нет судейской развилки. |
| поздний Interface Consilium | `one-shot`, `night-sprint`, `hackathon` | Частное cowork: нужен только там, где части строятся изолированно. |
| night handoff / checkpoints | все дневные маршруты | Частное night-sprint: автономная ночь не должна стать обязательной формой разработки. |

## Что появилось сверх списка

Сверх списка появился только явный `procedureKind` в реестре процедур. Это не
поле `EXECUTION_PROCEDURE`, а хвост ADR-0021: без него зуб не знает, к каким
процедурам применять интерфейс разработки.

## Арифметика корпуса

Prompt и ADR называют целевую раскладку `7 / 4 / 12`, но текущая stacked-база
после PR #1607 содержит 23 записи до `adr`, а после заведения `adr` — 24.
Кроме того, сам prompt использует восемь прожитых development-образцов:
`one-shot`, `membrana-local-sprint`, `hackathon`, `containerization`,
`day-sprint`, `cowork`, `competition`, `night-sprint`.

Поэтому машинная раскладка этого диффа честно сходится как:

| Род | Количество |
|---|---:|
| `разработка` | 8 |
| `решение` | 4 |
| `ритм` | 12 |

Подгонять её под `7 / 4 / 12` значило бы либо удалить существующую запись, либо
назвать один из проверенных маршрутов не разработкой. Это было бы хуже, чем
назвать расхождение входа.

## Что осталось частным

Частными остались все поля топологии: эстафета, изолированные блоки, конкурсные
команды, ночные чекпоинты, one-shot порог, sprint-cut/journal и контейнерный
крафт. Они описываются процедурами своих маршрутов, а не общим интерфейсом.

## Что интерфейс не описывает

Интерфейс не описывает решение, ритм и непрожитый марафон. Это правильно:
`meeting` производит вердикт, `storm` производит расходящийся конспект,
`adr` фиксирует архитектурное решение, а ритуалы поддерживают состояние. Ни у
одного из них нет обязанности иметь development-зону и объём исполнения.
