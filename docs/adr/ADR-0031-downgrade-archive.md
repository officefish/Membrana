## Контекст

Слово владельца 05.10 (#2587, #2588): при понижении тарифа со старшего на младший данные сверх квоты младшего тарифа не удаляются сразу, а уходят в **холодный архив**. Живыми остаются записи, отобранные одним из трёх режимов журнальной витрины chart-list; режим — настройка пользователя в кабинете с умолчанием и подтверждением в момент понижения. Разморозка — рукой пользователя, пока не истёк срок. Срок хранения — на пользователя, задаётся в office (умолчание 14 дней, тест 1 день); по сроку архив удаляется.

Ратифицированный канон говорил иначе:

- вердикт M5 заседания `tariff-grid` 29.07 — «**Retain (сохраняется).** … Не delete, не hide-as-missing» (`docs/seanses/tariff-grid-m5-produce-2026-07-29.md:135`);
- `packages/background-cabinet/src/domain/tariff-transition.ts:18` — «Понижение ничего не разрушает»;
- `packages/background-cabinet/src/domain/quota-ledger.ts:17-19` — «Автовытеснение и тихая деградация запрещены: система не решает за пользователя, что стереть».

Наблюдаемое состояние (ствол 796dfd87, замер фазы 1 в `docs/sprint/cut/tariff-downgrade-freeze-2587.json` → `//measure`): понижение — одна дверь `POST /v1/membranes/me/tariff`, меняет ссылку мембраны на тариф и перезаписывает лимиты прибора без сверки с занятым; занятое становится больше лимита, новые записи отказывают обычным путём переполнения; инвариант «used ≤ limit держится всегда» (`overflow-episode-registry.ts:7`) после понижения ложен. Понятий архив / заморозка / срок у записей нет; файлы лежат на диске media, удаление жёсткое.

Отдельно в матрице тарифов есть ячейка **`storage.cold`** (гранула `tariff-cold`, не ратифицирована: датчик 0 = «нельзя», старшие 2048 МиБ). Владелец 05.10: архив понижения — **отдельно** от этой ячейки, ограничен только сроком.

## Решения

### 1. Исключение из M5 «Retain» — принято

> M5 Retain сохраняет запрет **немедленного уничтожения** при смене тарифа. Понижение **по явному подтверждению пользователя** переводит избыток в архив понижения (downgrade-archive); физическое удаление — только по истечении срока партии (`expiresAt`), **не** как побочный эффект смены тарифа. Живая квота после заморозки удовлетворяет новому плану.

Retain остаётся нормой для всего остального: произведённое, детекции, сценарии, пользовательские наборы (v1) не трогаются. Отсылка на этот ADR — одной строкой в `tariff-grid-m5-produce-2026-07-29.md` (рядом с Retain) и в комментарии `tariff-transition.ts:18`. Правка канона без ADR («тихий edit transition.ts») запрещена.

### 2. Носитель архива в media — отдельные таблицы

`DowngradeArchiveBatch` + `DowngradeArchivedSample` (имена с префиксом архива понижения, **не** `ColdTariff*`). Строка пробы переносится из `Sample` в архивную таблицу; **файл остаётся на месте** под `MEDIA_BLOB_DIR` (zero-copy, только метаданные). Существующие запросы `Sample`, `getQuota`, витрины и путь воспроизведения не меняются — архивной строки в `Sample` нет. Пометка статуса на `Sample` — **отклонена** (смешивает словари «живая проба» и «архивная партия», правит все запросы и индексы квоты).

Партия несёт: `deviceId`, `membraneId`, `reason = 'tariff_downgrade'`, `fromTariffId`, `toTariffId`, `criterion`, `planDigest`, `frozenAt`, `expiresAt`, `state ∈ {frozen, restored, deleted, failed}`, `restoredAt?`, `deletedAt?`; индексы `(expiresAt)`, `(deviceId, state)`.

### 3. Служебная дверь кабинета для office — допустима, узкий scope

По образцу `cabinet-register` (ADR-0029, #2393): отдельный токен `CABINET_OFFICE_TOKEN`, не user-JWT. Scope v1: `GET` пользователей мембраны (минимум полей: id, тариф, `retentionDays`, опц. `displayLabel`, `createdAt`; **без** PII, учётных данных, проб, media-URL; пагинация, без поиска по PII) + идемпотентный `PUT retentionDays` на мембрану. Office **не** становится admin-API кабинета; расширение двери — новый ADR. Исполнение — #2588.

### 4. Срок — только снимок

При заморозке кабинет **передаёт** `retentionDays` в приказ media; media пишет `expiresAt = frozenAt + retentionDays` в партию. Смена срока позже **не** пересчитывает старые партии; следующая заморозка читает новое значение и снимает его в свою партию. Уборка — предикат `now >= expiresAt`. Чтение срока при уборке — отклонено (скрытое изменение контракта задним числом).

### 5. Порядок понижения и отказы

Порядок в кабинете: **подтверждённый предпросмотр → заморозка в media → commit тарифа → рассылка лимитов**. Понижение при избытке без подтверждённого предпросмотра — отказ. Media недоступна / заморозка упала / post-condition квоты (`sum(active bytes) ≤ новый лимит`) ложен / партия частичная — **тариф не коммитить**, UI показывает ошибку «тариф не изменён», партия в `failed` с явным id. Компенсирующий откат тарифа — только защита на случай, если commit ошибочно ушёл вперёд; v1 стремится к freeze-first. Media проверяет post-condition **до** ack.

### 6. Отбор «оставить, пока хватает байт» — новый чистый модуль

Режимы chart-list считают штуки, квота — байты. Новый pure-модуль в `@membrana/plugin-handlers` (`selectKeepWithinBytes`): жадное заполнение живого набора под бюджет байт поверх порядка трёх режимов. Приоритет keep: **размеченные и «хранить»** (`isPinnedByHuman`) — первыми; затем порядок режима (`CHART_LIST_CRITERIA` не расширяется, компараторы — адаптеры); при равенстве — **более новая `createdAt` остаётся** (старые в freeze раньше), затем стабильный `sampleId` asc. Пробы без ранга (`modeRank: null`: неизмеримые — тишина, ниже порога, не декодируются) — **после** ранжированных; остаются, пока хватает байт, новее — первыми. Отказ измерителя на предпросмотре — отказ предпросмотра закрытым словарём (`measure_nothing_decodable`, `measure_floor_not_measured`), а не «весь буфер неизмерим». Без Nest, без I/O, unit-тесты с фикстурами равных меток времени обязательны. Байтовый отбор, размазанный по UI, — BLOCK.

> Пересмотрено словом владельца 07.10 после прод-исхода (партия 06d49eec: 8359 из 8360 без ранга → в архив); консилиум 05.10 исходил из неверной посылки об инварианте — байты записи без ранга известны всегда, и добор под лимит инвариант `sum(keep) ≤ limit` не ломает. Issue [#2626](https://github.com/officefish/Membrana/issues/2626), PR [#2627](https://github.com/officefish/Membrana/pull/2627).
>
> **Уточнение причины (приёмка 07.10, [#2629](https://github.com/officefish/Membrana/issues/2629)).** Причина прод-исхода — **записи без ранга** (`modeRank: null`), а не «неизмеримые»: на приёмке после #2627 тот же буфер september (8360 записей) измерен целиком — в каждой нашлось событие громче фона, `unmeasured = 0`, — и строка «не измерено: N» в окне не появилась. Старый отбор морозил всё без ранга независимо от того, почему ранга нет; правило «без ранга — после ранжированных, пока хватает байт» (#2627) закрывает оба случая: итог приёмки — осталось 4379, в архив 3981 (партия 160dba7f). По коду ствола измеренная запись без ранга не остаётся: `modeOrderOf` (media) ставит тех, кого раунды chart-list не упорядочили, в хвост порядка по адресу. Как 8359 записей лишились ранга 07.10, замером не установлено; гипотеза — до #2627 отказ измерителя глотался как пустой набор кандидатов (все `modeRank: null`). Поэтому предпросмотр с #2629 отдаёт обе цифры — `unmeasured` (не измерены) и `unranked` (измерены, но места в очереди режима не получили, стоят в хвосте по адресу), — окно показывает каждую, когда она больше нуля.

## Схема (DDL-очертание под b2 плана)

Очертание, а не миграция: имена и типы — Prisma/Postgres как в `packages/background-media/prisma/schema.prisma`. Это грунт для блока b2 ратифицированного плана, новых решений здесь нет: колонки и индексы названы в стыке с #2588 (план `//junction-2588`) и в решениях 2 и 4.

**`DowngradeArchiveBatch`** — партия: единица заморозки, возврата и удаления.

| Поле | Тип | Null | Индекс / примечание |
|---|---|---|---|
| `id` | `String @id @default(uuid()) @db.Uuid` | нет | PK |
| `deviceId` | `String @db.Uuid` | нет | FK → `Device` (`onDelete: Cascade`); составной `(deviceId, state)` |
| `membraneId` | `String @db.Uuid` | нет | владелец в кабинете, для списка партий пользователя |
| `reason` | `String` | нет | закрытый словарь, v1 одно значение `tariff_downgrade` |
| `fromTariffId` | `String` | нет | тариф до понижения |
| `toTariffId` | `String` | нет | тариф после понижения |
| `criterion` | `String` | нет | режим chart-list (`loudness-over-floor` \| `spectral-variety` \| `drone-likeness`) |
| `planDigest` | `String` | нет | хеш подтверждённого предпросмотра; `@@unique([deviceId, planDigest])` — идемпотентность freeze |
| `retentionDays` | `Int` | нет | снимок срока, переданного кабинетом (решение 4) |
| `frozenAt` | `DateTime @default(now())` | нет | момент заморозки |
| `expiresAt` | `DateTime` | нет | `= frozenAt + retentionDays` суток; `@@index([expiresAt])` — предикат уборки #2588 |
| `state` | enum `DowngradeArchiveState { frozen, restored, deleted, failed }` | нет | `@@index([deviceId, state])` |
| `restoredAt` | `DateTime` | да | ставится при `restored` |
| `deletedAt` | `DateTime` | да | ставится уборкой #2588 при `deleted` |
| `keptBytes` | `BigInt` | нет | сумма живого после заморозки — вещдок post-condition |
| `frozenBytes` | `BigInt` | нет | сумма ушедшего в партию |

**`DowngradeArchivedSample`** — строка пробы, перенесённая из `Sample` целиком; блоб на месте.

| Поле | Тип | Null | Индекс / примечание |
|---|---|---|---|
| `id` | `String @id @db.Uuid` | нет | **тот же** `Sample.id` — возврат восстанавливает строку под прежним адресом |
| `batchId` | `String @db.Uuid` | нет | FK → `DowngradeArchiveBatch` (`onDelete: NoAction`, не `Restrict`: обе таблицы висят каскадом на `Device`, `RESTRICT` проверяется немедленно и ломал бы каскад прибора, `NO ACTION` — в конце оператора; смысл «партия не удаляется, пока есть строки» сохранён — явное удаление живой партии получает отказ БД; принято ведущей 05.10, PR #2594); `@@index([batchId])` |
| `deviceId` | `String @db.Uuid` | нет | `@@index([deviceId])` |
| `collectionId` | `String` | нет | куда вернуть (v1 всегда `__buffer__`) |
| `title`, `class`, `label`, `source`, `durationSec`, `sampleRate`, `channels`, `audioFormat`, `contentType`, `sizeBytes`, `storageRef`, `notes`, `createdAt` | как у `Sample` | как у `Sample` | копия один-в-один, чтобы restore был переносом без догадок |
| `modeRank` | `Int` | да | ранг режима на момент заморозки; `null` — неизмеримая (решение 6) |
| `archivedAt` | `DateTime @default(now())` | нет | — |

Инварианты схемы: строки одной пробы не бывает одновременно в `Sample` и в `DowngradeArchivedSample` (перенос — транзакция); `getQuota` не меняется, потому что считает только `Sample`; хвост `failed`-партии подбирает повторный freeze (строки переносятся в новую партию, `failed` остаётся следом с нулём строк).

## Контракт приказа freeze (под b3/b4 плана)

Дверь media `POST /v1/devices/:deviceId/downgrade-archive/freeze`; вызывающий — кабинет (b4), **до** commit тарифа (решение 5).

Вход:

| Поле | Тип | Смысл |
|---|---|---|
| `deviceId` | uuid (путь) | прибор |
| `membraneId` | uuid | владелец в кабинете |
| `criterion` | режим chart-list | тот же, что в предпросмотре |
| `planDigest` | sha256 hex | **хеш подтверждённого предпросмотра** (`preview` вернул его над отсортированным списком `sampleId` keep/freeze и `bufferLimitBytes`); расхождение с текущим состоянием буфера — отказ, а не «заморозим что есть» |
| `retentionDays` | int ≥ 1 | снимок срока от кабинета (`ArchiveRetentionReader.daysFor(membraneId)`, #2588) |
| `fromTariffId`, `toTariffId` | string | для журнала партии |
| `bufferLimitBytes` | int ≥ 0 | лимит оси на новом тарифе — предмет post-condition |

Выход (200): `{ batchId, state: 'frozen', frozenAt, expiresAt, frozenBytes, keptBytes, sampleCount }`. Повтор с тем же `planDigest` — та же партия, без второй заморозки.

Отказы — закрытый список (литералы чеканятся в `downgrade-archive.dto.ts`, как у словаря переполнения):

| Причина | Когда |
|---|---|
| `preview_required` | `planDigest` не задан или не найден среди предпросмотров прибора |
| `plan_stale` | буфер изменился после предпросмотра: хеш текущего состава ≠ `planDigest` |
| `invalid_retention` | `retentionDays` не целое ≥ 1 |
| `partial_freeze` | часть проб не перенесена (исчезла между preview и freeze) — партия `failed`, тариф не коммитить |
| `quota_invariant_violated` | post-condition `sum(active buffer bytes) ≤ bufferLimitBytes` ложен после переноса — партия `failed` |
| `device_not_found` | прибора нет |

Остальные двери (`preview`, `GET`-список, `restore` с отказами `restore_exceeds_quota` / `archive_expired`) — по `//dod` b3 плана; их словарь — в том же dto, тем же закрытым списком.

## Разведение: downgrade-archive ≠ tariff-cold

| | downgrade-archive (этот ADR) | `storage.cold` (гранула `tariff-cold`) |
|---|---|---|
| Что это | партия избытка **буфера**, замороженная при понижении | тарифная ячейка «холодное хранилище треков», продуктовый объём |
| Ограничение | только **срок партии** (`expiresAt`) | **объём** в МиБ по тарифу (не ратифицирован) |
| Где живёт | media, таблицы `DowngradeArchive*` | класс `cold` в `quota-ledger`, пока никем не позван |
| Связь | **нет**: архив понижения не наследует лимиты ячейки и не занимает её объём; ноль у датчика не запрещает архив понижения | — |

Смешение через месяц — именно то, от чего разводятся имена (`DowngradeArchive*`, не `ColdTariff*`).

## Последствия и границы v1

- v1 морозит **только буфер**; пользовательские наборы (`userStorage`) при понижении остаются как сегодня — без отдельного контракта не трогать.
- Разморозка — рукой пользователя, **целой партией**, и только если партия помещается под текущий лимит; auto-thaw нет.
- Узлы сверх нового `nodes.max` — не трогаются (слово владельца 05.10).
- Уборка: media исполняет `purgeExpired` по `state='frozen' AND expiresAt<=now` условным обновлением; пуск — office `@Cron` ежечасно с выключателем и режимом «только показать» (dry-run по умолчанию до первой боевой уборки). Исполнение — #2588.
- Замороженные пробы не участвуют в живой библиотеке, витринах и DSP-пути; thaw возвращает их в буфер тем же путём декодирования.
- Инвариант `used ≤ limit` на сервере записей восстанавливается после заморозки и снова проверяем предикатом.
