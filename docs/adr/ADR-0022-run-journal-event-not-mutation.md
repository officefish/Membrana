# ADR-0022 — журнал прогонов @1.1: событие вместо мутации; одна форма времени

> **Статус:** ACCEPTED · 2026-08-03 (LGTM владельца в сессии 03.08: «Хорошо, ADR LGTM»)

## Контекст

Слово владельца 02.08: «прогоны должны создаваться каждый раз при вызове процедуры,
журнал должен вестись сразу… писать по логике прецедентов все шероховатости». До 03.08
журнал `procedure-run-journal@1` умел только точечные записи-вердикты: 47 версий
документа дня — ноль записей; ноль fail за всю историю (обрыв не оставлял следа);
запись спринта `one-shot-recut` сделана рукой.

Спринт `run-journal-producer` (ратифицирован 03.08, дайджест `98a24f03…`, PR #1677 и
#1680) расширил схему. Лента append-only с `leafHash` по телу записи — «изменить
состояние прогона» правкой записи невозможно по построению. Веснин (конспект
`block-journal-friction-fail-vesnin.md`): без явной фиксации принципа «через два
спринта кто-то предложит „просто дописать корень на месте"».

## Решения

**Р1. Событие вместо мутации.** Любое изменение состояния прогона — НОВАЯ запись,
ссылающаяся на прежнюю, никогда не правка существующей. Ось `runPhase`, список закрыт:
`open` · `close` · `friction-amend`. Идентичность прогона — `runId`; счёт внутри
прогона — `sequence`, продолжается и не обнуляется (в том числе у close-сироты).

**Р2. started ⟺ open.** Статус `started` законен только у open-записи, open-запись не
несёт ничего другого: «прогон стартовал» — не «шаг отработал», подмена значением `pass`
была бы ложью статусом. Двусторонний инвариант build и validate.

**Р3. Шероховатости по логике прецедентов, симптом обязателен.** `friction[]`:
`symptom` (обязателен — «трение без симптома не наблюдение, а мнение») ·
`root`/`fix`/`prevention` — nullable-долг: в момент прогона честно известен только
симптом. Дозапись корня — `friction-amend` отдельной записью со ссылкой
`amends: {runId, sequence, frictionIndex}` и собственным evidence («дозаписанный корень
доказывается разбором, не словом»). Читатель видит ОБЕ версии по времени.

**Р4. Ленивое закрытие: журнал не ясновидящий.** Обрыв не пишет fail сам — статус
провала требует наблюдателя, пережившего обрыв. Им является следующий open той же
процедуры: он закрывает сирот `fail`/gap `orphaned` со ссылкой
`orphanedBy: {runId, sequence}`. Первый обрыв виден только на втором запуске — это
названная цена, а не дефект. Лента дневная, поэтому промёт кросс-файловый (7 суток,
CLI `procedure-run-record`); сирота закрывается В СВОЁМ файле.

**Р5. Обратная совместимость чтения.** Записи без `runPhase` (вся история до 03.08 и
точечные записи шотов) читаются как закрытые — кандидатами в сироты не становятся.
Новые записи жизненного цикла пишутся строго с `runPhase`.

**Р6. Одна форма времени: UTC `Z`.** Вещдок 03.08 дважды: утренний шот отказал по
`15:25Z`-как-локальному; ревью PR #1680 приняло смешение `+03:00` и `Z` в одной ленте
за нарушение монотонности (опровергнуто арифметикой, но чтение человеком уже
споткнулось). Норма: в ленты журнала `at` пишется в UTC (`…Z`). Существующие записи
с офсетом не переписываются (Р1 запрещает); исключение — `at` open-записи спринта
наследует форму `ratification.at` плана дословно: слово владельца не
переформатируется. Приведение к норме — заботa пишущего инструмента, не читателя.

## Следствия и названные долги

- Производители: ratify → open, gate → close (спринт); цепочки `ritual:day`/`ritual:evening`
  → open/close (ритуалы); шоты — три точки через `buildProcedureRunRecord`.
- Карточка #1681: переезд словаря спринта из `sprint-cut-check` в `lib`; структурный
  `orphanedBy` у кросс-файлового закрытия (сейчас — строкой в evidence).
- Опровергать протухшую запись правкой нельзя и после этого ADR: только новая запись
  (`friction-amend` — для трения; для прочего — следующий прогон).
