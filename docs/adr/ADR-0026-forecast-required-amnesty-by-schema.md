# ADR-0026 — Amnesty-by-schema для forecastRequired: @1 = амнистия, @2 = явный флаг у open

> **Статус:** DRAFT · 2026-08-10 (блок b2 спринта `s-queue-tail-2026-08-10`; рамка —
> вердикт tarasov 10.08, конспект [`../discussions/cut-s-queue-tail-vesnin.md`](../discussions/cut-s-queue-tail-vesnin.md);
> автор формы — vesnin, [`../discussions/block-b2-adr-vesnin.md`](../discussions/block-b2-adr-vesnin.md))

## Контекст

Долг мостика `#forecast-record-step-optional` (open с 07.08): провод «предсказание ↔ исход»
построен (`yarn sprint:experience`, `docs/sprint/experience/forecast-records.jsonl`), но
запись ничем не обязательна — 13 нарезок с записью из 47, последняя 03.08. Гейт
обязательности встаёт в `execution-gate` при `closeProcedureRun` (решение резчика 10.08:
новые проверки — в существующие органы, прецедент 01.08).

Но лента `docs/procedure-runs/` append-only (ADR-0022: событие вместо мутации), и в ней
уже живут прогоны, у которых прогноза исторически нет. Требовать прогноз у прошлого —
значит красить историю; амнистировать по дате или списку исключений — хрупко (Тень
«список исключений»). Тарасов (10.08): BLOCK локальному комментарию гейта — «правило в
подворотне»; ключ амнистии живёт в схеме журнала.

Наблюдаемое состояние (10.08):

- `scripts/lib/procedure-run-journal.mjs:12` — `JOURNAL_SCHEMA = 'procedure-run-journal@1'`;
  `validateProcedureRunRecord` (строка 198) требует точного совпадения `schema`.
- open-записи создаёт инструмент (`ensureSprintRunOpen` при `sprint:cut --ratify`),
  close — `closeProcedureRun` из `execution-gate`.
- Записи прогнозов связаны с прогоном ключом `sprintId == runId`; валидатор —
  `validateForecastRecord` (`scripts/lib/sprint-experience/forecast-record.mjs`).

## Решения

**Р1. Версия схемы — `procedure-run-journal@2`, не `@1.1`.** Маркер обязан быть заметным:
«additive» маскирует смену семантики под косметику, и через месяц никто не вспомнит, что
`@1` = амнистия. Обе версии живут в одной ленте; валидатор принимает закрытый список
`{@1, @2}`, всё прочее — дефект схемы, как и прежде.

**Р2. `forecastRequired` — только у open-записи `@2`, ставит держатель прогона при open.**
У `@2`-записи с `runPhase: "open"` поле `forecastRequired: boolean` обязательно; у записей
других фаз его нет (close-хвост не дублирует флаг — риск рассинхрона open↔close). Ставит
поле инструмент открытия прогона (держатель прогона), гейт его **только читает** —
ответственности не смешиваются (рамка tarasov).

**Р3. Амнистия по построению.** Запись `@1` поля не имеет и трактуется читателем как
`forecastRequired = false`. Ни списков исключений, ни дат: старые прогоны амнистированы
самим фактом своей версии схемы.

**Р4. Что проверяет гейт на close.** Формула:

```
требуется_прогноз(run) :=
  run.schema === 'procedure-run-journal@2'
  && run.runPhase === 'open'
  && run.forecastRequired === true

при требуется_прогноз: close валиден ⇔
  ∃ запись прогноза: sprintId === run.runId && validateForecastRecord(запись) === ok
```

Достаточно `predicted` (прогноз существует и валиден). `observed`/`outcome` — ретроспектива,
она живёт на своём такте после факта; тянуть её в close-гейт значит смешать прогноз и ретро.
Красный исход — **стоп** (exit non-zero), не предупреждение, с подсказкой
`yarn sprint:experience` (долг мостика читается дословно: «стоп, не жалоба»).

**Р5. Скоуп.** Обязательность — только для `procedureId === 'membrana-local-sprint'`.
Другие процедуры (one-shot, ритуалы) наследуют механизм, когда их держатели явно поставят
флаг у своих open-записей; сам ADR им ничего не включает.

## Границы

- Лента не переписывается: `@1`-записи вечно валидны, «миграции» историй нет.
- Следующий гейт со своей амнистией обязан использовать этот же ключ (версия схемы +
  явное поле у open), а не заводить свой — иначе возвращается «правило в подворотне».

## DoD

- [ ] `procedure-run-journal.mjs` принимает `{@1, @2}`; `@2`+open требует boolean `forecastRequired`.
- [ ] `execution-gate` реализует Р4; зубы на оба исхода (амнистия `@1`; стоп `@2` без прогноза).
- [ ] Долг `#forecast-record-step-optional` переведён в settled со ссылкой на гейт.
