Конструкция. Каталог — источник истины о провайдерах (кто существует, где живёт, чем аутентифицируется). Зонд — источник истины о том, **как проверяется живость** конкретного канала. Это две разные оси: «реестр» vs «проба». Смешивать их в одну таблицу — декор без конструкции; сводить надо через явный **join по providerId** с честным именованием несоответствий.

По трём вопросам:

**(1) Тело пробы.** Каталог не должен знать про body — это выходит за его роль (реестр каналов, не тест-план). Держим в зонде отдельную таблицу `probeSpecs: Record<providerId, { path, body, extractLatency }>` рядом с самим зондом. Каталог даёт `baseUrl + apiKeyEnv + apiFormat`; зонд даёт `path + body`. Сборка URL и заголовков — в зонде, по данным каталога. Одна копия знания на каждую ось, join по id.

**(2) voyage вне каталога.** Не «провайдер каталога, не покрытый зондом = находка», а два симметричных зуба на разных множествах:
- `catalog \ probeSpecs` — провайдер в каталоге, но зонд его не пробует → **находка** (пробел покрытия).
- `probeSpecs \ catalog` — зонд пробует то, чего нет в каталоге (voyage) → **не находка, а помеченная категория** `non-chat` / `outside-catalog`, с явной причиной в probeSpecs (`kind: 'embeddings'`).

Зуб врёт, если множества сравниваются симметрично без ярлыков; с ярлыком «почему вне каталога» — не врёт.

**(3) Имена ключей.** Источник истины — каталог (`apiKeyEnv: 'X_AI_API_KEY'`). Алиасы (`XAI_API_KEY`) — миграционный долг, не норма. Место зуба: линтер каталога/окружения, который (а) требует, чтобы `process.env[apiKeyEnv]` был определён для живых цепочек, (б) если задан только алиас — предупреждение «алиас без канона». Зонд читает **только** `apiKeyEnv` из каталога; если инфра ещё поддерживает алиасы — это отдельная задача чистки, не зонда.

Затронутые модули: `scripts/lib/llm-provider-catalog.json` (без изменений схемы), зонд `llm:probe` (убрать `PROVIDERS`, ввести `probeSpecs` + join), линтер имён ключей (новый или в существующем гварде окружения).

Рекомендация: **форма** — ADR не нужен, канон уже есть (каталог = реестр). Если решишь оформлять симметричные зубы отдельной процедурой покрытия — тогда короткая запись в реестре зубов, без ADR.
