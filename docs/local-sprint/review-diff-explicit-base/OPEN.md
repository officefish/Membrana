## Зачем

Строка 7 десятки хендофа 08.08, назначена владельцем. Ревью в режиме `--pr` брало дифф из
`gh pr diff` — ручки **без явной базы**, а вердикт привязывался к одному лишь head и
открывал мердж. Гейт заявлял «этот код осмотрен на этой ревизии», не называя, **чем** был
осмотренный код.

## Два дефекта разной природы

- **A. Кэш отстаёт — транзиентно.** Вещдок 07.08 (PR #1769): 23 файла против 13.
  Проверено 08.08 — **не воспроизвелось** ни на одном из трёх PR: #1728 (1/1), #1793 (27/27),
  #1801 (31/31/31 при том, что ствол вливался трижды). Чинится всё равно: источник без
  явной базы не даёт права быть уверенным.
- **B. В вердикте нет базы — всегда.** Маркер `pr-1801-code-review.md` нёс только
  `sha:348646c1…`. Постфактум проверить предмет осмотра было невозможно в принципе.

## Итог блоков

- **b1** — маркер вердикта принял поле `base:` (опционально, техникой `lead`/`at`);
  `reviewGateDecision` получил ветку сверки базы **между** «протух по head» и «прочитан
  срез» — место выбрано исполнителем: сначала тот ли head, потом та ли база, потом весь ли
  объём. Исход — `unknown`, не `block`: код не отвергнут, он не осмотрен на текущей границе.
- **b2** — [`review-diff-source.mjs`](../../../scripts/lib/review-diff-source.mjs): дифф
  добывается `gh api compare` (база и файлы согласованы в одном ответе, работает для
  чужого PR без выкачки ветки), локальный `merge-base` — фолбэк по канону
  `pr-recreate.mjs:88-93`, `gh pr diff` из тракта убран. Обрез ручки распознаётся по
  потолку `files[]` и по файлу с изменениями без патча.
- **b3** — CLI считает текущую merge-base тем же источником и отдаёт ядру; `--restamp`
  **сохраняет** базу прежнего маркера, а не подставляет сегодняшнюю.

Зубов: **83** на четыре семьи. Живые прогоны: чужой PR #1793 (`source=gh-compare`,
`head_match=false` названо), legacy-артефакт #1801 (проходит как прежде), сквозной прогон
ревью — маркер получил `base:1a092353`, артефакт получил блок `review-source`.

## Кто передаёт `currentBase` — доказательство грепом

Ревью PR #1807 просило подтвердить, что «все три потребителя» передают базу. Потребителей
решения **два**, и оба в одном файле:

```
$ git grep -n "reviewGateDecision({" -- 'scripts/**' | grep -v test
scripts/review-gate.mjs:154:  … reviewGateDecision({ headSha, currentBase, verdict: … })
scripts/review-gate.mjs:175:  … reviewGateDecision({ headSha, currentBase, verdict: … })

$ git grep -n "reviewGateDecision({" -- 'scripts/**' | grep -v currentBase | grep -v test
(пусто)
```

Трёх потребителей нет: `task-pr-land.mjs` и `code-review-ritual.mjs` импортируют из ядра
`parseVerdict` и `renderVerdictMarker`, а не само решение. Вызовы без `currentBase`
остались только в зубах — намеренно: они держат контракт «без базы поведение прежнее».

## Спор, решённый владельцем

Исполнитель b1 (Ожегов) требовал: legacy-вердикт без базы → `unknown`, «иначе legacy
становится дырой навсегда». Ратифицированный план говорит обратное: старые маркеры
открывают мердж как прежде. Владелец подтвердил **дважды**, второй раз явно после
возражения. Цена варианта Ожегова была измерима: сегодня же встали бы соседние PR с уже
вынесенными вердиктами, включая #1793 живой сессии.

**Возражение остаётся долгом:** маркер без базы недоказуем постфактум, и ратификация это
не лечит, а откладывает. Срок жизни legacy — отдельное решение владельца.
