## Приёмка ведущей 29.09 — выход за зоны и перерезка задним числом

Сверкой файлов стека #2517–#2521 с ратифицированными зонами найдено **9 файлов кода из 19 вне зон**;
отчёт о сдаче их не называл. Три — реэкспорты бочек пакетов (`plugin-contracts`, `plugin-handlers`,
`media-library`), без которых новый контракт не виден снаружи. Существенный — **порт**
`packages/services/media-library/src/ports/storage-backend.ts`: опциональный позиционный метод
`requestCollectionDetectorBatch`, только для серверного бэкенда. Это образец, закреплённый
арбитражем 27.09 после столкновения двух PR на этом же шве, и место санкционировано консилиумом
(`docs/seanses/batch-collection-run-contour-architecture-gate-2026-09-29.md`, строка 83).

**Причина структурная, не небрежность.** Консилиум был первым блоком нарезки, а зоны остальных
блоков нарисованы до него. Консилиум определил, куда ляжет код, — и после него была нужна
перерезка, которая не сделана. Урок процедуре: **блок, решающий форму, должен предшествовать
нарезке зон тех блоков, чью форму он решает** — или зоны после него перерезаются явно.

**Пробел ведущей.** Сессиям Claude после ратификации ведущая писала «зоны — контракт, выход за них —
перерезка». Сессии Codex, ратифицированные владельцем напрямую, этого указания не получали ни разу.

**Решение владельца 29.09:** перерезать задним числом и слить стек. Оформлено по правилу: прежнее
согласие снято, зоны расширены, акт перерезки в ленте, новая ратификация инструментом, `sprint:cut`
→ `contract`.

Приёмка ведущей своими руками: CI зелёный на всех пяти PR, `review/teamlead=success` опубликован
на каждой вершине; консилиум настоящий (метка `yarn consilium`, 36 реплик ролей) и предшествовал
коду; **порча** — снят различитель исходов `rejected`/`completed` в контракте → проверка типов
исполнителя пакетного прогона падает в четырёх местах (`TS2322`), контракт охраняется типами
потребителей. Отдельного теста у контракта нет (файл `batch-collection-run.test.ts` в зоне был, но не
создан) — охрана только типами.
