## 2. Шаги

### 2.0. Команды чтения ведущей

Все команды — **только чтение**, через `node scripts/_ssh-media-exec.mjs` (нужен корневой `.env`
с `BACKGROUND_MEDIA_*`; разрешение владельца на чтение прода — вопрос В6). Чтобы не воевать с кавычками,
удалённый текст кладётся в файл в `%TEMP%` и передаётся `node scripts/_ssh-media-exec.mjs "$(cat <файл>)"`.

Общая приставка удалённой команды:

```sh
DC="docker compose -f /root/membrana/packages/background-media/docker-compose.yml -f /root/membrana/deploy/background-media.prod.compose.yml --env-file /etc/membrana/media.env"
SQL() { $DC exec -T postgres psql -U membrana -d membrana_media -At -F ' | ' -c "$1"; }
# двери media изнутри контейнера: токен не покидает контейнер и не печатается
DOOR() { $DC exec -T media-api node -e "fetch('http://127.0.0.1:3010/v1/internal/downgrade-archive/'+process.argv[1],{headers:{'X-Membrana-Token':process.env.API_INTERNAL_TOKEN}}).then(async r=>console.log(r.status, await r.text()))" "$1"; }
BLOBS=/var/lib/membrana/media-blobs   # MEDIA_BLOB_HOST_DIR по умолчанию (deploy/background-media.prod.compose.yml:26)
```

### 2.1. Круг 1 — «Наблюдательный пункт» → «Блокпост» (буфер 4096 → 2048 МиБ)

### 2.2. Круг 2 — «Блокпост» → «Датчик» (буфер 2048 → 512 МиБ)

Тот же порядок, что 1.2–1.10, с партией `B2`, прогоном `R2`:
- 2.1: Q1 — буфер > 512 МиБ (после круга 1 обычно уже так; дописать записью с прибора по Т4 — вопрос В4);
- 2.2: понижение на «Датчик» с подтверждением; срок по-прежнему 1 день (П7);

## 3. Переход выключено → dry-run → live

Флаги — **только владелец**, в `/etc/membrana/office.env` на VDS office, затем перезапуск office
(`node scripts/_ssh-office-prod-up.mjs`). Переключателя в панели нет (вердикт 8, ADR-0032 Р5).
Смысл значений — `packages/background-office/.env.example:50-75`: ENABLED включён только `true`/`1`,
DRY_RUN выключен только `false`/`0`; опечатка = безопасная сторона.

| Этап | Флаги | Когда | Что видно | Условие перехода дальше |
|---|---|---|---|---|
| A. Выключено | `ENABLED=false` | исходное | режим `disabled`, пульс `disabled`; cron media не зовёт, строк `trigger=cron` не прибавляется (Q6). Превью владельца (`GET /v1/panel/admin/cold-archive/sweep-preview`) пишет строку `trigger=panel`, `enabledSnapshot=false` (решение 20.11) | П1–П8 выполнены |
| B. Холостые прогоны | `ENABLED=true`, `DRY_RUN=true` | **до шага 1.3** круга 1 | каждый час строка `trigger=cron`, `mode=dry_run`, `succeeded`; пульс `ok`; кандидаты = истёкшие `frozen` всех пользователей (D4/Q2) | **не меньше 3 подряд** успешных cron-прогонов `dry_run` и пульс `ok` (число — предложение, вопрос В2); владелец видел список кандидатов первого live (П10) |
| C0. Копия | — | непосредственно перед C | дамп БД media и копия тома (`docs/deploy/BACKGROUND_MEDIA_DEPLOY.md`, раздел 7) | копия названа в протоколе |
| C. Боевая | office `DRY_RUN=false` **и** media `PURGE_LIVE_ENABLED=true` (второй ключ, [#2699](https://github.com/officefish/Membrana/pull/2699), ADR-0032 Д3) | **после** холостых и копии, до `expiresAt(B1)` | первый live-тик удаляет все истёкшие `frozen` (до 20 за прогон). Без второго ключа media отказывает live-вызову, даже если office прислал `dryRun=false` | слово владельца «включаю боевую» — в чате, записывается в протокол дословно |

ставит владелец в окружении media, затем перезапускает media. Откатить live можно любым из двух ключей: office
`DRY_RUN=true` или media `PURGE_LIVE_ENABLED=false`. 20.11 оба ключа проверены в контейнерах до первого live
(см. [`CLOSURE.md`](./CLOSURE.md)).

После приёмки: оставить C или вернуть B/A — отдельное слово владельца (план: боевое включение на
постоянной основе — вне g7).

## 4. Критерий «принято» и протокол

**Принято**, если для **каждого** круга (`B1`/`R1`, `B2`/`R2`) одновременно:
1. Удаление произошло **по расписанию** (`trigger=cron`), без ручного запуска, на первом или втором
   тике после `expiresAt` (≤ 2 ч);
2. Журнал: прогон `succeeded`, задание партии `succeeded`, `failed=0`, `dead_letter=0`;
3. Аудит `verify` сейчас: `clean=true`;
4. База: партия `deleted`, строк архива 0;
5. Диск по снимку Q4, независимо от журнала: `exist=0 of N`;
6. Пульс `ok` после прогона; живой буфер на сервере ≤ лимита нового тарифа;
7. Ни одной кнопки удаления в панели не появилось; превью из панели (если делали) — `trigger=panel`
   и пульс не освежило (#2690).

Не принято — любой пункт ложен. Частичный успех («журнал чистый, а на диске файлы есть») — **не принято**:
это ровно та ложь, ради которой строился журнал (ADR-0032 Р4).

**Протокол (`CLOSURE.md`)** — по кругу: время понижения; `B`, `frozenAt`, `expiresAt`, `frozenBytes`,
`keptBytes`, Q3 (записей в архиве); Q5 до; id `R`, его `startedAt/finishedAt`, счётчики; исходы задания; `verify`
целиком (булевы, без путей); Q2/Q3/Q5 после; пульс до/после. Плюс: флаги и время каждой смены (кто), дословное
слово владельца на live, данные копии (C0), отклонения от сценария и их причины. Затем — дополнение
ADR-0031 и ADR-0032 (DoD g7; в ADR-0032 — решение 20.11 про `trigger=panel`).
