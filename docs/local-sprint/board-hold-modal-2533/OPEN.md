### 2. Почему «ещё не подтверждено сервером» — и почему это навсегда

- `overflowId === null` бывает только у эпизода **локального стража** (`deviceOverflowHold.ts:191-201`);
  серверный отказ несёт `overflowId` всегда (`wiring.ts:19-30`, предикат словаря).
- Страж входит в удержание при **95 %**: `BUFFER_STOP_RATIO = 0.95`
  (`packages/services/media-library/src/buffer-stop.ts:26`, `stopDecision` :83; `localGuard.ts:16-19`),
  по каждому обновлению квоты (`micBufferRecorderPlugin.ts:362-375`).
- Сервер отказывает при **`used + incoming > limit`** (~100 %):
  `packages/background-media/src/modules/samples/buffer-overflow-refusal.ts:100-102`, `samples.service.ts:224`.
- После входа стража шлюз закрывает POST: `wiring.ts:49` → `server-storage-backend.ts:598` бросает
  `UPLOAD_HELD` до `fetch`. Сервер не видит ни одной пробы → эпизод не чеканит → `promoted`
  (`deviceOverflowHold.ts:171-175`) не наступает никогда.
- Живые числа: **486.7 MB / 512 MB = 95.06 %** — первое пересечение порога стража, не серверный лимит.

Вывод: фраза «ещё не подтверждено сервером» — **постоянное** состояние каждой остановки при политике
`stop`, а не переходное. Она обещает подтверждение, которого не будет.

### 3. Гипотеза задачи (#2319, рестарт media) — для этого окна не работает

- Канала сервер→клиент об эпизоде нет: серверный реестр (`overflow-episode-registry.ts`, память процесса)
  читается только при чеканке отказа на POST (`samples.service.ts:229`); `GET /quota` overflow-полей не несёт
  (`devices.dto.ts` — только `bufferPolicy`).
- Эпизод клиента живёт в `localStorage` (`OVERFLOW_HOLD_STORE_KEY`, `deviceOverflowHold.ts:21,54-94`) и
  переживает перезагрузку; рестарт сервера его не касается.
- При переносе сервер сам закрывает свой эпизод (`samples.service.ts:447`) — даже если бы он был.
- Одно чтение прода (штатный путь: `GET /v1/devices/9e86ec85…/quota`, заголовок `X-Membrana-Token`
  = `VITE_MEDIA_API_TOKEN` из `.env` главного дерева, значение не печаталось):
  `buffer 0 / 536870912`, `userStorage 510302892 / 536870912` (95.05 %), `bufferPolicy stop`, HTTP 200.
  С `API_INTERNAL_TOKEN` — 401 (в `.env` заглушка).
- Кандидат «страж перевходит после вывоза по чужой оси (наборы 95 %)» опровергнут: эмиттер квоты берёт
  `resolveBufferQuota` (`mediaLibraryHubBridge.ts:39`), серверный бэкенд всегда пишет `bufferUsedBytes`
  (`server-storage-backend.ts:376`; при недоступности — нули, `:385`).
- #2484 (`startOverflowHoldVitals` не подключён) — к противоречию не относится: окно перечитывает квоту
  при открытии само (`OverflowWindowHost.tsx:87-92`), потому «сейчас 0 B» и было живым.

### 4. Корень

**Контракт #2314 верен** (удержание снимается только явно: `release('human'|'cleanup')`, авто-возобновления
нет — M3 DoD 7, зуб `deviceOverflowHold.test.ts:171`). Удержание «держится после вывоза» — правильно.
**Неправильны слова**: все три поверхности (заголовок/плашка окна, бейдж шапки, плашка микрофона) берут
слово «полон» из **замороженного эпизода** и не знают, что место освобождено; фаза локального эпизода
обещает подтверждение сервера, которого при политике `stop` не бывает по построению (95 % < 100 %).

Два дефекта, один класс — «данные не декорация» (Родченко): 1) нет состояния «место освобождено, удержание
не снято» в view-model; 2) лексика фазы `held_local` лжёт о будущем.

## Что НЕ входит

- **#2319** — носитель эпизода на сервере (память процесса media). Серверный долг; окном не читается, к
  симптому не относится (§3). Остаётся открытым.
- **#2484** — `startOverflowHoldVitals` не подключён. Отдельный выбор «подключить или снять»; здесь живая
  ось читается снимком сервиса, который обновляет хост при открытии окна и любой другой читатель.
- Счётчик «Записано до остановки» — носитель C его не несёт (#2316); строка остаётся «н/д» (развилка 4).
- Порог стража 95 % против серверных 100 % — не двигается (решение M3).
- Авто-снятие удержания по освобождению места — запрещено (M3 DoD 7).
- Квота наборов 486.7 / 512 MB («перенос не освободил, а переложил») — продуктовый факт, отдельный билет.
- Кабинет и его предикаты `dead` / `stopped_buffer_full` — не трогаются.

## Развилки на слово владельца (не решаются спринтом)

1. Заголовок при `freed` — «Место освобождено — снимите удержание» (умолчание) или короче «Место есть — снимите удержание».
2. Цвет бейджа доски при `freed` — жёлтый (умолчание; красный оставит ложную тревогу) или красный.
3. Фаза локального эпизода — «удержание · по стражу прибора (до отказа сервера не дошло)» (умолчание) или сухое «удержание · локально».
4. Строка «Записано до остановки: н/д» — оставить вне спринта (умолчание) или убрать, раз рядом «В буфере при остановке».
5. Порог `freed` — ниже 95 % `BUFFER_STOP_RATIO` (умолчание, симметрично стражу) или строго 0 B.
6. Наблюдение «бейдж держится при идущем луче» — **до** нажатия «Возобновить» или **после**? Если после — это второй факт (перевход стража, которого код не допускает) и не этот спринт.
