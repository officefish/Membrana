**Механизм.** Левая группа `flex-1 min-w-0` сжимается до остатка. Внутри неё сжимается только крошка (до нуля); остальные
дети `shrink-0` в сумме шире коробки и **вытекают вправо** (`overflow: visible` по умолчанию) — под правую группу. Правая
группа `shrink-0` ширину держит и стоит **позже в DOM**, поэтому рисуется поверх вытекшего бейджа: «текст обрезан, видна
галка». Из широких `shrink-0`-детей бейдж удержания стоит последним — страдает он. Фиксированных ширин нет.

**На каких ширинах.** Расчёт по шрифтам daisyUI (не замер): левая ≈ 228 (отступ) + 20 + ~92 («Сохранить») + 120–250
(server-first) + ~230 (бейдж, 33 знака `text-xs`) + промежутки ≈ 750–880 px; правая ≈ 700–760 px. Порог наложения ≈
**1450–1600 px** ширины окна при сопряжённом приборе с удержанием; при 1270 px дефицит 200–350 px — совпадает со снимком.
Заголовок бейджа приходит готовой строкой из клиента (`useOverflowHoldBoardView.ts:40-41`:
`${OVERFLOW_TITLE_BY_STANDING[standing]} · ${reasonText}`); для оси пользователя строка длиннее — укорочение слов наложение
не лечит, только отодвигает. Движка раскладки в jsdom нет — порог тестом не измерить; честный зуб — структурный (ниже).
