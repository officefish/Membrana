## Зачем

Читатель ритуала судит по документу, а не по предмету. Два симптома одного класса, оба замерены 29.09:

1. **Фидбек не видит сделанного.** Архитектурные слоты 27.09 по #2488/#2489 дали билеты #2492–#2498.
   Вечер читает `DAY_DOC_INPUTS` + git дня + гейт; билетов нет ни в одном входе. Четыре вечера
   (26, 27, 28.09, каркас 29.09) требуют слот, который сделан.
2. **Каркас дня врёт о перечеканке.** Генератор подкладывает `main-day-assertions.json` как текст,
   обрезанный до 22 000 знаков из 115 531. В окне — `//date` «Перечеканено 24.09» и
   `sources[0].date = 2026-09-29`; `//recut-29-09` и архив — за границей. Модель верит `//date`.

## Что показал замер (уточнение к заданию ведущей)

- Гипотеза «генератор читает архивные ключи `//retired-*` и принимает за текущее» — **опровергнута**:
  `//retired-rollout-magistral-24-09` лежит на позиции 70 456, `//recut-29-09` — 76 851, окно
  чтения — 22 000. Генератор их не видел.
- Настоящий корень симптома 2: мета-ключ `//date` застрял на 24.09 (перечеканки 28.09 и 29.09 писали
  только `//recut-*`), а факт свежести (`magistralFreshness` — предикат `yarn main-day-probe`) ни в
  каркас, ни в вечер не подаётся. Чинится читатель: проекция вместо сырого текста + строка свежести
  тем же предикатом. `//date` как долг чеканщика — ведущей, не спринту.
- Симптом 1: очередь `review:oversized` снимает PR только по host-local артефакту
  `docs/discussions/pr-N-code-review.md` (.gitignore) или commit-status `review/teamlead=success`.
  #2488 — голова очереди; #2489 снят артефактом от 27.09 13:38Z, которого нет на других клонах.
  `gh issue list --search "2488 created:2026-09-27..2026-09-29"` → #2492 #2493 #2494; по 2489 →
  #2492 #2495 #2496 #2497 #2498. Данные для «книги сделанного» есть, читателя нет.
