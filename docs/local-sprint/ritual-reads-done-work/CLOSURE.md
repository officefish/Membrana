## Что оказалось предметом

Читатель ритуала судил о свежести по **комментарию в файле**, а о сделанном — по **документам,
в которых сделанного нет**. Оба симптома — один класс: вход суждения не тот предмет, о котором
выносится вердикт.

- **Каркас дня.** `main-day-assertions.json` (115 531 байт) подкладывался текстом через
  `readBounded(…, 22_000)`. В окне — мета-ключ `//date` «Перечеканено 24.09» и `sources[0].date =
  2026-09-29`; `//recut-29-09` (позиция 76 851) и архив `//retired-*` (70 456, 74 273) — за окном.
  Гипотеза «читатель принимает архив за текущее» **опровергнута**: он архив не читал. Модель разрешила
  противоречие в пользу `//date`. Факт свежести (`magistralFreshness`, предикат `yarn main-day-probe`)
  в промпт не подавался.
- **Вечер.** Входы — `DAY_DOC_INPUTS`, git за день, гейт. Билеты #2492–#2498 по слотам 27.09 не
  несёт ни один вход; очередь `review:oversized` снимает PR только по host-local артефакту
  (`.gitignore`) или commit-status. Четыре вечера команда требовала сделанное.

## Признанные пределы (для ведущей и владельца)

1. Билет без явного `#PR` в заголовке/теле (по имени ветки, по файлу) книгой не находится — ноль
   ложных связок ценой возможных ложных «не заведён». Критерий — умолчание, принятое владельцем 29.09.
2. `gh issue list` — один запрос, лимит 200 билетов за окно (сегодня 43); хвост за лимитом не увидится.
3. Ствол книги — `origin/main` как его знает клон (без `fetch`); вечер идёт после доставки в ствол.
4. День предиката в каркасе — UTC (как у probe), прочие входы каркаса — локальный день; расхождение
   возможно только между 21:00Z и полуночью MSK.
5. `//date` в `main-day-assertions.json` по-прежнему «24.09» — **долг чеканщика, чинит ведущая
   отдельным коммитом ПОСЛЕ этой живой проверки** (слово владельца 29.09). Читатель теперь этим полем
   не судит, так что поле — след для человека.
