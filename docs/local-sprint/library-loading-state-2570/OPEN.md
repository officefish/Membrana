## Симптом (владелец 03.10, Studio `d8105f64`, прибор `9e86ec85`, «связан»)

Сразу после старта модуль показывает жёлтое «Ограниченное локальное хранилище · Media-server недоступен · 0.0 / 100.0 MB»,
коллекций нет, «Нет сэмплов». Через несколько секунд — «Хранилище сэмплов · Файлы на media-server · 486.7 / 4096 MB».

## Причина — три слоя (ствол `0d39cbad`)

1. **Начальный снимок.** У любого сервиса, в том числе серверного, — `backend: 'browser-limited'`, `serverReachable: false`,
   100 МБ. «Не прочитано» = «запасной». Серверный сервис держит его до конца первого `refresh()`, где квота — **последний**
   шаг после 209 GET проб буфера (#2571). Отсюда «несколько секунд».
2. **Ленивый default до подмены.** `getDefaultMediaLibraryService()` создаёт настоящий browser-limited сервис, модуль и
   панели зовут на нём `init()`. Мост пингует media до 3 раз (400/800 мс), потом `configureDefaultMediaLibraryService` —
   подмена **никого не оповещает**; `useMediaLibrary` переподписывается только при случайном ререндере.
3. **Режим → баннер.** `resolveMediaLibraryStorageMode` (`quota-status.ts:13-17`) всё не-серверное зовёт
   `browser-limited-fallback`; `MediaLibraryQuotaBanner.tsx` печатает «Media-server недоступен».

Подлинный отказ уже различим: мост при неудачном `attachService` ставит запасной сервис и инициализирует его.

**Пересечение с #2572.** Сверка открытия `refresh()` не зовёт. Но `refresh()` ставит `datasetSamplesCatalogId` сразу после
квоты: если квоту читать первой, присваивание должно остаться **после** списков проб — иначе сбой списков оставит
«набор загружен для каталога X», и сверка пропустит перечитывание. Зуб P10.

## Механика (умолчание)

- `MediaLibrarySnapshot.loadState: 'loading' | 'ready'` — один источник для баннера и модуля; `ready` — только после
  успешного `refresh()` целиком.
- `refresh()`: квота **первой** → промежуточная публикация (числа) → списки → в конце `datasetSamplesCatalogId` и `ready`.
- Ленивый default — **временный**: `init()` не исполняется, снимок `loading`; подмена оповещает
  `subscribeDefaultMediaLibraryService` ровно один раз; `useMediaLibrary()` без аргумента следит за подменой.
- Баннер: `loading` короткозамыкается **до** режима хранилища — «Хранилище сэмплов · Загрузка коллекций…», тон info,
  без чисел и без «Media-server недоступен». Модуль: вместо «Нет сэмплов» — та же константа.
- Мост, `quota-status.ts`, бэкенды, сервер — не трогаются.

## Развилки на слово владельца

1. **Источник «загрузки»:** **явное поле `loadState`** (умолчание, резчик) или вывод из `quota.readAt` (без поля, но
   путается с отказом серверного чтения).
2. **Ленивый default:** **временный + оповещение о подмене** (умолчание, резчик) или только оповещение (меньше правка,
   вспышка жёлтого до подмены остаётся).
3. **Промежуточная публикация квоты:** **да, числа раньше списков** (умолчание; цена — лишний цикл политики моста на старте)
   или одна публикация в конце.
4. **Панель микрофона** (стартует в том же ложном «browser-limited-fallback», через хаб моста): **отдельный билет**
   (умолчание плана: +мост и состояние плагина, ≈+80 строк, своя приёмка) или в этот же PR — **совет резчика** (иначе два
   источника истины про загрузку).
5. **Слова:** «Загрузка коллекций…» одной константой — умолчание; по слову владельца — Ожегову.
