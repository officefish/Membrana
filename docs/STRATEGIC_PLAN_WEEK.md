## 3. Риски и долг

### Технические риски

1. **Дрифт архитектурной правды** (Night Hunt drifts)
   - Design token drift: UI-компоненты расходятся с `DESIGN.md`
   - API contract drift: сервисы берут друг у друга типы неофициально, минуя `@membrana/core`
   - **Влияние:** когда нарастёт число сервисов (детекторы эшелона 1.B), перекрёстные зависимости снесут изоляцию
   - **Действие:** ревью дрифтов перед вводом `detection-ensemble` и `agentic-detector`

2. **Заморозка Этапа 2 без резервного плана**
   - TDOA, мультиузловая синхронизация, локализация — все типы в `@membrana/core` помечены `@experimental @stage 2`
   - Код заморожен, документация актуальна, но нет живого прототипа, который подогревал бы интеграцию при добавлении узлов
   - **Влияние:** если потребуется многоузловая демонстрация, потребуется спинт на раскрытие инструментов
   - **Допуск:** TDOA-разведка (сигнатура синхронизации, калибровка по известным источникам) может идти параллельно в отдельной ветке без блокировки основной цепи

3. **Непроверенная интеграция буферов узла**
   - Буферы аудио (ringbuffer) живут в audio-engine, но связь между квотой tariff и размером буфера — диагностирована, не реализована
   - **Влияние:** полевые узлы с ограниченным хранилищем (IoT) не смогут адаптировать буфер к своему лимиту
   - **Действие:** добавить `AudioEngineConfig.maxBufferDurationMs` с явной ссылкой на `device.tariff.bufferLimitBytes`

### Ограничения из WHITE_PAPER, релевантные сейчас

1. **Синхронизация времени (§9)** — GPS-PPS на ответственных узлах, кросс-калибровка. Без этого TDOA неточна. Сейчас никакой инфры (пока не актуально).
2. **Многолучёвость (§9)** — отражения от зданий искажают TDOA. GCC-PHAT и медианная фильтрация — в плане Этапа 2, на практике не реализованы.
3. **Скорость звука (§5.3)** — задержка доли сек/км лимитирует размер квадрата. Этап 2 молчит об адаптации метеоусловий (T, влажность).
4. **Этика буферов (§10)** — TTL для сырого аудио не реализован; это потребуется при включении полевых узлов.
