## 2. Магистраль недели: замкнуть звено «запись → разметка → приёмка»

### Задача A — Полевой сбор пригодного корпуса (высший приоритет)
**Почему:** оборудование приехало, полевое время конечно, съёмка выводом детектора **запрещена** (`#1955` — риск самозамера уровнем выше).
- Снять по протоколу `SESSION_V_CAPTURE_PROTOCOL_2026-08-16.md`: полигон (чистые дрон-положительные) + городской фон как отрицательные + круглосуточный полевой узел.
- Соблюсти четыре условия пригодности (`#1954`): отрицательные, похожие на цель (не тишина); разброс по дистанции/высоте; повторы условий; равные классы.
- Учесть объём заранее: ~317 МБ/час, ~53 ГБ/неделю — заложить хранение и правило случайной выборки фона.
- **DoD:** корпус ≥ N записей (определить с владельцем), классы сбалансированы, метаданные (что/дистанция/высота/место) объявлены человеком и **не смешаны** с измеренными сервером полями (защита от долга `#1950`).

### Задача B — Разметка слепого корпуса → операторская истина
**Почему:** звено 3 порвано; без истины приёмочное число — фикция (`#1940`, `HANDOFF`).
- Разметить слепой пилотный корпус (`vdr-hard-gate-pilot/samples/`, 33 записи) вслепую.
- Проверить intra-rater ≥ 95% (требование VDR hard-gate из WHITE_PAPER §8).
- Перенести метки по `blind-map.json` (механика переноса уже проверена: applied=3, unmatched=0).
- **DoD:** размеченный корпус с операторской истиной + зафиксированный intra-rater.

### Задача C — Первое честное приёмочное число
**Почему:** mfcc в бенчмарке есть, но 0.732 — самозамер; настоящее число считается по операторской истине.
- Прогнать `benchmark:detectors` на размеченном пилотном корпусе (не на train-порогах v0.2).
- Свести одной таблицей на пилоте: mfcc / trends+`DRONE_TIGHT` / yamnet — кто кандидат в hard-gate, кто объяснимый бэкап (это поддерживающая задача из приоритетов, теперь становится ядром).
- **DoD:** таблица метрик на *независимом* корпусе с явной пометкой «не самозамер»; вердикт по hard-gate 85/90 — pass/fail зафиксирован.
