# Заседание bridge-ledger-toolset · M1–M3 — РУЧНАЯ МОДЕЛЬ (ждёт ратификации владельца)

> **Честная пометка (S-M2):** это НЕ состоявшийся консилиум — фолбэк-канал его не держит
> (долг `converging-formats-fallback-dead`). Ручная модель одним агентом: линзы ролей
> честные, но НЕзависимые. Вес даёт **ратификация владельца** (`author=human`), не процесс.
> Порядок — из M0 (owner-ratified): M1 контракт → M2 форма → M3 зубы.

## M1 — контракт вещдока долга

**Посылки:** аудит машинен только над структурой (журнал: 38% «audit-открыто» на вольном тексте); `codereview-single-provider` протух, потому что `code-review.mjs:160` никто не валидировал.

**Линзы:**
- **Структурщик:** вещдок = типизированный union, у каждого типа свой резолвер.
- **Математик:** каждый тип обязан давать **решаемый** предикат `resolved | live | unknown`.
- **Ожегов:** имена типов однозначны; `run` = записанный прогон/артефакт (сеанс, CI), не «вообще».
- **Верстальщик:** вещдок рендерится ссылкой-действием (symbol→file:line, issue→gh) — как live-links.
- **Музыкант:** у вещдока есть часы свежести — `verifiedAt`, перепроверка каждым аудитом.

**Вердикт-кандидат M1:**
```
debt.evidence = { kind, ref, verifiedAt }
kind ∈ { symbol | issue | file | run | prose }
резолвер по kind → resolved | live | unknown :
  symbol  grep/граф: маркер исчез → resolved
  issue   gh state: CLOSED/MERGED → resolved
  file    existsSync: нужного файла нет/есть → по смыслу долга
  run     артефакт прогона существует и свеж
  prose   ВСЕГДА unknown → audit-открыто (явный эскейп, не молчком)
```
`prose` — честный запасной тип: не запрещаем вольное, но оно само себя метит «непроверяемо».

## M2 — форма выхода тула

**Посылки:** несущее из журнала — два числа `13 заявлено / ~8 реально`; но число не действие (Верстальщик). Зависит от M1 (команды типа settle требуют решаемого аудита).

**Линзы:**
- **Математик:** ядро — предикат `realActiveCount`; без него всё украшение.
- **Верстальщик:** число не исполнимо → команды settle/supersede/merge с confidence, человек визирует.
- **Структурщик:** не взаимоисключающи: предикат = **модель** (чистая функция над ledger), команды = **проекция** (эмиттер-вид). Одно ядро, две поверхности.
- **Teamlead:** сначала предикат (честный дешёвый метрик), команды — вторая поверхность.
- **Музыкант:** число — «пульс» на `status`; команды — «партитура» на `propose`.

**Вердикт-кандидат M2 (синтез, не или-или):**
```
ЯДРО (чистое):   realActiveCount + health-метрики (protruhших/кластеров/audit-открыто)
ПРОЕКЦИЯ (вид):  propose → исполнимые команды settle/supersede/merge + confidence, визирует человек
status/invariants показывают ЧИСЛО; propose эмитит КОМАНДЫ. Модель одна.
```

## M3 — состав и порядок зубов (build-order)

**Посылки:** зависит от M1 (audit требует типизации) и M2 (предикат — ядро). Журнал: `validate` дёшев и уже поймал протухший file-ref без сети.

**Линзы:**
- **Teamlead:** дешёвое первым — `validate` (живость ref + возраст), без сети.
- **Музыкант:** `supersede`/`amend` рядом с validate — то, что validate пометит стухшим, надо переформулировать с сохранением нити.
- **Математик:** `invariants` + `realActiveCount` — флагманское число — вторым.
- **Структурщик:** `audit` (сверка с main) зависит от M1 — третьим (тяжёлое).
- **Верстальщик:** `decompose --by` и `propose` — виды/эмиттер — последними.

**Вердикт-кандидат M3 (порядок стройки):**
```
1. validate  (+ supersede/amend verb)   ← дёшево, ловит стухшее, чинит нить
2. invariants + realActiveCount           ← честное число 13→~8
3. audit    (нужен контракт M1)           ← сверка вещдока с main
4. decompose --by / propose               ← виды и эмиттер команд
```

## Сборка → эпик (то, что нужно СЕГОДНЯ: buildable spec)

**Данные (M1):** `docs/bridge/DEBTS.md` строки получают поля `kind`/`ref`/`verifiedAt`
(миграция 14 долгов: раздать kind — большинство issue/symbol/file, часть prose).

**Ядро (M2):** чистый модуль `scripts/lib/bridge-debts-health.mjs` — `realActiveCount(debts)`,
`resolveEvidence(debt)` (union-резолвер), `healthMetrics(debts)`.

**Команды (M3, build-order):**
```
yarn bridge debt validate      # шаг 1 — краснеет стухший ref (дёшево, offline)
yarn bridge debt supersede --id X --to "…"   # шаг 1 — переформулировать с нитью
yarn bridge debt invariants    # шаг 2 — дубли/кластеры + realActiveCount
yarn bridge debt audit         # шаг 3 — сверка вещдока с main (нужен kind)
yarn bridge debt decompose --by theme|age|status   # шаг 4 — виды
yarn bridge debt propose       # шаг 4 — эмиттер команд + health-блок
```

**Владелец инструмента — Ангелина** (рамка T7). **Переносимый паттерн «суть зубов»**
(validate/audit/invariants/decompose поверх РАЗНЫХ реестров) — отдельная запись канона,
зеркалит мастерскую задач, но не сливается.
