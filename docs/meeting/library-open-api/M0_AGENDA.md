# Заседание «Открытое API библиотеки» — M0

**Объединяющее задание (одно на всё заседание):** довести задание партнёров до исполнимого
вида — открытое API библиотеки сэмплов: отдача наборов и треков, сведения о них, выборки
фильтрами. Развилка шторма, названная владельцем 01.09.

## Данности (закрыто штормом, НЕ переоткрывать)

- Открытое, а не публичное: пользователь берёт свои треки по авторизации.
- Трек уходит по одному, ссылкой с истечением; массовой раздачи медиа нет; списки в JSON.
- Ссылка предъявительская по замыслу: авторизация на ВЫДАЧЕ, анонимность на получении.
- Ключ лежит в самом JSON-списке и временный; кабинет его не выдаёт, а регулирует срок.
- Защита по умолчанию, снятие — явным движением человека; бессрочная ссылка есть его воля.
- Кабинет отвечает за «чьё», media — за «цела ли бумага». Ось пользователя в media не заводить.

## Фактура (сверена в стволе 01.09)

- В media нет ни пользователя, ни сессии; личность живёт в кабинете. `Device.membraneId`
  необязателен — прибор может не принадлежать мембране.
- Адресация вся по прибору: `/v1/devices/:deviceId/…`; охрана — один общий служебный токен.
- Потолок страницы 100, ответ несёт `total`.
- Блока настроек срока для ключей треков нет; соседний словарь длительностей — от 4 часов
  до 3 месяцев, то есть не того порядка для ключа-предъявителя.

## Кандидаты на упорядочивание (простым текстом, без рангов)

- Ось владения и носитель двери: цепочка `User → Membrane → Device → Collection → Sample`
  держится в двух сервисах, и `membraneId` необязателен — значит «свои треки» для части
  приборов не определены по устройству, а не по ошибке. Что считать осью владения и как
  дверь отвечает, когда звена нет.
- Форма контракта наружу: адресация не прибором, устойчивый ключ пробы вместо изменяемого
  заголовка, объявленная полнота ответа при потолке страницы 100, и статус самого JSON —
  раз он ушёл наружу, его поля перестали быть внутренним делом.
- Ключ-предъявитель и его срок: где живёт умолчание, чтобы оно действовало при пустом
  хранилище и незаходившем в настройки человеке; чем отзывается уже выданная ссылка, когда
  срок снят; на что распространяется выключатель — на пользователя, мембрану или набор.
- Границы выемки: фильтр по промежутку дат позволяет вытянуть документированную ночь
  целиком; список с ключами внутри есть связка ключей, а не метаданные; правило «по одному»
  требует носителя — счёта выдач, иначе оно пожелание.

## Зависимости-подсказки (для DAG, не вердикт)

- Ось владения — вход для формы контракта: пока не сказано, чей трек, неясно, чем адресовать.
- Срок ключа и границы выемки независимы друг от друга, но оба опираются на форму списка:
  ключ едет в списке, счёт выдач считается по нему же.
- Границы выемки — единственный кандидат, где решение может быть «не давать вовсе»
  (фильтр по датам), то есть его вердикт способен упростить остальные.
