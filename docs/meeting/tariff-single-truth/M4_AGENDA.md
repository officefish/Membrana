# Заседание «Тариф как единая правда» — M4 (D) Понижение тарифа и холодное хранилище как носитель

**Объединяющее задание (одно на всё заседание):** превратить тезисы шторма 08.09 в исполнимый
контракт поведения сервера и прибора на тарифе и при переходах, с одной правдой о тарифе —
матрицей из гранул — и производными, читающими её одинаково.

**Порядок M0 (ратифицирован владельцем 08.09):** M1 (R) пересев → M2 (P) право и объём → M3 (U)
повышение → **M4 (D) понижение и холод** → M5 (S) наборы. Предшественники — M1, M2, M3; их вердикты — посылки.

## Данности (закрыто штормом и принятыми вердиктами, НЕ переоткрывать)

- Линейка: датчик 512 МБ + 512 МБ; блокпост по 2 ГБ; наблюдательный пункт по 4 ГБ; системные наборы вне квоты (T1, T2, T10).
- Тезис шторма T3 — при понижении тарифа избыточные площади сверх нового лимита уходят **на неделю** в режим холодного хранилища.
- Тезис шторма T4 — в холодном хранилище звуки ещё можно **экспортировать**; редактировать, переносить между коллекциями и использовать в сценариях доски устройства — **нельзя**; статус держится неделю, после чего место освобождается и данные удаляются.
- Тезис шторма T5 — избыток сверх тарифа — не вещдоки, а данные сверх нормы: компания оплачивает их **ровно одну неделю**, после чего вправе освободить место; норма 31.08 «архив вещдоков чистит только человек» — о данных **внутри** тарифа.
- Тезис шторма T8 — квота никогда не отрицательна; избыток при понижении — только явный сценарий (T3/T4/T5); откат на прежний тариф — судьба долга названа.
- Вердикт M1 (принят) — версия контракта принадлежит релизу; колонки холода на `Tariff` нет, `storage.cold` вне зуба 2 — «судьба в M4».
- Вердикт M2 (принят) — «свободно» = `max(0, лимит − занято)` считает сервер записей; отказ ⇔ свободно < входящее; оси независимы; окно оператора — снимок эпизода.
- Вердикт M3 (принят) — порядок событий перехода: право в базе → разноска с версией и порядком перехода → приём на записи прибора по строгому росту пары → событие прибору → сигнал «принял» в кабинет; откат права запрещён; удержание снимается только человеком или очисткой; витрина права и витрина принятия разведены.
- Эпик «полный буфер» (в стволе) — удержание `DeviceOverflowHold`, `release('human' | 'cleanup')`, окно оператора «вывезти» → «почистить» → «сменить тариф», умная очистка закрыта гейтом до T12.

## Фактура (прод 08.09, ствол 4cfbb2d4; сверено председателем по коду)

- **Понижение кодом не отличается от повышения**: `domain/tariff-transition.ts:133-175 decideTransition` — самовыбор отказывает только на `unknown_target_tariff` и `same_tariff`; вниз пускает без условий; только промокод вверх. `selectTariff` → `TariffChangeLog` → разноска новых, меньших лимитов на записи приборов (M3).
- **Носителя холода нет нигде** (K1 шторма, сверено): ячейку `storage.cold` сетки читает только `domain/quota-ledger.ts` (в рантайм не проведён). У пробы (`packages/background-media/prisma/schema.prisma:147-168 model Sample`) — `label`, `sizeBytes`, `collectionId`, срока и статуса нет; у коллекции (`:136-137`) — `kind` (`buffer | user | system`), `systemKey`; полей «холод», «срок», «заморожено» нет. У `Tariff` колонки холода нет (M1).
- **Сетка сегодня несёт ячейку `storage.cold`** (`docs/tariffs/tariff-grid.json:34-38`, значения по релизу Б: датчик 0, старшие 2048 МиБ «не закреплено») — то есть сетка читает холод как **отдельную квоту**, а T3 — как **избыток сверх нового лимита** без своей квоты. Два прочтения одной ячейки; комната обязана выбрать одно.
- **Что можно делать с пробой на сервере записей** — `samples.controller.ts`: загрузка `POST collections/:id/samples` (:68), экспорт `GET samples/:id/blob` (:120; та же дверь в `library-open-api` :97 — открытая библиотека #2271), отчёт детекции `POST …/drone-detection-report` (:136), удаление `DELETE samples/:id` (:151), перенос `POST samples/:id/move` (:164), правка `PATCH samples/:id` (:181). Коллекции — `collections.controller.ts`: создание, удаление (:83), плагины (:97, :152). Чистка буфера — `buffer-cleanup.controller.ts` `POST plan` (:40), `POST execute` (:53). Ворот по статусу пробы ни в одной двери нет.
- **После понижения `занято > лимит`**: `axisRefuses` (`buffer-overflow-refusal.ts:100-102`) отказывает любой новой пробе; комментарий в коде «`used ≤ limit` на сервере держится всегда» — **ложен при понижении**; «свободно» по M2 = 0; счётчик занятого включает и то, что по T3 должно быть в холоде. Локальный страж прибора (`localGuard.ts:16-34`) судит по заполнению `/quota`: заполнение > 100 % после понижения — что он делает, в коде не описано (страж писался под рост занятого, не под падение лимита).
- **Сценарии доски и библиотека** читают пробы без оглядки на статус: `packages/services/media-library`, `device-scenarios` — ворот «нельзя использовать в сценарии» нет.
- **Кабинет**: витрина права после понижения показывает новый тариф сразу (M3: витрина права), занятое не показывает (M2); журнал `TariffChangeLog` хранит `from → to`, обратный переход — новая строка с большим порядком (M3).

## Вопрос M4 (ровно один)

**Q4 — Что происходит при понижении тарифа и что такое холодное хранилище как носитель, чтобы избыток был явным сценарием, а не отрицательной квотой: (а) носитель холода — где живёт статус «в холоде» и срок (проба, коллекция, запись прибора — на сервере записей) и как **выбирается** избыток при понижении (какие пробы уходят в холод: правило отбора, кто его исполняет, в какой момент относительно приёма новых лимитов по M3); (б) ворота холода — какие двери закрыты (правка, перенос, сценарии доски, чистка человеком?) и какие открыты (экспорт, удаление?), где стоят ворота (сервер записей — единственный носитель), что видит библиотека и доска; (в) неделя — кто считает срок, что происходит по истечении (удаление — процесс сервера записей от имени компании по T5, не человек), как это согласуется с нормой 31.08 «внутри тарифа чистит только человек», и что с «занято/свободно» по M2 в холодную неделю (занято включает холод или нет; «свободно» = 0 всю неделю?); (г) откат и долг (T8) — повышение обратно в течение недели снимает холод без потерь?; смысл ячейки `storage.cold` сетки: отдельная квота холода (тогда колонка на `Tariff` и зуб 2 M1 расширяются) или избыток без лимита (тогда ячейка уходит из сетки и матрицы — правка гранулы Б); что делает удержание прибора при падении лимита буфера ниже занятого? ГРАНИЦЫ: не решать пересев и версию (M1), функцию «свободно» (M2), порядок событий перехода (M3 — посылка), наборы при переходе (M5), алгоритм умной очистки (T12), ворота оплаты и промокод. Словарь: право, лимит, занято, свободно, избыток, холод (холодное хранилище), срок холода, запись прибора, проба, коллекция, разноска, удержание, сервер записей, витрина, библиотека, доска.**

Вердикт обязан назвать: носитель статуса и срока, правило отбора избытка и его исполнителя, закрытые и открытые двери с местом ворот, счёт недели и действие по истечении, поведение «занято/свободно» в холодную неделю, откат и долг, судьбу ячейки `storage.cold`, поведение удержания, что строить и что НЕ строить, носитель каждой части.

## Требования аудита (уроки M0–M3, обязательны с первого прогона)

1. **Посылки:** только сработавшие, каждая клауза покрыта цитируемой репликой; ссылка вида **[Роль] #N «первые пять слов реплики»** — ровно пять пробельных токенов, номера пересчитаны по ролям перед записью (реплики «Принимаю» считаются). Типы: **факт** — только ствол; **план** — невлитое или решённое M1–M3; **норма** — данности. Использованную наполовину посылку сузить.
2. **Фактура:** утверждение о коде — с путём файла и строкой; нет в стволе — не «факт»; оценка — не «факт».
3. **Проверки:** у каждой — путь файла-предмета по стволу, предикат, красный вход, кто краснеет (тест/CI), кто чинит (дом носителя); предикат, который не может покраснеть, — снять.
4. **DoD — одно имя** теста/файла/команды на пункт, читаемый красный случай, без дизъюнкций; тест только на именованные контракты из «Строить»; регламент — отдельным разделом.
5. **Словарь:** холод/холодное хранилище (не cold как нарицательное), удержание (не hold), разноска (не fanout), сервер записей (не records), свободно (не available/freely), удаление (не purge/evict), срок (не TTL/expiry в русском тексте); чужие слова (reconcile, upsert, rolling, drift, grace, retention, GC) — не употреблять; переопределение термина — одной строкой до употребления.
6. **Не вводить второго носителя правды** рядом с M1–M3 (второй флаг, второй кэш, вторая арифметика, второй журнал переходов).
7. **Не переоткрывать данности M1–M3**: правило приёма по паре «версия, порядок» (M3), «свободно» считает сервер записей (M2), версия — релиза (M1).
