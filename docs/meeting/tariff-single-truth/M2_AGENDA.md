# Заседание «Тариф как единая правда» — M2 (P) Право и объём

**Объединяющее задание (одно на всё заседание):** превратить тезисы шторма 08.09 в исполнимый
контракт поведения сервера и прибора на тарифе и при переходах, с одной правдой о тарифе —
матрицей из гранул — и производными, читающими её одинаково.

**Порядок M0 (ратифицирован владельцем 08.09):** M1 (R) пересев → **M2 (P) право и объём** → M3 (U)
повышение → M4 (D) понижение и холод → M5 (S) наборы. Предшественник — M1; его вердикт — посылка.

## Данности (закрыто штормом, НЕ переоткрывать)

- Линейка квот: датчик 512 МБ + 512 МБ; блокпост по 2 ГБ; наблюдательный пункт по 4 ГБ (буфер и коллекции); системные наборы вне квоты, отдельной строкой (T1, T2, T10).
- Квота никогда не отрицательна; «тариф действует» — вычислимая функция: доступная квота = f(тариф, занято, окно) (T8, T9).
- Тариф описывает право; объём каждого ресурса живёт в своём доме — прибор/сервер (T12); источник правды один — матрица (T13). Согласовать, не противопоставлять.
- Умолчание политики переполнения — stop; контракт остановки buffer-full-stop (отказ 200 + reason, overflowId, DeviceOverflowHold) — данность.

## Вердикт M1 (посылка, принят аудитом 08.09 после трёх прогонов и сборки; не переоткрывать)

- **Пересев** = вся цепочка релиз → сетка → база кабинета → записи приборов; **разноска** = звено база → сервер записей по мембране. Шаги S1–S7: закрепление релиза → `yarn tariff:reseed` (после влития Б) → `yarn tariff:grid` → сетка в образе кабинета → кабинет при старте только читает сетку (один раз за процесс, ноль записей) → проекция сетка → `Tariff` с версией → разноска на записи приборов существующим `membrane-context-fanout` + проход по мембранам на накате. Сервер записей сетку не читает.
- **Версия контракта** — то же поле `version` сетки (сейчас `1`), издаёт релиз; колонка на `Tariff` и новое поле на записи прибора; прибор отличает новую правду сравнением с последней известной. `updatedAt` у записи прибора нет.
- **Три зуба:** релиз ↔ сетка (`yarn tariff:grid`), сетка ↔ `Tariff` (четыре пары + версия; холод вне — колонки нет), `Tariff` ↔ `Device` сервера записей (пять пар + политика как поле мембраны/прибора; `maxNodesPerMembrane` остаётся в кабинете) — равенство полей, не счётчик разноски.
- **Переезд:** сид и `tariff-scalars.json` выводятся из авторов квот, `ensureFreeTariff()` удаляется, `TARIFF_GRID_MODE`/`tariff-cutover` подчиняются зубам и снимаются; один рубильник правды.
- **Для M2 несущее:** лимиты на записи прибора (`Device.userStorageQuotaBytes`, `bufferQuotaBytes`, `maxUserWorkspaces`, `datasetCatalogId`) — производная тарифа через разноску, версия при них. Функцию «доступная квота» M1 **не** решал — это M2.

## Фактура (прод 08.09, ствол 4cfbb2d4; сверено председателем по коду)

- **Сервер записей считает занятое сам** — `packages/background-media/src/modules/devices/devices.service.ts:223-278 getQuota`: лимиты — из записи прибора через `resolveDeviceLimits` (`device-limits.ts`), занятое — сумма `sizeBytes` проб прибора по виду коллекции: `kind === 'buffer'` → буфер; `kind === 'user'` **и** `kind === 'system'` с ключом, отличным от тарифного каталога → **пользовательское хранилище**; `kind === 'system'` с ключом тарифного каталога (`TARIFF_DATASET_SYSTEM_KEY`) → только счётчик `dataset.sampleCount`, в байты не входит. То есть **тарифный системный набор вне квоты уже сегодня, а прочие системные коллекции — внутри пользовательского хранилища** (это надо назвать, а не предполагать).
- **Отказ** — `samples/buffer-overflow-refusal.ts:100-102 axisRefuses`: `used + incoming > limit` по двум осям `buffer` и `userStorage`; инвариант «`used ≤ limit` держится всегда» записан в коде комментарием; отказ доменный 200 (#2314), 413 — только «большое тело». Рабочие места — своя ось: `device-workspaces.service.ts:113` отказ при `used >= maxUserWorkspaces`.
- **Ответ `/quota`** несёт `buffer{usedBytes,limitBytes,backend:'server'}`, `userStorage{…}`, `dataset{catalogId,sampleCount}`, `userWorkspaces{used,limit}`, `bufferPolicy` (эффективная: мембрана при привязке, иначе прибор). Числа для функции есть; **самой функции «доступная квота» как одного носителя нет** — «свободно» нигде не вычисляется, прибор и кабинет вычитают сами.
- **Кабинет** лимит знает из `Tariff`, занятое — только через сервер записей: `media-bridge.service.ts:224 getQuota` → единственный потребитель `sample-library.service.ts:78` (библиотека); витрина мембраны (`/v1/tariffs`, `tariff-catalog.ts`) показывает лимиты тарифа, занятое не показывает. `domain/quota-ledger.ts` (три ячейки хранения) в рантайм **не проведён** (M1).
- **Окно оператора** при удержании (#2316) строится из ответа отказа + состояния удержания, без второго запроса квоты (вердикт M5 «полный буфер»).

## Вопрос M2 (ровно один)

**Q2 — Где живёт и как считается «доступная квота», чтобы право (в матрице) и объём (в своём доме) читались вместе без второй правды: (а) единственный носитель функции «доступная квота = f(тариф, занято, окно)» — сервер записей (он считает занятое), кабинет (он знает право) или общий пакет-формула, которую оба вызывают на своих числах, и почему; (б) единицы и оси — буфер, коллекции, узлы, рабочие места, системные наборы отдельной строкой: что складывается, что нет, чтобы квота никогда не была отрицательной и «переполнено» не показывалось при формально свободном месте; (в) «окно» в функции — что это (эпизод переполнения, неделя холода, момент перехода) и кто его задаёт; (г) чем кабинет и прибор показывают одно и то же число — источник для витрины мембраны и для окна оператора при удержании? ГРАНИЦЫ: не решать пересев и версию (M1, посылка), повышение (M3), понижение и холодное хранилище (M4), наборы при переходе (M5), форму гранул (#2331), алгоритм умной очистки, ворота оплаты; словарь не подменять — «право», «объём», «доступная квота», «занято», «лимит», «окно».**

Вердикт обязан назвать: носитель функции и почему, оси и правила сложения, смысл «окна» и его владельца,
единый источник числа для витрины и окна, что строить и что НЕ строить, носитель каждой части.

## Требования аудита (уроки M0–M1, обязательны с первого прогона)

1. **Посылки (HR5):** только те, что реально сработали в реплике; ссылка вида **[Роль] #N «первые пять слов реплики»** — цитата обязательна, номера реплик автор вердикта пересчитывает по ролям перед записью; ссылка на реплику, где посылка не используется, «фон» и несуществующий номер — нарушение. Типы: **факт** — только то, что есть в стволе; **план** — то, что в невлитых спринтах или решено M1; **норма** — из данностей/шторма. Использованную наполовину посылку сузить.
2. **Фактура:** утверждение о коде — с путём файла; чего нет в стволе — не «факт».
3. **Проверки/предикаты:** у каждой — файл-предмет, предикат, кто краснеет, кто чинит, один красный вход.
4. **DoD — только предикаты** с именем теста/файла/команды и красным случаем; регламент и runbook — отдельным разделом, не в DoD.
5. **Словарь:** «право», «объём», «доступная квота», «занято», «лимит», «окно», «сервер записей», «запись прибора», «разноска», «версия контракта»; чужие слова (reconcile, upsert, rolling, drift, ledger как нарицательное) — не употреблять; переопределение термина — одной строкой до употребления.
