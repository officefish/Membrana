[Верстальщик]: Человеку о сессии нужны честные состояния без метафор: идёт, закрыта, закрыта досрочно. Не «магический прогресс», а `tabular-nums` по длительности и счётчику проб. Словарь статусов обязан быть конечным и читаемым в карточке прибора.

[Музыкант]: С потока: сессия — отрезок набора баз для будущих детекторов (Т6), не «вечная лента». Граница должна переживать офлайн прибора: звук мог писаться в локальный хвост, но истина приёма — на сервере записей. Не смешиваем часы MCU с часами media.

[Математик]: Численно: `durationMinutes ∈ [30, 600]`, умолчание 240. Слово владельца: полный буфер ~4 ГиБ ≈ за ~6 ч. При 240 мин < ~6 ч полный буфер раньше конца сессии вероятен лишь при длительности больше ~6 ч или при заранее занятом буфере — это арифметика повестки, не «всегда early-close».

[Teamlead]: Планка прогона 2: не повторить брак прогона 1. Атрибуция только по полям ствола; после закрытия по полному буферу следующая сессия не открывается поверх удержания; явно сказать, что удаляет Т4. M3/M4 не трогаем. Данности M1 не переоткрываем.

[Архитектор]: Конструкция границы: сессия — серверная сущность на media с окном времени. Часы — сервер записей (`new Date()`), как у уборщика. Открытие и закрытие не принимают время телом от прибора. Поля политики уже приняты в M1 — здесь только жизненный цикл окна.

[Структурщик]: Словарь: не смешивать `Sample`, «сессию» и «удержание». У `Sample` в стволе есть `deviceId`, `collectionId`, `createdAt`; поля `receivedAt` нет; поля сессии у пробы нет. Буфер — коллекция `__buffer__`. Новая лемма «RecordingSession» допустима, если без неё окно не зафиксировать.

[Верстальщик]: Для UI: статус `running` — badge нейтральный/info; `closed` — success/тихий; `closed_early` — warning (полный буфер раньше срока); `closed_incomplete` можно не плодить, а показать факт «проб меньше selectionLimit» вторичной меткой. Пустая сессия — empty-state, не ошибка.

[Музыкант]: Офлайн в момент конца: прибор молчит, сервер всё равно закрывает окно по своим часам. Поздние выгрузки после `closedAt` не должны «дотягивать» закрытую сессию — иначе граница плывёт. Локальный холд на dual-use не при чём: это про buffer full `stop`.

[Математик]: Атрибуция пробы к сессии: предикат `sample.deviceId = session.deviceId ∧ sample.collectionId = __buffer__ ∧ sample.createdAt ≥ openedAt ∧ sample.createdAt < closedAt`. Момент открытия — серверное `openedAt = now`; не «сетка cron», не часы прибора. Первая запись не обязана открывать: окно серверное, чтобы офлайн не блокировал старт/финиш границы.

## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| Чьи часы | Сервер записей (media): `openedAt` / `closedAt` / проверка длительности только серверным now; время телом от прибора не принимается. |
| Что открывает сессию | Эффективная политика `enabled=true` (M1) **и** нет running-сессии **и** подтверждено освобождение Т4 предыдущей (если была) **и** нет блокирующего ожидания после `buffer_full`. `openedAt = now` на сервере. Не сетка wall-cron; не обязательная «первая запись»; не часы прибора. |
| Что закрывает | (1) `now ≥ openedAt + durationMinutes` → reason `duration`, status `closed`; (2) при running отказ приёма `device_buffer_full` → `closed_early` + `buffer_full`; (3) `enabled=false` → `closed_early` + `policy_disabled`; (4) смена эффективной политики → `closed_early` + `policy_changed`. |
| Офлайн в момент конца | Сессия закрывается на сервере по правилам выше; связь прибора (`lastSeenAt`) на `closedAt` не влияет. |
| Пробы после конца / опоздание офлайна | Входят в сессию только при `createdAt ∈ [openedAt, closedAt)`; позже — не эта сессия. Истина метки — `Sample.createdAt` ствола. |
| Неполная / пустая | Закрываются как обычные; неполный объём относительно `selectionLimit` — факт метрики, не отдельный status; пустая допустима. |
| Hold при `stop` | Конец сессии **не** снимает hold. `release('cleanup')` — только после подтверждённого Т4 (место реально свободно); `human` — как в стволе. Авто-возобновления по факту close нет. |
| (а) Следующая сессия | Только если предыдущая в `closed`/`closed_early` **и** `t4LiberationConfirmed`. После `buffer_full` — **не** открывать до Т4 (и до возможности cleanup-release). Пауза без running между сессиями обязательна. |
| (б) Состав и Т4 | Состав = пробы device в `__buffer__` с `createdAt` в окне сессии. Т4 удаляет **остаток закрытой сессии** (окно ∩ буфер минус выборка Т2), не «весь буфер назло» и не пробы следующей (следующей ещё нет). В cold archive не уходит (Т4). |
| (в) Атрибуция | Только `deviceId`, `collectionId`, `createdAt` на `Sample`. Новое на Sample — не вводим. Новое: серверная сущность сессии (окно, status, closeReason) — причина: в стволе поля сессии у пробы нет, границу иначе не зафиксировать. |
| Словарь для человека | `running` \| `closed` \| `closed_early` + человекочитаемый reason; отдельно индикатор связи прибора. |

**Definition of Done (только M2):**

- Зафиксированы open/close rules, clock source, offline semantics, early-close, next-open-after-T4, T4 scope residual-only, attribution via `createdAt`.
- Словарь статусов `running | closed | closed_early` + closeReason.
- Инвариант: не более одной running на device; полуинтервалы окон не пересекаются.

# Заседание «Политика сессий записи прибора» — M2, граница сессии

> Прогон 2. Прогон 1 отклонён аудитом по существу: (1) атрибуция проб построена на поле `receivedAt`, которого в стволе нет — серверная метка пробы `Sample.createdAt` (см. «Фактура»); (2) правило «новая сессия открывается сразу после закрытия» не ждёт освобождения буфера по Т4: после закрытия по полному буферу новая сессия шла бы поверх полного буфера и удержания (мёртвое окно, цикл пустых досрочных закрытий), и не было сказано, ЧТО удаляет освобождение — остаток закрытой сессии или весь буфер (риск стереть пробы новой сессии). Формально: цитата начиналась с заглавной буквы при строчной в реплике. Также неверная арифметика: при 240 мин (4 ч) < ~6 ч полный буфер раньше конца сессии вероятен лишь при длительности больше ~6 ч или при заранее занятом буфере.

**Объединяющее задание (одно на всё заседание, дословно):** спроектировать «сессию записи» прибора от политики в кабинете до папки в библиотеке так, чтобы: политика задавалась на прибор (с общей политикой мембраны) и доходила до сервера записей; по концу сессии выборка по критерию делалась на сервере, остаток буфера доказанно освобождался, а выборка ложилась папкой в библиотеку; кольцо библиотеки удаляло только папки сессий и укладывалось в квоту хранилища. Повторно использовать то, что уже есть в стволе, если оно подходит; новое — только там, где старое не подходит, с причиной.

**Порядок заседания (утверждён владельцем 21.11):** политика (принята) → **граница (эта комната)** → машина → папка и кольцо.
