# Заседание «Политика сессий записи прибора» — M3, машина сессии (прогон 5)

> Прогон 4 отклонён: цитаты обрезаны без «…»; дыра П5 (поправлен). **Слово владельца 21.11 «Вариант А»:** проект написала рабочая сессия по коду (ствол `42d78fdb`); комната **принимает проект или правит его по пунктам** — не сочиняет заново.

**Порядок:** политика (принята) → граница (принята) → **машина (эта комната)** → папка и кольцо (M4).

## Данности (НЕ переоткрывать)

- Т2: по итогам сессии отбирается заданное число записей по одному из трёх критериев; выборка — в библиотеку.
- Слово «а»: буфер целиком принадлежит сессиям; выборка из записей сессии, остальное удаляется; записи паузы — следующей сессии. А1: записи до включения сессий удаляются с первой сессией.
- Вердикт M2: «буфер после T4 либо пуст, либо держит только пробы паузы для следующей». Часы — сервер записей (`Sample.createdAt`); сессия — серверная сущность; окно `prevClosedAt < createdAt ≤ closedAt`; следующая открывается только после подтверждённого освобождения, иначе пауза с ручным выходом.
- Владелец: «включение сессии дает разрешение на удаление». Помеченные «хранить» уходят в библиотеку сверх объёма. Отказ замера целиком — последние N, «выборка без замера», дежурство не встаёт.
- Владелец 21.11 «1 да 2 да»: помеченные среди записей до включения **переносятся** (не удаляются по А1); размеченные записи (метка не `unlabeled`) считаются помеченными и уходят сверх объёма.
- Канон #2308: удержание прибора снимается только `release('human' | 'cleanup')`, «авто-возобновления по освобождению места нет» (`apps/client/src/lib/device-overflow-hold/deviceOverflowHold.ts:120`).

## Проект машины (пути: BM=`packages/background-media/src`, DA=`BM/modules/downgrade-archive`, S=`BM/modules/samples/samples.service.ts`, H=`apps/client/src/lib/device-overflow-hold`, ML=`packages/services/media-library/src`)

П1. **Кто будит.** Office, новый cron раз в 1 мин → новая дверь media `POST /v1/internal/recording-sessions/tick` под `ApiTokenGuard`. Опора: у media нет `@Cron`; у office есть (`packages/background-office/src/modules/cold-archive-sweep/cold-archive-sweep.scheduler.ts:74`); ADR-0032 Р2 — будит только office. Граница считается от срока, не от тика. Флаг office `RECORDING_SESSIONS_TICK_ENABLED` (новое, умолч. выкл.).

П2. **Исполнитель.** Новое: исполнитель закрытия в media, таблицы `RecordingSession` (`seq` под `@@unique([deviceId, seq])`, состояние M2, `startedAt`, `closedAt`, `closeReason`, снимок политики) и задание закрытия (фаза, выбранные, помеченные, пути, попытки, лиз). Переиспользуется: замер `measureSampleSet` (`DA/downgrade-archive.service.ts:238`), порядок `modeOrder` (`:160`), пометка `isPinnedByHuman` (`ML/buffer-cleanup.ts:89-95`), перенос `moveBatch` (`S:384`), удаление `removeWithProof` (`BM/blob/blob-storage.service.ts:73-75`), повторы `decideAfterAttempt` (`DA/purge-retry-policy.ts:107-123`), лиз условным `updateMany` (`DA/purge-journal.store.ts:267-273`), порог `stopDecision` (`ML/buffer-stop.ts:49`, порог 0,95 — `:26`). Двери buffer-cleanup не берутся: ключ прибора (`BM/modules/buffer-cleanup/buffer-cleanup.controller.ts:32`), показ списка человеку.

П3. **Выборка.** Помеченные с `createdAt ≤ closedAt` — сверх объёма. Непомеченные окна: замер → порядок по критерию → первые `selectionLimit`; не раскодированные замером не выбираются. Отказ замера целиком (`packages/plugin-handlers/src/chart-list-measure/executor.ts:59`) → последние `selectionLimit` по `createdAt`, отметка «выборка без замера» (новое поле), закрытие идёт дальше. Выборка пишется в задание до переноса.

П4. **Перенос.** Цель — «папка сессии» (устройство — M4). `moveBatch` кусками ≤ 2000: сначала помеченные, затем выборка. Отказ `no-space` → пауза «нет места» (новое поле причины), следующая не открывается; остаток всё равно удаляется.

П5. **Удаление остатка.** Снимок «буфер прибора, `createdAt ≤ closedAt`, вне выбранных и помеченных» пишется в задание ДО удаления; строки удаляются с условием «ещё в буфере **и не помечена**» — пометка перепроверяется в момент удаления (`isPinnedByHuman`), запись, помеченная после снимка, не удаляется, а уходит в перенос (так и после долгой паузы «боевой выключен»); файлы — `removeWithProof`, исходы `removed | already_absent` — успех, `failed` → повтор/«мёртвая очередь». Квота буфера считает строки (`BM/modules/devices/devices.service.ts:239-258`), поэтому долг файлов сессию не держит.

П6. **«Освобождение подтверждено».** В буфере нет строк с `createdAt ≤ closedAt_k` вне выбранных и помеченных, и ни одна из них не в буфере. Пробы паузы (`createdAt > closedAt_k`) не смотрятся — без «буфер = 0». Для первой сессии то же правило исполняет А1.

П7. **Одно поле `/quota`.** Новое поле корня `sessionCleanup: { seq, sessionId, confirmedAt } | null`; `seq` растёт на каждое подтверждение. Поля `bufferFreeBytes` в стволе нет. Клиент: `getQuota()` лишние поля отбрасывает (`packages/services/media-library/src/backends/server-storage-backend.ts:397-411`); то же тело уже читает `getQuotaRaw()` (`:393-395`) каждым циклом опроса. Новый читатель в H: `seq > lastSeenSeq` ∧ удержание с причиной `device_buffer_full` → `release('cleanup')`; `lastSeenSeq` хранится на приборе (localStorage рядом с эпизодом удержания, `H/deviceOverflowHold.ts:53-80`), переживает рестарт; первое чтение без сохранённого значения — только запоминание. Снятие — событием очистки, не местом; канон цел. Если пробы паузы держат ≥ 95 %, локальный страж (`H/localGuard.ts:16-19`) вернёт удержание в том же цикле, а тик закроет следующую сессию.

П8. **Гонка.** Срок, полный буфер, выключение и смена политики только **просят** закрытие (первая причина побеждает, условный `updateMany`). Захват — тиком `running → pause` («ждёт освобождения»); неудачный захват — no-op. Работа и ручной повтор — под одним лизом 10 мин в БД. Открытие следующей — вставка `seq = last + 1` под `@@unique`, только тиком.

П9. **Полный буфер.** Удержание гасит отправку (`H/wiring.ts:49`), страж входит в него на 95 % без отказа сервера — серии отказов нет. Сигналы в БД: (1) первый же отказ `device_buffer_full` на ветке отказа приёма (`S:224-231`) пишет просьбу; (2) тик проверяет `stopDecision` по квоте. Эпизод отказа живёт в памяти процесса — сигналом не служит. Отказ в паузе — no-op.

П10. **Паузы и выходы.** Новые двери media: `GET v1/devices/:deviceId/recording-sessions/current`, `POST …/:id/resolve {retry | drop_unplaced}`. «Ждёт освобождения» — тик продолжает по истечении лиза; «закрытие не удалось» — ручной `retry`; «нет места» — тик повторяет, ручной `retry` или `drop_unplaced` (невлезшие непомеченные удалить по П5; помеченные человек выносит `samples.move`, `S:324`); «боевой выключен» — включение ключа. Вечных пауз нет.

П11. **Боевой ключ.** Новый `SESSION_PURGE_LIVE_ENABLED` в env media (умолч. выкл.), разбор как `PURGE_LIVE_ENABLED` (`BM/config/env.schema.ts:75`); чужой ключ не берётся — он ключ одной двери уборщика. Выключен — сухой ход: выборка и снимок в задание, переноса и удаления нет, пауза «боевой выключен».

П12. **Несколько процессов media.** Захват, лиз, открытие и сигнал — в БД, состояния в памяти нет; условие ADR-0032 Р2 для уборщика в силе.

П13. **Сбой.** Фазы `select → move → delete → verify` в задании; рестарт продолжает с фазы. Повтор переноса даёт «уже не в буфере», повтор удаления файлов — `already_absent`. До подтверждения следующая не открывается.

П14. **Первая сессия.** Media ставит `sessionEnabledAt` (новое) при `enabled false → true`; первая сессия с `startedAt = sessionEnabledAt`. Удаление `createdAt ≤ closedAt_1` сносит и записи до включения (А1); помеченные из них переносятся.

## Вопрос M3 (ровно один)

**Q3 — Принять ли проект машины сессии (П1–П14) и какие пункты поправить?**

Вердикт обязан по каждому пункту П1–П14 сказать «принят» или «поправка: …» с причиной; поправка не вводит поле, дверь или канал без пометки «новое»; не снимает удержание по месту; не использует двери buffer-cleanup; не оставляет паузу без выхода.

**Не решает M3:** папка и кольцо (M4); поля политики (M1); правила границы (M2).

**Список посылок** — секция с этим заголовком: тип (норма / факт / план), источник — раздел этой повестки, и под каждой посылкой дословная цитата реплики `[Роль]: «…»` **по предмету посылки**, символ в символ (регистр, кавычки, скобки, обратные кавычки, знаки). **Правило обрезки:** цитата — либо реплика целиком, либо её кусок, который НАЧИНАЕТСЯ и КОНЧАЕТСЯ знаком «…» (`[Роль]: «… кусок …»`); кусок с начала реплики — только конец «…», кусок до конца реплики — только начало «…». Источник — точное имя раздела: «Данности», «Проект машины» (с номером П), «Вопрос M3», «Порядок» или вводный абзац («Слово владельца "Вариант А"»). Иначе — не посылка.
