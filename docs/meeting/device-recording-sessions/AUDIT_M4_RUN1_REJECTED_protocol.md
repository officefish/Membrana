# Консилиум: M4 — папка сессии и кольцо К1–К9

**Повестка:** принять ли проект папки сессии и кольца (К1–К9) и какие пункты поправить; данности Т5/Т7/M3 и слова владельца 21.11 не переоткрывать.

[Музыкант]: Смотрю поток артефактов закрытия. Фазы `select → folder → ring → move → delete → verify` — кольцо стоит **до** переноса, место освобождается до `moveBatch`. Это правильно: иначе поток проб упрётся в `no-space` без жертв. Порядок «строки раньше файлов» (К5) совпадает с тем, что мы держали на уборщике архива 08.10: квота живёт в строках (`Q:239-262`), blob — после.

[Математик]: Инвариант границы однозначен. `need = Σ sizeBytes(выбранные ∪ помеченные)`, `free = limitBytes − usedBytes` (`Q:267-270`). Жертвы — по возрастанию `closedAt`, пока `need > free`. Своего бюджета «N папок» нет — это слово владельца 2 и совпадает с отказом `moveBatch` (`S:371-373`): второй лимит внутри той же квоты разошёлся бы численно. Принимаю К3 и К4 как чистые предикаты без скрытого состояния.

[Архитектор]: Конструкция К1 оправдана границей. `kind='system'`, `systemKey='recording-session'` (новый литерал; поле `P:143`), id `session-<RecordingSession.id>` — не `user`, потому что дверь удаления набора сносит `user` каскадом без blob (`C:53-55`, `C:25`), а `system` отвергает (`C:50-52`) и при этом в квоте (`Q:258`). Связь `RecordingSession.folderCollectionId` — одно поле, одна папка на сессию. Форма К1 принимается.

[Teamlead]: Положение: M3 принят, эта комната — только папка и кольцо. Не переоткрываем машину, поля M1, цену докупки. Планка: вердикт по каждому К1–К9, поправка без новых дверей «из воздуха». Связка на приёмку: Веснин границы → Ожегов словарь/API → Дынин предикаты → Курёхин порядок blob → Родченко лицо папки. Пока BLOCK не ставлю — идём по пунктам.

[Структурщик]: Словарь чистый: не смешивать `RecordingSession`, коллекцию `recording-session` и `SessionFolderEviction`. Кольцо перебирает **строки сессий**, не коллекции (К2) — это слабая связанность: имя не читается, буфер/user/тарифный набор (`BM/lib/collection-ids.ts:4`) не попадают по построению. `SessionFolderEviction` по форме `ColdArchivePurgeJob` (`P:390-406`), но не он — отдельная лемма, не привязка к прогону уборщика. К2 и каркас К5 принимаю.

[Верстальщик]: Человеку нужна конструкция, не «системный датасет». Сейчас кабинет на любую `system` пишет общую подпись (`SampleLibraryMainPanel.tsx:191-192`), клиент чужой `systemKey` отбрасывает (`server-storage-backend.ts:116`). К7 требует литерал в тип, подпись «папка сессии» и **вынос** проб — иначе у К6 (пропуск pinned) нет рук. Ручной двери удаления папки нет — слово владельца 3, не трогаем. Без UI-рук К6 — мёртвая политика.

[Музыкант]: К6: папка с `isPinnedByHuman` (`ML/buffer-cleanup.ts:89-95`) пропускается целиком — удаление только папкой, не «вырезать pinned». Пропуск редок: прибор шлёт `label: 'unlabeled'` (`micBufferRecorderPlugin.ts:154`). Выход при нехватке места — пауза M3 `retry | drop_unplaced` плюс человек выносит pinned своим `samples.move` (`S:324`). Поток ясен, артефакты не рвутся посередине папки.

[Математик]: Идемпотентность К9: повтор `deleteMany` — no-op, пути — `already_absent` (`blob-removal-proof.ts:10`); задания жертв — `updateMany` по лизу (`purge-journal.store.ts:267-273`). `ring → move` только когда у всех жертв сняты строки. Замка в памяти нет — ADR-0032 Р2. Численно сухо/live одним ключом `SESSION_PURGE_LIVE_ENABLED`: выключен → план и снимки есть, удаления нет. К5/К9 согласованы с доказательством удаления уборщика.

[Архитектор]: К4: кольцо **только** фазой `ring` закрытия M3, своего cron нет — граница с office/media как в ADR-0032: media исполняет, office будит. Крючок докупки только имя: байты в `userStorageQuotaBytes` до fanout (`membrane-context-fanout.service.ts:99`), кольцо не ветвится. Цену докупки комната не решает — верно вынесено. К3/К4 по форме принимаю без ADR-ветвления внутри M4.

[Teamlead]: К1–К4 без красного. Требую явный вердикт «принят» по каждому, не «в целом ок». К7 — не «потом UI»: DoD этой комнаты обязан зафиксировать интерфейсный минимум (литерал, подпись, вынос), иначе К6 не исполним человеком. Связка Родченко + Ожегов на тип и панель. Матч — политика в коде и руках, не зелёный только backend.

[Структурщик]: К8: внос в `recording-session` сейчас не запрещён публично (`S:217`, `S:334`, `S:400` бьют только тариф) — **новое**: отказ публичных `move`/`move-batch`/загрузки; исполнителю M3 — внутренний вызов. Это не новая «дверь удаления», а сужение существующей двери move — словарь остаётся, предикат цели ужесточается. Наборы `user` не трогаем. Принимаю К8 с этой пометкой «новое» как в проекте.

[Верстальщик]: Дверь `GET …/recording-sessions/current` + `ring: { evicted, skippedPinned, deadLetter }` — read-only след, конструктивизм: `tabular-nums`, badge статуса, без дашборда ради дашборда. Вынос проб — существующий `samples.move`, не новый канал. Подпись «папка сессии» вместо «системный датасет» — одна ветка по `systemKey`. Принимаю К7 как обязательный интерфейсный слой проекта, не украшение.

[Музыкант]: К5 порядок: снимок id/путей → `deleteMany` проб «ещё в этой папке» → строка коллекции → `removeWithProof` только для путей без ссылок (новое) → `decideAfterAttempt` (`purge-retry-policy.ts:107-123`). Строка сессии-жертвы остаётся, `folderEvictedAt` (новое) — след, не молчаливое исчезновение истории сессии. С потока: файл не трогаем, пока на него есть проба — гонка выноса человеком закрыта.

[Математик]: Жертвы: закрытые сессии с папкой, кроме текущей, `closedAt` ASC. План жертв в задании **до** удаления — аудируемо. `ringSkipped` (новое) для pinned-папок. Если после обхода `need > free` — пауза «нет места» без нового состояния машины M3. Формула не вводит второй счётчик папок. К4/К6 численно замкнуты.

[Архитектор]: Сухой ход: папку не создаёт (К1), удаления нет при выключенном live-ключе (К5) — одна ось с M3, не параллельный выключатель «кольца». Декора в API нет: нет ручной delete-folder door. К9: рестарт продолжает по плану в БД. Рекомендация: принять проект целиком; точечные поправки только уточняющие, без новых сущностей сверх уже помеченных «новое».

[Teamlead]: Слово владельца 21.11: (1) skip pinned-папки, (2) только байты, (3) удаляет только кольцо. Проект это несёт — данности не переоткрыты. Ставлю предварительный LGTM на К1–К6, К8–К9; К7 — LGTM при явном DoD на литерал+подпись+вынос. Поправок «сочинить заново» не будет — Вариант А.

[Структурщик]: Проверка импортов/границ: `SessionFolderEviction` живёт в media schema рядом с purge-журналом, не в office. Исполнитель закрытия пишет фазы в том же задании M3 — лиз тот же. [Верстальщик]: Empty/loading на кольце: человек видит `skippedPinned` и понимает, **почему** место не освободилось — иначе «нет места» без причины. `deadLetter` — warning badge, не silent. Фокус: первичное действие при skip — вынос pinned в свой набор, не «удалить папку» (её двери нет). К7 принимаю без ручного delete.

[Музыкант]: Ещё раз К2: строгий признак `folderCollectionId` из строки сессии **и** `kind='system' ∧ systemKey='recording-session'`. Имя коллекции не читаем — нельзя случайно снести user-набор опечаткой label. Тарифный набор исключён построением. Это защита потока библиотеки, принимаю.

[Математик]: Post-condition кольца перед `move`: `free' >= need` либо пауза. После eviction usedBytes падает за счёт удаления строк (квота — строки). Файлы после — не для квоты, а для диска и proof. Инвариант «строки раньше файлов» обязателен в тестах runner. К5 — принят; в DoD — тест на порядок и на skip pinned.
