# Заседание «Политика сессий записи прибора» — M4, папка сессии и кольцо (прогон 2)

> Прогон 1 принял проект, но отклонён: цитаты не по правилу обрезки; дыры К4 (двойной счёт `need`), К5 (поздняя пометка удалялась), К9 (отказ снятия строк без выхода) — поправлены.
> **Слово владельца 21.11 «Вариант А»:** проект написала рабочая сессия по коду (ствол `42d78fdb`, строки сверены); комната **принимает проект или правит его по пунктам** — не сочиняет заново.

**Порядок:** политика (принята) → граница (принята) → машина (принята) → **папка и кольцо (эта комната)**.

## Данности (НЕ переоткрывать)

- Т5: библиотека — кольцо сессий; память не бесконечна; дополнительная память — будущая платная услуга.
- Т7: сессия — папка в библиотеке; кольцо удаляет только папки сессий; политика по образцу политики буфера (прибор / привязка мембраны, как M1).
- M3 (принят): выборка и помеченные переносятся `samples.moveBatch` в «папку сессии» (коллекция прибора, не буфер, в квоте); при `no-space` — пауза «нет места», выходы `retry | drop_unplaced`; удаление с доказательством `removeWithProof`; сухой ход под `SESSION_PURGE_LIVE_ENABLED`; тик office раз в минуту; состояние и лиз в БД; фазы закрытия в задании.
- Владелец: помеченные «хранить» и размеченные (метка не `unlabeled`) уходят в библиотеку сверх объёма.
- **Владелец 21.11 (развилки проекта):** (1) «а» — кольцо **пропускает** старую папку, в которой есть помеченная запись; (2) «предел есть… должен опираться на объём библиотеки, а не кол-во папок» — граница кольца только байты квоты библиотеки, поля «не больше N папок» нет; (3) «старые папки сессий можно удалять в рамках общей работы логики кольца» — папки сессий удаляет только кольцо, ручной двери удаления папки нет.

## Проект (пути: BM=`packages/background-media/src`, P=`packages/background-media/prisma/schema.prisma`, S=`BM/modules/samples/samples.service.ts`, C=`BM/modules/collections/collections.service.ts`, Q=`BM/modules/devices/devices.service.ts`, ML=`packages/services/media-library/src`)

К1. **Папка сессии.** Коллекция прибора `kind='system'`, `systemKey='recording-session'` (новый литерал; поле есть — `P:143`), одна на сессию, id `session-<RecordingSession.id>` (новое; повтор после сбоя вторую не заводит, ключ `P:148`). Почему не `user`: дверь удаления набора сносит `user` строкой (`C:53-55`) каскадом проб без файлов — сервис блобов не знает (`C:25`); `system` эта дверь отвергает (`C:50-52`), при этом `system` в квоте (`Q:258`) и годна цели `moveBatch` (`S:399-411`). Создаёт исполнитель закрытия M3 новой фазой `folder` (после `select`, до переноса), повтор — no-op; связь `RecordingSession.folderCollectionId` (новое). Сухой ход папку не создаёт.

К2. **Строгий признак.** Кольцо перебирает строки `RecordingSession` прибора, не коллекции; снимает коллекцию только при совпадении id из строки сессии **и** `kind='system' ∧ systemKey='recording-session'`. Имя не читается; буфер, наборы `user` и тарифный набор (`BM/lib/collection-ids.ts:4`) не попадают по построению.

К3. **Граница.** Байты существующей оси `userStorage` (строки `user` и `system` кроме тарифного набора — `Q:254-262`; лимит `Device.userStorageQuotaBytes` — `P:66`). Своего бюджета и поля «число папок» нет (слово владельца 2): второй лимит внутри той же квоты разошёлся бы с отказом `moveBatch` (`S:371-373`). Выключателя нет — по Т5 кольцо свойство библиотеки. Крючок докупки (только имя): докупленные байты прибавляются к `userStorageQuotaBytes` в кабинете до рассылки (`packages/background-cabinet/src/modules/pair/membrane-context-fanout.service.ts:99`); кольцо не меняется.

К4. **Когда работает.** Только фазой `ring` закрытия M3, своего расписания нет. Фазы: `select → folder → ring → move → delete → verify`. `need = Σ sizeBytes(выбранные ∪ помеченные, **ещё лежащие в буфере**)` — уже перенесённые частичным `moveBatch` (`S:414-418`) сидят в `usedBytes` и второй раз не считаются, `free = limitBytes − usedBytes` (`Q:267-270`). Жертвы — закрытые сессии прибора с папкой, кроме текущей, по возрастанию `closedAt`, пока `need > free`. План жертв пишется в задание до удаления. На паузе «нет места» тик повторяет `ring` и `move`.

К5. **Как удаляет.** Новая таблица `SessionFolderEviction` (жертва, задание, id проб, пути, статус, попытки, лиз, исходы) — по форме `ColdArchivePurgeJob` (`P:390-406`), не он: тот привязан к прогону уборщика. Порядок уборщика (`BM/modules/downgrade-archive/purge-gc.runner.ts:6-9`): снимок id и путей → перед удалением **повторная сверка пометки** (пометку человек ставит в любой момент — `S:502`): нашлась помеченная проба → жертва отменяется и пишется в `ringSkipped`, берётся следующая → `deleteMany` проб с условием «ещё в этой папке» в одной транзакции со сверкой → строка коллекции → `removeWithProof` (`BM/blob/blob-storage.service.ts:73-75`) только для путей, на которые не ссылается ни одна проба (новое) → повторы `decideAfterAttempt` (`BM/modules/downgrade-archive/purge-retry-policy.ts:107-123`). Строки раньше файлов: квота — строки (`Q:239-262`). Строка сессии-жертвы остаётся следом, `folderEvictedAt` (новое). Ключ — тот же `SESSION_PURGE_LIVE_ENABLED`: выключен → план и снимки пишутся, удаления нет.

К6. **Помеченные в старых папках.** По слову владельца 1: папка с пробой `isPinnedByHuman` (`ML/buffer-cleanup.ts:89-95`) пропускается, берётся следующая; удаление только целиком. Прибор шлёт `label: 'unlabeled'` (`apps/client/src/plugins/mic-buffer-recorder/micBufferRecorderPlugin.ts:154`), помечает и размечает человек (`S:502`). Если места не хватило — пауза «нет места» M3 без нового состояния, выходы те же, плюс человек выносит помеченные в свой набор (`samples.move`, `S:324`) — папка становится жертвой, затем `retry`. Пропущенные пишутся в задание (`ringSkipped`, новое).

К7. **Что видит человек.** Дверь M3 `GET …/recording-sessions/current` добавляет `ring: { evicted, skippedPinned, deadLetter }` (новое). Клиент чужой `systemKey` отбрасывает (`ML/backends/server-storage-backend.ts:116`), кабинет на любую `system` пишет «системный датасет» (`apps/cabinet/src/components/sample-library/SampleLibraryMainPanel.tsx:191-192`). Новое (интерфейс): литерал в тип, подпись «папка сессии», вынос проб из неё — иначе у К6 нет рук. Ручной двери удаления папки нет (слово владельца 3).

К8. **Гонки.** С M3: кольцо — фаза того же задания под тем же лизом. Человек удаляет пробу из папки (`S:313-322`) — путь даёт `already_absent` (`BM/blob/blob-removal-proof.ts:10`). Выносит пробу — меняется `collectionId`: условие «ещё в этой папке» её не удалит, проверка «путь без ссылок» не тронет файл. Внос чужих проб в папку сейчас не запрещён (`S:217`, `S:334`, `S:400` отбивают только тариф) — новое: отказ публичных `move`/`move-batch`/загрузки в `recording-session`, исполнителю — внутренний вызов.

К9. **Процессы и сбой.** Как M3: всё в БД, задания жертв — условным `updateMany` по лизу (`BM/modules/downgrade-archive/purge-journal.store.ts:267-273`); рестарт продолжает по плану, повтор `deleteMany` — no-op, пути — `already_absent`; `ring → move` — когда у всех жертв сняты строки. Отказ снятия строк — повторы `decideAfterAttempt`; исчерпаны → пауза M3 «закрытие не удалось», выход `retry`. `deadLetter` бывает только у файлов: строки уже сняты, закрытие не держит. Замка в памяти нет; ADR-0032 Р2 в силе.

## Вопрос M4 (ровно один)

**Q4 — Принять ли проект папки сессии и кольца (К1–К9) и какие пункты поправить?**

Вердикт обязан по каждому пункту К1–К9 сказать «принят» или «поправка: …» с причиной; поправка не вводит поле, дверь или канал без пометки «новое»; не трогает наборы человека; не переоткрывает слова владельца, M1, M2, M3.

**Не решает M4:** цена и учёт докупки; понижение тарифа ниже занятого; поля M1; машина M3.

**Список посылок** — секция с этим заголовком: тип (норма / факт / план), источник — точное имя раздела («Данности», «Проект» с номером К, «Вопрос M4», «Порядок»), под каждой посылкой цитата реплики `[Роль]: «…»` по предмету посылки, символ в символ (кавычки внутри не менять). **Правило обрезки:** цитата — реплика целиком, либо кусок, который НАЧИНАЕТСЯ и КОНЧАЕТСЯ знаком «…»; кусок с начала реплики — только конец «…», кусок до конца реплики — только начало «…».
