# Консилиум: M0 — порядок четырёх кандидатов «Политика сессий записи прибора»

**Повестка:** Q0 — в каком порядке и с какими зависимостями решать четыре кандидата (машина сессии, политика сессии, граница сессии, папка сессии и кольцо), чтобы каждый следующий опирался на принятый предыдущий. Содержание кандидатов не решается.

**Участники:** Teamlead (Tarasov), Архитектор (Vesnin), Структурщик (Ozhegov), Математик (Dynin), Музыкант (Kuryokhin), Верстальщик (Rodchenko).

[Архитектор]: Q0 — только порядок. Четыре кандидата: (1) машина конца сессии, (2) политика сессии, (3) граница сессии, (4) папка и кольцо. Содержание полей, будильника и правил кольца сегодня не трогаем. Корень ищу там, где появляется словарь без исполнения.

[Структурщик]: Словарь важнее машины. Пока нет однозначного имени и полей политики, пакеты media/office/cabinet не знают, какой контракт нести. Кандидат (2) — лемма «что это»; (1), (3), (4) — употребления этой леммы. Начинать с машины — нарушить определение до реализации.

[Музыкант]: Со стороны потока артефактов: сначала ясно, *что* режется из непрерывной записи (критерий, объём, длительность — как параметры, не как выбор), потом — *когда* режется, потом — *кто будит рез*, потом — *куда папка*. Иначе кольцо библиотеки получит «что-то похожее на сессию» без контракта.

[Teamlead]: Планка M0: граф зависимостей, не дизайн. Данности 21.11 не переоткрываем: политика на прибор из кабинета, после сессии буфер свободен, библиотека — кольцо, запись для баз звуков. Кто полез в поля политики или в cron — вне вопроса, возвращаю в строй.

[Математик]: Формально: частичный порядок на четырёх вершинах. Ребро A→B только если контракт B цитирует выход A. Без ребра — либо независимость, либо запрет обратной ссылки. Корень — вершина с нулевой входящей степенью по смыслу домена.

[Верстальщик]: Кабинету и панели библиотеки нужен сначала язык политики (что пользователь задаёт), затем статусы границы (идёт / закрыта / неполная), затем след машины, затем вид папок кольца. UI не диктует порядок бэка, но ломается, если кольцо рисуют раньше полей политики.

[Архитектор]: Кандидат (2) — корень. Граница (3) берёт у политики длительность и смысл «сессия как интервал с правилом выборки», не booting. Машина (1) берёт у границы момент конца и у политики критерий/объём как вход отбора — без выбора «офис или свой таймер» сегодня. Папка (4) берёт закрытую сессию и состав выборки.

[Структурщик]: Ребро 2→3: следующий фиксирует жизненный цикл поверх полей, не изобретая их. Ребро 3→1: исполнитель конца не определяет семантику «когда сессия кончилась», а реализует её. Ребро 1→4: кольцо принимает уже произведённый артефакт сессии (папка/набор ссылок), а не будит отбор. Обратных рёбер 4→1, 1→2, 3→2 быть не должно.

[Музыкант]: Не-ребро 4→3: правила квоты кольца не должны переписывать границу «когда сессия закрыта». Не-ребро 1→3: будильник не есть граница; иначе снова смешаем office-cron уборщика с доменным концом сессии до решения границы. Поток: политика → время/полнота → акт закрытия → библиотека.

[Teamlead]: Параллель на старте не вижу: без (2) все трое гадают. После (2) жёстко только (3). После (3) — (1), затем (4). Частичная подготовка черновика (4) «что защищено» после (2)+(3) допустима как чтение, не как вердикт комнаты (4) до контракта выхода машины. Матч — последовательный проход, не четыре одновременных ADR.

[Математик]: Входящие: (2) indegree 0; (3) ← (2); (1) ← (2),(3); (4) ← (2),(3),(1). Минимальный линейный порядок, сохраняющий все рёбра: 2 ≺ 3 ≺ 1 ≺ 4. Параллельных пар с нулевой зависимостью нет: (1) и (4) связаны ребром 1→4 через «что именно кладётся и с каким доказательством переноса/освобождения буфера».

[Верстальщик]: Согласен с 2≺3≺1≺4. Экран политики в кабинете — после вердикта по (2), не раньше; статусы неполной сессии — после (3); журнал/след закрытия — после (1); список папок кольца и квота — после (4). Иначе a11y-состояния «что происходит с записью» врут пользователю.

[Архитектор]: Уточняю рёбра причинами, без содержания. 2→3: граница заимствует *какие* величины задают окно и критерий отбора как параметры контракта. 2→1: машина заимствует *тот же* критерий/объём как вход ранжирования или отказа от чужого. 2→4: кольцо заимствует, *что* считается единицей сессионного артефакта относительно политики.

[Структурщик]: 3→1: машина берёт предикаты начала/конца, офлайна и неполной сессии — точки, в которых вообще позволено будить закрытие. 3→4: папка/кольцо отличает полную, неполную и «удержание при полном буфере» только после семантики границы; иначе смешение с freeze/hold буфера без двери. Слабая связанность: граница — контракт, машина — исполнитель, кольцо — хранение.

[Музыкант]: 1→4: папка в библиотеке появляется как результат акта закрытия (выборка выложена, буфер после сессии освобождается — данность Т, не дизайн). Кольцо считает место и защиту уже над существующими папками сессий. Без машины (1) (4) спорит о GC без производителя объекта — как уборщик без freeze-партии.

[Teamlead]: Данность: после сессии буфер освобождается — это вход в граф (связь сессия→буфер), не повод открыть кандидата (1) первым. Подъём прибора без человека — вне заседания, в граф не входит. Фиксирую корень (2). Кто начнёт с «часов офиса как у уборщика» до политики и границы — BLOCK по M0.

[Математик]: Не-рёбра (явно): 1↛2, 3↛2, 4↛2, 4↛3, 4↛1, 1↛3 в смысле «не определяет семантику», 3↛1 наоборот есть. (1)∥(4) запрещено как одновременный вердикт: есть путь 1→4. Единственная ослабленная параллель — черновик вопросов защиты кольца *после* 2 и 3, *до* закрытия 1, без принятия (4).

[Верстальщик]: Имя политики — одно слово вместо «сессия/дежурство» — сидит в кандидате (2); UI подхватит термин после (2), не проектируя кольцо. Параллелить вёрстку кольца с машиной нельзя: empty state папок зависит от того, *когда* папка считается появившейся (3+1).

[Структурщик]: Пакетная проекция порядка (не содержание): cabinet несёт политику после (2); запись/media понимает границу после (3); office или иной будильник — только после (1); library ring API — после (4). [Teamlead]: Принимаю линейный каркас 2→3→1→4. Связка следующих комнат: сначала комната политики, без неё повестки границы не открываем. Definition of Done M0 — только граф и посылки, без полей и без выбора будильника. Параллельных вердиктных комнат нет.

Альтернатива 2→1→3 смешивает исполнителя и семантику конца — отклоняю численно как инверсию зависимости контракта.
