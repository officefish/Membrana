[Архитектор]: Имя понятия — одно слово: **сессиополитика** (в коде `sessionPolicy`). Определение: набор правил прибора, задающий, ведётся ли запись сессиями с выборкой, с какой длительностью окна, каким объёмом N и по какому из трёх критериев сервер отберёт корпус в конце окна. [Математик]: Диапазоны: `sessionDurationHours` ∈ [1, 24], умолчание **4** (пример Т2); `sessionSelectCount` ∈ [1, 10000], умолчание **200** (пример Т2); criterion default **`loudness-over-floor`** (`downgrade-policy.ts:16,:20` и зеркало media vocabulary `:12`). [Музыкант]: Почему не `on` по умолчанию: прибор может висеть под мембраной без задачи на корпус; непрерывный захват «в никуда» плодит мусор в буфере и путает оператора. Opt-in `off` → пользователь явно стартует сбор баз под детекторы. 4×200×loudness — слышимый и обозримый корпус, не «одна эпоха».

[Teamlead]: Принимаю opt-in. Данность Т6 — «сейчас запись для баз», но не «всегда пишем». Нет политики / mode=off ⇒ **нет сессий**, не «сессия с N=0». Это снимает двусмысленность для media до M2.

[Верстальщик]: В UI mode=off — одна ясная подпись вроде «Сессии записи выключены»; поля длительности/N/критерия disabled или скрыты вторичным блоком, чтобы не обещать папку в библиотеке. Критерий — те же label, что у downgrade, без второго словаря на экране.

[Архитектор]: Правило «своя ↔ мембраны» по Т7 и фактуре буфера: у прибора своя сессиополитика; мембрана может задать **общую** (те же поля на мембране). Пока привязка стоит, сервер записей видит **эффективную**: общая мембраны, если задана, иначе своя прибора. Своя на `Device` **не затирается** привязкой. После снятия привязки эффективная = снова своя прибора (в т.ч. `off`).

[Структурщик]: Общая на мембране — поля-близнецы на модели мембраны (nullable «не задано»), не отдельный сервис. Новый транспорт не вводим: сессиополитику включаем в тот же fanout-контекст.

[Математик]: Эффективная политика — чистая функция merge: `effective = membraneSessionPolicy ?? deviceSessionPolicy`, где «задана» для мембраны = mode и поля не null. Если effective.mode = `off` или политики нет (device без полей до миграции) → media **не** планирует сессий. Никаких NaN/0-часов: валидатор отвергает duration&lt;1 и count&lt;1 при mode=`on`.

[Музыкант]: Критерии не изобретаем: те же три, что уже кормят отбор в downgrade. Для баз детекторов `loudness-over-floor` как default — ок; `spectral-variety` и `drone-likeness` оставляем выбором оператора под тип будущего детектора.
