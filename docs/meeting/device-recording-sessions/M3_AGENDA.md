# Заседание «Политика сессий записи прибора» — M3, машина сессии (прогон 3)

> Прогоны 1–2 отклонены аудитом (протоколы — `AUDIT_M3_RUN*_REJECTED_protocol.md`). Главные ошибки: удаление через двери buffer-cleanup (нет доказательства, только ключ прибора, требуют показа человеку); несуществующие каналы к прибору; вынос выборки через несуществующее состояние; предикат «буфер = 0» против M2; вечная пауза при отказе измерителя; цитаты не по предмету.

**Объединяющее задание:** спроектировать «сессию записи» прибора от политики в кабинете до папки в библиотеке: политика на прибор доходит до сервера записей; по концу сессии выборка по критерию на сервере, остаток буфера доказанно освобождается, выборка ложится папкой в библиотеку; кольцо удаляет только папки сессий. Переиспользовать готовое, новое — с причиной.

**Порядок:** политика (принята) → граница (принята) → **машина (эта комната)** → папка и кольцо (M4).

## Данности (НЕ переоткрывать)

- Т2: по итогам сессии отбирается заданное число записей по одному из трёх критериев; выборка — в библиотеку.
- Слово владельца «а»: буфер целиком принадлежит сессиям; выборка из записей сессии, остальное удаляется; записи паузы — следующей сессии.
- Вердикт M2 (дословно): «буфер после T4 либо пуст, либо держит только пробы паузы для следующей». Часы — сервер записей (`Sample.createdAt`); сессия — серверная сущность; следующая открывается только после подтверждённого освобождения; иначе пауза с ручным выходом; будильник M2 отдал M3.
- Владелец 21.11: «включение сессии дает разрешение на удаление» (правило показа списка остаётся для ручной очистки).
- Владелец 21.11 («А»): помеченные «хранить» в буфере уходят в библиотеку с выборкой, сверх объёма.
- Владелец 21.11 («А»): если замер отказал целиком — выборка без замера, последние N записей, сессия помечается «выборка без замера», остаток удаляется; дежурство не встаёт.

## Вопрос M3 (ровно один)

**Q3 — Какая машина исполняет сессию: кто будит конец и открытие следующей, чем делается выборка, вынос и доказанное освобождение остатка, как прибор узнаёт об освобождении и как это переживает сбой, гонку и отказы?**

Вердикт обязан назвать: кто будит и частоту (минимальная сессия 30 мин); что исполняет закрытие и что переиспользуется (с причиной); выборку (с отказом замера по слову владельца); вынос выборки и помеченных в папку сессии через перенос — и что при отказе `no-space`; удаление остатка с доказательством; условие «освобождение подтверждено» в согласии с M2 (пробы паузы остаются законно, без «буфер = 0»); ОДНО поле ответа `/quota`, снимающее удержание, и почему оно верно при пробах паузы; гонку входов закрытия (срок, полный буфер, ручной повтор); серию отказов `device_buffer_full` и такой отказ в паузе; каждую паузу — с исполнимым выходом (не вечную); второй ключ боевого удаления; несколько процессов media.

**Не решает M3:** устройство папки и кольцо (M4); поля политики (M1); правила границы (M2).
