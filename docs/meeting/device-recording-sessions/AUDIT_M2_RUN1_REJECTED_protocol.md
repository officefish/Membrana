**Повестка:** Заседание «Политика сессий записи прибора», M2: Q2 — где граница сессии записи: старт/конец по времени сервера, офлайн в момент конца, неполная сессия, соотношение с полным буфером.

[Архитектор]: Граница сессии — серверная лемма, не клиентская. Часы — только сервер записей: в стволе уборщик уже берёт `new Date()` на media и не принимает время телом (`downgrade-archive-purge.controller.ts:115`). Сессия не меряется часами прибора и не сеткой кабинета.

[Музыкант]: С потока: прибор гонит пробы в буфер media; офлайн = пробы не доехали. Граница «кто успел лечь в буфер до `endsAt`» — честнее, чем верить device-clock. Иначе поздний выгруз после связи раздует чужую сессию и испортит базу для детекторов (Т6).

[Математик]: Интервал сессии численно: `startedAt` (server Instant), `endsAt = startedAt + durationMinutes` из эффективной политики M1, полуинтервал `[startedAt, endsAt)`. Предикат принадлежности пробы: `receivedAt ∈ [startedAt, endsAt)` на сервере. Пустая сессия — валидный исход: `sampleCount = 0`, закрытие не отменяется.

[Teamlead]: Планка: M1 не переоткрываем. `enabled=false` ⇒ сессий нет — уже норма. M2 фиксирует только границу; кто будит конец и как режет выборку — M3, папка — M4. Без расползания. Вердикт обязан закрыть старт, стоп, офлайн, неполную, hold/`stop`.

[Структурщик]: Словарь не смешивать: `Session` (серверный интервал + снимок политики) ≠ `buffer` (живой склад проб) ≠ `hold` (состояние прибора). Публичная лемма сессии живёт в media рядом с samples; кабинет лишь читает статус и задаёт политику (уже M1). `lastSeenAt` — факт связи, не часы сессии.

[Верстальщик]: Человеку нужен короткий словарь состояний, без жаргона hold/purge. Три видимых: «идёт», «закрыта», «закрыта досрочно». Причину досрочности — вторичной строкой (`buffer_full` / `policy_off` / `policy_changed`), `tabular-nums` для длительности и счётчика проб. Пустая сессия — «закрыта», бейдж «пусто», не отдельный статус.

[Архитектор]: Что открывает сессию: не «первая запись» и не cron-сетка стены. Открывает **сервер media**, когда эффективная политика имеет `enabled=true` и нет открытой сессии прибора: в момент доставки/применения контекста политики либо в момент, когда прежняя сессия закрылась, а `enabled` всё ещё true. Цепочка сессий, пока политика включена.

[Музыкант]: Первая запись как триггер старта опасна: тишина в поле = сессия «не началась», а длительность из M1 уже обещана человеку. Старт по политике на сервере — правильнее. Пробы, пришедшие в интервале, просто наполняют; тишина даёт пустую или неполную — это тоже база, честный пустой прогон.

[Математик]: Живой замер из фактуры: 61 запись / 30 мин после снятия удержания. При `durationMinutes=240` и потолке буфера ~6 ч (слово владельца) полный буфер **раньше** `endsAt` вероятен. Значит досрочное закрытие по `device_buffer_full` — не исключение, а ветка нормы: `closed_early`, reason=`buffer_full`, `actualEndedAt = receivedAt отказа`.

[Teamlead]: Принимаю ветку buffer_full как закрытие сессии. Не оставляем «сессия идёт, а приём уже stop» — это ложь в UI и дыра в Т4. Связка дальше: конец сессии обязан уметь привести к освобождению остатка (Т4) и к `release('cleanup')` на приборе — условие снятия hold только после доказанного освобождения буфера; сам механизм пробуждения — не здесь (M3).

[Структурщик]: Контракт закрытия (форма, без машины M3): сессия переходит `open → closed | closed_early`; в снимке — `startedAt`, `endsAt` (план), `actualEndedAt`, `closeReason ∈ {duration, buffer_full, policy_off, policy_changed}`, `policySnapshot` (duration/limit/criterion). Пробы после `actualEndedAt` **не** дописываются в закрытую сессию.

[Верстальщик]: Для hold на приборе человек уже видит удержание; конец сессии не должен молча «сам завестись». Если снятие hold через `cleanup` после освобождения буфера — в карточке сессии явный итог: «буфер очищен, удержание снято» / «буфер очищен, удержание снято человеком». Без авто-магии в подписи: в стволе авто-возобновления по месту нет (`deviceOverflowHold.ts:120`, `:238`).

[Архитектор]: Офлайн в момент календарного `endsAt`: сессия **всё равно закрывается по часам сервера** (`closeReason=duration`), даже если `lastSeenAt` древний. Связь прибора (`pairingStatus`, `lastSeenAt` в cabinet schema) не продлевает интервал. Иначе офлайн = бесконечная сессия — нарушает слово владельца про потолок длительности.

[Музыкант]: Пробы с опозданием после офлайна: пришли с `receivedAt >= actualEndedAt` → не в закрытую сессию. Если `enabled` ещё true и уже открыта **следующая** сессия — в неё, если `receivedAt` попадает в её интервал. Если `enabled=false` и сессий нет — проба живёт в буфере как обычный sample без session-id, до общей политики буфера; в выборку закрытой сессии не ретроактивно.

[Математик]: Неполная сессия: `0 ≤ n < selectionLimit` — не ошибка. Закрывается тем же предикатом времени/причины. Метка: `selectionAvailable = n`, `selectionShortfall = max(0, selectionLimit - n)`; пустая: `n=0`, `empty=true`. Выборка (M3) берёт `min(n, selectionLimit)` — здесь только граница и статус, не алгоритм критерия.

[Teamlead]: Смена политики посреди сессии — закрываем досрочно `policy_changed`, затем если новый effective `enabled=true` — открываем новую с новым снимком. Выключение `enabled=false` — `policy_off`, цепочка стоп. Не «мягко подменить criterion на лету»: иначе Т2-выборка по разным правилам в одной папке — каша для детекторов.

[Структурщик]: Имя состояний для API/UI одно: `open` | `closed` | `closed_early`. Не плодить `incomplete` как статус — это атрибут наполнения. `empty` — атрибут. Маппинг витрины: `open`→«идёт», `closed`→«закрыта», `closed_early`→«закрыта досрочно». Причину — enum отдельно, не третий десяток статусов.

[Верстальщик]: Витрина: на карточке прибора один бейдж статуса сессии + план/факт минут (`240 / 178`) + `n / selectionLimit`. Досрочно — `badge-warning`; штатно закрыта — `badge-success` или нейтраль; идёт — `badge-info`. Пустая закрытая — не error: `badge-ghost` «пусто». A11y: `aria-label` со словарем по-русски, не raw enum.

[Архитектор]: Итоговая конструкция старта: **включение/удержание `enabled=true` на сервере при отсутствии open-сессии**. Не сетка UTC-office, не первая проба. Office-cron UTC (фактура sweep) — чужой контур; сессионные часы = media `new Date()`, как у purge. Рекомендация формы: session-entity в media, cabinet read-model статуса.

[Музыкант]: Полный буфер и политика `stop` (`buffer-policy.ts:49`, `SMART_CLEANUP_AVAILABLE=false`): отказ `device_buffer_full` — сигнал границы. Сессия не продолжает «надеяться» на smart_cleanup. [Математик]: Инвариант: ∀ прибора не более одной `open` сессии. `endsAt` всегда = `startedAt + policySnapshot.durationMinutes` (минуты ∈ [30,600] — данность M1/владелец). `actualEndedAt ≤ endsAt`; при `duration` равенство; при early — строго раньше. [Структурщик]: Поздние пробы не «приклеивать» по device capture-time в закрытую — в фактуре источник истины времени уборки/исполнения серверный; тащить client clock = новый источник лжи. Поле `receivedAt` сервера уже есть в контуре samples; граница сессии на нём. Отдельный package-clock прибора не вводим.

[Верстальщик]: Человек о сессии видит: состояние (идёт / закрыта / закрыта досрочно), причину если early, окно времени сервера, факт пусто/неполно (`n` из `selectionLimit`), и отдельно строку удержания прибора (hold), не смешанную со статусом сессии. ## Итоговое решение консилиума

| Вопрос | Решение |
|--------|---------|
| Чьи часы меряют сессию | Только **сервер записей (media)** (`now = new Date()` на сервере). Часы прибора, кабинетный `lastSeenAt` и office-cron UTC **не** продлевают и не сдвигают границу. |
| Что открывает сессию | Сервер media при **effective `enabled=true`** и **отсутствии open-сессии** у прибора: (1) применение/доставка политики с `enabled=true`; (2) сразу после закрытия предыдущей, если `enabled` всё ещё true. **Не** первая проба, **не** календарная сетка. |
| Что закрывает сессию | (a) `now ≥ endsAt`, `endsAt = startedAt + policySnapshot.durationMinutes` → `closed`, reason=`duration`; (b) отказ приёма `device_buffer_full` при open → `closed_early`, `buffer_full`; (c) effective `enabled=false` → `closed_early`, `policy_off`; (d) смена значимых полей политики (duration/limit/criterion) или источника effective → `closed_early`, `policy_changed`, затем новая open при `enabled=true`. |
| Офлайн в момент конца | Сессия **закрывается по серверу в срок** (или earlier по policy). Офлайн **не** держит `open`. `lastSeenAt` / `pairingStatus` — диагностика связи, не часы сессии. |
| Пробы после конца / с опозданием | Принадлежность по **`receivedAt` на сервере**. В закрытую сессию **не** дописываются. При новой open и попадании в её интервал — в неё. Если сессий нет (`enabled=false`) — sample без `sessionId`, обычный буфер. Ретроактивной атрибуции по device-clock нет. |
| Неполная / пустая | Закрывается теми же правилами. Не статус, а атрибуты: `selectionAvailable=n`, `empty=(n=0)`, shortfall относительно `selectionLimit`. Выборка (не M2) берёт `min(n, limit)`. |
| Сессия и hold при `stop` | Полный буфер → early close (`buffer_full`) + hold на приборе как сейчас. **Конец сессии может снять hold** только через `release('cleanup')` и **только после** доказанного освобождения остатка буфера (Т4). Авто-возобновления «место появилось» нет. `release('human')` — по-прежнему ручной контур. |
| Словарь для человека | Состояния: **идёт** (`open`) / **закрыта** (`closed`) / **закрыта досрочно** (`closed_early`). Причина early отдельно. Пусто/неполно — подписи к счётчику, не четвёртый статус. Hold/буфер — **отдельный** индикатор от статуса сессии. |
| Вне скоупа M2 | Будильник конца, исполнение выборки и purge остатка — **M3**. Папка библиотеки и кольцо квоты — **M4**. Поля политики — **M1** (не переоткрывать). |
