# Повестка M0 — заседание server-plugin-foundation

**O1 — В каком порядке зависимостей разбирать шесть вопросов формы плагинной основы сервера?**

Единственный вердикт этой комнаты — порядок (DAG): какой вопрос фундамент, какие зависят.
Вердикты по существу самих вопросов здесь НЕ выносятся — каждый принадлежит своей будущей
комнате. Посылки шторма (Т1–Т4, MEETING_BRIEF.md) даны и не переоткрываются.

Кандидаты (простым текстом, номера — только для ссылок в DAG):

1. Словарь контрактов сервера: имена и границы — что есть плагин-манифест, три рода
   (обработчик · отчёт · витрина данных), где словарь живёт (свой пакет? модуль office?)
   и кто его владелец. Т4 решил «свой набор» — здесь его форма.
2. Дома крепления: состав серверных модулей — журнал · коллекции · устройства (под
   вопросом со шторма); что делает модуль домом (какой минимум обязан нести модуль,
   чтобы принимать плагины).
3. Дом результатов: адресация «модуль → плагин → версия → коллекция → прогон», два
   отпечатка (вход + конфигурация), заморозка состояния при выключении, окно накопления.
   Носитель — Mongo офиса? отдельная коллекция? файлы?
4. Повод и события: постфактум-запрос и живая подписка; журнал сегодня событий не
   испускает — объём и форма испускания (названная цена Т3.7).
5. Самоописание плагина для витрины: что объявляет плагин о себе (форма показа, входы,
   окно), чтобы клиентская страница могла показать и включить его, не зная заранее.
6. Первая волна и приёмка основы: шесть детекторов как плагины коллекций; первый живой
   плагин в день сдачи (Т3.11) — который именно и что считается его живым следом.

Посылки комнаты (даны, не обсуждаются): конспект шторма целиком
(docs/storm/storm-server-plugin-foundation-2026-08-17/THESES.md — Т1 определение плагина,
Т2 два темпоральных режима, Т3.1–Т3.11 свойства основы, Т4 решённая развилка «у сервера
свой набор контрактов»); границы задания — MEETING_BRIEF.md этой комнаты (Т4 не
переоткрывать; packages/agenda вне предмета; измеренное не подменяется объявленным #1950;
код — только после вердиктов).

Требование к вердикту: назвать порядок (DAG) с обоснованием рёбер И полный список посылок
вердикта в том же прогоне. Список посылок обязателен; лишняя посылка — тоже нарушение.
