# Повестка M6 — заседание server-plugin-foundation

**Q6 — Какова первая волна плагинов и что есть приёмка основы с первым живым плагином?**

Единственный вопрос комнаты — финал ратифицированного DAG: M6 ждёт M3, M4, M5 (все
сыграны). Контракты НЕ переоткрываются: словарь — M1 (авторитетен, пять полей манифеста:
id · version · kind · mountTarget · triggers), дома — M2, дом результатов — M3, поводы —
M4, самоописание — M5.

Что комната обязана решить (грани одного вопроса):

- Состав первой волны: шесть детекторов измерителя (harmonic, cepstral, spectral-flux,
  template-match, yamnet, mfcc — все пакеты с зубами) как плагины рода «обработчик»
  дома коллекций — все шесть сразу или порядок; и нужен ли в первой волне хотя бы один
  витринный (пример владельца Т2: сортировка по громкости / пиковые зоны) — решить.
- ПЕРВЫЙ живой плагин (Т3.11: основа сдаётся только вместе с ним): который именно, и
  почему он — с обоснованием против альтернатив.
- Живой след: что предъявляется как доказательство жизни — форма записи прогона в доме
  результатов (адрес M3, два отпечатка, resumeMode) на НАСТОЯЩЕЙ коллекции (какой:
  «Полевые записи 2026-08» уже существует на media с пробами тракта) — состав
  предъявления, не реализация.
- Приёмка основы: сборка Definition of Done из вердиктов M1–M5 в один приёмочный
  список — что обязано существовать и быть зелёным, чтобы основа считалась сданной;
  порядок поставки (какими PR, что первым) — укрупнённо, без нарезки задач.
- Что первая волна сознательно НЕ делает: границы, чтобы волна не расползлась
  (например: испускание событий журналом — отложенная цена Т3.7; витрина на клиенте —
  отдельная работа вне собрания).

Посылки комнаты (даны, не обсуждаются): вердикт M1 — словарь АВТОРИТЕТЕН (пять полей
манифеста: id, version, kind, mountTarget, triggers; PluginExecutor.execute; RunResult;
дом словаря packages/plugin-contracts; гейты владельца словаря); вердикт M2 (два дома:
background-office/journal, background-media/collections; IPluginHost; HOME_REGISTRY;
дефицит обоих модулей назван фактами); вердикт M3 (коллекция plugin-results в Mongo
офиса; RunAddress; два отпечатка; StateRecord/resumeMode; ConvergenceRecord); вердикт M4
(PLUGIN_TRIGGERS закрыт: journal.entry_created, collections.collection_created,
collections.sample_added; каналы notify/request; fire-and-forget с догонялкой через M3);
вердикт M5 (ShowcaseManifest: displayForm из закрытого словаря + description; включение
setPluginEnabled; у handler/report витринных полей нет); конспект шторма (Т3.5 шесть
детекторов; Т3.11 первый живой плагин при сдаче; Т2 пример владельца); факты
репозитория: шесть детекторов — пакеты packages/services/* с зубами; на media живёт
устройство field-node-2026-08 и коллекция «Полевые записи 2026-08» с пробами тракта;
границы MEETING_BRIEF.md (код — после вердиктов; #1950).

Требование к вердикту: назвать состав волны, первый живой плагин, форму живого следа,
приёмочный список и границы «не делаем» с обоснованием против альтернатив И полный
список посылок вердикта (факт/норма) в том же прогоне. Список посылок обязателен;
лишняя посылка — тоже нарушение. Контракты M1–M5 не переоткрывать; нарезку задач и
код не производить.
