# Повестка M3′ — заседание server-plugin-foundation (узкое переигрывание по вердикту аудита)

**Q3′ — Где в адресе прогона дом крепления и где объявляется окно накопления, при том что PluginId имеет вид `<org>.<kind>.<slug>` (regex `^[a-z][a-z0-9]*(\.[a-z][a-z0-9-]*){2}$`, пример `membrana.handler.mfcc`, второй сегмент — РОД плагина, НЕ модуль), а mountTarget манифеста — `HomeName` длинной формы (`background-office/journal` | `background-media/collections`)?**

Единственный вопрос комнаты. Это УЗКОЕ переигрывание M3 по вердикту аудита 17.08:
прежний вердикт M3 в части адресации стоял на ложной посылке «PluginId несёт namespace
модуля вида {namespace}:{name}» — такого M1 не выносил (находки A3-1/A3-2). Остальные
грани прежнего M3 (два отпечатка RunFingerprints, заморозка StateRecord, транзакционная
граница окна, ConvergenceRecord, носитель Mongo офиса `plugin-results` с индексами) —
В СИЛЕ и не переигрываются.

Что комната обязана решить (грани одного вопроса):

- Адресация прогона: цепочка Т3.3 «модуль → плагин → версия → коллекция → прогон» —
  как она ложится в `RunAddress`, если `pluginId` дом крепления НЕ кодирует (второй
  сегмент — род). Ввести поле дома (`mountTarget: HomeName`?) или обосновать, почему
  дом восстановим иначе — с обоснованием против альтернатив.
- Индексы носителя: прежний уникальный индекс `{pluginId, version, collectionId, runId}` —
  меняется ли составом при новом адресе.
- Окно накопления (закрытие находок A3-3/A3-4): прежний M3 положил `windowSize` в
  манифест — но M1 закрыл манифест пятью полями («шестого нет»), а расширения ведёт
  через расширяющие типы родов. Решить: окно объявляется в `HandlerManifest`
  (расширяющий тип рода — легально по M1) · в `StateRecord` · иное. Т3.10 шторма
  говорит ТОЛЬКО «накопление определяется окном» — где объявлять, Т3.10 не говорит,
  не приписывать ему этого.

Посылки комнаты (даны, не обсуждаются): M1_VERDICT.md — носитель авторитета словаря
(пять полей манифеста: id · version · kind · mountTarget · triggers; PluginId
`<org>.<kind>.<slug>` с regex; «шестого поля нет»; расширения — через
HandlerManifest/ReportManifest/ShowcaseManifest); M2_VERDICT.md (два дома длинной
формы; HomeName; HOME_REGISTRY; mountTarget: HomeName); прежний вердикт M3 в
непереигрываемой части (RunFingerprints два отпечатка; StateRecord с заморозкой;
транзакционная граница окна; ConvergenceRecord; Mongo офиса, коллекция plugin-results);
Т3.3 шторма (цепочка адресации — норма) и Т3.10 (окно — норма, БЕЗ слова «манифест»);
вердикт аудита 17.08 (находки A3-1…A3-6).

Требование к вердикту: назвать состав `RunAddress` и место объявления окна с
обоснованием против альтернатив И полный список посылок вердикта (факт/норма) в том же
прогоне. Список посылок обязателен; лишняя посылка — тоже нарушение. Непереигрываемые
грани M3 не трогать; контракты M1/M2 не переоткрывать.
