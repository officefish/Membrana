# Повестка M1 — заседание server-plugin-foundation

**Q1 — Какова форма словаря контрактов серверной плагинности: имена, границы, дом словаря, владелец?**

Единственный вопрос комнаты. По вердикту M0 (ратифицирован владельцем 17.08) это корень
DAG — все остальные комнаты (M2–M6) стоят на его словах.

Что комната обязана решить (грани одного вопроса, не отдельные вопросы):

- Имена сущностей: как называются плагин-манифест, установка/съём, включение/выключение,
  прогон, результат — серверными словами (Т4: словарь свой, клиентские имена не
  обязательны, но осознанное совпадение принципов Т1 обязательно).
- Три рода плагина (обработчик · отчёт · витрина данных, Т3.1): это три контракта, один
  контракт с родом-полем, или иная форма?
- Дом словаря: отдельный пакет (какой?), модуль внутри background-office, или иное —
  с обоснованием против альтернатив.
- Владелец словаря: кто вправе менять контракты и каким гейтом (консилиум? ADR?).
- Минимальный состав манифеста плагина: что обязан объявить каждый плагин независимо от
  рода (id, версия, род, дом крепления, повод — состав решить здесь, детали поводов — M4,
  детали самоописания для витрины — M5; сюда не залезать).

Посылки комнаты (даны, не обсуждаются): конспект шторма целиком
(docs/storm/storm-server-plugin-foundation-2026-08-17/THESES.md — Т1 определение плагина:
изоляция · версия · переключаемость на уровне модуля; Т2 два темпоральных режима;
Т3.1–Т3.11 свойства основы; Т4 решённая развилка: у сервера СВОЙ набор контрактов,
packages/agenda не трогается); вердикт M0 — порядок ратифицирован владельцем
(M0_VERDICT.md); границы MEETING_BRIEF.md (Т4 не переоткрывать; измеренное не
подменяется объявленным #1950; код — только после вердиктов; сервер — Nest в
packages/background-office и packages/background-media).

Требование к вердикту: назвать форму словаря по всем пяти граням с обоснованием против
альтернатив И полный список посылок вердикта в том же прогоне. Список посылок обязателен;
лишняя посылка — тоже нарушение. Решения соседних комнат (дома M2, адресация M3, события
M4, витрина M5, приёмка M6) не выносить — только именовать интерфейсы к ним.
