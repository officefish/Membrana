# Повестка M4 — заседание server-plugin-foundation

**Q4 — Какова форма повода: типизация triggers манифеста и испускание событий домами?**

Единственный вопрос комнаты. По ратифицированному DAG M4 ждёт M1 (сыгран) и M2 (сыгран);
задаёт форму повода для M6 («первый живой плагин запускается по поводу»). Со шторма
названа цена: журнал сегодня событий не испускает (Т3.7) — здесь решается её объём и форма.

Что комната обязана решить (грани одного вопроса):

- Типизация поводов: M1 оставил `triggers: string[]` с типизацией на этой комнате.
  Форма имени повода (закрытый словарь? пространство имён вида `<дом>.<событие>`?),
  и различение двух режимов Т2: запрос (постфактум) и подписка (живой) — два рода
  повода или одно имя с родом?
- Словарь событий первой очереди: какие события обязаны испускать два дома первой
  волны (журнал: запись внесена? коллекции: коллекция пополнена / сэмпл добавлен?) —
  минимальный закрытый список, не открытый простор.
- Механика испускания: чем испускает Nest-модуль (встроенный EventEmitter Nest?
  свой шинный интерфейс в plugin-contracts?) — с обоснованием против альтернатив;
  учесть, что дома в РАЗНЫХ пакетах (office и media) и общий процесс не гарантирован.
- Доставка и пропуск: что происходит, если плагин выключен в момент события
  (пропущенное событие теряется? копится? плагин догоняет по дому результатов?) —
  форма ответа, согласованная с заморозкой состояния из M3.
- Запрос как повод: форма вызова постфактум-плагина (кто вправе дёргать: витрина M5?
  CLI? расписание?) — только именование канала, детали витрины — M5.

Посылки комнаты (даны, не обсуждаются): вердикт M1 (пять полей манифеста, triggers:
string[] с типизацией на M4, PluginExecutor.execute(ctx)); вердикт M2 (два дома
длинной формы background-office/journal и background-media/collections, IPluginHost,
HOME_REGISTRY в plugin-contracts); вердикт M3 (дом результатов в Mongo офиса,
StateRecord с заморозкой и resumeMode, окно с транзакционной границей); конспект шторма
(Т2 два темпоральных режима; Т3.7 повод обязателен, журнал событий не испускает —
названная цена); границы MEETING_BRIEF.md (код — только после вердиктов; сервер — Nest;
дома в разных пакетах и, возможно, разных процессах).

Требование к вердикту: назвать форму повода по всем граням с обоснованием против
альтернатив И полный список посылок вердикта (факт/норма) в том же прогоне. Список
посылок обязателен; лишняя посылка — тоже нарушение. Не проектировать: поля витрины (M5),
приёмку (M6), реализацию испускания в коде — только контракты и именование.
