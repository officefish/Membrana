# M4 — вердикт: повод и события (с эрратумом аудита)

> Носитель вердикта. Протокол: `docs/seanses/server-plugin-foundation-m4-triggers-2026-08-17.md`.
> Эрратум по вердикту аудита 17.08 (A4-1, A4-2): вердикт по существу в силе,
> формулировки приведены к контрактам M1/M3.

- **Типизация:** `PluginTrigger` — закрытый юнион из const-объекта `PLUGIN_TRIGGERS`
  в `plugin-contracts`; форма имени `<дом>.<событие>`; произвольные строки исключены.
- **Словарь первой волны (закрыт):** `journal.entry_created` ·
  `collections.collection_created` · `collections.sample_added`. Расширение — через
  `plugin-contracts` с вердиктом комнаты или ADR.
- **Один словарь на оба режима Т2;** различие — каналом дома: `notify` (живой,
  подписка) · `request` (постфактум, запрос). Плагин не знает канала доставки.
- **Payload:** `IPluginEvent<T> { trigger, occurredAt, payload }` + три минимальных
  payload-типа в `plugin-contracts`.
- **Механика:** дом вызывает `IPluginHost.notify(event)`. EventEmitter Nest исключён
  (процессная граница), Redis исключён (лишняя инфраструктура). Транспорт — вне контракта.
- **Доставка:** live — fire-and-forget; выключенный плагин живой сигнал теряет,
  буферизация не вводится.
- **ЭРРАТУМ (A4-1).** Догонялка: при включении плагин **читает дом результатов по
  `RunAddress` за своё окно** — механизм называется своим именем. Поле `resumeMode`
  (по M3: поле `RunRecord`, значения `'from-freeze' | 'fresh'`) — лишь **объявление**
  того, с чего прогон начал; механизмом чтения оно не является и в `StateRecord` не живёт.
- **ЭРРАТУМ (A4-2).** Сигнатура запроса: `request(pluginId: PluginId, …)` — branded-тип
  из M1, не сырая строка (как у `setPluginEnabled` в M5).
- **Журнал и Т3.7:** `journal.entry_created` в словаре как будущая точка; реализация
  испускания в доме журнала — после снятия отложенной цены Т3.7, не в этом собрании.
