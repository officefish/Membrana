# Повестка M3 — заседание server-plugin-foundation

**Q3 — Какова форма дома результатов: адресация, отпечатки, состояние, окно, носитель?**

Единственный вопрос комнаты. По ратифицированному DAG M3 ждёт M1 (сыгран: словарь) и
M2 (сыгран: дома) и задаёт вход для M6 («живой след» первого плагина — прогон в доме
результатов).

Что комната обязана решить (грани одного вопроса):

- Адресация записи результата: со шторма дана цепочка «модуль → плагин → версия →
  коллекция → прогон» (Т3.3); здесь — её точная форма с учётом вердиктов M1/M2
  (PluginId уже несёт пространство имён; mountTarget уже длинной формы) — без двойного
  кодирования одного и того же в адресе.
- Два отпечатка (Т3.4): отпечаток входа (хеш состава коллекции) и отпечаток
  конфигурации (какие плагины каких версий включены) — что именно хешируется, где
  отпечатки лежат в записи, и как по расхождению входа результат объявляется протухшим
  (кем: чтением? сторожем?).
- Состояние накопительного плагина (Т3.8): жилец того же дома под версией; форма
  заморозки при выключении и честное объявление «с заморозки»/«заново» при включении.
- Окно накопления (Т3.10): где объявляется окно (манифест? запись состояния?) и что
  происходит на границе окна.
- Сходимость живого и пересчёта (Т3.9): где живёт зуб сверяемости — форма, не реализация.
- Носитель дома: Mongo офиса (там уже живёт архивариус с 106К спанов) · отдельная
  коллекция · файлы — с обоснованием против альтернатив; учесть, что коллекции звуков
  живут в media, а журнал в office (вердикт M2).

Посылки комнаты (даны, не обсуждаются): вердикт M1
(docs/seanses/server-plugin-foundation-m1-vocabulary-2026-08-17.md — PluginId с
пространством имён, RunResult с completedAt и kind, PluginContext — заглушка до M3);
вердикт M2 (docs/seanses/server-plugin-foundation-m2-mount-homes-2026-08-17.md — два
дома длинной формы background-office/journal и background-media/collections, HOME_REGISTRY
в plugin-contracts); конспект шторма (Т3.3 адресация, Т3.4 два отпечатка, Т3.8 заморозка,
Т3.9 сходимость, Т3.10 окно); границы MEETING_BRIEF.md (измеренное не подменяется
объявленным #1950; код — только после вердиктов); факт репозитория: контейнер сессий
архивариуса живёт в Mongo офиса (packages/background-office, ~106К спанов), медиа несёт
свою БД (Prisma) для коллекций и сэмплов.

Требование к вердикту: назвать форму дома результатов по всем граням с обоснованием
против альтернатив И полный список посылок вердикта в том же прогоне (факт/норма).
Список посылок обязателен; лишняя посылка — тоже нарушение. Не проектировать: форму
событий (M4), поля витрины (M5), приёмку (M6) — только именовать интерфейсы.
