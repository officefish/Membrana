# Повестка M2 — заседание server-plugin-foundation

**Q2 — Каков состав серверных модулей-домов и что делает модуль домом, способным принимать плагины?**

Единственный вопрос комнаты. По ратифицированному DAG M2 ждёт M1 (сыгран) и задаёт
первое звено адресации для M3, конкретный дом «журнал» для M4 и домены самоописания для M5.

Что комната обязана решить (грани одного вопроса):

- Состав домов первой очереди: журнал · коллекции — оба со шторма; «устройства» — под
  вопросом со шторма (Т3.2), решить здесь: входят сейчас, позже, или никогда.
- Что делает модуль домом: минимальный контракт дома — что обязан нести Nest-модуль,
  чтобы значиться допустимым `mountTarget` манифеста (вердикт M1). Форма: интерфейс?
  регистрация в реестре домов? декоратор?
- Кто ведёт реестр домов: где записано «журнал — дом, коллекции — дом», как дом
  добавляется (гейт), и как манифест с несуществующим `mountTarget` отвергается.
- Соответствие журнала и коллекций этому контракту сегодня: чего им не хватает до
  статуса дома (перечислить фактами по коду, не проектировать доработку — доработка
  уедет в задачи после M6).

Посылки комнаты (даны, не обсуждаются): вердикт M1 целиком
(docs/seanses/server-plugin-foundation-m1-vocabulary-2026-08-17.md — имена, discriminated
union родов, дом словаря packages/plugin-contracts, пять полей манифеста, mountTarget:
string как адрес Nest-модуля крепления); конспект шторма
(docs/storm/storm-server-plugin-foundation-2026-08-17/THESES.md — Т1–Т4, в частности
Т3.2 «журнал · коллекции · (устройства?)» и Т2 два темпоральных режима); вердикт M0 —
порядок ратифицирован владельцем; границы MEETING_BRIEF.md (Т4 не переоткрывать;
packages/agenda вне предмета; код — только после вердиктов; сервер — Nest в
packages/background-office и packages/background-media; журнал живёт в office, коллекции
и сэмплы — в media).

Требование к вердикту: назвать состав домов и контракт дома по всем граням с обоснованием
против альтернатив И полный список посылок вердикта в том же прогоне. Список посылок
обязателен; лишняя посылка — тоже нарушение. Не проектировать: адресацию результатов (M3),
форму событий (M4), поля витрины (M5), приёмку (M6) — только именовать интерфейсы.
