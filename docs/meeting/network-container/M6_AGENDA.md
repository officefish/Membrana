# Повестка M6 — заседание network-container

**В6 — Где живут исходящие правила класса K1 словом и каким зубом они проверяются?**

Единственный вердикт этой комнаты — форма правила направления трафика (класс K1:
«office не ходит в Linear — ходит через media-VPS») как проверяемого. Политика машины
(В7 — режет по источнику, не по направлению) — чужая комната, здесь НЕ решается.

Что требуется решить:

- Носитель правила: где правило K1 живёт словом — файл правил в доме docs/audit/network?
  раздел infra-policy? отдельный canon-док? Правило — не единица ленты (M1), но контейнер
  network — его дом или нет?
- Форма записи правила: закрытые поля (источник-зона, назначение-класс, вердикт
  allowed/forbidden/via, ссылка на прецедент) — чтобы правило было данными, не прозой.
- Зуб: что и когда проверяет — снимки ленты против правил (наблюдение нарушило правило →
  находка в канал M4)? статически код (гейт-событие «правка серверных вызовов» из M4)?
  Оба? Кто исполняет зуб НЕ решается (держатель — M4, кандидат Ожегов).
- Миграция K1: сегодня правило живёт прозой в коде (media-snapshot.client) — акт
  переноса в носитель без изменения поведения кода (не чинить сеть, #1425).
