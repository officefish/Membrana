# Задание-нарезка: магистраль `logging-observability-contour`

> Сборка активных вердиктов заседания `logging-observability-cut` (2026-08-24).
> Вход: шторм `storm-logging-observability-2026-08-24` (Т1–Т6 + Д1, все со словом
> владельца) + полевой разбор 23.08 (PR #2111). Порядок M0 ратифицирован владельцем.
> **Статус: РАТИФИЦИРОВАНО владельцем 2026-08-24.** Слово владельца по обоим открытым
> пунктам: очередь `A → {B ∥ C}` — принята как есть (A строго первым); тишина сторожа —
> только телеграм, в картотеку не летит.

---

## Очередь работ

```text
A (сторож диска, Д1 — первым)
   → { B (контракт отказа + номер) ∥ C (пульс дежурства) }
        → D (/health/deep — после B и C)
        → E (контейнер Сентри — после контракта B)   [E ∥ C, E ∥ D]
```

Очередь выведена из: Д1 (сторож — первым, до всех сборщиков) · Т1 (издатели прежде
сборщиков) · ратифицированного DAG M0 (К1→К2, К4→К2, сторож независим). B и C можно
вести параллельно; E не начинать раньше, чем контракт B зафиксирован в коде (Сентри
чеканит номера ПО контракту, не наоборот).

Словарь «издатель/сборщик» — относительный, фиксируем: B, C, D издают (кабинет/узел
рождают числа и номера); E (Сентри) — сборщик-картотека; будущие Prometheus/Grafana —
сборщики над D. Реплика M0 «(2) собирает числа кабинета» — о том же D-уровне
относительно пульса, противоречия нет.

*Выбор председателя, ратифицирован владельцем 2026-08-24:* строка `A → {B ∥ C}` делает
сторожа блокирующим и для издателей (строже буквы Д1, которая требует его лишь прежде
**сборщиков**). Владелец принял консервативную трактовку: **A строго первым**.

---

## Кусок A — сторож диска (Д1)

**Вердикт:** [m1c-disk-guard](../../seanses/logging-observability-cut-m1c-disk-guard-2026-08-24.md)

Что делается: ops-юнит на машине с диском (media / кабинет): каждые 5 мин `df` тома
записи → `T_remain = free / write_rate`; при `T_remain < 60 мин` — тревога **прямым**
HTTPS в Telegram Bot API (свой токен `DISK_WATCHDOG_TG_*`, не офисный), офис — только
fallback; sibling-таймер на том же хосте поднимает stale-тревогу при тишине сторожа
дольше 15 мин. Первым шагом куска — добыча фактуры: замер достижимости
`api.telegram.org` с хостов media/кабинета; до успеха прямой путь в прод не объявляется
готовым (degraded: лог + офис).

**DoD (из вердикта M1c):** тревога доставляется при мёртвом офисе (предикат A);
stale-тревога не позже 20 мин после остановки сторожа (B); тишина ≠ «всё хорошо» (C);
замер достижимости записан (D); секретов в репозитории нет, прод не тронут без слова
владельца (E); формула `T_remain` и калибровка `write_rate_ref` тестируемы (F);
сторож активен без работающих сборщиков (G).

## Кусок B — контракт отказа и номер происшествия

**Вердикт:** [m1-incident-number](../../seanses/logging-observability-cut-m1-incident-number-2026-08-24.md)

Что делается: `AllExceptionsFilter` кабинета перестаёт отдавать голую пятисотку. Отказ
несёт `genus: broken | busy | unreachable` (Т3); при `broken` — `incidentId` в теле и
заголовке `X-Incident-Id` (CORS expose), рядом `requestId`; в лог — структурированные
`genus`/`incidentId`/`requestId` тем же литералом. Форма номера: `INC-XXXX-XXXX`
(Crockford Base32, диктуемо голосом), чеканит Сентри; пока Сентри нет/недоступен —
суррогат `TMP-XXXX-XXXX` (в картотеку не пишется). Кусок жизнеспособен ДО куска E:
до Сентри все номера — TMP, лицо ошибки уже есть.

**DoD (из вердикта M1, 8 предикатов):** broken всегда с непустым `incidentId`;
заголовок = телу; лог несёт тот же литерал; при живом Сентри INC находим в картотеке;
при мёртвом — TMP, не 500-простыня; busy/unreachable без номера; `X-Request-Id` не
сломан; #2113/#2110 встают на контракт без переделки (ревью-проверка: нет новых
обязательных зависимостей журнала/сортировки от клиента Сентри).

## Кусок C — пульс дежурства

**Вердикт:** [m1b-duty-pulse](../../seanses/logging-observability-cut-m1b-duty-pulse-2026-08-24.md)

Что делается: процесс узла/борда в режиме duty-записи издаёт раз в 60 с
`DutyPulseSample` (`probes_total · step_s · media_used_mb / media_cap_mb`) на локальную
ленту; издание не зависит от кабинета (замерено 23.08). Локальный детектор тишины:
stale > 60 с, silent > 120 с; переход alive→silent рождает **одно** происшествие через
контракт куска B (дедуп до выхода из silent). Кабинетная read-model пульса — optional.

**DoD (из вердикта M1b, 5 предикатов):** тик ≤ 60 с при живой записи и лежащем
кабинете; витрина показывает три числа и возраст (`ok|stale|silent` по порогам 60/120);
тишина > 120 с → одно происшествие в картотеке, без размножения; при нормальном тике
записей пульса в картотеке нет; издание не тянет поля детектора и кабинет.

## Кусок D — `/health/deep`

**Вердикт:** [m2-health-deep](../../seanses/logging-observability-cut-m2-health-deep-2026-08-24.md)

Что делается: новый endpoint кабинета. Обязательные числа: `tape_length`,
`db_latency_ms`, `ingest_arrived_ratio` (окно 900 с) + `status: ok|degraded`, явные
warn/fail пороги с физическим смыслом (tape fail — из калибровки квадратичной стоимости;
db 1000/3000 мс; ratio 0,95/0,80), `measured_at`, `requestId`. Отказ — строго по
контракту B (genus; broken → incidentId). Optional `duty_pulse` словами куска C, без
переименований. Цена вызова: p99 ≤ 50 мс, источники — gauge с write-path / TTL-sample,
никаких Θ(N²) на request-path. `/health` не трогается, liveness на deep не переводится.

**DoD (из вердикта M2, 7 предикатов):** схема зафиксирована; request-path без
квадратичных агрегатов; p99 ≤ 50 мс на стенде; **ретро-предикат 23.08** — обязательная
тест-фикстура (`tape_length ≥ 2400` или `db_latency_ms ≥ 3900` → не «ок», числа в
теле); калибровка α записана рядом с контрактом; `/health` не расширен; сборщиков и
экранов в куске нет.

## Кусок E — контейнер Сентри на офисе

**Решение владельца (Т5/Т6), реализация по контракту B.**

Что делается: полный Sentry отдельным контейнером на офисе — картотека происшествий.
Чеканка INC подключается к контракту B (TMP → INC); в картотеку летят происшествия и
сбои пульса/сторожа, не сами пульс и метрики (Т6). Первым шагом куска — добыча фактуры:
замер свободных мощностей офиса (Т5: несколько ГБ памяти — цена принята; при упоре —
наращивание мощностей офиса, слово владельца). Прод не трогать без слова владельца.

**DoD:** контейнер поднят и изолирован от общего дома логов; ошибка рода «сломан» из
кабинета рождает запись в картотеке, находимую по продиктованному `INC-…`; группировка
повторов и счётчик работают; сбой пульса (M1b) виден в картотеке как происшествие;
замер мощностей записан; пульс и метрики в картотеку не летят.

*Пункт закрыт словом владельца 2026-08-24:* тишина сторожа — **только телеграм**
(`[disk-watchdog-stale]`, как в вердикте M1c); в картотеку Сентри не летит.

## Границы (унаследованы заданием и вердиктами)

- **Прод не трогать без слова владельца** — каждый кусок отдаёт план/код/тесты; деплой
  отдельным словом.
- **#2113 (линеаризация журнала) и #2110 (плагин сортировки)** — соседние линии, не
  наши; контракт B согласован так, что обе встают на него без переделки (`incidentId` —
  opaque string; полей сортировки и алгоритма линеаризации вердикт не предписывает).
- **Общий дом логов (Loki и род ему)** — отложено штормом, здесь не решается.
- **Санитарный список прямых вызовов Anthropic** — не в этой магистрали.
- Экраны и сборщики метрик (Prometheus/Grafana и род) — не раньше, чем издатели B, C, D
  живы (Т1); в этой нарезке их нет.
