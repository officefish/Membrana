### Вердикты — кратко

- **M1 (К1):** отказ несёт `genus` (`broken|busy|unreachable`); при `broken` —
  `incidentId` `INC-XXXX-XXXX` (Crockford Base32, чеканит Сентри) в теле **и** заголовке
  `X-Incident-Id`, рядом `requestId`; Сентри недоступен → суррогат `TMP-…`, лицо
  сохраняется; `busy`/`unreachable` номера не несут; `X-Request-Id` живёт рядом.
- **M1b (К4):** пульс издаёт узел записи (не кабинет): раз в 60 с
  `probes_total · step_s · media_used_mb/media_cap_mb` на локальную ленту; тишина
  ловится локально (stale 60 с, silent 120 с); переход alive→silent → **одно**
  происшествие по контракту К1; сам пульс в картотеку не летит.
- **M1c (К3):** сторож живёт на машине с диском; primary — прямой HTTPS в Bot API со
  своим токеном, офис — только fallback; sibling-таймер на том же хосте ловит тишину
  сторожа (15 мин); пороги в минутах оставшейся записи (fail 60 мин); прямой путь в
  прод не включать до замера достижимости `api.telegram.org` с хоста.
- **M2 (К2):** `/health/deep` издаёт `tape_length`, `db_latency_ms`,
  `ingest_arrived_ratio` (+ optional `duty_pulse` словами M1b), явные warn/fail пороги
  с физическим смыслом, отказ — по контракту M1; p99 ≤ 50 мс, никаких Θ(N²) на
  request-path; ретро-предикат «авария 23.08 видна» — обязательная тест-фикстура;
  `/health` не трогается.
