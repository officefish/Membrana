## Данности (шторм, не переоткрывать)

T1–T17 отчёта шторма. Ключевые: умолчание «стоп»; сигнал «полон» — отказ сервера с машинным кодом; связь не рвётся; политика у прибора, галочка — привязка; буфер — вещдоки; одно поведение на доску и микрофон; одно окно на факт, повтор при новом запуске.

## Вердикты комнат (только то, что вынесла комната)

| M | Вопрос | Решение (суть) | Что НЕ строить | Носитель | Протокол |
|---|---|---|---|---|---|
| M1 (P) | Политика на сервере и её место | Поле политики в записи прибора на сервере записей, разноска из кабинета тем же классом, что квоты; клиентская настройка — зеркало, не хозяин. Страница мембраны: режим, параметры, галочка «применить ко всем» — привязка с явным подтверждением; при снятой — режим на прибор в списке узлов на той же витрине. Умолчание при первой привязке, при обновлении старого прибора и при любой дыре синка/порче — `stop`; неизвестное значение отвергается; откат на старую автоочистку запрещён. Умная очистка выбираема только при полном наборе параметров (порог, критерий отбора, защита вещдоков), проверяет сервер (кабинет при записи, сервер записей при разноске); пустой набор — режим не записывается | отдельную страницу настроек прибора; мастер-политику в плагине; дефолт автоочистки; чтение политики прибором через кабинет; галочку-снимок; автозаполнение параметров; алгоритм очистки (T12); всё из M2–M5; тарифы #2297 | сервер записей + кабинет | `buffer-full-stop-m1-policy-2026-09-06.md` |
| M2 (C) | Код отказа и его словарь | Отказ «полон» — доменный по конвенции кабинета 12.08: HTTP 200 + `{ok:false, reason, …}`; 413 остаётся только настоящему «тело слишком большое». `reason` из закрытого списка: `device_buffer_full`, `user_storage_full`; место для прочих (T15) без назначения литералов. Обязательные поля: `buffer{usedBytes,limitBytes}`, `userStorage{usedBytes,limitBytes}`, `overflowPolicy` (stop / smart_cleanup), `overflowId` — идентификатор эпизода переполнения, стабильный на все отказы эпизода. Словарь — единственный носитель в shared-пакете монорепо: сервер чеканит литералы; **потребители — только импорт + проверка полноты; три копии строк запрещены** | остановку и память на приборе (M3); каналы после (M4); окно (M5); тексты прочих причин (T15); алгоритм очистки (T12); тарифы (#2297); HTTP-код как причину; общий «квота» без субъекта; разбор английского текста | сервер записей + shared-пакет | `buffer-full-stop-m2-refusal-code-2026-09-06.md` |
| M3 (S) | Что останавливается на приборе и как один раз | Гасится при `stop`: складирование и отправка новых проб, активная запись, новый старт записи; сценарий не убивается — медиа-ветка в постоянное удержание без авто-возобновления. Живёт: связь с сервером, детекция и наблюдение без записи, рантайм доски и плагина; гасить телеметрию «вместо» отправки запрещено. Источник вердикта: главный — ответ сервера по M2 (`ok:false` + `reason` + `overflowId`), вторичный — своё чтение квоты до отправки; при расхождении главнее сервер; локальное удержание без id повышается до серверного `overflowId` без второго эпизода и окна. Память — один носитель на прибор `DeviceOverflowHold`: факт + `overflowId` + снимок причины/режима; один id → один сигнал окна; новый запуск при удержании отбивается тем же фактом; удержание переживает рестарт сценария; сброс — действием человека или очисткой (в M3 не специфицируется). Общий носитель вердикта + два тонких адаптера (доска, микрофон) | стоп канала/телеметрии как суррогат; убийство сценария целиком; дубль машины состояний в доске и микрофоне; авто-возобновление; ретраи отправки при удержании; поля/коды M2; каналы M4; окно M5; T12; #2297 | прибор (клиент) | `buffer-full-stop-m3-device-stop-2026-09-06.md` |
| M4 (L) | Жизнь после остановки | Обязаны жить после `stop`: health-ping → link-state на текущей частоте контракта узла; чтение квоты ≥ 1/мин; состояние сценария/узла на чтение с push при входе в удержание и при его смене. Законно замолкает живая медиа-телеметрия `telemetry-track/v1`; её молчание — не остановка жизни узла. Узел несёт «остановлен: буфер полон» в состоянии узла/сценария отдельным значением: фаза, `reason` из словаря M2, тот же `overflowId`; кабинет показывает «жив, не пишет, причина», не «нет телеметрии». «Умер» ⇔ молчание health-ping/link-state дольше существующего таймаута link-state кабинета (новый порог от телеметрии не вводится); «штатный стоп» ⇔ связь жива ∧ удержание активно ∧ `overflowId` есть. Ночной обрыв — рабочая гипотеза №1: производитель телеметрии привязан к циклу записи сегментов; вещдоки: (1) путь в коде, (2) репродукция «стоп записи без переполнения → телеметрии нет при живом сердцебиении», (3) временнáя склейка с первой волной 413 без падения линка; если (1) ложен — гипотеза о падении вебсокет-сессии | смерть по телеметрии; фиктивную телеметрию 6/мин; второй канал только для переполнения; авто-возобновление; переоткрытие M3 (что гасится/память/сброс), M5 (окно), M2 (код/поля), T12, #2297 | прибор + кабинет | `buffer-full-stop-m4-life-after-2026-09-06.md` |
| M5 (W) | Окно оператора и дороги из него | Окно строится только из ответа отказа M2 + статуса удержания (M3/M4), без второго запроса квоты: причина словами (таблица код→текст; неизвестный код → «Буфер полон» + приглушённый сырой код), две шкалы buffer и коллекции — занято/лимит/свободно, время факта (одно на `overflowId`), режим/фаза прибора, что записано до остановки — **если есть в состоянии узла, иначе явная строка «н/д»**. Кнопки: 1) «Вывезти в набор» — первая, не стирает вещдок (T7), ведёт в существующий вывоз библиотеки (#2226); 2) «Почистить» — только с подтверждением и счётом того, что уйдёт, после — факт ушедшего; 3) «Сменить тариф» — в кабинет на мембрану (#2286); если переходить некуда — выключена + текст «доступных тарифов для перехода нет». Вне окна (T8): плашка на панели записи/квоты — причина + остаток, **клик открывает то же окно того же `overflowId`**; статус сценария/узла — фаза + причина + «жив, не пишет»; бейдж на доске того же факта. Поведение окна — посылка M3/T5/T9, не переоткрыто; закрытие не снимает удержание. Один презентационный носитель модалки + два адаптера; после чистки/вывоза — «что и сколько ушло», «вывезено: N» ≠ «удалено: N», пусто = показать пусто | поля/код M2; машину удержания M3; каналы M4; алгоритм очистки T12; тарифы в базе #2297; вывоз пролёта #2302; авто-возобновление; второе окно; обход стопа; повторный запрос квоты для окна | прибор (клиент) | `buffer-full-stop-m5-operator-window-2026-09-06.md` |

## Открытые швы (ни одна комната не решала — дозаказ при раздаче, не вердикт)

- **Время факта переполнения.** M5 требует показать время факта (одно на `overflowId`), но ни ответ M2, ни удержание M3, ни состояние M4 поля времени не несут, а второй запрос запрещён. Кандидат: чеканить время вместе с `overflowId` на сервере (носитель M2) — решение исполнителю по слову владельца при раздаче; в эпике стоит открытым.
- Что записано до остановки — данные есть только если состояние узла их несёт; иначе «н/д» (M5 захеджировала).

## Швы между вердиктами (для раздачи)

- `overflowId`: чеканит сервер (M2) → прибор хранит зеркало в удержании (M3) → узел публикует в состоянии (M4) → окно одно на id (M5) ← T9.
- Дороги из окна упираются во внешнее: тарифы в базе #2297 (сегодня один из трёх — кнопка честно выключена), вывоз #2302 — не узлы.
- Ночной анти-паттерн (телеметрия оборвалась, пробы стучали 11 ч) закрыт тремя комнатами: M3 запрещает гасить канал вместо отправки, M4 развязывает признаки жизни от медиа-телеметрии, M5 показывает причину без окна.
