## Данности (шторм, не переоткрывать)

T1–T17 отчёта шторма; ключевые: умолчание «стоп»; сигнал «полон» — отказ сервера с машинным кодом; связь не рвётся; политика у прибора, галочка — привязка; буфер — вещдоки; одно поведение на доску и микрофон; одно окно на факт, повтор при новом запуске.

## Вердикты

| M | Вопрос | Решение (суть) | Носитель | Протокол |
|---|---|---|---|---|
| M1 (P) | Политика на сервере и её место | Поле политики в записи прибора на сервере записей, разноска из кабинета как квота; клиентская настройка — зеркало. Страница мембраны: режим, параметры, галочка-привязка с подтверждением; при снятой — на прибор в списке узлов. Умолчание и любая дыра — `stop`; умная очистка выбираема только при полном наборе параметров, проверяет сервер | сервер записей + кабинет | `buffer-full-stop-m1-policy-2026-09-06.md` |
| M2 (C) | Код отказа и его словарь | Отказ «полон» — доменный: 200 + `{ok:false, reason}`; 413 — только настоящему «большое тело». `reason` ∈ {`device_buffer_full`, `user_storage_full`}, место для прочих (T15). Поля: занято/лимит по буферу и хранилищу, `overflowPolicy`, `overflowId` (один на эпизод). Словарь — один shared-пакет; сервер чеканит | сервер записей + shared-пакет | `buffer-full-stop-m2-refusal-code-2026-09-06.md` |
| M3 (S) | Что останавливается на приборе и как один раз | Гасится: новые пробы, активная запись, новый старт; медиа-ветка — в постоянное удержание без авто-возобновления. Живёт: связь, детекция без записи, рантайм. Главный источник — ответ сервера (M2), вторичный — своё чтение квоты; сервер главнее. `DeviceOverflowHold` на прибор: факт + `overflowId`; один id → одно окно; новый запуск отбивается тем же фактом. Общий носитель + два адаптера (доска, микрофон) | прибор (клиент) | `buffer-full-stop-m3-device-stop-2026-09-06.md` |
| M4 (L) | Жизнь после остановки | _(при вёрстке: посылка «M1» снята как лишняя по аудиту; T1 — фон)_ Живут: health-ping/link-state, чтение квоты ≥1/мин, состояние узла с push при смене удержания; медиа-телеметрия законно молчит. Узел несёт «остановлен: буфер полон» в состоянии узла/сценария с `reason` и `overflowId`. «Умер» — по молчанию health/link-state (существующий таймаут), не по телеметрии. Ночной обрыв — гипотеза №1 **подтверждена кодом** (аудит M4: телеметрия пишется только после импорта клипа микрофона); остаётся репродукция «стоп записи без переполнения → телеметрии нет при живом heartbeat». Таймаут «умер» — назвать один из трёх существующих (кандидат: presence-окно 300 с) | прибор + кабинет | `buffer-full-stop-m4-life-after-2026-09-06.md` |
| M5 (W) | Окно оператора и дороги из него | Окно из ответа M2 + статуса M3/M4 без второго запроса: причина словами, две шкалы, время факта, режим, что записано. Кнопки: вывезти в набор (первая — не стирает вещдок) → почистить (подтверждение + счёт) → сменить тариф (если некуда — выключена с честным текстом). Вне окна: плашка, статус сценария, бейдж доски. Один носитель + два адаптера; после действия — «что и сколько ушло», пусто показывать пустым | прибор (клиент) | `buffer-full-stop-m5-operator-window-2026-09-06.md` |

## Швы между вердиктами (для раздачи, не для переоткрытия)

- `overflowId`: чеканит сервер (M2) → прибор хранит зеркало в удержании (M3) → узел публикует в состоянии (M4) → окно одно на id (M5).
- `overflowPolicy` в ответе (M2) ≠ `bufferPolicy` в настройке прибора (M1: зеркало) — разные сущности, следить за именами.
- Однократность считается по отказам, повтор — по новому запуску (M3, DoD 3) — посылка для M5.
- Дороги из окна упираются во внешнее: тарифы в базе #2297, вывоз #2302 — не узлы.
