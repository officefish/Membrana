# Заседание «Полный буфер: контракт остановки» — M2 (C) Код отказа и его словарь

**Объединяющее задание (одно на всё заседание):** превратить тезисы шторма 06.09 в исполнимый
контракт остановки при полном буфере — сервер, прибор, оператор, — чтобы ночь 05→06.09 не
повторилась и вещдоки в буфере не пострадали.

**Порядок M0 (ратифицирован владельцем 06.09):** M1 (P) политика → **M2 (C) код отказа** →
M3 (S) остановка на приборе → M4 (L) жизнь после → M5 (W) окно оператора. Предшественник —
M1; его вердикт — посылка этой комнаты.

## Данности (закрыто штормом, НЕ переоткрывать)

- Сигнал «полон» для прибора — отказ сервера с конкретным кодом ошибки; по коду прибор знает, что показать (T14).
- Другие причины отказа — тот же механизм, другие тексты; разбираются отдельно, позже; здесь — только базовый сценарий «буфер полон» (T15).
- При полном буфере связь не рвётся: ограничение только на складирование новых медиафайлов (T16).
- Окно оператора строится из ответа сервера, не из догадок прибора; в окне — свободное место по буферу и по коллекциям (T3, T4, T8).

## Вердикт M1 (посылка, не переоткрывать)

- Политика переполнения — поле в записи прибора на сервере записей, разносится из кабинета; клиентская настройка — зеркало.
- Умолчание fail-closed — `stop`; умная очистка выбираема только при полном наборе параметров, проверяет сервер.
- Следствие для этой комнаты: сервер знает режим прибора в момент отказа и может назвать его в ответе.

## Фактура (сверено в стволе da051639 и на проде 06.09)

- Сегодня при полном буфере сервер записей отвечает на загрузку пробы HTTP 413; текст различает «Buffer storage quota exceeded» и «User storage quota exceeded», но машинного кода причины нет ни у одного, чисел занято/лимит и режима в ответе нет; прибор по коду не отличит «буфер полон» от «хранилище полно» и от «слишком большое тело».
- Кабинет для доменных отказов держит конвенцию 12.08: транспортные 4xx только за транспорт, доменный отказ — 200 с полем `ok:false` и машинной причиной `reason` из закрытого списка (пример — тарифы: `unknown_target_tariff`, `same_tariff`, `self_gate_closed`).
- Ответ квоты прибора (`/quota`) уже несёт `buffer.usedBytes/limitBytes` и `userStorage.usedBytes/limitBytes` — числа для окна на сервере есть.
- Ночью прибор получил ~6500 одинаковых 413 за 11 часов и ни разу не остановился.

## Вопрос M2 (ровно один)

**Q2 — Каким должен быть ответ сервера записей на попытку сложить пробу в полный буфер, чтобы прибор остановился по нему один раз, а окно оператора собралось из него без догадок: (а) транспорт — оставить 413 или перейти на доменный отказ по конвенции кабинета (200 + ok:false + reason), и почему; (б) машинный код причины «буфер полон» и его словарь — закрытый список причин с отличием «буфер прибора полон» от «хранилище коллекций полно» и от прочих отказов; (в) обязательные поля ответа помимо кода — занято/лимит по буферу и по коллекциям, режим прибора (stop / умная очистка), идентификатор факта переполнения для однократности окна; (г) где этот словарь живёт как единственный носитель, чтобы сервер, кабинет и прибор читали один список, а не три копии? ГРАНИЦЫ: не решать, что именно останавливается на приборе и как он помнит остановку (M3), какие каналы живут после остановки (M4), содержание и кнопки окна (M5), тексты других причин отказа (T15), алгоритм умной очистки (T12), тарифы в базе (#2297).**

Вердикт обязан назвать: транспорт и код, словарь причин (закрытый список, базовый сценарий +
место для остальных без их решения), обязательные поля ответа, носитель словаря и кто его
проверяет, что строить и что НЕ строить.

**Требование аудита (HR5):** в «Список посылок» вносить только те посылки, на которые комната сослалась в обсуждении; неиспользованная посылка — лишняя.

**⚠️ Требование к вердикту (машинный гейт):** вердикт ОБЯЗАН нести секцию-заголовок
**«Список посылок»** с типом каждой (норма/факт) и основанием в этом же протоколе. Вердикт
без неё = заседание не состоялось (S-M2); дописать задним числом запрещено.
