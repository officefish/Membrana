## Порядок (M0)

Вердикт M0 (протокол `docs/seanses/buffer-full-stop-m0-order-2026-09-06.md`), **ратифицирован владельцем 06.09** («Ратифицируем»):

```text
M1 = (P) Политика на сервере и её место
 → M2 = (C) Код отказа и его словарь
   → M3 = (S) Что именно останавливается на приборе и как один раз
   → M4 = (L) Жизнь после остановки        (в календаре S перед L; по предмету S ∥ L)
     → M5 = (W) Окно оператора и дороги из него
```

Рёбра: P→C, C→S, C→L, C→W, S→W, **L→W — только статус** (status-only: окно показывает состояние «жив/остановлен», но не зависит от L по существу — оговорка комнаты, стр. 76 протокола, потерянная в итоговой таблице; возвращена по аудиту). Не узлы: тарифы #2297, вывоз #2302 (упоры дорог из окна).
Первый созыв M0 отклонён гейтом до прогона (повестка не вместилась при общих контекстах) — повтор с `--no-context --no-rag`, кредит первого не потрачен.

## Вердикт M1 (P) — кратко (полный: протокол)

- **Носитель:** сервер записей — поле политики переполнения в записи прибора, с разноской из кабинета тем же классом, что квоты; клиентский `bufferPolicy` — зеркало, не хозяин.
- **Место в кабинете:** страница мембраны — режим, параметры, галочка «применить ко всем» (привязка, с подтверждением); при снятой привязке — режим на прибор в списке узлов на той же витрине; отдельной страницы прибора не строим.
- **Умолчание fail-closed:** при первой привязке и при обновлении старого прибора — `stop`; backfill → stop; неизвестное значение отвергается; при дыре синка/порче — effective = stop на сервере и на клиенте; fallback на старую автоочистку запрещён.
- **Умная очистка:** выбираема только при полном наборе параметров (порог, критерий отбора, защита вещдоков); проверяет сервер (кабинет при записи, сервер записей при разноске); пустой/частичный набор — режим не записывается.
- **Не строить:** мастер-политику в плагине; дефолт автоочистки; чтение политики прибором через кабинет; галочку-снимок; автозаполнение параметров; алгоритм очистки (T12); всё из M2–M5; тарифы #2297.
