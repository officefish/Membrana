## Вердикт M1 (P) — кратко (полный: протокол)

- **Носитель:** сервер записей — поле политики переполнения в записи прибора, с разноской из кабинета тем же классом, что квоты; клиентский `bufferPolicy` — зеркало, не хозяин.
- **Место в кабинете:** страница мембраны — режим, параметры, галочка «применить ко всем» (привязка, с подтверждением); при снятой привязке — режим на прибор в списке узлов на той же витрине; отдельной страницы прибора не строим.
- **Умолчание fail-closed:** при первой привязке и при обновлении старого прибора — `stop`; backfill → stop; неизвестное значение отвергается; при дыре синка/порче — effective = stop на сервере и на клиенте; fallback на старую автоочистку запрещён.
- **Умная очистка:** выбираема только при полном наборе параметров (порог, критерий отбора, защита вещдоков); проверяет сервер (кабинет при записи, сервер записей при разноске); пустой/частичный набор — режим не записывается.
- **Не строить:** мастер-политику в плагине; дефолт автоочистки; чтение политики прибором через кабинет; галочку-снимок; автозаполнение параметров; алгоритм очистки (T12); всё из M2–M5; тарифы #2297.

## Вердикт M2 (C) — кратко (полный: протокол)

- **Транспорт:** отказ «буфер/хранилище полон» — доменный, по конвенции кабинета 12.08: HTTP 200 + `{ ok:false, reason, … }`; 413 остаётся только настоящему «тело слишком большое».
- **Словарь причин** (закрытый список): `device_buffer_full`, `user_storage_full`; место для прочих (T15) — тот же список, литералы здесь не назначаются. Запрещены: HTTP-код как причина, общий «квота» без субъекта, разбор английского текста.
- **Обязательные поля ответа:** занято/лимит по буферу и по хранилищу (те же оси, что `/quota`), `overflowPolicy` (stop / smart_cleanup — сервер знает из M1), `overflowId` — идентификатор эпизода переполнения, стабильный на все отказы одного эпизода (однократность окна).
- **Носитель словаря:** один shared-пакет монорепо — тип причины и тип тела; сервер чеканит, кабинет и прибор только импортируют; три копии строк запрещены.
- **Не строить:** остановку и память на приборе (M3), каналы после (M4), окно (M5), тексты прочих причин (T15), алгоритм очистки (T12), тарифы (#2297).

## Вердикт M3 (S) — кратко (полный: протокол)

- **Что гасится при `stop`:** складирование и отправка новых проб, активная запись, новый старт записи; сценарий не убивается — медиа-ветка уходит в постоянное удержание без авто-возобновления. **Живёт:** связь с сервером, детекция и наблюдение без записи, рантайм доски и плагина. Гасить телеметрию «вместо» отправки — запрещено (анти-паттерн ночи).
- **Источник вердикта:** оба — главный: ответ сервера по контракту M2 (`ok:false` + `reason` + `overflowId`); вторичный: своё чтение квоты до отправки как ранний страж. При расхождении главнее сервер; локальное удержание без id повышается до серверного `overflowId` без второго эпизода и окна.
- **Память «уже остановлен»:** один носитель на прибор — `DeviceOverflowHold`: факт удержания + `overflowId` + снимок причины/режима; один id → один сигнал окна (T9); новый запуск при удержании отбивается тем же фактом (T5); удержание переживает рестарт сценария; сброс — действием человека или очисткой.
- **Два входа:** общий носитель вердикта + два тонких адаптера (доска, микрофон), не две реализации (T6).
- **Не строить:** остановку канала/телеметрии как суррогат; убийство сценария целиком; дубль машины состояний в доске и микрофоне; авто-возобновление; ретраи отправки при удержании; всё из M2/M4/M5/T12/#2297.
