# Заседание «Полный буфер: контракт остановки» — M5 (W) Окно оператора и дороги из него

**Объединяющее задание (одно на всё заседание):** превратить тезисы шторма 06.09 в исполнимый
контракт остановки при полном буфере — сервер, прибор, оператор, — чтобы ночь 05→06.09 не
повторилась и вещдоки в буфере не пострадали.

**Порядок M0 (ратифицирован владельцем 06.09):** M1 (P) → M2 (C) → M3 (S) → M4 (L) → **M5 (W)
окно оператора** — последний узел, сходятся все рёбра: C→W, S→W, L→W (только статус).

## Данности (закрыто штормом, НЕ переоткрывать)

- Модальное окно оператору с двумя предложениями: почистить буфер в коллекции сэмплов либо поменять тариф на сервере (T3).
- В окне — свободное место по двум шкалам: по коллекциям пользователя и по буферу (T4).
- Окно закрываемо, но не обходимо: повторный запуск сценария при полном буфере снова останавливает и снова поднимает то же окно (T5).
- Буфер — архив вещдоков; чистит только оператор вручную или алгоритмы второго режима; вывоз в набор — путь, не стирающий вещдок (T7, норма 31.08).
- «Буфер полон» — честный слой интерфейса и без окна (T8); одно окно на факт переполнения (T9); после чистки экран показывает, что и сколько ушло (T11).
- Одно поведение в двух местах: доска устройства и модуль микрофона (T6).

## Вердикты предшественников (посылки)

- **M1:** политика на сервере; умолчание `stop`; умная очистка — только при полных параметрах.
- **M2:** ответ отказа несёт `reason`, `buffer`/`userStorage` (занято/лимит), `overflowPolicy`, `overflowId` — окно строится из него без второго запроса.
- **M3 (формула однократности — посылка, НЕ вопрос):** однократность считается по отказам — один `overflowId` → один сигнал окна; повтор — по новому запуску сценария при активном удержании (T5): окно поднимается снова тем же фактом. Это решено; M5 берёт как данность.
- **M3:**
  - Гасится при `stop`: новые пробы (отправка и складирование), активная запись, новый старт; сценарий — в постоянное удержание медиа без авто-возобновления. Живёт: связь, детекция без записи, рантайм.
  - Источник вердикта: главный — ответ сервера (M2: reason + overflowId); вторичный — своё чтение квоты; сервер главнее.
  - Память: `DeviceOverflowHold` на прибор — факт + `overflowId`; один id → одно окно; новый запуск отбивается тем же фактом; сброс — человек или очистка.
  - Два входа: общий носитель + два адаптера.
- **M4:** _дописывается после закрытия M4 (только статус «жив/остановлен»)_
