## Главное: каскад S-M3 не пройден (M2)

M2 записал: «в пределах переданного контекста умирает одна норма; других вердиктов, зависящих
от строки Lifecycle M4, в материалах не названо». Оговорка честная — **утверждение фактически
неверно**. Сверено по протоколам заседания `meeting-evening-auditor`:

| Вердикт того заседания | Что стоит на порядке «ревью → аудит» | Судьба |
|---|---|---|
| **M1 (B, КОРЕНЬ DAG)** | `audit(logs, dayPlan, truthCrystals) → derivedReport`, область определения **замкнута тремя входами** | `logs` — выход дневного код-ревью. После перестановки хроника идёт ДО ревью → один из трёх замыкающих входов не существует в момент прогона. **Корень умирает каскадом** |
| **M1′ (D1)** | отображение дословно: «**код-ревью ↔ `logs`**, probe ↔ `truthCrystals`, delta ↔ `dayPlan`» — документальное доказательство, что `logs` и есть дневное ревью | **умирает** |
| **M2′ (DA1)** | «владелец `logs` — ритуал-источник»; провенанс входа | **умирает частично** |
| M2 (H1) | механический признак ≠ вердикт | выживает |
| M3 (T1) | `consumed` вечер↔утро | выживает — совпадает с выводом M2 |

**И «выживающая» часть M4 отзыв не переживает.** M4 несёт правило «пустой вход = нет данных,
вердикт „неполный аудит“, не ложное зелёное». После перестановки вход `logs` пуст **каждый
вечер** — выживший тернарный вердикт по собственному правилу обязан давать «неполный аудит»
постоянно. Ортогональность, на которой стоит частичный отзыв, не держится.

**Отягчающее:** у M4 **нет секции посылок вообще**, а `MEETING_ACTIVE` того заседания
квалифицирует его «⚠ вердикт есть, посылки не названы» и запрещает переносить F1 в код до
назначения посылок. Отделимость проверяется по списку посылок — списка нет, значит «хирургически»
отозвать одну строку нельзя в принципе.

**Причина промаха:** комнате подали только M4. Ни повестка M2, ни `MEETING_BRIEF` не упоминают
M1/M1′/M2′ того заседания. Это дефект **председателя**, не комнаты.
