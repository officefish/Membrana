# M3 — всплытие из подсознания

**C3 —** Как единица подсознания поднимается в поле внимания персоны: устройство
облака кандидатов (похожие + дальние), роль MMR/диверсификации и serendipity-слотов,
мультизапрос (повестка + порождённые оттенки), качественные веса резонанса — и где
проходит граница между лифтом (retrieval-механикой) и актом всплытия (судящим звеном
персоны)? Что в v1 при живом носителе RAG, что — именованные слоты v2.
Как всплывшее помечается в протоколе (провенанс «из подсознания», кто и почему
поднял); имеет ли персона право отвергнуть поданное облако целиком.
**Список посылок обязателен.**

## Вводные (только для C3; архив C1 и ранг C2 ратифицированы; цикл C4, метрики C5, extractor C6 — не решать)

- Рамка C1 (ратифицирована): архив — полная адресуемая лента per-persona jsonl;
  summary всегда с fullRef; C3 резолвит id/provenance из архива.
- Рамка C2 (ратифицирована): классы position|insight|precedent|routine, lifecycle,
  importance pinned|normal — доступны отбору всплытия как признаки (условное ребро
  C2→C3 из M0: «если отбор всплытия использует приоритет» — комнате решить, использует ли).
- Слово владельца (дословно, 27.07): «Из подсознания что-то всплывает когда это
  касается темы консилиума»; его же паттерн из редизайна снов: тема = синтез двух
  СЛУЧАЙНЫХ тезисов + «два аутсайдера в стол».
- Опасение владельца (27.07, дословно): «а подсознание точно сможет доставать облако
  похожих воспоминаний, не будет ли оно слишком заскриптованным?» — ответ сессии,
  одобренный владельцем: похожесть ≠ ассоциация; одинаковый запрос → одинаковый
  топ-K без сюрприза; лечение — мультизапрос (противоположность темы, «кто спорил»,
  аналогия соседнего домена) + serendipity-бюджет 1–2 записи из хвоста + веса
  резонанса (конфликт/опровержение/слово капитана всплывают охотнее ровных).
- Research (9 источников, #1366): наивный топ-K даёт ~45% ложных привязок — MMR/
  submodular снимает; лидеры бенчмарков — multi-strategy retrieval с fusion+rerank;
  «акт всплытия за персоной» рифмуется с LLM-reranker поверх кандидатов.
- Принцип сессии (одобрен владельцем): «скрипт — это лифт, а не память» — retrieval
  подаёт широкое облако кандидатов, судящее звено персоны выбирает, что действительно
  всплыло, и обязано назвать почему; в протоколе — «Дынин вспомнил X, потому что Y»,
  не «системе подсунуло пять записей».
- Живой носитель: RAG-контур `retrieveRagContext` (подмешивает контекст в ask,
  persona-RAG для Веснина/Ожегова уже существует) — направить на архивы; эмбеддинги
  ищут близость по смыслу. Судящее звено — вызов персоны по панельной цепочке.
- Кейс memory-outweighs-topic (27.07): полный груз памяти топит узкую повестку —
  селективная подача обязана остаться селективной (облако ограничено, не «всё
  релевантное»).
- Ограничение: расписание всплытия (когда зовётся — утро/консилиум/жест) — C4;
  метрики качества всплытия (recall, «утонуло и не всплыло») — C5; провод в
  extractor/ask — C6; численные веса и обучение ранкера — v2 (калибровка C5).
