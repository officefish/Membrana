## §1 · Дом, неймспейс, предикат `belongs`

**Источник:** комната M1, протокол [`workshop-wires-m1-home-namespace-2026-07-30`](../../seanses/workshop-wires-m1-home-namespace-2026-07-30.md).

**Дом** — каталог с `workshop.manifest.json` (поля `pattern`, `name`, `worksOn`, `kit`,
`verbs`). Контракт `HOME_WORKSHOP` этой комнатой не менялся.

**Неймспейс** — запись в реестре `docs/namespaces/REGISTRY.json`. Не поле home-манифеста,
не кит, не строка индекса справочника.

Поля записи неймспейса:

| поле | обязательность | содержание |
|---|---|---|
| `id` | да | `[a-z][a-z0-9-]*` |
| `title` | да | человекочитаемое имя |
| `holder` | **да** | `persona` XOR `ownerRef`; пустой держатель — запись невалидна |
| `membership` | да | `{ kind: pathPrefix \| namePrefix \| pathGlob \| explicitList, value }` |
| `containerKind` | нет | `plain \| bidi` — пометка двумерного контейнера |
| `verbs`, `worksOn`, `kit`, `roots` | **запрещены** | это признаки дома, не неймспейса |

**Различение машинное:** `isHome(x) ⇔ workshop.manifest с паттерном дома`;
`isNamespace(x) ⇔ запись реестра`. Дом обязан глаголами; неймспейс их не умеет и не обязан.
Отличие — по типу носителя, не по интонации README.

**Держатель неймспейса** отвечает за смысл правила и стабильность `id`, **не** за глаголы.

**Предикат принадлежности:**

```text
belongs(s) → { kind: 'home', id } | { kind: 'namespace', id } | { kind: 'orphan' }
```

Порядок разрешения: сначала дом (по корню манифеста, префикс каталога), иначе неймспейс с
совпавшим `membership`, иначе `orphan`. Конфликт неймспейсов — длиннейший `pathPrefix`,
иначе минимальный `id`; конфликт `explicitList` — отказ проверки реестра.

**`orphan` — честный третий исход.** Текущие 476 носителей — orphan, пока нет правила или дома.

**Запреты §1:** неймспейс без держателя · имена `misc`/`other`/`tmp`/«всё сиротское» ·
второй источник истины членства · перечень кластеров вместо правила образования.

## §2 · Тест как спутник предмета

**Источник:** комната M8, протокол [`workshop-wires-m8-tests-parking-2026-07-30`](../../seanses/workshop-wires-m8-tests-parking-2026-07-30.md).

Файл `*.test.mjs` **не имеет собственной принадлежности** — он наследует принадлежность
своего предмета.

```text
subjectOf(t): stem = basename(t) без '.test.mjs'
  локусы по порядку (список ЗАКРЫТ):
    1) dirname(t)/stem.mjs
    2) scripts/lib/stem.mjs
  первый существующий файл = предмет
```

**Встройка в предикат §1 — ветвь, не второй механизм:**

```text
isTest(t) ∧ subjectOf(t) ≠ ∅  ⇒  belongs(t) := belongs(subjectOf(t))
isTest(t) ∧ subjectOf(t) = ∅  ⇒  orphan, reason: 'subject_unresolved'
```

**Знаменатель инварианта** — инструменты ∪ тесты: **887** носителей на замер 30.07.
Исключение тестов из счёта «потому что забыли» запрещено.

**Явная парковка манифестами** остаётся **606**: спутники не перечисляются. Ручной работы
по тестам — ноль; 33 случая «инструмент припаркован, тест нет» закрываются правилом сами.

**Запреты §2:** отдельный дом `docs/tests` · неймспейс `membership = *.test.mjs` ·
второй предикат рядом с `belongs` · чтение тела теста или import-графа для определения
предмета · **молчаливое** расширение списка локусов (только отдельным вердиктом).

**Незакрытое:** 37 файлов с неразрешённым предметом — находки об именах, разбираются
поштучно, классом не признаны.

## §3 · Обнаружение справочником

**Источник:** комната M2, протокол [`workshop-wires-m2-atlas-discovery-2026-07-30`](../../seanses/workshop-wires-m2-atlas-discovery-2026-07-30.md).

**Дом и мастерская разделены.** Манифест перестаёт быть паспортом дома:

```text
D_home(c)      ⇔ ∃ README.md в c  ∧  path(c) ⊨ RootPolicy
D_workshop(c)  ⇔ D_home(c) ∧ ∃ workshop.manifest.json
```

`RootPolicy` — явный набор path-паттернов в библиотеке атласа; минимум обязан покрывать
прямые `docs/*` с README и де-факто дома вроде `docs/procedures/*`, `docs/seanses/night-hunt`
— так, чтобы **`docs/network` попал в `D_home`**. Тридцать три невидимки становятся видны
как `home` **без заведения 33 манифестов**.

**«Контейнер без мастерской» — законное состояние,** третий вид записи индекса: `home` без
`workshop`. Не дефект. Мастерская — подтип дома, не обязанность каждого дома.

**Источники справочника названы честно:**

| источник | что даёт |
|---|---|
| `RootPolicy` + `README.md` | обнаружение дома |
| `workshop.manifest.json` | поля мастерской |
| `docs/namespaces/REGISTRY.json` | проекция неймспейсов |
| `README.md` (повторно) | выжимка заголовка и абзаца — **не** обнаружение |

Прежняя шапка `ATLAS.md` называла README источником *обнаружения* — **нечестна**; код был
*неполон* относительно собственного канона «агрегирует каждый контейнер». Чинятся оба.

**Место неймспейса — не противоречие §1, а разделение ролей:** `REGISTRY.json` остаётся
**единственным источником истины**; атлас — **потребитель-агрегатор**, вход `derive` и
проекция в индекс отдельной секцией. Ручная «строка ATLAS» истиной не является.

**Исполнение T9 (тезис владельца):** дом и неймспейс находимы **инструментами справочника** —
глаголы `list` / `find` / `show` над проекцией реестра и деревом домов. Тезис исполняется;
`ATLAS` вторым носителем членства не становится.

**Дрейф:** `--check` расширяется до трёх разниц — `Δ(обнаружение домов, индекс)`,
`Δ(манифесты, workshop-записи)`, `Δ(REGISTRY, проекция ns)`. Нынешняя проверка «только
против манифестов» после M2 признана недостаточной. Fail-closed на расхождении; дом без
мастерской — **не** повод падать.

**Запреты §3:** заводить 33 манифеста «для зелени» · второй паспорт дома (`homes.json`) ·
ручная запись в индекс как источник истины · молчаливое расширение `RootPolicy`.

## §4 · Прибор мастерской скриптов — **условно, две сверки не пройдены**

**Источник:** комната M3, протокол [`workshop-wires-m3-scripts-instrument-2026-07-30`](../../seanses/workshop-wires-m3-scripts-instrument-2026-07-30.md).

> **СТАТУС: ЗАЯВКА, НЕ ОКОНЧАТЕЛЬНЫЙ РАЗДЕЛ.** Независимый аудит (Фаррелл, отдельный агент)
> нашёл два расхождения, проверенные председателем по коду и канону. До их снятия §4
> действует как заявка, а не как принятая часть контракта.
>
> **Расхождение 1 — §4 правит §3, объявленный своей же повесткой непересматриваемым.**
> Повестка M3 в разделе «Входы, которые не пересматриваются» несла `D_home ⇔ README ∧ RootPolicy`
> из §3. Вердикт расширил саму `RootPolicy` (добавил allowlist контейнеров в корне). По
> регламенту обнаружение справочником — предмет комнаты 2, она закрыта. То, что M2 написала
> «минимум обязан покрывать», не мандат соседней комнате дописывать класс правил.
> **Требуется:** либо расширение проводится через M2 (переоткрытие или поправка задания),
> либо §4 остаётся заявкой на пересмотр §3 — но не тихим соседством. Иначе через две комнаты
> §3 читается «про `docs/*`», а живое правило лежит в §4.
>
> **Расхождение 2 — предложенный манифест несовместим с ратифицированным паттерном.**
> `docs/patterns/HOME_WORKSHOP.md` (Ф1, ратифицирован владельцем 22.07) фиксирует поля:
> `pattern` · `name` · `worksOn` (ровно 1) · `verbs` (**словарь**) · `kit`. Проверено
> председателем: **ни один** из 12 живых манифестов не несёт поля `holder` — его в каноне
> нет. Вердикт M3 предлагает `version` · `home` · `holder` · `worksOn` · `verbs` (**массив**) ·
> `setsSource`: из канона уцелел один `worksOn`; `pattern` и `name` пропали; `kit`
> (сингулярная связь «мастерская заказывает кит») подменён `setsSource.kitsGlob` — другая
> семантика; каноническая тройка инвентаря `audit`/`decompose`/`inspectElement` не названа
> ни реализованной, ни вынесенной. Канон в посылках комнаты не упомянут ни разу.
> **Требуется:** привести поля в соответствие Ф1–Ф2 либо оформить расхождение отдельным
> вердиктом с ценой.
>
> Содержательная часть ниже (глаголы, исходы, различение трёх молчаний) расхождениями **не
> затронута** и сохраняется.
>
> **СВЕРКА 31.07 — [`RECONCILE_M3.md`](RECONCILE_M3.md).** Расхождение 2 **снято**: поля
> приведены к Ф1 целиком (`version`, `home`, `holder`, `setsSource` убраны, `worksOn` стал
> одиночным, `verbs` — словарём), носитель положен —
> [`scripts/workshop.manifest.json`](../../../scripts/workshop.manifest.json). Каноническая
> тройка инвентаря закрыта вся: `audit` = `scripts:orphans`, `decompose` = `scripts:registry`,
> `inspectElement` = `scripts:sets-of`; пометок ⚠ нет ни на одном.
>
> Расхождение 1 **подтверждено и подорожало**. Замер: обнаружение мастерских — не набор
> паттернов в данных, а захардкоженный корень обхода `validate-workshop.mjs:220`
> (`join(repoRoot, 'docs')`), питающий `validate:workshop` и справочник; все 12 живых
> манифестов лежат под `docs/`. Манифест в `scripts/` сегодня **не читает никто**, поэтому §4
> опирается на предпосылку, которой в проде нет. Правка корня — предмет §3 (комната M2), и
> сверка его сознательно не трогает. Развилка вынесена владельцу: поправка к §3 (двухклассовая
> `RootPolicy` + правка двух потребителей) либо §4 остаётся заявкой до переоткрытия M2.
>
> **До слова владельца §4 остаётся заявкой, а зуб §5 — заблокированным.**

**`scripts/` становится домом и мастерской.** `RootPolicy` из §3 расширяется:

```text
RootPolicy = docs-subtree homes  ∨  allowlist контейнеров в корне репозитория
```

В allowlist входит `scripts`. Переноса `scripts/` под `docs/` не происходит; «любая папка с
README» домом не становится.

**Носитель:** `scripts/workshop.manifest.json` — `version`, `home: "scripts"`,
`holder: "dynin"`, `worksOn: ["scripts/**"]` (инструменты ∪ тесты по §2),
`verbs: ["orphans", "sets-of"]`, `setsSource.kitsGlob: "kits/*/MANIFEST.json"`.
Новый кит `scripts-master` **не** заводится: наборы — существующие киты.

**Глагол первый — `orphans`** (`yarn scripts:orphans`):

| | |
|---|---|
| вход | `{ includeTests?: boolean = true }`; область — `worksOn` ∩ знаменатель §2 |
| «бесхозный» | **только** `belongs(s) = orphan`. Не «вне китов», не «вне pins» |
| выход | `{ status: "clean" \| "has_orphans", orphans: Path[], counted, denominator }` |
| пустота | бесхозных нет → `status: "clean"`, `orphans: []`, `denominator > 0`. **Молчаливый пустой ответ без статуса запрещён** |

**Глагол второй — `sets-of`** (`yarn scripts:sets-of <path>`):

| | |
|---|---|
| вход | `{ path }`, относительный к корню |
| что считается набором | **только кит**: `SetRef = { kind: "kit", id }`. Не неймспейс, не дом |
| членство | `path ∈ roots ∨ pins` манифеста кита; дубликат внутри одного кита → один `SetRef` |
| выход | `{ path, sets: SetRef[], outcome }` |
| исходы | `found` · `found_multi` (>1, не ошибка, сортировка по `id`) · `not_in_any_set` · `unknown_path` |

**Три молчания различаются:** `set_empty` (кит объявлен, членов нет) · `not_declared`
(кита с таким `id` нет) · `not_in_any_set` (файл проверен, ни в одном наборе). Схлопывать в
пустой список запрещено.

**Держатель:** `dynin`; поддержка по форме связанности — `ozhegov`.

**Отношение к существующему:** `orphans` и `sets-of` — **соседние глаголы** того же контура,
не замена `tooling:overview` / `scripts:registry`.

## §5 · Инвариант принадлежности и место зуба

**Источник:** комната M4, протокол [`workshop-wires-m4-invariant-tooth-2026-07-30`](../../seanses/workshop-wires-m4-invariant-tooth-2026-07-30.md).

**Инвариант двухфазный.** Основной предикат — не доля и не порог:

```text
фаза 1, рабочая:  I_growth ⇔ O(t) \ B \ W = ∅     — прирост бесхозного отсутствует
фаза 2:           I_abs    ⇔ O(t) \ W = ∅         — бесхозных нет вовсе
```

`O(t)` — текущее множество `orphan`; `B` — baseline, замороженный в момент включения;
`W` — действующие освобождения. **`I_abs` включается только явным решением владельца** или
явным событием «наследство закрыто» — не по календарю и не автоматически.

**Два места проверки, одна лемма:**

| место | область | поведение |
|---|---|---|
| pre-push | **затронутое пушем** | строгий: падает, если `(O \ B \ W) ∩ A ≠ ∅` в режиме прироста |
| CI и/или ритуал дня | полный знаменатель | отчёт: список прироста и счётчик наследства; **не** подменяет pre-push |

**Включение:** прирост-инвариант, вшивание в pre-push и заморозка baseline — **сразу** после
реализации, не «когда парковка кончится».

**При красном — блок push.** Законные ходы: припарковать (в дом или неймспейс) · убрать путь
из диффа · выдать действующее освобождение · снизить наследство парковкой (наследство само по
себе не блокирует).

**Освобождение — `orphan-waiver`** `{ path, issuer, ref?, note? }`, привязано к пути, оставляет
след в выводе зуба. `SKIP_PREPUSH=1` — рубильник всего хука, **освобождением инварианта не
является**. Тихий проход запрещён.

**Наследство против прироста разведены:** `B` замораживается при включении; прирост —
`O(t) \ B`, наследство — `O(t) ∩ B`. Перезаморозка baseline — **явный акт со следом**, не
побочный эффект пуша.

> **Два условия перед реализацией — от независимого аудита, приняты председателем.**
>
> **Условие 1 — зуб не включается раньше §4.** Предикат блокирует push на **любом** новом
> файле с `belongs = orphan`. Названный законный выход «припарковать в дом» для `scripts/`
> сегодня **недоступен**: `scripts/workshop.manifest.json` не существует, §4 остаётся заявкой.
> Если включить зуб раньше, у автора рутинного нового скрипта останется один практический
> ход — освобождение, и исключение станет нормой. **Включение прироста-инварианта привязано
> к ратификации §4**, а не к «сразу после реализации», как записано в вердикте.
>
> **Условие 2 — у освобождения обязан быть срок.** В финальную форму
> `{ path, issuer, ref?, note? }` поле `expiry` **не попало**, хотя предлагалось в диалоге.
> Без срока освобождение превращается в вечный третий бакет: не дом, не неймспейс и не
> честный `orphan`, а «orphan, которому разрешили быть им навсегда» — практический второй
> источник истины о членстве. **Форма waiver дополняется обязательным `expiry`** либо
> расхождение оформляется отдельным решением с ценой.

## §6 · Хук старта сессии

**Источник:** комната M6, протокол [`workshop-wires-m6-session-hook-2026-07-30`](../../seanses/workshop-wires-m6-session-hook-2026-07-30.md).

**Состав выдачи (холодная сессия):** штампы свежести и полоса статуса · список мастерских
(`id`, краткое описание из манифеста, входной глагол или честный прочерк) · минимальный набор
callable реестра (не более двенадцати) плюс строка политики «греп — последний» · одна ссылка
на документацию · отчёт первого уровня и метка свежести второго.
**Тёплая сессия:** только штампы и отчёт, без повторной печати каталога.
**Не входит:** список бесхозных, знаменатель, киты, сброс README, атлас как источник истины.
**Сжатая форма** при более чем пятнадцати мастерских или сорока строках.

**Источник выдачи — только проекция:** манифесты ∪ реестр ∪ штампы git. **Ручная запись в
текст выдачи запрещена**; руками правится манифест или реестр.

**Триггер:** каждый старт сессии даёт штампы и первый уровень; полная выдача — только
холодной сессии. Холодная определяется отсутствием валидного маркера в пределах жизни
контекста; носитель маркера — кэш хука, не git.

**Валидация в тот же момент (уровень 1):** разбор манифестов · читаемость реестра · полнота
проекции · опционально дрейф штампов. Исход всегда `ok` либо `degraded` с причинами;
**сессию не блокирует**, автопочинки нет.

**Два уровня:** первый — в хуке каждой сессии, плюс сигнал «второй просрочен» при разрыве
больше недели. Второй — уже зарегистрированная недельная процедура «мёртвые провода» (#1447):
полный инвентарь, дрейф, бесхозные, зубы вне цепочек. Хук второй уровень **не запускает**.

**При недоступности — не утверждать ненаблюдённое:** нет сети — не заявлять состояние
origin; нет зависимостей — навыки помечаются недоступными, без подмены на «просто грепни»;
пустое дерево — честная пустота с полосой `DEGRADED` первой строкой.

**Цена:** сеть не более 15 секунд; первый уровень — чтение манифестов и реестра;
предупреждение при выдаче свыше сорока строк; обход знаменателя на старте — дефект.

> **Оговорка аудита.** Порог «сорок строк» назначен без арифметики против собственных чисел
> комнаты: по грубому счёту сегодняшний полный состав даёт 30–38 строк, то есть сжатая форма
> рискует включиться уже на следующей мастерской. Проверить при реализации.
>
> **Передано комнате 9, а не решено здесь.** Архитектура вердикта (один генератор, единая
> проекция, единая схема на все мастерские разом) **де-факто предрешает** вопрос «оптовое
> против поштучного», формально вынесенный за скоуп. Комната 9 приходит к готовому прецеденту
> и вправе его назвать предрешением.

## §7 · Оптовое и поштучное

**Источник:** комната M9, протокол [`workshop-wires-m9-wholesale-retail-2026-07-30`](../../seanses/workshop-wires-m9-wholesale-retail-2026-07-30.md).

**Сосуществование слоями. Ни один подход не отменяет другой** — сказано прямо, как требовала
повестка.

| слой | что делает | объект правки |
|---|---|---|
| **A — оптовый** | пол §6: единая проекция, всем холодным сессиям одинаково | схема пола, генератор, проекция мастерских, входные глаголы, порог сжатия |
| **B — поштучный** | метод #1467: один инструмент — один разбор — один провод | разбор прецедента на инструмент, парковка, привязка вызова, стык |

**Граница:** A правит артефакты пола, B — артефакты провода конкретного инструмента.
Запрещено: проводить инструменты пачкой «как навигацию» · считать инструмент проведённым
потому, что он есть строкой в полу · править шаблон хука тикетом на один инструмент.

**Пол ≠ провод.** После появления пола поштучным остаётся всё, чего не покрывает
обнаружение: разбор холодного прецедента, парковка, привязка вызова, проверка, что сессия
**зовёт** инструмент, а не грепает.

**Метод прецедентов жив и обязателен для слоя B.** «Нет прецедента — нет заявки» теперь
означает: нет заявки на **провод**. На появление строки в полу прецедент не нужен — пол
рождается проекцией. Прецедент по-прежнему показывает, **куда** проводить.

**Признак выбора:** `mode(u) = A`, если правка попадает в артефакты пола; `= B`, если в
артефакты провода конкретного инструмента; иначе работа делится.

**Цена оптового названа:** **ложное покрытие** — «есть в полу» читают как «проведено» ·
шум при разрастании выдачи · вещдоки холодных сессий остаются возможны, пока слой B пуст:
пол не лечит нулевую частоту вызовов.

> **Оговорка аудита.** Перечень артефактов пола **не закрыт**, и признак выбора не покрывает
> центральный случай этого заседания: куда отнести акт «завести манифест новой мастерской» —
> он меняет и состав пола, и принадлежность контейнера. Граница там не проведена; решать при
> реализации или отдельным вердиктом.

## §8 · Норма в фундаментальных документах

**Источник:** комната M7, протокол [`workshop-wires-m7-norm-in-docs-2026-07-30`](../../seanses/workshop-wires-m7-norm-in-docs-2026-07-30.md).

**Носитель:** источник истины — `AGENTS.md`, §Agent tooling, как **норма-порядок**.
Зеркала-указатели (не вторая редакция) — по одной строке-отсылке в `.cursorrules` и
`.claude/CLAUDE.md`; скиллы и промпты ссылаются, не копируют. Пол сессии несёт строку политики
**только проекцией** (§6), ручная правка выдачи запрещена.

**Почему не в таблице граблей:** грабли про укусы, а не про устав порядка. Пол — не источник
истины: «есть в полу» ≠ проведено (§7).

**Дословная норма:**

1. Нужен инструмент, команда или обзор инструментария — сначала `yarn tooling:overview`
   и/или узкий глагол мастерской по задаче (`neighbors`, `orphans`, `sets-of`, …).
2. Узкий прибор мастерской вызывается **до** разведочного поиска по дереву.
3. Поиск по репозиторию **для обнаружения инструмента** — последним, если мастерская не
   дала ответа.
4. Поиск по коду текущей задачи при уже известном инструменте **не запрещён**. Абсолютного
   запрета на греп нет.

**Подпорка — не зуб.** Невызов машине в момент нарушения не виден (§5 назвал цену раннего
зуба). Механизм: **разбор транскриптов постфактум**, исход — находка, не блок. Предикаты по
умолчанию: сессия с потребностью в инструменте · «первым действием был разведочный поиск» ·
за 28 дней доля таких сессий не выше 0.2 и доля сессий хотя бы с одним вызовом мастерской не
ниже 0.5. Меньше пяти сессий в окне — честное «выборки недостаточно», а не зелёный.

**Признак жизни измерим:** через 28 дней двойной порог выше **или** честное «недостаточно
выборки». Плакат «строка есть в `AGENTS.md`» признаком жизни **не является**.

**Отношение к §6:** подтверждено и уточнено. Запрет снимка инвентаря в `AGENTS.md` остаётся;
в том же разделе живёт **политика порядка** — это не снимок. Выдача хука не переписывается.

> **Оговорки аудита.** (1) Пункт 6 списка посылок несёт собственный вывод комнаты
> («опора нормы ≠ гейт»), пристёгнутый к факту §5 — прошёл потому, что машинной фильтрации в
> этот раз не было. (2) **Цена подпорки занижена:** существующие `session-mining.mjs` и
> `transcript.mjs` читают **только текст реплик**, а предикат требует упорядоченного списка
> **вызовов инструментов**. Парсера событий `tool_use` в репозитории нет ни в зачаточном
> виде — это отдельная работа, а не «регулярный прогон существующего».

## §9 · Кит как вид фрейма процедуры

**Источник:** комната M5, протокол [`workshop-wires-m5-kit-frame-2026-07-30`](../../seanses/workshop-wires-m5-kit-frame-2026-07-30.md).

**Вид появляется: `кит` — четвёртый служебный фрейм** рядом с проводами, времянками и
доставкой.

**Что объявляет:** что процедура на прогоне отдаёт сессии набор инструментов **по ссылке**.
Поля элемента (статус рекомендации): `id`, `holder`, тег `кит`, **`kitId`** — идентификатор
манифеста кита. Содержимое `roots` и `pins` во фрейме **не дублируется**.

**Недоступный кит** — объявление некорректно: на будущем зубе отказ манифеста **процедуры**;
пока статус рекомендательный — дефект автора. Здоровый аудит другого кита битую ссылку не
оправдывает.

**Отношение к тегу `провода` — сосед, не расширение и не синоним.** Поштучный слой B (§7)
остаётся у проводов и прибора; фрейм кита отдаёт набор целиком.

**Держатель фрейма** отвечает за **уместность объявления и живость ссылки** у процедуры.
Это **не** `leadPersona` кита — тот отвечает за содержимое набора. Разные леммы.

**Проверяемость сегодня — никакой машинной проверки на тег `кит` нет.** `kits:audit`
проверяет кит, а не фрейм. Путь зуба (после ратификации, **не этим вердиктом**): проверка
существования `kits/<kitId>/MANIFEST.json` в валидаторе процедуры.

**Цена и путь ратификации:** строка таблицы, абзац лемм и пример в паттерне. Держатель
правки — `ozhegov`, эпик #900. Превращение в обязательное требование и схемный зуб — **только**
через `frames-alive` S0 или отдельный стол, **не контрабандой валидатора**.
