# Повестка M2 — заседание one-shot-manifest

**N1 — Какова форма назначения исполнителя тимлидом: каким актом записывается назначение и
чем проверяется след профильного контекста до `execute`?**

Комната обязана вынести: где и в какой форме живёт акт «тимлид назначил исполнителя»
(запись, её носитель, обязательные поля) и какой вещдок доказывает, что назначенный прогнал
свой профильный контекст **до** исполнения — так, чтобы проверка была предикатом, а не
дисциплиной.

Границы, нарушать нельзя:

- вердикт M1 — посылка: три фрейма (`first-frame` Веснин · `owner-ratify` владелец ·
  `execute` назначается тимлидом), прогоны в общей ленте `docs/procedure-runs/` тремя
  точками записи, схема записи прогона с `frames[]`;
- Т1: исполнитель — профильный контекст, не лицо; Т3: исполнитель один на весь шот;
  Т4: назначает тимлид. Тезисы не пересматриваются;
- чужие комнаты: предикат объёма — M3; основание однородности — M4; состав фреймов —
  закрыт M1, не переоткрывать;
- вес формата: шоту не переносится лента следов спринта из четырёх родов — у шота один
  след контекста (конспект шторма); решение не должно стать второй нарезкой.

Посылки комнаты (даны, не обсуждаются): вердикт M1 (закрыт 03.08); Т1–Т8 шторма 03.08;
образец спринта — акты нарезки `cut_context_run` в ленте `docs/sprint/cut/trail/` и
вердикт `honest_pair` гейта исполнения (и его известная слабость #1641: выдаётся при
одном следе); прецедент 30.07 — `cutBy` проставлялся именем без прогона контекста, поймал
владелец, не механизм.

Требование к вердикту: назвать полный список посылок в том же прогоне; лишняя посылка —
тоже нарушение.
