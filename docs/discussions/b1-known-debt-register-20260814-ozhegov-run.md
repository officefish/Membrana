**Ответ по делу.**

**(1) Имя.** `известный долг` / слаг `known-debt`. Обоснование по словарю:
- `признанный` — оценочный глагол, читается как «мы простили» → амнистия.
- `известный` — фактический: «знаем о нём, он в регистре, а не в тени». Это и есть леса: временная опора, видимая всем.
- `recognized-debt` в англояз. коде тянет юридическую коннотацию (acknowledged liability); `known-debt` нейтрален и совпадает с русским.
- В коде: `known-debt.json`, модуль `knownDebt`, поле отчёта `knownDebt`, ошибка «…не входит в регистр известного долга».

**(2) Дом.** `scripts/lib/known-debt.json` рядом с валидатором.
- против `docs/adr/`: ADR — это решение, а не живой список; регистр меняется по мере закрытия #1787.
- против `docs/procedures/`: там процедуры-нормы, а не данные с TTL.
- за `scripts/lib/`: единственный потребитель — валидатор; граница пакета = граница словаря; при снятии долга правится там же, где читается. В ADR-0025 остаётся ссылка на файл, не наоборот.

**(3) Форма записи.** Твой набор почти полный. Правки:
- `kind: 'frame' | 'home'` — оставить.
- `procedure` — оставить (без него не понять область).
- `frameId` — оставить для `frame`; для `home` — `null` или отсутствует (или добавить `homeId`, если у дома есть идентификатор кроме `procedure`).
- `currentHolder` — оставить (это и есть отклонение от нормы).
- `bornAt` — переименовать в `recordedAt`: фиксируем момент внесения в регистр, а не «рождение» нарушения (его точной даты мы не знаем).
- `clearedBy: "#1787"` — оставить как ссылку на задачу-ликвидатор.
- **добавить** `expectedHolder` — какой holder ждёт норма (developer-slug). Без этого ошибка валидатора не сможет подсказать «кому передать».
- **не добавлять** свободный текст «почему признан»: `clearedBy` + ADR-0025 в шапке файла — достаточно. Свободный текст размывает словарь.

**(4) Текст ошибки валидатора:**

> Holder `<currentHolder>` в кадре `<frameId>` процедуры `<procedure>` не входит в регистр известного долга (`scripts/lib/known-debt.json`) и не является разработчиком. Передайте кадр разработчику из списка нормы либо, если это признанное отклонение, внесите запись в регистр со ссылкой на задачу-ликвидатор.

**(5) Строка отчёта аудита:**

> Известный долг: 21 запись в регистре (20 кадров, 1 дом-мост), ликвидатор #1787. Ствол зелёный.

При изменении числа — те же поля, счётчик пересчитывается из файла, литерала «21» в коде нет.

**Риски связанности:** регистр читают только валидатор и генератор отчёта — через один модуль `knownDebt` с `index.ts`. Прямой импорт JSON из других мест — нарушение нормы.
