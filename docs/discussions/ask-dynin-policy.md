По существу, тремя пунктами.

1. **Ретенция.** Сигнатура почти верная, но неполная. `now` параметром — да, обязательно (иначе зуб недетерминирован, ловушка часового пояса тут же). Не хватает трёх вещей: (а) `artifacts` должны быть уже распарсенными записями `{name, createdAt, sizeBytes, sha256?}` — парсинг имени — отдельная чистая функция `parseArtifactName(name)`, не смешивать; (б) `policy` должна нести не число «сколько хранить», а **уровни ретенции** как данные: `{tiers: [{maxAgeHours, minCount}, ...], hardCap}`; (в) `reasons` — это map `name → reasonCode` из закрытого перечисления (`kept:within-daily-window`, `dropped:superseded-by-newer`, `dropped:corrupt-manifest`, `kept:hard-floor`), иначе зубы будут ловить строки. По сути вопроса: при RPO=сутки достаточно **держать N=7 суточных + 1 «пол»** (последний валидный, что бы ни случилось) — недельные/месячные уровни здесь **преждевременная сложность**, вводить, когда появится второй потребитель (offsite). Инвариант: `keep ∪ drop = artifacts`, `keep ∩ drop = ∅`, `∃ a ∈ keep: a.valid` (пока есть хоть один валидный — не выкидываем последний).

2. **Манифест как предикат.** Пяти полей мало — это опись. Чтобы завтрашний healthcheck мог сказать «пригоден/непригоден» **без** восстановления (#1809 — соседняя карточка, не лезу), манифест обязан нести:
   - `sha256` — не файла целиком, а **тела дампа** отдельно от манифеста (иначе циклическая зависимость при верификации);
   - `mongodumpExitCode: 0` и `mongodumpStderrTail` (последние N строк) — без этого «файл есть» ≠ «дамп прошёл»;
   - `dbInventory: [{db, collection, documentCount}]` — минимальная опись содержимого; без неё пустой дамп валидной базы неотличим от полного;
   - `startedAt` **и** `finishedAt` (не один `createdAt`) — длительность сама по себе healthcheck-сигнал (внезапно быстрый дамп = подозрение);
   - `schemaVersion` манифеста — иначе первый же рефактор поля сломает ретенцию задним числом.
   Предикат `isFitForRetention(manifest) ⇔ exitCode=0 ∧ sha256 непуст ∧ sizeBytes ≥ floor ∧ dbInventory непуст ∧ schemaVersion ∈ known`.

3. **Схема имён.** Минимум: `mongo-dump--YYYYMMDDTHHMMSSZ--<mongoVersion>--<shortSha>.archive` (или `.gz`). Обязательно **UTC с суффиксом Z** — иначе сортировка строк соврёт при переходе TZ на сервере. Обязательно **лексикографически сортируемый timestamp** (ISO basic без разделителей — `20260808T161631Z`), тогда `sort()` по имени = сортировка по времени, ретенция строится без чтения манифестов. Ловушки:
   - **коллизия в одну секунду** — добавь `--<counter>` или 3 знака миллисекунд (`20260808T161631042Z`); без этого два прогона перезапишут друг друга;
   - **TZ дрейф** — категорически не локальное время, только UTC; фиксируй в тесте;
   - **shortSha в имени** должен совпадать с `sha256` в манифесте (первые 8) — это делает имя проверяемым против манифеста без внешнего индекса.

**Одна вещь, которая выглядит правильной и развалится:** «`sha256` файла-артефакта в манифесте». Если хешируется файл, внутри которого лежит сам манифест (или манифест лежит рядом и назван по хешу тела) — получишь либо циклическую зависимость, либо молчаливое рассогласование при пересжатии. Хешируй **тело дампа до упаковки/после — но зафиксируй что именно** (`sha256Of: "mongodump-archive-body" | "gzip-stream"`), и пусть это будет отдельное поле, а не «просто sha256». Ловится до кода — одним зубом `manifest.sha256Of ∈ known`.
