**Ответ:**

Конструкция.

Журнал — append-only с leafHash по телу; значит любое «изменение состояния прогона» — это **новая запись, ссылающаяся на прежнюю по (runId, index)**. Open/close/поправка корня — не мутации, а события над идентичностью прогона. Идентичность = `runId`; последовательность внутри прогона = его собственный `index`. Ленивое закрытие — тоже событие в ленте, оформленное как close с явной маркировкой сиротства.

По пунктам:

1) **runPhase ∈ {open, close}** в корне — правильная ось. Статус open — не `pass`: pass означает «шаг отработал», а «прогон стартовал» — другое семантическое поле. Введи для open фиксированный `status: "started"` (или переиспользуй `blocked`-подобный нейтральный — нет, честнее новый) с evidence = манифест/план. Правило инварианта: **прогон закрыт ⟺ ∃ close с тем же runId**. Никаких «pass с манифестом» — это подмена семантики ради экономии значения.

2) **Close-сирота** — новая запись с `runId` осиротевшего прогона, её собственный `index = N+1` его ленты (счёт продолжается, не обнуляется), `runPhase: "close"`, `status: "fail"`, `gap: "orphaned"`, ссылка — **`orphanedBy: {runId, index}`** на вытеснившую open. `supersededBy` — не тот словарь: здесь не замена, а факт вытеснения. Автор close-сироты — новый прогон (он это обнаружил); подпись leafHash — его.

3) **Дозапись корня** — отдельная запись `runPhase: "friction-amend"` (не третье значение основной оси прогона, а амандмент — читается как «поправка к трению»). Поля: `amends: {runId, index, frictionIndex}`, `root?/fix?/prevention?`, `amendedAt`. Читатель видит обе версии по времени: исходная запись — симптом на момент прогона, амандмент — корень позже. Никаких «обновлений на месте».

4) **Расширяй build**. Это твой файл, friction — часть контракта записи, а не M2-нашлёпка шота. Второй путь пересборки хеша ради friction — украшательство и долг. Валидация `symptom обязателен, root/fix/prevention nullable` — внутри `buildProcedureRunRecord`, там же нормализация `friction[]`. M2-путь оставь тому, для чего он рождён.

Затронутые модули: `scripts/lib/procedure-run-journal.mjs` (build + новые API `appendOpen`, `appendClose`, `appendFrictionAmend`, `closeOrphaned`); зуб к нему; `docs/procedures/*` — фиксация схемы @1.1 (runPhase, friction, amends, orphanedBy).

5) **Минимальные зубы сверх DoD:**
- open без close того же runId + следующая open той же процедуры → close-сирота append-нулся; leafHash валиден; index продолжает ленту сироты.
- friction: symptom пуст/отсутствует → throw; nullable-поля корректно сериализуются (null vs undefined — одно представление).
- friction-amend на несуществующий (runId, index, frictionIndex) → throw; амандмент к уже заамандменной записи допустим (цепочка), последняя выигрывает по времени.
- leafHash пересчитывается по расширённому телу; старые записи без runPhase читаются как close (обратная совместимость чтения) — или явный отказ, если решаем ломать. Мой голос: читать старое как close, писать новое строго с runPhase.

Рекомендация: **нужен ADR** — расширение схемы записи (`runPhase`, `friction[]`, `amends`, `orphanedBy`) и правило «событие вместо мутации» стоит зафиксировать явно, иначе через два спринта кто-то предложит «просто дописать корень на месте». Консилиум не нужен — развилок нет, есть один честный путь.
