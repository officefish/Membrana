Теперь по блоку.

**1) Тексты и порядок чисел.** Порядок в строке узла правильный: «Останется N · уйдёт в архив M · ≈X МБ» — глаз сначала ловит, что сохранится, потом цену. Шапка-итог «{totalFrozen} записей уйдут в архив» хороша, но в ней нет симметричной «останется», и нет числа **узлов с избытком** — а это первое, что оператор ищет: «на скольких приборах правка». Предложил бы: «На K узлах: останется A · уйдёт в архив B записей · ≈Y. Архив хранится N дн., примерно до DATE, вернуть можно со страницы узла». «Записи не удаляются сейчас» — лишнее отрицание, снимает тревогу ценой длины; «уйдут в архив» уже это говорит.

**2) a11y окна — чего не хватает.**
- **Возврата фокуса на источник нет** — после `onCancel/onConfirm` фокус улетит в `<body>`. Нужен либо `previouslyFocused = document.activeElement` на mount + restore в cleanup, либо проброс `triggerRef` снаружи. Это несущая конструкция, не опция.
- **Тост успеха** живёт вне окна — ему нужен `aria-live="polite"` в общем live-region кабинета (если уже есть — ок, в b5 не вижу).
- `alert` блок **уже** `role="alert"` — ок, но при повторной ошибке с тем же текстом скринридер не перечитает; на `refusal` стоит менять `key` или оборачивать в `aria-live="assertive"` контейнер и очищать перед заменой.
- `aria-describedby` указывает на вводный абзац — хорошо; список узлов имеет `aria-label="По узлам"` — тоже ок.
- Мелочь: `select` без `id`, label завязан через вложение — валидно, но `htmlFor`+`id` надёжнее для AT.

**3) Выбор режима внутри окна.** Уместен и правилен: смена критерия пересобирает план, человек видит новые числа **до** подтверждения, `confirmedDigests` остаются честными. Единственная ловушка — во время перезапроса select активен, числа старые: нужен `aria-busy` на `<ul>` и визуальное приглушение списка (opacity-60), иначе на секунду покажется «я переключил, а не поменялось».

**4) Объём 690 (код ~510).** Резать. Три шва видны невооружённым глазом и дают по ~80–120 строк каждый, без логики:

- Хук фокус-ловушки `useDialogFocusTrap(boxRef, { onEscape, restoreTo })` → `lib/useDialogFocusTrap.ts` — переиспользуемо, заодно решает п.2.
- Строка узла → `<DowngradeNodeRow>` подкомпонент.
После этого сам `DowngradeConfirmDialog.tsx` сядет в ~180–220 строк, PR уйдёт под 400 без `--size-reason`. Зубы (178) оставить как есть.
