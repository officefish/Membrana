# Ответ (Математик)

## 1) Ключ `pkg:id` — достаточен ли он?

**Да, достаточен по контракту.** Но с оговоркой:

- Если две записи одного пакета различаются **только полями вне `{pkg, id}`** (например, severity, url изменился, а сам advisory тот же), они схлопнутся под один ключ и изменение будет невидимо.
- Это **дефект спецификации**, не реализации. Надо явно: либо `pkg:id:severity` в ключе (если severity меняется у жившей записи), либо в docs сказать: «severity и url не меняются; если изменились — переиздание, новый id».
- Текущий код **честен**: молчит об этом сценарии. Риск низкий (реестры редко меняют severity уже выпущенной advisory), но не нулевой.

**Решение:** добавить ассерт в тесты: две находки с одинаковыми `pkg:id`, но разными severity → шум, требует руки.

## 2) Симметрия — есть ли вход, где fresh и gone оба непусты, но это одна запись?

**Нет, невозможно.**

По построению: `fresh = curr.filter(f => !prevKeys.has(keyOf(f)))`, `gone = prev.filter(f => !currKeys.has(keyOf(f)))`.  
Если запись `F` в `fresh`, то её ключ `k = keyOf(F)` **не в** `prevKeys`.  
Если запись `G` в `gone`, то её ключ `k = keyOf(G)` **не в** `currKeys`.

Для того чтобы это была **одна и та же логическая запись** (с изменённым полем, но одинаковым `pkg:id`), нужно `keyOf(F) === keyOf(G)`. Но тогда `keyOf(F) ∈ prevKeys` (там живёт `G`), что **противоречит** условию `F ∈ fresh`.

**Вывод:** `fresh` и `gone` всегда **непересекаются** по ключам. Запись не может одновременно пропасть и появиться.

## 3) Что отчёт по-прежнему не отвечает?

1. **Почему молчит адвизори** — known: дозор не различает причины (исправлена / выпала из дерева / отозвана).
2. **Была ли замена** (вместо исчезновения): если `pkg:foo` пропал, а `pkg:bar` появился **в один день**, отчёт не скажет, связаны ли они. Надо **diff на уровне пакета**, не advisory.
3. **Хронология причин** — на каком шаге `npm audit` узнал о молчании? Сравнение снимков фиксирует только **факт разницы**, не **момент и адрес** в зависимостях.
4. **Корень новой находки** — если `pkg` появилась, откуда она пришла? Это зависимость новая, или проснулась старая при обновлении parent-пакета?

**Итог:** ядро верно — это **детектор изменений**, а не диагностика причин.
