**Конструкция.** Глагол — чистый предикат состояния ветки относительно ствола и удалёнки. Его правда — это дизъюнкция трёх независимых блокировок; ядро их не сворачивает.

**1) Чем мерить «содержание в стволе» после squash.**
- Честный способ — `git cherry -v origin/main <branch>`: для каждого коммита ветки ищет эквивалент по patch-id в стволе; `-` значит «уже там». Это и есть patch-id сравнение, только руками git.
- Предел: patch-id считается по diff без контекста имён коммитов и порядка; **ломается**, если при squash был конфликт-resolve, ручная правка сообщения diff-а, или ветка тянула из main поверх (merge-commits в истории). Тогда часть коммитов покажется «неслитой», хотя семантически в стволе. Это надо честно назвать в §4, а не прятать за эвристикой «diff против merge-base пуст».
- `diff origin/main...branch` пуст — более грубый, но робастный дубль-чек для финального «да, содержания в стволе не осталось».

**2) Форма при нескольких причинах.** Объект `{ safe: boolean, reasons: Reason[] }`, где `Reason` — именованный вариант (`open-pr`, `unpushed-commits`, `unmerged-content`). Строка `blocked:<одна>` — ложь по опущению: и живой PR, и незапушенное бывают вместе, агент починит первое и напорется на второе. CLI-обёртка печатает `safe` либо `blocked: open-pr, unpushed-commits` — форматирование поверх честного объекта.

**3) Граница ядра и порта.** Ядро принимает значением: имя ветки, снапшот рефов (`branch → sha`, `origin/main → sha`), список коммитов ветки не в стволе (результат `cherry`), список PR-ов по имени ветки (`{number, state}[]`), список незапушенных коммитов. Всё, что стучится в git, GitHub, файловую систему — порты. Ядро — pure функция `(snapshot) → {safe, reasons}`, тестируется на фикстурах без git вообще.

**4) Чего глагол НЕ обещает** (печатать в `--help` и в hand-off):
- не говорит, безопасно ли **удалять** ветку — только «двигать голову».
- не проверяет чужие форки и удалёнки кроме `origin`.
- `unmerged-content` при наличии merge-commits внутри ветки может быть **ложно-положительным** — глагол это признаёт, а не скрывает.
- не судит о working tree (dirty index, stash) — это забота другого слоя.

Рекомендация: **форма**, ADR не нужен. Если внутри блока A всплывёт вопрос «а можно ли safe при dirty tree» — тогда консилиум с держателем A, но это уже про глагол шипа, не про этот контракт.
