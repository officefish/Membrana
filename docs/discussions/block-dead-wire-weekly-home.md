## 1) Поля, отличающие дом недельной от дневной

**Различающие (обязательны только в недельной):**
- `cadence: "weekly" | "daily"` — явный язычок такта.
- `window: { startsAt: ISO, endsAt: ISO, dayOfWeek: number }` — точное временное окно (не «когда успеем»).
- `owner: { persona, until: ISO }` — владелец такта на период, не расплывчатое распределение ответственности.
- `checkInterval: duration` — как часто прогонять; для недельной — не чаще раза в 7 суток.
- `escalationOnMiss: { to: persona, after: duration }` — что делать, если такт пропущен.

**Общие, но заполняются по-другому:**
- `doneWhen` — для недельной = «зуб был зелёным в последний день такта»; для дневной — во время дня.
- `outOfScope` — список того, что **не** касается этого такта (например, в dead-wire — реализация инструментов).

## 5) Что делать 09.08, когда pending истекают

**При первом прогоне после 09.08.23:59 UTC:**

1. `yarn dead-wire:check` поднимает код `1` (находки).
2. Для каждой из шести записей с `expiresAt ≤ now`:
   - Статус **автоматически** переходит в `expired` (новое поле в `dead-wire-pending.json`).
   - Процедура **не** удаляет; владелец такта получает **уведомление** (Notice в Evidence-ленту спринта).
3. Владелец выбирает: `implement` / `pending` (новый срок) / `remove`.
4. Если выбора нет — карточка `#XXXX` → `blocked` со статусом `awaiting-owner-decision`, уведомление Teamlead.

**В доме — пункт про expiry:**
```markdown
## Обработка истёкших сроков

Когда `expiresAt` записи pending ≤ текущему времени, процедура:
- Регистрирует `status: expired` в перечне.
- Отправляет Notice владельцу такта (в Evidence спринта).
- **Не удаляет** молча; решение — только владелец такта.
```
