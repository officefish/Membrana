По существу.

1) **Подстрока vs AST.** Хрупкость односторонняя: зуб ложно-отрицателен, ложно-положителен быть не может. Пропустит любую копию, где тело переписано семантически эквивалентно: `start + fftSize <= samples.length` → `start <= samples.length - fftSize`, `samples.length >= start + fftSize`, `end = start + fftSize; end <= samples.length`, разворот в `for`, замена `fftSize` на локальную `N`. Также молча пройдёт копия в `.js`/`.mjs` (обход фильтрует по `.ts`). Стоимость false-negative: ровно тот дефект 01.08 повторится. Компромисс: добавить второй предикат по инварианту — «единственный файл, где `samples.length` и `fftSize` встречаются в одном арифметическом выражении шага окна» — либо перейти на ts-morph, но это уже отдельный носитель, его тоже надо будет держать в одном экземпляре.

2) **Число сводов = 2.** Не мешает, если правило роста формализовано в самом зубе. Сейчас «2» — магическая константа, и законный третий свод (например, медианный под робастную статистику выбросов) уронит зуб без подсказки, что делать. Правильная форма: `carriers.length === EXPECTED_MEANS.length`, где `EXPECTED_MEANS` — список с комментарием «одна природа — один свод», и добавление строки в список и есть акт признания новой природы. Тогда зуб держит биекцию «природа ↔ свод», а не число.

3) **Чего нет в пяти проверках:**
   - **Публичность носителя.** Не проверено, что `sample-window.ts` реэкспортирован из `detector-base/src/index.ts`; детектор может импортировать глубоким путём в обход публичного API, и зуб этого не заметит.
   - **Отсутствие приватной `iterWindows`** и её родичей по имени в детекторах — прямой рецидив 02.08 ловится дешевле, чем через тело цикла.
   - **`.js`/`.mjs`/тесты.** Обход ограничен `packages/**/src/**/*.ts`; копия в `scripts/`, `apps/`, `__tests__` или `.mjs` пройдёт мимо.
   - **Симметрия обратного направления:** носитель не тянет обратно в детекторы (нет импорта из `detectors/*` в `base/`) — граф зависимостей §1e держится другим механизмом, но раз уж зуб межпакетный, дешевле дописать здесь.
   - **Живость носителя:** что `prepareFftSamples` реально вызывается хотя бы одним детектором — иначе единственность объявления совместима с мёртвым кодом.
