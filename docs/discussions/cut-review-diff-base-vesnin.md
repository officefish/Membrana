## Решения по развилкам

1. **Источник диффа:** `gh api compare` как первичный (онлайн, `merge_base_commit` + файлы согласованы в одном ответе, работает для соседних PR без выкачки ветки). Локальный `git merge-base` + `git diff` — фолбэк, когда сеть/rate-limit отказал. `gh pr diff` из ручек убираем.
2. **Локальный head ≠ headRefOid PR:** не молчим. Базовый режим `--pr` жёстко идёт по `headRefOid` из `compare` — локальный worktree не участвует. Если запрошено ревью локального состояния — отдельный явный флаг `--local`, в маркере пишем `head` фактический и пометку `scope:local`.
3. **База в артефакте:** и туда, и туда, но с разной ролью. В маркер вердикта — поле `base:<sha>` (машиночитаемо для гейта). В тело — строка провенанса «base / head / merge_base / source=compare|local» (для человека и постфактум-разбора). Одно поле не заменяет другое.
4. **`review-gate` и база:** сверяет. Три исхода: `base == current merge-base` → LGTM в силе; `base != current merge-base` → **stale-base** (отдельный исход, не то же самое, что «новые коммиты в head»), требуется пере-ревью; маркер без `base:` — legacy, см. п.5.
5. **Обратная совместимость:** парсер маркеров читает и с `base:`, и без. Legacy-маркеры (без базы) продолжают открывать мердж как раньше — переписывать историю не будем. Новое правило `stale-base` включается **только** для маркеров с полем `base:`. Так старые артефакты в `docs/discussions/` не ломаются, а новые несут больше правды.
