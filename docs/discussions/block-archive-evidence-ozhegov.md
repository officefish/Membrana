## 1. Разбор трёх скриптов — построчно по смыслу

### `scripts/audit-evening.mjs` (158 строк)

**Входная роль:** оркестратор. Вызывает два модуля и объединяет результаты.

- Парсит ввод: `--stdout`, `--date` (опц., по умолчанию `new Date()`).
- Проходит `auditEvening()` из `scripts/lib/audit-evening.mjs` — основной расчёт.
- Записывает в два места:
  - `docs/DAILY_AUDIT.md` — текущий снимок (всегда перезаписывается).
  - `docs/archive/daily-day/<YYYY-MM-DD>/audit.md` — датированный архив.
- Возвращает процесс с кодом 0 при успехе.

**Что правится здесь:** ничего логики. Точка входа уже правильная, вызовы на месте. Проблема не в оркестраторе, а в отсутствии вызова из цепочки и неподтянутом индексе.

### `scripts/lib/audit-evening.mjs` (375 строк)

**Входная роль:** хронист. Собирает три источника, форматирует, не судит.

Ожидаемые роли:
1. **Инвентарь репозитория** — какие ветки, коммиты, теги на момент `now`.
2. **Реестр задач** — открытые карточки, спринты, статусы из `docs/tasks/registry.json`.
3. **Граф правды** — вещдоки, предикаты, история из `docs/evidence/registry.jsonl` (или его версия на диске).

**Что правится здесь:** функция `auditEvening(date)` получает один параметр и мустит три инвентаря в Markdown. При дефекте — генерирует пустой или искажённый отчёт, что и видели в проверке 31.07 (отсутствие 12 дней — признак того, что функция вызывалась, но результат либо не писался в архив, либо писался, но данные были невалидными).

Главный контракт: **функция воспроизводима** — один вход (`date`) → один выход (Markdown-снимок). Не зависит от текущего времени после расчёта (`date`).

### `scripts/lib/evidence-inventory.mjs` (неполный размер в бриефе)

**Входная роль:** индексер реестра вещдоков.

- Парсит `docs/evidence/registry.jsonl` (append-only архив).
- Генерирует `docs/evidence/INDEX.md` — читаемый справочник (léger table or list).
- Зуб `evidence-inventory.test.mjs` проверяет: перегенерация из реестра даёт **идентичный** INDEX.

**Что правится здесь:** контракт между реестром и индексом **запотел**. Вероятная причина:
- `day-memo.mjs` пишет новую запись в `registry.jsonl` без触발 перегенерации индекса.
- При следующем запуске любого скрипта, который читает индекс или его валидирует, обнаруживается расхождение.

**Решение:** либо `day-memo` сам регенерирует индекс (и должен этот шаг объявить), либо индексирование отдельным шагом в цепочке **сразу после** `day-memo`.

**Контракт явно:**

- **Шаг 1:** `evidence-index-regenerate` вызывает `yarn run evidence index` (или экспортирует `regenerateIndex()` для синхронного вызова из манифеста).

  - **Выход:** `docs/evidence/INDEX.md` перезаписан, тест `evidence-inventory.test.mjs` пройдёт.
  - **Зависимость:** `day-memo` уже завершил и написал новую запись.

- **Шаг 2 (опциональный):** `audit-evening-run` вызывает `yarn audit:evening`.
  - **Вход:** `docs/evidence/registry.jsonl`, `docs/tasks/registry.json`, состояние репо.
  - **Выход:** `docs/DAILY_AUDIT.md` + `docs/archive/daily-day/<YYYY-MM-DD>/audit.md`.
  - **Зависимость:** `evidence-index-regenerate` завершил (в целях консистентности, хотя аудит может работать и независимо).

## 3. Порядок шагов: `evidence-index-regenerate` ↔ `archive-daily-day`

**Правильный порядок:**

```
day-memo
  ↓
evidence-index-regenerate       ← ТВОЙ блок
  ↓
audit-evening-run              ← ТВОЙ блок (опционально)
  ↓
archive-daily-day              ← СОСЕДНИЙ блок
```

**Обоснование:**

1. **`day-memo` → `evidence-index-regenerate`:** Новая запись в реестр должна быть отражена в индексе до того, как кто-либо его читает.

2. **`evidence-index-regenerate` → `audit-evening-run`:** Если аудит читает индекс или строит отчёт, основанный на индексе, то индекс должен быть свежий. Если аудит опирается только на `registry.jsonl` напрямую (минуя индекс), то зависимость может быть ослаблена, но здравый смысл говорит: держи индекс в консистентном состоянии.

3. **`audit-evening-run` → `archive-daily-day`:** Оба пишут в `docs/archive/daily-day/<date>/`. Аудит пишет `audit.md`, сосед может писать другие снимки (манифест дня, карточки). **Порядок важен для атомарности:** сначала оба вычисления, потом архивирование, чтобы снимок дня был полный.

   Если `archive-daily-day` просто копирует `docs/archive/` в какое-то хранилище или создаёт `.tar`, то оба скрипта должны завершиться до архивирования.
