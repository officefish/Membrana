## 1. Кадр доставки: секция, соседи, `holder`

Кадр `deliver-to-main` должен встать в секцию **`frames`** (активные единицы процедуры, как и утром), после шага `archive-daily-day` по логике следствия — архив выложен, теперь проверяем доставку.

**Соседство:** 
- перед: `evening-tail` (диспетчер цепочки); 
- после: последний шаг, который может быть заблокирован отсутствием артефактов.

**`holder`**: `ritual-evening` (вечерняя процедура сама владеет кадром, как утренняя владеет своим).

**Почему:** Кадр — это **ворота**. Если артефакты не в main, цепочка стопится и уведомляет владельца. Движок (`ritual-deliver-to-main.mjs`) уже готов считать статусы; манифест обязан обозвать ворота явно, иначе от кадра — только листок бумаги.

## 3. Форма шага аудита: `id`, `criticality`, `consumes`/`produces`, место

```json
{
  "id": "audit-evening-artifacts",
  "script": "yarn audit:evening",
  "kind": "mechanic",
  "criticality": "critical",
  "label": "Audit evening artifacts against manifest",
  "consumes": [
    "docs/procedures/ritual-evening/MANIFEST.json",
    "docs/tasks/evening-ritual-steps.json"
  ],
  "produces": [
    "docs/archive/daily-day/<date>/audit.md"
  ]
}
```

**Место в порядке:** После `archive-daily-day` (чтобы архив существовал), **до** `deliver-to-main` (чтобы отказать кадру при ошибке аудита).

**Критичность: `critical`** с обоснованием: аудит выявляет раздвижение между объявленным манифестом и реальностью; fail здесь — это обязательная стоп-сигнал для владельца, иначе поддельные артефакты заедят main.
