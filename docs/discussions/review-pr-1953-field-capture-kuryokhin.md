## Разбор Курёхина — тракт

| Звено | Что делает PR | Оценка |
|---|---|---|
| Вход | `ffmpeg -f dshow … -channels 2 -af pan=mono\|c0=c0` — берёт вход 1 отдельным каналом, не сведение L+R | ✓ правильно: пустой вход 2 не подмешивается |
| Разрядность | wav по умолчанию ffmpeg — PCM16 LE; `measureWav` разбирает чанки, не смещение 44 | ✓ совместимо с декодерами (media `decode-wav-mono`, измеритель, плагин — все PCM16) |
| Уровень | пик/средний в dBFS; ниже −60 dBFS — «ТИШИНА, наружу не отправляю» | ✓ нормализации нет и **не должно быть**: в корпус идут сырые отсчёты, уровень — измеренный факт, не приведённый; порог тишины ловит отвалившееся фантомное питание |
| Ресемплинг | отсутствует | ✓ по норме: сервер меряет, объявленное не перебивает измеренное (#1950) |
| **Частота** | по умолчанию **`rate: 44100`** (`parseArgs`), меняется `--rate` | **✗ несогласована с воротами**: калибровка mfcc снята при `sr48000` (`mel40-c24-buf4096-sr48000`); измеритель и плагин запись на 44,1 кГц **не судят** («частота 44100 ≠ 48000, на которой сняты ворота — несравнимо»). Живое следствие уже есть: запись 2026-08-16T14-56-54 (11,99 с, 44 100 Гц) получила `refused` в первом живом прогоне `membrana.handler.mfcc` 18.08 |

Ресемплинг на тракте ставить не надо — он бы сделал «сырые отсчёты» не сырыми; правильное место
согласования — **умолчание частоты захвата**: 48 000, как у ворот, с явным предупреждением, если
оператор задаёт иное. Пересчитывать под чужие ворота нельзя ни на сервере, ни в детекторе (#1603) —
значит, единственная точка, где частоту можно выбрать верно, это момент записи.
