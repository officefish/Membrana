## 2026-09-08 08:53 UTC · ozhegov

**Контекст:** GitHub Issue #2331: «Матрица тарифов как единственный источник правды: гранулы по ресурсу + шаблон в контейнере strategic-docs, сетка — производная (сессия Б, спринт)»
**Вопрос:** Прогон контекста перед блоком b1 matrix-passport-storage спринта tariff-matrix-2331 (ты — ответственный контекст блоков b1 и b2). Предмет b1: форма паспорта гранулы ресурса в контейнере strategic-docs и первые гранулы хранения (purpose, buffer, collections, cold). Паспорт (T14): версия, дата закрепления, владелец, ресурс, единица, домен, правило пересева; значения по трём тарифам внутри гранулы (тариф — колонка). Носитель значений — resource.json рядом с granule.json; строка таблицы релиза рендерится функцией render.mjs из resource.json (function granule контейнера). Вопросы словаря и формы: (1) имена ресурсов и их русские заголовки в таблице — buffer «буфер записи», collections «коллекции (горячая память)», cold «холодное хранилище», nodes «приборы», workspaces «сценарии», datasets «наборы звуков», instruments «инструменты» — что поправить, чтобы слово не лгало (например «коллекции» против storage.hot сетки); (2) закрытый список значений «правило пересева» (reseedRule) — предложи 3–4 значения с определениями (например exact-bytes: число из гранулы едет в сетку байтами без пересчёта; catalog-id: идентификатор набора едет как есть; enabled-flag; gated-by-precondition); (3) как словами записать в грануле datasets заглушку «наблюдательный пункт пока на наборе блокпоста» так, чтобы будущий пересев не принял заглушку за решение; (4) единицы: МиБ в паспорте vs байты в сетке — где живёт пересчёт и как назвать поле, чтобы 512 МиБ не читалось как 512 МБ; (5) домен паспорта — что это за ось (storage / rights / catalog / instrument) и нужна ли она. Ответь по пунктам, коротко, вердикт формы в конце.

**Ответ:**

**Контекст → решение.** Прогон словаря перед b1: слово должно быть леммой, а не ассоциацией.

1. **Имена ресурсов.** `collections` → «коллекции» лжёт: в сетке это `storage.hot`. Либо ресурс называем `hot` (единица — коллекции), либо в грануле явно: `resource: storage.hot`, заголовок «коллекции (горячая память)». `cold` — «холодное хранилище» — ок. `buffer` — «буфер записи» — ок. `instruments` — «инструменты» — ок, если это приборы анализа, а не плагины; иначе `tools`.

2. **reseedRule:** `exact-bytes` (число из гранулы — в сетку байтами, без пересчёта), `catalog-id` (идентификатор набора едет как есть, строка), `enabled-flag` (булево, без значения), `gated-by-precondition` (значение не едет; сетка берёт его из условия, описанного в паспорте). Четырёх достаточно.

3. **Заглушка datasets:** писать не словами в значении, а в паспорте гранулы полем `observation` с датой: «наблюдательный пункт использует набор блокпоста; решение не закреплено, пересев не Berücksichtigung». Значение в грануле — `null` + `reseedRule: gated-by-precondition`. Так пересев не примет заглушку за решение: null ≠ число.

4. **Единицы.** В паспорте — `unit: MiB`; поле в resource.json — `bytes: 536870912` (число). Пересчёт — в render.mjs: единственное место. Поле для сетки — `bytes`, не `size`; `sizeMiB` — только в паспорте для чтения человеком.

5. **Домен.** Нужен: это ось общих словарей (хранение/права/каталог). Для b1 — `storage.hot`, `storage.cold`; не смешивать с `catalog`.

**Вердикт формы:** паспорт — `resource.json` (версия, дата, владелец, домен, единица, правило пересева, значения по тарифам) + `granule.json` (только метаданные и ссылка). Один носитель значений — без дублирования.
