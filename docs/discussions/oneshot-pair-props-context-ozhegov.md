По существу, до кода:

1) Имя. `eg-review-before-run` — терпимо, но слово `review` уже занято старой находкой, и читатель не различит «раньше подписи» и «раньше прогона». Предлагаю пару-словарь:
   - ORDER_REVIEW_BEFORE_SIGN (переименовать ORDER_REVIEW_EARLY — «early» без опоры, антисловарно).
   - ORDER_REVIEW_BEFORE_RUN (новая).
   Общий термин обеих — «предвременное ревью», различие — по **опорной точке**: sign (подпись субъекта) vs run (прогон контекста субъекта). В `reason` находки — короткая словарная статья: «ревью_ок зафиксировано раньше {sign|run} того же субъекта».

2) Семантика «раньше чего именно». Честный вариант — **раньше первого `context_run` субъекта в окне honest_pair**. Обоснование: находка ловит нарушение «ревью после прогона», т.е. первое появление прогона и есть граница нормы. «Последний до данного review_pass» тихо разрешает случай «прогнали, потом отревьюили, потом ещё раз прогнали» — это уже другое свойство (ревизия между следами), и оно как раз закрывается композицией #1641+#1638. Не смешивать.

3) Куда класть замер. Замер порядка пары — **представление гейта**, не самостоятельный вычислитель (см. вторую всплытую строку). Кладём в отчёт шота отдельной секцией `pair-order` (subject, review_pass.ts, first_context_run.ts, verdict). Отдельный артефакт — только если его будет читать другой предикат; сейчас читателей нет — не плодить фасад.
