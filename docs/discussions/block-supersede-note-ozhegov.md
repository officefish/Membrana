## 2026-08-03 11:11 UTC · ozhegov

**Контекст:** docs/discussions/trace-supersede-evidence.md
**Вопрос:** Два блока за тобой в спринте gate-stale-supersede-by-recut: supersede-wire (CLI читает ленту актов переиспользованием readActsTrail и передаёт recutActs значением; после разбора Дынина добавлена сверка sprintId записи — лента названа по спринту, но чужая запись внутри файла открыла бы дверь чужим актом) и evidence-note (вещдок: изъятая строка не существует даже в git-истории; раздел ПОЧЕМУ время а не факт акта — три довода: старый акт легализует всё, чужая перерезка отзывает чужое, изъятие остаётся выгоднее; таблица трёх зубов-часовых). Ответь как структурщик коротко: 1) провод execution-gate → readActsTrail из sprint-cut-check — не завёл ли я связь скрипт-к-скрипту, которой словарь проекта запрещает быть, и если да, где правильный дом для readActsTrail; 2) слова «отозван актом, не изъят» в причине дисквалификации — точны ли; 3) вещдок-нота: не не хватает ли ей команды воспроизведения для утверждения про git-историю.

**Ответ:**

Контекст → решение → пути → риски.

**1) Провод execution-gate → readActsTrail (дом функции).**
Скрипт-к-скрипту — да, это нарушение нормы, если `execution-gate` тянет `import` из `sprint-cut-check/*` напрямую. Скрипты — это исполняемые точки входа, не библиотеки; между ними нет `index.ts`, и любая такая связь становится «тайным API». Правильный дом для `readActsTrail` — общий модуль-читатель ленты актов, экспортируемый через `index.ts`: например, `tools/sprint-trail/src/acts-trail.ts` (или `packages/services/sprint-trail-service`, если лента актов — уже полноценный сервис проекта). Оба скрипта импортируют лемму `readActsTrail` из одного словаря, а не друг из друга. Иначе — `нарушена слабая связанность`: скрипт → скрипт, минуя фасад.

**2) «Отозван актом, не изъят» в причине дисквалификации.**
Формулировка близка, но лемму лучше сузить. «Отозван» — омоним: можно понять как «удалён». Здесь смысл строже: **след дисквалифицирован актом перерезки в окне `[t_stale, revisionAt]`**. Предлагаю причину назвать так, как код её и зовёт: `eg-superseded-by-recut`, а прозой — «дисквалифицирован актом перерезки (не изъят)». Тогда пара «superseded ≠ removed» держится словарно, и таблица трёх зубов не расходится с текстом.

**3) Вещдок-нота и команда воспроизведения.**
Да, не хватает. Утверждение «строки нет даже в git-истории» — проверяемое, и без команды оно живёт на честном слове. Добавь в ноту точный однострочник, который резчик уже прогнал, с ожидаемым выводом:

```bash
git log --all --oneline -S 'tr-port-vesnin-run-v1' -- docs/sprint/trail/subconscious-lift-c3.jsonl
# ожидание: пусто (0 коммитов) — строка не существовала в ленте ни в один момент
```

И симметрично — команду, показывающую отсутствие `recut_act` в ленте актов того спринта. Тогда вещдок сам себя воспроизводит, а не ссылается на память разведки.

**Затронутое:** `tools/sprint-trail/*` (или новый сервис), `scripts/execution-gate`, `scripts/sprint-cut-check`, `docs/discussions/trace-supersede-evidence.md`.
**Риск связанности:** если `readActsTrail` останется внутри `sprint-cut-check`, любой третий потребитель ленты актов родит второй такой же читатель — синоним-фасад, который потом придётся сводить ADR-ом.
