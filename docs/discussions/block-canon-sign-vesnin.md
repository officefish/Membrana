# Блок `canon-sign-preserves-provenance` — анализ

Вижу дело. Две регрессии в одном скрипте: провенанс стирается при смене автора, и устаревшая карта ролей. Давай разбираться по пунктам.

## 1. Как сохранить `readAt` при смене автора

**Способ:** перед заменой всего блока (`<!-- angelina {...} -->`) на строке 45 — **разобрать существующую шапку регексом**, вытащить `readAt` из старого контракта, передать в новый.

```js
// Что-то вроде:
const existingHeader = content.match(/<!-- angelina ({.*?}) -->/);
const oldReadAt = existingHeader ? JSON.parse(existingHeader[1]).readAt || {} : {};

const header = provenanceHeader({ 
  author: provAuthor, 
  readAt: oldReadAt  // ← сохраняем прежние отметки
});
```

**Риск:** если JSON в старой шапке битый или разбирается неправильно, `oldReadAt` останется пустым и мы снова сотрём провенанс. Значит, нужна **строгая валидация**.

## 2. Если шапки нет (новая подпись)

В этом случае `readAt` брать неоткуда — законно. Шапка впервые добавляется с пустым или минимальным `readAt: {}`. Это нормально: генераторы заполнят отметки при следующих проходах.

**Вход:** проверить, что на строке 51 при `// Add new header` ты не передаёшь в `provenanceHeader` никакие `readAt` — пусть будет `{}` по умолчанию.

## 3. Если существующая шапка битая

**Правильный ответ:** **отказать явно**, не молчать. Если JSON не распарсится — выбросить Error с адресом, что именно сломалось. Молчаливый фолбэк (`readAt: {}`) — тот же класс лжи, что ловили сегодня трижды. Владелец должен узнать, что подпись невалидна, и чинить руками.

```js
try {
  const oldReadAt = JSON.parse(existingHeader[1]).readAt;
} catch (e) {
  throw new Error(
    `canon-sign: битая шапка провенанса в документе. ` +
    `Не могу разобрать JSON: ${e.message}\n` +
    `Строка: ${existingHeader[0]}`
  );
}
```
