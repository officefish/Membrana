# Блок 1 `smoke-inside-image` — прогон контекста Веснина

**Спринт:** `dockerfile-copy-manifest-drifts` ([#1797](https://github.com/officefish/Membrana/issues/1797)).
**Исполнитель:** vesnin. **Дата:** 2026-08-08.

## Что предъявлено контексту

Задача блока — прибор, доказывающий, что образ офиса ИСПОЛНЯЕТ свой рантайм, а не только
собирается. BLOCK-условие резчика: список рантайм-модулей НЕ дублируется между офисом и
прибором.

## Найденный способ выполнить условие буквально

Список не понадобился **вообще**. У офиса есть публичный путь `GET /v1/dreams/digest/:day`
(`dreams.controller.ts:12`, гварда на нём нет — `ApiTokenGuard` висит только на `POST tick`),
который через `DreamsService.lib()` (`dreams.service.ts:83`) грузит `dreams-log`,
`dreams-tick`, `dreams-format`, `night-research`, `dreams-providers` и их транзитив, а в сеть
не ходит: читает журнал с тома и форматирует.

Поэтому прибор поднимает контейнер и просит дайджест. Пропал скопированный файл — путь
падает `MODULE_NOT_FOUND`, и прибор называет **имя файла**. Источник истины остался один —
код офиса; прибор проверяет его исполнением, а не сверкой двух списков. План предполагал
файл `scripts/lib/office-runtime-modules.mjs` как единственное место списка — он не создан,
потому что нашёлся способ без списка совсем. Отклонение в сторону строгого выполнения
BLOCK-условия, а не в обход него.

Обязательные env (`API_INTERNAL_TOKEN`, `ANTHROPIC_API_KEY`, `GITHUB_TOKEN`, `GITHUB_OWNER`,
`GITHUB_REPO` — `env.schema.ts`) заполняются заведомо нерабочими значениями: проверяется
резолв модулей, а не синтез. Секреты прибору не нужны, поэтому он идёт и на PR из форка.

## Разделение диагнозов — и красный зуб, который его вытребовал

Исходы закрыты списком: `pass` · `missing-module` · `unhealthy` · `broken`. Склеить их в одно
«красное» значило бы заставить читателя гадать, что чинить.

Имя модуля ищется ПЕРВЫМ и в двух источниках — в теле ответа и в логах контейнера. Причина:
самый частый случай расхождения — офис не поднимается вообще, `health` молчит; диагноз
«unhealthy» скрыл бы настоящую причину, то есть повторил бы молчание, стоившее 07.08.

Порядок проверок стоил одного красного зуба: сначала ядро отвечало `broken` на пару
«health не ok, дайджест не опрошен», хотя это `unhealthy` — отсутствие дайджеста здесь
СЛЕДСТВИЕ мёртвого контейнера, а не вторая поломка. Зуб был прав, ядро нет; исправлено, и
теперь порядок держится зубом.

## Пределы объявлены вслух

Печатаются вместе с вердиктом: прибор проверяет путь снов (модули, которые грузит только
другой путь офиса, вне области); лениво читаемые json-данные его слепое пятно; он судит
полноту образа, а не корректность поведения — пустой дайджест это законный `pass`.

## Гап живого прогона — назван, не замолчан

Зубы: **9/9**. Живой отказ проверен: без docker прибор даёт `exit 2` «прогон НЕ состоялся»,
а не зелёное. Полный прогон в контейнере локально **не выполнен** — docker daemon на машине
не запущен (`failed to connect to the docker API at npipe:…dockerDesktopLinuxEngine`).
Поднимать Docker Desktop на машине владельца ради этого не стал. Проверка делегирована CI:
workflow `office-image-smoke.yml` собирает образ и гоняет прибор на первом же PR, который
трогает офис или `scripts/lib` — то есть на этом самом.
