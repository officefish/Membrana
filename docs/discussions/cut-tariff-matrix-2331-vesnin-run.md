**Контекст:** GitHub Issue #2331: «Матрица тарифов как единственный источник правды: гранулы по ресурсу + шаблон в контейнере strategic-docs, сетка — производная (сессия Б, спринт)»
**Вопрос:** Прогон контекста резчика перед ратификацией нарезки спринта tariff-matrix-2331 (membrana-local-sprint). План нарезки: b1 matrix-passport-storage (ozhegov: дизайн паспорта гранулы TARIFF-MATRIX-DESIGN.md, чистое ядро паспорта scripts/lib/tariff-matrix/passport.mjs с зубом полноты, гранулы tariff-matrix-purpose, tariff-buffer, tariff-collections, tariff-cold — каждая с granule.json, resource.json (паспорт: версия, дата закрепления, владелец, ресурс, единица, домен, правило пересева; значения по трём тарифам) и render.mjs строки таблицы); b2 matrix-granules-rights (ozhegov: tariff-nodes, tariff-workspaces, tariff-datasets с заглушкой observatory→checkpoint словами, tariff-instruments); b3 matrix-template-release (vesnin: шаблон tariff-matrix, релиз через yarn strategic-docs:generate, корневой указатель docs/TARIFF_MATRIX.md, строки README/WORKSHOP контейнера); b4 reseed-grid (dynin: глагол yarn tariff:reseed — генерация docs/tariffs/tariff-grid.json из релиза и resource.json гранул, зуб tariff:grid — красный только G↔R, скаляры S0 — замороженная эпоха сида с печатным списком расхождений по консилиуму tariff-matrix-scalars-fate-2026-09-08; провода package.json и workshop.catalog.json); b5 sprint-closure (vesnin). Границы: только матрица и сетка; пересев базы/приборов — В. Вопросы к тебе как архитектору-держателю: (1) держится ли граница «данные (resource.json) → форма (render/template) → производная (reseed)» и не рождает ли b4 второй дом чисел; (2) правильно ли, что значения по тарифам живут внутри гранулы ресурса (тариф — колонка), а не в гранулах по тарифу; (3) нужен ли ADR или достаточно консилиума по скалярам; (4) что в нарезке ты бы изменил.

**Ответ:**

Конструкция держится: гранула ресурса — данные, шаблон — форма, reseed — производная. b4 не рождает второй дом чисел: он читает release.json и resource.json, пишет tariff-grid.json — это конвейер, не новый источник. Единственный источник — матрица в strategic-docs, сетка остаётся производной, что соответствует T13/T16.

По п.2 — верно. Тариф — это колонка в грануле ресурса, а не отдельная сущность: значения принадлежат ресурсу (буфер, коллекции), а не наоборот. Разделение по тарифам создало бы дублирование и риск расхождения между гранулами одного ресурса.

По п.3 — консилиум по скалярам достаточен: здесь нет изменения границ пакетов или контрактов между слоями. Скаляры — решение о значениях, а не об устройстве. ADR потребуется только если позже решим менять схему паспорта (resource.json) или правило пересева.

По п.4 — одно замечание: в b1 паспорт-зуб полноты отнесён к чистому ядру passport.mjs. Убедись, что зуб проверяет не только наличие полей, но и замкнутость домена правила пересева (список значений закрыт). В остальном нарезка согласована с границами — матрица и сетка, без захода в В.
