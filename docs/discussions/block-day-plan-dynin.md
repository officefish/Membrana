## 1. Предикат «день закрыт» — составляющие и источники

**День закрыт**, если состояло **ВСЕ из этого:**

- `ritual:evening` завершился → запись вида `{kind: 'evening-compress', timestamp, result: 'ok'}` в журнал runs (или в памяти если localstorage).
- `team-evening-feedback` зафиксирован → есть текст протокола в `docs/seanses/team-evening-feedback-<DATE>.md`.
- **Отправка произошла** → `hasSentRecord(logPath, {kind: 'swallow', date: yesterday})` вернул `true`.

**Источники:**
- `ritual:evening` → либо `scripts/day-plan.mjs` сам его вызывает (тогда фактом в `gatherPremises` становится результат `$(...)`), либо он завершился ранее и зафиксирован в persisted state.
- `team-evening-feedback` → `fs.existsSync(docs/seanses/team-evening-feedback-YYYY-MM-DD.md)` (простой check).
- Отправка → `hasSentRecord()` из `comms-sent-log.mjs`.

**Синтез:** предикат `dayClosed(yesterday) = existsEveningRitual(yesterday) AND existsFeedbackMd(yesterday) AND hasSentRecord(yesterday, 'swallow')`.

## 2. Переиспользуемость `hasSentRecord` и граница её ответственности

`hasSentRecord(logPath, q)` ищет по `sha256` конкретного черновика.

**Вопрос «была ли вчера отправка рода X»** — это ИНОЙ вопрос, чем «совпадает ли этот конкретный draft с записью». Ответ:

**Новый предикат нужен**, и его **дом — `comms-sent-log.mjs`** (там живёт read-only доступ к логу). Но из твоей зоны (`day-plan-assemble.mjs`) ты эту функцию **вызываешь**, не пишешь.

```js
// в comms-sent-log.mjs добавить (чтение, без побочных эффектов):
export function hasSentByKindAndDate(logPath, {kind, dateStr}) 
  // → ищет row.kind === kind && row.sentAt.startsWith(dateStr) && row.sent === true
```

В твоей зоне:
```js
import { hasSentByKindAndDate } from './lib/comms-sent-log.mjs';

const sentYesterday = hasSentByKindAndDate(sentLogPath, {
  kind: 'swallow',
  dateStr: yesterdayIsoDate.split('T')[0]  // YYYY-MM-DD
```

## 3. Связь вычисленного с санитарным разделом — способ и цена

**Проблема:** модель получает `sanitary: "…вчерашний протокол читан…"` и одновременно может сгенерировать `"…протокола нет…"`. Они не связаны в промпте.

**Три варианта:**

### Вариант A: Механический шаблон (0 модели, надёжно)
```js
// в day-plan-assemble.mjs
const dayClosed = dayClosed(yesterday);

// Строка генерируется, а не модель:
const sanitaryLines = [
  dayClosed 
    ? `✓ вчерашний день закрыт: протокол + отправка`
    : `✗ вчерашний день НЕ закрыт: ${whyNotClosed(yesterday).join('; ')}`
];

// Остальные 3–4 линии — модель сочиняет про хвосты/долги, но эта первая линия фактом.
```

**Цена:** +5 строк, нет модели в этой части, противоречие невозможно.

### Вариант B: Факт в system-prompt (модель ограничена, но не детерминирована)
```js
const dayClosed = dayClosed(yesterday);
const systemFact = dayClosed 
  ? "FACT: Yesterday's day was closed (protocol exists, swallow sent)."
  : "FACT: Yesterday's day was NOT closed. Reasons: ...";

// В промпт day-plan.mjs передаётся systemFact, и модель ему следует
```

**Цена:** +3 строки, модель может проигнорировать, но обычно следует фактам в system-prompt.

### Вариант C: Санитарный раздел полностью механический (самый строгий)
Санитарные строки вообще не поручаются модели — все они вычисляются:
- Хвосты вчерашние → `git diff --stat <yesterday-commit> HEAD`
- Долги по ревью → запрос к Linear API (если доступно)
- Помехи прогонов → grep в логах CI

**Цена:** +40–60 строк, требует доступа к Git/API, но 100% детерминирован.

## 4. Граница вычислимого и сочиняемого в санитарных

**Вычислимо:**
- День закрыт (yes/no) — видит проект через протокол + лог отправок.
- Хвосты вчерашние — `git diff-tree` между дневными коммитами.
- Незакрытые задачи в Linear, отмеченные `status: Waiting` — запрос API.

**Сочиняемо (модель, с фактами в контексте):**
- Что из этих хвостов может помешать сегодня (интерпретация).
- Про какие долги забыли напомнить (лёгкая генерация, есть факты).
- Рекомендация по приоритизации помех.

**Граница:** всё, что подтверждается файлом или API — вычисляется, остальное — модель поверх фактов.
