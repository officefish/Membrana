ПРЕДМЕТ (из иссью, не из памяти): после мерджа pr:ship делает sync-checkout main → sync-fetch → sync-ff и оставляет дерево на базе. Утренний ритуал при этом считает держателя main НАХОДКОЙ (#1232) — штатный инструмент штатно приводит дерево в состояние, которое другой штатный инструмент объявляет нарушением. Девять срабатываний за 10 дней, все — агентские. Флаг --keep-branch есть с 28.07 и не помог: «опциональный флаг не побеждает привычку; если правильное поведение требует помнить флаг — неверно выбрано умолчание».

ДВА СЛЕДСТВИЯ (вещдоки 06–07.08): (а) дерево осталось на main — не менее трёх раз, один раз инструмент сам отказал «на ветке main — не коммитим прямо в base»; (б) сброс ветки при живом PR — не менее трёх раз: агент тянулся выровнять дерево checkout -B … origin/main, не зная, кончился ли --merge-only; следствия — пропавшая из дерева правка, сорванный гвард --merge-only, ручное восстановление головы PR.

ТРИ СЛОЯ ЛЕЧЕНИЯ, названные в иссью:
1) Перевернуть умолчание, но НЕ в --keep-branch: оставить дерево на прежней голове тоже плохо (после squash ветка расходится со стволом). Правильное конечное состояние — `git checkout -B <рабочая-ветка> origin/main`: дерево на СВОЕЙ ветке и вровень со свежим стволом, main никто не держит. «Сесть на base» — опция. ГВАРД обязателен: перецеливать можно, только если все коммиты ветки уже в стволе, причём сравнение ПО СОДЕРЖАНИЮ, не по предкам (squash: `git branch --merged` слеп, замер #492); есть незапушенное или неслитое — стоп с явным отказом.
2) Запретить движение ветки, пока на ней живой PR: отказ ДО действия.
3) Сделать состояние отвечаемым одной командой: «эту ветку сейчас безопасно двигать?» — сейчас такого способа нет, и почти все случаи произошли не от незнания правила, а от невозможности быстро узнать состояние. В иссью назван «самым дешёвым и самым недооценённым» слоем.

ЧТО УЖЕ ЕСТЬ: scripts/pr-ship.mjs (шаги sync-*, флаг --keep-branch, гвард «не коммитить в base», гвард --merge-only, шаг verify), scripts/pr-verify.mjs (факт мерджа состоянием), yarn neighbors (кто держит ветку). НЕТ: команды «безопасно ли двигать».

**Ответ:**

Положение: девять срабатываний за десять дней — это не «недосмотр агента», это неверно выбранное умолчание в штатном инструменте. Флаг --keep-branch доказал, что опция привычку не бьёт. Планка не опускается: закрываем окно сегодня.

Решение по пунктам:

1) **Два блока, не три.** Слои 1–2 живут в одном месте — хвост `pr-ship.mjs` после `sync-ff`: перецеливание рабочей ветки на `origin/main` с гвардом «по содержанию, не по предкам» и отказом при живом PR/незапушенном/неслитом. Разрывать их — плодить два PR на одну мышцу и оставлять окно между релизами. Слой 3 — отдельный блок: это новая наблюдаемость, а не действие.

2) **Держатели:**
- Блок A (слои 1–2, хвост `pr-ship.mjs` + гвард по содержанию): **Ожегов** — глаголы, цепочка доставки, гварды в шагах его земля.
- Блок B (слой 3, ответ одной командой): **Веснин** — это контракт «безопасно ли двигать», форма ответа шипа, а не его глагол. Ожегов на ревью формы отказа, чтобы совпадала с языком `pr:ship`.

3) **Слой 3 — новый глагол, `yarn branch:status` (или `pr:can-move`).** Не флаг `pr:verify` (тот про факт мерджа состоянием, другой субъект) и не `neighbors` (тот про «кто держит», а не «что с содержимым»). Один вопрос — один глагол; ответ: `safe | blocked:<причина>` с явной причиной по имени (живой PR / незапушенное / неслитое по содержимому). Этот глагол потом вызывается изнутри блока A как гвард — так слой 3 окупает себя дважды: снаружи для агента, внутри для шипа.

4) **Окно:** сегодня. Связка на день:
- утро–день: Ожегов ведёт блок A, Веснин параллельно блок B (глагол + формат отказа);
- к вечеру: блок B мерджится первым, блок A подхватывает его как гвард — иначе получим повторение истории с `--merge-only` (гвард без способа быстро свериться).

Вердикт: **LGTM на план в две связки, окно — сегодня.** BLOCK, если к вечернему разбору блок A уедет без вызова глагола из блока B — тогда мы снова опция, а не умолчание.
