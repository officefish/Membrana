**Блоки (утверждено с правками):**

1. **journal-friction-fail** — LGTM по зоне и держателю. Веснин. Оценка ~220 (недожал на API дописи friction: симптом→корень постфактум — это отдельный path `record-friction --run <id>`, забываешь его). **DoD:** тест «open без close → следующий open той же процедуры находит висящую запись и закрывает её как fail с gap=`orphaned`»; тест «friction без симптома — throw»; тест «friction с одним симптомом валиден, корень/фикс/профилактика — nullable долг».

2. **sprint-producer** — LGTM. Дынин. Оценка ~260 (маппинг вердиктов в gaps — не строчка, а таблица). **DoD:** `sprint:cut --ratify` создаёт open-запись с runId=sprintId и manifestRef; `sprint:gate` закрывает её; все honest_* → pass; любой stop/block → fail с gaps=[имена вердиктов]; тест на дважды-ratify (идемпотентность — вторая ratify не плодит запись, а находит открытую).

3. **ritual-producer** — держателя меняю. **Ожегов остаётся на врезке в package.json** (глаголы цепочек — его), но **сам `procedure-run-record.mjs` — Веснин**: это второй потребитель библиотеки журнала, писать его должен тот же, кто расширяет библиотеку блоком 1, иначе получим два диалекта. **Ответ на (2) — fail при обрыве:** обёртку-раннер не строим, это лишний слой. Механизм — **ленивое закрытие следующим прогоном той же процедуры**: `procedure-run-record open` перед созданием новой записи ищет незакрытые записи с тем же procedureId; если находит — закрывает их fail с gap=`orphaned` и ссылкой на новую запись.
