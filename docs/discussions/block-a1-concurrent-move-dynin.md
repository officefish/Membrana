По решениям:

**(1) Комментарий над типом (53–62).** Не переписывать сказанное, дописать одним абзацем ниже существующего:

```
// tariff_moved_concurrently — из того же рода: субъект не домен,
// а состояние базы между вердиктом домена и записью сервиса.
// Домен о параллельной смене не знает и знать не должен;
// поэтому причина живёт здесь, а не в TransitionDenyReason.
```

Ключевое слово — «того же рода»: связывает четвёртую причину с тремя предыдущими явным предикатом принадлежности, а не соседством в union.

**(2) Ужесточение существующего зуба (service.test.ts:107).** Ничего не удалять; добавить строку после проверки `out.ok===false`:

```ts
expect(out.ok).toBe(false);
if (!out.ok) expect(out.reason).toBe('tariff_moved_concurrently');
expect(journal).toHaveLength(0); // как было
```

`if (!out.ok)` — narrowing для типа, без него `reason` может быть недоступен. Старые проверки сохранены дословно.

**(3) Второй зуб на `same_tariff`.** Да, нужен, и живёт **в зубах сервиса**, не домена. Причина: `same_tariff` формально принадлежит `TransitionDenyReason` (домен), но подмена рода произошла именно в сервисе — значит проверять «`same_tariff` возвращается только когда цель = текущий тариф» надо там, где случилась ошибка. Один короткий кейс: вход с `targetTariff === currentTariff`, ожидание `reason === 'same_tariff'`, без ConcurrentTariffMove на стенде.

**(4) Риск, невидимый плану.** Один. `TransitionOutcome` — union, и его потребители (если есть `switch(reason)` где-то выше по стеку) молча получат новый литерал. Проверяемо: `grep -r "same_tariff\|promo_unknown\|membrane_unknown\|grid_unavailable"` по пакету перед PR. Если есть исчерпывающий `switch` без `default: never` — TypeScript промолчит, а ветка `tariff_moved_concurrently` уйдёт в дыру. Ложный минус тут стоит дороже ложного плюса: пользователь увидит пустой ответ вместо причины.
