## 2026-08-04 16:22 UTC · tarasov

**Вопрос:** Ты резчик. Спринт deploy-procedures — вторая важная задача дня по слову владельца: «Деплой как процедура с прогонами. У нас два сервера — значит и процедуры будет две. Пока две. Некоторые деплои со временем ещё конкретизируем».

**Ответ:**

Положение: слово владельца даёт ровно две процедуры — два сервера, никакой абстракции «деплой вообще». Спринт deploy-procedures принимаю как вторую важную задачу дня.

Решение: связка — «Веснин (границы процедур) + секретарь (протокол прогонов) + ты (приём)». Расклад по порядку:
1. Фиксируем две процедуры как конкретные ритуалы: одна для prod-ритмов (morning-care, review, standup), вторая для экспериментов (opencode:task, analyzers:research). Это зеркалит устоявшееся разделение потоков из прошлых сеансов — не выдумываем третью.
2. Каждая процедура — чек-лист с прогоном; красный прогон блокирует деплой, без утешений.
3. CI гоняет процедуры ежедневно, а не к событию — иначе это церемония.

Вопрос один: что считается «прогоном» для второй процедуры — фактический запуск opencode-задачи или только сухой прогон чек-листа? Ответ нужен до назначения задач в спринте.
