**Ответы по четырём развилкам #1809:**

1. **Что сверять.** Трёхслойная мерка, все три обязательны:
   - `count(*)` по каждой коллекции — ловит потерю коллекции целиком, дёшево.
   - **SHA256 отсортированного дампа коллекции** (по `_id`) — ловит частичную порчу без выборочности. Это уже подготовлено в политике (`SHA256_SUBJECTS`), нужно расширить на per-collection.
   - Инварианты бизнес-схемы из `INVENTORY_SOURCES` (счётчики ключевых сущностей: sent-log, procedures, bridge-ledger).
   
   Выборка контрольных сумм — отклоняю: даёт вероятностную гарантию там, где детерминированная исполнима. Полное сравнение коллекций как отдельный шаг — избыточно, SHA его поглощает.

2. **Где поднимать.** Изолированность доказывается **отдельным `MONGO_URI` и отдельным томом Docker** — не сетевой изоляцией. Поднимаем `mongo:7` в compose-профиле `restore-drill` с томом `archivarius-restore-data` (не `archivarius-data`), портом `27018`. Доказательство изоляции — предикат: `docker volume ls` показывает разные тома, `MONGO_URI` прогона ≠ прод-URI. Одной машины достаточно.

3. **Как часто.** **Каждый дамп** — иначе теряется смысл слова «бэкап» (мой же тезис 08.08). Дешёвая автоматика: `backup:dump` завершается вызовом `backup:restore-drill`, оба глагола в одной цепочке. Реже — только если p95 прогона > 10 мин; тогда развилка на отдельный эпик.

4. **Что делает провал.** Красный идёт в **три канала одновременно**: (а) exit code ≠ 0 у `backup:restore-drill` — блокирует последующий `task:archive`; (б) запись в `docs/bridge/debt-ledger.jsonl` как `birth` с id `archivarius-restore-failed-<date>`; (в) ласточка в Telegram через office. Молчание в логах — не сигнал.
