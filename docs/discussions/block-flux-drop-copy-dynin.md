По делу, коротко:

1) **Да, это признак.** Если из общего носителя ровно один потребитель берёт «половину» (обход без сводов), шов проведён по удобству реализации, а не по природе данных. Правильный шов: `frameIterator(window)` — базовая операция, `aggregate*(frames)` — производные над ней. Сейчас у нас, судя по описанию, `fftFrames` совмещает роль источника и роль «уже посчитано». Flux — честный индикатор кривизны шва: он не может пользоваться сводами по определению (Δ между соседями), и именно поэтому обнажает шов.

2) **Риск реален и именно тихий.** Инвариант, который сейчас нигде не зафиксирован: `frames[i]` и `frames[i+1]` — соседние окна одной сессии, без дополнений, без re-windowing, без внутреннего padding хвоста. Любое «безобидное» изменение в `detector-base` (zero-pad последнего кадра, повтор хвоста, ресемпл, окно Ханна вместо прямоугольного) сломает **только flux**, и сломает без падения — просто сдвинет распределение Δ. Harmonic/template этого не заметят, потому что усредняют.

3) Пакету после удаления копии не хватает трёх вещей:
