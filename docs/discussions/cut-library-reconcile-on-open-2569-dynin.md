**Вопрос:** Ты резчик этого спринта. Проверь корень по замерам, годится ли механика и нарезка на 2 блока как контракт, честны ли зубы P1-P3 и чего им не хватает, какие BLOCK-условия для b1 и b2, и что по каждой из 5 развилок ты рекомендуешь владельцу. Кратко, по пунктам.

**Ответ:**

**Корень по замерам.** Диагноз сходится: `refresh()` безусловно тянет `listSamples` по всем коллекциям (209 GET на буфер) — это O(N_samples), а не O(N_collections). Умолчание механики переводит open-path в O(1) по буферу и O(N_system)=~3 GET только при расхождении. Арифметически обоснованно.

**Контракт нарезки.** 2 блока как контракт — годится при условии, что b2 — это **предикат приёмки**, а не «посмотреть глазами». Нужен сценарий владельца: (a) открыть библиотеку без смены тарифа — 0 `listSamples`; (b) сервер переименовал — после open имя обновилось; (c) смена тарифа free→paid — буфер **не** перечитан, системный — перечитан. Без явного сценария b2 деградирует до LGTM.

**Зубы P1–P3 — что честно, чего нет.**
- P1 (listSamples=0 после open) — честный, но слабый: не ловит «лёгкая сверка не прошла». Добавить P1': `ensureReserved=1 ∧ listCollections=1 ∧ getQuota=1` и P1'': параллельные `reconcileOnOpen()` → один сетевой залп (дедуп промиса).
- P2 (имя после open) — честный; добавить P2': `sampleCount` системного набора обновился после фонового provision (расхождение → досев).
- P3 (`dataset.catalogId` в quota) — честный на уровне поля; добавить P3': смена `catalogId` между вызовами → триггерит перечитывание системного набора; P3'': **буфер не перечитывается никогда** (явный counter-зуб: `listSamples(bufferId)` call count = 0 при смене каталога).
- Чего не хватает в целом: зуба на StrictMode double-mount (ожидание: 1 сетевой залп, не 2) и зуба на 5 панелей-потребителей `useMediaLibrary` (ожидание: сверка не триггерится из хука).

**BLOCK для b1:** любой из — (i) `listSamples` буфера вызван на open-path; (ii) нет дедупа параллельных `reconcileOnOpen`; (iii) сверка вызвана из `useMediaLibrary` вместо модуля/кабинета; (iv) запомненный `catalogId` вынесен из памяти сервиса на диск; (v) зубы P1–P3 + добавленные выше не красные до патча.

**BLOCK для b2:** нет письменного сценария владельца с тремя кейсами выше; приёмка без фиксации сетевых счётчиков в devtools/HAR.

**Развилки — рекомендации.**
1. **Лёгкая сверка всегда, глубокая по смене каталога ИЛИ по расхождению sampleCount системного набора.** Строгий вариант не чинит случай 03.10 — отклоняю.
2. **По `catalogId` из `/quota`.** `tariffId` сопряжения — другой слой; `catalogId` — то, что media уже отдаёт и чем оперирует сервер. Один источник истины (ср. tariff-single-truth: версия контракта там, где её выдаёт сервер).
3. **ensure + listCollections (2 запроса, порт не трогаем).** Экономия 1 запроса не стоит мутации `IStorageBackend` в спешке; порт — контракт, его меняем отдельным PR с собственным ревью.
4. **Кабинет в этом же спринте.** Иначе P2/P3 на кабинете останутся красными и контракт нарезки неполный; стоимость — тот же `reconcileOnOpen()` в `useCabinetSampleLibrary`.
5. **Поле `dataset` из #2563 в этот спринт — как зависимость, не как часть b1.** Без него P3 недоказуем. Либо #2563 сливается первым, либо b1 временно читает `catalogId` через расширение ответа `/quota` под фичефлагом с удалением после #2563.
