**(1) Формы токенов — где надёжно, где пересекается.**
- `pr`: `#\d{3,}` — надёжно, дизъюнктно.
- `path`: содержит `/` и матчит `^(scripts|packages|apps|docs)/…\.(mjs|ts|tsx|md|json)$` — надёжно.
- `verb`: начинается с `yarn ` (или `npm run `) — надёжно.
- `doc`: ALLCAPS с `_` или расширение `.md` без `/` — почти надёжно (пересечение с `symbol` при ALLCAPS-константах: `PROMO_REVOKED`). Резолвится по факту: если есть `docs/**/<TOKEN>.md` — `doc`, иначе кандидат в `symbol`.
- `card`: `kebab-case` без `/` и без расширения (`morning-gates-two-moments`) — пересекается со строковыми литералами и slug'ами. **Неустранимо** без реестра карточек: класс валиден только если токен есть в `docs/tasks/**` или Linear-реестре; иначе — `opaque`.
- `symbol`: `camelCase`/`PascalCase` идентификатор — пересекается с ALLCAPS-константами и с именами файлов без расширения. **Неустранимо** на форме; разводится фактом (наличие декларации).
- `opaque`: строковые константы (`promo_revoked`), snake_case — сдаёмся честно.

Правило: **токен несёт множество классов-кандидатов**; verdict проверяет каждый; любой `holds` побеждает.

**(2) Что считать телом утверждения.**
- Парсер markdown → блочная модель. **Исключаются**: fenced code (```` ``` ````), inline code внутри code fence, таблицы целиком (строки, начинающиеся с `|`), YAML-frontmatter, цитаты (`>` — это чужой голос).
- **Включаются**: параграфы, списки, заголовки. Внутри — inline code (` `` `) — это и есть носитель утверждения (символы, пути, PR).
- Токен = содержимое одиночного backtick-span в разрешённом блоке. Голый текст без backtick — не токен (снижает шум).

**(3) Форма факта — тотальность без исключений.**
```
Facts = {
  fs:     { exists: (path) => bool | null, grep: (needle) => Hit[] | null },
  symbol: { decls: (name) => Loc[] | null, refs: (name) => Loc[] | null },
  pr:     { files: (num) => string[] | null, mergedAt: (num) => ts | null },
  cards:  { status: (slug) => 'active'|'done'|null }
}
```
`null` = «узнать не удалось» (нет сети, нет `gh`, парсер упал). Тогда verdict → `unknown` с причиной `facts.<probe>=null`. Никаких throw: обвязка ловит и подставляет `null` **до** ядра.

**(4) Где решается soft/hard.**
Внутри `verdict` таблицей:
- `hard`: класс однозначно опознан **и** факт однозначно опровергает (символа нет в дереве при 0 деклараций; PR не содержит `apps/**` при утверждении о клиентской части). Требование: **ровно один** класс-кандидат прошёл дальше формы, и его probe вернул `false` (не `null`).
- `soft`: класс опознан, но опровержение косвенное (карточка `active` при влитом PR — «реестр протух»); либо несколько классов дали `false`, ни один — `holds`.
- Защита от шума soft: **soft не блокирует ласточку**, копится в секцию «сомнения»; порог перехода soft→hard — только явным правилом класса, не суммой.

**(5) Обязательные зубы (regression corpus).**
- `PromoDeclineReason` в inline code → `symbol`, `symbol.decls=[]` → **hard**.
- `#1776` рядом со словом «клиент/UI/apps» → `pr`, `pr.files ∩ apps/** = ∅` → **hard**.
- `morning-gates-two-moments` в «предложение на завтра» + `cards.status='active'` + PR влит → **soft** (находка «реестр протух»), не hard.
- ALLCAPS-документ `MAIN_DAY_ISSUE` без расширения — `doc` при наличии `docs/**/MAIN_DAY_ISSUE.md`; иначе `opaque`, не `symbol`.
- Токен из fenced code (` ``` js … ``` `) — **игнор**, не токен (защита от 03.08: не проверять по неверному адресу).
- Токен в цитате `>` — **игнор** (чужой голос).
- Все пять протоколов 03.08–07.08 → ноль hard кроме двух вшитых вещдоков 07.08.

Вход ядра `atoms(md) → Atom[]`, `Atom = { token, classes: Class[], span: {line, col}, block: 'para'|'list'|'heading' }`. Вход `verdict(atom, facts) → { outcome: 'holds'|'hard'|'soft'|'unknown', addr: string, reason: string }` — `addr` обязателен, чтобы «перепроверить руками» из DoD выполнялось буквально.
