Ответь по пунктам, коротко, с предикатами.

**Ответ:**

По пунктам, коротко.

**(1) Предикаты и порча.** Зуб: `red ⇔ G ≠ proj(R) ∨ ¬form(G)`. Детерминизм генерации обеспечивается: сортировка ключей по каноническому порядку (sku asc, cell asc), отсутствие `generatedAt` в теле, версия релиза в шапке — она же есть в `proj(R)`, поэтому ручная правка версии в сетке даст расхождение с R. Порча демонстрируется: генерируем, зелёный; правим руками, красный (G≠proj(R)); регенерируем, зелёный. Один носитель предиката — `proj(R)` в коде зуба, а не в скрипте генерации (иначе два источника правды).

**(2) `//provisional`.** Генерировать из паспорта: `provisional ⇔ passport.status ≠ ratified`. Если поле не нужно — снять совсем, но тогда теряется маркер «не закреплено» для зуба. Оставляю: паспорт — единственный источник, сетка — производная.

**(3) Проекция T1.** В паспорте гранулы поле `ratifiedAt: string | null`; `null` → «не закреплено». Зуб: `legal(value, granule) ⇔ value = granule.values[tariff]` — он судит соответствие, а не легитимность числа. Для cold 0/2048/2048: в грануле `values` — как в релизе, `ratifiedAt: null`, комментарий «не решено заседанием». Зуб не краснеет: G=R, форма верна.

**(4) scalarsCrossFindings.** Оставить как есть внутри печатного списка — он сверяет то, что сверял; расширение на буфер и каталог добавит шум без пользы (S — замороженная эпоха). Важно: список печатается, но не красит. Не трогаем.

**(5) Порядок.** Верен: форма → G↔R (red) → S↔R (print). Форма дешевле, отсекает мусор до сравнения; G↔R — единственный красный; S↔R — информация к размышлению, не гейт.

Что НЕ сказано: зуб не проверяет, что значения `proj(R)` осмысленны — он лишь зеркалит релиз. Осмысленность — ответственность гранулы и паспорта.
