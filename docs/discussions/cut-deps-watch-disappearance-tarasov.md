**Недостаточно:** вы забыли **четвёртый блок — валидация ядра перед вызовом из обоих режимов**.

Ядро вернёт `{fresh: [], gone: []}` если аудит пуст. Это тот случай, когда сравнение **НЕ ДОЛЖНО производиться вовсе**. Логика проверки "пуста ли сводка" должна быть **перед** вызовом `deps-watch-diff()`, иначе:
- Утренний режим скажет "ничего не исчезло" вместо "аудит не отработал".
- Вечерний режим будет молча сравнивать пустоту с прежним.

## 3) Главный риск — утренний режим и `exit 0`

**Проблема:** утренний режим стоит в `ritual:day`, и вы напрямую обращались к FS для перезаписи снимка. Есть три места, где случайное исключение обрушит ритуал:

1. **`validateAuditSnapshot()`** — аудит пуст, снимок не может быть прочитан, или JSON повреждён.
   - **Зубой:** вернуть `{ isValid: false, reason: "…" }` вместо `throw`.
   - **В утреннем режиме:** если `!isValid` → print reason, `exit 0`, **не трогать файл**.

2. **`compareBeforeOverwrite()`** — чтение старого снимка для сравнения.
   - **Зубой:** если старого нет → first run, `gone = []`, перезаписать без сравнения.
   - **Если старый повреждён** → "восстановить сравнение не удалось", print, `exit 0`, оставить старый.

3. **FS операции (readFile, writeFile)**.
   - **Обе** обёрнуты в `try-catch` с явным return и exitCode 0.

**Контрольная строка в test:**
```js
it('morning mode always exits 0, even if validation fails', async () => {
  // аудит пуст → validateAuditSnapshot returns isValid: false
  // утренний режим печатает причину, НЕ перезаписывает снимок, exit 0
});
```
