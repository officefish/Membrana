## Разбор Веснина — архитектура и границы измерителя

1. **Измеритель судит пакетом, а не своей копией счёта.** `runMfcc` зовёт `evaluatePipe` из
   `packages/services/mfcc-analyzer/dist` (динамический импорт по `pathToFileURL`, `ensureBuilt`
   сторожит сборку) и считает `meyda` собственным экземпляром настроек. Урок 31.07 («прибор судил
   собственной копией — мерил себя») соблюдён. ✓
2. **Один источник ворот.** Пресет читается из `data/detectors-benchmark/v0.2/reports/mfcc-gates-first-cut.json`
   (ключ `preset`), клиентский `presets.ts` объявлен копией для сборки. `mfccPresetProblem` проверяет
   длину коридоров против числа коэффициентов **из отпечатка** (`-sr` обязателен) — пресет под чужую
   сетку не доедет до судьи. ✓
3. **Самозамер назван, а не спрятан.** Ворота сняты на v0.2, прогон по умолчанию идёт по v0.2 —
   `mfccSelfMeasurement` кладёт в паспорт `self: true` с причиной; цифра читается как верхняя оценка.
   Это правильная форма: измеритель не может снять самозамер, но обязан его назвать. ✓
4. **P2 инструмента про `evaluatePipe([])` — проверено, поведение определено.** `judgeRun` →
   `corpusProblem([])` → отказ «корпус пуст: судить нечем» → `runMfcc` бросает «`<id>`: судья отказал —
   корпус пуст». Запись короче кадра роняет прогон **именованно**, а не даёт `predDrone:false`.
   Для измерителя это верно: корпус обязан быть однородным, молчаливый пропуск записи исказил бы
   знаменатель метрик. Не дефект; можно закрыть зубом `runMfcc` на записи < `bufferSize` (P3).
5. **Граница, которую стоит назвать вслух:** измеритель и плагин `membrana.handler.mfcc` судят
   одним судьёй и одним пресетом, но **по-разному относятся к отказу**: измеритель роняет весь прогон
   (однородный корпус), плагин пишет `outcome: 'refused'` по пробе (живая коллекция неоднородна по
   определению). Обе формы честные; расхождение — свойство предмета, не ошибка. Зафиксировано здесь,
   чтобы следующий читатель не «унифицировал» их в одну.
6. **Oversized (+625).** Связный новый модуль + зубы; дробление «lib / CLI / зубы» было возможно
   (три PR по ~200) и было бы лучше для ревью. На будущее — норма, не переделка.
