## 2026-08-06 13:02 UTC · vesnin

**Вопрос:** Ты держатель обеих процедур разворачивания (leadPersona `deploy-office-vds` и `deploy-media-vps`, ADR-0023) и контракта процедур. Нужно ОДНО решение: какой `procedureKind` у процедур деплоя.

ПОЛОЖЕНИЕ (проверено кодом): PR #1613 вводит обязательное поле `procedureKind` с закрытым списком {разработка, решение, ритм} (ADR-0021). После вливания генератор проекции реестра ОТКАЗЫВАЕТ машинно: «deploy-media-vps: procedureKind ∉ {разработка, решение, ритм}». Обе процедуры деплоя заведены 04.08, уже после написания PR, поэтому рода не имеют.

КАК РАСПРЕДЕЛЕНЫ ОСТАЛЬНЫЕ 24 (факт реестра):
- ритм (12): ritual-evening, ritual-day, ritual-dreams, attribution, test-runs, ship-gate, tasks-audit, git-audit, code-review, bridge, membrana-leveling, weekly-dead-wire
- решение (4): meeting, storm, consilium, adr
- разработка (8): day-sprint, membrana-local-sprint, hackathon, containerization, cowork, competition, night-sprint, one-shot

ЧТО ЕСТЬ ДЕПЛОЙ ПО ФАКТУ МАНИФЕСТА: кадры build → rollout (гейт owner-rollout, владелец сам запускает напечатанную команду) → smoke → record; trigger kind captain-word (`yarn vds:run` / `yarn cabinet:deploy:prod`); прогон пишется в общую ленту журнала; сервис — параметр прогона.

ВОПРОС: какой род и почему? Три кандидата с ценой каждого: (а) `разработка` — деплой есть работа над изделием, но интерфейс рода «разработка» по EXECUTION_PROCEDURE требует полного route-контракта, которого у деплоя нет; (б) `ритм` — рядом стоят ship-gate и test-runs, тоже про доставку и проверку, но деплой не регулярен по расписанию, он по слову владельца; (в) `решение` — очевидно нет. Ответь одним словом-родом и одной фразой обоснования; если выбор ломает интерфейс рода — скажи прямо.

**Ответ:**

**ритм** — деплой по слову владельца, без route-контракта разработки, живёт в одной шкатулке с ship-gate и test-runs (гейт → прогон → запись в общую ленту); нерегулярность расписания интерфейс рода «ритм» не ломает — триггер captain-word там уже легитимен (ср. bridge, membrana-leveling).

Цена: если позже у деплоя вырастет route-контракт (планирование → билд → раскатка → откат как отдельные этапы с owner-ами), придётся переводить в `разработка`. Пока кадров четыре и владелец сам жмёт кнопку — это ритм доставки, не разработка.
