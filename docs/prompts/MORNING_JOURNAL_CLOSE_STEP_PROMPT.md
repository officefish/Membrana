# Промпт: шаг закрытия журнала у утра — статус по факту, а не константой

> **Task-промпт.** Размер: **M**. Ведёт Ozhegov, поддержка Vesnin.
> Процедура: [`membrana-local-sprint`](../procedures/membrana-local-sprint/README.md).
> **GitHub Issue:** [#1782](https://github.com/officefish/Membrana/issues/1782)

## ⛔ Зависимость: НЕ начинать, пока у фреймов утра нет держателя

Заблокирована цепочкой `frame-holder-moderator-split`
([#1781](https://github.com/officefish/Membrana/issues/1781)) →
`frame-holders-reassign-twenty` ([#1787](https://github.com/officefish/Membrana/issues/1787)).

Так велит [ADR-0025](../adr/ADR-0025-frame-holder-and-moderator-two-roles.md) в разделе
«Out of scope»: шаг `journal-close` заводится **после** появления держателя у фреймов утра,
«иначе у нового шага не будет исполнителя ровно так же, как нет его сейчас».

Проверить готовность входа: фреймы `ritual-day` в `docs/procedures/ritual-day/MANIFEST.json`
несут `holder` из разработчиков, а не модератора.

## Предмет — двойной дефект, проверен 08.08 своим прогоном

**Хвост цепочки `ritual:day` в `package.json`:**

```
… && node scripts/procedure-run-record.mjs close --procedure ritual-day --status pass …
```

1. **Закрытия может не быть вовсе.** Это последнее звено `&&`-цепочки: любой обрыв раньше —
   и записи не появится. Вещдок: прогон утра 07.08 остался без закрывающей записи
   (`docs/procedure-runs/trail/2026-08-07.jsonl`, `ritual-day-2026-08-07-r2` — только `open`).
2. **Если закрытие случилось — оно всегда рапортует `pass`.** Статус зашит константой,
   то есть журнал утра не способен сказать «прогон был неполным».

## Образец рядом: вечер это место уже починил

`scripts/ritual-evening-run.mjs:178-179`:

```js
// Статус close — ПО ФАКТУ прогона; gaps называют упавшие критичные шаги.
const closeStatus = failed.length > 0 ? 'fail' : 'pass';
```

Утро обязано получить то же свойство: статус вычисляется, разрывы называются. Смотреть туда,
а не изобретать заново — обзор «что уже есть» (норма #1573) здесь даёт готовую форму.

## Границы

**В предмете:** шаг закрытия в манифесте утра, вычисление статуса по факту, называние
разрывов, гарантия выполнения при обрыве цепочки.

**Вне предмета:** **два раннера утра** — цепочка `ritual:day` (17 звеньев, пишет журнал) и
`scripts/morning-ritual-run.mjs` (12 шагов по манифесту, журнала не касается) описывают одно
утро по-разному и друг о друге не знают. ADR выносит это отдельным предметом; в этот спринт
не втягивать.

## Заметки постановщику

- После merge: отчёт в Issue → `yarn task:archive morning-journal-close-step --notes "…"`.
- Проверка: прогон утра с намеренным обрывом даёт закрывающую запись со статусом `fail`
  и названными разрывами, а не отсутствие записи и не `pass`.
