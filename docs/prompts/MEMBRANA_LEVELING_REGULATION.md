## 1. Что это (T1–T5, R2)

`membrana-leveling` — **зонтичная процедура детерминированного выравнивания общего рабочего
пространства к `main`**. Объект — проект как целое (не «своё/чужое»: одно пространство, ось —
**состояние**, R2). Главная цель: **`main` актуален** — всё **готовое**, что «не доехало»,
оказывается в `main` (T4). Конечное состояние — точка, удобная для продолжения общей работы (T5).
Центр тяжести — **вечер**, и **обе половины обязательны**: обнаружить мусор/незавершёнку И долить
готовое в `main` — не или-или (T10).

Два скрипта по очереди (T2): **`main-fill`** (ветки → `main`, сериализованный `pr:ship`-поезд,
T9/#700) → **`workspace-level`** (`main` → деревья + гигиена). Процедура — **во фреймах** (T12),
не скрипт-монолит.

## 2. Гранула `disposition` (вердикт M1 / K1)

Ядро процедуры — чистая функция состояния файла/работы:

```
disposition(path, ctx) → live | ready | unfinished | trash
порядок ветвлений (first-match):
  1. isTempOrScratch(path)                 → trash  (по расположению)
  2. dirty ∧ inActiveSession               → live
  3. ready-предикат (см. таблицу)          → ready
  4. registered ∧ ¬(1–3)                   → unfinished
  5. dirty ∧ ¬registered ∧ ¬(1–2)          → trash  (fallback: несохранённый хлам, не в работе)
```

> **Исправление порядка (post-ратификация, багфикс, честит замысел R2).** Первоначальная запись
> вердикта M1 ставила `trash = … ∨ (dirty ∧ ¬registered)` **первым** ветвлением — это ловило
> активную незарегистрированную правку как мусор, и гейт снёс бы живую работу. `live` обязан идти
> ДО клаузы `dirty ∧ ¬registered`; последняя — только **fallback** (шаг 5). Замысел R2 (live
> пропускается) сохранён, поправлен лишь порядок выражения.

| Состояние | Предикат | Действие гейта |
|-----------|----------|----------------|
| `trash` (по расположению) | `isTempOrScratch(path)` — шаг 1 | убрать/назвать поимённо; **останавливает** гейт (T11, R2) |
| `live` | `dirty ∧ inActiveSession` (session-lock, **не** голый mtime) — шаг 2 | пропустить, не везти (R2) |
| `ready` | `registered ∧ CI_green ∧ ¬conflicts(main) ∧ PR_approved ∧ leadStamp ∧ ¬inActiveSession` (T8) — шаг 3 | в очередь `main-fill` |
| `unfinished` | `registered ∧ ¬(шаги 1–3)` — шаг 4 | регистрировать (T7); включает «ждёт штампа» |
| `trash` (fallback) | `dirty ∧ ¬registered ∧ ¬(шаги 1–2)` — шаг 5 | несохранённый хлам не в активной работе; убрать/назвать |

**Граница детерминизм ↔ штамп (T8):** детерминированы факты (`dirty`, `registered`, `CI`,
`conflicts`, `PR_approved`, `path`-паттерн, **наличие** `leadStamp` в ctx). Не детерминированы
функцией: **решение** зарегистрировать path и **выставить** штамп — человек/тимлид. После записи
в ctx — снова детерминизм. `readyFacts` без штампа → `unfinished`, **не** `ready`.

## 3. Гейт «не уснуть над мусором» (вердикт M2 / K4)

Гейт — **оркестратор вечера** над снимком `{path, disposition}[]`; не классификатор, не пересчёт K1.

```
1. снять dirty-paths снимка
2. для каждого: d = disposition(path, ctx)
3. корзины L, R, U, T
4. L: no-op
5. T: акт именования (path + утилизация/ignore-with-reason); неполный → STOP (unnamed-trash)
6. U: карточка реестра по мин. контракту; иначе → STOP (unregistered-unfinished)
7. R: main-fill; провал → STOP (main-fill-failed); R=∅ → noop
8. нет STOP → PASS
9. выход: {status, reason[], baskets, mainFill ∈ done|noop|failed|pending}
```

**Условие прохождения (обе половины T10, конъюнкция):**
`PASS = Named(T) ∧ Registered(U) ∧ Filled(R)`.
Только уборка без `main-fill` — **не прошёл** (готовое застряло). Только `main-fill` без
обнаружения — **не прошёл** (неназванный мусор копится под коммитами).

**Минимальный контракт карточки `unfinished` (T7, К-Фаррелл):** (1) id/ссылка на path; (2) `state=unfinished`;
(3) why-not-ready; (4) next-action или owner/persona; (5) привязка к снимку/дате гейта.
**WIP-коммит регистрацию НЕ заменяет** — коммит-и-забыл = обман гейта.

**Триггер:** вечерний ритм (К-Kuryokhin). Голова-гейт (маршрутизация состояний) важнее
хвоста-сантехники (как именно лить).

## 4. Манифест-отчёт `workspace-level` (вердикт M3 / K2)

**Детерминированный view над persisted-выходом гейта** (`buildWorkspaceLevelReport`), не вычислитель.
Канон = gate-output; отчёт — представление (не два источника истины).

Три раздела (поимённо, не счётчиком — К-Rodchenko):

1. **Влито в `main`** — path из `R` с `mainFill=done`.
2. **Застряло** — `R` с `mainFill=failed|pending` ∪ `U` (+ stop-reason у каждого).
3. **Мусор найден** — path из `T`, названо.

Шапка: `status`, `reason[]`, указатель на gate-артефакт, время сборки; пустой раздел → явное «(пусто)».
Корзина `L` — справочный факт в мете, **не** четвёртый раздел и не «влито». **Факт** в теле
(path, basket, mainFill, status, reason); **суждение** — только опциональный хвост «Вопросы владельцу»
(указатели, не предписания). **Счётчики запрещены** как единственный слой — прячут имена.

**Носитель:** вечерний артефакт `workspace-level`; шов к [`HANDOFF.md`](../HANDOFF.md) / вечернему
ритуалу — ссылкой (канон HANDOFF не переписывается). **Переживание обрыва:** `report = f(persisted
gate-output)`; без входа отчёт не выдумывается («нет входа»), сборка из чата запрещена.

## 5. Фрейм-рельсы (вердикт M4 / K3, по паттерну [`PROCEDURE_FRAMES`](../patterns/PROCEDURE_FRAMES.md) #1094)

Шесть фреймов: серия **сюжетных** (основная линия) + три **служебных** (провода/времянки/доставка).

| Фрейм | Тег | Holder | Полоса | Что несёт |
|-------|-----|--------|--------|-----------|
| `leveling-wires` | служебный · провода | Vesnin | `preflight` | входы: `disposition` (K1), снимок dirty, LLM-канал; SoT не здесь — только доставляет |
| `leveling-gate` | сюжетный | Vesnin | `preflight` | голова-гейт (K4): решение по disposition; без PASS полоса `frames` не открывается |
| `leveling-main-fill` | сюжетный | Vesnin | `frames` | `ready` → `main` (T9/#700-поезд) |
| `leveling-workspace` | сюжетный | Ozhegov | `frames` | `main` → деревья + гигиена; SoT для `isLeveled`/`legit`; материал отчёта K2 |
| `leveling-scratch` | служебный · времянки | Dynin | `frames` | T13: времянки в `%TEMP%`/scratchpad; cleanup; **never commit** — убивает WIP-снимок-антипаттерн |
| `leveling-deliver` | служебный · доставка | Vesnin | `post` | доставка манифест-отчёта (K2) до сервера/соседей; шов к вечернему ритуалу/`HANDOFF` |

**Порядок полос:** `preflight` (wires → gate; без PASS дальше нет) → `frames` (main-fill →
workspace; scratch параллельно, cleanup к концу полосы) → `post` (deliver).

**Риск пропуска служебного фрейма:** без `wires` — гейт на устаревших входах; без `scratch` —
возврат WIP-антипаттерна (T13 нарушен); без `deliver` — локально выровнено, но слепок соседям не доехал.
