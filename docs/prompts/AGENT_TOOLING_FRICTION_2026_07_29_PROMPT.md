### Что построить (продуктовое описание)

Четыре независимые фазы, **каждая отдельным PR, внедрять по одному**. Порядок обязателен:
Ф1 дешёвая и снимает диагноз той боли, чья причина — Ф4; Ф4 последней, потому что упирается
в решение владельца.

**Ф1 · Зуб воркспейс-резолва** (XS, скрипт)

Боль: `TS2307 Cannot find module '@membrana/rag-service'` указывает на файл-потребитель, а причина —
«симлинк ведёт в дерево, где нет `dist`». Диагноз 29.07 занял несколько заходов: пришлось прятать
правки в stash и гонять базовую линию, чтобы доказать непричастность своих изменений. `turbo` не
помогает — отдаёт `cache hit` и собирает копию в своём дереве, тогда как ссылка ведёт в главное.

Проверено, что инструмента нет: `deps:watch` — про другое; `membrana-tooling-doctor` закрывает
stale-dist через `build:affected`, но случай «ссылка наружу + там пусто» не ловит.

Делать: пройти `node_modules/@membrana/*`; для каждой ссылки сказать, куда она ведёт и есть ли по
тому пути `dist`/`types` из её `package.json`. Красное = причина одной строкой. Read-only, без починки.

**Ф2 · `pr:ship --with-review`** (S, фикс)

Боль: последовательность `pr:ship` → гейт «ревью не найдено» → `code-review:pr N` →
`pr:ship --merge-only` повторена за одну сессию **дважды** знак в знак (PR #1461, #1464).
В `scripts/pr-ship.mjs` на этот случай только текст-подсказка.

Делать: флаг, который при исходе гейта «ревью не найдено» зовёт `code-review:pr <N>` и продолжает
хвост. При **BLOCK** — стоп, как сейчас. Owner-гейт не ослабляется: вердикт по-прежнему выносит
ревьюер, флаг лишь убирает ручную пересадку между шагами.

**Ф3 · Грабли в `AGENTS.md`** (XS, норма) — долг, а не предложение

Скилл обязывает обновлять раздел граблей, когда снята ложная находка (#554 TF-7). За сессию 29.07:

- **снята ложная находка:** `deepseek.service` числился в README контейнера третьим случаем грабли
  с голым `fetch`; на деле прямой путь ратифицирован ADR-0007 (в доке контейнера поправлено, в
  `AGENTS.md` — нет). Без этой строки следующий агент «починит» несуществующее;
- `node --test <каталог>` на Windows даёт `pass 0, fail 1` — выглядит как падение своего теста;
  лечится перечислением файлов явно;
- словари kind ветки (`layer-rules.json`) и conventional-типа коммита разные **намеренно**:
  kind описывает характер работы (`meeting`, `storm`, `night`, `sprint`), тип коммита — стандарт;
- две починки 29.07: самоссылка `review/teamlead` в ci-wait, ранний гейт типа в `pr:ship`.

Только грабли, не инвентарь: список команд генерируется `yarn tooling:overview`, руками не ведём.

**Ф4 · `worktree:bootstrap` против канона** (S, фикс + норма) — **требует решения владельца**

Расхождение: [`AGENTS.md:83`](../../AGENTS.md) — «Sibling worktree: junction shared `node_modules` —
**Anti-pattern (#725)**: ломает Nest11/express resolve. Канон — per-wt `yarn install` + копия `.env`.
**Не заводить новый bootstrap с junction**». При этом `scripts/worktree-bootstrap.mjs` делает ровно
junction (`mklink /J`), про #725 не знает и пишет в карточку `WORKTREE.md` константой
`| install | свой |` — то есть утверждает канонное состояние, которого не создавал.

Эпизод: дерево `Membrana-tooling` живёт на junction. Отсюда 29.07 — пять падавших e2e и красный
typecheck на резолве `@membrana/rag-service`; чинилось руками сборкой rag в главном дереве. Туда же
`yarn` в этом дереве с `esbuild postinstall: Manifest not found`.

**Развилка — не решать агенту.** Либо умолчание `bootstrap` → `yarn install`, а junction только
явным `--junction` с громким предупреждением; либо снять запрет из канона, раз junction де-факто
рабочий. Полный install × 8 живых деревьев — это диск и минуты на каждое. Агент готовит развилку
(ADR по `membrana-adr`), решение принимает владелец; после решения — согласовать инструмент и канон,
чтобы они не противоречили друг другу.

1. **Teamlead** — держит порядок фаз и не пускает Ф4 вперёд решения владельца.

3. **Математик** — предикаты Ф1 (ссылка × наличие dist × отсутствие node_modules) и Ф2 (найдено / не найдено / BLOCK).
