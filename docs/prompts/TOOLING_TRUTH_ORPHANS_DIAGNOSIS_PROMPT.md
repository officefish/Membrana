## Контекст

Два прибора проекта говорят о себе то, чего не замеряли, и оба замера сделаны, а не предположены.

**Первый — `yarn scripts:orphans`.** Он печатает предупреждение «правил членства ноль —
сиротство ниже означает „правила ещё нет“, а не „место потеряно“» и выводит его из посылки
`registry.namespaces.length === 0`, то есть из состояния реестра, а не из причин, по которым
носители на самом деле оказались сиротами. Прогон 02.08 на `9dc167d0`: **51 сирота из 1000, у
всех до единой `reason = subject_unresolved`, по ветке `no_rule` — ноль**. Посылка верна
(неймспейсов действительно ноль), вывод из неё ложен: читатель идёт чинить правило членства,
тогда как чинить надо резолвер предмета `subjectOf`.

**Механизма писать не надо — он уже есть.** Предикат `belongs()` возвращает `reason` из
закрытого списка `ORPHAN_REASONS` ровно затем, чтобы «сирота» не была неотличима от «предикат
не справился». Теряется он одной строкой в `orphans()`: фильтр по `kind === 'orphan'`
выбрасывает вердикт целиком и оставляет голый путь. Задача — **донести уже существующую
причину до отчёта**, а не завести вторую диагностику (норма
[#1573](https://github.com/officefish/Membrana/issues/1573)).

**Второй — ревью.** 01.08 замерено трижды: на диффе 1524 строки из пяти блокеров четыре
оказались ложными, на 929 строках пять блокеров были настоящими, на 236 прогон прошёл начисто.
Это измеренное свойство собственного гейта, а не ощущение «ревью придирается», и оно живёт
только в протоколе вечернего фидбека 01.08. Через неделю вещдоки придётся восстанавливать по
логам — поэтому запись прецедентом входит в этот же спринт.

**Что не трогаем.** `subjectOf` и список его локусов: §2 закрывает перечень, третий локус —
вердикт владельца, а не правка кода. Красный `precedent:register --validate` на чужой записи
`2026-07-26-issue-979` (класс `task-lifecycle` вне `classes.json`) — чужая запись, не наша.
Перечень `classes.json` не расширяем: класс прецедента взят из закрытых пяти по слову
владельца 02.08 — `tooling-gap`.

### Что построить (продуктовое описание)

1. **`orphans()` перестаёт терять причину.** Результат прогона несёт не только список путей, но
   и вердикт по каждому: `{path, reason}` плюс сводка `byReason`. Форма расширяется, а не
   заменяется: `orphans[]` со строками путей остаётся — на него смотрят соседи и `--json`.
2. **Предупреждение выводится из замера.** Строка про нулевые правила членства печатается
   только тогда, когда хотя бы одна сирота действительно пришла по `no_rule`. Когда все сироты
   пришли по `subject_unresolved`, прибор говорит именно это и называет адрес починки —
   резолвер предмета, а не реестр неймспейсов.
3. **Сводка причин в отчёте.** После строки «✖ бесхозных N из M» — разбивка по причинам с
   числами, чтобы диагноз читался без `--json`.
4. **Прецедент `tooling-gap`** о пределе ревью: три замера 01.08 с числами, корень, профилактика.
