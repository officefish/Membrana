# Сессия Г — 103 ветки без копии на сервере: спасение до того, как их снесут (17.09)

**Подкрепление магистрали дня** `worktree-sanitation-day2`.
**Дерево:** своё, отдельное.

## Предмет и почему это срочно

Сухой прогон `yarn repo:clean` утром 17.09 (ствол `4542603a`) дал строку:

> `103 · нет PR и нет на origin — уникальные коммиты пропадут безвозвратно`

Это ветки, которые существуют **только на этой машине**. Ни запроса на слияние, ни копии на сервере. Пока они целы, содержимое восстановимо; после любой неосторожной уборки — нет. Инструмент их не трогает, и это правильно, но защита держится на одном его отказе.

Сегодня в соседней зоне работает сессия Б — она сносит ветки с мёртвым PR. Пересечения по списку быть не должно, но запас прочности нужен именно здесь.

## Задача

1. Получить список: ветки без соответствующей ветки на сервере. Источник истины — состояние PR, а не `git branch --merged`: слияние через squash делает его слепым.
2. По каждой ответить **замером, а не впечатлением**:
   - есть ли в ветке коммиты, которых нет в стволе (`git log origin/main..<ветка> --oneline`);
   - если есть — какие файлы они трогают и одни ли это документы;
   - не вошло ли то же содержимое в ствол другим путём (тот же файл тем же содержимым — тогда ветка пустая по смыслу, даже если коммиты формально уникальны).
3. Разложить на три корзины: **пусто по смыслу** (всё уже в стволе) · **ценное** (есть работа, которой нет нигде) · **неясно**.
4. Ценное — отправить на сервер как ветку `rescue/<имя>-20260917`, чтобы оно перестало держаться на одной машине. Если отправке мешает хук проверки перед отправкой, а работа с этим не связана — сказать об этом в отчёте явно, не умалчивать.
5. Свести таблицу в `docs/evidence/orphan-branches-2026-09-17.md`: ветка · дата последнего коммита · уникальных коммитов · какие области затронуты · корзина · куда спасено.

## Границы

- **Ничего не удалять.** Задание только про спасение и опись. Снос — не твоя зона сегодня.
- Ветку, занятую рабочим деревом, не переключать и не перебазировать: в дереве может лежать чужая незакоммиченная работа.
- `git checkout <ревизия> -- .` в чужом или общем дереве не звать: он затирает несохранённые правки без предупреждения (16.09 так были потеряны правки пяти файлов).
- Свои файлы коммитить поимённо.

## Готово, когда

- в таблице разобраны все ветки из списка, ни одной без ответа;
- по каждой «ценной» есть ветка на сервере и её имя записано в таблице;
- корзина «неясно» сведена к списку с вопросами — по ним решает владелец;
- работа отправлена в ствол через `yarn pr:ship`.

**Слияние — только по прямому слову владельца тебе.**
