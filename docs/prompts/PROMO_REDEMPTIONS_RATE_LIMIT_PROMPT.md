# Промпт: Promo-эндпойнт без rate-limit — 429 после N попыток (В2)

> Task-промпт. Реестр: `promo-redemptions-rate-limit` · размер **S** · форма **шот**.
> Issue: [#1917](https://github.com/officefish/Membrana/issues/1917) (bug). Исполнитель — сессия В (Codex).

## Контекст

`POST …/promo-redemptions` в `packages/background-cabinet` принимает код без ограничения
частоты — промокоды перебираются. Кабинет уже несёт контракт отказа с родом и номером
происшествия (кусок B, #2135): отказ «занят» должен звучать тем же словарём.

## Что построить

1. Ограничитель на эндпойнт по IP **и** по аккаунту, N попыток за окно (умолчания в конфиге,
   например 5/мин по аккаунту, 20/мин по IP).
2. Ответ `429` рода «занят» по контракту куска B, с `Retry-After`.
3. Ядро лимитера чистое (счётчик + окно, часы инъекцией); хранилище в памяти за интерфейсом.

## Границы

- Не трогать логику погашения промокода и тарифы; внешних зависимостей не вводить.

## DoD и порча

- Зуб: N запросов → по существу, N+1 → `429` с `Retry-After`; окно истекло → пропускает.
- **Порча:** убрать проверку по аккаунту → тест красный (перебор с одного аккаунта через разные IP).
- Прод не трогать; выкатка кабинета — ведущая в окно.
