## Контекст

Генератор задачи дня второй день подряд роняет все пять слотов: 25.07 и 26.07 `MAIN_DAY_ISSUE.md`
чеканился рукой. Гипотеза «канал не подведён» **опровергнута разведкой 26.07**: процедура
`ritual-main-day-issue` зарегистрирована в [`scripts/lib/llm-procedures.json`](../../scripts/lib/llm-procedures.json),
вызывается в [`scripts/_main-day-issue.mjs:400`](../../scripts/_main-day-issue.mjs) через
`invokeProcedureLlm`, и рядом уже стоит ретрай по потерянным слотам (`missingSlotHeadings`,
`skeletonCorrection`).

Значит корень другой: **звено цепочки отвечает, слоты в ответе теряются, а скрипт этот ответ
принимает** и пишет полый артефакт. Anthropic исчерпан до 01.08, отвечают deepseek/xai — по
наблюдению 26.07 строгие форматы они не держат. Но какое именно звено ответило, нигде не
записано, поэтому диагноз до сих пор не поставлен, а утро платит ручной чеканкой.

**Границу держим строго (рамка хендофа 26.07):** это диагноз **канала**. Генератор не
переписываем, эпик `strategy-day-generator` (#592) не трогаем, состав слотов не меняем.

### Что построить (продуктовое описание)

1. **Свидетельство.** Лог попыток канала через `onAttempt` (образец — `code-review.mjs:141-149`)
   и провенанс ответившего звена (`provider` / `model` / `source`) **в шапку** `MAIN_DAY_ISSUE.md`,
   машиночитаемо. Сейчас звено не называет себя нигде, поэтому диагноз невозможен.
2. **Громкий отказ.** Если после всех ретраев `missingSlotHeadings(body)` не пусто — шаг падает
   с кодом ≠ 0 и текстом, называющим **провайдера, модель и перечень потерянных слотов**.
   Полый артефакт не пишется: именно он двое суток выдавал себя за результат.
3. **Вещдок.** Сохранить один живой сырой ответ звена (во временное место, не в репозиторий —
   `%TEMP%` / `$TMPDIR`) и записать вердикт в карточку: какое звено роняет строгий формат.

### Архитектура / контракт

| Слой | Путь | Ответственность |
|------|------|-----------------|
| Вызов канала | `scripts/_main-day-issue.mjs` | `onAttempt`-лог, провенанс наружу |
| Предикат полноты | `missingSlotHeadings` (существует) | **не менять сигнатуру**, только использовать в гарде |
| Гард | `scripts/_main-day-issue.mjs` | слоты потеряны → ошибка с именем звена, без записи файла |
| Шапка артефакта | запись `MAIN_DAY_ISSUE.md` | `provider` / `model` / `source` |

**Запрещено:**

- Переписывать генератор, менять состав и порядок слотов, править эпик #592.
- Менять `invokeProcedureLlm`, цепочки других процедур, каталог провайдеров.
- Смягчать `missingSlotHeadings` (например, «считать слот найденным по частичному совпадению») —
  это подгонка предиката под сломанный канал, ровно тот класс, что чинит `main-day-probe-gate` (#533).
- `process.exit()` после сетевого вызова: Windows libuv `UV_HANDLE_CLOSING` подменяет код на 127.
  Выход через `exitCode`.
- Класть сырой ответ звена в репозиторий (может содержать чувствительное) — только `%TEMP%`.

### Тесты

| Область | Минимум |
|---------|---------|
| Полный ответ | все слоты на месте → артефакт записан, в шапке имя звена |
| Потерянные слоты | ответ без слотов после ретраев → exit ≠ 0, текст содержит провайдера и список слотов, **файл не записан** |
| Ретрай | первый ответ неполон, второй полон → успех, в логе видны обе попытки |
| dry-run | `main-day-issue:dry` API не зовёт |
