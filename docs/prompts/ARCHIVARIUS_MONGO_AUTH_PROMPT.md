# Промпт: Archivarius-Mongo с аутентификацией (В4)

> Task-промпт. Реестр: `archivarius-mongo-auth` · размер **S** · форма **шот**.
> Issue: [#1753](https://github.com/officefish/Membrana/issues/1753). Исполнитель — сессия В (Codex).

## Контекст

`membrana-office-archivarius-mongo-1` на офисе поднят без аутентификации: строка подключения в
`packages/background-office` без учётных данных. Mongo слушает внутри docker-сети, но принцип
«сервер-БД за API с учётными данными» (server-first, #349) нарушен.

## Что построить

1. Compose офиса (`deploy/`): `MONGO_INITDB_ROOT_USERNAME/PASSWORD` из `/etc/membrana/office.env`
   (секреты руками владельца, в репо не попадают).
2. Строка подключения архивариуса — с учётными данными из env; без них сервис **отказывается
   стартовать** с внятным словом, а не подключается анонимно.
3. Инструкция владельцу: создать пользователя на живом Mongo без потери данных (один раз, до
   перезапуска с auth) и смоук архивариуса после.

## Границы

- Прод офиса не трогать: код, compose, инструкция — твои; выкатка — руки владельца.
- Схему коллекций архивариуса не менять.

## DoD и порча

- Зуб: строка без учётных данных → сервис не стартует с названной причиной.
- **Порча:** убрать проверку env → тест красный.
- Доклад — `gh pr view <N> --json state,mergeCommit` + текст инструкции.
