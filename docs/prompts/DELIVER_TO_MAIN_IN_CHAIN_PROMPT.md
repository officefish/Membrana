# Промпт: Доставка в ствол внутри цепочки ритуала (Б, после #2147)

> Task-промпт. Реестр: `deliver-to-main-in-chain` · размер **M** · форма **шот**.
> Issue: [#2081](https://github.com/officefish/Membrana/issues/2081). Исполнитель — сессия Б после пяти зубов.

## Контекст

Шаг `deliver-to-main` в обеих цепочках (`ritual:day`, `ritual:evening`) роняет ритуал кодом 2:
документы созданы, но «не на main», и ведущая запускает
`yarn ritual:deliver-to-main --ritual … --execute` вторым заходом — 24–25.08 четыре раза из
четырёх (трейл `docs/procedure-runs/trail/`). Причина конструктивная: шаг не умеет ждать CI.

## Что построить

1. Доставка внутри цепочки: PR → **ждать CI** (`pr:wait`) → влить → перечитать кадр — одним
   шагом с таймаутом и исходом `delivered` / `pending-ci` / `failed`.
2. `delivered` → ритуал `exit 0`; `pending-ci` — названный хвост с командой продолжения, не отказ;
   `failed` — красный.
3. Журнал прогона получает исход шага, а не «сироту, закрытую лениво» назавтра.

## Границы

- Состав документов и гейты Ангелины не менять; review-gate не обходить.

## DoD и порча

- Зуб на конечный автомат шага с подменой `pr:wait`.
- **Порча:** `pr:wait` возвращает таймаут → `pending-ci`, ритуал ни exit 2, ни ложный exit 0.
- Приёмка: два утра и два вечера подряд без второго захода.
