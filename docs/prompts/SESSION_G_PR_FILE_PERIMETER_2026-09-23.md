# Задание сессии G: предикат «PR не выходит за файловый периметр сессии» (23.09)

**Основание:** предложение команды в вечернем фидбеке 22.09 (Архитектор; эксперимент из плана дня 22.09), принято владельцем утром 23.09. Подкрепление магистрали дня `cabinet-registration-rollout`.

**Зачем:** 22.09 четыре сессии работали по ратифицированным границам файлов, и ни одна не вышла за периметр — но проверяла это ведущая руками по списку файлов каждого PR. Станок под конкретную продукцию: параллельные сессии с границами. Предикат должен быть механическим и читаемым: красный с именами лишних файлов, зелёный с перечнем проверенных.

**Дерево:** своё, отдельное, от свежего `origin/main`. Ветка вида `feat/pr-file-perimeter`. Коммиты только своих файлов поимённо.

## Границы файлов

- **новый** `scripts/pr-perimeter-check.mjs` и **новый** `scripts/pr-perimeter-check.test.mjs` (по образцу соседних `scripts/*.test.mjs` на `node --test`)
- одна строка-скрипт в `package.json` (`"pr:perimeter": "node scripts/pr-perimeter-check.mjs"`) — только добавление
- **новый** `.github/workflows/pr-perimeter.yml` — отдельная необязательная проверка (не в обязательные проверки ветки; включение в обязательные — слово владельца после недели наблюдения)
- запись в реестре скриптов, если он регенерируется (`yarn scripts-registry` или как в `package.json`; проверить, не править руками)

Ничего иного: ни существующих workflow, ни `pr-ship`, ни правил защиты ветки.

## Контракт предиката

**Вход:** периметр — список путей и глобов, объявленный **в самом PR**: блок в теле PR

```
<!-- perimeter
packages/background-cabinet/src/modules/auth/**
packages/background-cabinet/src/config/env.schema.ts
-->
```

Источник периметра для сессий A–D 22.09 — раздел «Сессии» в `docs/meeting/cabinet-registration-promo/MEETING_ACTIVE.md`; предикат читает **только тело PR**, карточки заседаний не парсит (карточки — для людей, в них нет машинного формата). Нет блока в теле → предикат **пропускает с пометкой** «периметр не объявлен» (зелёный, не красный): станок не должен ломать PR, у которых периметра нет по замыслу (ритуальные, санитарные). Пустой блок → красный: объявлен, но пуст.

**Правило:** каждый файл из `gh pr view --json files` (или `git diff --name-only base...head`) обязан подходить хотя бы под один путь или глоб периметра. Точный путь = точное совпадение; глоб — по правилам `minimatch`/`picomatch`, что уже есть в зависимостях корня (проверить `package.json`, новых зависимостей не добавлять). Механические спутники объявляются явно строкой в периметре (`yarn.lock`), автоматических исключений нет — так решено на M2/M4 (Р7): следствие тоже называется словами.

**Выход:** зелёный — таблица «файл → правило периметра»; красный — список файлов вне периметра и код выхода 1. Никаких «предупреждений» без кода выхода (норма «проверка без предмета», 03.09).

**Локально:** `yarn pr:perimeter --pr <N>` (читает тело и файлы через `gh`) и `yarn pr:perimeter --base origin/main --perimeter-file <файл>` для прогона без PR.

## Зубы (красные до реализации)

- файл вне периметра → 1 и имя файла в выводе;
- все файлы внутри → 0 и таблица;
- глоб `dir/**` покрывает вложенные, не покрывает соседний каталог;
- блока нет → 0 с пометкой «периметр не объявлен»; блок пуст → 1;
- `yarn.lock` не покрыт неявно: без строки в периметре — красный;
- разбор блока устойчив к CRLF и пробелам.

## Проверка на живом

Прогнать локально на пяти влитых PR эпика (#2393, #2396, #2397, #2398, #2401) с периметрами, взятыми из раздела «Сессии» карточки (расширения по ратификациям включить): ожидание — все пять зелёные; вывод пяти прогонов — в тело PR. Если какой-то красный — это находка, а не повод править правило: сказать ведущей.

## Сдача

`yarn pr:ship --type feat --scope tooling --execute`; PR без слияния; в теле: команды зубов до/после, пять живых прогонов, workflow как необязательный. Слияние — по приёмке ведущей (прогон зубов и живых PR у себя).

## Отчёт ведущей

- ветка, вершина, файлы (все в границах; в теле своего PR — свой же блок периметра, и предикат должен быть зелёным на самом себе);
- зубы до/после цитатой; пять живых прогонов;
- спорное — вопросом, не решением (например, формат блока в теле PR — если найдёшь в репозитории уже принятый машинный формат для тела PR, скажи до того, как заводить свой).
