# Промпт: `EXECUTION_PROCEDURE` — интерфейс маршрутов разработки

> **Task-промпт для агента-разработчика.** Адресат — сессия, построившая
> `DEVELOPMENT_MATRIX` и процедуру `hackathon` (PR #1607): у неё контекст гранул,
> генератора, реестра процедур и свежий отчёт о форме.
> Размер: **L**. Ожидаемый артефакт: интерфейс + зуб + миграция реестра.

---

## Что уже ратифицировано и не подлежит пересмотру

**ADR-0021** (ACCEPTED, 01.08) — `docs/adr/ADR-0021-procedure-kind-two-closed-lists.md`:

- **род процедуры** — пятая статья словаря, три значения: `разработка` · `решение` · `ритм`;
  делят реестр без остатка (7 / 4 / 12 после добавления `adr`);
- **два закрытых списка**: маршруты разработки (7) и форматы решения (4); ритм не запирается;
- **два интерфейса, а не один** — у заседания нет зоны и объёма, у спринта нет повестки;
  общий интерфейс дал бы поля, не обязательные ни для кого;
- **состав интерфейсов вынесен из решения**: оба обязаны быть **выведены из прожитых
  образцов**, а не сочинены.

**Форма процедуры** ратифицирована ещё раньше — заседание `procedural-layer` 21.07, вердикты
Р1–Р5. Пятиполёвка манифеста, дом, границы слоёв, грамматика веток. Это фундамент, интерфейс
строится **над** ним, а не вместо.

**Задача этого промпта — только `EXECUTION_PROCEDURE`, интерфейс рода `разработка`.**
Интерфейс формата решения — отдельная работа; проектировать его здесь **запрещено**.

## Отправная точка, а не ответ

`docs/procedures/hackathon/FORM_REPORT.md` (PR #1607) уже назвал кандидатов в обязательные:

```
id · leadPersona · trigger · steps · gates · frames с holder · mode ·
home или честное «дома нет» · portfolio или честное отсутствие ·
precedents, если маршрут выводится из прожитого образца
```

И отдельно — **частное для эстафеты**: H-этапы, `stage-completion-checklist`, гейт передачи,
правило четырёх передач.

**Это гипотеза одного образца.** Её надо проверить, а не принять.

---

## Несущее требование: проверка опровержением

Манифесты есть у **пяти** маршрутов из семи:

| маршрут | манифест | живой материал, если манифеста нет |
|---|---|---|
| `one shot` | ✓ | |
| `membrana-local-sprint` | ✓ | |
| `hackathon` | ✓ (PR #1607) | |
| `containerization` | ✓ | |
| `day-sprint` | ✓ | |
| `cowork` | **—** | 4 коворка в `docs/cowork-sprint/`, бриф, интерфейсный контракт, фазы 0→5, ретроспектива |
| `challenge` (`competition`) | **—** | `docs/COMPETITION_SPRINT_REGULATION.md`, 4 соревнования в `docs/competition-sprint/` и архиве |
| `night build` (`night-sprint`) | **—** | скилл `membrana-night-sprint`, глаголы `night:open` / `night:close` |
| `marathon` | **—** | **не прожит ни разу** — тела нет |

**Правило вывода: поле обязательно, только если его удалось заполнить для ВСЕХ прожитых
маршрутов** — включая три безманифестных, по их живому материалу. Не заполнилось хотя бы для
одного — значит поле **не обязательное**, а частное. Опровержение сильнее подтверждения:
пять согласных образцов ничего не доказывают, один несогласный закрывает вопрос.

`marathon` из проверки **исключается** — у него нет материала, и подгонять интерфейс под
задумку значит сочинять.

## Граница, которую назвал сам отчёт о форме

> будущий `EXECUTION_PROCEDURE` нельзя свести к `trigger · steps · gates`… **но топология
> маршрута должна оставаться частной: иначе интерфейс начнёт навязывать всем процедурам форму
> эстафеты.**

Это и есть главный риск работы. Интерфейс обязан различать:

- **общее** — то, без чего маршрут не маршрут;
- **частное** — то, чем один маршрут отличается от другого.

Если в обязательных окажется что-то, чего нет у коворка (параллельная изоляция) или у
соревнования (три команды, судья), — интерфейс навязывает эстафету и построен неверно.

## Задание

### 1. Интерфейс

Вывести и записать `EXECUTION_PROCEDURE`: обязательные поля с обоснованием **каждого** —
почему без него маршрут не маршрут, и на каких образцах это проверено.

Отдельной секцией — **частные поля**, с указанием, чьи они.

Форма записи — на ваше усмотрение (гранула strategic-docs, документ в `docs/procedures/`,
расширение `CORE.md`), но **одна редакция**, зеркала указателями.

### 2. Зуб

`validateProcedure` уже проверяет общую форму. Расширить его так, чтобы процедура рода
`разработка` проверялась **дополнительно** по `EXECUTION_PROCEDURE`, а рода `решение` и
`ритм` — нет. Отсутствие обязательного поля у маршрута — дефект; у ритуала — не дефект.

### 3. Хвост ADR-0021: род у всех записей реестра

Р5 требует объявленного рода у **каждой** записи `docs/procedures/registry.json`. Сейчас его
нет ни у одной, включая свежую запись `hackathon` — исполнитель принять требование не мог,
ADR был принят после выдачи того задания.

Проставить род всем 22 записям. Раскладка обязана сойтись: **разработка 7 · решение 4 ·
ритм 12** (после заведения `adr` — см. пункт 4).

### 4. Хвост ADR-0021: `adr` заводится процедурой

Р2а: формат решения, которым принимается ADR-0021, сам не числится процедурой. Контейнер
`docs/procedures/adr/` по форме Р1 заседания 21.07, запись в реестре, род `решение`.

Канон-каталог `docs/adr/` и шаблон остаются на месте — контейнер описывает **процесс**, а не
хранит записи. То же различение «определения ≠ прогоны», по которому `storm/` и `meeting/` не
мигрировали.

### 5. Отчёт о выводе

Как и с хакатоном — **отдельным документом**, и он снова несущий:

- какие поля-кандидаты из `FORM_REPORT` **не выдержали** проверки семью образцами и почему;
- какие появились сверх списка;
- на каком образце сломалось каждое отвергнутое поле — поимённо;
- что осталось частным и чьё оно;
- **чего интерфейс намеренно не описывает** и почему это правильно.

## Definition of Done

- [ ] `EXECUTION_PROCEDURE` записан одной редакцией; зеркала — указатели
- [ ] Каждое обязательное поле обосновано и проверено на **семи** прожитых маршрутах
- [ ] Частные поля отделены, у каждого назван владелец-маршрут
- [ ] `validateProcedure` применяет интерфейс к роду `разработка` и **не применяет** к
      `решение` и `ритм`; сателлит на оба случая
- [ ] Род проставлен всем записям реестра; раскладка 7 / 4 / 12 сходится машинно
- [ ] `adr` заведён процедурой с родом `решение`
- [ ] Отчёт о выводе сдан отдельным документом
- [ ] Всё в стволе; матрица при необходимости пересобрана из гранул, а не правлена в релизе

## Чего НЕ делать

- **Не проектировать интерфейс формата решения.** ADR-0021 назвал его отдельным; его имя —
  акт структурщика, состав — отдельная работа. Здесь только род `разработка`.
- **Не строить `marathon`** и не подгонять под него интерфейс: тела нет, подгонка = сочинение.
- **Не заводить манифесты `cowork`, `competition`, `night-sprint`** в этой работе — они нужны
  как **материал для проверки**, а их заведение это отдельные работы со своими держателями.
  Если по ходу окажется, что без манифеста проверить нельзя, — назвать это находкой, а не
  расширять зону молча.
- **Не переопределять форму процедуры** (Р1–Р5 заседания 21.07). Интерфейс строится над ней.
- **Не править релиз матрицы руками** — только гранулы и пересборка.
