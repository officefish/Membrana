## Контекст

Корпус «один тракт — два класса» (600 звуков, весь август, владелец 02.08: отдельным
сервисом, не в репозитории) — главный носитель августовской работы по MFCC. Кристалл
`reader-before-next-carrier` (owner, 01.08) велит строить приёмник ДО записи: «приедет
корпус, который нечем принять, если признак годности назначать потом». Спецификация
трека уже существует и принята — инсайт
[`insight-own-field-corpus-single-spec`](../insights/insight-own-field-corpus-single-spec/INSIGHT.md)
(adopted 7.0, 18.07): семь полей, каждое обосновано конкретными граблями внешнего
массива DADS (18.07). Предикат ЧЕКАНИТ эту спеку в проверяемую форму — критерии не
выдумываются, а берутся из инсайта.

Шот 04.08 по этой находке отказан предикатом S честно (capability_chaining: третий
смежный выстрел в `scripts/` за окно, 376 строк цепочки при потолке 200) — потому
карточка. Прецедент формы: `scripts/lib/one-shot-s-predicate.mjs` — детерминированный
вход → вердикт с названными основаниями.

### Что построить (продуктовое описание)

1. **`acceptCorpusTrack(track)`** — чистая функция: запись трека → `{ok, problems[]}`.
   Проверяет присутствие и форму семи полей спеки: id записи-источника; сцена
   (место/время/погода/ветер); дистанция/высота/модель/режим (для класса «дрон»;
   у негатива — null с причиной); ссылка на парный негатив той же сцены; микрофон и
   тракт записи; длительность и частота дискретизации; подтверждение оператора.
   Каждый problem — названное основание, не булев провал.
2. **`acceptCorpusBatch(tracks)`** — батч-инварианты: один тракт (единый chain-id на
   корпус), единая частота дискретизации, оба класса присутствуют, парность позитивов
   негативами той же сцены. Слепоту назвать полем (`blind`): предикат судит провенанс,
   НЕ качество звука.
