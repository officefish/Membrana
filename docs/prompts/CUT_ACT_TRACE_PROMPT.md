# Промпт: Носитель следа для акта нарезки

> **Task-промпт для агента-разработчика.** Маршрут — `membrana-local-sprint`
> ([канон процедуры](../procedures/membrana-local-sprint/README.md)).
> Размер: **M**. Ожидаемый артефакт: **1 PR** — акт нарезки получает вещдок, а
> `honest_pair` перестаёт быть слабее, чем читается.
> Реестр: `id` = `cut-act-trace` · GH [#1566](https://github.com/officefish/Membrana/issues/1566).

## Контекст

**Долг `#sprint-cut-act-has-no-trace`** ([`docs/bridge/DEBTS.md`](../bridge/DEBTS.md), заведён
30.07): акт нарезки не имеет рода следа. `cutBy` можно проставить именем **без прогона через
контекст резчика**, и гейт этого не увидит.

**Вещдок 30.07.** Первый боевой спринт `mfcc-compare-sprint`: план v1 написала сессия и
проставила `cutBy=tarasov` без прогона контекста тимлида. Поймал **владелец** («не вижу, что ты
вызвал спринт через скилл»), а не механизм.

**Корень, названный в долге.** Четыре рода следа (`contract_signature`, `session_prep`,
`context_run`, `review_pass`) описывают **исполнение блока**; форма следа требует `blockId`. Акт
нарезки блоку не принадлежит — он про план целиком и происходит **до** окна работы. Втиснуть его
в ленту исполнения значило бы **соврать формой**. Список родов закрыт по построению: у окна
четыре момента, пятый род потребовал бы пятого момента.

**Смежный дефект — [#1566](https://github.com/officefish/Membrana/issues/1566), открыт.**
Перерезка блока: родитель разобран структурщиком, из него нарезаны три ребёнка, прогон контекста
остался один — **все три получили `honest_pair`**. Дети «не существовали в той форме, когда
персона говорила». Решение владельца 31.07: перерезал блок — прогоняй заново по каждому куску,
разбор родителя на детей **не наследуется**. Формулировка issue дословно: «`honest_pair` слабее,
чем читается».

**Вещдок 01.08 (свежий, из прогона `meeting-gates-teeth`).** Председатель написал
`cutBy: "tarasov"` рукой — никто не спросил, прогонялся ли контекст тимлида. Затем перерезал план
v1→v2 и **не двинул `revisionAt` ни у одного блока** — ничто не заставило, и следы, написанные
после перерезки, зачлись как свежие. Сама перерезка не оставила следа нигде, кроме смены дайджеста.

**Замок есть, но ключ у того, кого он запирает.** `isStale(t, b) => t.at < b.revisionAt`
(`scripts/lib/execution-trace/predicates.mjs`) — свежесть считается от ревизии предмета,
календарного TTL нет намеренно. Но `revisionAt` пишет **тот же, кто режет**.

## Промпт целиком (для вставки агенту)

### Что построить

1. **Лента актов плана — отдельная от ленты исполнения.** Свой носитель
   (`docs/sprint/cut/trail/<sprintId>.jsonl` либо иной, названный явно) и **свой закрытый
   перечень родов**: прогон контекста резчика · акт нарезки · акт перерезки. Роды исполнения
   **не трогать**: их список закрыт по числу моментов окна, и добавление пятого есть обход гейта
   новым словом.
2. **`revisionAt` перестаёт быть самозаявленным.** Его пишет **инструмент** в момент ратификации
   и перерезки — так же, как уже пишет дайджест. Тогда «перенос согласия» и «протух след»
   опираются на одну машинную метку, а не на честность резчика.
3. **Перерезка обнуляет разбор родителя** (#1566): дети не наследуют `context_run` родителя, и
   гейт **понижает вердикт**, а не молчит. Сегодня механизм разницу видит и поводом не считает.
4. **`cutBy` становится проверяемым:** без следа прогона контекста резчика план получает находку.
   Перечень находок нарезки закрыт шестью (`cut_shape`, `block_oversized`, `performer_unnamed`,
   `context_unnamed`, `zones_overlap`, `plan_unratified`) плюс седьмая «резчик ≠ исполнитель» —
   расширение только актом, не по вкусу.

### Архитектура / контракт

| Слой | Путь | Ответственность |
|------|------|-----------------|
| роды актов плана | новый модуль рядом с `scripts/lib/sprint-cut/` | закрытый перечень, зеркало-док, зуб на расхождение |
| ратификация | `scripts/lib/sprint-cut/ratification.mjs` | машинный `revisionAt` при ратификации и перерезке |
| проверка плана | `scripts/lib/sprint-cut/cut-plan.mjs` · `scripts/sprint-cut-check.mjs` | находка «нет следа прогона контекста резчика» |
| гейт исполнения | `scripts/lib/execution-trace/predicates.mjs` | наследование не переносится через перерезку; вердикт понижается |

**Запрещено:**

- Добавлять пятый род в `TRACE_KINDS` — список закрыт **по построению**; род вне списка есть
  ошибка входа `E_TRACE_KIND_UNKNOWN`, и открытие списка = обход гейта новым словом.
- Календарный TTL для свежести: его нет **намеренно**, свежесть считается от ревизии предмета.
- Переписывать исторические планы и ленты — они вещдоки прошлых прогонов.
- Молча трогать открытый хвост #1566 про `evidenceRefs`: либо явно в scope, либо явно вне.

### Тесты

| Область | Минимум |
|---------|---------|
| роды актов плана | перечень закрыт; чужой род — ошибка входа, не «прочее» |
| `cutBy` без следа | план получает находку; со следом — не получает |
| машинный `revisionAt` | ратификация двигает метку; правка тела сбрасывает согласие (регресс дайджеста) |
| перерезка | ребёнок не наследует `context_run` родителя; вердикт понижен, а не `honest_pair` |
| регресс | шесть находок нарезки и семь вердиктов гейта не поехали |

### Definition of Done

- [ ] Лента актов плана существует, роды закрыты, зеркало-док согласовано зубом.
- [ ] `cutBy` без следа прогона контекста резчика даёт находку.
- [ ] `revisionAt` пишет инструмент при ратификации и перерезке.
- [ ] Перерезка обнуляет наследование разбора; гейт понижает вердикт (#1566).
- [ ] Список родов исполнения **не изменён**.
- [ ] Живой прогон как вещдок (норма [#1565](https://github.com/officefish/Membrana/issues/1565)).
- [ ] `yarn turbo run lint typecheck test build --continue` — зелёный.
- [ ] `procedure-run:journal` несёт subject, evidence и gaps этого прогона.
- [ ] LGTM Teamlead.

### Out of scope

- Два рода следа без носителя (`contract_signature`, `session_prep`) — отдельный долг.
- Привязка сегментов ревью к блоку (N1) и журнал остановок ведущей (N2).
- Ложный отказ `sprint:experience` на лексикографическом сравнении ISO-меток с разными
  смещениями — найден 01.08, свой предмет.

**Открытый хвост #1566, решить явно ДО нарезки:** почему валидный `context_run` со ссылкой
`docs/discussions/block-mfcc-core-ozhegov.md` не попал в `evidenceRefs`. Если это дефект подсчёта,
а не данных — он меняет цену задачи.

### Порядок работы ролей

1. **Teamlead** — режет на блоки, держит границу «новая лента ≠ пятый род».
2. **Структурщик** — закрытый перечень родов актов и его зеркало.
3. **Математик** — предикаты: наследование через перерезку, понижение вердикта, машинная метка.
4. **Музыкант** — что происходит с прогонами, начатыми до перерезки.
5. **Верстальщик** — как перерезка видна в отчёте гейта человеку.
