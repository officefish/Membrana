# Задание сессии D: форма регистрации по коду в веб-кабинете и правда на лендинге (21.09)

**Контур:** заседание «Регистрация в кабинете по промокоду панели», комната M4 «форма, фраза, частота, лендинг» — **ратифицирована владельцем 21.09**. Решение комнаты ниже приведено дословно из протокола; менять его сессия не может — только исполнить. Спорное — в чат ведущей, не в код.

**Данности:** промокод регистрации выдаёт панель офиса; кабинет его только вводит и передаёт. Форма не проверяет код заранее и не различает причины отказа (Q3, ADR-0005). Контракт двери сервера — по M3 (сессия C): `POST /v1/auth/register`, тело `{ login, password, code }`; ответы **201** с телом сессии как у входа; **401** «Registration is disabled»; **429** «Too many requests» (10 попыток за 600000 мс на адрес); **403** «Registration was not accepted» на любой отказ по коду, логину, длинам; **503** «Please try again later». Фразы сервера английские, в интерфейс не попадают — фраза выбирается по HTTP-статусу.

**Очерёдность:** по M0 сессия D стартует **после C** по контракту двери; писать код можно параллельно, сливать — после PR C (иначе форма зовёт дверь, которой в стволе нет). Правку лендинга «сейчас» можно сливать **сразу**, не дожидаясь C (M0: «лендинг — сразу»).

**Дерево:** своё, отдельное, от свежего `origin/main`. Ветка вида `feat/cabinet-register-form`. Коммитить только свои файлы поимённо, никогда `git add -A`.

## Границы файлов (M0 + расширение по ратификации M4)

Ровно эти пути, ничего кроме:

- `apps/cabinet/src/pages/LoginPage.tsx`
- `apps/cabinet/src/api/auth.ts`
- `deploy/root-site/index.html` (карточка кабинета, строки 153–157)
- `apps/cabinet/src/context/AuthContext.tsx` (расширение: метод `register`)
- **новые** `apps/cabinet/src/api/auth.register.test.ts`, `apps/cabinet/src/pages/LoginPage.register.test.tsx` (расширение)
- `apps/cabinet/package.json`, `apps/cabinet/vite.config.ts` (расширение) — **ровно** на объявление тестового окружения DOM и его dev-зависимостей (`jsdom` и библиотека рендера для тестов); сверх этого в этих файлах ничего не менять; в браузерный бандл ничего не добавлять

**Не трогать:** сервер кабинета (`packages/background-cabinet`, сессии B и C), офис (A), другие страницы и компоненты `apps/cabinet`, маршрутизацию (её нет — и не заводить), секреты, прод. Ключ офиса в браузер не попадает.

## Решение комнаты M4 (протокол `docs/seanses/cabinet-registration-promo-m4-form-landing-2026-09-21.md`, строки 126–154, дословно)

| Вопрос | Решение |
|--------|---------|
| Место формы | Та же `LoginPage`, режим `login` \| `register`, переключатель «У меня уже есть вход» / «Создать учётную запись». Отдельный экран и router — нет (маршрутизатора в стволе нет). |
| Поля | Порядок: «Логин», «Пароль», «Код приглашения». Повтора пароля нет. `login.trim()`, `code.trim()`, пароль без trim. Пустые после trim — локально «Заполните все поля.» без fetch. |
| Вызов API | `registerRequest(login, password, code)` в `apps/cabinet/src/api/auth.ts` → `POST /v1/auth/register`, тело `{ login, password, code }`, успех 201 → `{ token }` (как login). Ошибки — `AuthApiError` со `status` и русской `message`. |
| Сессия после 201 | Расширение **вне M0-D**: `apps/cabinet/src/context/AuthContext.tsx` — метод `register(...)` по образцу `login` (request → `setStoredToken` → me). Со страницы `setStoredToken` напрямую — запрещён. |
| Фразы по статусу | Только HTTP-статус (не English message). 401: «Регистрация сейчас закрыта.» 403: «Регистрация не принята.» 429: «Слишком много попыток. Подождите 10 минут.» 503: «Сервис временно недоступен. Попробуйте ещё раз.» Иной статус: «Не удалось выполнить регистрацию. Попробуйте ещё раз.» Сеть: «Нет связи с сервером. Проверьте интернет и попробуйте снова.» 201 — без фразы, вход в сессию. Все 403 — одна фраза. |
| Чинить parseError | На register-пути: не отдавать сырой `body.message` в UI; `mapRegisterErrorStatus(status)` + `AuthApiError`. Статус сохраняется в ошибке. |
| Частота | Кнопка disabled при `submitting`; guard от двойного submit; автоповторов нет. После 429: фраза 429 + disabled **600 секунд** (`retryBlockedUntil = now + 600000`). После 503 и сети — повтор сразу. После 401 — без 600 с блока. |
| Подпись внизу (prod) | «Учётная запись открывается по коду приглашения. Код выдаёт владелец.» DEV seed-текст сохранить. |
| Лендинг сейчас | title: «Кабинет — вход по приглашению»; description: «Вход в кабинет по приглашению владельца. Устройства, сценарии и журнал — на сервере.»; href: `https://cabinet.membrana.space`. |
| Лендинг после формы | title: «Кабинет — регистрация по приглашению»; description: «Создайте учётную запись по коду приглашения. Привязка устройств, сценарии и журнал с сервера.»; href тот же. |
| Зубы D | `apps/cabinet/src/api/auth.register.test.ts` — mock fetch, статус→фраза буква в букву, разные message 403 → одна фраза. `apps/cabinet/src/pages/LoginPage.register.test.tsx` — disabled кнопки при submit и после 429; одна фраза на 403. Файлы тестов — **расширение границ D**. |
| Что не строить | check кода до отправки; ветвление причин 403; капча; почта; восстановление пароля; RegisterPage/router; countdown; i18n-фреймворк; английский message в UI register. |
| Расширение границ D | Явно: `AuthContext.tsx` (метод `register`); `auth.register.test.ts`; `LoginPage.register.test.tsx`. В границах M0: `LoginPage.tsx`, `api/auth.ts`, `deploy/root-site/index.html`. |

**Критерии готовности:**

- Переключатель режимов на `LoginPage`; поля логин/пароль/код; prod-подпись заменена.
- `registerRequest` + `mapRegisterErrorStatus` + `AuthApiError`; `register` в `AuthContext`.
- Русские фразы на 401/403/429/503/default/сеть — дословно как в таблице.
- Блок 600 с после 429; submitting-guard; нет автоretry.
- Лендинг: текст «сейчас» в `index.html` (выкатка — владелец); текст «после» готов к смене при выкатке формы.
- Тесты api и формы зелёные; нет check и нет разных фраз 403.
- Не тронуты контракты M1–M3 (дверь сервера, office client, английские message сервера).

## Факты ствола, которые уходят в задание (сверены председателем и аудитором по `origin/main`; решение не меняют)

- **Страница входа** — `LoginPage.tsx`: `useAuth()` даёт сегодня только `login` (5); состояние `loginName`, `password`, `error`, `submitting` (6–9); отправка (16); показ ошибки `{error}` (60); подпись в проде (77–80) — заменить текстом из таблицы; DEV-подпись (73–76) сохранить.
- **Клиент API** — `api/auth.ts`: `LoginResponse = { token, user }` (11–14) — `registerRequest` возвращает **тот же тип**, «`{ token }` (как login)» в таблице читается как «как `loginRequest`»; `parseError` (36–45) склеивает `body.message` и теряет статус — для пути регистрации заменить на `AuthApiError { status, message }` с фразой из `mapRegisterErrorStatus(status)`; `loginRequest` не ломать (перевод его фраз — не в этом задании).
- **Контекст** — `AuthContext.tsx`: тип (26) и реализация `login` (48–49) — `register` по тому же образцу: запрос → `setStoredToken` → загрузка `me`.
- **Тесты веб-кабинета сегодня** — vitest без DOM-окружения: `vite.config.ts` без блока `test`, зависимостей `jsdom`/библиотеки рендера нет, единственный tsx-тест `components/nodes/NodeOverflowHoldLine.test.tsx` рендерит `renderToStaticMarkup`. Для теста формы объявить окружение `jsdom` в `vite.config.ts` (блок `test`, можно только для файлов `*.test.tsx`) и добавить dev-зависимости в `apps/cabinet/package.json`; таймеры — `vi.useFakeTimers()` и сдвиг на 600000 мс. Проверить, что существующие тесты кабинета остаются зелёными, а `yarn build` веб-кабинета не тянет тестовые зависимости в бандл.
- **Лендинг** — `deploy/root-site/index.html:153–157`, карточка «Кабинет — регистрация»; правка «сейчас» — отдельным маленьким PR, сливается сразу; выкатка — `scripts/_ssh-root-site-setup.mjs`, **слово владельца**, сессия не выкатывает. Текст «после» — комментарием рядом с карточкой или в теле PR формы, не в живую страницу до формы.
- **Словарь.** Подписи полей, переключатель, фразы — буква в букву из таблицы; в коде комментарии по-русски: блокировка, попытка, фраза — не «retry», «cooldown».

## Порядок работы

1. Лендинг «сейчас» — первый PR, сразу (`yarn pr:ship --type docs --scope landing …`).
2. Красные зубы: `auth.register.test.ts` (подмена `fetch`, таблица статус → фраза) — на стволе падает на импорте `registerRequest`; показать. Затем окружение DOM и `LoginPage.register.test.tsx` — красный до правки формы.
3. `api/auth.ts` → `AuthContext.register` → `LoginPage` (режим, поля, блокировка, подпись).
4. PR формы через `yarn pr:ship --type feat --scope cabinet --message "…" --execute`; в теле — команды по критериям готовности, вывод тестов до/после, вывод `yarn build` кабинета. Не `gh pr merge`. Слияние формы — после PR сессии C.
5. Ревью и слияние — по приёмке ведущей по факту; отдельного слова владельца не нужно. Прод не выкатывать.
