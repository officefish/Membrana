# СЕССИЯ В — #2046: первый трек после старта сценария 44.1 кГц вместо отказа

Дата старта: 2026-08-22
GitHub Issue: #2046
Процедура: `membrana-local-sprint`
Worktree: отдельный sibling checkout, не `practice/Membrana`

## Симптом

На живом узле Firebat 21.08 ровно первый захват после запуска сценария уходит
в частоту системы 44100 Гц, а последующие захваты держат 48000 Гц.

- 09:41:44 UTC — 44100, 2.88 с, первый трек пробы после установки.
- 09:41:49...09:41:59 UTC — 48000, остальные три трека пробы.
- 09:45:18 UTC — 44100, 3.02 с, первый трек часового сеанса.
- 09:45:23 UTC и дальше — 48000, весь остальной час.

## Дефект

PR #2042 обещал fail-closed: если браузер/OS возвращает не 48000, capture падает
с `WEB_AUDIO_SAMPLE_RATE_UNAVAILABLE` и 44.1-сэмпл не пишется. Первый трек
пишется вместо отказа, значит проверка не закрывает реальный путь записи.

## Проверенная стартовая гипотеза

Проверку #2042 нельзя считать достаточной для трека записи: она стоит в
`LiveSampler.start`, а `ScenarioMicJournalBridge.recordChunk` пишет через
`startClipRecorder(stream, 'wav')` -> `startWavRecorder`. В этом пути
`AudioContext` создаётся в recorder, worklet начинает складывать PCM в
`pcmChunks`, а `ctx.sampleRate` читается в `stop()` уже после записи.

## Нужно

- Сдвинуть проверку фактической частоты до первого PCM chunk.
- Поведение: либо отказ до записи, либо запись уже на 48000.
- Отдельный зуб на класс "первый захват после старта".
