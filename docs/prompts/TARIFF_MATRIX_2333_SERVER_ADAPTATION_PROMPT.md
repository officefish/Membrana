## Что построить

### v1 — версия контракта на носителях

Добавить одно поле версии контракта на строку `Tariff` в cabinet и одно поле на запись `Device` сервера записей. Имя в коде выбери одно и удержи рядом с термином M1: версия контракта — число, которое издаёт релиз; в сетке это существующее `version`.

Разноска `membrane-context-fanout` должна передавать версию в той же полезной нагрузке, что квоты. Приём `PATCH /v1/devices/:id/membrane` сохраняет её. `/quota` отдаёт версию рядом с лимитами. Поле `updatedAt` не использовать как версию. Прибор-край #2323 не трогать.

### v2 — проекция сетка -> база кабинета и зуб 2

Сделать одну команду проекции, например `tariff:project-cabinet`: она читает `docs/tariffs/tariff-grid.json` и пишет строки `Tariff` для всех рядов сетки значениями релиза и версией. Команду зовёт человек по слову или ритуал наката; это не HTTP-трафик и не старт процесса.

Закрыть путь #2297: `checkpoint-v1` и `observatory-v1` получают автора в дереве этим путём. Вывести `prisma/seed.mjs` и `docs/tariffs/tariff-scalars.json` из авторов квот: повторный seed не должен менять free в обход сетки. Удалить мёртвый `ensureFreeTariff`. Старт кабинета: `tariff-grid-source.ts` читает сетку ровно один раз за процесс и не пишет в `Tariff`.

### v3 — зуб 3 и проход разноски

Сделать `tariff:devices-check`: сверка cabinet `Tariff` (+ политика) с media `Device` по парам полей, не по счётчику разноски. Красный вход: прямой SQL/PATCH по записи прибора в обход кабинета.

Добавить идемпотентный проход разноски по всем мембранам на накате. Если зуб 3 красный — повтор разноски чинит расхождение.

### v4 — один рубильник правды

`TARIFF_GRID_MODE` и предикаты `tariff-cutover` подчинить зубам как зеркало готовности, затем снять как переключатель правды. `tariff-cutover` не источник чисел; опора на `S0_scalars` уходит. Второй рубильник истины запрещён.

В этом блоке также проводятся package scripts для команд, созданных v2/v3, после появления их файлов.

## Definition of Done

1. Зуб 2: тест красный при расхождении любой пары `userStorageQuotaBytes <-> storage.hot`, `bufferQuotaBytes <-> storage.buffer`, `maxNodesPerMembrane <-> nodes.max`, `maxUserWorkspaces <-> workspaces.user.max` или версии `Tariff` != `version` сетки; фикстура без колонки холода не краснеет.
2. Зуб 3: команда сверки красная при неравенстве любой из пяти пар или политики; счётчик разноски критерием не является; порча — прямой SQL/PATCH по записи прибора -> красный.
3. Старт кабинета: тест на `tariff-grid-source.ts` — одно чтение сетки за процесс, ноль записей в `Tariff`.
4. Посев: тест на `seed.mjs` — не читает `tariff-scalars.json` для квот; прогон seed не меняет free в обход сетки.
5. `rg ensureFreeTariff packages/background-cabinet` пусто.
6. Версия: миграции обеих баз несут поле; тест разноски рядом с `membrane-context-fanout.service.test.ts` красный, если версия на записи прибора != `version` сетки после проекции и разноски.
7. `rg TARIFF_GRID_MODE packages/ scripts/` пуст после переезда; `tariff-cutover.mjs` не опирается на `S0_scalars`.
8. Живая проверка после выкатки только по отдельному слову владельца: `GET /v1/tariffs` — три ряда с числами релиза; `/quota` прибора несёт версию; строка `Tariff` free = значение сетки, не 1 ГБ; зубы 2 и 3 зелёные на проде.
9. Перед докладом "чисто" назвать, чем проверено и сколько файлов взяла проверка; посылка о стволе несёт замер.
