# Сессия Г — 21.08: деплой связки с per-device ключами + включение шифрованного хранения (ADR-0028 Р4)

> Точка входа отдельной сессии. **Всё через `membrana-local-sprint`**. Деплой — по **явному
> слову владельца**, не по своему усмотрению: без него код в ствол, прод не трогать.

## Часть 1 — деплой связки media + cabinet (после слова владельца)

В стволе с 20.08 (`28369bf0`, PR #2031): `NodeKey.audience: node | client`, media выдаёт
per-device client key, `pair.service.ts` кладёт его в `mediaToken` вместо `MEDIA_API_TOKEN`,
отзыв связки в кабинете каскадно гасит media-ключ. **Прод работает по-старому — не выкачено.**

Проверено 21.08: новый страж `media-device-access.guard.ts` **принимает служебный токен**
(строка 31) — выкатка обратно совместима, уже связанная Studio владельца продолжит работать.

Порядок: **office не нужен · media первым · cabinet вторым** (cabinet зовёт media при связке).
Миграция `20260820111700_node_key_audience` применится entrypoint'ом. Перед деплоем убедиться,
что CI-шаг **App DI smoke** (#2009) на стволе зелёный — Тарасов без него деплой не подписывает.

Приёмка части 1 (вещдоки с сервера, не со слов клиента):
- health обоих сервисов после подъёма;
- **перевыдача**: владелец в кабинете делает новую связку → в ответе `mediaToken` НЕ равен
  `API_INTERNAL_TOKEN`, в таблице `NodeKey` появилась строка `audience='client'`;
- запись из Studio после этого принимается (устройство `1c04f0bc-…`, мембрана `c144a9ef-…`);
- отзыв связки в кабинете → строка `client`-ключа получает `revokedAt`, загрузка тем ключом
  отбивается.

Если что-то идёт не так — **откат сначала, разбор потом**: старый образ на месте.

## Часть 2 — ADR-0028 Р4: включить шифрованное хранение кредов на клиенте

Провод построен вчера (b4): канал `membrana:secure-storage` в main Studio, мост
`membranaSecureStorage` в preload с `available:false`, клиентский порт
`apps/client/src/lib/pairing-credentials-store.ts` с Electron-заглушкой `@stage ADR-0028`.
Включение = **миграция** существующих кредов из localStorage в шифртекст одним стартом +
политика «расшифровка не удалась → чистый ре-парринг, не крах».

Ограничение Ожегова и Веснина (b2/b5, держать): порт остаётся **синхронным** (три глагола
read/write/clear); асинхронность моста вводится отдельным именем (`AsyncPairingCredentialsStore`)
либо кэшем при старте — смешивать в один порт запрещено.
