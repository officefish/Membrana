# Промпт: Пользовательский путь — Studio на Firebat, парринг ключом из кабинета

> **Task-промпт.** Размер L. Реестр: `studio-firebat-user-pairing`. Магистраль 20.08
> (owner-choice). Слово владельца 19.08: «взаимодействуем не через скрипты, а через
> электрон-приложение с авторизацией из-под конкретного пользователя; датасет — как набор
> конкретного пользователя; ключи выдаёт кабинет — уже умеет».

## Что есть (разведка 20.08, кодом)

Studio (`apps/membrana-studio`) грузит dist клиента; NSIS-установщик собран 19.08.
Парринг: кабинет `POST /v1/pair {accessKey}` (ключ генерирует пользователь в кабинете) →
устройство регистрируется на media под `membraneId`, reserved-коллекции создаются →
клиент (`MembranePairingPanel`, `api/pairing.ts`) сохраняет креды. Долг: в ответе
`mediaToken = MEDIA_API_TOKEN` (служебный, у каждого клиента, в голом localStorage).

## Что построить (нарезка ратифицирована 10:16Z)

b2 порт хранения кредов (Ожегов) · b3 чистый словарь API (Дынин) · b4 IPC secureStorage
в Studio (Родченко, шифрование за флагом до ADR-0028) · b5 ADR-0028 — долг словом +
сверка словарей NodeKey vs ключ парринга (Веснин) · b6 приёмка вещдоками (Тарасов).

## Запрещено

Менять контракт PairResponse (cabinet+client+media разом) · включать шифрование без
миграции и ротации · строить выдачу ключей заново · трогать магистраль соседей.

## DoD

Studio стоит на Firebat; устройство связано ключом из кабинета; запись из Studio лежит
в наборе пользователя (membraneId сходится); порт хранения в коде; ADR-0028 в стволе;
приёмка b6 с машинно-проверяемыми вещдоками.
