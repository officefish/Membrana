# Workflow Examples Marathon — task prompt

**Размер:** L
**Род карточки:** `marathon`
**Статус маршрута:** матрица разработки описывает marathon, отдельная процедура
marathon ещё не построена. Эта карточка не создаёт и не имитирует её.

## Цель

Накопить проверяемые примеры для всех объектов Mintlify-раздела Workflow:

- все мастерские из живых `workshop.manifest.json`;
- все процедуры из `docs/procedures/registry.json`.

На момент регистрации baseline равен **13 мастерским и 23 процедурам**. Числа не
являются ручным каноном: каждый новый прогон заново читает оба источника.

Документация должна показывать фактическую форму проекта, а не убедительный
пересказ. Пример засчитывается только вместе с источником, входным условием и
наблюдаемым результатом.

## Evidence contract

Каждая запись примера обязана содержать:

| Поле | Требование |
|------|------------|
| `objectType` | `workshop` или `procedure` |
| `objectId` | ID из живого манифеста или реестра |
| `evidenceKind` | `run`, `boundary`, `failure` или `fixture` |
| `source` | существующий repo-relative путь к первичному следу |
| `measuredAt` | дата фактического наблюдения |
| `input` | команда, trigger или воспроизводимое входное состояние |
| `expected` | что контракт обещал до запуска |
| `observed` | что получилось фактически, включая отрицательный результат |
| `verification` | как независимый рецензент перепроверяет утверждение |

`fixture` показывает форму, но **не закрывает** требование lived evidence.
Текст, придуманный ради документации, evidence не является.

## Definition of Done

- для каждого объекта живого корпуса есть минимум один `run`;
- для каждого объекта есть минимум один `boundary` или `failure`;
- генератор публикует baseline и coverage: covered/total отдельно для workshop и procedure;
- отсутствующий пример остаётся видимым требованием, а не исчезает из страницы;
- все `source` существуют, а дубликаты одного следа не раздувают coverage;
- Mintlify-каталог строится только из валидированного evidence;
- минимум один холодный агент воспроизводит выборочный пример по записи;
- code review видит точный diff/SHA и выдаёт LGTM или BLOCK;
- после merge карточка архивируется по task lifecycle.

## Порядок накопления

1. Снять машинный baseline по живым мастерским и процедурам.
2. Сначала закрыть объекты без любого портфолио или usage evidence.
3. Отдельно добыть lived run для мастерской веток: текущий fixture не засчитывать.
4. Для процедур с портфолио формы отделить carrier от lived run.
5. Для `declared-not-built` не сочинять прогон: сначала построить процедуру отдельной
   ратифицированной задачей либо оставить requirement открытым.
6. После каждой стадии оставлять standing artifact: evidence-записи, coverage и
   проверяемый Mintlify-срез.

## Запреты

- не строить marathon procedure внутри этой карточки;
- не менять статусы процедур ради зелёного coverage;
- не считать шаблон, engine, regulation или synthetic fixture прожитым run;
- не копировать примеры вручную в производный MDX;
- не скрывать `0/N`, BLOCK, skipped и not-run знаменатели.

---

## Acceptance criteria

- [ ] Coverage считает ровно текущие workshop/procedure ID из живых источников.
- [ ] У каждого объекта есть валидированный `run` и `boundary|failure` с source.
- [ ] Fixture нигде не увеличивает lived-run coverage.
- [ ] Нулевое покрытие и declared-not-built остаются видимыми в Mintlify.
- [ ] Холодный агент воспроизводит выборочный пример без контекста исходной сессии.
- [ ] Точный diff/SHA проходит машинные проверки и командное LGTM.
