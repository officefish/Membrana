## Ф1 · Грабли: две ловушки, стоившие ложных выводов (XS, норма)

Обе — строки в `AGENTS.md` §Agent tooling, одним заходом.

**`yarn npm audit` без `--all` врёт в успокаивающую сторону.** Гонял
`yarn npm audit --severity high --recursive` для проверки корзины deps — получил **три**
находки вместо 23, потому что без `--all` аудит смотрит один корневой воркспейс. На этом
основании заявил владельцу, что «карточка #1422 устарела». Был неправ. `deps:watch`
внутри зовёт правильно (`--all --recursive`, `scripts/deps-watch.mjs:41`) — ловушка
только у ручного вызова. В граблях про `npm audit` нет ни строки.

**`yarn install` в junction-дереве всегда заканчивается `Failed with errors`.** Четыре
установки за сессию, каждая падала на `esbuild@0.27.7` (`Manifest not found`) и
`cpu-features` (опциональный ускоритель ssh2). При этом `yarn.lock` обновлялся корректно.
Каждый раз приходилось отдельно доказывать, что «Failed» — про нативные сборки, а не про
резолв.

## Ф2 · Проверка живости ключей `resolutions` (S, скрипт)

`resolutions` действуют по **запрошенному дескриптору**, а не по разрешённой версии:
`postcss@npm:8.5.14` бесполезен, если `tailwindcss` просит `^8.4.47`. Стоило трёх полных
циклов `install` + `deps:watch` (~20 минут) при разборе корзины #1422, и дважды диагноз
звучал как «патча нет», хотя патч был. На третьем заходе я вычистил ключи «как мёртвые» и
снёс два ЖИВЫХ — точные пины `js-yaml@npm:5.2.1` и `postcss@npm:8.5.14` оказались
настоящими запросами.

Проверено, что инструмента нет: о `resolutions` не знает ни один файл в `scripts/`;
`yarn` о неиспользованных ключах не предупреждает.

Делать: пройти `resolutions`, для каждого ключа искать дескриптор в `yarn.lock`. Ключ без
запроса → находка «мёртвый, покрытия не даёт». Ключ с запросом → сказать, встала ли
целевая версия. Read-only.

## Ф3 · Маршрут «ребейз → ветка непригодна» назван неверно (S, норма + фикс)

Force-push в deny-листе политики. После ребейза ветка с уже отправленным PR становится
непригодной: `--merge-only` упирается в `DIRTY`, перезаписать нельзя. 30.07 это стоило
лишнего PR (#1487 вместо #1484), ручного закрытия перекрытого и комментария-объяснения.

Грабля в `AGENTS.md` при этом советует ровно недоступное: «rebase →
`yarn git:rebase-continue` → **force-with-lease** → снова `--merge-only`». Канон описывает
маршрут, который политика запрещает.

Делать: поправить строку граблей на работающий маршрут (новая ветка от свежего base →
`pr:ship --no-commit` → закрыть перекрытый ссылкой). Опционально — флаг
`pr:ship --successor`, который делает это одной командой.

## Ф4 · Красный CI без ответа «моё или флак» (M, скрипт)

CI на #1487 упал на двух тестах детекторов с
`does not provide an export named 'fuseDetectorConfidences'` — символ переименован 13.07,
в кеше CI лежал устаревший dist. Правка касалась консилиума и к детекторам отношения не
имела. Чтобы это установить, потребовалось четыре шага (`pr checks` → `run list` →
`run view --log-failed` → грепы) плюс сверка зелени main на базе ветки. Перезапуск джобы
дал зелёное на том же коммите.

Проверено, что инструмента нет: скриптов вокруг CI-логов в `scripts/` нет; `pr-wait` о
флаках не знает — честно говорит «красный» и на этом всё.

Делать: по номеру PR достать упавшие тесты и сопоставить их файлы с файлами диффа.
Пересечение пусто → «падение вне диффа, вероятен флак/кеш, попробуй
`gh run rerun --failed`». Пересечение есть → «твоё». Разница между минутами и получасом
на каждом красном.
