## Что построить

### 1. Бюджет ожидания статуса (`packages/services/sample-playback/src/sequence.ts:35`)

`waitForStatus` резолвится только по нужному статусу либо по `AbortSignal`. Хаб застрял
(сломанный декодер, оборванная сеть, не пришёл `ended`) → промис не резолвится никогда,
панель «Дубли набора» висит в проигрывании. Отмена есть, кнопки отмены в панели нет.

- Добавить budget-таймаут (длительность пробы + запас; значение назвать константой рядом).
- Исход при исчерпании — `error` с `failedSampleId`, как для настоящей ошибки. Молчаливый
  `skip` запрещён: для ошибок это уже соблюдено, распространить на таймаут.

### 2. Stale `outcome` при смене набора (один класс, две панели)

- `apps/cabinet/src/components/sample-library/CabinetSampleDuplicatesPanel.tsx:53,70`
- `apps/cabinet/src/components/sample-library/CabinetSampleChartListPanel.tsx:50,64`

Отчёт прошлого набора виден, пока грузится новый — человек читает числа не того набора.
Сбрасывать `outcome` при смене `collectionId`, не дожидаясь ответа.

## DoD и порча

- **Порча 1:** фиктивный хаб, который после `play()` статус не меняет → сегодня тест висит
  до таймаута раннера; после фикса — `outcome.error` с именем пробы за названный бюджет.
- **Порча 2:** сменить `collectionId` при медленном ответе → в тесте видно старое число;
  после фикса — пусто/загрузка.
- `yarn turbo run typecheck test --filter=@membrana/sample-playback --filter=@membrana/cabinet` — зелёный.
