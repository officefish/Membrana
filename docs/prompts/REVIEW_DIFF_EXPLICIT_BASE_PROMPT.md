# Промпт: ревью читает дифф без явной базы — вердикт не отвечает за то, что осмотрел

> **Task-промпт.** Размер: **M**. Держатель: Vesnin, поддержка Ozhegov, Dynin.
> Иссью [#1771](https://github.com/officefish/Membrana/issues/1771), строка 7 десятки
> хендофа 08.08. Маршрут — `membrana-local-sprint`.

## Предмет

В режиме `--pr` ревью берёт дифф из `gh pr diff` — ручки **без явной базы**
([`code-review-ritual.mjs:307`](../../scripts/lib/code-review-ritual.mjs)). Этажом выше, при
выборе ведущего, тот же прогон считает пути честно: `git diff --name-only origin/main...HEAD`
([`code-review.mjs:132`](../../scripts/code-review.mjs)). Два источника правды о том, **что
именно ревьюится**, в одном прогоне.

Вердикт привязывается к head SHA и **открывает мердж** (`review-gate.mjs`). То есть гейт
заявляет: «этот код осмотрен на этой ревизии» — а чем именно был этот код, из артефакта
не восстановить.

## Два дефекта, и они разной природы — это главное для нарезки

### A. Кэш отстаёт — ТРАНЗИЕНТНО

Вещдок 07.08 (PR #1769): `gh pr diff --name-only` дал **23** файла против **13** у
`compare` и у локального `git diff origin/main...HEAD`. Ревью назвало в разборе файлы
соседского #1768, уже влитого в ствол. Условие: merge-base сдвинулся после создания PR.

**Проверено 08.08 — сегодня не воспроизводится.** Три PR, все три источника сошлись:

| PR | `gh pr diff` | `gh api compare` | локально | merge_base |
|---|---|---|---|---|
| #1728 | 1 | 1 | — | `1a00835e` |
| #1793 | 27 | 27 | — | `5522d4a7` |
| #1801 (ствол вливался **трижды**) | 31 | 31 | 31 | `1a092353` |

Значит отставание кэша — не детерминированное поведение ручки, а состояние гонки на
стороне GitHub. Чинить всё равно надо: источник без явной базы не даёт *права* быть
уверенным, а тишина сегодня ничего не обещает завтра.

### B. В вердикте нет базы — ВСЕГДА

Маркер вердикта несёт только head:

```
<!-- review-verdict sha:348646c1a00117471d822c70be8d3325582ec654 verdict:LGTM lead:ozhegov at:2026-08-08T14:33:35.862Z -->
```

(артефакт `docs/discussions/pr-1801-code-review.md`, снят 08.08). Базы нет ни в маркере, ни
в теле. Постфактум проверить, что вердикт вынесен по фактическому изменению, **невозможно
в принципе** — этот дефект воспроизводится на каждом ревью, включая сегодняшние.

Опасное направление названо в иссью: если кэш отстанет так, что часть настоящего изменения
в дифф не попадёт, ревью её не увидит, а вердикт всё равно привяжется к SHA и разрешит
мердж. Гейт останется формально зелёным, будучи фактически пустым на этих файлах.

## Готовый канон, который нельзя переизобретать

[`scripts/pr-recreate.mjs:88-93`](../../scripts/pr-recreate.mjs) уже делает это правильно:

```js
mergeBase = git(['merge-base', head, `origin/${base}`]);
const files = git(['diff', '--name-status', mergeBase, head])
```

Явная база, локальный git, честный отказ (`return 4`) когда общей базы нет.

## Развилки на нарезку

1. **Источник диффа**: `gh api repos/…/compare/{base}...{head}` (онлайн, отдаёт
   `merge_base_commit` и файлы согласованно) или локальный `git merge-base` + `git diff`
   по образцу `pr-recreate`. У второго нет сети в зависимостях, но он требует, чтобы ветка
   была выкачана.
2. **Что делать, когда локальный head ≠ `headRefOid` PR** (ветка не выкачана, чужой
   worktree, ревью соседнего PR): честный отказ, или падение на `compare`, или ревью с
   явной пометкой «осмотрено локальное состояние, не head PR»?
3. **Куда писать базу**: расширить маркер вердикта полем `base:` (тогда парсер обязан
   читать и старые маркеры без него — их в дереве уже десятки) или держать базу отдельной
   строкой провенанса в теле артефакта?
4. **Проверяет ли `review-gate` базу.** Сегодня он сверяет только head. Сверять ли ещё и
   то, что база вердикта совпадает с текущей merge-base — и если разошлась, это протухание
   (как при новых коммитах) или отдельный исход?
5. **Обратная совместимость.** Артефакты ревью с маркерами старого вида лежат в
   `docs/discussions/` и в архиве; гейт обязан продолжать их читать.

## DoD

- [ ] В режиме `--pr` дифф берётся из источника с **явной базой**; `gh pr diff` в этой роли
      больше не участвует.
- [ ] База (merge-base) попадает в артефакт ревью рядом с head SHA.
- [ ] Расхождение «локальный head ≠ headRefOid PR» **названо**, а не проглочено молча.
- [ ] Старые маркеры вердикта без базы читаются гейтом по-прежнему — зуб.
- [ ] Зуб на само правило: дифф с явной базой не меняется от того, что merge-base сдвинулся
      после создания PR.
- [ ] Ревью соседнего PR (не текущей ветки) продолжает работать — проверено живым прогоном.

## Вне границ

- Ускорение или кэширование самого `gh` — не наш слой.
- Правка `review-gate` под «мердж без ревью» и прочие исходы гейта — другой предмет.
- Переписывание артефактов ревью, уже лежащих в дереве: старые вердикты остаются как есть,
  их формат только читается.
