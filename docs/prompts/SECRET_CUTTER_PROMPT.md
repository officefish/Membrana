## Контекст

[`scripts/night-triage-secret-scan.mjs`](../../scripts/night-triage-secret-scan.mjs) экспортирует
только детекторы: `scanTextForSecrets`, `scanJsonForSensitiveKeys`, `scanFile`,
`scanRoutineReadPaths`. Сканер **находит, но не вырезает**. Веха горизонта `secret-parser-built`
([`docs/strategy/day-horizon.json`](../strategy/day-horizon.json)) поэтому не взята, и за ней
стоят архивация сессий и прецедентов ([#1229](https://github.com/officefish/Membrana/issues/1229))
и аудит дня ([#1230](https://github.com/officefish/Membrana/issues/1230)): полные сессии хранить
нельзя, пока секрет нельзя вырезать.

Задача даёт вехе **первое честное свидетельство** — прогон, а не заявление. Идём по классам
секретов, а не всё скопом: сначала текстовый класс, затем ключи JSON.

### Что построить (продуктовое описание)

1. **Чистая функция** `redactSecrets(text) → { text, cuts[] }` — на **существующих** детекторах.
   Второго набора правил не заводить: два детектора = два голоса, и они разойдутся (урок #537).
   `cuts[]` описывает каждое вырезание (класс правила, позиция/строка, длина) — без самого секрета.
2. **Свойства, закреплённые тестами:**
   - **идемпотентность** — `redactSecrets(redactSecrets(x).text).text === redactSecrets(x).text`;
   - **CRLF/LF** — вырезание не зависит от перевода строк и не портит их (Windows — прецедент, не теория);
   - **стабильная заглушка** — детерминированный вид, без счётчиков, времени и случайности,
     иначе два прогона по одному входу дадут разные файлы и сверка следов станет невозможной.
3. **CLI** `--redact`: пишет **очищенную копию**. Никогда не in-place — вход остаётся нетронутым.
4. **Порядок классов:** сначала текстовый (`scanTextForSecrets`), затем ключи JSON
   (`scanJsonForSensitiveKeys`). Второй класс допускается отдельным PR — веха берётся по частям.

### Архитектура / контракт

| Слой | Путь | Ответственность |
|------|------|-----------------|
| Чистое ядро | `scripts/lib/*` (новый модуль) | `redactSecrets(text)` — без файловой системы и сети |
| Детекторы | `scripts/night-triage-secret-scan.mjs` | правила поиска (переиспользуются как есть) |
| Обвязка | CLI `--redact` | чтение входа, запись копии, отчёт по `cuts[]` |
| Тесты | рядом со ядром | golden-фикстуры + свойства |

**Запрещено:**

- Второй детектор, свои регулярки в обход существующих правил.
- Запись поверх входного файла (in-place) — при ошибке вырезания оригинал будет утрачен.
- Класть фикстуры с настоящими секретами в репозиторий — только синтетические образцы.
- Логировать вырезанное значение (в `cuts[]`, stdout или отчёт) — иначе резак сам станет утечкой.
- Заглушка, кодирующая исходный секрет (длина-в-символах допустима, содержимое — нет).

---

### Тесты

| Область | Минимум |
|---------|---------|
| Главный критерий | повторный скан вырезанного текста даёт **ноль** находок — «ни один секрет не выжил» |
| Идемпотентность | двойное применение даёт тот же текст |
| CRLF/LF | один и тот же вход в двух переводах строк — вырезано одинаково, переводы сохранены |
| Golden | синтетические фикстуры по каждому классу правил |
| Целостность | несекретный текст не изменён ни на байт |
| CLI | вход не изменён, копия создана, отчёт по `cuts[]` без значений |
