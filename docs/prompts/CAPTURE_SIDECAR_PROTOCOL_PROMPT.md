# Промпт: Спутник записи и порядок съёмки

> Задача `capture-sidecar-protocol`, размер **M**. Маршрут исполнения:
> `membrana-local-sprint`. Ожидаемый артефакт: не более двух PR по 400 строк.

## Контекст

Полевой узел уже пишет WAV и отправляет его в media через `yarn field:capture`, но
объявленные условия съёмки остаются свободным текстом. Нужен JSON-спутник рядом с
каждой записью и повторяемый порядок съёмки, чтобы записи разных дней можно было
сравнивать и использовать для калибровки.

Посылка и границы: [`SESSION_V_CAPTURE_PROTOCOL_2026-08-16.md`](./SESSION_V_CAPTURE_PROTOCOL_2026-08-16.md),
точка входа: [`SESSION_V_CAPTURE_SIDECAR_SPRINT_2026-08-19.md`](./SESSION_V_CAPTURE_SIDECAR_SPRINT_2026-08-19.md).
Живой тракт описан в [`LIVE_SERVICES.md`](../LIVE_SERVICES.md).

GitHub Issue не заводится до ратификации формы владельцем.

## Что построить

1. Строгую форму спутника с отдельными разделами `declared` и `measured`.
2. Создание `<recording>.sidecar.json` рядом с WAV в тракте `field:capture`.
3. Человеческий порядок съёмки: дистанции 20/50/100/200 м, повторы и равные классы.
4. `yarn capture:sidecar --check <file>` с именованными отказами.
5. Вещдок проверки спутника рядом с одной живой записью узла.

## Контракт

- `declared`: предмет, аппарат, дистанция, высота, место, погода/ветер, оператор,
  усиление. Пустой раздел запрещён.
- `measured`: только значения, полученные инструментом из записи; слова оператора
  сюда не переносятся.
- Поля двух разделов не пересекаются; измеряемое в `declared` даёт отказ.
- Спутник живёт рядом с записью, второй реестр не создаётся.

## Проверки

- валидный спутник принимается;
- пустой `declared` отвергается именованно;
- измеряемое поле в `declared` отвергается;
- объявленное поле в `measured` отвергается;
- спутник не проходит без связи с конкретной записью;
- одна живая запись `62fe8ea1…` или `c4cfbf06…` проверена тем же глаголом.
