Мастерская — именованный набор инструментов для работы с **одним домом** проекта.
Она отвечает не «где лежит работа» и не «в каком порядке её выполнять», а
«как осмотреть этот предмет, разложить его и рассмотреть один элемент».

## Четыре разных предмета

| Понятие | На какой вопрос отвечает | Пример |
|---------|--------------------------|--------|
| **Дом** | Где живёт группа предметов? | `docs/audit/git` хранит разборы веток |
| **Мастерская** | Какими инструментами работать с этим домом? | `yarn repo:branches`, `repo:branches:decompose` |
| **Кит** | Какая оснастка поставляется держателю? | `kits/tasks-master` |
| **Процедура** | Когда, кем и через какие гейты выполняется работа? | `membrana-local-sprint` |

Смешение понятий опасно. Команда может принадлежать мастерской, но её вызов ещё
не становится процедурой. Процедура может использовать несколько мастерских и
оставлять собственный журнал прогона.

## Что обещает мастерская

У мастерской есть точный адрес `worksOn`: один дом, над которым она работает.
Инвентарный профиль строится вокруг трёх ролей:

- `audit` — осмотреть дом и получить отчёт;
- `decompose` — разложить дом на элементы по его собственным правилам;
- `inspectElement` — рассмотреть один элемент глубже.

Предметные глаголы могут быть другими: например, мастерская веток умеет
`reconcile`, а мастерская кейсов — `portfolio`. Каталог показывает именно живые
команды. Строка с пометкой «план» не является дверью.

<Warning>
Дом без мастерской — законное состояние. Манифест без команды также не даёт
права придумывать вызов: такой пробел показывается явно.
</Warning>

## Два разных вида evidence

### Fixture состояния веток

Мастерская `docs/audit/git` несёт воспроизводимый искусственный fixture с
`example-finished-work` и тестовыми SHA. Он показывает форму сверки, но не
доказывает прожитый разбор настоящей ветки:

```powershell
yarn repo:branches
yarn repo:branches:reconcile
```

Fixture различает `base moved` и изменение каждой цели. Его источник, фрагмент
вывода и дата находятся в [каталоге](/workflow/workshops/catalog#мастерская-веток).
Прожитый пример ещё должен быть накоплен marathon-задачей.

### Прожитый выбор тестового setup

Тестовая мастерская не обещает «запустить всё». Она сначала показывает точный
набор для текущей дельты и знаменатель покрытия:

```powershell
node scripts/tests-container.mjs --setup gate --list
```

На прогоне 2026-08-01 результат был `run=32/319, not run=287, skipped=0`.
Это честнее фразы «тесты зелёные»: видно и выполненную, и невыполненную часть.
