Каждый контейнер несёт свою группу и мастерскую (три глагола: осмотр · декомпозиция · рассмотрение). Источник истины — `README.md` и `workshop.manifest.json` каждого контейнера. Ссылка/адрес — **`home`**. `docs/tasks` (задания) ≠ `docs/audit/tasks` (отчёты про задачи).

Входной глагол: `yarn case:register --validate`

Одна семья: оба про прогон, оба append-only, оба с закрытыми перечнями, оба ссылаются на процедуру. Спека — Issue #1298 (принята капитаном 26.07).

- **Плоскость:** domain
- **role:** —

- **Предметные инструменты:** `portfolio` → `yarn case:portfolio`; `generalize` → `yarn case:generalize`

## Meta (атлас)

### мастерская атласа контейнеров (`docs/tooling-atlas`)

Входной глагол: `yarn tooling:atlas --audit`

**Контейнер контейнеров** (`plane=meta`). Его группа — сами контейнеры проекта вместе с их мастерскими. Он не хранит собственных описаний, а **агрегирует** документацию из каждого контейнера в единый производный индекс. Реализация паттерна `GROUP_CONTAINERIZATION`; оснастка — паттерн `HOME_WORKSHOP`.

- **Плоскость:** meta
- **role:** —
- **worksOn:** `docs/tooling-atlas`
- **Глаголы мастерской:** `audit`, `decompose`, `inspectElement`
- **kit:** `—`
