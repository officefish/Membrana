# Калибровка порогов `/health/deep` (кусок D #2121, вердикт M2)

Пороги ленты обязаны ВЫЧИСЛЯТЬСЯ, не подгоняться (Т2): стоимость чтения ленты
квадратична, `C(N) ≈ α·N²`; `tape_fail = max N: C(N) ≤ B`, где B — бюджет
задержки чтения (за B берём warn-порог базы, 1000 мс).

## Стартовые значения (ДО калибровки)

| Порог | Значение | Основание |
| --- | --- | --- |
| `tape_warn` | 2400 | фактический уровень аварии 23.08 — лента доросла, пора калибровать |
| `tape_fail` | — не вооружён | включается ТОЛЬКО явным env после α-замера: 24.08 порог 2400 при базе 2 мс кричал busy зря (лента 3209, здоровый простой) |
| `db_warn/fail` | 1000 / 3000 мс | вердикт M2 |
| `ratio_warn/fail` | 0,95 / 0,80 | вердикт M2 |

Переопределение — env: `HEALTH_DEEP_TAPE_WARN/FAIL`, `HEALTH_DEEP_DB_WARN_MS/FAIL_MS`,
`HEALTH_DEEP_RATIO_WARN/FAIL`.

## Протокол замера α

1. На представительном агрегате (стенд с прод-подобной базой) замерить время полного
   чтения ленты `C(N)` минимум в трёх точках N (напр. 500 / 1500 / 3000 записей —
   наполняется фикстурой).
2. `α = C(N) / N²` по каждой точке; взять максимум (консервативно).
3. `tape_fail = floor(sqrt(B / α))`, `tape_warn = floor(tape_fail / 2)`.
4. Записать вычисленные значения В ЭТОТ файл таблицей с датой и SHA замера и выставить
   env на проде (по слову владельца).

**Важно:** линия #2113 (линеаризация чтения журнала) снимает квадратичность класса —
после её мерджа замер повторить: α упадёт на порядки, пороги ленты станут мягче,
и их смысл сместится с «чтение убьёт базу» на «объём требует старения ленты».
