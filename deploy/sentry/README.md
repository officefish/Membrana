# Сентри на офисе — картотека происшествий (кусок E)

> Issue [#2122](https://github.com/officefish/Membrana/issues/2122) · зонтик #2117 ·
> решение владельца (Т5/Т6, 24.08): **полный Sentry, свой дом на офисе, отдельный
> контейнер-картотека** — не часть общего дома логов; при упоре в ограничения —
> наращивание мощностей офиса, не отступление на лёгкий двойник.
> Задание и DoD: [`EPIC.md`](../../docs/meeting/logging-observability-cut/EPIC.md), кусок E.

## Порядок (фактура прежде стройки)

1. **Замер мощностей офиса** — владелец, read-only:

   ```bash
   ssh root@<office-vds> 'bash -s' < deploy/sentry/office-capacity-probe.sh
   ```

   Результат записать комментарием в #2122. Сверка: официальные требования
   self-hosted Sentry — **4 CPU · 16 GiB RAM · 20 GiB диска** (очередь Kafka +
   аналитическая база ClickHouse + Redis — цена, принятая владельцем как «несколько
   ГБ»; официальный минимум выше — по замеру решается наращивание).
2. **Развёртывание** (по слову владельца, после замера): официальный дистрибутив
   [getsentry/self-hosted](https://github.com/getsentry/self-hosted) —
   `git clone` на офисе → `./install.sh` → `docker compose up -d`. Свой compose-стек,
   изолированный от прод-стека офиса; наружу — только HTTPS-ингест за Caddy
   (`sentry.mmbrn.tech` или порт за фильтром провайдера — решает владелец при деплое).
3. **Подключение кабинета**: env `SENTRY_DSN` у background-cabinet → чекан номеров
   переключается с `TMP-…` на `INC-…` (см. ниже). Без DSN интеграция спит —
   поведение кабинета не меняется ни на байт.

## Как чеканится INC (контракт B, вердикт M1)

- Кабинет минтит номер формы `INC-XXXX-XXXX` (Crockford Base32) и отправляет событие
  в Сентри с тегом `incident_id` — запись **находима в картотеке по продиктованному
  номеру** (поиск по тегу).
- Сентри не сконфигурирован (нет DSN) → суррогат `TMP-…`, в картотеку не пишется —
  ровно поведение кусков B–D сегодня.
- Транспорт — тонкий envelope-клиент (без @sentry/node: SDK тащит OTel-хвост, ломавший lockfile 24.08), fire-and-forget, proxy-aware; обрыв доставки — warn в лог; честная гарантия
  «INC ⇒ в картотеке» проверяется смоуком после деплоя (DoD куска E); на смоуке отдельно сверить, что ингест принял `timestamp` ISO-строкой (иначе перейти на unix-seconds — замечание ревью #2143).

## Что летит в картотеку, а что нет (Т6 + слово владельца 24.08)

| Летит | Не летит |
| --- | --- |
| происшествия рода «сломан» (кабинет, borда-клиент — по мере подключения) | сам пульс дежурства и метрики |
| сбой пульса: переход alive→silent (событие уже рождается и дедупится — кусок C) | тишина сторожа диска (только телеграм — слово владельца) |
| | обычные 4xx, busy, unreachable (без номера по M1) |

## DoD куска E (из EPIC)

- [ ] Замер мощностей записан (#2122).
- [ ] Контейнер поднят (стенд/офис по слову владельца), изолирован от дома логов.
- [ ] Ошибка «сломан» из кабинета рождает запись, находимую по `INC-…`.
- [ ] Группировка повторов и счётчик работают.
- [ ] Сбой пульса виден в картотеке как происшествие.
- [ ] Пульс/метрики/stale сторожа в картотеку не летят.
- [ ] Прод-деплой — только по слову владельца.
